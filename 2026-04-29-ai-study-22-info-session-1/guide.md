## 0. 한눈에 보는 22기 선택 흐름

1. 바이브 코딩의 의미를 이해한다: 코드를 직접 짜는 것이 아니라 원하는 결과를 말하고 AI가 구현하게 하는 방식이다.
2. 자기 레벨을 고른다: AI가 처음이면 입문, 자동화나 웹사이트를 만들어봤으면 중급, 여러 기수 경험과 에이전트 경험이 있으면 고급을 본다.
3. 관심 결과물을 정한다: 영상, 전자책, 제안서, 투자 에이전트, 리서치, 창업, 개인 OS처럼 4주 후 남기고 싶은 것을 기준으로 고른다.
4. 우선 하나를 신청한다: 완벽히 맞는지 몰라도 1주차 OT를 보고 금요일까지 바꿀 수 있다.
5. 1주차 OT를 최대한 많이 듣는다: 같은 요일에 겹친 것은 다음날 다시보기로 확인한다.
6. 오프라인 모임에 가능하면 참석한다: 얼굴을 튼 뒤 온라인 스터디에 들어가면 질문과 도움 요청이 쉬워진다.
7. 매주 사례 게시글을 낸다: 내 과제를 해야 다른 스터디 다시보기 권한도 열린다.
8. 베스트 발표는 라이브로 듣는다: 20개 스터디의 압축된 사례를 한 번에 따라잡는 장치다.
9. 4주 후 결과물을 남긴다: 강의를 들었다는 기록보다 내가 만든 산출물이 핵심이다.

## 1. 왜 AI 스터디가 아니라 바이브 코딩 스터디인가

진행자는 예전 AI 활용을 "인간이 AI들의 중계 역할을 하던 방식"으로 설명했다. GPT에 상황을 설명하고, 결과를 복사해서 Gemini나 Claude로 옮기고, 다시 파일을 만들고, 오류가 나면 사람이 캡처해서 다른 AI에게 물어보는 식이었다.

22기에서 말하는 바이브 코딩은 이 흐름을 바꾼다. AI가 내 컴퓨터 안에 들어와 폴더와 파일을 읽고, 작업 환경의 맥락을 유지한 채 파일을 만들고 수정하며, 사용자는 "이런 느낌으로 만들어줘", "이 자료를 차트로 정리해줘", "이 워크플로우를 자동화해줘"처럼 의도를 말한다.

> 바이브 코딩에서 더 중요한 것은 코드를 많이 아는 능력이 아니라, 내가 원하는 것이 무엇인지 명확히 설명하는 능력이다.

### 바이브 코딩으로 볼 수 있는 작업

| 작업 | 코딩처럼 보이지 않는 이유 | 그래도 바이브 코딩인 이유 |
|---|---|---|
| 서비스 기획서 기능 리스트 정리 | 문서 작업처럼 보인다 | AI가 요구사항을 구조화하고 로직을 만든다 |
| UI 패턴 정리 | 디자인 분석처럼 보인다 | 화면 규칙과 컴포넌트 구조를 추론한다 |
| 전략 리서치 | 검색과 요약처럼 보인다 | 목적에 맞춰 자료 수집, 분류, 보고서를 만든다 |
| 제안서 자동화 | 문서 템플릿처럼 보인다 | 변수, 섹션, 출력 형식을 자동 처리한다 |
| 슬랙 알림 자동화 | 운영 업무처럼 보인다 | 조건과 실행 흐름을 워크플로우로 만든다 |

## 2. 커뮤니티가 필요한 이유

AI 변화 속도는 6개월 단위에서 3개월, 다시 한 달 단위로 빨라졌다는 것이 설명회의 핵심 배경이다. 새로운 모델과 도구가 계속 나오기 때문에 혼자 모든 변화를 쫓으면 피로감이 커진다.

지피터스는 한 기수에 400명에서 500명 정도가 참여하고, 한 기수에 1000개 안팎의 사례 게시글이 올라온다고 소개됐다. 병원, 마케팅, 자영업, 창업, 연구, 교육처럼 서로 다른 도메인에서 AI를 어떻게 적용했는지가 쌓이기 때문에, 최신 트렌드를 의식적으로 다 파지 않아도 커뮤니티 안에서 자연스럽게 듣게 된다.

| 혼자 강의 듣기 | 지피터스 스터디 |
|---|---|
| 영상만 보고 따라 하다 막힐 수 있다 | 스터디장과 멤버가 질문에 반응한다 |
| 강의를 사놓고 안 듣기 쉽다 | 과제와 사례 발표가 있어 실행하게 된다 |
| 검색어조차 모를 때 시작이 어렵다 | 비슷한 시행착오를 겪은 멤버가 방향을 알려준다 |
| 결과물이 흐려질 수 있다 | 매주 사례 게시글과 발표로 산출물이 쌓인다 |

## 3. 4주 운영 방식

22기는 2026년 5월 18일부터 시작된다. 1주차에는 핵심 강의와 스터디별 OT가 있고, 화요일, 수요일, 목요일에 나뉘어 20개 스터디의 OT가 열린다. 참여자는 우선 신청한 스터디 OT에 들어가되, 다른 요일 OT도 들을 수 있고, 겹친 것은 다음날 다시보기로 확인할 수 있다.

금요일까지 수강 변경이 가능하다. 그래서 진행자는 "지금은 마음에 드는 것 하나를 찜해놓고 OT를 다 듣고 변경할 수 있다"고 안내했다.

| 주차 | 핵심 일정 | 참여자가 해야 할 일 |
|---|---|---|
| 1주차 | 핵심 강의, 스터디별 OT, 수강 변경, 오프라인 모임 | 여러 OT를 들어보고 최종 스터디를 확정한 뒤 미니 사례 제출 |
| 2주차 | 핵심 강의, 스터디별 사례 발표 | 1주차에 만든 사례를 발표하고 피드백 받기 |
| 3주차 | 주차별 사례 발표와 베스트 발표 | 본인 사례를 발전시키고 다른 스터디의 우수 사례 듣기 |
| 4주차 | 마지막 사례 발표, 클로징 | 4주 결과물을 정리하고 전체 흐름 마무리 |

### 필수와 선택

| 구분 | 내용 | 판단 |
|---|---|---|
| 필수 | 본인이 선택한 스터디의 정규 모임 4회 | 반드시 들어가는 축 |
| 강력 추천 | 1주차 OT 다수 청강 | 수강 변경 판단에 필요 |

| 선택 | 다른 스터디 다시보기 | 사례 게시글을 쓰면 권한이 열린다 |

## 4. 입문, 중급, 고급 레벨 기준

이번 22기는 레벨을 입문, 중급, 고급으로 나눴다. 진행자는 주제보다 레벨을 먼저 보라고 강조했다. 같은 AI 스터디라도 도구 조건, PC 환경, 사전 경험이 맞지 않으면 4주가 불필요하게 힘들어질 수 있기 때문이다.

| 레벨 | 기준 | 추천 대상 |
|---|---|---|
| 입문 | GPT와 대화는 해봤지만 무언가 만들어 본 적이 없거나 터미널이 낯선 상태 | AI가 처음이거나 결과물 경험이 없는 사람 |
| 중급 | 자동화나 간단한 웹사이트를 만들어본 경험이 있음 | 업무, 투자, 리서치, 영상 등 특정 결과물을 만들고 싶은 사람 |
| 고급 | 지피터스 3기수 이상 경험, Claude Code나 에이전트 경험, 하드한 도구 사용 경험 | 에이전트 팀, 로컬 LLM, 고급 자동화까지 파고 싶은 사람 |

### 레벨 선택 실수 줄이기

| 상황 | 추천 |
|---|---|
| GPT도 거의 처음이다 | 입문만 본다 |
| 중급이 끌리지만 설치와 기본 도구가 걱정된다 | AI 온보딩 같은 입문 스터디로 기초를 깐다 |
| 업무 자동화 경험이 조금 있다 | 중급에서 제안서, 투자, 리서치, 강의 자료 계열을 본다 |
| Claude Code를 유료로 많이 쓰고 있다 | 고급 Claude Code나 CTO 계열을 검토한다 |
| 로컬 모델을 쓰고 싶다 | PC 사양과 램 조건을 먼저 확인한다 |

## 5. 20개 주제는 어떻게 고를까

설명회에서는 모든 스터디를 세부 커리큘럼까지 다루기보다, 어떤 사람이 어떤 방향으로 고르면 좋은지에 초점을 맞췄다. 핵심은 "도구 이름"보다 "내가 만들 결과물"이다.

### 입문 스터디 방향

| 주제 | 맞는 사람 | 주의할 점 |
|---|---|---|
| 반려 에이전트 | 나만의 AI 비서나 반려봇을 만들고 싶은 사람 | GPT나 Claude 구독 비용을 준비해야 한다 |
| 영상 | AI로 스토리텔링 영상 결과물을 만들고 싶은 사람 | 도구 이름보다 목표가 영상인지가 중요하다 |
| 전자책 | 작가가 되고 싶거나 내 경험을 책으로 묶고 싶은 사람 | 명확한 사업 목표가 없어도 시작하기 좋다 |
| AI 온보딩 | 무엇을 골라야 할지 모르겠고 중급, 고급 도구가 무서운 사람 | 다른 스터디 청강을 병행하기 위한 기초반 성격 |
| 당근마켓 첫 사업 | 육아, 동네 비즈니스, 첫 부수입 실험에 관심 있는 사람 | 아이 동반 줌 참여도 가능하다고 소개됐다 |
| NotebookLM 지식관리 | 자료는 많은데 소화가 안 되고 지식체계가 흐트러진 사람 | AI 시대의 폴더와 지식 관리에 초점 |
| AI 투자 에이전트 | 금융 문맹을 벗어나고 ETF 같은 투자 기초를 배우고 싶은 사람 | AI와 금융을 모두 초보자 맞춤으로 다룬다 |
| 스타트업 실험실 | 1인 창업가, 사업가, 마케팅과 브랜딩을 AI로 실험하고 싶은 사람 | 하네스라는 개념은 도구보다 사업 실험 구조로 이해하면 된다 |

### 중급 스터디 방향

| 주제 | 맞는 사람 | 핵심 결과 |
|---|---|---|
| 리서치 하네스 | 연구, 리서치, 멀티 에이전트 팀 구축에 관심 있는 사람 | 도메인에 맞는 에이전트 팀과 검증 흐름 |
| 제안서 자동화 | 회사 업무에서 기획안, 제안서, 사업계획서를 자주 쓰는 사람 | HTML, PDF, 공유 링크 형태의 문서 자동화 |
| 투자 자동화 | 투자와 n8n 계열 자동화에 관심 있는 사람 | Claude Code가 자동화 도구 로직을 짜도록 활용 |
| 논문 작성 | 연구자, 교수, 박사과정생, 리서치 기반 글쓰기 사용자 | 초록, 논문, 연구 문서 작성 보조 |
| 강의 자료 | 강사, 교육자, 교재와 강의 구조를 만드는 사람 | 강의 프로세스와 자료 제작 자동화 |
| 터미널 인터페이스 | Claude Code를 더 편한 인터페이스로 조작하고 싶은 사람 | Telegram 같은 별도 조작 인터페이스 |
| 중급 영상 | 기본 편집 경험이 있고 AI 영상 도구를 더 깊게 쓰고 싶은 사람 | 짧은 생성물을 합쳐 완성도 있는 영상으로 제작 |

### 고급 스터디 방향

| 주제 | 맞는 사람 | 참여 조건 또는 특징 |
|---|---|---|
| 인생 OS | 경험과 지식을 AI로 재설계하고 싶은 중장년, 사업가, 전문가 | 삶과 사업의 운영체계를 만드는 방향 |
| CTO 스터디 | 사이드 프로젝트를 에이전트 팀으로 만들고 싶은 사람 | CTO 지망형 바이브 코더 대상 |
| Claude Code 끝판왕 | Claude Code를 이미 하드하게 쓰고 결과물을 많이 내고 싶은 사람 | 스킬, 에이전트 개념과 설치 경험 필요 |
| Hermes 로컬 LLM | API 비용과 보안이 걱정되어 로컬 모델을 쓰고 싶은 사람 | 램 8기가는 어렵고 16기가 이상, 24-32기가 권장 |
| Hermes 메가 진화 | 에이전트 내부 구조와 협업 방식을 깊게 파고 싶은 사람 | 비개발자여도 구조 자체에 호기심이 큰 사람에게 적합 |

## 6. 스터디장 소개에서 나온 현장 포인트

후반부에는 일부 스터디장들이 직접 짧게 소개했다. 공통적으로 "강의만 듣는 구조가 아니라 4주 동안 직접 결과물을 만든다"는 메시지가 반복됐다.

| 스터디장 소개 | 핵심 메시지 |
|---|---|
| 전자책 | 돈을 많이 들이지 않고도 본인의 경험과 사례를 전자책으로 묶어 작가가 되는 것을 목표로 한다 |
| 영상 | Gemini 계열 도구를 활용해 영상을 충분히 만들 수 있도록 함께 요금제와 실습 흐름을 잡는다 |
| AI 온보딩 | 중급, 고급 스터디에 바로 가기 어려운 사람이 기본 설치와 사용 흐름을 확실히 잡는 반이다 |
| Claude Code 고급 | 앞단 설계와 하네스 엔지니어링을 해두고 개발은 Claude Code가 자동 운용하도록 만드는 방향이다 |
| 반려 에이전트 | 초보자도 에이전트 하나를 제대로 만들어 쓰는 것이 목표지만, 좋은 도구 구독 비용은 필요하다 |
| 당근마켓 첫 사업 | 동네 비즈니스 아이디어를 거의 제로 코스트에 가깝게 테스트하는 경험을 만든다 |
| 중급 영상 | AI 영상은 한 번에 완성본을 뽑기 어렵기 때문에 생성물들을 나누어 만들고 간단히 합치는 편집이 필요하다 |
| 제안서 자동화 | 기획안, 제안서, 계획서의 반복 섹션과 변수 값을 나누어 외부 공유 가능한 결과물로 만든다 |
| AI 투자 | ETF 입문자를 위한 4주 실전 스터디로, AI와 금융을 모두 초보자 맞춤으로 다룬다 |
| 리서치 하네스 | 에이전트 팀의 할루시네이션과 도메인 검증 문제를 잡는 엔지니어링을 함께 다룬다 |

## 7. 설명회가 던진 참여 판단 질문

이 설명회는 스터디 홍보이기도 하지만, 동시에 "내가 4주 동안 실제로 참여할 수 있는가"를 점검하게 만든다. 진행자는 1주차가 제일 바쁘고, 앉아만 있어서는 들을 수 없는 구조라는 점을 숨기지 않았다.

| 판단 질문 | 해석 |
|---|---|
| 나는 강의 소비보다 사례 생산을 하고 싶은가 | 그렇다면 스터디 구조와 잘 맞는다 |
| 1주차에 여러 OT를 들어볼 수 있는가 | 선택 실패를 줄일 수 있다 |
| 수강 변경까지 활용할 마음이 있는가 | 처음 선택을 완벽하게 하려는 부담을 덜 수 있다 |
| 온라인에서 질문할 수 있는가 | 커뮤니티의 도움을 실제로 받을 수 있다 |
| 결과물 하나를 작게라도 내고 싶은가 | 4주 뒤 만족도가 높아질 가능성이 크다 |

> 스터디는 "AI를 안다"보다 "AI로 해봤다"를 남기도록 설계되어 있다.

## 8. 자주 막히는 곳

| 증상 | 대응 |
|---|---|
| 듣고 싶은 스터디가 너무 많아 선택이 어렵다 | 우선 하나를 신청하고 1주차 OT와 다시보기를 본 뒤 금요일 수강 변경을 활용한다 |
| 입문, 중급, 고급 중 어디인지 모르겠다 | AI로 실제 결과물을 만든 경험이 없으면 입문, 자동화나 웹사이트 경험이 있으면 중급, 에이전트를 하드하게 쓰면 고급을 본다 |
| 고급반이 끌리지만 도구 설치가 걱정된다 | AI 온보딩이나 입문반에서 기본 도구를 먼저 잡고 청강으로 확장한다 |
| 다시보기로 충분할 것 같다 | 베스트 발표는 밀리면 잘 안 보게 되므로 가능하면 라이브 일정을 먼저 확보한다 |
| 오프라인 모임 참석이 부담스럽다 | 필수는 아니지만 얼굴을 익히면 이후 질문과 협업이 쉬워지므로 가능하면 참석한다 |
| 반려 에이전트나 Claude Code 비용이 부담스럽다 | 스터디별 구독 필요 여부를 먼저 확인하고, 비용이 부담되면 전자책, NotebookLM, 온보딩처럼 진입 비용이 낮은 선택지를 검토한다 |
| 로컬 LLM 스터디를 듣고 싶지만 PC 사양이 애매하다 | 램 8기가는 어렵다고 안내됐고, 최소 16기가 이상과 가능하면 24-32기가 환경을 확인한다 |
| 스터디가 강의처럼 편하게 들릴 줄 알았다 | 매주 사례 게시글과 발표가 핵심이므로 4주 동안 실행 시간을 따로 확보한다 |
