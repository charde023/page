[한글자막] 비싼 AI가 더 잘할까? Kimi K3.1 vs Claude Opus 5.5

원작자 Claude Opus · Kimi · 업로드 2026-10-31 · 10.2분 · 원본 영상 ↗

먼저 읽는 쉬운 요약

처음 보는 사람을 위한 읽기 안내

영상 미시청 기준 · 약 7분 · 선수지식: 없음 이 부분만 읽어도 아래 중심 질문에 자기 말로 답할 수 있게 설명한다.

큰 그림: 비싼 모델의 결과가 항상 더 좋은가

이 영상은 두 코딩 AI에 같은 과제를 맡기고 결과를 비교한다. 화자의 설명에 따르면 두 모델은 같은 프롬프트와 같은 도구를 받았고, 각 모델에 맞는 코딩 실행 환경을 최대 노력 설정으로 사용했다. Kimi K3.1 Pro는 Kimi Code, Claude Opus 5.5는 Claude Code를 사용했다.

핵심은 ‘더 좋다’는 말을 하나의 기준으로 판단할 수 없었다는 것이다. Claude Opus 5.5는 여러 장면에서 더 사실적이고 정교한 화면을 만들었지만, 처음부터 열리지 않거나 캐릭터를 움직일 수 없는 결과도 있었다. Kimi는 평균 제작 시간이 짧고 화자가 보기에 더 일관적이었지만, 특정 게임에서는 조작 방향이 잘못되어 제대로 플레이하기 어려웠다.

따라서 가격표만 비교하면 중요한 차이를 놓친다. 화면이 화려한지, 핵심 기능이 실제로 작동하는지, 완성까지 얼마나 기다려야 하는지, 오류를 고치는 데 추가 작업이 필요한지를 따로 확인해야 한다.

읽는 법: 위에서 아래로 읽는다. 가운데 네 상자는 어느 하나가 나머지를 대신할 수 없는 별도 기준이다. 이 그림은 점수 그래프가 아니라 영상의 비교 구조를 정리한 개념도다.

제작 시간과 품질은 같은 값이 아니다

화자가 제시한 평균 제작 시간은 Kimi K3.1 Pro가 29분 41초, Claude Opus 5.5가 47분 2초였다. 이 실험에서는 Kimi가 더 빨랐지만, 화자도 제작 시간이 곧 품질은 아니라고 구분했다.

기계식 키보드 사례가 이를 잘 보여준다. Kimi 결과는 색상과 스위치를 바꾸고 실제로 타이핑하며 키보드를 분해된 모습으로 펼쳐 볼 수 있었다. Claude 결과는 처음에는 열리지 않아 화자가 수정 요청을 보냈다. 수정 후에는 키와 매트의 해상도, 재질감, 기하 형태가 더 사실적으로 보인다는 평가를 받았다. 즉 Claude 쪽은 더 오래 걸렸고 초기 실행에도 실패했지만, 고친 뒤의 화면은 더 정교하다는 평가였다.

은하 충돌 시뮬레이션에서도 기능은 대체로 비슷해 보였지만 Claude 결과가 더 우주답고 아름답다는 것이 화자의 판단이었다. 다만 화자 자신도 이 차이는 설계 품질보다 취향의 영향일 수 있다고 말했다.

읽는 법: 모바일에서는 표 안을 좌우로 이동해 두 모델을 비교한다. 시간과 가격은 발화 수치이고, 시각 품질은 화자의 주관적 평가다. 모든 항목을 합친 공식 점수는 제시되지 않았다.

과제마다 승패가 뒤집혔다

스크롤형 심해 랜딩 페이지에서는 Kimi가 외부 이미지 생성기 없이 HTML과 SVG만으로 결과를 만들었다. Claude는 수영하는 상어와 3D 효과를 넣어 더 재미있는 화면을 만들었지만 페이지가 더 느렸다고 한다.

건물 철거 시뮬레이션에서는 Kimi가 유리 파편과 다시 보기 기능을 구현했고, Claude는 도시 배경과 더 높은 수준의 애니메이션을 보여줬다는 평가를 받았다. 반면 Claude 결과에는 화자가 불편하다고 느낀 소리가 있었고, 연기 표현도 어색하다고 평가했다.

Minecraft형 게임에서는 Kimi 결과가 달리기, 조명 변화, 자동 축소 보기 기능을 제공했고 실제 이동도 가능했다. Claude 결과는 보기에는 좋았지만 캐릭터를 앞으로 움직일 수 없었다. 반대로 화자가 과거에 만들었던 액션 게임을 재현한 과제에서는 Kimi의 상하 조작이 뒤집혀 플레이하기 어려웠고, Claude 결과는 재미와 화면 품질 모두 높은 평가를 받았다.

읽는 법: 위에서 아래로 영상의 소개 순서를 따른다. 파란색·보라색 등은 단계를 구분할 뿐, 모델별 점수나 우열을 뜻하지 않는다. 핵심은 한 과제의 승자가 다음 과제에서도 그대로 이기지 않았다는 점이다.

가격보다 먼저 통과 기준을 정해야 한다

화자는 Kimi가 Claude보다 못한 점이 많지만, 더 낮은 품질에도 불구하고 더 일관적으로 보였다고 정리했다. 또한 Kimi 가격을 입력 100만 토큰당 2달러, 출력 100만 토큰당 10달러라고 말하고, Claude Opus 5.5는 두 배 비용이라고 표현했다. 다만 실제 실험은 API 사용량 과금이 아니라 요금제에서 진행했다고 밝혔다.

따라서 이 영상만으로 “Kimi가 항상 더 경제적이다” 또는 “Claude가 항상 더 좋다”고 결론 내릴 수는 없다. 대신 다음처럼 판단할 수 있다.

  1. 반드시 작동해야 하는 기능을 먼저 적는다.
  2. 화면 품질, 속도, 비용을 서로 다른 항목으로 측정한다.
  3. 첫 결과뿐 아니라 수정 요청에 들어간 시간도 함께 본다.
  4. 내 작업에서 실패 비용이 큰 항목을 우선한다.

예를 들어 예쁜 시제품이 목적이라면 Claude의 시각적 정교함이 중요할 수 있다. 반대로 빠르게 여러 안을 만들거나 첫 실행 성공이 중요하다면 Kimi의 속도와 화자가 관찰한 일관성이 더 중요할 수 있다. 이는 영상 결과를 모든 작업에 일반화한 결론이 아니라, 작업의 통과 기준에 따라 선택을 달리하자는 해석이다.

확인이 필요한 경계
  • 제목과 도입부는 Kimi K3.1이라고 쓰지만 실험 본문은 Kimi K3.1 Pro, 기능 화면은 Kimi K3.1 Pro High라고 부른다. 이 명칭들이 같은 모델·등급인지 전사만으로 확정할 수 없다.
  • 화자는 “여덟 개 데모 목록에서 Claude가 두 번 실패했다”고 말한다. 그러나 제공된 전사에서 두 모델의 결과를 구체적으로 맞대어 설명한 과제는 키보드, 은하, 랜딩 페이지, 철거, Minecraft형 게임, 액션 게임의 여섯 개다. 나머지 두 항목의 정체와 결과는 확인되지 않는다.
  • META의 원작자 후보는 Claude Opus, 소속 후보는 Kimi지만 provenance.note는 이를 “화자 이름+SNS 기준 추정 출처”라고 표시한다. 동시에 META의 social_links는 비어 있고 원본 영상 링크도 없으며, 전사는 실험 진행자를 개발 유튜버 닉 사라예프라고 소개한다. 어느 값이 실제 원작자·소속인지 확정할 수 없다.
  • 20만 개가 넘는 별, 수백 개 에이전트, 가격과 두 배 비용은 화자의 발언이다. 독립 검증 자료는 제공되지 않았다.

여기까지만 이해하면 충분

  • 비싼 코딩 AI가 모든 과제에서 더 빠르고 더 잘 작동한 것은 아니다.
  • 시각적 완성도와 실제 기능 작동 여부는 반드시 따로 평가해야 한다.
  • 모델의 평균 우열보다 내 작업의 필수 기능, 실패 비용, 수정 시간을 기준으로 선택해야 한다.
  • 이 비교는 한 제작자의 실험이며, 데모 개수·모델 명칭·출처 정보에 확인되지 않은 충돌이 있다.

한 장면으로 이해하기

두 모델이 만든 게임을 나란히 열었더니 하나는 화면이 아름답지만 캐릭터가 움직이지 않고, 다른 하나는 움직이지만 특정 게임의 조작 방향이 뒤집혀 있다. 이때 “어느 모델의 화면이 더 예쁜가”만 물어서는 실제 사용 가능성을 판단할 수 없다.

"화면 품질 하나로 모델을 평가한다" 문제
→ "필수 기능·시각 품질·시간·비용을 분리해 확인한다" 작동 방식
→ "작업별 실패 비용에 맞는 모델을 선택한다" 결과

비유와 깨지는 지점

집을 고칠 기술자를 고르는 일

한 기술자는 마감이 아름답지만 문이 열리지 않게 만들고, 다른 기술자는 빨리 끝내지만 일부 손잡이 방향을 거꾸로 달 수 있다. 견적만 비교하지 말고 문이 실제로 열리는지, 마감은 원하는 수준인지, 재작업이 얼마나 필요한지를 따로 검사해야 한다.

비유가 깨지는 지점: 코딩 AI의 결과는 같은 모델에서도 프롬프트, 도구, 실행 환경, 노력 설정에 따라 달라질 수 있다. 한 번의 결과를 사람의 고정된 실력처럼 취급하면 안 된다.

시각적 정교함과 기능 검증은 별개의 기준이기 때문이다. Claude 결과 중에는 키보드가 처음 열리지 않거나 Minecraft형 게임에서 캐릭터가 움직이지 않는 사례가 있었다. 핵심 기능이 실패하면 보기 좋은 화면만으로는 과제를 완료했다고 보기 어렵다.

2. 대조

빠른 제작 시간과 좋은 최종 품질은 어떻게 다른가?

모범 답안 보기

제작 시간은 결과가 나올 때까지 걸린 시간을 뜻하고, 최종 품질은 기능·화면·사용성 등이 요구를 충족한 정도를 뜻한다. 이 실험에서 Kimi는 평균적으로 더 빨랐지만 모든 과제에서 더 좋지는 않았고, Claude는 더 오래 걸렸지만 여러 장면에서 더 정교한 화면을 만들었다.

3. 적용

새 코딩 AI 두 개를 비교한다면 어떤 기준을 먼저 정해야 하는가?

모범 답안 보기

먼저 작업에서 반드시 작동해야 하는 기능을 짧은 체크리스트로 만든다. 그다음 같은 프롬프트와 가능한 한 같은 도구 조건에서 실행하고, 수정 없이 통과한 기능 수를 비교한다. 화면 품질이나 속도는 별도 항목으로 기록하며, 어느 항목의 실패 비용이 큰지에 따라 최종 선택을 달리한다.

이번 글의 통찰

1. 높은 가격은 모든 품질 축의 우위를 보장하지 않는다

  • [원문] Claude Opus 5.5는 여러 과제에서 더 사실적이고 정교한 화면을 만들었지만, 키보드 초기 로딩과 Minecraft형 게임 이동에 실패했다. Kimi도 액션 게임 조작 오류를 냈다.
  • [해석] 모델 가격이 아니라 작업의 필수 기능, 시각 기준, 대기 시간, 수정 비용을 분리해서 평가해야 한다.
  • [경계] 한 제작자가 수행한 사례 비교이며 공식 점수, 반복 횟수, 독립 평가자는 제시되지 않았다. 전체 모델 성능으로 일반화할 수 없다.

2. ‘보이는 품질’과 ‘사용 가능한 품질’은 다르다

  • [원문] Claude의 Minecraft형 게임은 시각적으로 매력적이었지만 이동할 수 없었다. Kimi의 액션 게임은 화면이 생성됐지만 상하 조작이 뒤집혀 있었다.
  • [해석] 실제 사용 여부를 판단하려면 결과물을 보는 데서 끝내지 말고 핵심 행동을 직접 실행해야 한다.
  • [경계] 영상에서 언급한 오류가 모델 자체, 생성 코드, 실행 환경, 코딩 하네스 중 어디에서 비롯됐는지는 확인되지 않았다.

3. 비교 자료의 숫자와 이름도 검증 대상이다

  • [원문] 화자는 여덟 개 데모 중 Claude가 두 번 실패했다고 말하지만, 제공된 전사는 여섯 개의 짝지은 비교만 구체적으로 설명한다. 제목은 Kimi K3.1, 본문은 Kimi K3.1 Pro와 Pro High를 사용한다.
  • [해석] 모델 비교를 재사용하기 전에 모델 버전, 과제 수, 과금 조건, 평가 단위를 먼저 고정해야 한다.
  • [경계] 누락된 두 데모가 무엇인지, 세 Kimi 명칭이 동일한 실행 조건을 뜻하는지 알 수 없다. META의 Claude Opus·Kimi 출처 후보와 전사의 실험 진행자 닉 사라예프도 서로 일치하지 않으며 원본 링크가 없어 확정할 수 없다.

차드의 4렌즈

교육자 · 직접 전이

  • 관련성: 영상은 “예뻐 보인다”는 인상과 “실제로 움직인다”는 관찰을 분리한다.
  • 통찰: 학습자의 이해도 말이나 결과물 외형이 아니라, 핵심 기능을 직접 설명하고 실행하는지로 확인할 수 있다.
  • 질문/행동: 결과물을 보여 달라고만 하지 말고, 필수 동작 하나를 이유와 함께 재현하게 할 수 있는가?

사업가 · 구조적 비유

  • 관련성: 모델 선택에는 가격뿐 아니라 대기 시간, 재작업, 기능 실패 위험이 함께 들어간다.
  • 통찰: APOM의 현재 시스템 상태는 자료에 없으므로 직접 적용 사실을 말할 수 없다. 다만 향후 도구를 비교한다면 낮은 단가보다 수정 없이 통과한 필수 작업 수를 함께 보는 가설은 시험할 수 있다.
  • 질문/행동: 더 비싼 도구가 절약한 재작업 시간이 추가 비용보다 큰지 어떻게 기록할 것인가?

마케터 · 직접 전이

  • 관련성: 영상은 “더 사실적이다”라는 주장과 실제 로딩·이동·조작 장면을 함께 보여준다.
  • 통찰: 화려한 결과 이미지는 시선을 끌지만, 작동 장면과 실패 조건이 신뢰를 만든다.
  • 질문/행동: 상세페이지나 카피에서 형용사 대신 고객이 직접 확인할 수 있는 동작 하나를 증거로 보여줄 수 있는가?

AI/SW 학습자 · 직접 전이

  • 관련성: 같은 프롬프트를 사용해도 실행 시간, 기능 오류, 화면 품질이 과제마다 달라졌다.
  • 통찰: 모델 이름보다 실제 작업량과 실패 기준에 맞는 평가 묶음이 필요하다. 정상 출력뿐 아니라 로딩 실패, 이동 불가, 반전된 조작 같은 예외를 시험해야 한다.
  • 질문/행동: 다음 비교에서 실행 전에 필수 기능 체크리스트를 만들고 수정 없는 첫 결과를 따로 기록할 수 있는가?

  • 중단 기준 1개: 더 비싼 모델의 수정 없는 통과 항목 수가 더 저렴한 모델보다 많지 않으면 확대 시험을 멈춘다.

# 섹션 요지
1 비교 조건과 시간 같은 프롬프트·도구를 사용했다는 조건과 평균 제작 시간을 제시한다.
2 여섯 개의 구체적 비교 과제마다 시각 품질과 기능 성공 여부가 엇갈린다.
3 Kimi 기능 소개 짧은 추론 기록, 파일·이미지·플러그인·스킬·Swarm을 소개한다.
4 가격과 최종 평가 Kimi의 낮은 가격과 일관성, Claude의 높은 품질을 함께 언급한다.
5 충돌과 미확인 조건 데모 개수, 모델 이름, 출처 후보, 가격 비교 조건이 완전히 확인되지 않는다.

1. 비교 조건과 평균 제작 시간

화자는 두 모델에 정확히 같은 프롬프트와 같은 도구를 제공했다고 말한다. 다만 실행 환경은 모델별로 달랐다.

  • Kimi K3.1: Kimi Code
  • Claude Opus 5.5: Claude Code
  • 두 환경 모두 최대 노력 설정
  • 화자는 결과가 완성되기 전에는 어느 쪽도 채점하지 않았다고 설명
  • Kimi K3.1 Pro 평균 제작 시간: 29분 41초
  • Claude Opus 5.5 평균 제작 시간: 47분 2초

화자는 시간 차이가 크다고 보면서도 제작 시간과 품질은 다른 문제라고 분명히 구분했다.

2. 기계식 키보드 시뮬레이션

첫 과제는 Loom이라는 3D 기계식 키보드 재현이었다.

Kimi 결과에서는 다음 기능이 소개됐다.

  • 키보드와 키 색상 변경
  • 스위치 유형 변경
  • 실제 타이핑
  • 키보드를 분해된 형태로 펼치는 기능
  • 장바구니 추가

Claude 결과는 처음에는 열리지 않았다. 화자는 수정 메시지를 보냈고, 이후 열린 결과를 비교했다. 수정 후 Claude 결과는 키와 매트의 해상도, 키 형태의 기하학적 정교함, 전체적인 사실감에서 더 높게 평가됐다. 기능은 대체로 비슷했고 색상 선택지는 Claude 쪽이 조금 더 많았지만, 화자는 이를 중요한 차이로 보지 않았다.

3. 은하 충돌 시뮬레이션

Kimi 결과는 두 은하가 합쳐지는 과정을 보여 줬다. 화자는 20만 개가 넘는 별이 들어간 것 같다고 추정했으며, 한 은하의 가장자리가 다른 은하의 블랙홀 쪽으로 끌려가는 장면과 재생 속도 조절을 소개했다.

Claude 결과는 은하의 아름다움과 우주다운 표현에서 더 높은 평가를 받았다. 그러나 화자는 입자 수를 직접 세지 않았고, 차이가 설계 품질보다 배경색과 취향의 문제일 수 있다고 말했다. 두 결과의 기능은 대부분 비슷하다는 평가였다.

4. 심해 스크롤 랜딩 페이지

과제는 Abyssal이라는 심해 잠수 관련 스크롤형 페이지였다. 외부 이미지 생성기를 사용하지 않고 HTML과 SVG만으로 만들도록 제한했다.

  • Kimi: 100% HTML과 SVG로 구성된 비교적 단순한 스크롤 페이지
  • Claude: 수영하는 상어와 3D 효과를 추가한 더 화려한 페이지
  • 화자의 평가: Claude 쪽이 스크롤하는 재미는 더 컸지만 페이지 속도는 더 느렸음

화자는 느린 이유를 자원 최적화 부족으로 추정했지만 직접 확인한 원인은 제시하지 않았다.

5. 건물 철거 시뮬레이션

Kimi는 Kestrel Tower 철거 장면을 만들었다.

  • 아래에서 위로 폭발 진행
  • 유리 파편이 떨어지는 표현
  • 철거 장면의 즉시 다시 보기
  • 주변 도시는 비교적 비어 보였다는 평가

Claude 결과는 건물이 도시 안에 배치돼 있었고 애니메이션 품질도 더 높다는 평가를 받았다. 반면 소리가 거슬렸고 연기 기둥은 어색해 보인다는 지적이 있었다.

6. Minecraft형 게임

Kimi 결과는 다음 요소로 좋은 평가를 받았다.

  • 높은 품질의 음영
  • 달리기
  • 조명 변화
  • 자동 축소 보기 기능
  • 물속에 들어갔을 때의 흐림 효과

화자는 산소 설정은 보이지 않는다고 말했다.

Claude의 Beyond the Veil 또는 Golden Hour로 언급된 결과는 시각적으로 좋아 보였지만 캐릭터가 앞으로 움직이지 않았다. 화자는 이를 최종 검증 부족 가능성과 연결했으나 원인을 확정하지 않았다.

이 지점에서 화자는 Claude가 “여덟 개 데모 목록에서 두 번” 실패했다고 말했다.

7. 액션 게임 재현

Kimi는 화자가 과거에 만든 게임을 재현했다. 좌우 조작은 정상 방향이었지만 위쪽 입력이 아래쪽 이동으로 이어져 합리적으로 플레이하기 어려웠다.

Claude 결과는 화자가 매우 아름답고 재미있다고 평가했다.

  • 그림자 표현에 높은 평가
  • 실제 플레이 가능
  • 화자가 만든 원래 게임보다 낫다는 주장
  • 일부 요소가 앞선 Minecraft 결과를 활용했을 가능성을 화자가 추정

이 과제에서는 앞선 Minecraft형 게임과 반대로 Claude 쪽이 확실히 더 좋은 평가를 받았다.

8. 추론 기록과 Kimi 기능

Thinking Complete 탭에서는 짧은 추론 기록을 확인할 수 있다고 소개한다. 전사에는 “hello”에 간단히 답하는 예가 포함돼 있다.

화자는 Claude 모델과 OpenAI 모델의 추론 기록 길이 차이도 언급하지만, “이쪽이 더 짧다”는 표현이 전사에서 정확히 어느 모델을 가리키는지는 선명하지 않다.

Kimi 인터페이스 기능으로 다음 항목이 소개됐다.

  • 파일과 이미지 추가
  • 플러그인
  • 스킬
  • Swarm

화자는 Swarm이 Kimi 전용 기능이며 수백 개의 에이전트에 정보 탐색을 맡길 수 있다고 설명했다. 예시 요청은 가짜 제품을 위한 독립적인 랜딩 페이지 열 개를 만드는 것이었다. 이후 다양한 제품 구성과 서로 다른 스타일, 디렉터리 구성을 요청했다. 실제로 몇 개의 에이전트가 사용됐고 열 개 페이지가 모두 완성됐는지는 전사에서 확인되지 않는다.

9. 가격과 최종 평가

화자가 제시한 Kimi 가격은 다음과 같다.

  • 입력 100만 토큰당 2달러
  • 출력 100만 토큰당 10달러

화자는 Claude Opus 5.5가 두 배 비용이라고 표현하면서, 품질도 두 배인지 질문했다. 동시에 실제 비교는 API 사용량 과금이 아니라 요금제에서 진행했으며 Kimi 요금제의 허용량이 넉넉하다고 말했다.

최종 평가는 단일 승자 선언이 아니었다.

  • Kimi K3.1 Pro는 여러 면에서 Claude Opus 5.5보다 못하다는 평가
  • 낮은 품질에도 더 일관적으로 보였다는 평가
  • 낮은 비용을 고려하면 강력한 경쟁자라는 평가
  • 지식 작업에도 충분히 유능하다는 화자의 주장
  • 높은 품질 영역에서는 작은 개선도 최종 결과에 큰 차이를 만들 수 있다는 주장

10. 숫자·명칭·출처 충돌

  1. 데모 개수: 화자는 여덟 개 데모라고 말하지만 제공된 전사에서 두 모델의 결과를 구체적으로 짝지어 비교한 과제는 여섯 개다. 앱 기능과 Swarm을 포함하면 주제 항목은 여덟 개가 되지만, 이 둘은 앞선 형식의 양쪽 모델 데모 비교가 아니다.
  2. Kimi 명칭: 제목과 도입은 Kimi K3.1, 비교 본문은 Kimi K3.1 Pro, 기능 화면은 Kimi K3.1 Pro High라고 한다. 동일 모델의 요금제·노력 등급인지 별도 모델인지 확인되지 않는다.
  3. 출처 후보: META는 원작자 후보를 Claude Opus, 소속 후보를 Kimi로 기록하면서 추정 출처라고 표시한다. 반면 전사는 개발 유튜버 닉 사라예프가 실험했다고 소개한다. META에는 근거라고 적힌 SNS 링크와 원본 영상 링크가 없다.
  4. 가격 비교: Kimi의 입력·출력 가격은 제시됐지만 Claude의 대응 입력·출력 단가는 전사에 없다. “두 배 비용”의 계산 기준은 확인할 수 없다.
  5. 실험 과금 조건: 토큰 가격을 논의하지만 실제 실행은 API 사용량 과금이 아니라 요금제에서 이뤄졌다. 제시된 단가와 실험의 실제 지출을 직접 연결할 수 없다.

비싼 AI가 결과도 더 좋을까요? 이번에는 같은 과제를 받은 두 코딩 모델의 실제 결과를 비교합니다. 이번 실험은 개발 유튜버 닉 사라예프가 진행합니다. 키미와 클로드 오퍼스로 만든 웹사이트와 게임을 비교합니다. 더 보기 좋은 결과와 실제로 작동하는 결과가 언제 엇갈리는지 제작 시간과 오류까지 함께 살펴보세요. 한 제작자의 실험이라는 점을 염두에 두고 내 작업에 어떤 차이가 중요한지 판단해 보시죠.

이제 실용적인 핸즈온 데모를 조금 더 자세히 살펴보겠습니다. 여기서는 Kimi K3.1과 Claude Opus 5.5의 데모를 모두 호스팅하는 랜딩 페이지를 만들었습니다.

이 비교에서 제가 정한 규칙은 두 모델에 정확히 같은 프롬프트를 입력하는 것이었습니다. 두 모델은 정확히 같은 도구를 사용했고, 각각의 코딩 하네스(coding harness)를 최대 노력(max effort)으로 실행했습니다. 즉, Kimi K3.1에는 Kimi Code를, Claude Opus 5.5에는 Claude Code를 사용했습니다. 아직 어느 쪽에도 점수를 매기지는 않았습니다. 사실 둘 다 지금 백그라운드에서 실행 중입니다. 그러니 이 테스트가 알아서 진행되도록 두고, 모두 준비되면 다시 돌아오겠습니다.

좋습니다. 평균적으로 Kimi K3.1 Pro는 빌드하는 데 29분 41초가 걸렸고, Opus 5.5는 47분 2초가 걸린 것 같습니다.

우선 빌드 시간에서부터 큰 차이가 보입니다. 물론 빌드 시간과 품질은 별개의 문제이니, 이제 품질을 살펴보겠습니다. 첫 번째 데모는 기본적으로 Loom이라는 기계식 키보드 복제 시뮬레이션입니다. 보시다시피 3D 디자인입니다. 이건 전부 Kimi K3.1이 만들었습니다. 색상을 조금 바꿔보면 내추럴 그래파이트부터 샌드까지 선택할 수 있는 컬러 피커가 보입니다. 실제 키에는 듄 색상을 적용할 수도 있습니다. 귀여운 효과가 나타나네요. 저는 여기 있는 어두운 색이 마음에 드니 녹턴으로 하겠습니다. 스위치도 바꿔서 클릭키(clicky)로 만들 수 있습니다. 그리고 정말 멋진 점은, 저도 처음에는 몰랐는데 실제로 키보드에 타이핑할 수 있다는 겁니다. 물론 오디오를 켜면 여러 가지가 꼬일 수 있으니 켜지는 않겠습니다. 하지만 여기서 타이핑할 수 있는 것 같습니다. 이걸 분해해서 펼쳐볼 수도 있습니다. 품질이 아주 높고 정말 멋집니다.

제가 처음 생각했던 것보다 훨씬 발전된 결과물이고, 마지막에는 카트에 추가할 수도 있습니다. 이제 이걸 Opus 5.5와 비교하고 있는데, 농담이 아니라 로딩이 되지 않습니다. 분명 어떤 식으로든 빌드가 망가진 것 같습니다. 훨씬 오래 걸렸는데도 작동하는지 확인조차 하지 않았습니다. 일단 메시지를 빠르게 보내서 망가뜨린 부분을 수정하도록 하겠습니다. 아무튼 지금은 Kimi가 Opus를 확실히 압도하고 있고, 이게 바로 Opus 5.5입니다.

우선 눈에 띄는 건 시각적 충실도가 더 높다는 점입니다. 키의 해상도도 조금 더 높고, 매트(mat) 품질도 더 좋습니다. 색상 변경 같은 기능은 사실상 동일합니다. 색상이 몇 가지 더 있기는 하지만 그다지 중요한 차이는 아닙니다.

지금 타이핑을 해보니 그 결과로 멋진 애니메이션이 몇 가지 나타납니다. 보시다시피 스위치 종류도 다릅니다. 즉, 소리 등이 서로 다르다는 뜻입니다. 마지막으로 데스크 매트도 바꿀 수 있습니다. 이제 두 결과물을 나란히 놓고, 둘 다 어떻게 보이는지 볼 수 있도록 조금 축소해보겠습니다.

보시면 둘 다 반드시 나쁘다고 할 수는 없습니다. 엄청난 차이는 아닙니다. 물론 Opus 5.5 쪽이 조금 더 현실적으로 보입니다. 키 자체의 기하 구조도 조금 더 정교하다고 할 수 있겠습니다. 하지만 솔직히 Kimi K3.1 Pro가 훨씬 저렴하다는 점을 생각하면 나쁘지 않습니다. 다음으로 보여드릴 테스트는 Kimi가 두 은하의 충돌을 모델링한 것입니다. 여기에는 두 은하가 합쳐지는 총 시간이 백만 년 단위로 표시됩니다. 20만 개가 넘는 별이 포함된 전체 규모의 시뮬레이션인 것 같습니다. 한 은하의 가장자리가 다른 은하의 블랙홀로 빨려 들어가면서 정말 기이한 플룸(plume)이 발생합니다. 지금 1배속으로 재생하고 있는데, 보시다시피 은하가 완전히 뒤틀리고 있습니다. 중심부도 서로 가까워지고 있습니다. 꽤 멋집니다. 물론 저는 은하가 다른 은하와 충돌하는 모습을 실제로 본 적은 없지만, 아마 이런 모습과 비슷하지 않을까 싶습니다. 이제 Opus 5.5의 결과와 비교해보겠습니다. 시각적 충실도와 은하가 얼마나 아름다운지는 확실히 다릅니다. Kimi K3.1 Pro의 결과는 이것과 비교하면 거의 어린이용처럼 보일 정도로, 이쪽이 훨씬 더 우주답습니다.

다만 저는 이것이 디자인 품질이라기보다는 취향의 차이를 반영한다고 생각합니다. 이 디자인에서 입자의 총 개수를 세고 있는 것도 아니고요. 하지만 보시다시피 기능 대부분은 사실상 완전히 동일합니다. 이제 축소해보면 일종의 멋진 상부 구조가 보입니다.

전체적으로 보면, 이 모든 것이 빠르게 또는 느리게 움직이는 모습을 보는 건 꽤 재미있습니다. 하지만 Kimi가 그렇게까지 못했다고 말할 만한 근거는 충분하지 않은 것 같습니다. 사실상 배경색의 차이일 뿐입니다. 다음은 스크롤 기반 랜딩 페이지 사이트입니다. 보아하니 Abyssal이라는 심해 다이버를 주제로 한 것으로, 현재 보이는 것은 그 설계도 형태의 목업입니다. 핵심은 이 결과물이 아주 인상적으로 보이지 않더라도 다른 리소스를 전혀 사용하지 않았다는 점입니다. 어떤 이미지 생성기로 가서 가짜 이미지를 만들 수도 없었습니다. 전부 100% SVG와 HTML로 만들어야 했습니다. 지금 진행 중인 작업도 바로 그것입니다. 웹사이트 전체를 스크롤하고 있는데, 100% SVG와 HTML로 생성되었습니다.

이게 Kimi의 결과입니다. 이제 Opus 5.5와 비교해보면 Opus가 조금 더 나아갔습니다. 살아 있는 상어들이 헤엄치도록 만들었고, 제 생각에는 이 부분이 차이였습니다. 실제로 이렇게 하기로 결정했네요.

아, 3D 효과로 구동하기로 했습니다. 지금은 잘 느껴지지 않겠지만 한 가지 말씀드리면 페이지가 훨씬 느립니다. 아마 리소스가 제대로 최적화되지 않은 것 같습니다. 그래도 Kimi K3.1 Pro의 결과보다 이 웹사이트를 스크롤하는 게 훨씬 재미있기는 합니다.

이건 꽤 흥미롭습니다. 타워 철거 시뮬레이션입니다. 여기는 케스트럴 타워(Kestrel Tower)입니다. 확대해서 실제로 볼 수도 있습니다. 비교적 잘 디자인되어 있지만 주변 도시는 조금 휑해 보입니다. 시뮬레이션을 실행해보겠습니다. 스페이스바를 누르면 아래쪽부터 폭파됩니다. 유리와 각종 잔해가 지상으로 무너지는 모습을 볼 수 있습니다. 상당한 연산을 필요로 하는 실제 시뮬레이션입니다. 모든 것이 파괴되는 장면을 보여주는 일종의 즉시 재생 영상도 있습니다.

이걸 Claude Opus 5.5와 비교해보면, 이 건물은 확실히 도시 안에 있습니다. Kimi K3.1에는 없었던 요소입니다. 이제 이 녀석을 작동시켜보겠습니다. 사고를 좀 쳐보죠. Opus 5.5에는 정말 성가신 소리가 있었다는 점은 언급할 만합니다. Kimi에서는 그런 소리가 없어서 좋았지만, 물론 애니메이션 측면에서는 Opus가 훨씬 높은 품질이었습니다. 다만 연기 기둥은 제게 조금 우스꽝스럽게 느껴집니다.

Kimi가 만든 의무적인 마인크래프트 게임도 있습니다. 정말 아름답게 만들어졌습니다. 솔직히 더 제안할 만한 건 별로 없다고 생각합니다. 이제 이런 모델들이 얼마나 쉽게 마인크래프트 같은 게임을 플레이할 수 있는지가 꽤 흥미롭습니다. 음영 처리도 정말 고품질입니다. 방금 조명을 껐다는 점을 말씀드리지만, 그래도 아주 탄탄합니다. 달리기도 할 수 있고, 자동으로 화면을 축소해주는 기능도 훌륭합니다.

밤에 여기서 물속으로 뛰어들면 어떻게 되는지 보겠습니다. 오, 정말 으스스하네요. 산소 설정은 없는 것 같습니다. 하지만 이제 화면이 흐려지기 시작하는 것도 정말 멋집니다.

이걸 Opus 5.5의 Beyond the Veil과 비교해보면, 안타깝게도 움직일 수가 없습니다. 좀 이상하네요. 정말 움직일 수 없습니다. 캐릭터가 앞으로 나아갈 수가 없습니다. 그래서 시각적으로는 매우 매력적으로 보이지만, 이런 테스트를 하지 않은 탓에 Opus 5.5가 약간 일을 망친 것 같습니다. Golden Hour는 정말 멋져 보이지만, 그걸로 할 수 있는 일이 별로 없습니다. 아쉽네요.

Opus 5.5가 8개 데모 중 두 번이나 실수한 것 같습니다. 아마 마지막에 작업을 검증하지 않았기 때문일 겁니다. 정확히는 모르겠지만요. 그래도 최대 모드(max mode)로 실행했는데 이런 결과라니 실망스럽습니다.

이건 제가 얼마 전에 만든 게임을 Kimi K3.1이 재현한 것입니다. 안타깝게도 조작이 꽤 끔찍합니다. 위로 가면 아래로 가고, 오른쪽과 왼쪽은 실제로 오른쪽과 왼쪽으로 가기 때문에 제대로 플레이할 수가 없습니다. 그래서 플레이하기가 상당히 혼란스럽습니다.

이걸 Claude Opus 5.5 버전과 비교하면 확실히 훨씬 낫습니다. 실제로 꽤 재미있고 매우 아름답습니다. 솔직히 제가 이보다 더 잘 만들 수는 없었을 것 같습니다. 지금은 거의 바이럴이 된 제가 개발한 게임조차도 이 결과물에 확실히 밀립니다. 정말 아름다운 게임입니다. 멋진 그림자도 있습니다. 어쩌면 사실적으로 표현하기 위해 마인크래프트 빌드의 일부를 사용했을 수도 있겠습니다. 그래도 아주 탄탄하고, 다시 플레이하고 싶은 게임으로 10점 만점에 10점입니다.

아무튼 Thinking Complete 탭을 클릭하면 그 아래에서 추론 과정(reasoning trace)을 실제로 볼 수 있습니다.

“hello”에는 간단하게 답하겠습니다. 도구는 필요 없다고 판단해야 합니다. 사용자의 언어는 영어입니다. 따뜻하고 간결하게 답하면 됩니다. 아마도 “안녕하세요. 오늘 무엇을 도와드릴까요?”라고 하면 되겠죠.

Claude 모델의 추론을 읽는 것과 OpenAI 모델의 추론을 읽는 것 사이에는 차이가 있다는 걸 알 수 있습니다. 차이는 이쪽 모델들이 훨씬 짧게 작성한다는 점입니다.

아무튼 아래쪽에 있는 이 버튼을 클릭하면 파일과 이미지를 추가하는 등 다양한 기능이 있다는 것을 볼 수 있습니다. 플러그인도 있고, 스킬도 있습니다. Swarm도 있습니다. 이건 Kimi만의 기능입니다. 이 버튼을 클릭하면 수백 개의 에이전트가 여러분을 대신해 정보를 찾도록 작업을 맡길 수 있습니다.

여기서 “가상의 제품을 위한 독립적인 랜딩 페이지 10개를 만들어줘”라고 입력하겠습니다. 이제 제가 단일 에이전트와 대화하는 대신 실제로 스웜(swarm)에 작업을 위임하는 것입니다. 이 기능은 Kimi에서 기본으로 지원되며, 이를 수행하는 방식은 이런 에이전트를 여러 개 생성하는 것입니다.

여기 아래에 제가 지금 사용 중인 모델인 Kimi K3.1 Pro High가 있습니다. 하지만 Claude와 Codex 모델에서 할 수 있는 것처럼, 원하는 대로 작업 수준(effort level)을 변경할 수 있습니다. 이제 모델이 저에게 질문을 하기로 했고, 이 멋진 UX 패널을 통해 질문할 수 있습니다.

그래서 “다양한 제품 구성으로 해줘(Do a varied product mix)”라고 말하겠습니다. 그리고 하나—아니요, 디렉터리와 함께 서로 다른 스타일을 원합니다. 이제 실제로 나가서 그것들을 만들어 주고 있습니다.

전반적으로 여기의 모델들은 꽤 탄탄합니다. Kimi K3.1 Pro는 여러 면에서 Opus 5.5만큼 뛰어나지는 않지만, 품질은 더 낮아도 일관성은 더 높은 것처럼 보였습니다. 또한 입력 토큰 100만 개당 2달러, 출력 토큰 100만 개당 10달러라는 점도 고려할 만합니다. Opus 5.5는 비용이 두 배이므로, 문제는 품질도 두 배인가 하는 것입니다.

당연히 품질이 좋아질수록 약간의 비율 개선도 최종 결과에 더 큰 영향을 줍니다. 하지만 전반적으로 Kimi K3.1 Pro는 상당히 진지한 경쟁자이자 지식 작업에 꽤 유능한 모델임을 입증했다고 생각합니다. 참고로 저는 이 테스트들을 요금제(plan)에서 실행했습니다. API 사용으로 실행한 것은 아니지만, Kimi 역시 요금제에서 사용할 수 있는 한도가 매우 넉넉합니다.
