처음 보는 사람을 위한 읽기 안내

영상 미시청 기준 · 약 9분 · 선수지식: 없음 이 부분만 읽어도 아래 중심 질문에 자기 말로 답할 수 있게 설명한다.

큰 그림: 답보다 답을 만들 때 따라가는 정보가 비쌀 수 있다

AI 코딩 도구에 메시지를 보내면 사용자가 쓴 요청만 모델로 전달되는 것이 아니다. 영상의 설명에 따르면 프로젝트 지침, 사용 가능한 도구 목록, MCP 도구와 스킬, 이전 대화도 함께 전달된다. 현재 작업에 필요 없는 정보까지 매번 따라가거나, 다른 세션에서 이미 겪은 실패를 다시 반복하면 토큰이 낭비된다.

영상은 Graft처럼 작업 전에 파일 지도를 만들어 탐색 비용을 줄이는 방식과 Token Economizer가 실제 세션을 관찰해 프로젝트별 낭비 습관을 학습하는 방식을 대조한다. Token Economizer는 다음 세 경로를 독립적으로 조정해 불필요한 문맥과 반복 시도를 줄이려 한다.

읽는 법: 위에서 아래로 읽는다. 가운데 세 카드는 순서대로 실행되는 단계가 아니라 서로 다른 낭비를 다루는 독립 경로다. 아래 결과는 세 기능이 항상 같은 양의 토큰을 절감한다는 뜻이 아니라, 영상이 설명한 공통 목표를 나타낸다.

세 가지 낭비를 어떻게 줄이는가

첫째, 에이전트가 같은 프로젝트에서 작동하지 않는 명령을 반복하면 Token Economizer는 이를 프로젝트에 관한 사실로 정리한다. 영상은 이 사실을 마이크로스킬(MicroSkills)이라고 부른다. 몇 차례의 세션이 사실을 더 확인하면 새 세션 시작 때 에이전트가 미리 읽는다. 목표는 같은 실패를 세션마다 처음부터 다시 배우지 않게 하는 것이다.

둘째, 영상 설명상 어떤 도구가 최소 두 세션에 걸친 메시지 10개 동안 사용되지 않으면 그 프로젝트에서 자동으로 꺼진다. 이는 도구 프로그램을 삭제하는 것이 아니라, 이후 요청에 붙는 도구 문맥에서 제외하는 조치다. 필요한 도구는 복원할 수 있고, 한 번 복원한 도구는 다시 자동으로 꺼지지 않는다고 설명한다.

[경계] 미사용 도구 안내에 관한 자료 차이: 원문 화자는 도구를 사전에 묻지 않고 제외하며 사용자는 빠진 사실도 모를 수 있다고 설명한다. 반면 META는 2026년 11월 2일 확인한 공식 문서가 도구의 동작을 한 줄로 알린다고 전한다. 사전 허락 없이 제외하는 것과 제외 뒤 상태를 알리는 것은 별개의 문제다. 제공 자료만으로 실제 사용 버전이 언제, 어디에, 얼마나 분명하게 안내하는지는 확정할 수 없다.

셋째, 에이전트가 평소보다 오래 같은 문제를 반복하면 별도 모델이 정말 막혔는지 확인한다. 막힌 것으로 판단되면 다른 방법을 한 번 시도하라고 권한다. 방향 전환으로 해결되거나 처음부터 막히지 않았다면 작업을 계속한다. 그래도 계속 막혔을 때만 사용자에게 Escape를 눌러 중단하라고 요청하며, 플러그인이 작업을 직접 종료하지는 않는다.

세션 안의 분기와 다음 세션으로 돌아오는 순환

플러그인은 정해진 시점에 자동 실행되는 훅을 사용한다. 세션 시작 때 저장된 마이크로스킬을 전달하고, 작업 중에는 도구를 사용할 때마다 막힘 여부를 확인한다. 세션이 끝난 뒤에는 새 프로젝트 사실과 미사용 도구 횟수를 기록한다. 이 기록이 다음 세션의 시작 입력을 바꾸면서 순환이 이어진다.

읽는 법: 가운데를 위에서 아래로 따라간다. 오른쪽과 왼쪽의 짧은 복귀선은 막히지 않았거나 방향 전환으로 해결된 경우 다시 작업을 계속한다는 뜻이다. 왼쪽 긴 선은 정상 완료나 일반 종료가 중단 안내 없이 세션 종료로 이어지는 경로다. 계속 막혔을 때만 Escape 요청과 사용자 종료를 거친다. 가장 오른쪽 바깥선은 종료 뒤 기록이 다음 세션 시작으로 실제 연결되는 복귀 경로다.

처음에는 더 비쌀 수 있고, 저장된 사실은 공격 통로가 될 수 있다

Token Economizer는 프로젝트별로 학습하므로 처음 설치했을 때는 줄일 대상을 아직 모른다. 영상은 Microsoft 시험에서 거의 모든 프로젝트가 초기에 플러그인 없는 실행보다 비쌌고, 여섯 번째 작업부터 더 저렴해졌다고 설명한다. 학습과 막힘 확인도 모델과 토큰을 사용하기 때문이다.

마이크로스킬은 설치 직후 기본적으로 꺼져 있다고 설명된다. 기능을 켜면 세 세션마다 모델이 최근 기록을 읽고 프로젝트 사실을 작성해 추가 토큰을 사용한다. 더 큰 문제는 프롬프트 인젝션이다. 다운로드한 프로젝트의 명령 출력에 숨은 지시가 있다면, 그 지시가 마이크로스킬에 프로젝트 사실처럼 저장되어 이후 세션에 반복 전달될 수 있다. 영상은 자신이 소유한 프로젝트에서는 켜라고 권하지만, 이는 화자의 권고다. 소유한 프로젝트라도 명령 출력과 외부 의존성이 자동으로 안전해지는 것은 아니다.

영상 제작 측은 초기 학습 비용을 줄이려고 도구를 직접 수정했다고 말한다. Claude Code가 기본 .claude 폴더에 30일 동안 보관한다는 과거 세션을 읽고, 같은 폴더의 이전 작업을 초기 학습 자료로 사용하게 했다는 것이다. 이는 원래 도구의 기본 기능이 아니라 영상 제작 측이 추가했다고 설명한 수정 사항이다. 과거 기록이 없는 새 프로젝트에는 효과가 없다.

서로 다른 절감 수치를 같은 실험처럼 합치면 안 된다

아래 표는 좌우로 이동해 볼 수 있다.

읽는 법: 각 행을 왼쪽에서 오른쪽으로 읽는다. 23.6%·30.9%는 Microsoft 시험의 모델별 비용 결과이고, 약 29%는 메시지에 붙는 도구 문맥 감소이며, 약 21%는 다른 앱에서 세 작업을 완료한 전체 비용 비교다. 표본과 지표가 다르므로 하나의 연속된 절감률처럼 합치면 안 된다.

전체 통찰과 경계

핵심은 모든 프로젝트 정보를 한 번에 압축하는 것이 아니라, 반복 세션에서 발견된 낭비를 다음 요청의 입력과 현재 작업의 행동에 반영하는 것이다. 따라서 같은 프로젝트를 오래 반복해서 다룰수록 학습 비용을 회수할 가능성이 커지지만, 새 프로젝트나 짧은 일회성 작업에서는 추가 분석 비용이 더 클 수 있다.

문맥이 짧아졌다는 사실만으로 작업 능력이 좋아졌다고 결론 내릴 수도 없다. 필요한 도구까지 제외되면 토큰은 줄어도 작업은 실패할 수 있다. 절감률과 함께 동일한 품질 검사를 통과했는지, 제외된 도구를 확인·복원할 수 있는지, 저장된 마이크로스킬을 검토할 수 있는지를 함께 봐야 한다.

[경계] 자료 안의 이름과 수량: META의 채널과 업로더는 Tech Bridge지만 전사 첫 문장은 AI LABS를 주어로 사용한다. 두 이름의 관계와 원작자는 제공 자료로 확인되지 않는다. 또한 전사는 5개 설정이라고 하면서 Claude Code·Codex·GitHub Copilot이라는 3개 제품군만 열거하므로 정확한 5개 조합은 알 수 없다.

[경계] 초기 비용의 범위: 전사는 Microsoft 시험에서 “거의 모든 프로젝트”가 처음에는 더 비쌌다고 한 뒤, 프로젝트별로 따로 학습하므로 “모든 프로젝트에서” 이런 일이 생긴다고 설명한다. 제공 자료만으로 모든 프로젝트가 실제로 같은 비용 곡선을 보였다고 확정할 수 없다.

[경계] 수치의 지위: 277개 버그·6개 프로젝트·5개 설정과 각 절감률은 화자가 전달한 시험 및 데모 결과다. 제공 자료만으로 원자료, 전체 설정, 독립 재현 여부는 확인되지 않았다.

여기까지만 이해하면 충분

  • Token Economizer는 반복 실수, 미사용 도구, 막힌 작업이라는 세 종류의 낭비를 프로젝트별로 다룬다.
  • 막히지 않았거나 방향 전환으로 해결되면 작업을 계속하며, 계속 막혔을 때만 사용자에게 중단을 요청한다.
  • 처음에는 학습 비용 때문에 더 비쌀 수 있고, 과거 세션을 읽는 기능은 영상 제작 측이 추가했다고 설명한 수정 사항이다.
  • 절감률은 메시지 문맥과 작업 전체 비용을 구분하고, 동일한 품질 검사·도구 복원·마이크로스킬 보안 검토와 함께 판단해야 한다.

비유와 깨지는 지점

작업장의 인수인계 노트와 공구함

마이크로스킬은 교대할 때 넘기는 인수인계 노트, 도구 제외는 잘 쓰지 않는 공구를 작업대에서 치우는 일, 막힘 감지는 같은 수리를 반복하는 작업자에게 다른 방법을 권하는 감독자에 가깝다.

비유가 깨지는 지점: 실제 플러그인은 모델을 사용해 기록을 만들기 때문에 그 과정에도 토큰이 든다. 또한 명령 출력에 숨은 지시까지 사실로 저장할 수 있다. 종이 노트와 공구함보다 자동화된 기록의 신뢰·보안 문제가 훨씬 크다.

1. 원인

Token Economizer가 설치 직후에는 절감하지 못하고 오히려 더 많은 비용을 쓸 수 있는 이유는 무엇인가?

모범 답안 보기

이 도구는 프로젝트별 세션을 관찰한 뒤 반복 실수와 미사용 도구를 학습한다. 처음에는 학습 자료가 없어 줄일 문맥이 없고, 세션 분석에는 별도 모델과 토큰이 필요하다. 따라서 충분한 반복 작업이 있기 전에는 추가 분석 비용이 절감분보다 클 수 있다.

2. 대조

Graft처럼 파일 지도를 미리 만드는 방식과 Token Economizer의 방식은 무엇이 다른가?

모범 답안 보기

영상 설명상 Graft는 작업 전에 프로젝트 파일 지도를 만들어 에이전트의 탐색 비용을 줄인다. Token Economizer는 실제 세션과 명령을 관찰해 반복 실패, 미사용 도구, 막힘을 프로젝트별로 학습한다. 전자는 구조를 미리 정리하는 접근이고 후자는 사용 기록을 바탕으로 다음 세션을 조정하는 접근이다.

3. 적용

AI 코딩 프로젝트에 이 도구를 시험한다면, 토큰 절감 외에 무엇을 함께 확인해야 하는가?

모범 답안 보기

동일한 시작 코드와 작업을 사용하고, 플러그인 켬·끔 모두 같은 품질 검사를 통과했는지 확인해야 한다. 제외된 도구 때문에 기능이 사라지지 않았는지, 마이크로스킬에 잘못되거나 악의적인 지시가 들어가지 않았는지도 검토한다. 새 프로젝트와 반복 프로젝트를 구분하고, 전체 작업 비용을 같은 기준으로 비교해야 한다.

이번 글의 통찰

1. 절감의 핵심은 압축보다 프로젝트별 기억이다

  • [원문] 화자는 매 요청에 지침, 도구 목록, MCP 도구와 스킬, 이전 대화가 함께 전달되며, 반복 실패와 미사용 도구가 토큰을 낭비한다고 설명한다.
  • [해석] 장기 프로젝트에서는 더 많은 정보를 추가하는 것보다 다음 요청에서 필요 없는 정보와 이미 배운 실패를 빼는 편이 중요할 수 있다.
  • [경계] 어떤 정보가 불필요한지는 작업에 따라 달라진다. 필요한 도구까지 제외하면 토큰은 줄어도 성공률은 낮아질 수 있다.

2. 초기 비용을 없앤 것이 아니라 과거 기록으로 앞당겼다

  • [원문] 영상 제작 측은 기본적으로 빈 상태에서 시작하는 도구를 수정해 Claude Code의 .claude 폴더에 30일간 저장된 같은 폴더의 과거 세션을 읽게 했다고 말한다.
  • [해석] 기존 기록을 초기 학습 자료로 재사용하면 오래 운영한 프로젝트에서 손익분기 시점을 앞당길 가능성이 있다.
  • [경계] 이는 영상에서 수정했다고 밝힌 버전의 계획·구현 주장이다. 새 프로젝트에는 기록이 없으며, “모든 프로젝트가 혜택을 받는다”는 표현도 각 프로젝트에 같은 폴더의 과거 기록이 있을 때로 제한해야 한다.

3. 절감률보다 측정 조건과 자동 생성된 기억의 신뢰가 먼저다

  • [원문] 영상은 Microsoft 시험의 23.6%와 30.9%, 데모의 메시지당 약 29%, 다른 앱의 전체 비용 약 21% 절감을 제시한다. 동시에 마이크로스킬의 프롬프트 인젝션 위험을 경고한다.
  • [해석] 비용 지표만 보면 자동화가 좋아 보이지만, 같은 품질 검사와 저장된 사실의 안전성을 함께 보지 않으면 불완전한 평가다.
  • [경계] 수치는 독립 검증되지 않았다. 5개 설정이라고 했지만 Claude Code·Codex·GitHub Copilot이라는 3개 제품군만 열거해 정확한 5개 조합은 알 수 없다. 또한 “거의 모든 프로젝트가 초기에 더 비쌌다”와 “모든 프로젝트에서 이런 일이 생긴다”는 표현의 범위가 달라, 모든 프로젝트의 정확한 비용 곡선을 확정할 수 없다. META의 채널·업로더는 Tech Bridge지만 전사 첫 문장은 AI LABS를 주어로 사용하며, 원작자 후보와 두 이름의 관계는 제공 자료로 확인되지 않는다.

# 섹션 요지
1 접근 방식과 Microsoft 시험 파일 지도 대신 세션 행동을 학습하며, 277개 버그 시험의 절감률을 제시한다.
2 세 가지 절감 장치 반복 실수, 미사용 도구, 막힌 작업을 각각 처리한다.
3 설치와 자동 실행 플러그인 명령과 세션 훅으로 자동 개입한다.
4 마이크로스킬의 비용과 위험 기본 비활성화 이유는 추가 토큰과 프롬프트 인젝션이다.
5 초기 비용과 수정 버전 과거 30일 세션 기록을 읽도록 제작 측이 도구를 수정했다.
6 상태 확인과 두 프로젝트 결과 4세션 데모와 5세션 학습 후 비교 결과를 제시한다.

1. 접근 방식과 Microsoft 시험

영상은 토큰 절약 도구가 이미 많으며 Graft도 그중 하나라고 소개한다. Graft와 비슷한 도구는 작업 전에 프로젝트 파일 지도를 만들어 에이전트가 필요한 파일을 빨리 찾게 한다고 설명한다.

Token Economizer는 파일 지도를 먼저 만드는 대신 세션과 에이전트 명령을 관찰한다. 토큰이 낭비되는 위치를 찾고 이후 세션에서 그 낭비를 줄이는 방식이라고 화자는 설명한다.

Microsoft 시험에 관한 화자의 설명은 다음과 같다.

  • GitHub의 실제 프로젝트 6개
  • 실제 버그 277개
  • 각 프로젝트의 버그를 차례대로 수정
  • Claude Code, Codex, GitHub Copilot에 걸친 5개 설정
  • 모든 설정에서 도구를 사용한 쪽의 비용이 더 낮았다고 주장
  • Claude Code의 Sonnet 5: 23.6% 절감
  • Claude Code의 Opus 4.8: 30.9% 절감

다만 제품군은 3개만 열거되며, 5개 설정의 정확한 조합은 전사에 없다.

2. 세 가지 절감 장치

반복 실수와 마이크로스킬

에이전트는 세션이 바뀌면 이전에 실패한 명령을 다시 시도할 수 있다. Token Economizer는 같은 실수가 여러 번 나타나면 이를 프로젝트 사실로 적는다. 이후 몇 차례의 세션이 사실을 확인하면 해당 프로젝트에 저장하고, 새 세션 시작 때 에이전트에게 제공한다.

미사용 도구 제외

Claude Code는 많은 도구를 매 세션에 싣는다고 설명된다. 특정 도구가 최소 두 세션에 걸친 열 번의 메시지 동안 사용되지 않으면 프로젝트에서 자동으로 꺼진다. 영상은 Microsoft 수치에서 이 기능이 매 요청의 도구 문맥을 줄이므로 가장 많은 토큰을 절약했다고 말한다.

사용자에게 먼저 묻지 않고 도구를 끄므로 제외 목록을 확인할 필요가 있다. 필요한 도구는 복원할 수 있고, 한 번 복원한 도구는 다시 자동으로 꺼지지 않는다고 설명한다.

막힌 작업 감지

작업이 해당 프로젝트의 평소 응답보다 오래 계속되면 모델이 실제로 막혔는지 검사한다. 막혔다고 판단되면 다른 방법을 한 번 시도하라고 알린다. 그래도 막혀 있으면 사용자에게 Escape를 눌러 중단하라고 한다. 플러그인이 직접 종료하지는 않는다.

3. 설치와 자동 실행

Token Economizer는 Claude Code, Codex와 몇몇 AI 에이전트에서 사용할 수 있는 플러그인이라고 소개된다. 공식 저장소의 설치 구역에서 사용하는 에이전트에 맞는 명령을 복사해 터미널에서 실행하는 방식이다.

Claude Code에서는 플러그인 명령으로 목록을 확인할 수 있으며, 다음 훅이 자동으로 실행된다고 설명한다.

  • 세션 시작: 저장된 마이크로스킬 전달
  • 작업 중 도구 사용 뒤: 막힘 여부 확인
  • 세션 종료 뒤: 세션을 분석해 새 사실과 미사용 도구 횟수 기록

4. 마이크로스킬의 비용과 위험

설치 뒤 설정 명령을 실행하면 대부분의 기능은 켜져 있지만 마이크로스킬은 기본적으로 꺼져 있다고 설명한다.

첫 번째 이유는 토큰 비용이다. 기능을 켜면 세 세션마다 모델이 최근 세션을 읽고 프로젝트 사실을 작성하며, 이 과정이 사용자의 토큰 한도를 사용한다.

두 번째 이유는 안전이다. 프로젝트 명령의 출력에 숨은 지시가 있으면 그 지시가 프로젝트 사실에 들어갈 수 있다. 이후 Claude가 매 세션 시작 때 이를 사실로 읽을 수 있다. 영상은 이를 프롬프트 인젝션이라고 설명한다.

화자는 자신이 소유한 프로젝트에서는 Microsoft 시험에서 많은 토큰을 절약한 기능이므로 켜라고 권한다. 다만 이는 화자의 권고이며, 제공 자료에는 생성된 사실을 안전하게 검증하는 별도 절차가 제시되지 않는다.

5. 초기 비용과 수정 버전

도구는 설치 직후 프로젝트에 관해 아는 것이 없다. 기존에 오래 작업한 프로젝트라도 설치 이전 기록을 기본적으로 배우지 못하므로 처음부터 관찰해야 한다고 설명한다.

Microsoft 시험에 관한 영상의 추가 설명은 다음과 같다.

  • 거의 모든 프로젝트가 처음에는 플러그인 사용 시 더 비쌌다.
  • 여섯 번째 작업이 되어서야 더 저렴해졌다.
  • 프로젝트별로 따로 배우며 다른 프로젝트로 학습 내용이 넘어가지 않는다.

이어 화자는 Claude Code가 기본 .claude 폴더에 모든 세션을 30일 동안 보관한다고 말한다. 영상 제작 측은 저장소를 Claude Code에 제공하고, 시작할 때 같은 폴더의 과거 세션을 읽도록 도구를 수정해 달라고 요청했다고 설명한다.

수정 버전은 설치 후 첫 세션에서 백그라운드 작업을 시작해 이전 세션을 읽고, 그 결과를 빈 상태 대신 초기값으로 사용한다고 한다. 전체 설치로 설정되지 않았다면 Claude에게 모든 곳에서 사용하도록 다시 변경해 달라고 요청하라고 안내한다.

과거 기록이 없는 새 프로젝트에는 아무 효과가 없다. 또한 “모든 프로젝트”라는 표현은 각 프로젝트에 읽을 수 있는 이전 기록이 있을 때만 성립한다.

6. 상태 확인과 두 프로젝트 결과

영상은 다음 명령의 역할을 설명한다.

  • status 명령: 학습한 세션 수, 해당 세션의 토큰, 각 기능의 동작 현황 확인
  • MicroSkills 명령: 세션 시작 때 전달하는 사실과 아직 확인 중인 사실 확인
  • tool prune 명령: 제외된 도구와 사용되지 않은 세션·메시지 수 확인
  • tool prune measure 명령: 전체 도구 문맥과 실제 사용하는 도구만 남긴 문맥의 토큰 비교
  • tool prune restore 명령: 지정한 도구 복원

첫 번째 데모 프로젝트에서는 다음 결과를 제시한다.

  • 과거 세션 4개 학습
  • 막힘 감지는 개입하지 않음
  • 세션 4개에서 도구 276개가 모두 미사용 상태
  • 메시지당 약 34,300토큰에서 약 24,400토큰으로 감소
  • 약 29% 절감

두 번째 앱에서는 먼저 플러그인을 켜고 세션 5개를 실행했다. 이 과정에서 도구 303개를 껐다. 이후 새 작업 3개를 플러그인 켬·끔으로 각각 실행했으며, 두 실행은 같은 코드에서 시작했다고 설명한다.

  • 플러그인 없음: 세 작업 완료에 99단계
  • 플러그인 있음: 세 작업 완료에 79단계
  • 전체 비용: 약 21% 절감
  • 두 버전 모두 같은 검사를 통과했다고 주장
  • 첫 학습 세션에서는 플러그인 사용 쪽이 조금 더 비쌌음
  • 이후 세션에서 절감이 나타났다고 설명

작업 3개를 플러그인 켬·끔으로 각각 1회씩 실행해 총 6회 비교했다는 점은 제시되지만, 검사의 구체적 종류와 추가 반복 시험 및 결과의 분산은 전사에 제시되지 않았다.

전체 전사 펼치기

클로드 코드의 사용량 제한은 왜 이렇게 빨리 닳을까요? AI LABS는 마이크로소프트의 토큰 이코노마이저가 반복 실수와 쓰지 않는 도구를 줄이는 방식을 소개합니다. 또 기존 대화 기록을 활용하도록 도구를 직접 수정해 실제 테스트에서 어떤 차이가 났는지 보여줍니다. 처음에는 오히려 비용이 늘 수 있다는데요. 설치와 설정 방법부터 그 이유, 그리고 주의할 보안 문제까지 함께 살펴보겠습니다.

토큰을 절약해 주는 도구가 이미 많다고 생각할 수도 있습니다. 저희 채널에서도 몇 가지를 다뤘고, Graft도 그중 하나입니다. 그렇다면 또 다른 도구가 왜 필요할까요? Graft와 다른 많은 도구는 작업을 시작하기 전에 프로젝트의 모든 파일을 지도처럼 정리합니다. 그래서 에이전트가 무언가를 필요로 할 때 토큰을 낭비하며 찾지 않고 바로 찾아낼 수 있습니다.

하지만 Token Economizer는 조금 다르게 작동합니다. 지도를 만드는 대신, 사용자의 작업 방식을 학습합니다. 모든 세션과 그 안에서 에이전트가 실행하는 명령을 지켜보면서 토큰이 어디에서 낭비되는지 추적합니다. 그리고 이후 세션에서 그 낭비를 줄입니다. 이제 Microsoft는 자체 테스트 결과와 그 근거가 되는 데이터도 모두 공개했습니다. GitHub의 실제 프로젝트 6개에서 실제 버그 277개를 에이전트에게 수정하게 했습니다.

그리고 각 프로젝트의 버그를 차례로 수정하게 했습니다. Claude Code, Codex, GitHub Copilot에서 5가지 설정으로 테스트했습니다. 모든 설정에서 이 도구를 사용했을 때 작업 비용이 사용하지 않았을 때보다 낮았습니다. Claude Code에서는 Sonnet 5의 비용이 23.6% 줄었고, Opus 4.8은 30.9% 줄었습니다. 하지만 Token Economizer를 설치하기 전에, 이 도구가 실제로 어떻게 작동하는지 알아보겠습니다.

이 도구가 토큰 사용량을 어떻게 줄이는지 보려면, 먼저 실제로 무엇이 토큰을 소모하는지 이해해야 합니다. 에이전트에게 메시지를 보낼 때마다 에이전트는 답변을 생성하는 모델에 요청을 보냅니다. 하지만 사용자의 프롬프트만 모델에 보내는 것은 아닙니다. 모델은 스스로 무언가를 기억하지 못하기 때문에 프로젝트의 모든 내용에 관한 추가 컨텍스트도 보내야 합니다. 따라서 모든 요청에는 에이전트가 항상 따르는 지침과 프로젝트 작업에 사용할 수 있는 모든 도구의 목록이 포함됩니다.

추가한 MCP 도구와 스킬(skill), 그리고 그 시점까지의 전체 대화도 포함됩니다. 하지만 같은 프로젝트에서 계속 작업하면 모델에 전송되는 컨텍스트 중 상당 부분은 모델에게 실제로 필요하지 않은 내용입니다. 이 모든 내용이 컨텍스트에 남아 토큰을 낭비합니다. 에이전트는 실수 때문에도 토큰을 낭비합니다.

한 세션에서 실수를 수정해도, 다음번에 같은 프로젝트에서 실행하면 그 실수를 저지르며 다시 같은 내용을 학습해야 합니다. 게다가 실제로 사용하지 않는 도구까지 계속 가지고 다닙니다. Token Economizer는 에이전트가 토큰을 낭비하는 이런 지점을 찾아냅니다.

이 도구는 해당 프로젝트에서 열었던 세션을 지켜보며 세 가지를 처리합니다. 첫 번째는 프로젝트에서 Claude가 계속 반복하는 실수입니다. 예를 들어 작동하지 않는 도구나 명령을 실행하는 경우입니다. Claude는 세션이 바뀌면 무엇이 작동했고 무엇이 작동하지 않았는지를 기억하지 못합니다. 그래서 작동하지 않았던 같은 명령을 매번 시도하고, 같은 실수를 수정하느라 토큰을 사용합니다. 이 부분을 도구가 도와줍니다. 이런 실수를 감시하는 것입니다.

Claude가 같은 실수를 여러 번 하는 것을 확인하면, 도구는 이를 프로젝트에 관한 사실로 기록합니다. 이러한 사실을 마이크로 스킬(MicroSkills)이라고 부릅니다.

몇 개의 세션에서 해당 사실이 맞다는 것이 추가로 확인되면, 도구는 이를 해당 프로젝트에 저장합니다. 새 세션을 시작할 때마다 에이전트에게 해당 정보를 작업에 관한 사실로 이미 알고 있는 내용처럼 전달합니다. 그러면 에이전트는 이것이 이전에 작동하지 않았다는 사실을 이미 알고 있으므로 다시 시도하지 않습니다. 두 번째는 사용하지 않는 도구입니다. Claude Code는 모든 세션에 많은 도구를 불러옵니다. 최소 두 세션에 걸쳐 메시지 10개를 보내는 동안 그중 하나가 사용되지 않으면, 도구가 해당 프로젝트에서 그 도구를 끕니다.

그렇게 하면 모든 메시지와 함께 해당 도구가 계속 전송되는 것을 막을 수 있습니다. Microsoft의 자체 수치에 따르면 이 기능이 토큰을 가장 많이 절약합니다. 각 턴마다 전송되는 도구의 수를 줄이기 때문입니다. 하지만 사용자에게 묻지 않고 처리하므로, 어떤 도구가 컨텍스트 창에서 빠졌는지도 알 수 없습니다. 다만 꺼진 도구를 보여 주는 명령이 있으며, 영상 후반에 그 명령을 보여 드리겠습니다. 세 번째는 Claude가 막히는 경우입니다. 에이전트가 작업을 하다가 방법을 찾지 못해 작동하지 않는 방법을 계속 시도하는 경우가 있습니다.

그리고 때로는 해당 프로젝트에서 Claude가 메시지 하나에 답하는 데 보통 걸리는 시간보다 훨씬 오래 계속 작업하기도 합니다. 도구가 이런 상황을 감지하면, Claude가 정말 막힌 것인지 모델에 확인을 요청합니다.

정말 막힌 경우에만 도구가 Claude에게 한 번 다른 방법을 시도하라고 알립니다. 그래야 반복되는 루프에 계속 갇히지 않습니다. 그 후에도 Claude가 계속 막혀 있으면 도구가 사용자에게 Escape를 눌러 중지하라고 알립니다. Claude를 스스로 중지하는 일은 절대 없습니다. 이제 이 도구는 Claude Code, Codex 및 몇 가지 다른 AI 에이전트에서 사용할 수 있는 플러그인입니다. 이 도구를 설치하려면 GitHub 저장소로 이동해 설치 섹션까지 아래로 스크롤하면 됩니다.

모든 에이전트의 설치 명령이 그곳에 나와 있으므로, 사용 중인 에이전트에 해당하는 명령을 복사해 터미널에 붙여 넣기만 하면 설치됩니다. Claude Code를 열고 플러그인 명령을 실행하면 목록에 Token Economizer가 표시됩니다. 이 도구는 몇 가지 명령과 훅(hook)을 추가합니다. 훅은 세션이 시작될 때나 메시지를 보낼 때처럼 정해진 시점에 자동으로 실행됩니다. 이러한 훅이 앞서 설명한 세 가지 기능을 사용자가 아무것도 하지 않아도 플러그인이 실행하도록 합니다.

앞서 이야기한 마이크로 스킬은 모든 세션 시작 시 실행되는 훅을 통해 Claude에 전달됩니다. 따라서 Claude는 해당 프로젝트에 관한 모든 사실을 이미 갖게 됩니다. Claude가 프롬프트를 처리하는 동안에는 또 다른 훅이 Claude가 사용하는 각 도구를 실행한 뒤 상태를 확인합니다. 이를 통해 플러그인은 Claude가 언제 막혔고 도움이 필요한지 알 수 있습니다.

세션이 끝나면 플러그인은 세션에서 일어난 모든 일을 자동으로 되돌아봅니다. 이 과정에서 다음번에 사용할 새로운 사실을 학습하고, 한 번도 사용되지 않은 도구의 횟수를 계속 집계합니다. 이제 이 도구를 설치하고 config 명령을 실행하면 대부분의 기능은 켜져 있지만, 처음 설치할 때 MicroSkills는 꺼져 있는 것을 볼 수 있습니다. MicroSkills가 꺼져 있는 이유는 두 가지입니다.

첫 번째 이유는 토큰 한도를 절약하기 위해서입니다. 이 기능을 켜면 세 세션마다 모델에 최근 세션을 읽고 사실을 작성하도록 요청하는데, 이 과정에서 사용자의 토큰 한도를 일부 사용합니다. 두 번째 이유는 안전입니다.

도구가 작성하는 사실은 프로젝트의 명령이 출력하는 내용에서 가져오며, Claude는 모든 세션의 시작 시 이를 프로젝트에 관한 사실인 것처럼 읽습니다.

따라서 다른 사람이 만든 프로젝트를 다운로드하면, 제작자가 명령 출력 내용에 지침을 숨길 수 있습니다. 그러한 지침은 사실에 포함되고, 사용자가 직접 변경하지 않는 한 Claude는 모든 세션에서 이를 사실로 취급하게 됩니다. 이는 기본적으로 프롬프트 인젝션(prompt injection)으로 알려진 공격입니다. 그래서 Microsoft는 선택권을 사용자에게 맡깁니다.

하지만 자신의 프로젝트에서는 이 기능을 켜는 것이 좋습니다. Microsoft의 테스트에서 토큰을 많이 절약한 기능이 바로 이 기능이었기 때문입니다. 따라서 MicroSkills를 켜려면 TokenEconomizer config 명령을 실행하고 MicroSkills를 on으로 설정해야 합니다. 그러면 이 기능을 사용할 수 있습니다. 하지만 MicroSkills를 켜도 이 도구에는 한 가지 문제가 있습니다. 앞서 말했듯이 이 도구는 사용자가 에이전트를 사용하는 방식에서 학습합니다. 따라서 처음 설치했을 때는 아직 아무것도 학습하지 않은 상태이므로 처음에는 아무것도 절약해 주지 못합니다.

먼저 결과를 보려면 같은 프로젝트에서 한동안 사용해야 합니다. 이미 오랫동안 작업해 온 프로젝트도 마찬가지입니다. 지금 설치하면 학습할 내용이 전혀 없기 때문입니다.

따라서 효과가 나타날 때까지 기다려야 하며, 학습하는 동안에는 처음에 오히려 비용이 더 들 수도 있습니다.
