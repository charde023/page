먼저 읽는 쉬운 요약

처음 보는 사람을 위한 읽기 안내

영상 미시청 기준 · 약 2분 · 선수지식: 없음 이 부분만 읽어도 아래 중심 질문에 자기 말로 답할 수 있게 설명한다.

이 영상은 Claude 채팅과 Co-work가 같은 ‘공용 메모장’을 쓰게 됐다는 소개다. 화자에 따르면 새 시스템은 대화가 끝난 뒤 전체 내용을 요약하는 대신, 대화 도중 기억할 내용을 주제별로 추가한다. 사용자는 저장된 항목을 파일처럼 확인하고 고치거나 지울 수 있으며, 민감한 주제는 기본적으로 저장하지 않되 설정으로 허용할 수 있다고 한다. 덕분에 한쪽에서 알려 준 선호나 업무 맥락을 다른 쪽에서 다시 설명하지 않고 이어 쓸 수 있다. 다만 공유 메모리는 Co-work를 클라우드에서 실행할 때만 작동하며, 로컬 실행과 Claude Code는 포함되지 않는다. 영상의 왕복 시연은 작동 사례를 보여주지만 모든 계정과 상황에서의 정확성을 검증한 결과는 아니다.

여기까지만 이해하면 충분

  • 채팅과 Co-work가 하나의 메모리를 공유하면 같은 맥락을 반복해서 설명하는 일을 줄일 수 있다.
  • 저장된 기억은 주제별로 확인·수정·삭제할 수 있다고 화자는 설명한다.
  • 공유 범위는 클라우드에서 실행하는 Co-work와 채팅이며, 로컬 Co-work와 Claude Code는 제외된다.

비유와 깨지는 지점

두 작업실 사이의 공용 메모장

채팅과 Co-work를 서로 다른 작업실이라고 보면, 공유 메모리는 두 방에서 함께 보는 공용 메모장과 비슷하다. 한쪽에서 항목을 추가하거나 고치면 다른 쪽에서도 같은 내용을 참고할 수 있다.

비유가 깨지는 지점: 종이 메모장은 사람이 직접 기록할 내용을 정하지만, 이 시스템은 화자의 설명상 대화 중 무엇을 저장할지 자동으로 판단한다. 또한 실제 공유는 Co-work의 클라우드 실행이라는 기술 조건에 묶여 있다.

1. 원인

공유 메모리가 반복 설명을 줄일 수 있는 이유는 무엇인가?

모범 답안 보기

채팅과 Co-work가 같은 주제별 메모리를 참고하기 때문이다. 한쪽에서 저장된 선호나 프로젝트 맥락을 다른 쪽이 불러올 수 있으므로, 사용자가 같은 내용을 처음부터 다시 입력할 필요가 줄어든다. 단, Co-work에서는 클라우드 실행 조건이 붙는다.

2. 대조

공유 메모리와 대화 기록 전체는 어떻게 다른가?

모범 답안 보기

영상에서 설명한 메모리는 대화 전체를 그대로 보여주는 기록이 아니라, 필요한 내용을 주제별 항목으로 정리해 재사용하는 구조다. 사용자가 항목을 고치거나 삭제할 수 있지만, 무엇을 자동으로 선택하고 얼마나 정확히 정리하는지는 별도 검증이 필요하다.

3. 적용

업무용 AI에 이 기능을 적용하기 전에 무엇을 확인해야 하는가?

모범 답안 보기

먼저 사용하는 환경이 채팅과 클라우드 Co-work인지 확인한다. 그다음 비민감한 시험 항목을 양쪽에서 저장·수정·조회해 왕복 동기화와 정확성을 측정한다. 민감 정보는 저장 필요성, 삭제 가능성, 접근 범위를 따로 검토해야 한다.

이번 글의 통찰

1. 메모리의 가치는 저장량보다 재사용 범위에서 나온다

  • [원문] 화자는 채팅과 Co-work가 하나의 메모리를 공유해 이전 맥락을 이어 쓸 수 있다고 설명하고, 양방향 조회를 시연한다.
  • [해석] 기억을 많이 쌓는 것보다 필요한 환경에서 정확히 다시 꺼낼 수 있는지가 반복 설명 감소를 결정한다.
  • [경계] 영상의 의류 선호 왕복 시연은 한 사례다. 장기 정확성, 누락률, 잘못 저장된 기억의 빈도는 제시되지 않았다.

2. 사용자 편집은 통제 수단이지만 자동 정확성을 보장하지 않는다

  • [원문] 화자는 저장된 메모리를 주제별로 보고 수정하거나 삭제할 수 있으며, 민감 주제 저장 여부도 설정할 수 있다고 말한다.
  • [해석] AI 기억은 숨겨진 내부 상태보다 사용자가 검사하고 교정할 수 있는 기록일 때 관리하기 쉽다.
  • [경계] 화자는 민감 주제를 개인적으로 켰지만 이는 개인 선택이다. 개인정보 보호·보안 수준에 대한 독립적인 근거나 검증 결과는 제시되지 않았다.

3. 제품 소개 문구와 실제 적용 조건을 분리해야 한다

  • [원문] 화자는 Free·Pro·Max 요금제의 웹·데스크톱·모바일에서 기본 제공된다고 말하면서도, Co-work의 공유 메모리는 클라우드 실행에서만 작동하며 Claude Code와는 연동되지 않는다고 설명한다.
  • [해석] ‘어디서나 작동한다’는 큰 문구보다 제품 조합, 실행 위치, 설정 상태를 확인해야 실제 사용 범위를 알 수 있다.
  • [경계] 전사는 메모리 화면의 핵심 주제를 먼저 “a couple”이라고 표현한 뒤 profile, preferences, meal planning, client pitching, half-marathon training의 5개 이름을 제시한다. 표현상 개수와 실제 열거가 일치하지 않는다. 또한 기본 제공 주장과 설정 저장 화면의 관계, 기존 채팅 메모리의 전환 방식은 명확히 설명되지 않았다. Claude Code 연동이 향후 몇 주나 몇 달 안에 나올 것이라는 말은 화자도 추측이라고 밝혔다. META의 original_affiliation 후보인 Bit 역시 화자 이름과 SNS를 근거로 한 추정이며, 원본 영상 링크와 원작자 이름은 확인되지 않았다.

  • 질문/행동: 학습자가 이전 설명을 새 사례에서 정확히 재사용하는지 확인한다.

사업가 · 구조적 비유

  • 관련성: 반복 설명 감소는 시간 절약과 인수인계 품질이라는 자원 가치에 연결될 수 있다.
  • 통찰: APOM의 현재 시스템 상태는 출처에 없으므로 직접 적용 사실로 볼 수 없다. 업무 맥락을 공유 메모리로 넘기는 방식은 검증 전 가상 적용으로만 시험할 수 있다.
  • 질문/행동: 비민감한 가상 업무 정보 하나가 채팅과 클라우드 Co-work 사이에서 정확히 왕복하는지 먼저 확인한다.

마케터 · 직접 전이

  • 관련성: 영상은 ‘어디서나 작동’이라는 큰 주장 뒤에 클라우드 전용, Claude Code 미지원이라는 조건을 제시한다.
  • 통찰: 기능 카피는 편의만 강조하지 말고 지원 환경과 제외 범위를 함께 보여줘야 과장을 줄일 수 있다.
  • 질문/행동: 기능을 소개할 때 주장 옆에 지원 제품, 실행 위치, 실제 시연 결과를 붙인다.

AI/SW 학습자 · 직접 전이

  • 관련성: 이 사례는 에이전트의 기억 저장, 동기화, 실행 환경, 예외 조건을 함께 점검하게 한다.
  • 통찰: 기술 이름보다 저장·수정·조회가 어느 실행 환경에서 성공하는지를 왕복 테스트해야 한다.
  • 질문/행동: 채팅→Co-work와 Co-work→채팅을 각각 시험하고 로컬 실행을 별도 실패 조건으로 확인한다.

1. 공유 메모리 발표

화자는 기존 Co-work의 약점으로 지속적인 기억 부족을 들었다. 새 시스템에서는 채팅에서 사용하는 메모리와 Co-work의 메모리가 같아져, 이전 대화에서 쌓인 사용자 정보나 프로젝트 맥락을 Co-work 작업에서도 이어 쓸 수 있다고 설명했다.

기사의 핵심 문구로 “Claude의 메모리는 어디서나 작동하며, 무엇을 넣을지는 사용자가 결정한다”는 취지의 문장을 소개했다. 다만 뒤에서 Co-work의 로컬 실행은 제외된다고 밝혀 ‘어디서나’에는 실행 조건이 붙는다.

2. 저장 방식과 사용자 제어

화자에 따르면 새 방식은 대화가 끝난 뒤 전체 내용을 요약하는 대신 대화 중 필요한 내용을 주제별 메모리에 추가한다. 사용자가 매번 “기억해 줘”라고 말하지 않아도 자동으로 저장할 수 있다고 설명했지만, 선택 기준과 정확성 수치는 제시하지 않았다.

저장된 메모리는 파일처럼 확인하고 수정하거나 삭제할 수 있다고 소개했다. 건강이나 신념처럼 민감하다고 여겨지는 주제는 기본적으로 저장하지 않으며, 사용자가 설정에서 허용할 수 있다고 설명했다.

화자는 예시 화면을 설명하면서 먼저 핵심 주제가 “a couple”이라고 말했지만, 이어서 profile, preferences, meal planning, client pitching, half-marathon training의 5개 이름을 제시했다. 따라서 표현된 개수와 열거된 이름 수가 일치하지 않는다.

3. 지원 범위와 제외 대상

화자는 이 기능이 Free·Pro·Max 요금제의 웹·데스크톱·모바일에서 기본 제공된다고 주장했다. 그러나 영상에는 선호를 저장하거나 나중으로 미루는 화면도 등장하므로, 기본 활성화되는 범위와 사용자가 선택해야 하는 민감 주제 설정은 구분해서 볼 필요가 있다.

현재 공유 대상은 Co-work와 채팅이라고 설명했다. Claude Code와 공유하는 방법은 없으며, 향후 몇 주나 몇 달 안에 제공될 수 있다는 전망은 화자 자신의 추측이라고 명시했다.

4. 설정과 메모리 편집 시연

화자는 Claude 계정의 프로필에서 Settings로 들어가 플러그인 아래의 Memory 메뉴를 선택하는 경로를 보여줬다. 기존 메모리는 당시 채팅에서 만들어진 것이라고 설명했다.

화면에는 ChatGPT나 Gemini 같은 다른 AI 제공자의 메모리를 가져오는 메뉴가 있었다고 소개했다. 메모리는 preferences, profile과 여러 주제로 나뉘었으며, 화자의 사업 파트너 Aiden도 자주 언급한 사람으로 저장돼 있었다고 말했다.

의류 항목에는 박시하지 않은 남성용 후드, 늘어난 손목과 허리 시보리를 피하려는 선호가 저장돼 있었다. 화자가 셔츠의 팔 부분은 더 넉넉하게, 길이는 너무 길지 않게, 면 소재를 더 선호한다고 입력하자 해당 내용이 메모리에 추가되는 장면을 보여줬다.

5. 클라우드 조건과 왕복 시험

Co-work 작업은 클라우드 또는 사용자 컴퓨터에서 실행할 수 있다고 설명했다. 클라우드 실행은 앱이나 컴퓨터를 닫아도 계속되지만, 로컬 실행은 컴퓨터가 켜져 있을 때만 작동한다고 화자는 말했다.

공유 메모리는 클라우드 Co-work에서만 작동한다고 강조했다. 클라우드 작업에서도 로컬 컴퓨터의 폴더를 선택할 수 있다고 시연했지만, 폴더 접근과 메모리 실행 위치는 같은 개념이 아니다.

화자는 채팅에서 저장한 셔츠 선호를 클라우드 Co-work가 불러오는 장면을 보여줬다. 이어 Co-work에서 바지를 약간 넉넉하게 입는다는 선호를 저장한 뒤 채팅에 질문해 같은 내용을 가져오는 양방향 시연을 했다. 휴대전화에서도 저장된 메모리를 볼 수 있을 것이라고 말했지만, 전사에는 휴대전화 화면에서 직접 확인한 결과가 포함되지 않았다.

제가 함께 일하거나 자주 언급하는 사람들도 포함되어 있습니다. 여기 보이는 Aiden은 제 사업 파트너인데, Claude가 그를 기억하고 있습니다.

이 중 하나를 클릭해서 어떤 모습인지 보여드리겠습니다. Clothing을 클릭하면 매우 단순한 메모리가 나옵니다. 제가 좋아하는 특정 후드티 핏이 표시되고, 저에 관한 세부 사항과 제가 좋아하는 남성용 후드티 유형까지 나옵니다.

예를 들어 제가 박시하지 않은 남성용 후드티만 원한다는 내용이 표시되는 것이 꽤 재미있습니다. 비싼 후드티를 샀는데 손목 시보리와 허리 시보리가 늘어나 있었다고 제가 불평했던 내용까지 기억하고 있으며, 그런 일이 다시 일어나지 않기를 원한다는 점도 기억합니다.

이 메모리를 바꾸고 싶다고 해 보죠. 여기에서 “셔츠에 관해서도 언급하고 싶은데, 요즘은 소매 부분이 조금 더 오버사이즈인 스타일을 정말 좋아합니다. 하지만 너무 길지는 않았으면 좋겠습니다. 그리고 면 소재를 더 선호합니다”라고 말할 수 있습니다.

그냥 생각나는 내용을 쭉 입력한 다음 Send를 클릭하겠습니다. 그러면 Claude가 이 정보를 해당 메모리 파일에 맞게 정리합니다. 이렇게 하자 메모리 가장 아래에 제가 셔츠를 어떤 스타일로 좋아하는지에 관한 내용이 추가되었습니다.

여기서 꼭 이야기해야 할 정말 중요한 내용이 하나 있습니다. 바로 이 모든 메모리가 이곳을 제외한 모든 곳에 저장된다는 점입니다.

이 새로운 메모리 시스템을 켜면 Claude Co-work와 채팅 모드에서 작동하지만, 클라우드에서 실행할 때만 작동합니다. Claude Co-work를 컴퓨터에서 로컬로 실행한다면 동일한 공유 메모리 시스템을 사용할 수 없습니다.

컴퓨터에서 로컬로 작동하는 것과 클라우드에서 작동하는 것의 차이를 완전히 이해하지 못했을 수도 있으니, 좀 더 설명하겠습니다.

여기 Claude Co-work로 돌아오면 오른쪽 맨 위에 작은 데스크톱 아이콘이 보입니다. 이것을 클릭하겠습니다.

이 작업을 실행하는 방법은 두 가지입니다. 클라우드에서 실행할 수도 있습니다. 이 기능은 베타 버전이며, 컴퓨터에서 앱을 닫거나 컴퓨터를 종료해도 모든 작업이 계속 진행됩니다. 또는 컴퓨터에서 직접 실행할 수도 있습니다.

컴퓨터에서 실행하면 컴퓨터가 켜져 있을 때만 작동합니다. 따라서 Claude Co-work와 채팅 모드 사이에서 공유 메모리를 사용하려면 클라우드에서 실행해야 합니다. 그렇지 않으면 작동하지 않습니다.

그렇다고 큰 문제는 아닙니다. 지금 보시는 것처럼 저는 이 작업을 클라우드에서 실행하고 있지만, 여전히 컴퓨터에 있는 여러 폴더를 선택할 수 있습니다.

예를 들어, 로컬 데스크톱에 있는 YouTube 동영상 프로젝트와 폴더를 선택해 보겠습니다. 여기 와서 “저는 어떤 셔츠를 선호하나요?”라고 물어볼 수 있습니다. YouTube 동영상과는 전혀 상관없는 내용인 건 알지만, 일단 전송해 보겠습니다.

그러면 앞서 Claude 채팅 모드(Claude chat mode)에서 저장한 메모리가 연동되어 Co-work 안에서도 액세스할 수 있다는 것을 보여줄 겁니다.

이렇게 메모리를 검색하고 있습니다. 의류 관련 메모리를 불러오고 있네요. 그리고 정확히 이런 내용을 찾았습니다. 소매 부분은 조금 더 오버사이즈이고, 길이는 너무 길지 않으며, 원단은 면 함량이 더 높은 것을 선호한다는 내용입니다. 앞서 제가 저장한 메모리와 정확히 일치합니다.

이번에는 Co-work 쪽에서 테스트해 보겠습니다. 메모리를 하나 생성하게 한 다음, 이 내용이 채팅 모드로도 연동되는지 확인해 보죠.

제 바지는 요즘 약간 오버사이즈인 스타일이 마음에 듭니다. 이것도 메모리에 저장해 줄 수 있나요?

자, 여기 보시면 메모리에 추가했다고 나옵니다. 메모리를 클릭하면 제가 바지를 어떻게 입는 것을 좋아하는지에 관한 세부 내용도 추가된 것을 확인할 수 있습니다.

다시 채팅 모드로 돌아와서 “제가 바지를 어떻게 스타일링하는 것을 좋아하는지 알고 있나요?”라고 물어보겠습니다.

자, 메모리 파일에서 바로 가져왔습니다. 이 내용은 Claude Co-work와 채팅 모드 사이에서 동기화되고 있습니다. 다시 말씀드리지만, 이 기능은 클라우드에서 실행되고 있어야 합니다.

지금 보시는 것처럼 이 메모리를 데스크톱 앱 안에 저장할 뿐만 아니라, 휴대폰을 꺼내 보면 휴대폰에도 이 메모리가 저장되어 있을 겁니다.

아무튼 여러분, 이상입니다.
