Meta 스태프 소프트웨어 엔지니어는 왜 Claude Code에 푹 빠졌을까요?

한 줄 요약

Claude Code 중독은 단순히 코드를 빨리 쓰기 위한 것이 아니라, 에이전트를 관리하는 새로운 일의 형태를 미리 체험하는 것이다.

핵심 학습 포인트 (내가 배워야 할 것)

개념 왜 중요한가 한 줄
에이전트 저글링 (Agentic Flow) 여러 Claude Code 세션을 동시에 조율하는 것이 미래 엔지니어의 핵심 기술 스타크래프트 매크로·마이크로처럼 컨텍스트와 세션을 동시에 관리
Plan Mode 활용 AI 코딩에서도 학습이 가능한 방식 — 코드를 짜는 시간보다 읽고 이해하는 시간을 늘린다 실행보다 계획·독해에 더 많은 시간을 쓰면 성장이 유지된다
에이전틱 하네스 (Agentic Harness) 검증 루프·자기 수정 루프를 갖춘 시스템 구축이 진짜 레버리지 에이전트가 버그를 직접 고치게 하면 토큰 비용은 높아지지만 산출물 품질도 높아진다
컨텍스트 엔지니어링 AI가 틀린 게 아니라 컨텍스트가 부족한 것 — 하네스와 검증 루프가 해결책 "AI가 멍청하다"는 말은 대부분 컨텍스트·하네스 부재의 신호
AI-ready 코드베이스 에이전트가 스스로 일할 수 있게 텔레메트리·피드백 루프·관찰 레이어를 설계 미래에는 코드베이스 자체가 에이전트 친화적으로 설계되어야 한다
Jensen 토큰 사고 실험 시니어 엔지니어의 보이지 않는 작업량 = 더 많은 토큰 소비 → 토큰 ≈ 레버리지 $500K 엔지니어는 $250K 이상 토큰을 써야 한다는 주장의 논리

내가 모를 만한 것 / 처음 보는 것

  • Agentic Engineering — 에이전트(AI)를 위한 시스템·하네스·피드백 루프를 설계하는 엔지니어링 분야. 단순 프롬프트 작성과 다름.
  • Harness (하네스) — 에이전트의 실행 환경 및 검증 루프 구조체. 에이전트가 스스로 출력을 검증·수정하도록 감싸는 틀.
  • Compound Engineering — 에이전트 여러 개를 체계적으로 조합해 복리적으로 산출물을 쌓아가는 방식.
  • OpenCode — 오픈소스 AI 코딩 CLI 도구. Claude Code, Cursor 등과 같은 계열.
  • Codex (OpenAI) — OpenAI의 코드 에이전트. 화자는 PR 리뷰 "세컨드 오피니언"으로 사용.
  • Comfy UI — 이미지·오디오·비디오 생성을 위한 노드 기반 로컬 워크플로우 도구.
  • Suno — AI 오디오/음악 생성 도구.
  • VO3 — 구글의 비디오 생성 모델.
  • Gemma 4 — 구글의 로컬 실행 가능한 오픈 LLM. 화자는 OpenCode + Gemma 4로 로컬 크론잡에 활용.
  • Observable Layer (관찰 레이어) — 에이전트가 수행한 작업을 추적·모니터링할 수 있는 텔레메트리 계층. AI-ready 코드베이스의 핵심 요소.
  • Andrej Karpathy의 "Skill Issue" — Karpathy가 AI 도구 불만의 상당 부분을 도구 탓이 아닌 사용자의 숙련 부족으로 보는 시각. 용어노트

화자의 디테일 (놓치기 쉬운 포인트)

  1. 하루 종일 5~10개 Claude Code 인스턴스를 동시에 유지하며, 여러 머신에서 SSH 원격 제어도 병행한다.
  2. 수만 달러(tens of thousands of dollars) 의 토큰을 이미 소비했다고 직접 언급.
  3. 도구 스택: Claude Code (메인) + Codex (PR 리뷰 세컨드 오피니언) + OpenCode + Gemma 4 (로컬 크론잡) — 특정 도구에 올인하지 않고 용도별로 분리.
  4. Meta에서 수백 명의 엔지니어에게 Claude Code 등 AI 도구를 교육했다고 언급.
  5. 뉴스레터 파이프라인의 구체 구조: 차량 내 음성 녹음 → 자동 전사 → Claude Code 파이프라인 (컨텍스트 수집기 + 에디터 + 라이터 3-에이전트 팀) → 자기 채점·반복 → 이미지 생성 → Substack 게시. 완전 자동화.
  6. "one more prompt" — 슬롯머신처럼 마지막 프롬프트를 한 번 더 당기고 싶은 심리. 동료가 점심 가기 전에 항상 이 말을 한다고.
  7. Jensen Huang 발언: $500,000 엔지니어가 연간 $5,000 토큰만 쓰면 "go ape(격분)" → 최소 $250,000 토큰을 써야 한다고 주장. 화자는 이를 시니어 엔지니어의 보이지 않는 작업량에 빗댄다.
  8. AI 코딩이 학습을 저해한다는 우려에 대해: Meta 실무에서는 자신이 ship하는 코드를 전부 읽는다고 명확히 밝힘 — "AI가 썼어요"는 프로덕션 환경에서 면피 불가.
  9. 미래에는 코드 리뷰 자체를 혼자 하는 것이 '코드 스멜'이 될 것이라고 예측. 에이전트가 사람보다 잘할 때가 거의 와 있다고 주장.
  10. 화자 본인이 한국인임을 직접 언급: "I am Korean after all" — 스타크래프트 브루드워 언급과 연결.
  11. 모바일 엔지니어가 메인이지만 풀스택·클라우드 경험도 있으며, 수십억 유저 규모 앱 다수를 ship했다고 소개.

1. 화자 소개

Meta 스태프 엔지니어, 10년 이상 경력. 모바일 엔지니어링이 메인이지만 풀스택·클라우드 경험 다수. 수십억 유저 앱 다수 ship. Codex, Cursor, OpenCode, Ollama(Gemma), Comfy UI, Suno, VO3 등 사실상 모든 AI 도구를 실사용. 뉴스레터 getpushtoprod.substack.com 운영. Meta 내부에서 수백 명 엔지니어 AI 교육 진행.

2. 중독 이유 ① — 게임 같은 몰입감

StarCraft Brood War의 매크로(기지 관리)·마이크로(유닛 조작) 동시 수행 경험과 동일한 구조. 세션 간 빠른 탐색(마이크로)과 에이전트별 컨텍스트 관리(매크로)가 합쳐져 새로운 형태의 몰입(zone)을 만든다.

기존 코딩의 몰입(목공처럼 혼자 집중)과는 다른 종류의 고양감. ADHD 성향이거나 RTS 전략 게임을 즐겼던 사람에게 특히 강하게 작동한다. 단, 이 방식을 극도로 싫어하는 개발자도 많다.

3. 중독 이유 ② — 빌더 기질

"매달 10개를 만들고 싶은" 사람, 사이드 프로젝트 백로그가 끝없는 사람에게 Claude Code는 아이디어 → 구현의 비용을 수 배 낮춰준다. 20% 노력으로 80% 결과. 완벽한 코드보다 사용 가능한 결과물을 선호하는 사람에게 맞는 도구.

반면 일과 후 코딩을 하지 않는 대부분의 엔지니어에게는 "약간의 생산성 향상" 그 이상도 이하도 아니다.

4. 중독 이유 ③ — 자동화 보상

한 번 구축한 시스템이 스스로 반복 작동하는 것 자체가 보상. 뉴스레터 파이프라인이 구체적 사례: 차 안에서 음성 녹음 → 전사 → 3-에이전트(컨텍스트 수집기·에디터·라이터) → 자기 채점·반복 → 이미지 생성 → Substack 발행. 이 YouTube 채널 제작 시스템도 동일하게 구축 중.

"나를 복제하는 느낌(duplicating and cloning myself)" — 자동화 자체가 목적이 된 사람에게만 진짜 보상으로 작동한다.

5. 보너스 — "one more prompt" 슬롯머신 심리

Claude Code와 Codex가 창의적인 답을 낼 때 기대치를 넘어서는 순간이 있고, 그것이 슬롯머신처럼 다음 프롬프트를 당기게 만든다. 적절한 컨텍스트 엔지니어링이 이 창의성을 더 자주 끌어낼 수 있다.

6. 반대 진영 분석

① 도덕 (학습 데이터·저작권): 화자도 답이 없다고 인정. 그러나 이미 산업이 이 방향으로 수렴했고, 앞으로 만지는 소프트웨어 모두에 AI가 내재될 것 — 선을 어디서 긋든 점점 유지하기 어려워진다.

② 장인정신: 코딩 자체를 즐기는 사람들이 느끼는 고양감을 에이전트 관리는 대체할 수 없다. 화자도 인정. 억지로 설득할 생각 없음. 그러나 왜 화가 나는지는 알아야 한다 — 잃어가는 것이 무엇인지 인식해야 미래를 준비할 수 있다.

③ 완벽주의: "AI가 틀렸어"라는 반응의 대부분은 컨텍스트 부족·하네스·검증 루프의 부재 신호. Andrej Karpathy도 이를 "skill issue"라고 지적. 올바른 컨텍스트와 도구를 주면 현재 모델로도 대부분의 작업을 잘 해낸다.

④ 학습 저해: 사이드 프로젝트에서는 어느 정도 인정. 그러나 실무(Meta)에서는 자신이 ship하는 코드를 전부 읽는다. "AI가 썼어요"는 프로덕션에서 면피 불가. Plan Mode를 적극 활용하면 코드를 읽고 이해하는 시간이 오히려 늘어난다.

7. Jensen Huang 토큰 사고실험

Jensen의 주장: $500K 엔지니어가 연간 $5K 토큰 → 격분. $250K 이상이어야 한다. 처음에 많은 사람이 비웃었지만, 화자의 해석은 다르다:

시니어 엔지니어는 PM과 대화하고, 스펙을 결정하고, 자체적으로 실행한 후 완성물만 보고하는 보이지 않는 작업량이 크다. 에이전트도 동일 — 하네스·검증 루프로 스스로 검토·수정하면 토큰은 많이 쓰지만 그것이 레버리지다. 토큰 소비 ≈ 보이지 않는 작업량 ≈ 레버리지.

8. 미래 직업의 변화

미래의 핵심 기술은 코드 작성이 아니라 에이전틱 시스템 구축이다.

  • 에이전트가 코드 리뷰를 사람보다 잘하는 시대가 거의 도래
  • 혼자 코드 리뷰하는 것이 "코드 스멜"이 될 수 있음
  • AI-ready 코드베이스 설계: 관찰 레이어(텔레메트리), 좋은 피드백 루프, 완료 기준(taste) 정의
  • 에이전트 파인튜닝 역량

지금 Claude Code에 중독된 사람들이 이 근육을 미리 키우고 있다. 이것이 미래 직업에서 가장 스마트한 선택이 될 것.

9. 결론·권고

AI 코딩에 저항하는 사람도 이해하지만, 9-to-5 직업을 유지하려면 적응이 불가피하다. 당장 파워유저가 될 필요는 없다. 하나의 워크플로우를 골라 자동화하는 것부터 시작. 매주 조금씩 Claude Code에 더 쌓아가라.

저는 Claude Code에 확실히 중독됐습니다. 캐주얼하게가 아니라, 하루 종일 여러 머신에 걸쳐 5~10개 인스턴스를 거의 항상 돌리고 있어요. SSH로 원격 머신에 접속해서 제어하고, 토큰에 수만 달러를 이미 썼습니다. 지금은 이 모든 도구를 활용해서 최대한 배우는 것에 집중하고 있어요. 이 도구들을 잘 쓰는 사람과 못 쓰는 사람 사이에 실력 격차가 생기고 있다는 걸 느낍니다.

그런데 이 Claude Code 중독을 생각해보니, 단순히 "코드를 빨리 써줘서"가 아니었어요. 훨씬 흥미로운 이유가 있었습니다. 그리고 지금 테크 업계에는 AI 코딩을 둘러싼 실제 분열이 있어요. 한쪽은 "AI가 미래, 거스를 수 없다", 다른 쪽은 "장인정신을 파괴하고 있다, 다 과대포장이다". 저는 양쪽 다 어느 정도 맞다고 생각합니다.

우선 제 배경을 말씀드리면: 저는 Meta의 스태프 소프트웨어 엔지니어입니다. 10년 이상 경력, 모바일 메인이지만 풀스택·클라우드 경험도 풍부하고, 수십억 유저 앱들에 수많은 제품을 ship했어요. AI 도구 측면에서는 Codex, Cursor, OpenCode, Ollama(Gemma 모델), Comfy UI, Suno, VO3 등 사실상 전부 써봤고, 이 모든 도구로 처음부터 끝까지 완전한 제품을 만들어봤습니다. 뉴스레터에도 이를 공개적으로 씁니다. 지금은 Claude Code가 메인이고, Codex는 PR 리뷰 세컨드 오피니언으로, OpenCode + Gemma 4는 로컬 크론잡에 씁니다. 스폰서 없이 그냥 다 씁니다. Meta에서 수백 명 엔지니어에게 AI 도구 교육도 했어요.

이제 중독의 진짜 이유입니다. 코드 자체에 관한 게 아니에요. 저는 세 가지 심리적 훅으로 정리했습니다.

이유 1: 비디오 게임 같은 몰입감

저는 스타크래프트를 정말 많이 했어요. 브루드워가 제 작품입니다. 저 한국인이니까요. 스타크래프트를 하면 매크로(기지 관리)와 마이크로(유닛 조작)를 동시에 하는 느낌을 아실 거예요. 기지를 관리하고 공장을 짓고 SCV를 돌리면서 동시에 다른 지역으로 화면을 전환해 유닛을 제어하는 것. 대부분은 엄청 지치지만, 어떤 사람들에게는 극도로 중독적이에요. 저도 그런 사람이고요.

Claude Code와 Codex를 대규모로 돌리는 게 정확히 이 느낌입니다. 마이크로는 세션 간 전환 — 여러 Claude Code 세션, 여러 터미널, 여러 pane을 모두 hotkey로 묶어서 빠르게 이동해요. 매크로는 각 에이전트와 프로젝트의 컨텍스트를 관리하는 것. 한 pane에 들어가서 에이전트에게 할 일을 빠르게 지시하고, 다음으로 이동하고, 출력을 검증하고, 방향을 수정하고, 다시 다음으로. 그리고 그 위에 에이전틱 엔지니어링·하네스 구축 레이어가 있어요. 이게 스타크래프트로 치면 미래 자동화를 위한 기지를 짓는 것과 같습니다.

저도 예전에는 직접 코딩하는 걸 정말 좋아했어요. 문제를 머릿속에 완전히 담고 몰입해서 풀어나가는 그 느낌. 목공처럼 모든 조각이 어디 가야 할지 알면서 도구를 집어 드는 것. 카타르시스가 있죠. AI 코딩은 그 느낌을 줄 수가 없어요, 특히 인스턴스 하나만 두고 결과 기다리다 딴짓하면. 하지만 저는 이 스타크래프트 플레이 방식으로 새로운 zone을 찾았어요. 이게 제가 지금 중독된 것입니다. 단, ADHD 성향이 있거나 RTS를 즐긴 사람이어야 이게 잘 맞아요. 많은 사람들은 이 방식을 극도로 싫어합니다.

이유 2: 맹렬한 빌더 기질

끝없는 프로젝트 아이디어를 가진 사람이어야 합니다. 문제를 보면 즉시 해결하고 싶고, 매달 10개를 만들고 싶고, 사이드 프로젝트 백로그가 무한한 그런 사람. 솔직히 대부분의 엔지니어는 그렇지 않아요. 일은 일이고, 일 끝나면 코딩 안 합니다. 그 캠프에 있다면 AI 코딩은 그냥 "약간의 생산성 향상"이에요. 깊게 파고들어야 할 동기가 없죠.

하지만 매달 10개를 만들고 싶은 사람이라면, Claude Code는 아이디어 구현 비용을 수 배 낮춰줍니다. 20% 노력으로 80% 결과. 그 이하도 가능하고요. 사이드 프로젝트는 완벽한 코드보다 쓸 수 있는 결과물이 목적이니까. 그래서 저는 예전 방식으로 돌아가기가 너무 어렵습니다.

이유 3: 자동화 그 자체가 보상

일정에 따라 혼자 돌아가는 워크플로우를 만들어본 적 있으시면 이 느낌 아실 거예요. 시스템을 구축하는 데 많은 시간을 쓰지만, 그게 계속 배당을 지급하고 자는 동안에도 일을 해줄 때의 그 만족감. 제 뉴스레터가 좋은 예입니다. 차 안에서 음성으로 주제를 쏟아내면, 자동으로 전사되어 Claude Code로 만든 파이프라인에 들어갑니다. 이전 글들의 컨텍스트를 끌어오고, 내 말투와 규칙대로 초안을 쓰고, 에이전트 팀(에디터, 컨텍스트 수집기, 라이터)이 검토하고 채점하며 반복한 뒤, 이미지까지 자동 생성해서 Substack에 올릴 준비를 해줍니다. 이건 생산성 트릭이 아니라 시스템 구축이에요. 저를 복제하는 느낌이랄까요.

보너스: "one more prompt" 슬롯머신 심리

동료가 점심 가기 전에 항상 "one more prompt"를 외쳐요. 슬롯머신 당기는 느낌이죠. 물론 뭘 하는지 알면 그냥 방향을 잡는 거지만, 때로는 Claude나 Codex가 기대 이상으로 창의적인 답을 줄 때가 있어요. 컨텍스트 엔지니어링과 프롬프팅을 잘할수록 이 창의성이 더 자주 나옵니다.

이제 반대 진영 얘기입니다. AI 코딩을 진심으로 싫어하는 사람들의 이유가 있고, 저도 공감하는 부분이 있어요.

반대 이유 1 — 도덕 (학습 데이터·저작권)

저도 의견이 있지만 솔직히 별로 의미가 없어요. 산업은 어차피 이 방향으로 가고 있으니까요. 앞으로 몇 년 안에 당신이 만지는 모든 소프트웨어에 AI가 들어갈 거예요. 이미 그렇게 되고 있고요. 나이키와 스웨트샵처럼, 솔직히 마음이 편하지 않지만 선을 긋는 게 점점 어려워집니다.

반대 이유 2 — 장인정신

코딩 자체를 사랑하는 사람들이요. 목공처럼 집중해서 직접 무언가를 만드는 그 느낌. AI 코딩은 그 느낌을 주지 않아요. 제가 말한 스타크래프트 zone도 그것과는 달라요. 다른 종류의 고양감이죠. 이 새로운 방식을 즐기지 못하는 분들을 설득할 생각 없어요. 하지만 왜 화가 나는지는 알아야 해요 — 에이전트 관리가 왜 그렇게 불편한지, 이해해야 미래를 준비할 수 있습니다.

반대 이유 3 — 완벽주의

AI가 계속 실수한다는 분들. 맞아요, 항상 100%는 아닙니다. 그런데 제 경험상 "AI 쓰레기야, 멍청한 실수만 해"라는 말은 대부분 컨텍스트 부족, 하네스 부재, 검증 루프 없음의 신호예요. Andrej Karpathy도 이런 AI 시스템 불만 대부분을 "skill issue"라고 했어요. 올바른 도구·스킬·컨텍스트를 주면 현재 모델로도 거의 모든 작업을 잘할 수 있어요. 100%는 아니지만, 제대로 준비하면 매우 잘합니다.

반대 이유 4 — 학습 저해

AI가 엔지니어 성장을 방해한다는 논점. 사이드 프로젝트에서는 어느 정도 인정해요. 저도 결과물에 관심이 있지 코드 품질에는 덜 집중하니까요. 하지만 Meta 실무에서는 제가 ship하는 코드를 모두 읽습니다. 프로덕션 환경에서 동료들과 코드를 공유하고 유지보수해야 하고, 뭔가 잘못되면 "AI가 썼어요"는 답이 안 되니까요. 실제로 많은 AI 코딩에서 이 패턴이 나타날 것 같아 우려도 됩니다. 그래서 우려는 타당하지만, 원한다면 AI를 쓰면서도 충분히 배울 수 있어요. 저는 실제로 Plan Mode에서 코드베이스를 탐색하고 기회를 발견하는 데 대부분의 시간을 씁니다. 코딩보다 읽고 이해하는 시간이 더 많아요.

Jensen Huang의 토큰 발언

최근 Jensen이 한 말이 화제가 됐어요. "연봉 50만 달러짜리 엔지니어가 연간 토큰 5천 달러만 썼다면 격분하겠다. 최소 25만 달러 어치를 써야 한다"고. 많은 사람이 비웃었는데, 이유가 있어요 — 10만 달러 어치 토큰을 써보려면 정말 미친 짓을 해야 하거든요.

하지만 노이즈를 걷어내고 생각해보면 논리가 있어요. 주니어 엔지니어는 작업 하나 주면 후속 질문 10개가 돌아옵니다. 시니어 엔지니어는 "이것 만들어"라고 하면 PM과 논의하고 스펙 결정하고 결정 내리고 완성물만 가져옵니다. 이 시니어의 보이지 않는 작업량이 곧 추가 토큰 소비예요. 에이전트도 마찬가지 — 하네스와 검증 루프로 스스로 검토·수정하면 토큰은 많이 쓰지만, 그것 자체가 레버리지입니다. 최소 입력 → 최대 고품질 출력. 이 수준에 도달하면 Jensen의 발언이 더 이상 이상하게 들리지 않습니다.

그래서 직업이 근본적으로 변하고 있어요. 코드 리뷰를 혼자 하는 것이 미래에는 "코드 스멜"이 될 수 있다는 게 저도 놀랍지만, 에이전트가 사람보다 코드 리뷰를 잘하는 시대가 거의 와 있습니다. 미래의 진짜 일은 에이전틱 시스템 구축, 하네스, 에이전트가 쓰기 좋은 코드베이스(관찰 레이어·텔레메트리·피드백 루프), 완료 기준 정의, 파인튜닝입니다. 지금 Claude Code에 중독된 사람들이 이 근육을 먼저 키우고 있어요.

결론

어디쯤 있든 제 제안은 간단합니다. 하룻밤 사이에 파워유저가 될 필요 없어요. 워크플로우 하나를 골라서 자동화해보세요. 매주 조금씩 Claude Code에 더 쌓아가세요. 솔직히 AI 코딩을 싫어하고 직접 손으로 코딩하는 분들이 9-to-5 직업에서 이 선택을 고집하긴 어려울 거예요. 컨텐츠 크리에이터가 되거나 이미 부자이거나. 9-to-5라면 선택의 여지가 없어요. 그래서 받아들이고 새로운 방식을 찾으세요.

가장 중요한 메시지는 이겁니다: 미래의 직업은 코드를 직접 쓰는 것이 아니라 에이전트가 코드를 써줄 시스템을 만드는 것입니다. 지금 중독된 사람들은 그 근육을 일찍 키우고 있어요. 아마도 여러분이 추구할 가장 현명한 선택일 겁니다. 그러니 중독되세요. 이상하게 들려도 그게 맞습니다.
