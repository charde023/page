웹 검색은 실제로 어떻게 작동하는가

원작자 Parag Agrawal · Parallel Web Systems · 업로드 2026-08-26 · 1.5분 · 원본 영상 ↗
한 줄 요약

검색엔진은 웹을 미리 읽고 정리한 뒤, 사용자의 질의가 들어오면 수천억 개 페이지 중 가장 관련 높은 결과를 빠르게 골라내는 거대한 매칭 시스템이다.

핵심 학습 포인트 (내가 배워야 할 것)

개념 왜 중요한가 한 줄
웹 검색(Web Search) 사용자가 원하는 정보를 웹 어디선가 찾아주는 기본 문제다 “어디 있는지 모르는 정보”를 가장 편한 위치에 보여주는 일
크롤링(Crawling) 검색엔진이 검색 가능한 후보를 확보하는 첫 단계다 웹상의 URL을 찾아 읽어오는 과정
색인(Index) 검색 시점에 페이지를 매번 읽으면 너무 느리기 때문에 필요하다 미리 읽고 정리해 둔 검색용 데이터베이스
전처리(Preprocessing) 질의가 들어오기 전에 정보를 검색하기 좋은 형태로 바꾼다 빠른 검색을 위해 데이터를 미리 가공한다
검색·회수(Retrieval) 방대한 문서 중 후보 결과를 빠르게 줄인다 수천억 페이지에서 관련 있을 만한 결과를 추린다
랭킹(Ranking) 후보 중 사용자가 가장 원할 결과를 위로 올린다 5개, 10개, ideally 1개로 좁히는 단계
매칭 문제(Matching Problem) 검색의 본질을 이해하는 관점이다 수천억 페이지와 수천억 질의를 서로 연결하는 일

내가 모를 만한 것 / 처음 보는 것

  • 크롤링(Crawling) — 검색엔진이 웹을 돌아다니며 URL을 발견하고 페이지 내용을 읽는 작업.
  • 색인(Index) — 책의 색인처럼, 검색어가 들어왔을 때 관련 문서를 빨리 찾기 위해 미리 정리한 구조.
  • 검색·회수(Retrieval) — 전체 문서에서 관련 가능성이 높은 후보 문서를 먼저 가져오는 단계.
  • 랭킹(Ranking) — 가져온 후보들을 관련도, 품질, 의도 적합성 등에 따라 순서대로 배치하는 단계.
  • 수십억 대 수십억 매칭(Billion-to-billion matching) — 검색은 단순히 “검색어 포함 페이지 찾기”가 아니라, 엄청난 수의 질의와 문서를 서로 연결하는 문제라는 표현.

화자의 디테일 (놓치기 쉬운 포인트)

화자가 흘리듯 말한 구체 수치·설정값·명령어·뉘앙스. 원어 용어 괄호 병기, 맥락까지.

  1. 수천억 개 페이지(hundreds of billions of pages) — 검색엔진이 다루는 웹 문서의 규모를 설명하기 위해 든 수치다.
  2. 수천억 개 질의(hundreds of billions of queries) — 시간이 흐르며 들어오는 검색 요청 역시 페이지 수만큼 거대하다는 의미다.
  3. 5개, 10개, 이상적으로는 1개 결과 — 검색엔진의 목표는 많은 후보를 보여주는 것이 아니라, 사용자가 지금 원하는 답에 최대한 가깝게 좁히는 것이다.
  4. 메모리의 한 위치에 둔다(in memory in one location) — 실제 검색엔진 구조는 훨씬 복잡하지만, 설명상 “미리 한곳에 준비해 둔다”는 비유로 이해하면 된다.
  5. 질의가 들어오기 전에 전처리(preprocessing) — 검색 속도는 사용자가 검색 버튼을 누른 뒤가 아니라, 그 전에 얼마나 준비해 두었는지에 크게 달려 있다.

# 섹션 요지

2 크롤링과 색인 검색엔진은 미리 웹을 읽고 정리해 빠른 검색이 가능하게 만든다
3 질의 처리 사용자의 검색어를 이해하고 관련 결과 후보를 찾는다
4 검색과 랭킹 많은 후보 중 가장 관련 높은 결과를 상위에 올린다
5 거대한 매칭 문제 검색은 수천억 페이지와 수천억 질의를 연결하는 문제다

1. 웹 검색의 기본 문제

웹 검색(Web Search)의 출발점은 단순하다. 사용자는 어떤 정보를 찾고 싶지만, 그 정보가 웹의 어느 위치에 있는지 모른다. 그래서 Google 같은 검색엔진(Search Engine)에 질의를 입력한다.

검색엔진의 역할은 사용자가 원하는 답을 가능한 한 편리한 위치에 보여주는 것이다. 여기서 “편리한 위치”란 단순히 웹페이지 목록을 많이 보여주는 것이 아니라, 사용자가 지금 찾는 답에 가까운 결과를 빠르게 보여주는 것을 뜻한다.

2. 검색엔진은 먼저 웹을 크롤링한다

검색엔진은 사용자의 검색어가 들어온 뒤에야 웹 전체를 뒤지는 것이 아니다. 그렇게 하면 너무 느리다.

대신 검색엔진은 미리 웹을 크롤링(Crawling)한다. 크롤링이란 웹상에 존재하는 URL을 발견하고, 각 페이지를 읽고, 그 안의 정보를 수집하는 과정이다.

즉 검색엔진은 사전에 “웹에 어떤 페이지들이 있고, 그 페이지들에 어떤 내용이 있는지”를 최대한 많이 파악해 둔다.

3. 읽은 정보를 색인으로 정리한다

크롤링한 정보를 그대로 쌓아두기만 하면 검색에 적합하지 않다. 그래서 검색엔진은 이 정보를 색인(Index)이라는 구조로 정리한다.

색인은 사용자가 질의를 입력했을 때 관련 페이지를 빠르게 찾기 위한 사전 정리 시스템이다. 책 뒤쪽의 색인을 떠올리면 이해하기 쉽다. 특정 단어가 어느 페이지에 나오는지 미리 정리해 두면, 책 전체를 매번 처음부터 읽지 않아도 된다.

검색엔진도 마찬가지다. 페이지 내용을 미리 읽고 전처리(Preprocessing)해 두기 때문에, 질의가 들어왔을 때 매번 웹페이지를 새로 불러오지 않아도 된다.

검색 속도의 핵심은 “검색하는 순간”이 아니라 “검색 전에 얼마나 잘 준비해 두었는가”에 있다.

4. 질의가 들어오면 빠르게 이해하고 후보를 찾는다

사용자가 검색어를 입력하면 검색엔진은 먼저 그 질의(Query)를 이해해야 한다.

예를 들어 사용자가 입력한 단어가 어떤 의도를 담고 있는지, 정보 탐색인지, 특정 사이트 이동인지, 구매 의도인지 등을 파악해야 한다. 영상에서는 이 부분을 짧게 설명하지만, 실제 검색 품질에서는 매우 중요한 단계다.

그다음 검색엔진은 색인에서 관련성이 높은 후보 결과를 빠르게 찾아낸다. 이 단계가 검색·회수(Retrieval)에 해당한다.

5. 검색과 랭킹을 거쳐 결과를 좁힌다

웹에는 수천억 개의 페이지가 있다. 검색엔진은 이 거대한 후보군에서 사용자가 원하는 결과를 찾아야 한다.

하지만 사용자에게 수백만 개 결과를 그대로 보여주는 것은 의미가 없다. 실제 목표는 수천억 페이지를 5개, 10개, 가능하면 1개의 가장 적합한 결과로 좁히는 것이다.

이를 위해 검색엔진은 여러 단계의 검색·회수(Retrieval)와 랭킹(Ranking)을 거친다.

  • 검색·회수(Retrieval): 관련 있을 만한 후보를 빠르게 추린다.
  • 랭킹(Ranking): 후보 중 더 좋은 결과를 위쪽에 배치한다.
  • 최종 노출: 사용자가 볼 만한 소수의 결과만 보여준다.

6. 웹 검색은 거대한 매칭 문제다

화자는 웹 검색을 수십억 대 수십억 매칭 문제(Billion-to-billion matching problem)로 설명한다.

한쪽에는 수천억 개의 웹페이지가 있다. 다른 한쪽에는 시간이 지나며 쌓이는 수천억 개의 사용자 질의가 있다. 검색엔진은 이 둘 사이에서 가장 잘 맞는 조합을 찾아야 한다.

즉 검색은 단순히 “검색어가 포함된 문서 찾기”가 아니다. 사용자의 의도와 웹페이지의 내용을 연결하는 매칭 시스템이다.

이 관점에서 보면 검색엔진의 핵심 역량은 다음과 같다.

  • 웹을 얼마나 넓게 수집하는가
  • 정보를 얼마나 잘 정리하는가
  • 질의를 얼마나 정확히 이해하는가
  • 후보를 얼마나 빠르게 줄이는가
  • 최종 순서를 얼마나 잘 매기는가

교정 전사 (한국어)

전체 전사 펼치기

웹 검색(Web Search)의 문제는 우리 모두가 알고 있고 경험하는 문제입니다. 무언가를 찾고 싶은데, 그것이 웹의 어디에 있는지 모를 때 우리는 Google 같은 검색엔진(Search Engine)에 갑니다. 그러면 검색엔진은 우리가 원하는 답을 가장 편리한 위치에 보여주려고 합니다. 이것이 기본 문제입니다.

그렇다면 이를 위해 검색엔진은 무엇을 할까요? 검색엔진은 웹을 크롤링(Crawling)합니다. 이는 존재하는 모든 URL을 찾고, 그것을 읽으려 하며, 그 정보를 색인(Index)이라고 부를 수 있는 구조로 정리하는 것을 의미합니다.

이렇게 모든 정보를 한곳의 메모리(Memory)에 가진 상태로 준비해 두면, 질의(Query)가 들어왔을 때 페이지를 새로 불러오느라 시간을 쓰지 않아도 됩니다. 이미 페이지를 확보해 두었고, 정보를 정리하기 위한 전처리(Preprocessing)도 끝내 두었기 때문입니다.

그다음 실제로 질의가 들어오면, 검색엔진은 질의를 빠르게 이해하고 가장 관련성 높은 결과를 찾습니다. 결과는 매우 많습니다. 본질적으로 수천억 개의 페이지를 가져와서, 사용자가 지금 찾는 것에 맞게 5개나 10개, 이상적으로는 1개의 결과로 좁히는 일이기 때문입니다.

검색엔진은 가장 관련성 높은 결과를 보여주기 위해 여러 단계의 검색·회수(Retrieval)와 랭킹(Ranking)을 거칩니다. 이를 생각하는 한 가지 방식은, 이것이 수십억 대 수십억 매칭 문제(Billion-to-billion matching problem)라는 것입니다. 수천억 개의 페이지와 시간이 지나며 쌓이는 수천억 개의 질의가 있고, 검색엔진은 이 둘을 어떻게 서로 연결할지 알아내야 합니다.
