OpenClaw에는 없던 Hermes 활용 사례 6가지

한 줄 요약

Hermes 에이전트는 Wake Agent / no_agent 플래그, 진화하는 메모리, 스킬 시스템 덕분에 OpenClaw가 제공하지 못하는 조직 자동화·비용 절감·콘텐츠 자동화를 실현한다.

내가 모를 만한 것 / 처음 보는 것

  • Hermes 에이전트: OpenClaw 대비 Wake Agent·no_agent 플래그, 진화하는 메모리(memory editing), 스킬 시스템을 갖춘 AI 에이전트 프레임워크
  • Wake Agent 플래그: cron 작업 스크립트 안에 설정하는 불리언 플래그. false이면 LLM 미호출, 변화 감지 시에만 true로 전환
  • no_agent 플래그: LLM을 전혀 호출하지 않고 Hermes 에코시스템 내에서 cron 작업을 실행하는 모드 — 실질적으로 무료
  • 메모리 캡(memory cap): 프로필별 메모리를 캐릭터 수 기준으로 제한하는 예산 관리 기능
  • XURL 스킬: X(트위터)에 콘텐츠를 자동 포스팅하는 Hermes 내장 스킬
  • PRD를 스킬로 유지: 평문 문서가 아닌 스킬 형태로 PRD를 저장하면 필요 시에만 로드되고 컨텍스트 창의 "신선한" 영역에 위치함 — 이전 영상에서 다룬 개념
  • AI Labs Pro: 이 채널의 제작사. 커뮤니티 + 튜토리얼 제공 (ailabspro.io)
  • Brilliant: 수학·코딩·AI 인터랙티브 학습 플랫폼 (협찬 언급, MIT/Harvard/Stanford 교수진 제작 코스)

화자의 디테일 (놓치기 쉬운 포인트)

  1. Hermes 데스크톱 앱은 TUI(터미널 UI)의 래퍼(wrapper)이며, 여러 프로필을 병렬 실행하고 동시에 작업을 위임하는 게 핵심 장점이다. TUI에서는 프로필 전환에 여러 명령어가 필요했음.
  2. Wake Agent 플래그: false로 두면 해당 cron 이벤트에서 LLM이 전혀 호출되지 않는다. OpenClaw는 이 구분이 없어서 매 cron마다 LLM이 실행됐음.
  3. no_agent 플래그로 만든 cron 작업은 Hermes가 직접 빌드해 준다 — 프롬프트 하나로. 필요한 스킬을 가져와 자동화 전체를 구성함.
  4. no_agent cron 사례: TLS 인증서 만료 감시 + Stripe 앱 헬스 체크 → Slack 채널에 결과 게시. 거의 비용 없음.
  5. AWS 비용 + Gemini API 비용을 묶어서 Wake Agent로 모니터링하고, 비용 급등 시 Slack 알림 + Stripe MCP 연동으로 자동 조치까지 연결 가능.
  6. Google Play Store 리뷰 관리에도 Wake Agent 적용 가능: 1성 리뷰 감지 → Slack 보고 + 이슈 식별 → 제품 개선 인사이트 도출.
  7. 회사 두 번째 뇌 구현 시 Hermes가 company skill을 자동으로 생성하여 조직 전체 운영 컨텍스트를 저장. PM이 이 스킬로 목표 추적·태스크 배분 가능.
  8. OpenClaw는 sole file(단일 파일)이 비대해지면 리셋이 필요하지만, Hermes는 memory editing 기능으로 장기 워크플로우를 지속 유지함.
  9. Gmail 연동: Google Cloud 프로젝트 생성 → 자격증명 + 콜백 토큰 추가 → Hermes가 Gmail 읽기·전송·회신 권한 획득. 설정이 길지만 단순 단계들.
  10. 웹훅(webhook) 기반 리드 자동 응답: Hermes가 company skill + webhook skill을 조합해 수신 이메일을 분석, 잠재 고객 감지 시 자동 회신 + 캘린더 미팅 예약까지 처리.
  11. PRD 기반 경쟁사 분석 cron은 주간 주기로 실행됨 (경쟁사가 보통 그 정도 주기로 업데이트를 출시하기 때문).
  12. SNS 자동화에서 X 포스트와 LinkedIn 포스트를 폴더에 파일로 저장한 뒤 사람이 검토 후 게시 명령 → 콘텐츠 정확성 담보를 위한 의도적 인간 개입 단계.
  13. X 포스트 생성 시 캐릭터 한도 자동 준수를 Hermes가 처리함.

1. 데스크톱 앱 + 다중 프로필 병렬 실행

Hermes에는 이제 데스크톱 앱이 있다 (TUI의 래퍼). 가장 큰 차이점은 여러 프로필을 병렬로 실행하고 동시에 작업을 위임할 수 있다는 것이다. 프로필(profile)은 각자 독립된 메모리와 스킬을 가진 개별 Hermes 에이전트 인스턴스다.

TUI에서는 프로필 전환에 여러 명령어가 필요했지만, 데스크톱 앱은 UI로 모든 것을 처리한다. 설정 패널에서 모델, 도구, 스킬 활성화, 메모리 캡(캐릭터 수 기준)을 설정한다.

2. Wake Agent 플래그 — 조건부 LLM 호출

Wake Agent는 cron 스크립트에 포함된 플래그다. false이면 LLM이 호출되지 않는다. 실제로 변화가 있을 때만 LLM을 깨운다.

OpenClaw와의 차이: OpenClaw는 cron 실행마다 무조건 LLM이 호출됐다. Wake Agent 플래그로 Hermes는 "이번 이벤트에 LLM 토큰을 쓸 가치가 있는가?"를 먼저 판단한다.

활용 사례: - AWS 비용 + Gemini API 비용 모니터링 → 비용 급등 시 Slack 알림 + Stripe MCP 자동 조치 - Google Play Store 리뷰 감시 → 1성 리뷰 감지 시 Slack 보고 + 이슈 요약

3. no_agent 플래그 — LLM 없는 Hermes cron

no_agent = true로 설정된 cron은 AI 모델을 전혀 호출하지 않는다. 일반 cron과 기능적으로 같지만, Hermes 에코시스템 안에서 동작하므로 설정이 훨씬 간단하다 (Hermes가 필요한 스킬을 가져와 자동화 전체를 빌드해 줌).

비용: 사실상 무료 (LLM 호출 없음).

활용 사례: - TLS 인증서 만료 감시 - Stripe 앱 헬스 체크 - 주요 메트릭 수집 → Slack 채널 보고

알림이 발생하면 Hermes에 태그해서 조치 지시 → 기존 데이터를 유지하면서 처리.

4. Slack 연동 — 조직의 두 번째 뇌

Hermes 봇을 Slack 워크스페이스에 연결하면, 팀원들이 직접 인터랙션하면서 에이전트가 조직 컨텍스트를 축적한다. Hermes는 자동으로 company skill을 생성해 회사가 무엇을 하는지, 진행 중인 태스크와 진척도를 모두 저장한다.

OpenClaw 대비 장점: OpenClaw는 sole file이 비대해지면 리셋이 필요하다. Hermes는 memory editing 기능으로 장기 워크플로우를 지속 유지한다.

PM 활용: 목표 설정 → Hermes가 태스크 배분 + 진척 업데이트 자동화.

5. Gmail 리드 자동 응답 + PRD 경쟁사 분석

Gmail 연동 절차: 1. Google Cloud 프로젝트 생성 + 자격증명 발급 2. 콜백 토큰 추가 3. Hermes가 Gmail 읽기·전송·회신 권한 획득

연동 후 웹훅 생성: 수신 이메일 분석 → 잠재 리드 감지 → company skill 기반 자동 회신 + 캘린더 미팅 예약.

PRD 스킬 + 경쟁사 분석: PRD를 스킬로 유지하면 컨텍스트 창의 신선한 영역에 로드된다. 이 스킬을 재사용해 경쟁사 분석 cron을 설정: - 주간 주기로 경쟁사 업데이트 수집 - PRD에 추가 가능한 기능 제안 업데이트 - 별도 경쟁사 추적 문서 자동 유지

6. X / LinkedIn 소셜 미디어 자동화

XURL 스킬을 사용해 영상 스크립트 → X + LinkedIn 포스트 초안을 자동 생성한다. Hermes가 이미 채널의 목소리와 글쓰기 스타일을 알고 있으므로 (company skill의 컨텍스트) 별도 설명 없이도 맞춤 포스트를 생성한다.

의도적 인간 개입 단계: 포스트를 직접 발행하지 않고 지정 폴더에 파일로 저장 → 사람이 검토·수정 → 게시 명령. 콘텐츠 정확성 담보를 위한 설계.

X 포스트는 캐릭터 한도를 자동으로 준수한다.

전체 전사 펼치기

Hermes 에이전트는 가장 강력한 에이전트 중 하나인데, 사람들은 실제로 일상적인 프로세스를 최적화하는 데 사용할 때 얼마나 강력해질 수 있는지를 잘 모른다.

OpenClaw [?OpenClaw]를 써온 분들은 같은 용도라고 생각할 수 있다. 맞다. 하지만 Hermes에는 OpenClaw에는 없던 추가 기능들이 내장되어 있고, 그것이 훨씬 더 강력하게 만드는 요인이다.

데스크톱 앱

활용 사례로 넘어가기 전에 먼저 언급할 것이 있다. Hermes 에이전트에 이제 데스크톱 앱이 생겼다 — 에이전트 설정을 감싼 래퍼(wrapper)다. 이전 영상에서는 터미널 인터페이스를 사용했는데, 데스크톱 앱을 테스트해보니 UI가 에이전트 동작을 모니터링하고 설정을 구성하기 훨씬 쉽게 해줘서 터미널 UI보다 훨씬 인터랙티브한 방식이었다. 이전 영상도 확인해보길 바란다 — Claude Code와 Hermes 에이전트를 함께 사용하면 새로운 활용 사례가 많이 열린다.

가장 큰 차이점은 여러 프로필을 관리하는 것이었다. 프로필이란 기본적으로 각자 독립된 메모리와 스킬을 가진 개별 Hermes 에이전트로, 서로 다른 페르소나를 분리해 유지한다. 터미널에서는 프로필을 관리하고 전환하려면 많은 명령어를 실행해야 했다. 하지만 데스크톱 앱에서는 여러 프로필을 병렬로 실행하고 동시에 각각에 태스크를 위임할 수 있다.

설치는 사용 중인 운영체제용 설치 파일을 다운로드해서 실행하면 바로 사용 가능하다. 설치 후 설정 패널에서 모델, 도구 등 이전 영상에서 설명한 나머지 설정을 구성할 수 있다. 스킬 패널에서 활성화할 스킬도 설정할 수 있다. 같은 설정 패널에서 이전 영상에서 언급한 메모리 캡 — 캐릭터 수 기준으로 메모리와 프로필 예산을 관리하는 기능 — 도 설정할 수 있다.

Wake Agent 플래그

Hermes 에이전트 활용 방법을 많이 열어주는 새로운 기능이 있다. wake agent 기능이다. 항상 방해 금지 모드로 켜져 있는 핸드폰처럼 에이전트도 항상 켜져 있지만, 핸드폰과 달리 실제로 필요할 때만 응답한다.

Wake agent는 cron 작업에 사용하는 스크립트 안의 플래그다. 실행 중에 Hermes 에이전트가 실제로 LLM을 사용해야 하는지를 결정한다. Wake agent 플래그가 false로 설정되면 해당 이벤트에서 LLM이 호출되지 않으므로, 실제로 주의가 필요한 변화가 있을 때만 에이전트가 실행된다. 이렇게 하면 Hermes 에이전트 사용 비용을 절약하고, LLM이 처리할 필요가 없는 것들에 실행되는 것을 방지한다.

이것은 OpenClaw에서는 불가능했다 — OpenClaw는 필요 없을 때도 매 cron 작업마다 에이전트가 실행됐다. 하지만 이 플래그를 사용하면 예약 작업에 비용이 드는 LLM 토큰을 쓰는 것이 정당한지를 먼저 결정하는 무료 의사결정자가 생기는 것이다.

다양하게 활용 가능하다. 예를 들어, 설정한 프로젝트의 AWS 비용과 Gemini API 비용을 함께 모니터링하는 cron 작업 그룹을 스킬과 함께 설정하고, 비용이 평소보다 높아지면 설정된 채널에 보고할 수 있다. 단순 보고를 원하지 않는다면 Stripe MCP와 다른 도구를 연결해 그에 기반한 조치를 취하게 할 수도 있다. 이것이 잘 작동하는 이유는 비용 급등이 없는 이벤트에서 에이전트를 호출하고 토큰을 낭비하지 않기 때문이다. 에이전트는 실제 비용 급등이 발생했을 때만 호출된다.

같은 플래그를 사용해 Google Play Store 앱의 리뷰를 관리하게 할 수도 있다. Google Play API를 설정해 앱 리뷰에 접근하고 적절한 cron 작업을 설정하면 된다. 1성 리뷰를 남기는 고객에게 답글만 다는 것이 아니라, 해당 리뷰를 Slack에 보고하고 사람들이 겪는 문제를 식별해서 실제 사용자들이 앱에 대해 어떻게 느끼는지 제대로 이해할 수 있는 의미 있는 업데이트를 보낼 수 있다.

no_agent 플래그

이전 자동화는 wake agent 기능을 사용해 무언가 주의가 필요할 때만 LLM을 호출했다. 하지만 알아야 할 또 다른 플래그가 있다 — no agent다. 이것은 AI 모델을 전혀 호출하지 않고 작업을 완료한다.

AI 모델이 관여하지 않으면 그냥 일반 cron 작업 아닌가 싶을 것이다. 맞다. 하지만 차별점은 여전히 Hermes 에코시스템 안에서 실행된다는 것이다. 일반 cron 작업처럼 작동하지만, Hermes는 이미 내가 어떻게 일하는지에 대한 훨씬 많은 컨텍스트를 갖고 있다. 그래서 동일한 것을 다른 시스템에서 설정하는 것보다 설정이 훨씬 쉽다.

예를 들어, TLS를 모니터링해서 웹사이트가 갑자기 작동을 멈추지 않도록 하는 cron 작업을 이 플래그로 설정했다. Stripe 앱 헬스와 애플리케이션의 다른 중요 메트릭도 모니터링하고, 헬스 체크 결과를 Slack 채널에 바로 게시한다. Hermes가 no agent 플래그를 true로 설정해서 이 cron 작업을 빌드해준다.

이런 작업의 큰 장점은 에이전트가 전혀 관여하지 않아서 사실상 무료라는 것이다. Hermes에게 설정 프롬프트를 주면, 필요한 스킬을 가져와서 전체 자동화를 빌드해준다. 알림 중 하나에 실제로 조치를 취하고 싶을 때 — 문제를 고치거나 무엇이든 — 채팅에서 태그하고 필요한 것을 말하면, 기존 데이터를 유지하면서 모든 것을 처리해준다.

조직의 두 번째 뇌

또 다른 활용 사례는 Hermes 에이전트를 조직의 두 번째 뇌로 구현하는 것이다. 작동 방식은 Hermes 봇을 Slack 워크스페이스에 연결하고 모든 팀원이 직접 인터랙션하게 하는 것이다.

다른 플랫폼보다 잘 작동하는 이유는 진화하는 메모리와 스킬 덕분이다. 일상적인 태스크를 관찰해서 재사용 가능한 워크플로우로 만들고, 나에 대한 많은 컨텍스트를 수집해서 결국에는 친엄마보다 나를 더 잘 알게 된다.

사람들이 Hermes 에이전트를 사용하고 호출하면서, 에이전트는 회사가 무엇인지, 무엇을 하는지, 모든 태스크와 진행 상황을 파악한다. 그런 다음 회사 운영을 이해하는 데 필요한 모든 것을 담은 스킬을 생성하고, 그 스킬로 회사의 완전한 두 번째 뇌 역할을 한다.

이렇게 Hermes는 모든 것을 추적하는 중앙 허브가 된다. 팀 전체에 컨텍스트를 공유하므로 팀원들이 직접 호출해서 질문하거나 조직 전반의 상황을 확인할 수 있다. PM은 이미 다양한 이니셔티브의 컨텍스트와 진행 상황을 갖고 있으므로 목표 추적에도 사용할 수 있고, 거기서 팀원들에게 태스크를 배분하고 설정한 목표에 따라 업데이트할 수 있다.

Hermes가 두 번째 뇌로서 유지되는 이유는 장기 실행 태스크에서 잘 작동하기 때문이다. 좋은 예는 각 팀원이 에이전트와 시간을 두고 인터랙션하는 것인데, 메모리 편집 기능이 그런 워크플로우를 지속할 수 있게 한다. OpenClaw 같은 에이전트는 sole file이 비대해져서 실제로 집중해야 할 것을 놓치기 시작하므로, 장기적으로 효과적이게 유지하려면 그 sole file을 리셋해야 한다.

Gmail 리드 자동 응답 + PRD 경쟁사 분석

조직의 두 번째 뇌 역할 외에도, Hermes의 진화하는 메모리와 스킬은 대신 행동을 취하게 해준다. 게으르다면, 에이전트가 수집한 정보와 구축한 스킬을 바탕으로 모든 잠재 리드에 자동 응답하게 할 수 있다.

Hermes에는 Google Workspace에 접근하는 내장 스킬이 있다 — 에이전트가 Google 제품과 인터랙션하게 하는 스크립트를 통해서. Gmail 연결을 위해서는 먼저 Google Cloud에서 프로젝트를 설정하고 자격증명을 얻어야 한다. 설정이 길지만 단순한 단계들이다. Claude에게 물어보거나 AI Labs Pro 커뮤니티에서 설정을 가져올 수 있다. 자격증명과 콜백 토큰을 추가하면 Hermes가 Gmail에 연결된다. 이메일 읽기, 전송, 회신이 모두 가능해진다. 여기서부터 이메일 자동화를 구축할 수 있다.

Gmail 설정 후 다음 단계는 프로세스 자동화다. 웹훅을 생성하면 된다. 웹훅은 한 앱이 다른 앱에 어떤 이벤트가 발생했음을 알려줘서 다른 앱이 그에 기반한 조치를 취할 수 있게 하는 방식이다. 연결된 Gmail 계정으로 들어오는 잠재 리드처럼 보이는 모든 이메일에 자동 회신하는 웹훅을 Hermes로 만들 수 있다. 회사에 대해 알고 있는 모든 것을 기반으로 회신을 생성하므로, 수동으로 이메일을 보내는 대신 전체를 자동으로 처리한다. 이를 위해 웹훅 생성 스킬과 조직 컨텍스트를 위한 company skill을 사용해, 수신 이메일을 모니터링하고 분석해 잠재 고객을 파악하고 응답을 생성하는 웹훅을 빌드한다. 설정이 완료되면 잠재 고객처럼 보이는 이메일을 감지할 때마다 회사 정보를 사용해 자동으로 응답하고, 미팅이 포함된 경우 열린 시간대를 기반으로 캘린더에 예약까지 처리한다.

이전 영상에서 이야기했듯이 PRD를 스킬로 만들 수 있다. 스킬로 유지하는 것이 평문 문서보다 중요한 이유는, 스킬은 실제로 필요할 때만 로드되고 모델이 주의를 기울이는 컨텍스트 창의 신선한 부분에 위치해서 에이전트가 중요한 요구사항을 놓치지 않기 때문이다. 그 스킬이 이미 만들고 있는 제품에 대한 모든 것을 알고 있으므로, 같은 설정을 재사용해 경쟁사 분석도 요청할 수 있다. Hermes 설정에서 그 경쟁사들을 연구하고 추가할 수 있는 잠재적 기능으로 PRD를 업데이트하면서 경쟁사 진행 상황을 추적하는 별도 문서를 유지하는 cron 작업을 만들 수 있다. 덕분에 X에서 업데이트를 수동으로 확인하는 시간이 줄어든다. Hermes가 cron 작업을 설정해주고 주기는 보통 주 1회 — 경쟁사들이 대략 그 주기로 업데이트를 출시하기 때문이다. 작업은 경쟁사 목록을 유지하고, 경쟁사 분석 파일을 만들고, PRD를 자체적으로 계속 업데이트한다. 이 파일들이 기본적으로 에이전트 컨텍스트의 일부가 되므로, 생성된 권장 사항을 받아서 제품을 만들면서 바로 적용할 수 있다.

소셜 미디어 자동화

Hermes에 위임할 수 있는 또 다른 것은 소셜 미디어다. XURL이라는 스킬이 있는데, X에 콘텐츠를 자동 포스팅하는 기능이다. 특히 롱폼 영상 스크립트를 X 포스트와 LinkedIn 포스트로 변환할 때 유용하다.

Hermes 에이전트로 이것이 훨씬 쉬워지는 이유는, 이미 채널의 목소리와 보통 어떻게 포스트를 작성하는지 알고 있기 때문이다 — 모든 컨텍스트를 갖고 있으므로. 새 스킬을 만들어서 영상 스크립트를 넘기면, X와 LinkedIn 양쪽을 위한 포스트를 생성하고 특정 폴더에 작성해준다. 직접 포스팅하지 않고 폴더에 쓰는 이유는 사람의 검토 단계를 두고 싶기 때문이다 — 종종 수정할 것들이 있으므로. 이렇게 계정에 올라가는 콘텐츠가 정확하고 원하는 방향에 맞는지 확인할 수 있다.

스킬 설정 후 슬래시 커맨드와 스킬 이름으로 로드하고, 포스트를 만들 영상 스크립트를 넘긴다. X 포스트가 캐릭터 한도를 지키면서 두 포스트 모두 같은 폴더에 초안을 작성하고, 검토해서 맞춤화할 수 있도록 기다린다. 검토 완료 후 Hermes 에이전트에게 X에 포스팅해달라고 하면 스킬을 호출해서 포스트를 게시한다.
