Claude Code 새로운 기능 소개 | Anthropic "Code w/ Claude" 발표

원작자 Dixon Tsai · Anthropic · 업로드 2026-05-09 · 24.9분 · 원본 영상 ↗
한 줄 요약

Claude Code는 개발자 경험(원격 제어·플리커 없는 터미널·GUI 개선)과 자율성(Auto Mode·worktree·Auto Memory·코드 리뷰·Routines)이라는 두 축으로 진화 중이며, 키보드를 떠나 있는 동안에도 Claude가 더 오래, 더 안전하게 작업을 수행할 수 있도록 설계됐다.

원작자 Dixon Tsai · Anthropic (Claude Code 팀, 플러그인 & Claude Code on the web 담당) · 추정 출처 https://www.youtube.com/watch?v=adIV8wlAFFE · 업로드 2026-05-09 · 24.9분 · 전사 Whisper large-v3 (auto)

핵심 학습 포인트 (내가 배워야 할 것)

개념 왜 중요한가 한 줄
Remote Control 로컬 세션을 모바일/웹에서 이어받을 수 있음 remote control 명령으로 링크 생성 → 어디서든 동일 dev 환경 접근
전체화면 모드 (Full-screen TUI) 플리커 없는 터미널 렌더링 + 가상 스크롤백 2e full-screen으로 활성화, 도구 호출 항목 클릭으로 펼치기 가능
worktree 통합 여러 기능을 충돌 없이 병렬 개발 claude -w 또는 --worktree 플래그, Claude 스스로도 EnterWorktree 도구 사용
Auto Mode 권한 승인 피로 해소 분류기(classifier)가 파괴적 행동·프롬프트 인젝션 여부 판단 후 자동 허용/차단
Auto Memory 세션 간 지식 누적 .claude/memory/memory.md 인덱스 파일로 관리, 서브에이전트에도 적용
/ultra review 다중 에이전트 코드 리뷰 여러 리뷰어 서브에이전트 → 독립 검토 → 검증 단계 → 가치 있는 지적만 보고
Routines 에이전트 실행 자동화 cron/GitHub webhook/API 트리거 설정 → 서버에서 무인 실행

내가 모를 만한 것 / 처음 보는 것

  • 전체화면 모드 활성화 단축키: 2e = terminal UI 약어. 2e full-screen으로 전환
  • Voice Mode: /voice 명령으로 토글 → 스페이스바 누르고 있으면 음성 프롬프트 입력 가능
  • Pin as Chapter: GUI에서 어시스턴트 메시지에 마우스 올리면 챕터로 고정 → 목차(Table of Contents) 자동 생성. 실험적 기능
  • /loop: 단일 세션 내에서 주기적 작업 설정 (/loop 1분 tell me a joke 형태). Claude의 cron_create 도구 활용
  • Tool Search 도구: Claude가 전체 도구 목록을 컨텍스트에 직접 포함하지 않고 필요할 때 검색 → 컨텍스트 소비 최소화
  • EnterWorktree / ExitWorktree 도구: Claude 자신이 판단해서 격리 환경 생성·해제
  • GitHub App 연동: PR 생성 시 자동으로 /ultra review 코드 리뷰 실행
  • Slack 커넥터: Routine 결과를 Slack 다이제스트로 전송
  • memory user / memory project: 서브에이전트에서 메모리 디렉토리 경로 지정 방식

화자의 디테일 (놓치기 쉬운 포인트)

  1. Dixon Tsai는 Claude Code 팀 소속 — 플러그인 & Claude Code on the web 담당. 발표 자체가 내부 팀원의 리얼 사용 사례 기반
  2. 플리커 문제의 원인 설명: 기존 방식이 기존 터미널 스크롤백에 append하는 방식이었기 때문에 한 칸 어긋나도 전체 리페인팅이 트리거됨. 전체화면 모드는 스크롤백을 가상화해서 보장
  3. 전체화면 모드는 메모리 사용량도 평탄화: 매우 긴 세션에서도 메모리가 선형으로 늘지 않음
  4. Auto Mode 분류기(classifier) 판단 기준 2가지: (1) 해당 액션이 파괴적(destructive)인가, (2) 프롬프트 인젝션처럼 보이는가. 둘 다 아니면 자동 허용
  5. Auto Memory의 기반 모델: Opus 4.5, Opus 4.7 등 최근 모델이 파일 디렉토리로 메모리를 관리하는 능력이 향상됐기 때문에 가능해진 기능이라고 명시함. "Claude가 포켓몬에서 훨씬 잘하고 있다"는 예시로 언급
  6. worktree에서 공유 파일 설정: claude code settings에서 node_modules 같이 워크트리 간에 공유할 파일을 선언 가능 (복사 비용 절감)
  7. /ultra review 내부 구조: (1) 여러 서브에이전트가 코드의 독립적인 측면을 병렬 검토 → (2) 검토 결과의 유효성 검증(verify) 단계 존재 → 가치 있는 지적만 최종 보고
  8. Routines는 현재 Research Preview 상태. 로컬(데스크톱)과 원격 서버 실행 모두 지원하며 Dixon 본인은 원격 실행 선호
  9. Dixon 자신의 Routine 실제 사용 예: GitHub 공개 이슈 중 area:plugins, area:hooks 레이블, 최근 24시간 내 생성된 것 스캔 → 리액션 순 Top 10 정렬 → 매일 자동 리포트. 1주일째 운영 중
  10. Anthony Morris: Claude Code Desktop 리드. "X(트위터)에서 요청하면 다음날 바로 shipped할 것"이라고 언급 — 빠른 릴리즈 속도 시사
  11. Enterprise 기능으로 추가: Windows 지원 개선, 클라우드 프로바이더 설정, 네이티브 설치, 관리자 설정 관리, 플러그인을 통한 회사 단위 harness 개선

1. Remote Control — 어디서든 세션 이어받기

로컬에서 시작한 Claude Code 세션을 웹 또는 모바일에서 이어서 볼 수 있다.

사용법: 세션 내에서 remote control 입력 → Claude Code on the web 링크 생성 → 모바일 브라우저/앱에서 열기

패턴 권장: 이미 많은 컨텍스트가 쌓인 장기 세션에서 Remote Control을 활성화한 뒤, 그 세션에 서브에이전트를 생성해서 새 기능을 구현하도록 시키고 자리를 비움.

2. 전체화면 TUI (Flicker-free Rendering)

기존 방식은 터미널 스크롤백에 append 방식 → 한 줄 어긋나도 전체 리페인팅 발생 → 플리커 유발. 전체화면 모드는 스크롤백을 가상화(virtualize)해서 문제 해결.

추가 이점: - 도구 호출(tool call) 접힌 항목 클릭 한 번으로 펼치기 - 장기 세션에서도 메모리 사용량 평탄 유지 - 새 메시지 도착 시 "jump to bottom" 버튼 — 현재 보던 위치 유지한 채 알림만 표시

활성화: 2e full-screen (2e = terminal UI 약어)

Voice Mode: /voice로 토글 → 스페이스바 누르는 동안 음성 프롬프트 입력

3. Claude Code Desktop GUI 개선

  • 사이드바: 핀 섹션, 고급 필터링/그룹핑(예: 프로젝트별 그룹), 드래그 앤 드롭으로 분할 뷰 오픈
  • 세션 뷰 종류: 트랜스크립트 / 플랜(플랜 특정 부분 하이라이트 + 코멘트 추가, Claude가 나중에 취합·처리) / diff 뷰(라인 단위 코멘트) / 파일 뷰(작업 디렉토리 전체 + 빠른 편집)
  • Pin as Chapter (실험적): 어시스턴트 메시지 위에 마우스 올리면 챕터 고정 버튼 → 자동 제목 생성 → 트랜스크립트 좌상단에 목차(ToC) 생성. 제목 변경·삭제 가능

Claude Code Desktop 리드 Anthony Morris에게 X에서 기능 요청하면 빠르게 반영된다고 Dixon이 언급.

4. Auto Mode — 자동 권한 판단

기존에는 도구 호출마다 권한 승인 프롬프트가 나타나 장기 작업 중 방치하면 멈춰 있는 경우가 많았다.

Auto Mode 동작: 1. 도구 호출 발생 → 분류기(classifier) 판단 2. 파괴적 행동인가? + 프롬프트 인젝션 징후인가? 3. 안전하다고 판단 → 자동 실행 / 위험하다고 판단 → 차단, 에이전트가 대안 모색

Anthropic 내부 팀에서 실제 사용 중이며 "돌아왔더니 멈춰있는" 상황을 크게 줄였다고 밝힘.

5. worktree 통합 — 병렬 기능 개발

Git worktree는 새 브랜치 + 파일 복사본을 만들어 격리된 환경에서 작업 가능. Claude Code가 날카로운 엣지 케이스들을 처리해서 더 편한 인터페이스로 제공.

핵심 개선점: - Claude Code 설정에서 node_modules 등 워크트리 간 공유 파일 선언 가능 - claude -w (또는 --worktree) 플래그로 새 세션 + 새 worktree 동시 시작 - Claude 자신이 EnterWorktree / ExitWorktree 도구를 사용해서 스스로 격리 환경 판단·생성·정리 - CLAUDE.md에 "새 기능은 격리된 환경에서 구현해"라고 써두면 매번 명시 안 해도 됨

실제 사용 예 (데모): Excalidraw에서 동시에 (1) 여섯 번째 색상 추가, (2) border radius 슬라이더 추가, (3) 별 모양 추가 — 세 에이전트가 각자 worktree에서 병렬 작업.

6. Auto Memory — 세션 간 지식 누적

문제: Claude Code는 매번 빈 슬레이트에서 시작 → 빌드 명령, 프로젝트 설정 등을 반복 설명해야 함

해결: 프로젝트마다 .claude/memory/ 디렉토리 생성 → memory.md 인덱스 파일이 CLAUDE.md처럼 대화에 자동 포함 → 더 상세한 내용은 같은 디렉토리의 다른 파일로 링크(Progressive disclosure)

기억 대상 예시: 빌드 명령, 디버깅 인사이트, 색상 코딩/렌더링 스웨덴(Swedish?)[?원문], 프로젝트 설정

서브에이전트 지원: 커스텀 서브에이전트에서 memory user 또는 memory project로 메모리 디렉토리 지정 가능

모델 능력과의 관계: Opus 4.5, Opus 4.7 등 최근 모델이 파일 디렉토리 기반 메모리 관리를 훨씬 잘 수행하게 됐기에 가능해진 기능. Dixon은 Claude가 포켓몬 게임에서 더 잘하게 된 것도 이 능력 덕분이라고 언급.

7. /ultra review — 다중 에이전트 코드 리뷰

패턴: 여러 리뷰어 서브에이전트가 코드의 독립적인 측면을 병렬 검토 → 결과 유효성 검증 → 실제로 보고할 가치 있는 지적만 최종 보고

효과: 직접 몇 시간 걸려야 발견할 이슈 또는 놓쳤을 이슈를 사전에 포착

사용 방법: - 수동: Claude Code에서 /ultra review 명령 - 자동화: GitHub App 연동 → 모든 PR에 자동으로 코드 리뷰 실행

8. Routines + /loop — 에이전트 실행 자동화

/loop: 단일 세션 내 자동화. Claude의 cron_create 도구를 사용해 세션 내 스케줄 작업 설정. - 예: /loop 1분 tell me a joke → 1분마다 농담 생성 - stop the loop 프롬프트로 취소 (Claude가 의도를 해석해서 cron 삭제)

Routines (Research Preview): 로컬 또는 원격 서버에서 실행. 원격 실행 시 Anthropic 서버가 스케줄·실행 관리.

트리거 종류: cron 스케줄(시간별/일별) / GitHub webhook 이벤트 / API 엔드포인트 호출

설정 구성요소: 프롬프트 + 리포지토리 + 커넥터(예: Slack) 설정 후 트리거 선택 → 이후 자동 실행

Dixon의 실제 Routine 예: - GitHub 공개 이슈 스캔 (area:plugins, area:hooks 레이블, 최근 24시간 생성 기준) - 리액션 수 기준 Top 10 정렬 보고서 생성 - 매일 자동 실행 중 (1주일 이상) - 다음 단계 구상: 이 보고서를 서브에이전트가 자동 인제스트 → 이슈 수정 런치

Tool Search 도구: 모든 도구를 컨텍스트에 직접 포함하지 않고, Claude가 필요할 때 검색해서 가져옴 → 더 많은 도구를 컨텍스트 부담 없이 제공 가능

Dixon Tsai: 안녕하세요, 여러분. 저는 Claude Code 팀의 Dixon입니다. 플러그인과 Claude Code on the web을 담당하고 있습니다. 오늘 세션은 Claude Code의 새로운 기능들에 대한 이야기입니다. 최근 공개 changelog를 보셨다면 우리 팀이 얼마나 많이 출시하고 있는지 아실 겁니다. 따라가기가 쉽지 않죠. 그래서 오늘은 changelog에서 한 발짝 물러서서 전체 그림을 보여드리고 싶습니다. 새로운 기능들이 어떻게 연결되는지, 왜 우리가 이것들을 좋아하는지.

새로운 기능들은 두 가지 테마로 나뉩니다. 첫째는 개발자 경험(developer experience) — Claude Code와 함께하는 시간이 더 늘어날수록 더 편하게 만드는 방법. 둘째는 자율성(autonomy) — 키보드를 떠나 있는 동안 Claude가 더 많은 것을 할 수 있도록 하는 방법. 마지막으로 오늘 다 다루지 못한 내용을 어디서 더 알아볼 수 있는지 안내하겠습니다.

Claude Code의 일상 사용자로서 저희는 Claude가 더 긴 작업을 스스로 처리할 수 있게 되더라도 여전히 사람의 경험에 투자하고 있습니다.

[개발자 경험]

원격 제어(Remote Control): 로컬 머신에서 세션을 시작하고 외출 중에 이어받을 수 있습니다. 폰에서도 같은 세션, 같은 개발 환경에 접근할 수 있습니다. 장기 작업을 시작해놓고 심부름을 다녀오는 건 어떤가요?

[데모] 새 세션에서 콘텐츠를 입력하고 remote control을 입력하면 Claude Code on the web 링크가 생성됩니다. 이 링크를 모바일 브라우저나 모바일 앱에서 열면 터미널 내용이 그대로 보입니다. 웹에서 3 + 3 같은 것을 입력하면 터미널에 나타납니다. 같은 개발 환경이 그대로 실행됩니다. 터미널에서 입력해도 Claude Code on the web에서 확인됩니다. 제가 가장 좋아하는 패턴은 많은 컨텍스트가 쌓인 장기 세션에서 Remote Control을 활성화하고, 그 세션에 서브에이전트를 만들어 아이디어를 구현시키는 겁니다.

플리커 없는 렌더링(Flicker-free Rendering): 플리커를 경험해본 분 손 들어보세요! (많은 분들이 손을 들었군요) 바로 OG(진짜 오래된 유저)라는 증거죠. 플리커가 터미널 경험을 망친다는 피드백을 많이 들었습니다. 기존 방식은 기존 터미널 스크롤백에 내용을 추가(append)하는 방식이었는데, 조금이라도 어긋나면 리페인팅이 트리거되어 플리커가 발생했습니다. 이제 Claude Code 터미널 UI에 전체화면 모드가 생겼고, 스크롤백을 가상화해서 플리커 없는 출력을 보장합니다. 추가로 Claude Code 터미널 요소들을 클릭 가능하게 만들었고, 매우 긴 세션에서도 메모리 사용량을 평탄하게 유지할 수 있습니다. 저희 팀 대부분이 이미 전환했고, 여러분도 바로 차이를 느끼실 겁니다.

[데모] 새 세션에서 2e full-screen으로 전체화면 모드 활성화. 참고로 Claude에는 음성 모드(voice mode)도 있습니다! /voice로 켜고 끄며, 스페이스바를 누르고 있으면 프롬프트를 말할 수 있습니다. "농담 10개 담은 파일과 흥미로운 사실 10개 담은 파일을 작성해줘"라고 말하면 실행됩니다. Claude가 작업하는 동안 전체화면 모드에서 렌더링이 얼마나 부드러운지 확인할 수 있습니다. 접힌 도구 호출도 클릭 한 번으로 펼쳐집니다. 가상 스크롤링: 스크롤 중에 아래에서 새 메시지가 오면 "jump to bottom" 버튼이 나타나고, 위쪽을 보던 뷰에는 영향을 주지 않습니다. 전체화면 모드는 터미널에서 많은 시간을 보내는 분들에게 부드럽고 직관적인 경험을 제공합니다.

Claude Code GUI 개선: 팀원 중 일부는 터미널을 선호하지만 점점 더 많은 사람이 데스크톱과 웹의 Claude Code GUI를 사용하고 있습니다. GUI를 완전히 개선해서 (1) 여러 세션 동시 관리, (2) 세션에 필요한 모든 관련 컨텍스트 표시가 훨씬 나아졌습니다.

[데모] Excalidraw(오픈소스 화이트보딩 앱) 기반 데모. 사이드바에 핀 섹션과 고급 필터링/그룹핑(예: 프로젝트별 그룹) 기능이 생겼습니다. 사이드바에서 드래그 앤 드롭으로 분할 뷰 오픈. 우상단에 세션 뷰 여러 가지: 플랜 보기(특정 부분 하이라이트 + 코멘트 추가, Claude가 나중에 취합·처리), diff 뷰(라인 단위 코멘트 가능), 파일 뷰(전체 작업 디렉토리, 빠른 편집 가능). 앞으로 Claude가 더 많은 것을 처리할수록 이런 기능들은 선택적 보조 도구로 자리잡을 겁니다.

실험적 기능 — Pin as Chapter: 긴 트랜스크립트에서 어시스턴트 메시지에 마우스를 올리면 "챕터로 고정(pin as chapter)" 버튼이 나타납니다. 클릭하면 해당 메시지 위에 맥락에 맞는 제목이 자동 생성됩니다. 여러 개를 고정하면 좌상단에 목차(ToC)가 생겨서 트랜스크립트 각 부분으로 바로 이동 가능합니다. 제목 변경·삭제도 가능합니다. Claude Code Desktop 리드 Anthony Morris에게 X에서 요청하면 아마 다음날 바로 출시할 겁니다. [데모 마지막] localhost 3002에서 서버 실행 후 사다리꼴(trapezoid) 도형 그리기, 주황색으로 색상 변경까지 확인.

[자율성]

이번 기능들은 모두 같은 경험에서 나왔습니다. 장기 작업을 시작했는데 권한 승인 프롬프트, 브랜치 충돌, 잊어버린 빌드 명령 하나 때문에 "Claude, 왜 그랬어?"라며 돌아오는 상황. 다음에 소개할 기능들은 자리를 비워도 Claude가 원하는 대로 할 것이라는 자신감을 줍니다.

Auto Mode: 권한 승인 프롬프트에 지치신 분 손 들어보세요! (거의 다 드셨네요) Auto Mode는 Claude Code의 새로운 권한 모드로, 분류기(classifier)를 사용해 Claude가 대신 권한 결정을 내립니다. 도구 호출이 권한 프롬프트를 트리거할 상황이 되면 분류기가 두 가지를 확인합니다: (1) 행동이 파괴적(destructive)인가? (2) 프롬프트 인젝션처럼 보이는가? 안전하다고 판단하면 그냥 실행. 그렇지 않으면 도구 호출을 차단하고 에이전트가 다음 대응을 결정합니다. Anthropic에서 많은 시간을 절약했고, 장기 작업을 시작했다고 생각했는데 권한 프롬프트에 멈춰있는 경우를 크게 줄였습니다.

worktree 통합: 여러 기능을 Claude끼리 충돌 없이 어떻게 개발할까요? Worktree는 제가 가장 좋아하는 기능입니다. 이 고통을 해결해줬거든요. Git worktree는 Claude Code 이전부터 존재했지만 날카로운 엣지 케이스가 많았습니다. 저희는 그 엣지 케이스들을 파악하고 더 친화적인 인터페이스로 다듬었습니다. 예를 들어 Claude Code 설정에 node_modules 같이 워크트리 간 공유할 파일을 선언하는 필드를 추가했습니다. 새 세션을 시작할 때 --worktree 플래그를 쓰면 새 세션과 함께 새 worktree가 생성됩니다. 또는 Claude에게 worktree를 만들어달라고 요청할 수도 있습니다.

[데모] Excalidraw에서 두 가지 추가: 새 색상 + border radius 슬라이더. claude -W (= --worktree 약어)로 colors용 worktree, border-radius용 worktree 시작. 각각에 프롬프트 입력 후 병렬 작업 진행. 그 사이 Claude에게 "별 모양 추가를 위한 worktree 만들어줘"라고 요청 → Claude가 EnterWorktree 도구를 사용해서 스스로 격리 환경을 만들고 구현 시작 여부를 물어봄. "leave the work tree"라고 하면 harness가 자동으로 정리. 색상 기능 완료 후 localhost 3003에서 확인 — 여섯 번째 색상 추가됨. 에이전트가 독립적으로 기능을 완성한 것.

Auto Memory: 항상 같은 것들에 토큰을 쓰고 있다고 느끼시나요? Claude Code가 빈 슬레이트에서 시작한다고 생각하시겠지만, Auto Memory로 이제 Claude가 세션 간에 지식을 쌓습니다. 빌드 명령, 디버깅 인사이트, 프로젝트 설정 등을 기억하도록 요청할 수 있습니다. Claude는 미래 대화에 유용할지 여부를 기준으로 기억할 내용을 스스로 결정합니다. 각 프로젝트마다 디렉토리를 관리하고, 그 안의 memory.md 파일이 CLAUDE.md처럼 대화에 포함됩니다. 더 상세한 내용은 같은 디렉토리의 다른 파일로 링크됩니다(스킬과 유사한 점진적 공개 방식). 서브에이전트에서도 작동하며 memory user / memory project로 메모리 디렉토리를 설정할 수 있습니다. 이 기능은 Opus 4.5, Opus 4.7 등 최근 모델의 파일 디렉토리 기반 메모리 관리 능력 향상 덕분에 가능해졌습니다. (Claude가 포켓몬에서 더 잘하고 있는 것도 이 덕분입니다.)

다중 에이전트 코드 리뷰 (/ultra review): Anthropic에서 발견한 더 효과적인 코드 리뷰 패턴 — 다중 단계(multi-phase), 다중 에이전트(multi-agent). 독립적인 코드 측면을 담당하는 리뷰어 팀을 만들고, 발견 사항이 실제로 보고할 가치가 있는지 검증합니다. 이 과정은 직접 수 시간이 걸려야 발견하거나 아예 놓쳤을 이슈를 잡아냅니다. GitHub App으로 모든 PR에 자동 설정하거나 Claude Code에서 /ultra review로 수동 시도할 수 있습니다.

정리하면: Auto Mode + worktree + Auto Memory + 코드 리뷰 = 승인할 액션 수 감소, 더 많은 에이전트 안전한 병렬 작업, 세션 간 지식 누적, Claude 팀이 직접 PR 검토 — 여러분이 직접 각 PR을 볼 필요가 줄어듭니다.

Routines + /loop (Research Preview): Routines는 사용자 개입 없이 Claude Code 세션을 트리거할 수 있게 해줍니다. 기능 개발을 자율적으로 하는 것을 넘어서, 아이디어 생성 자체를 자동화합니다. 설정은 단순합니다: 프롬프트 + 리포지토리 + 관련 커넥터를 한 번 설정하고 트리거를 선택(cron 스케줄, GitHub webhook, API 엔드포인트). 이후 Claude가 여러분 없이 실행됩니다. 예: 매일 GitHub 이슈 트리아지 → Slack 커넥터로 top 이슈 다이제스트 전송. 또는 이커머스 사이트에 판매가 발생할 때마다 실행되는 routine.

[데모] /loop 1분 tell me a joke → 1분마다 농담 생성. Claude의 cron_create 도구 사용. 분할 뷰에서 확인. stop the loop 프롬프트로 중지 — Claude가 의도를 해석해서 cron 삭제.

Routines와 비교: 로컬 또는 원격 서버에서 실행. 원격 실행 시 Anthropic 서버가 스케줄·실행 관리. Dixon 자신의 Routine: GitHub 공개 이슈 중 area:plugins, area:hooks 레이블, 최근 하루 내 생성된 것 스캔 → 리액션 순 Top 10 → 매일 자동 리포트 (1주일째 운영 중). 이 보고서를 서브에이전트가 자동 처리해서 이슈 수정 런치까지 구상 중.

추가 언급 — Tool Search 도구: 더 많은 도구를 컨텍스트에 직접 포함하지 않고, 간접 계층(layer of indirection)을 추가해 필요할 때 검색. 컨텍스트에 직접적인 영향 없이 더 많은 도구 제공 가능.
