내가 모를 만한 것 / 처음 보는 것

  • 스킬(Skill) — AI 에이전트가 특정 도구 사용, 워크플로 실행, 작업 처리 등을 수행하도록 만든 기능 단위.
  • Eval — 모델이나 에이전트가 목표를 제대로 달성하는지 확인하는 평가 테스트. 일반 소프트웨어의 테스트 코드와 비슷하지만, AI의 불확실성까지 고려해야 한다.
  • 벤치마크(Benchmark) — 여러 시스템이나 방법을 같은 기준으로 비교·평가하는 테스트 묶음.
  • 스킬벤치(SkillBench) — GitHub에서 수집한 대규모 스킬을 분석한 평가·벤치마크 자료.
  • 비결정적 에이전트(Non-deterministic agents) — 같은 작업을 줘도 실행 결과가 달라질 수 있는 AI 에이전트의 특성.

1. 문제 제기: 스킬은 쓰지만 Eval은 없다

화자는 “모두가 스킬(Skill)을 쓰지만, 아무도 평가(Eval)를 갖고 있지 않다”고 말한다.

여기서 스킬은 AI 에이전트가 특정 작업을 수행하기 위해 사용하는 기능 단위다. 예를 들어 파일을 읽고 정리하기, API 호출하기, 이메일 작성하기, 주문 데이터를 분석하기 같은 작업 절차가 스킬이 될 수 있다.

문제는 스킬을 만들고 사용하는 사람은 많지만, 그 스킬이 정확히 작동하는지 검증하는 테스트 체계는 거의 없다는 점이다.

2. SkillBench가 보여준 현실

스킬벤치(SkillBench)는 GitHub에서 50,000개 이상의 스킬을 색인화하고 분석한 벤치마크(Benchmark)다.

그 결과, 거의 대부분의 스킬에는 Eval이 없었다. 즉, “이 스킬이 잘 작동한다”는 것을 확인할 수 있는 기준이나 테스트가 부족했다.

화자는 많은 스킬이 AI-written, 즉 AI가 작성한 것으로 보이며, 실제 검증은 충분히 되지 않았다고 지적한다.

3. 왜 Eval이 중요한가

AI가 작성한 스킬은 겉보기에는 그럴듯해 보일 수 있다. 하지만 실제 업무나 서비스 환경에서는 예외 상황, 이상한 입력, 애매한 지시, 도구 오류 같은 문제가 생긴다.

Eval이 없으면 다음을 알기 어렵다.

  • 스킬이 정상적으로 작동하는지
  • 어떤 입력에서 실패하는지
  • 실패율이 어느 정도인지
  • 수정 후 품질이 좋아졌는지 나빠졌는지
  • 실제 서비스에 넣어도 되는 수준인지

결국 Eval은 AI 스킬의 품질관리(Quality control) 역할을 한다.

4. 에이전트는 비결정적이라 더 어렵다

일반 소프트웨어는 같은 입력을 넣으면 대체로 같은 결과가 나온다. 하지만 AI 에이전트는 비결정적(Non-deterministic)이다.

즉, 같은 요청을 해도 답변이나 행동이 달라질 수 있다.

그래서 작업이 실패했을 때 원인을 바로 알기 어렵다.

  • 스킬 자체가 잘못 만들어진 것인가?
  • 모델이 그 작업을 수행하기에 능력이 부족한 것인가?
  • 작업 지시가 너무 어려운 것인가?
  • 에이전트가 우연히 다른 경로를 선택한 것인가?

이 구분이 안 되면 개선도 어렵다. 그래서 화자는 스킬을 만드는 것만큼 Eval을 만드는 것이 중요하다고 강조한다.
