내가 모를 만한 것 / 처음 보는 것

  • Graphify — 오픈소스 코드베이스 지식 그래프 생성 도구. 약 60,000 GitHub 스타. safishamsi/graphify
  • Tree-sitter — AST(Abstract Syntax Tree) 파서. 언어별 코드 파일에서 클래스·함수·임포트·콜 그래프·인라인 주석을 추출. LLM 없이 로컬 실행.
  • faster-whisper — OpenAI Whisper 경량화 버전. Graphify 2패스에서 영상/오디오 파일 전사에 사용.
  • Graph RAG vs Graphify — GraphRAG(Microsoft), LightRAG, RagAnything 등은 임베딩 기반 비정형 문서용. Graphify는 임베딩 없이 코드 구조 특화.
  • "God nodes" — 그래프 내에서 가장 많은 엣지를 가진 핵심 노드. Graphify 결과 요약에 자동 리스트업.
  • Community (그래프 용어) — 성격이 유사한 노드들의 대규모 클러스터링. Graphify는 커뮤니티 수로 코드베이스 구조 파악.
  • Open Design — 데모에 사용된 오픈소스 프로젝트. "Claude Design"의 오픈소스 버전이라고 화자가 설명.
  • Chase AI+ — Chase가 운영하는 Claude Code Masterclass 유료 멤버십 (Skool 기반).

화자의 디테일 (놓치기 쉬운 포인트)

  1. "70배 토큰 절감"은 과장이라고 직접 언급 — 실측 결과는 Graphify 80k 토큰 vs 비Graphify 200k 토큰 (약 2.5배, 60% 절감).
  2. Graphify가 처음 코드베이스 크롤을 마치면, 이후 동일 세션 내 추가 질문은 비Graphify도 비용이 비슷해짐 — 최초 1회 크롤 비용이 핵심.
  3. Graphify의 진짜 가치는 시각화 그래프가 아니라 지식 그래프를 Claude Code에 핸드오프한다는 점 — "cool looking이지만 핵심은 map을 줬다는 것".
  4. /graphify . 한 번 실행 후 Open Design 203파일, 1,907 노드, 3,447 엣지, 109 커뮤니티, ~120k 출력 토큰, 소요 6분.
  5. graphify hook install 실행 시 커밋마다 AST 패스만 자동 재실행 — API 비용 0원 ("deterministic").
  6. graphify claude install로 항상 Graphify 사용 훅 설정 가능 — 이후 /graphify query 등 명시 없이도 자동 참조.
  7. Obsidian 연동(--obsidian 플래그)은 이 영상에서 다음 영상 예고로만 언급, 세부 설명은 별도 영상 예정.
  8. Graphify 설치 가장 쉬운 방법: GitHub 링크를 복사해 Claude Code에 "Graphify 설치해줘"라고 붙여넣기.
  9. 팀 환경(두 개발자 동시 작업)에서도 지식 그래프 충돌 없이 동작한다고 언급.

1 Graphify란 코드베이스를 지식 그래프로 변환 — AI 코딩 어시스턴트에 "지도" 제공

3 Graphify vs GraphRAG 코드 특화 + 임베딩 없음 vs 비정형 문서 + 임베딩 기반
4 설치·슬래시 커맨드 GitHub 링크 → Claude Code에 맡기거나 수동 설치, skill이 자동 관리
5 실측 데모 (Open Design) 6분 실행, 80k vs 200k 토큰 비교
6 지속 갱신·팀 환경 hook install로 커밋마다 AST 재빌드 (비용 0)

1. Graphify란 무엇이고 왜 써야 하나

Claude Code(또는 다른 AI 코딩 어시스턴트)는 기본적으로 코드베이스를 "grep" 방식으로 탐색한다 — 마치 Ctrl+F로 파일을 뒤지는 것과 같다. Graphify는 이 방식 대신 전체 저장소를 지식 그래프(knowledge graph)로 매핑해 Claude Code에게 사전에 완성된 "지도"를 넘겨준다.

지식 그래프는 노드(개별 코드 요소), 엣지(연결), 커뮤니티(유사 노드 클러스터)로 구성된다. Claude Code는 이 그래프를 활용해 A→B→C 연결 경로와 그 이유를 이미 알고 있으므로, 질문에 더 빠르고 정확하게 답변한다.

GitHub 스타 약 60,000개. 오픈소스이고 완전 무료.

2. 3-패스 동작 원리

1패스 — 코드 구조 분석 (비용 없음) - Tree-sitter가 코드 파일을 파싱해 클래스·함수·임포트·콜 그래프·인라인 주석 추출 - LLM 관여 없음 — 완전 결정론적(deterministic), 로컬 실행 - 시각화 그래프의 대부분이 이 패스의 결과

2패스 — 오디오/영상 전사 - 저장소 내 오디오·영상 파일이 있을 경우만 실행 - faster-whisper로 전사 후 텍스트를 지식 그래프에 주입

3패스 — 문서·이미지 의미 분석 (LLM 개입) - PDF·마크다운·이미지 등 코드 외 파일 처리 - LLM이 "이 문서의 의미가 뭔지, 그래프의 어디에 위치해야 하는지"를 판단 - RAG의 임베딩 없이 의미 연결 — "RAG Lite"에 가까운 동작

3. Graphify vs GraphRAG — 언제 무엇을 쓰나

항목 Graphify GraphRAG (LightRAG·RagAnything·MS GraphRAG)
최적 대상 코드베이스 탐색·이해 수만 건 비정형 문서 (정책·PDF 등)
임베딩 사용 없음 있음
코드 구조 인식 특화 (AST) 없음
운영 비용 무료 (1패스) + LLM (3패스) 임베딩 + LLM 비용
경계 마크다운/문서 저장소도 가능 (3패스) 코드 구조 이해 불가

Graphify는 "코드베이스 이해"와 "진짜 RAG" 사이 중간 지점에 위치한다.

4. 설치 및 슬래시 커맨드

설치 (가장 쉬운 방법)

GitHub 링크를 복사 → Claude Code 채팅에 붙여넣고 "Graphify 설치해줘" 입력

또는 GitHub README의 수동 설치 단계 따라 진행. 플랫폼 무관, 모든 AI 코딩 어시스턴트와 호환.

설치 후 — skill 파일이 모든 커맨드 관리 Claude Code는 어느 커맨드를 언제 쓸지 자동 판단. 암기 불필요.

주요 커맨드

커맨드 동작
/graphify . 현재 디렉터리 전체를 그래프화
/graphify query <질문> 지식 그래프를 명시적으로 참조해 답변
/graphify explain <주제> 지식 그래프 기반 설명
graphify claude install 이후 모든 질문에 자동으로 Graphify 사용 (훅 등록)
graphify hook install 커밋마다 AST 패스 자동 재빌드 (비용 0)
/graphify --obsidian md 저장소를 Obsidian Vault로 변환

5. 실측 데모 — Open Design 코드베이스

환경: Open Design 저장소 (Claude Design의 오픈소스 버전), Claude Code 내에서 실행

Graphify 실행 결과: - 소요 시간: 6분 - 처리 파일: 203개 - 노드: 1,907개, 엣지: 3,447개, 커뮤니티: 109개 - 출력 토큰: ~120k

질문 비교 실험 — "web app에서 coding agent까지 design request가 흐르는 경로를 추적해줘"

방식 토큰 사용량 방식
Graphify 사용 ~80k 토큰 skill 로드 → graphify query 실행
Graphify 미사용 ~200k 토큰 explorer 에이전트 2개 생성, 100k 즉시 소비 + 메인 세션 50k

결과: 약 60% 토큰 절감 (약 2.5배 차이). 70배는 과장, 실측은 이 수준.

6. 지속 갱신 및 팀 환경 지원

  • graphify hook install → 커밋마다 1패스(AST) 자동 재실행
  • 1패스는 LLM 미사용, API 비용 0 — 완전 결정론적
  • 변경된 파일만 재분석, 새 연결만 업데이트
  • 두 개발자가 동일 저장소를 병렬 작업해도 충돌 없이 처리

결과: "한 번 만들면 항상 최신 상태인 영구 지식 그래프" 유지.

7. Obsidian 연동 (예고)

  • --obsidian 플래그 한 번으로 Obsidian Vault 자동 생성 가능
  • 코드가 없는 마크다운 저장소(문서·노트 모음)에도 적용 가능
  • 세부 데모는 별도 영상 예정 — 이 영상에서는 가능성만 언급

Graphify의 포지션: Obsidian(마크다운 노트) ↔ 진짜 RAG 인프라 사이의 중간 지점.

교정 전사 (한국어)

전체 전사 펼치기

Graphify가 방금 Claude Code(클로드 코드)의 메모리 문제를 해결했습니다. 어떤 저장소든 가져와서 여기 보이는 것 같은 지식 그래프로 변환할 수 있습니다. 이 과정에서 Claude Code가 훨씬 더 정확한 답변을 훨씬 적은 토큰 비용으로 제공할 수 있게 됩니다. 전체 코드베이스를 순회하며 모든 연결을 매핑하고, 그 연결의 "이유"까지 파악하는 방식으로 동작합니다. 그리고 가장 좋은 점은 오픈소스이며 완전 무료라는 것입니다.

오늘은 이것을 직접 작동시키는 방법과 내부에서 실제로 어떤 일이 일어나는지를 보여드리겠습니다.

Graphify는 몇 달 전에 출시됐는데 GitHub 스타가 거의 60,000개에 달합니다. 이 도구는 AI 코딩 어시스턴트(반드시 Claude Code일 필요는 없지만 오늘은 Claude Code를 씁니다)가 전체 프로젝트 — 코드, 문서, PDF, 이미지, 영상까지 — 를 지식 그래프로 매핑해 파일을 grep하는 대신 그래프를 쿼리할 수 있게 해줍니다.

Graphify를 원하는 저장소에 가리키면 이런 지식 그래프가 만들어집니다. 이게 중요한 이유는 지식 그래프가 생성되면 A가 B에, B가 C에 어떻게 연결되는지, 그리고 그 연결이 왜 중요한지가 이미 정리되어 있기 때문에 Claude Code가 저장소 관련 질문에 훨씬 쉽게 답할 수 있기 때문입니다. 기존의 파일 grep 방식 — Claude Code 같은 AI 코딩 어시스턴트가 보통 동작하는 방식 — 과 대비됩니다. 단순한 비유지만, 마치 Ctrl+F로 검색하는 것 vs 모든 경로가 명확하게 지도로 그려진 것의 차이입니다. Graphify는 Claude Code에 지도를 주는 것이고, grep은 지도가 없는 것입니다.

따라서 Graphify를 쓰면 더 정확한 답변을 더 적은 토큰으로 얻을 수 있습니다. 그 절감 효과가 얼마나 클까요? 일부에서는 70배까지 주장하는데, 저는 그게 좀 높다고 생각하고 오늘 데모에서 보시겠지만 70배보다는 낮습니다. 그래도 여전히 상당한 절감입니다.

동작 방식 — 3패스

코드베이스에서 지식 그래프로 어떻게 만들어지는지, 그리고 이게 Graph RAG 지식 베이스와 어떻게 다른지 알아보겠습니다.

1패스 — 코드 구조 분석 코드 구조를 분석합니다. 비용 없음. 화면에 보이는 모든 것은 이 1패스만으로 만들어집니다. 결정론적이고 AI가 추측하는 방식이 아닙니다. 코드 자체를 보면서 "이 코드가 저 코드와 연결된다"는 것을 파악합니다. 이미 코드베이스에 명시된 연결들입니다. Tree-sitter가 코드 파일을 파싱해 클래스, 함수, 임포트, 콜 그래프, 인라인 주석을 추출합니다. LLM 없이 로컬에서 실행됩니다.

2패스 — 영상·오디오 전사 저장소에 영상·오디오 파일이 있을 때만 실행됩니다. 있다면 faster-whisper로 전사한 후 텍스트를 지식 그래프에 주입합니다.

3패스 — 문서·논문·이미지 코드가 아닌 파일 — PDF, 문서, 이미지 등 — 을 처리합니다. 여기서 대형 언어 모델이 실제로 개입합니다. 의미 분석을 통해 "이 문서가 실제로 무슨 의미인지, 이 큰 지식 그래프의 어디에 위치해야 하는지"를 판단합니다. 이 3패스는 진짜 임베딩 없이 RAG 시스템과 비슷한 역할을 합니다.

이 모든 처리가 끝나면 실제 지식 그래프를 만들기 시작합니다. 노드(동그라미들), 엣지(두 노드를 연결하는 선), 커뮤니티(성격이 유사한 노드들의 대규모 그룹)로 구성됩니다. 화면에 보이는 것은 486개 커뮤니티입니다.

자주 묻는 질문

Q: 코드 구조가 없으면? 마크다운 파일만 가득한 저장소라면? A: 가능합니다. 사실 Graphify로 Obsidian Vault를 만들 수도 있습니다. 마지막에 잠깐 얘기할게요.

Q: GraphRAG랑 매우 비슷해 보이는데, 차이가 뭐고 언제 어느 쪽을 써야 하나? A: 가장 큰 차이는 임베딩입니다. Graphify는 임베딩을 전혀 쓰지 않습니다. 두 번째 차이는 사용 목적입니다. Graphify는 코드베이스에 가장 적합합니다. LightRAG, RagAnything, Microsoft GraphRAG 같은 GraphRAG 시스템은 비정형 데이터 — 수만 건의 PDF나 마크다운 파일처럼 서로 명확하게 연결되어 있지 않은 문서 모음 — 에 더 적합합니다. 예를 들어 정책 문서들이 수십 개 있고 "X에 대한 정책이 뭔가요?"라고 물을 때, 답이 어느 문서에나 있을 수 있고 구조도 없는 경우 — 그게 GraphRAG나 RAG 시스템이 빛나는 상황입니다. 다만 경계는 좀 흐릿합니다. 3패스에서 언급했듯이 Graphify로도 어느 정도 할 수 있어서 "RAG Lite" 시스템에 가깝기도 합니다.

설치 및 커맨드

설치는 상대적으로 간단합니다. 사전 요구사항과 설치 방법이 있습니다. Claude Code를 쓰고 있다면 이렇게 하세요: Graphify GitHub 링크를 복사해서 Claude Code에 붙여넣고 "Graphify 설치해줘"라고 말하면 됩니다. 수동으로 하고 싶으면 단계별로 따라 하면 됩니다. Graphify는 플랫폼 무관이고 모든 코딩 에이전트와 호환됩니다.

커맨드가 꽤 많아서 전부 외우실 필요 없습니다. 설치하면 Graphify skill 파일이 함께 딸려 옵니다. 이 skill이 Claude Code에게 언제 어떤 커맨드를 써야 하는지 자연어 기반으로 가르쳐 줍니다. GitHub 저장소를 어느 정도 살펴보면서 뭐가 가능한지 파악해두면 좋지만 암기는 불필요합니다.

중요한 커맨드 몇 가지: - /graphify (점 포함): 현재 디렉터리 전체 그래프화 - graphify query, graphify explain: 지식 그래프를 명시적으로 참조해 답변 - graphify claude install: 항상 Graphify를 쓰도록 훅 등록 — 명시하지 않아도 자동 사용 - --obsidian 플래그: 한 커맨드로 Obsidian Vault 생성

데모 — Open Design 코드베이스

Open Design(Claude Design의 오픈소스 버전)을 대상으로 데모를 진행합니다. 디렉터리 안에서 /graphify .을 실행합니다.

6분 실행 후 결과: - 파일 203개 처리 - 노드 1,907개, 엣지 3,447개, 커뮤니티 109개 - 출력 토큰 약 120k

결과 요약에는 "God nodes"(가장 많이 연결된 핵심 노드), 예상치 못한 연결(surprising connections), 제안 질문(suggested questions)이 나옵니다.

그래프 시각화를 열면 커뮤니티(클러스터), 노드(점), 엣지(연결선)가 보입니다. 노드를 클릭하면 타입(코드 노드 등), 커뮤니티, 출처, 이웃 노드 정보가 표시됩니다. 하지만 이 시각화가 멋있어 보인다고 해서 핵심은 아닙니다. 진짜 가치는 Claude Code에 지도를 넘겨줬다는 것입니다.

토큰 비교 실험

동일 질문: "web app에서 coding agent까지 design request가 어떻게 흐르는지 추적해줘"

  • Graphify 탭: skill 즉시 로드 → graphify query 실행 → 약 80k 토큰
  • 비Graphify 탭: 탐색 에이전트 2개 생성, 100k 토큰 즉시 소비 + 메인 세션 50k = 약 200k 토큰

답변 품질은 동일했지만 토큰은 약 60% 절감(비Graphify의 40% 수준).

참고: 비Graphify 방식은 이후 동일 세션에서 추가 질문 시 이미 크롤한 내용이 있어 비용이 줄어듭니다. 반면 Graphify는 한 번 만든 지식 그래프를 계속 재사용 — 추가 크롤 비용 없음.

지속 갱신 및 팀 환경

살아있는 저장소라면 업데이트 시 지식 그래프도 갱신됩니다. graphify hook install 실행 → 커밋마다 자동 재빌드. AST 패스만 재실행, API 비용 0원, 완전 결정론적. 팀 환경(두 개발자 병렬 작업)에서도 정상 동작합니다. 결과: 원하는 저장소의 영구적이면서도 항상 최신인 지식 지도 유지.

Graphify는 메모리 인접 도구 스펙트럼에서 Obsidian과 진짜 RAG 시스템 사이 어딘가에 위치합니다. 마크다운만 쓰는 게 아니거나 대형 RAG 인프라가 과하다면 이 중간 지점이 딱 맞는 선택입니다. 올바른 도구를 골라 쓸 수 있다는 게 핵심입니다.
