출력 스타일 (Output Styles) exploratory / learning 모드로 엔지니어가 AI 사용 중에도 학습 가능 /config output-style=exploratory

내가 모를 만한 것 / 처음 보는 것

  • Loops (루프) — Claude.ai 데스크톱의 Routines 기능. 에이전트가 주기적으로 반복 실행되며 코드 리뷰, 피드백 수집, 유지보수 작업 등을 자동화.
  • Co-work (코워크) — 비엔지니어용 Claude Code. Claude 데스크톱 앱 안에 포함. VM 격리, OS 훅, 프롬프트 인젝션 방어 내장. Claude Agent SDK 동일 기반.
  • Fable — Anthropic의 최신 플래그십 모델(Opus 4.8 이후). 누앙스·가설 추론에서 이전 모델 대비 큰 도약. 발표 당시 일부 사용자에게 일시 접근 제한 상태.
  • Dynamic Workflows — Claude가 파이썬 프로그램 형태의 워크플로우를 VM에서 실행해 수백~수천 개 서브 Claude를 동적으로 생성. "use a workflow" 지시어 하나로 활성화.
  • Effort Settings — Claude 모델의 테스트타임 컴퓨트 조절값. low / medium / high / extra-high / max 다섯 단계.
  • Advisor Model 패턴 — 기본 모델을 Opus로 두고 복잡한 작업만 Fable로 위임, 토큰 비용 약 50% 절감.
  • RBAC 기반 토큰 예산 — Claude Code 엔터프라이즈에서 부서별·역할별 토큰 사용량 상한 설정 가능.

화자의 디테일 (놓치기 쉬운 포인트)

Boris가 직접 공개한 수치·설정·뉘앙스.

  1. 8B 토큰 (3월 이후) — Boris 본인이 March 2026 이후 사용한 토큰 총량. 데이터 보존 기한 이후는 확인 불가.
  2. 1,700 PRs, +400K/-250K 줄 — Boris의 연간 코드 기여 규모. 2024년에는 삭제가 더 많았으나 2025년은 추가가 더 많음.
  3. Anthropic 전사 AI 코드 비율 80~90% — 2026년 상반기 기준, 일부 팀은 이미 100%.
  4. 코드 리뷰 병목 해결 수치 — Claude Code Review가 버그 98~99% 포착 주장. 아직 100% 목표로 개선 중.
  5. CI 최적화 실험 — 단 하나의 프롬프트("use a workflow to look at CI timings and optimize CI")로 동적 워크플로우 가동 → 수 시간 실행, 수백만 토큰 소비 → PR 4개, CI 시간 50% 단축.
  6. 프롬프트 인젝션 성공률 1% (100회 시도) — Anthropic system card 기준, 업계 최저 수준 주장.
  7. 보안 Auto Mode 전환 배경 — 내부 엔지니어들이 권한 프롬프트에 무감각해져 "예스맨"이 되는 현상을 보안팀이 포착 → 오히려 보안 저하 → Auto Mode 개발.
  8. 30%가 루프 코드 — Boris 기준 평균적으로 하루 코드의 30%는 루프가 작성. 최선일 때 100% 가능하나 아직 완전히 클릭되지 않음.
  9. Fable 한계 인정 — Product Sense(아이디어 생성)와 분산 시스템 설계는 아직 Boris보다 약함. 연말까지 분산 시스템 설계 대폭 개선 예상.
  10. /config output-style=exploratory — 신규 엔지니어 온보딩 시 강력 권장하는 설정. Claude가 변경 전 아키텍처·언어·코드베이스를 설명.

1. AI 코딩 현황 — Boris의 실제 사용 데이터

Boris는 Opus 4.5 출시(2025년 11월) 이후 IDE를 삭제하고 코드 100%를 Claude Code로 작성. 2026년 현재까지 8B 토큰 사용, 1,700개 PR, +40만/-25만 줄 기록. 대부분의 코딩이 스마트폰에서 이루어지고 있으며, 이는 6개월 전에는 예상하지 못한 변화다.

2. ROI 프레임 — 비용이 아닌 수익

AI 도입 비용을 "월 $1,500 예산" 식으로 통제하려는 접근은 잘못된 프레임. 올바른 접근:

  1. 전사 토큰 개방 — 엔지니어만 아니라 PM·디자이너·데이터 사이언티스트·회계·마케팅 전원에게 토큰 지급. 혁신은 예상 밖에서 나온다.
  2. 실험 안전망 확보 — 실패해도 불이익 없는 환경 조성.
  3. 사용 사례 발굴 후 최적화 — 먼저 사용 사례를 찾고, 규모가 커지면 그때 백엔드에서 비용 통제.
  4. 수익 측정 재정의 — "AI 코드 비율"이 100%에 도달하면 다음 지표는 "엔지니어 1인당 코드량 가속도", 그 다음은 "아이디어 생성 속도"로 이동.

Anthropic 자체도 연초 대비 8배 코드/엔지니어 증가를 기록.

3. Loops — 다음 추상화 계층

소스코드 (statement)
  ↓
에이전트가 코드 작성 (function)
  ↓
루프: 에이전트를 반복 호출하는 에이전트 (higher-order function)

현재 루프는 1.5년 전 에이전트가 있던 위치와 같다 — 초기지만 작동 신호가 보임. Boris의 실제 루프 목록: - 모든 PR의 코드 리뷰 - Threads 피드백을 5~10분마다 읽어 수정 PR 제출 - 코드베이스 아키텍처 개선 / 플레이키 테스트 제거 / 중복 추상화 통합 - 보안 취약점 주간 스캔 및 자율 수정

4. Co-work — 비엔지니어용 Claude Code

Claude 데스크톱 앱 내 포함. Claude Agent SDK 동일 기반이므로 Claude Code와 완전 동일. 비엔지니어 배려 요소: - VM 격리 + OS 훅으로 실수 삭제 방지 - 프롬프트 인젝션 방어 - 브라우저 자동화 내장 (Claude Chrome Extension과 연동)

Boris 실제 사례: - 매일 아침 Slack으로 각 엔지니어에게 상태 묻고 스프레드시트 자동 채움 (Claude끼리 대화) - 여행 일정을 이메일·구글 캘린더에서 읽고 자동으로 항공권·호텔 예약 (도쿄·런던·베를린 Code with Claude 이벤트 전부 자동 처리)

5. Fable 모델 — 누앙스와 차원의 도약

Opus 4.5가 "IDE 삭제 시점"이었다면, Fable(Opus 4.8 이후 신모델)은 그 이상의 도약. - 강점: 가설 기반 디버깅, 데이터 분석의 "왜 3번 묻기", 코딩 원샷 해결 - 아직 약한 부분: 제품 아이디어 생성, 분산 시스템 설계 (연말 개선 예상) - 비용 최적화 팁: Advisor Model 패턴 — Opus 기본 + Fable 위임으로 비용 ~50% 절감 가능. 단 수익 관점에서 최고 모델 사용이 맞다는 결론.

Fable 활용 예: "use a workflow"로 CI 최적화 프롬프트 1개 → 수 시간 실행 → PR 4개 → CI 50% 단축.

6. 엔지니어 역할 변화

코딩이 병목에서 해제된 이후 순서: 1. 코딩 → AI 2. 다음 병목: 좋은 아이디어, 시장 조사, 팀 커뮤니케이션, PM·디자이너 협업 3. 그 다음 병목: 아이디어를 시장에 내보내는 GTM·마케팅 속도 4. 루프 추상화로 이 과정 자체도 점진적 자동화

현재 Boris는 대부분 오디오(음성) 프롬프트로 작업. 병목은 "좋은 아이디어를 얼마나 빠르게 생각해내느냐"로 이동.

7. 코드 리뷰·보안 병목 해결

Claude Code Review: - Anthropic 내부에서 모든 PR에 적용 중 - 타 제품 대비 더 많은 토큰 소비 → 버그 98~99% 사전 포착 - 리뷰어는 "이 PR이 필요한가"만 판단

Claude Security: - 주간 전체 코드베이스 스캔 + 자율 수정 - 신기능 출시 전 Red Teaming + 침투 테스트 - Opus 4.8부터 전문 펜테스터가 놓친 취약점도 발견

8. 동적 워크플로우 vs 루프

구분 루프 동적 워크플로우
정의 에이전트의 반복 실행 스케줄 단일 작업 내 수백~수천 서브에이전트 병렬 오케스트레이션
시간 축 시간에 걸쳐 반복 (5분마다, 매주 등) 단일 실행 내 병렬 확장
비유 반복 함수 실행 분산 병렬 컴퓨팅
활성화 Claude.ai Routines 프롬프트에 "use a workflow"
테스트타임 컴퓨트 관계 루프 자체는 별개 동적 워크플로우 = 새로운 형태의 TTC

기존 테스트타임 컴퓨트 조절은 Effort Settings(low~max)으로 처리.

9. Auto Mode — 권한 프롬프트 피로 해소

기존 문제: 모든 명령 실행 전 yes/no 권한 프롬프트 → 엔지니어가 내용 확인 없이 "예스맨"화 → 보안 저하.

Auto Mode 해결책: - 권한 판단을 모델이 대화 맥락 기반으로 자동 결정 - Dangerous Mode·기본 모드 대비 보안 성능 향상 실증 - 프롬프트 인젝션 성공률 ~1% (100회 시도, system card 기준) - 수 시간~수 일 장시간 에이전트 실행 가능 - Anthropic 내부 기본 모드, 현재 대다수 사용자가 채택

10. Claude Code 비전

  • 주간·월간 단위 계획 (연간 계획 없음 — 지수적 변화 속도 때문)
  • "가장 유능한 에이전트" + "어디서나 작동" + "새 모델 역량을 가장 잘 체험"
  • 장기 실행 작업 리드 유지·확대
  • 코드 품질·보안·정렬(alignment) 지속 개선

청중 질문: AI 코드 폭증으로 코드 리뷰 패러다임이 바뀌고 있는데, 어떻게 생각하나요?

Boris: 코드를 쓰고 → 프로덕션에 가고 → 비즈니스 지표를 만드는 흐름에서 병목이 순서대로 이동합니다.

  1. 코딩 병목 → Claude Code로 해결.
  2. 코드 리뷰 병목 → Claude Code Review로 해결. PR당 버그 98~99% 자동 포착. 리뷰어는 "이 PR이 필요한가"만 판단.
  3. 보안 병목 → Claude Security로 해결. 주간 코드베이스 스캔·자율 수정. Opus 4.8부터 펜테스터도 못 잡는 취약점 발견.
  4. 다음 병목 → 아이디어 생성, CI 최적화.

CI 최적화 예시: 어제 밤 "CI 데이터를 보고 워크플로우로 최적화해" 한 줄 프롬프트 → 수 시간 실행 → PR 4개 → CI 50% 단축.

방향: 가장 유능한 에이전트 → 어디서나 작동 → 새 모델 역량을 가장 잘 체험할 수 있는 방법 제공. 장기 실행 작업 리드를 더 벌릴 것입니다.

청중 질문: 대규모 프로젝트에서 유지보수가 더 큰 문제입니다. 어떻게 처리하나요?

Boris: 루프로 유지보수를 자동화하고 있어요. - 아키텍처 개선 루프 - 플레이키(flaky) 테스트 제거 루프 - 불필요한 테스트 삭제 루프 - 중복 추상화 통합 루프

루프가 PR을 올리면 제가 검토합니다. "use a workflow"를 붙이면 더 많은 테스트타임 컴퓨트를 던져 품질이 높아집니다.

청중 질문: 워크플로우(Workflows)와 루프의 차이가 뭔가요?

Boris: 기존 AI 스케일링 법칙(데이터·신경망 크기·학습 컴퓨트) 외에 최근 추가된 네 번째 요소가 테스트타임 컴퓨트(test-time compute)입니다. 이를 조절하는 두 가지 방법:

  1. 에포트 설정 — low/medium/high/extra-high/max. 토큰 출력량을 조절하는 것.
  2. 동적 워크플로우 — Claude가 VM 안에서 프로그램을 작성해 수십~수천 개 서브 Claude를 오케스트레이션. 새로운 형태의 테스트타임 컴퓨트.

청중 질문: Fable도 어려워하는 문제가 있나요?

Boris: 두 가지 — 제품 아이디어 생성과 분산 시스템 설계. 코딩이나 프론트엔드 디자인은 제보다 잘하지만, 아직 이 두 영역은 제가 우위입니다. 연말까지 분산 시스템 설계는 상당히 좋아질 거라 봐요.

청중 질문: 엔지니어들이 AI 출력을 무비판적으로 승인하는 것을 어떻게 막나요?

Boris: 두 가지로 생각해볼게요.

  1. Auto Mode — 권한 프롬프트를 모델이 맥락 기반으로 자동 판단. 프롬프트 피로로 사람이 오히려 보안을 저하시킨다는 걸 보안팀이 발견했어요. Auto Mode가 더 안전하고, 수 시간 장시간 실행이 가능해집니다. 프롬프트 인젝션 성공률이 ~1%로 업계 최저. Prompt injection classifier도 함께 실행.

  2. 출력 스타일 — exploratory 스타일: 변경 전 아키텍처·언어·코드베이스를 설명. learning 스타일: 직접 변경 대신 단계별 안내로 사용자가 직접 작업하며 학습. 신규 엔지니어 온보딩 시 필수 설정.
