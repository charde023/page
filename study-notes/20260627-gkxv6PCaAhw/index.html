화자의 디테일 (놓치기 쉬운 포인트)

  1. Anthropic 스킬의 SKILL.md에 AI slop 목록이 명시적으로 박혀 있다 — 모델이 과용하는 폰트, 보라 그라디언트+흰 배경 조합이 직접 금지 목록으로 기재돼 있음. 스킬이 "올바른 방향을 선택하도록" 강제하는 방식이 흥미롭다.
  2. Anthropic 스킬은 기능 UI(앱 내부)에는 맞지 않는다 — 랜딩페이지·포트폴리오처럼 디자인 자체가 제품인 곳에만 효과적. 실제 앱 UI(대시보드 등)에는 shadcn으로 넘어가야 한다.
  3. shadcn skill vs shadcn MCP의 차이 — MCP는 컨텍스트 창에 항상 올라가 있고, 스킬은 필요할 때만 로딩된다. 스킬은 규칙·패턴·프로젝트 컨텍스트를 제공해 MCP가 컴포넌트를 올바르게 쓸 수 있는 판단력을 주는 역할. 둘은 보완 관계.
  4. Opus 4.8과 Fable 5의 프롬프팅 가이드 — 화자가 "Claude가 바뀌었고 주는 지침도 바뀌어야 한다"며 자사 마케팅 UI 스킬에 이를 반영했다고 언급. Anthropic 원본 스킬이 새 모델에서 "약간 구식"이라는 평가.
  5. GSAP 성능 팁: transform/opacity만 써야 한다 — AI가 만든 애니메이션이 끊기는 이유가 width·height·position 변경 → 브라우저가 매 프레임 전체 페이지를 다시 렌더링하기 때문. GSAP 스킬이 모델을 브라우저가 쉽게 처리하는 transform·opacity 위주로 유도한다.
  6. UI UX Pro Max는 5개 검색을 동시에 돌린다 — GitHub의 오픈소스 DB 161개 업종 카테고리에서 병렬 검색, 필터링 후 색상 팔레트·폰트 조합·페이지 레이아웃을 도출. 다른 스킬들이 "모델의 취향을 개선"하는 방식이라면 이건 "결정 자체를 내려주는" 방식이 다르다.
  7. Material 3 스킬은 색상 하나로 전체 테마를 생성한다 — 하나의 시드 색상을 넣으면 스킬이 Google 가이드라인에 맞는 전체 색상 팔레트를 완성.
  8. SwiftUI 스킬은 Mac의 Xcode에서 Apple 공식 문서를 직접 꺼낸다 — 단순히 "Apple 스타일로"가 아니라 실제 Apple 문서를 룰로 쓰기 때문에 네이티브 느낌이 난다는 것이 핵심.

1. AI 디자인 수렴 문제 — 왜 다 똑같아 보이나

모델은 방대한 데이터에서 학습했고, 디자인 결정을 내릴 때 가장 흔한 패턴으로 수렴한다. 프로젝트가 뭔지 관계없이 "안전한 기본 선택"으로 기운다. 결과: 다 다른 사이트인데 느낌이 같다.

해결책은 모델에게 취향이나 후처리를 시키는 게 아니라, 코드 쓰기 전에 디자인 방향을 확정하도록 강제하는 것이다. 스킬(Skill)이 바로 그 역할이다.

2. Anthropic front-end design skill — 랜딩페이지의 기반

  • SKILL.md 안에 AI가 남발하는 패턴(보라 그라디언트+흰 배경, 특정 과용 폰트 등)이 직접 금지 목록으로 박혀 있다.
  • 모델이 "올바름"을 최적화하는 대신 디자인 방향을 확정하고 일관되게 유지하도록 유도한다.
  • 적합 용도: 랜딩페이지, 포트폴리오 — 디자인 자체가 제품인 곳.
  • 부적합 용도: 대시보드, 앱 내부 UI — 기능 UI로 넘어가면 문제의 성격이 달라진다.
  • Ailabspro 팀은 이 스킬을 기반으로 마케팅 UI 스킬을 만들되, Opus 4.8·Fable 5 프롬프팅 가이드를 반영해 수정했다(원본이 새 모델에 맞지 않는 부분이 생겼기 때문).

3. shadcn skill + shadcn MCP — 대시보드·앱 UI

앱을 만들 때 필요한 컴포넌트(버튼, 테이블, 입력창 등)는 이미 전문가들이 높은 수준으로 만들어 놓았다. 모델이 처음부터 직접 만들 이유가 없다.

shadcn/ui는 그 라이브러리다. 컴포넌트를 npm 패키지로 설치하는 게 아니라 코드를 직접 가져오는 방식으로, 자유도가 높다.

  • shadcn skill — shadcn의 올바른 사용 규칙 + 내 프로젝트 구조를 모델에게 주입. 한 번에 깔끔한 결과물을 내도록 실수를 사전 차단.
  • shadcn MCP — 레지스트리(컴포넌트 모음)에 실시간 연결해 컴포넌트를 프로젝트에 직접 가져온다.
  • 둘의 관계: MCP는 항상 컨텍스트에 올라가 있지만, 스킬은 필요할 때만 로딩. 스킬이 "판단력"을 주고, MCP가 "부품"을 가져오는 구조. 함께 써야 제대로 된 결과가 나온다.

4. dashboard skill — 정보 배치 전문

대시보드는 일반 앱과 다른 핵심 문제를 가진다: 컴포넌트 일관성보다 정보 배치·그룹화·밀도가 어렵다.

  • shadcn과 별개 개발자가 만든 스킬로, 모델이 레이아웃 구조를 먼저 추론하게 유도한다.
  • 결과물이 "컴포넌트 모음"이 아닌 실제 분석 도구처럼 느껴지게 된다.

5. UI UX Pro Max — 업종별 디자인 시스템 자동 결정

다른 스킬들이 "모델의 취향을 개선"하는 방식이라면, 이 스킬은 결정 자체를 먼저 내린다.

작동 방식: 1. 요청을 받으면 코드로 바로 가지 않고 내부 엔진을 먼저 돌린다. 2. GitHub의 오픈소스 DB에서 5개 검색을 동시에 실행. 3. 161개 업종 카테고리 중 맞는 스타일을 선별. 4. 색상 팔레트, 폰트 조합, 페이지 레이아웃을 결정. 5. 해당 제품 유형에 어울리지 않는 선택지를 필터링. 6. 완성된 디자인 시스템(모델이 따를 룰북)을 건네줌.

결과: 모델이 디자인을 "발명하고 잘 되길 바라는" 대신, 해당 업종에 맞게 추론된 디자인 시스템에서 출발한다.

6. GSAP skill — 애니메이션

AI가 만든 애니메이션의 두 가지 문제: 1. 단조로움 — 스크롤하면 요소들이 위에서 나타나는 reveal 하나뿐. 2. 성능 불량 — width·height·position을 바꿔 브라우저가 매 프레임 전체를 다시 렌더링 → 끊김.

GSAP은 전문 사이트가 실제로 쓰는 애니메이션 라이브러리. 스킬이 직접 팀에서 나왔으므로 올바른 패턴을 그대로 쓴다.

  • 기본 이동부터 스크롤 연동 대형 애니메이션까지 커버.
  • 브라우저가 쉽게 처리하는 transform·opacity 위주로 모델을 유도 → 끊김 방지.
  • 랜딩페이지·스크롤 스토리텔링에 특히 효과적.

Ailabspro 팀은 마케팅 UI 스킬 내부에 "애니메이션 필요 시 반드시 GSAP 스킬 사용"을 명시해 뒀다.

7. 스타일 taste 스킬 4종 — 분위기 프리셋

전체 시스템이 아닌 "분위기 방향" 프리셋. 하나만 골라 쓴다.

전체 전사 펼치기

사람들이 자주 틀리는 부분이 있다. 모델들은 디자인 면에서 날로 좋아지고 있고 매일 개선되는 걸 볼 수 있다. 그런데 어느 순간부터 그 훌륭한 디자인들이 죄다 똑같아 보이기 시작한다. 진짜 질문은, 내 디자인을 어떻게 실제로 튀게 만드느냐다.

그 상당 부분이 올바른 프롬프트와 지침에 달려 있다. 이게 바로 스킬(Skill)이 등장하는 이유다. 이제 실제로 잘 동작하는 것들을 패키지화해 누구와도 공유할 수 있는 재사용 가능한 워크플로로 만들 수 있다. 많은 사람들이 디자인용 스킬을 만들어왔고, 특히 좋은 것들은 해당 도구를 만든 팀에서 직접 나온다. 다만 모든 스킬이 쓸 만하진 않고, 디자인에 별 도움이 안 되는 것도 많다.

배경 설명을 하자면, 우리는 소프트웨어 회사이고 이 채널 AI Labs에서 AI로 프로세스를 최적화하는 방법을 보여준다. 우리가 자체적으로 최적화한 것들처럼.

좀 더 창의적인 스킬로 들어가기 전에, 다른 디자인 스킬들의 기반이 되는 것부터 시작하자. Anthropic의 프론트엔드 디자인 스킬(Anthropic's front-end design skill)이 사이트의 디자인 방향을 잡아주는 역할을 한다. 이전 영상에서도 사용했다.

AI로 랜딩페이지를 충분히 만들다 보면 패턴이 보이기 시작한다. 사이트들은 다 다른데 어딘가 느낌이 똑같다. 모델이 같은 패턴들로 가득 찬 방대한 데이터로 학습했기 때문이다. 그래서 디자인 결정을 내릴 때 가장 흔한 것으로 간다. 프로젝트가 실제로 어떤 것이든 상관없이 안전하고 평범한 선택으로 계속 수렴한다.

이 스킬이 정확히 그 문제를 해결한다. 모델이 코드를 쓰기 전에 실제 디자인 방향을 확정하도록 강제해서 안전한 선택에서 탈출한다. 안전한 공통된 외관을 기본값으로 삼는 대신, 방향을 선택하고 일관되게 유지하게 된다. 스킬의 SKILL.md — 기본적으로 스킬의 지침서 — 파일 안에 AI slop 목록을 직접 기재해뒀다. 그래서 모델이 같은 남발 폰트나 보라 그라디언트+흰 배경 조합으로 가지 않게 된다.

이게 생각보다 중요하다. 대부분의 모델이 랜딩페이지를 만들 때 "올바름"을 최적화하기 때문이다. 하지만 이 스킬은 대신 디자인 방향을 확정하도록 밀어붙인다. 그래서 우리는 주로 랜딩페이지나 포트폴리오에 쓴다 — 디자인 자체가 제품의 일부인 곳에서. 시작 전에 모델에게 더 강한 관점을 주기 때문이다.

테스트로 요구사항을 주고 랜딩페이지를 만들게 했더니, 확정한 디자인 방향을 유지하면서 일반적인 AI slop 없이 사이트를 생성했다.

AI Labs의 디자인 시스템에는 두 가지 스킬이 있다. 각각 별도의 역할을 위한 것이다. 하나는 대시보드처럼 실제로 사람들이 사용해야 하는 기능 UI를 만드는 기능 스킬, 그리고 마케팅 UI를 위한 것. 마케팅 스킬 내부의 SKILL.md는 "break the default(기본값 탈출)"라는 프롬프트를 사용하는데, 이게 기본적으로 Anthropic의 프론트엔드 디자인 스킬을 약간 수정한 것이다. 원본이 최신 모델에 맞게 약간 구식이 됐기 때문에 수정했다. Opus 4.8과 Fable 5 [?Fable 5] 모두 Claude가 어떻게 바뀌었는지, 그리고 주는 지침도 어떻게 바뀌어야 하는지를 보여주는 프롬프팅 가이드와 함께 출시됐다. 그걸 우리 자체 디자인 시스템에 반영했다.

이미 말했듯이 Anthropic 디자인 스킬은 기능 UI에는 잘 맞지 않는다. 실제 제품을 만들기 시작하면 문제가 완전히 바뀐다. 더 이상 뭔가를 예쁘게만 만들려는 게 아니다. 제대로 동작해야 하는 컴포넌트가 많은 제품으로서 작동하도록 만들어야 한다. 랜딩페이지에서 실제 애플리케이션으로 전환되는 지점이다.

예를 들어 AI Labs Pro에서 랜딩페이지는 훨씬 예술적인 디자인 언어를 갖고 있지만, 커뮤니티의 실제 기능 레이어는 지금까지 상호작용해온 다른 웹 인터페이스처럼 정말 평범하고 단조롭다. 그리고 여기서 shadcn이 등장한다.

모델이 대시보드를 혼자 만들 수 있다. 하지만 대시보드에서 흔히 쓰이는 모든 컴포넌트는 이미 실제 사람들이 전문적인 수준으로 만들어놨다. 그러니 모델이 처음부터 컴포넌트를 생성하고 혼자 애니메이션을 설정할 필요가 없다. 기본적으로 이미 만들어진 컴포넌트들의 큰 라이브러리인 레지스트리에서 이미 미리 만들어진 컴포넌트를 가져오면 된다. 그게 shadcn의 전부다.

모델이 각 컴포넌트를 손으로 만드는 대신, 이미 전문 수준으로 만들어진 부품 라이브러리에서 가져와 앱에 사용한다. 그래서 결과물이 실제 제품처럼 느껴진다. 거친 초안에서 시작해 천천히 고쳐나가는 게 아니라, 이미 출시 수준으로 만들어진 부품에서 시작하기 때문이다.

shadcn 설정은 함께 동작하는 두 부분으로 이루어진다. 첫 번째는 스킬. 규칙집이라고 생각하면 된다. shadcn에는 올바른 빌드 방법이 있고 스킬이 그 규칙들을 전부 담고 있다. 그 위에, 내 프로젝트가 어떻게 설정돼 있는지도 확인한다. 그래서 모델에게 뭔가 만들어달라고 하면, 스킬이 shadcn의 규칙을 따르고 내 프로젝트가 이미 동작하는 방식에 맞게 결과물을 만들도록 한다. 이점은 단순하다. 같은 실수를 반복해서 고칠 필요 없이 처음에 깔끔한 결과물이 나온다.

두 번째는 shadcn MCP다. shadcn 레지스트리에 실시간으로 연결해 모델이 실제 컴포넌트를 프로젝트에 직접 가져올 수 있게 해준다. MCP가 이미 있는데 왜 스킬도 쓰냐고 할 수 있다. 답은, 스킬은 MCP처럼 항상 컨텍스트 창에 있지 않고 실제로 필요할 때만 로딩된다는 것이다. shadcn 스킬이 코딩 에이전트에게 규칙·패턴·프로젝트 컨텍스트를 준다. 그게 합쳐져서 컴포넌트를 올바르게 쓸 수 있는 판단력이 생긴다.

일반 앱은 컴포넌트를 하나씩 쌓아가며 만들고, 그 방식이 잘 된다. 그래서 대시보드에도 그대로 적용될 거라 생각할 수 있다. 어느 정도는 맞다. 하지만 대시보드는 일반 앱과 다른 핵심 문제가 있다. 컴포넌트를 일관되게 유지하는 것보다 화면에 정보를 어떻게 배치하느냐가 더 중요하다. 데이터를 어떻게 그룹화하고, 지저분해지기 전에 한 화면에 얼마나 담을 수 있는지 결정해야 한다. 그래서 dashboard 스킬이 따로 있다. shadcn이 아닌 다른 개발자가 만들었고, 정확히 그 배치 문제에 모델을 집중시킨다. 그리고 먼저 배치를 추론하기 때문에 결과물이 지저분한 게 아니라 실제 분석 도구처럼 느껴진다.

UI UX Pro Max는 지금까지와는 다르게 동작한다. 대부분의 스킬은 모델에게 디자인 원칙을 주고 적용하도록 신뢰하지만, 이건 먼저 실제 엔진을 돌린다. 이 스킬이 해결하는 문제는, 좋은 방향과 탄탄한 컴포넌트 세트가 있어도 모델이 어떤 종류의 디자인 선택이 제품에 맞는지 결정해야 한다는 것이다. 대부분의 스킬은 디자인을 "좋은 것의 일반적 개념"으로 다뤄서, 뭘 만들든 같은 외관으로 수렴한다. 이 스킬이 그 간극을 메운다. 뭔가 만들어달라고 하면 바로 코드로 가지 않고 먼저 엔진을 돌린다. 이 엔진이 GitHub의 오픈소스 DB에서 다섯 가지 검색을 한 번에 실행한다. 161개 업종 카테고리에서 제품에 맞는 스타일을 뽑고, 그중에서 색상 팔레트·폰트 조합·페이지 레이아웃을 골라 실제로 만들고 있는 업종에 맞게 조율한다. 그런 다음 그 종류의 제품에 어울리지 않는 걸 필터링하고, 모델에게 맞춤 디자인 시스템을 건네준다 — 기본적으로 웹사이트를 만들 때 모델이 따르는 완전한 규칙집이다.

그래서 모든 디자인 속성이 웹사이트 아이디어에 맞는 진짜 강한 웹사이트가 나온다. 모델이 디자인을 발명하고 잘 되길 바라는 대신, 실제 사용 사례에 맞게 추론된 것에서 출발한다. 이 스킬은 다른 것들과 진짜 다르다. 다른 것들은 모델에게 더 나은 취향을 주는 반면, 이건 시작 전에 결정을 내려준다 — 실제 만들고 있는 제품의 종류에 맞게 조율된.

(광고 섹션 생략)

지금까지 추가한 것들은 사이트가 멈춰 있을 때 제대로 보이게 만들어준다. 하지만 정적 페이지는 여기까지다. 애니메이션은 실제로 중요하다. 사용자 경험을 높이고 사이트 체류 시간도 늘려주기 때문이다. 문제는, 애니메이션이 AI 생성 코드가 무너지는 지점이라는 것이다. 모델에게 애니메이션을 추가해달라고 하면, 거의 항상 똑같은 걸 한다 — 스크롤하면 요소들이 뷰에 나타나는 것. 그 스크롤 reveal 하나가 유일한 수다. 그런데 그게 AI가 만든 사이트 절반에서 보이는 것과 같은 애니메이션이고, 실제 모션이 할 수 있는 것과는 거리가 멀다.

여기서 GSAP 스킬이 등장한다. GSAP(GreenSock Animation Platform)은 많은 전문 사이트들이 실제로 쓰는 애니메이션 라이브러리이고, 이 스킬은 직접 만드는 팀에서 나왔다. 그래서 모델이 어떻게 동작하는지 추측하는 대신, 올바른 패턴으로 작업한다. 기본 이동부터 스크롤하면서 펼쳐지는 큰 애니메이션까지 커버한다. 성능 면도 처리하는데, 사람들이 가장 과소평가하는 부분이다. AI 애니메이션이 끊기는 큰 이유는 모델이 크기나 위치를 변경해 이동시키기 때문이다. 그 변경들이 브라우저를 매 프레임마다 전체 페이지를 다시 그리게 강제한다. 그래서 스킬이 모델을 브라우저가 쉽게 처리할 수 있는 종류의 움직임으로 유도하고, 그 하나의 습관만으로 애니메이션이 매끄러워진다.

GSAP은 랜딩페이지와 스크롤 스토리텔링에서 최고다 — 모든 게 이야기처럼 펼쳐지면서 중요한 디테일이 뷰어에게 착지하는. 그게 사이트를 정적에서 동적으로 바꾼다. 그래서 AI Labs 디자인 시스템에서 마케팅 UI 스킬 내부에 "애니메이션이 필요할 때는 반드시 GSAP 스킬을 사용해 랜딩페이지 애니메이션을 구현"한다고 명시해뒀다.

다음 스킬 그룹은 전체 시스템이 아닌, 모델을 원하는 하나의 특정 외관으로 밀어붙이는 취향 프리셋이다.

첫 번째는 미니멀리스트 UI(minimalist UI). 페이지에 너무 많은 걸 쑤셔넣는 대신 단순하고 열린 상태를 유지하는 디자인 유형이다. 내용이 주목을 위해 경쟁하는 게 아니라 숨쉬게 하고 싶은 신문이나 블로그 사이트에 쓴다.

정반대에는 인더스트리얼 브루탈리스트 UI(industrial brutalist UI) 스킬이 있다. 그 반기업적 스타일로 거칠고 무겁다. 그다음 front-end UI UX — 극단적인 걸 원하지 않을 때 탄탄한 기본값을 위한 일반 올라운더. 그냥 깔끔하고 전문적으로 보여야 하는 제품이나 비즈니스 랜딩페이지의 안전한 선택이다. 그리고 프리미엄 프론트엔드 UI(premium front-end UI) 스킬은 사이트를 명품 패션 브랜드 랜딩페이지처럼 보이게 만든다.

이것들을 한꺼번에 쌓지는 않는다. 대신 원하는 분위기에 맞는 하나를 고르고 디자인을 조종하게 둔다. 머릿속에 이미 방향이 있다면, 모델에게 그걸 가장 빠르게 전달하는 방법이다.

이 시점이면 구조가 좋고, 잘 움직이고, 진짜 스타일이 있는 사이트를 만들 수 있다. 하지만 전문가 수준의 웹사이트엔 애니메이션 이상의 것이 필요하다. 실제 이미지와 영상 비주얼이 필요하다. 모델들은 혼자서는 대부분 인터넷에서 스톡 이미지를 가져오는데, 대부분 필요한 것과 맞지 않는다. Higgs Field가 그걸 건너뛰게 해준다. 이미지와 영상 생성을 에이전트 안에 바로 연결해줘서, 터미널을 벗어나지 않고 히어로 이미지나 배경 클립을 요청할 수 있다. Higgs Field는 하나의 모델에 묶여 있지 않다. 좋은 이미지·영상 모델 대부분을 지원한다. 영상을 한다면 Seedance가 현재 최고 수준의 영상 생성 모델이라서 실제 비주얼이 나온다.

이전 스킬들은 모두 웹 용이었다. 이제 모바일 스킬을 다룬다. AI가 만든 모바일 UI는 조용히 무너지는 경우가 많다. 단순한 이유가 있다 — 모델이 폰을 작은 웹사이트처럼 다루면서 같은 웹 습관을 축소해서 적용하는 경향이 있다. 하지만 모바일은 더 작은 웹이 아니다. 자체 규칙이 있다. 사람이 폰을 잡는 방식, 엄지가 실제로 닿을 수 있는 곳, 내비게이션이 어떻게 작동해야 하는지 — 다 다르다. 그리고 모든 플랫폼에는 모델이 보통 제대로 따르지 않는 고유한 디자인 언어가 있다.

모바일 개발을 최적화하는 스킬이 여러 개 있다. 첫 번째는 모바일 앱 UI 디자인(mobile app UI design) — 원칙 레이어. 혼자서는 모델이 좋은 모바일 디자인의 규칙을 꽤 느슨하게 다룬다. 하지만 이 스킬이 직접 그것들을 내재화한다. 엄지가 실제로 닿는 곳에 주요 버튼을 유지하는 thumb zone, 일관된 간격, 10가지 다른 크기 대신 깔끔하고 제한된 폰트 크기 세트 등. 이것들은 기본적으로 Airbnb·Duolingo·Spotify 같은 인기 앱 뒤의 같은 규칙들이다. 그래서 모델이 추측하는 대신 그 감각으로 디자인하게 된다.

두 번째는 Material 3 — 기본적으로 shadcn이 웹에서 한 것의 모바일 버전이다. 모델에게 대부분의 Android·Pixel 앱 뒤의 Google 실제 디자인 시스템을 준다. Google의 디자인 언어는 진짜 개성이 있다. 굵고 색채가 풍부하며 큰 둥근 형태와 탄성 있는 모션이 모바일 디자인의 표현적인 쪽에 자리한다. 스킬이 컴포넌트와 색상의 전체 시스템을 가져온다. 그래서 색상 하나를 주면 완전히 맞는 전체 테마를 만든다. 심지어 앱이 Google 가이드라인을 얼마나 따르는지 확인한다. 그래서 만드는 앱이 디자인 시스템을 정확히 따른다.

iPhone에서 완전히 네이티브로 만든다면 SwiftUI 스킬을 쓸 수 있다. Apple의 디자인은 Google과 정반대에 있다. Material이 굵고 색채가 풍부하다면, Apple은 더 절제되고 이제 Liquid Glass라고 부르는 반투명 유리 느낌에 기댄다. 스킬이 Mac의 Xcode에서 Apple 자체 문서를 직접 꺼내 모델에게 규칙으로 건네준다. 그래서 모델이 Apple 앱이 어때야 할지 추측하는 게 아니라, Apple의 실제 지침에서 작업한다. 대충 iPhone 앱처럼 보이는 것 대신, 실제로 네이티브하게 느껴지는 것이 나온다.

iPhone과 Android를 동시에 만든다면 공식 Expo 스킬이 있다. Expo는 Android·iOS 모두에서 실행되는 하나의 앱을 만드는 프레임워크다. 그래서 같은 앱을 두 번 만들지 않는다. 내비게이션·스타일링·플랫폼 기능까지, 두 플랫폼에서 실행되는 실제 앱에 필요한 모든 것을 한 곳에서 커버한다.

한 플랫폼이든 동시에 두 곳이든, 실제로 그 영역을 아는 스킬이 있다.

우리가 만들고 영상에서 보여주는 모든 스킬·워크플로는 커뮤니티인 AI Labs Pro에서 찾을 수 있다. 리소스·스타터팩과 함께 우리 팀을 포함한 같은 생각을 가진 사람들과 교류할 수 있다. 링크는 설명란에.
