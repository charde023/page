Claude Code에 Hermes Agent를 연결하면 정말 놀랍습니다

한 줄 요약

Hermes Agent를 Claude Code의 MCP 서버로 연결하면, self-evolving 스킬과 지속 메모리를 통해 Claude Code만으로는 불가능한 완전 자율 자동화 워크플로우를 구현할 수 있다.

내가 모를 만한 것 / 처음 보는 것

  • Nous Research — 오픈소스 AI 선도 연구소. Hermes Agent의 제작사. OpenCode보다 먼저 개발.
  • Hermes Agent — Nous Research의 퍼스널 에이전트 프레임워크. OpenCode와 동일 기능 + 지속 메모리 + self-evolving 스킬.
  • Skill Hub — Hermes의 공식 스킬 마켓플레이스. 90개 사전 설치 스킬 포함. 각 스킬은 보안 스캔 통과.
  • OpenCode (전사에서 "OpenClaw"로 오인식) — Hermes와 비교 대상이 되는 에이전트 프레임워크. 메모리 무제한 증가, 샌드박스 미지원이 단점.
  • PRD 스킬 — Product Requirements Document를 에이전트 스킬로 관리. 팀 채널 논의를 자동 반영해 진화.
  • VPS (Virtual Private Server) — 개인이 임대해 운영하는 서버. Hermes 배포 옵션 중 하나.
  • Cron Job — 일정 주기로 자동 실행되는 예약 작업. Hermes에서 에이전트에게 직접 요청 가능.
  • hermes mcp serve — Hermes를 MCP 서버로 띄우는 커맨드. 터미널 출력 없이 백그라운드 실행.
  • .mcp.json — Claude Code 프로젝트의 MCP 서버 설정 파일. 프로젝트 스코프 또는 루트 .claude 경로로 전역 등록 가능.

화자의 디테일 (놓치기 쉬운 포인트)

  1. Hermes는 user.md와 memory.md 파일 크기에 강제 토큰 상한을 둔다. 상한 초과 시 모델이 파일을 직접 검토해 오래되거나 불필요한 내용을 삭제한다.
  2. OpenCode 스킬은 보안 검증 없이 배포되어 데이터 외부 전송 스크립트가 포함된 사례가 있었다. Hermes Skill Hub는 각 스킬에 보안 스캔을 강제 적용한다.
  3. Anthropic이 6월 15일부터 Claude 구독으로 서드파티 앱(Hermes 포함) 연결 시 별도 Agent SDK 크레딧 과금 정책을 적용 예정. 현재도 일부 계정에서 이미 요구하기 시작했다고 언급.
  4. Claude Code의 non-interactive 모드 — 허가 프롬프트 없이 백그라운드에서 Claude Code를 실행하는 모드. 에이전트 자동화에 핵심. 이 모드도 6월 15일 이후 과금 대상.
  5. Slack MCP의 제약: 기본적으로 태그된 메시지만 읽고 전체 대화 히스토리를 가져오지 않는다. 그래서 Hermes 에이전트를 통해 직접 동기화하는 방식이 더 낫다.
  6. Hermes를 MCP 서버로 실행하면 이미 연결된 모든 앱(Discord, Slack 등)을 다른 에이전트가 별도 연결 없이 Hermes를 통해 재사용 가능.
  7. 헬스체크 스킬이 이슈를 발견하고 스킬을 업데이트하면 로컬 프로젝트에 자동 동기화 설정 가능. Claude Code도 해당 맥락을 유지.
  8. Hermes 설치 시 OpenCode 설정 import 옵션 제공. 단, 채널/크레덴셜/soul 파일이 OpenCode 전용으로 작성되어 그대로 가져오면 문제 발생 — 화자는 import 안 함.
  9. 에이전트 온보딩: 한 달 동안 대화하며 자연스럽게 학습시키거나, Second Brain(옵시디언 볼트) 경로를 직접 전달해 즉시 온보딩 가능.
  10. Mac Mini를 Hermes 전용 서버로 사용 중이라고 언급. 기업 AI B2B SaaS 자금 소진으로 Mac Mini 구매 영향 없었다는 자조적 코멘트.

1. Hermes Agent vs OpenCode — 왜 더 나은가

Hermes Agent는 Nous Research가 개발한 퍼스널 에이전트로, OpenCode와 유사한 기능 세트를 갖추되 두 가지 핵심 기능이 추가된다: 지속 메모리(Persistent Memory)와 Self-evolving Skill 시스템.

Nous Research 팀이 OpenCode를 직접 사용하다 문제를 겪고 직접 만든 것이 Hermes다. 오픈소스로 공개되어 있으며 Nous Research의 가장 인기 있는 프로젝트 중 하나.

주요 차이점: - 메모리: OpenCode도 지속 메모리가 있지만 무제한 증가. Hermes는 파일 크기 상한 → 자동 정리. - 스킬: Hermes는 대화에서 재사용 가능한 워크플로우를 자동으로 스킬화. - 보안: OpenCode는 샌드박스 없음. Hermes는 기본 샌드박스 격리 실행.

2. 지속 메모리와 컨텍스트 관리

모델은 컨텍스트 윈도우 안의 모든 정보(프롬프트, 툴, 시스템 인스트럭션, 첨부 파일)가 동시에 경쟁한다. 정보가 많을수록 모델의 실제 작업 집중도는 낮아진다.

Hermes의 해법: user.md와 memory.md에 토큰 상한 설정. 대화마다 파일 업데이트, 상한 도달 시 모델이 직접 검토해 오래되거나 불필요한 정보를 제거. 최신 정보만 유지.

OpenCode는 이 과정이 없어 메모리가 계속 쌓인다.

3. Hermes 설치 및 초기 설정

터미널에서 설치 커맨드 실행 → 의존성 설치 → 인터랙티브 인스톨러 실행.

설정 옵션: - Nous Plan (Nous 모델/빌트인 툴) 또는 Manual 선택 → Manual 권장 - OpenCode 설정 import 여부 → 크레덴셜·채널·soul 파일이 OpenCode 전용으로 작성되어 있어 import 시 문제 발생. 화자는 미import. - 모델 선택 (Anthropic Claude 등). 단, 6월 15일 이후 구독 연동에 추가 과금 정책 적용 예정. - 실행 위치: 호스팅 / VPS / 로컬 중 선택 - 메시징 플랫폼 연결 (Discord, Slack 등)

에이전트 온보딩: hermes 명령어로 UI 실행 후 자기소개 직접 입력 또는 옵시디언 Second Brain 경로 전달로 자동 학습.

4. Skill Hub와 보안

Hermes의 공식 스킬 마켓플레이스. 90개 사전 설치 스킬 포함. 각 스킬은 Nous Research가 유지관리하며 보안 스캔 필수 통과.

OpenCode 스킬의 문제: 외부 서버로 데이터를 전송하는 악성 스크립트가 포함된 사례 존재. Hermes Skill Hub는 이를 자동 감지.

5. Hermes를 MCP 서버로 실행 — Claude Code 연결

hermes mcp serve

터미널 출력 없이 MCP 서버로 백그라운드 실행. .mcp.json에 Hermes MCP를 추가하면 Claude Code에서 Hermes의 모든 기능을 툴로 호출 가능.

// .mcp.json (프로젝트 스코프) 또는 루트 .claude 경로에 추가 (전역)
{
  "mcpServers": {
    "hermes": { ... }
  }
}

이 연결로 Claude Code가 얻는 것: - Hermes의 지속 메모리와 self-evolving 스킬 - 이미 연결된 모든 앱(Discord, Slack 등) 별도 설정 없이 재사용 - Claude Code 전용 스킬(Hermes에 번들 포함)

6. Slack 채널 모니터링 + PRD 자동 갱신

팀 Slack 워크스페이스에 연결한 후, 특정 프로젝트 채널을 30분 cron job으로 모니터링하도록 Hermes에게 지시.

워크플로우: 1. Hermes가 채널 메시지에서 요구사항 논의 감지 2. PRD 스킬 자동 생성/갱신 3. 스킬이 필요할 때마다 컨텍스트에 자동 로드 → 프로젝트가 원래 요구사항에서 벗어나지 않음

Slack MCP 직접 사용 대신 Hermes를 통하는 이유: Slack MCP는 기본적으로 태그된 메시지만 읽고 전체 히스토리를 가져오지 못하는 제약이 있음.

7. 배포 앱 헬스체크 — Self-evolving 스킬 적용

Claude Code로 빌드한 배포 앱에 Hermes 헬스체크 스킬 부착: 1. Claude Code가 앱 컨텍스트를 가장 잘 알기 때문에 Claude Code가 헬스체크 스킬 정의 2. 스킬을 Hermes에 import → cron job 설정 3. 에이전트가 스케줄에 따라 앱과 코드 모두 모니터링 4. 이슈 발견 시 스킬 업데이트 → 로컬 프로젝트에 동기화 → Claude Code도 최신 컨텍스트 유지 5. Discord로 리포트 전송, 팀원 수정 제안도 Claude Code 내에서 직접 구현 가능

스킬이 실행될 때마다 스스로 개선되는 것이 self-evolving의 핵심.

전체 전사 펼치기

아마 이미 들어봤겠지만, Hermes 에이전트는 현존하는 가장 강력한 퍼스널 에이전트다. 실제로 OpenCode(전사: OpenClaw)보다 훨씬 뛰어나게 만드는 수많은 기능을 갖추고 있다. 그렇다면 이걸 최고의 코딩 에이전트 중 하나인 Claude Code(전사: CloudCode)와 연결하면 어떻게 될까?

Claude Code만으로도 훌륭하지만, Hermes 에이전트의 self-evolving 스킬 시스템이 빠져 있다. 이 스킬 시스템을 더하면, 우리가 자동화될 것이라 생각지 못했던 일들까지 훨씬 더 자율적인 워크플로우를 만들 수 있다. 퍼스널 에이전트 용도 외에도, 프로세스를 자동화하려는 어떤 비즈니스에도 쉽게 적용 가능하다.

Hermes 에이전트가 처음인 분들을 위해 처음부터 안내할 것이다. 셋업으로 들어가기 전에, 왜 self-evolving 스킬 시스템이 중요한지 먼저 살펴보자.

처음 접했을 때 OpenCode보다 더 나을 수 있겠다고 생각했다. 단순한 프로젝트가 아니라, Nous Research(전사: Noose Research)가 만든 것이다. 오픈소스 AI 분야의 선도 연구소로, Hermes는 그들의 가장 인기 있는 프로젝트 중 하나가 됐다.

흥미로운 점은, Hermes 에이전트가 OpenCode보다 먼저 만들어졌다는 것이다. 처음엔 크게 주목받지 못했을 뿐이다. Nous Research 팀도 OpenCode를 써봤는데 문제가 생겨서 자체 솔루션으로 전환했다. 문제를 직접 겪고 해결책을 오픈소스로 공개한 것이다.

Hermes의 대부분 기능은 OpenCode와 동일하다. 다중 플랫폼 연결도 같다. 하지만 두 가지가 다르다. 첫째는 지속 메모리(Persistent Memory), 둘째는 자기 개선 스킬(Self-improving Skills)이다.

OpenCode도 지속 메모리가 있어 사용자 정보를 기억하고 답변을 맞춤화할 수 있지만, 한계가 있다. Hermes는 더 나아가, 메모리를 저장하고 대화에서 재사용 가능한 워크플로우를 발견하면 스킬로 변환한다.

Hermes의 지속 메모리는 스마트한 구조로 되어 있다. user.md와 memory.md 파일의 크기에 상한을 둔다. 대화를 나눌 때마다 이 파일들을 업데이트한다. 왜 크기 제한이 필요할까?

모델의 주의력은 제한적이다. 한 번에 집중할 수 있는 정보량이 정해져 있고, 많은 정보가 주어지면 혼란스러워진다. 프롬프트, 툴, 시스템 인스트럭션, 첨부 파일 — 이 모든 것이 컨텍스트 윈도우에서 모델의 주의를 놓고 경쟁한다. 컨텍스트를 꽉 채울수록 모델은 실제 작업에 집중하기 어려워지고, 불필요한 정보는 노이즈가 된다.

토큰 제한에 도달하면 모델이 파일을 검토해 불필요한 내용을 정리한다. 최신 정보만 메모리에 유지하고 오래된 불필요한 내용은 제거한다. OpenCode는 이 과정이 없어 메모리가 계속 쌓인다.

OpenCode에서 또 다른 문제가 있었다. 보안을 위해 직접 샌드박스를 구성해야 했다. Hermes는 자체 샌드박스에서 실행된다. 격리된 환경에서 동작하기 때문에 해서는 안 되는 것에 접근하거나 실수로 잘못된 작업을 수행할 수 없다. OpenCode의 대부분 보안 문제를 해소한다.

지금 Hermes와 Claude Code를 함께 세팅하기에 가장 좋은 시점이다. Dario(앤트로픽 CEO)가 Claude 구독을 서드파티 앱에 연결하는 것에 과금하기 시작했기 때문이다. 6월 15일 이후부터는 Hermes 같은 에이전트를 Claude 구독으로 무료로 사용할 수 없다. 월정액에 에이전트 SDK 크레딧이 포함되고, 서드파티 앱을 구독 연결로 실행할 때마다 그 크레딧이 차감된다.

Non-interactive 모드로 Claude Code를 실행하는 것도 마찬가지다 — 에이전트가 백그라운드에서 Claude Code를 허가 프롬프트 없이 실행하는 바로 그 모드. 그래서 6월 15일 이전까지는 Hermes 에이전트를 API 비용 없이 사용 가능하다.

Hermes 에이전트 셋업은 사실 단순하다. 설치 커맨드를 복사해 터미널에서 실행하면 된다. 먼저 필요한 모든 의존성을 설치하고 인터랙티브 모드로 인스톨러를 실행한다.

Nous 플랜(그들의 모델과 빌트인 툴 제공)으로 세팅하고 싶으면 그렇게 할 수 있다. 우리는 자체 셋업을 원해서 Manual 옵션을 선택했다. 나중에 hermes setup 커맨드로 재구성도 가능하다.

이 단계에서 에이전트에 필요한 모든 것을 설정한다. Hermes는 기존 OpenCode 설정에서 import할 수 있다 — 사용자 프로필, 크레덴셜, 스킬, soul 파일(에이전트의 성격과 인스트럭션)을 가져올 수 있다. 하지만 OpenCode에서 상속받는 것에는 문제가 따른다. 가져온 로그인 정보는 OpenCode 에이전트가 사용하던 채널을 여전히 가리키고, OpenCode가 의존하던 파일들도 OpenCode 전용으로 작성되어 있어 그대로 가져오면 문제가 생긴다. 그래서 우리는 import를 안 했다.

그 다음 Hermes가 사용할 모델을 선택한다. Claude 모델을 Anthropic 구독으로 쓰려 했는데 에러가 발생했다. Dario가 이미 추가 사용 설정을 요구하고 있었다 — 아직 6월 15일이 아닌데도. 이 정책이 이미 점진적으로 롤아웃 중인 것 같다. 하지만 여러분은 여전히 작동할 수 있다. 어떻게든 Claude Code를 non-interactive 모드로 사용할 수 있었고, 대부분의 작업은 이 모드로 진행할 것이다. 모델 제공자는 나중에 바꿀 수 있다.

모델이 설정되면 에이전트가 실행될 위치를 선택한다 — 호스팅, VPS, 로컬 중 하나. 우리는 이것만을 위해 Mac Mini를 돌리고 있어서 로컬 옵션을 선택했다. 참고로, Mac Mini 부족 현상을 우리가 일으킨 건 아니다 — 아쉽게도 우리 AI B2B SaaS 사업이 자금 소진으로 멈췄기 때문이다. 이후 원하는 메시징 플랫폼을 연결한다. 우리는 Discord를 선택했지만 어떤 것이든 가능하다.

Discord 봇 셋업은 여기서 다루지 않겠다. 커뮤니티 AI Labs Pro에 전체 가이드가 있다. 완료 후 몇 가지 질문에 답하면 에이전트가 준비된다.

hermes를 입력하면 UI가 로드되고 바로 대화를 시작할 수 있다. 자신에 맞게 맞춤화하려면 사용자 정보가 필요하다 — 한 달 동안 사용하면서 스스로 파악하게 두거나, 처음부터 직접 알려줄 수 있다. 퍼스널 에이전트로 설정하려면 채팅에서 모든 정보를 알려주거나, Second Brain 볼트(옵시디언 등) 경로를 주고 거기서 스스로 온보딩하게 할 수 있다. 특정 자동화 용도로 설정하려면 해당 use case 문서나 회사 정보를 제공하면 된다.

그 전에 스폰서 소개가 있었다. (Educative — LLM, MCP, Agentic AI, LLM 부트캠프 등 강의 플랫폼. 300만 개발자 이용, 2300개 이상 강좌.)

Hermes 에이전트에 Skill Hub에서 스킬 컬렉션을 구성할 수 있다. 90개의 사전 설치 스킬이 있으며 이는 Nous Research가 직접 유지관리하므로 안전하다. OpenCode 스킬은 보안 이슈가 있었다 — 외부 서버로 데이터를 전송하는 위험한 스크립트가 포함된 것도 있었다. Skill Hub는 각 스킬에 보안 스캔을 실행해 이런 문제를 걸러낸다.

다른 에이전트와 마찬가지로 원하는 MCP 서버를 Hermes에 연결할 수 있다. 하지만 Hermes의 진짜 차별점은 이것이다: 자신의 Hermes 셋업을 MCP 서버로 실행해 다른 에이전트에 연결할 수 있다. 다른 에이전트가 툴을 통해 Hermes에 접근하고 통신이 양방향으로 이루어진다.

Claude Code 단독으로는 사용자에 대해 아무것도 기억하지 못하고, 스킬이 스스로 수정·개선되지 않는다. 이 MCP 연결을 통해 Hermes가 할 수 있는 모든 것에 접근할 수 있다. 또한 이미 Hermes에 연결한 모든 앱을 각 에이전트마다 별도 연결 없이 Hermes를 통해 사용할 수 있다.

Hermes를 MCP로 실행하려면 hermes mcp serve를 실행하면 된다. 터미널에 출력이 없지만 MCP 서버로 실행 중이다. .mcp.json 파일에 Hermes MCP를 추가하면 사용 가능해진다. 프로젝트 스코프 또는 루트 .claude 경로(전역)에 추가할 수 있다.

Hermes에는 Claude Code 스킬이 번들로 포함되어 있다. Hermes를 통해 Claude Code를 사용하는 방법을 안내하는 스킬이다. MCP 서버로 실행 중인 Hermes 셋업과 결합하면 많은 것이 가능해진다.

Hermes 에이전트와 Claude Code의 조합은 반복 가능한 프로세스를 처리하는 여러 자동화를 구축할 수 있는 비즈니스 용도에서 특히 유용하다.

그 중 하나가 Claude Code를 팀의 Slack 워크스페이스에 연결하는 것이다. Hermes는 항상 실행 중인 에이전트이고, Claude Code는 실제 개발이 이루어지는 곳이다. 그래서 Hermes 에이전트로 팀 워크스페이스에 접근한다. Discord 셋업처럼 Slack 연결도 여기서 다루지 않겠다 — 커뮤니티에 가이드가 있다.

대부분의 워크스페이스에는 프로젝트 전용 채널이 있고 팀이 다양한 논의를 한다. Hermes 에이전트에게 그 채널을 모니터링하는 cron job을 만들도록 요청할 수 있다. 채널에서 논의되는 요구사항으로 PRD 스킬을 구성하고, 프로젝트가 발전하면서 스킬도 진화하게 된다.

PRD를 스킬로 관리하면 실제 제품 개발 세션에서 매우 유용하다. 필요할 때마다 PRD의 관련 부분이 컨텍스트로 로드되어 프로젝트가 원래 요구사항에서 벗어나지 않는다.

앞서 이야기한 이유와 같다 — 에이전트는 뭘 집중해야 할지 혼란스러워하는 경우가 있다. 스킬은 필요할 때 호출되어 모델이 실제로 주의를 기울이는 컨텍스트의 최신 부분에 머문다.

그래서 Hermes가 지시에 따라 스킬을 생성하고 30분마다 cron job으로 실행한다. 채널에서 요구사항 변경이 논의되면 PRD가 업데이트되고, Hermes 에이전트가 변경사항이 양방향으로 반영되도록 보장한다. 프로젝트 안의 스킬도 최신 상태로 유지된다.

이 시점에 이런 생각이 들 수 있다: 이미 Hermes 에이전트에 MCP가 연결되어 있는데 Slack 채널에서 정보를 당겨오는 툴을 쓰면 안 되나? 이유는 Slack MCP의 제약 때문이다. 기본적으로 전체 대화 히스토리를 읽지 못하고, 태그된 메시지만 읽으며, 해당 메시지가 특별히 컨텍스트를 필요로 하지 않는 한 전체 히스토리를 당겨오지 않는다. 그래서 Hermes 에이전트를 통해 설정하는 것이 더 나은 방법이다.

이를 통해 Hermes 에이전트 채널을 통해 Claude Code non-interactive 모드로 원하는 기능을 구현하도록 요청할 수도 있다. 앞서 이야기한 Claude Code 스킬을 로드하고, Claude Code를 실행해 기능을 빌드한다.

Hermes를 배포된 앱에 붙일 수도 있다 — 자신을 위한 것이든 클라이언트를 위한 것이든. Claude Code로 빌드한 배포 앱이 있다면, 실행 중인 앱 모니터링 방법을 안내하는 헬스체크 스킬을 만들 수 있다. Claude Code가 앱에 대한 최고의 컨텍스트를 갖고 있기 때문이다. 그 스킬을 Hermes 에이전트에 import하고 cron job을 설정한다.

에이전트가 호스팅된 앱과 코드 모두를 모니터링하게 된다. 스킬을 실행하다 이슈를 발견해 업데이트하면 그 스킬을 로컬 프로젝트에 다시 동기화하도록 설정했다. Claude Code도 해당 컨텍스트를 유지하게 된다. 이것이 self-evolving 스킬이 실행마다 개선되는 지속적 헬스체크를 구축하는 방법이다.

Hermes에게 프롬프트를 주면 cron job을 설정해준다. 테스트 실행으로 제대로 구성됐는지 확인 가능하다. 설정한 채널(우리 경우 Discord)로 리포트를 준다. MCP 구성을 통해 그 리포트를 Claude Code 내에서 바로 받아볼 수 있고, 팀원의 수정 제안을 함께 받아 프로젝트에 직접 구현하거나, 직접 수정을 푸시하거나, Hermes 에이전트가 발견한 이슈를 Claude Code로 수정하도록 설정할 수 있다.

AI Labs Pro 커뮤니티에 이 영상의 셋업 가이드를 포함해 모든 리소스를 정리해뒀다. 이상으로 이번 영상을 마친다.
