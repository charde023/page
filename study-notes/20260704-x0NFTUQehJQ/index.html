Claude Tag가 바꾸는 일의 미래

원작자 Boris Cherny, Cat Wu · Anthropic · 업로드 2026-07-04 · 11.4분 · 원본 영상 ↗

Claude Tag는 사람이 매번 프롬프트를 입력하지 않아도 Slack 같은 협업 채널에서 필요한 일을 스스로 판단하고, 장기 작업과 후속 조치까지 이어가는 팀 단위 AI 협업 에이전트다.

핵심 학습 포인트 (내가 배워야 할 것)

개념 왜 중요한가 한 줄
Claude Tag AI가 개인 도구에서 팀 협업 도구로 이동하는 사례 채널에 들어와 일을 감지하고 처리하는 협업형 AI
능동형 에이전트(Proactive Agent) 사용자가 시켜야만 움직이는 AI와 다름 필요한 순간을 판단해 먼저 개입한다
장기 실행 작업(Long-running Task) 데이터 분석, 실험, 버그 수정처럼 며칠 걸리는 업무에 중요 Claude가 스스로 후속 일정을 잡고 계속 진행한다
메모리(Memory) 매번 같은 지시를 반복하지 않아도 됨 채널별 규칙과 선호를 기억한다
멀티플레이어 협업(Multiplayer Collaboration) AI 작업 과정을 팀 전체가 보고 개선할 수 있음 개인 AI가 아니라 공개 채널 속 팀 AI가 된다
PR 자동화(Pull Request Automation) 개발 생산성에 직접 연결 버그 발견부터 수정 PR 작성까지 맡는다
공개 채널(Public Channel) AI 활용법이 조직 안에서 빠르게 전파됨 잘 쓰는 사람의 패턴을 모두가 학습한다

내가 모를 만한 것 / 처음 보는 것

  • Claude Tag — Slack 채널에 추가해 팀 대화 속에서 일을 찾아 처리하는 Claude 기반 AI 에이전트.
  • Claude Code — Anthropic의 코딩용 AI 에이전트 도구. 터미널, 코드베이스, 개발 작업과 연결된다.
  • PR(Pull Request) — 코드 변경사항을 리뷰받고 병합하기 위해 올리는 요청.
  • 원격 샌드박스(Remote Sandbox) — AI가 안전하게 코드를 실행·검증할 수 있는 격리된 실행 환경.
  • 에이전트 SDK(Agent SDK) — 에이전트가 도구, 코드, 외부 시스템을 사용할 수 있게 해주는 개발 도구 모음.
  • 소스 오브 트루스(Source of Truth) — 조직에서 공식 기준으로 삼는 문서, 파일, 데이터 저장소.
  • 셀프서브(Self-serve) — 담당자에게 직접 묻지 않고 사용자가 스스로 답을 얻는 방식.
  • 타입어헤드(Type-ahead) — 사용자가 코드를 입력하는 중 다음 코드를 자동완성해주는 방식.

화자의 디테일 (놓치기 쉬운 포인트)

화자가 흘리듯 말한 구체 수치·설정값·명령어·뉘앙스. 원어 용어 괄호 병기, 맥락까지.

  1. 최신 모델은 한 번에 16시간 작업할 수 있는 수준이라고 설명한다 — 단순 챗봇이 아니라 장시간 자율 작업을 염두에 둔 모델이라는 뜻.
  2. Claude Tag는 작업을 며칠, 몇 주, 몇 달 뒤 후속 일정으로 스스로 예약할 수 있다고 말한다 — 장기 프로젝트 관리에 가까운 기능.
  3. 한 화자는 개인적으로 며칠, 몇 주, 한 달짜리 Tag 세션도 돌리고 있다고 한다 — 매일 데이터 확인, 버그 수정 PR, 리포트를 수행.
  4. Anthropic 제품 조직에서 Tag가 작성한 PR 비중이 약 65%까지 올라왔다고 언급한다 — 내부 개발 생산성 변화의 핵심 수치.
  5. PM은 보통 5~10개 기능을 동시에 다루며, Claude Tag에게 각 기능 상태를 보고 매일 리포트하게 한다고 한다.
  6. Slack에서 시작했지만 향후 Microsoft Teams 같은 다른 협업 플랫폼으로 확장하려 한다.
  7. 단순 답변뿐 아니라 버튼이 몇 픽셀 어긋난 버그 수정 같은 작은 UI 수정부터 복잡한 작업까지 점점 맡기고 있다.
  8. Tag가 버그를 고친 뒤 Slack에 검증 영상(video)을 올려준다고 한다 — 사용자가 개발 환경을 열지 않고도 결과를 확인하게 하기 위함.
  9. 공개 채널에서 작동하기 때문에, 초보자가 전문가의 AI 사용 패턴을 관찰하고 따라 하게 되는 사용법 확산(diffusion) 이 일어난다.
  10. 채널에서 “이 유형의 이슈만 모니터링하고 다른 카테고리는 제외해줘”라고 지시하면, Claude Tag가 그 규칙을 계속 기억한다고 한다.

# 섹션 요지
1 AI 코딩의 변화 자동완성에서 기능 구현, 이제는 전체 업무 처리로 이동
2 Claude Tag란 무엇인가 채널 안에서 먼저 개입하고 기억하며 후속 작업까지 수행
3 기술적 기반 장기 실행, 자율 일정 관리, 메모리, 적절한 개입 판단
4 실제 활용 패턴 데이터 분석, Q&A, 버그 수정, PR 작성, 피드백 처리
5 조직 변화 개인 AI에서 팀 전체가 함께 쓰는 공개 협업 AI로 전환
6 Claude Code와의 차이 직접 코딩 도구는 Claude Code, 채널 기반 업무 자동화는 Tag
7 앞으로의 방향 Slack을 넘어 Teams 등 지식노동 플랫폼 전반으로 확장

1. AI 코딩은 자동완성에서 팀 에이전트로 이동했다

화자들은 몇 년 전만 해도 AI 코딩의 중심이 타입어헤드(Type-ahead), 즉 코드 자동완성이었다고 말한다. 당시 엔지니어는 여전히 “내가 이 줄을 써야겠다”고 결정했고, AI는 그 한 줄을 조금 도와주는 역할에 가까웠다.

이후 Claude Code 같은 도구가 나오면서 AI는 함수, 파일, 기능 단위까지 작성하기 시작했다. 그리고 Claude Tag 단계에서는 더 나아가 기능 구현, 실험, 데이터 분석, 버그 수정, PR 작성까지 전체 업무 흐름을 맡는다.

핵심 변화는 다음과 같다.

  • 과거: 사람이 줄 단위로 입력하고 AI가 보조
  • 중간 단계: 한 사람이 여러 Claude를 활용해 여러 기능을 병렬로 진행
  • 현재: Claude가 더 주도적으로 움직이고, 한 개인이 아니라 팀 전체가 함께 상호작용

즉 Claude Tag는 “개인 생산성 도구”가 아니라 팀 업무 운영 방식 자체를 바꾸는 AI로 소개된다.

2. Claude Tag는 채널 안에서 먼저 일을 찾아 처리한다

기존 Claude 사용 방식은 사용자가 Claude를 열고, 프롬프트를 입력하고, 필요한 도구를 연결해 일을 시키는 구조였다. 반면 Claude Tag는 Slack 채널에 추가해두면 다음과 같이 작동한다.

  • 필요한 순간을 판단해 먼저 개입
  • 사용자가 매번 부르지 않아도 작업 수행
  • 며칠이나 몇 주 걸리는 일도 계속 진행
  • 후속 작업을 스스로 챙김
  • 이전 지시와 채널별 규칙을 기억

화자들은 이를 능동형(Proactive) 경험이라고 설명한다. 사용자가 “Claude, 이제 이것 해줘”라고 계속 말할 필요가 줄어든다.

특히 중요한 점은 공개 채널에서 작동한다는 것이다. 모든 팀원이 Claude가 무엇을 하고 있는지 볼 수 있고, 필요하면 누구나 중간에 방향을 조정할 수 있다. 그래서 화자들은 이를 멀티플레이어(Multiplayer) 방식이라고 표현한다.

3. Claude Tag를 가능하게 한 기술: 장기 실행과 메모리

Claude Tag의 핵심 기술 기반은 크게 두 가지다.

첫째, 장기 실행 자율성(Long-running Autonomy) 이다. Anthropic은 모델이 더 오래, 더 자율적으로 일하도록 연구해왔다고 말한다. 최신 평가에서는 모델이 한 번에 16시간 작업할 수 있는 수준이며, 이제는 실제로 얼마나 오래 가능한지 정확히 측정하기 어려운 영역에 들어갔다고 설명한다.

Claude Tag에서는 여기에 셀프 스케줄링(Self-scheduling) 이 결합된다. 예를 들어 한 번의 16시간짜리 작업에서 끝나는 것이 아니라, Claude가 며칠 뒤, 몇 주 뒤, 몇 달 뒤 후속 작업을 스스로 예약할 수 있다.

둘째, 메모리(Memory) 다. Claude Tag는 채널에서 받은 지시를 기억한다. 예를 들어 사용자가 “이 채널에서는 특정 유형의 이슈만 모니터링하고, 다른 카테고리는 무시해줘”라고 말하면, 이후에도 그 규칙을 유지한다. 다른 팀원이 범위를 넓히라고 하면 그에 맞게 조정한다.

이 메모리 덕분에 Claude Tag는 단발성 챗봇이 아니라 채널별 업무 담당자처럼 동작한다.

4. Claude Tag는 어디에 쓰이나

화자들이 언급한 실제 사용 사례는 다양하다.

  • PR(Pull Request) 작성
  • 프로덕션 이슈 디버깅
  • 데이터 분석
  • Q&A 채널 답변
  • 답변 완료 후 체크 표시 반응
  • Claude Code 피드백 채널의 버그 수정
  • 기능 상태 추적과 일일 리포트
  • 신규 입사자의 법무·HR 질문 답변

예를 들어 데이터 질문이 있으면 데이터 채널에 질문을 올리고 Claude Tag를 부른다. 처음에는 매번 Tag를 호출했지만, 반복되자 “앞으로는 매번 답해줘”라고 설정했고, 이후 Claude Tag가 자동으로 1차 답변을 제공하게 되었다고 한다.

또 다른 예시는 Q&A 채널이다. “질문이 답변되면 반드시 체크 표시를 해줘”라고 말하면, Claude Tag가 답변하고 체크 반응까지 붙인다. 이런 작은 운영 자동화가 팀의 반복 업무를 줄인다.

5. 공개 채널에서 AI 활용법이 조직 전체로 퍼진다

Claude Tag의 중요한 효과는 AI 활용법이 조직 안에서 자연스럽게 전파된다는 점이다.

기존 AI 도구는 보통 개인과 AI 사이의 비공개 작업이었다. 결과물을 복사해 팀에 공유하는 방식이 많았다. 하지만 Claude Tag는 공개 채널 안에서 작동하기 때문에 다음 일이 일어난다.

  • 전문가가 Claude Tag를 어떻게 지시하는지 모두가 본다.
  • 다른 팀원이 그 패턴을 따라 한다.
  • Claude Tag도 팀원들의 피드백을 듣고 더 잘 맞춰진다.
  • 결과물은 한 사람의 판단이 아니라 팀 전체의 조정으로 개선된다.

화자들은 이것이 AI 도구에서 매우 새로운 현상이라고 본다. AI 사용법이 교육 자료로만 전파되는 것이 아니라, 실제 업무 채널에서 관찰을 통해 퍼진다.

6. Claude Tag는 비개발자도 코드베이스에 기여하게 만든다

화자는 “모두가 코드베이스에 기여했으면 좋겠다”고 말한다. 하지만 많은 사람은 터미널, Git, 코드 체크아웃 같은 개발 환경 때문에 코드 기여를 두려워한다.

Claude Tag는 이 장벽을 낮춘다. 사용자는 Slack 채널에서 “이 버그 고쳐줘”라고 말하면 되고, Claude Tag가 코드 수정과 PR 작성까지 진행할 수 있다. 특히 PM, 운영 담당자, 데이터 담당자도 개발자처럼 코드 변경을 요청하고 결과를 확인할 수 있다.

이는 비개발자에게도 중요한 변화다. 이커머스나 물류 회사에서도 비슷하게 생각할 수 있다. 예를 들어 다음과 같은 요청을 채널에서 처리하게 만들 수 있다.

  • “주문 지연 리포트 매일 아침 요약해줘”
  • “CS에서 반복되는 배송 오류 유형을 분류해줘”
  • “상품 상세 페이지 오류 제보가 오면 개발 이슈로 정리해줘”
  • “재고 데이터 이상치를 발견하면 담당자에게 알려줘”

핵심은 AI가 별도 앱 안에 갇혀 있는 것이 아니라, 팀이 이미 일하는 채널 안에 들어온다는 점이다.

7. Claude Code와 Claude Tag의 역할 차이

화자는 원래 모든 작업에 Claude Code를 썼지만, 점점 Claude Tag를 더 많이 쓰게 되었다고 말한다.

초기에는 간단한 수정에 Tag를 사용했다.

  • 버튼 위치가 몇 픽셀 어긋난 문제
  • 단순한 데이터 질문
  • 작은 버그 수정

하지만 몇 주 동안 사용하면서 더 복잡한 일도 맡기게 되었다. 이유는 Claude Tag도 같은 원격 샌드박스(Remote Sandbox)와 에이전트 SDK(Agent SDK)를 사용해 작업을 검증할 수 있기 때문이다.

차이를 정리하면 다음과 같다.

도구 적합한 상황
Claude Code 개발자가 직접 코드 작업을 깊게 진행할 때
Claude Tag 채널에서 발생한 업무를 자동으로 추적·처리·보고할 때

Claude Tag는 작업 후 Slack에 검증 영상까지 올릴 수 있어, 사용자가 개발 환경을 열지 않고도 결과를 확인할 수 있다.

8. 앞으로는 모든 협업 플랫폼 안에 Claude가 들어간다

Claude Tag는 Slack에서 시작했지만, Anthropic은 Microsoft Teams 같은 다른 협업 플랫폼으로 확장하려 한다고 말한다.

목표는 모든 지식노동자가 어떤 도구에서 일하든 Claude에 가까이 접근할 수 있게 하는 것이다. Claude Tag는 개인 업무 방식뿐 아니라 조직 전체의 일하는 방식을 바꾸는 도구로 소개된다.

특히 Claude Code처럼 높은 수준의 커스터마이징이 가능하게 만들었기 때문에, 각 조직이 자기 업무 방식에 맞게 Claude Tag를 조정할 수 있을 것으로 기대한다.

채널에 Claude가 없으면 어떻게 하나요?

모르겠습니다. Claude가 채널에 없던 세상이 잘 기억나지 않습니다.

시간을 되돌려보죠. 3년 전에는 우리가 일상 업무에 AI를 막 도입하기 시작하던 시기였습니다. 그때는 어땠고, 지금은 어디까지 왔나요?

2년 전만 해도 저는 여전히 타입어헤드(Type-ahead)를 쓰고 있었습니다. 엔지니어에게 AI가 해줄 수 있는 일이란 그 정도였습니다. 이후 우리는 Claude Code를 만들었고, 에이전트(Agent)와 새로운 코딩 방식을 도입했습니다. 그 뒤로 정말 많은 것이 바뀌었습니다.

타입어헤드 시절에는 제가 “이 코드 한 줄을 써야겠다”고 결정했고, 에이전트는 조금 도와주는 정도였습니다. 한 줄을 써주는 수준이었죠. 그러다 함수 전체, 파일 전체, 기능 전체를 작성하는 단계까지 왔습니다. 이제 Tag에 와서는 전체 일을 처리합니다. 기능을 만들고, 실험을 처음부터 끝까지 수행하고, 데이터 분석도 해줍니다. 2년 사이에 두 번의 큰 도약이 있었던 느낌입니다.

지난 몇 년을 돌아보면 전환이 있었습니다. 처음에는 사람이 항상 루프 안에 있었습니다. 한 사람이 앉아서 한 줄씩 입력했죠. 그다음에는 한 사람이 앉아서 10개의 Claude와 함께 여러 기능을 동시에 만드는 단계가 되었습니다. 이제는 Claude가 조금 더 주도합니다. 그리고 더 이상 한 사람만의 일이 아닙니다. 팀 전체가 Claude와 상호작용합니다.

그렇다면 Claude Tag는 무엇인가요?

과거에는 Claude를 열고 무언가를 물어봐야 했습니다. 그러면 Claude가 일을 했습니다. 도구를 사용하고, 컴퓨터를 사용하고, 작업을 끝냈습니다. 예전 방식은 그랬습니다.

Claude Tag에서는 Claude가 직접 끼어듭니다. 능동적으로 움직이고, 언제 개입해야 하는지 압니다. 며칠이나 몇 주가 걸려도 일을 하고, 후속 조치도 합니다. 가장 멋진 점은 다음번을 위해 제가 말한 내용을 기억한다는 것입니다.

예전에는 매번 Claude에게 프롬프트를 입력해야 했습니다. “Claude, 이제 이것 해줘”, “이제 저것 해줘”라고 말해야 했고, 제가 그걸 기억해야 했습니다. 이제는 채널에 Claude를 추가하기만 하면 됩니다. Claude가 능동적으로 개입해 일을 합니다. 모두가 그 과정을 볼 수 있고, 모두가 참여할 수 있습니다. 멀티플레이어(Multiplayer) 방식이기 때문입니다. 그리고 다음번을 위해 기억합니다.

연구 측면에서는 무엇이 이것을 가능하게 했나요? Tag가 이렇게 잘 작동하는 이유는 무엇인가요?

우리는 수년 동안 모델이 더 오래 실행되고 더 자율적으로 움직이게 만드는 일을 해왔습니다. 최신 평가(Eval)를 보면, 최신 모델은 한 번에 16시간 동안 작업할 수 있습니다. 이제는 모델이 얼마나 오래 작업할 수 있는지 정확히 감지하기 어려운 영역에 들어왔습니다.

Claude Tag 같은 제품에서는 Claude가 스스로 작업 일정을 잡을 수 있습니다. 그래서 하나의 16시간짜리 작업이 시간이 지나며 더 확장됩니다. Claude가 며칠, 몇 주, 몇 달 뒤 후속 작업을 예약할 수 있기 때문입니다.

예전에는 믿고 맡기기 어려웠던 작업도 이제는 거의 매번 해낼 수 있다고 느낍니다.

개인적으로 저는 며칠, 몇 주 동안 돌아가는 Claude Tag 세션을 여러 개 가지고 있습니다. 아마 한 달 정도 된 것도 있을 겁니다. 본질적으로는 장기 실행 실험입니다. 매일 확인하고, 데이터를 점검합니다. 가끔 수정해야 할 버그가 있으면 버그 수정 PR(Pull Request)을 보냅니다. 저는 PR이 올라오는 것을 보고, 매일 데이터 리포트를 받습니다.

또 다른 큰 혁신은 모델에 메모리(Memory)를 넣을 수 있게 된 것입니다. 모델은 자기 자신을 위해 알림을 설정할 수 있을 뿐 아니라, 시간이 지나며 모든 사용자가 준 지시를 기억할 수 있습니다.

메모리는 해결하는 데 오래 걸렸습니다. Claude Code에 맞게 제대로 만들려고 수년 동안 시도했던 것 같습니다. 이제 마침내 제대로 된 느낌입니다. 사용감이 정말 좋습니다.

Claude Tag와 채널에서 일할 때 “이 유형의 이슈만 모니터링하고, 다른 카테고리는 보지 말아줘”라고 말하면 그대로 합니다. 그리고 그 채널에서는 이후에도 계속 기억합니다. 누군가가 “사실 범위를 이 새로운 항목까지 넓혀줘”라고 말하면 조정합니다.

사람들이 좋아하는 또 다른 큰 요소는 Claude의 성격과 EQ입니다. 가끔 사람들에게 Claude Tag를 채널에 추가하는 이야기를 하면 “모든 스레드에 끼어들어 귀찮게 굴지 않는다는 걸 어떻게 알죠?”라고 묻습니다. Claude는 언제 필요한지 감각을 갖도록 훈련되어 있고, 뒤로 물러나 있을 수도 있습니다. 만약 너무 과하게 잘못된 방향으로 가면 “덜 끼어들어줘” 또는 “더 자주 개입해줘”라고 말하면 됩니다. 그러면 앞으로 기억합니다.

내부 사용 사례와 Claude Tag를 막 시작한 고객들을 보면 어떤 패턴이 보이나요?

가장 멋진 점은 고객들이 스스로 활용법을 찾아간다는 것입니다. Claude Tag는 PR을 작성할 수 있습니다. 프로덕션 이슈를 디버깅할 수 있습니다. 데이터 분석을 할 수 있습니다. 필요한 것은 도구에 연결하는 것뿐입니다. 이것은 메모리가 매우 좋기 때문에 가능하다고 생각합니다.

저는 사람들이 창발적인 방식으로 쓰는 것을 봤습니다. 예를 들어 “이 채널은 Q&A 채널이다. 질문이 답변될 때마다 반드시 체크 표시를 해야 한다”고 Claude Tag에게 말합니다. 그러면 Claude Tag는 그대로 합니다. 질문에 답하고 매번 체크 반응을 붙입니다. 이런 일을 대신 해줍니다. 우리는 데이터 질문 채널이 있는데 이제 Tag가 모든 질문에 답합니다. Claude Code 피드백 채널도 있는데, 이제 Tag가 모든 것을 고칩니다.

제가 데이터 질문을 하는 가장 흔한 방식은 데이터 채널에 글을 올리고 Tag를 호출하는 것입니다. 그러면 Tag가 첫 번째 답변을 합니다. 보통 꽤 좋습니다. 여러 채널에서 계속 이렇게 하다 보니, 매번 태그하는 것이 귀찮아졌습니다. 그래서 그냥 “매번 답해줘”라고 말했습니다.

이런 일이 가능하다는 것 자체가 메모리가 얼마나 강력한지 보여줍니다. “앞으로 항상 이 일을 기억해줘”라고 말하면, Claude가 뒤에서 받쳐줍니다.

이것은 우리가 일하는 방식을 크게 바꾸었습니다. 또한 더 많은 사람이 AI와 일하는 방법을 이해하게 해주는 방식이기도 합니다. Claude Tag는 공개 채널에서 일하기 때문에, 모든 사람이 숙련 사용자가 그것을 어떻게 활용하는지 관찰할 수 있습니다. 그런 다음 그 패턴을 가져가 자신이 하는 새로운 프로젝트에 적용합니다. 내부적으로도, 함께 일한 고객들에게서도 Claude Tag 모범 사례가 퍼지는 모습을 보고 있습니다. 이는 AI 도구에서는 매우 새로운 현상이라고 생각합니다.

얼마나 빠르게 퍼졌는지가 놀라웠습니다. 이제는 거의 모든 채널에서 Tag를 보는 것 같습니다. 모든 피드백 채널, 모든 데이터 채널에 있습니다. 처음에는 몇 명만 사용했지만, 다른 사람들이 그 사용 모습을 보자 매우 빠르게 따라 하기 시작했습니다.

Claude Tag가 뒤에서 도와준다는 것은 큰 힘이 됩니다. 기존 도구, 예를 들어 채팅, 코워킹(Coworking), Claude Code는 보통 사용자가 열어야 한다는 것을 기억해야 합니다. 그래서 더 반응형(Reactive) 경험입니다. Claude Tag의 좋은 점은 더 높은 수준의 목표를 줄 수 있다는 것입니다. 예를 들어 “이 채널의 모든 버그에 대해 PR을 올려줘”라고 하면, 매번 상기시키지 않아도 모든 버그에 대해 PR을 올려줍니다.

두 번째로 멋진 점은 멀티플레이어라는 것입니다. 지금 사람들이 쓰는 거의 모든 AI 도구는 사용자와 Claude가 함께 작업한 뒤 결과물을 팀에 복사해 붙여넣는 방식입니다. Claude Tag가 만드는 큰 변화는 Claude를 업무의 한가운데로 데려온다는 점입니다. 여러 사람이 세션을 더 나은 결과로 이끌 수 있습니다.

여기에는 많은 역학이 있습니다. 첫째, 우리는 다른 사람을 관찰하면서 Claude Tag를 더 잘 쓰는 법을 배웁니다. 둘째, Claude Tag는 우리가 주는 지침을 들으며 우리와 더 잘 일하는 법을 배웁니다. 결국 고객은 더 나은 결과를 얻습니다. 해결책이 제 의견만으로 정해지는 것이 아니라, 팀 전체가 개입해 PR을 가능한 최선의 상태로 다듬을 수 있기 때문입니다.

저는 이 아이디어를 정말 좋아합니다. 저는 모두에게 코드베이스(Codebase)에 기여했으면 좋겠다고 계속 말합니다. 그런데 많은 사람이 두려워합니다. 터미널을 열어야 하고, 데스크톱 앱을 써야 하며, Git과 코드 체크아웃 같은 것을 다뤄야 하기 때문입니다. Tag가 있으면 그냥 할 수 있습니다. 정말 멋집니다.

또 하나 중요한 것은 협업 플랫폼에 공개 채널(Public Channel)이 있어야 한다는 점입니다. 그래야 Claude Tag가 추적 중인 여러 프로젝트를 모니터링할 수 있습니다. PM으로서 저는 보통 5개에서 10개의 기능을 동시에 다룹니다. Claude Tag가 각각의 상태를 보고 매일 리포트를 주게 합니다.

우리가 본 또 다른 큰 전환점은 사람들이 이제 질문을 셀프서브(Self-serve)할 수 있다는 점입니다. 회사에 온보딩할 때, “이 말을 해도 되는지” 법무팀에 묻거나, 복리후생이 무엇인지 HR팀에 묻는 대신 Claude Tag를 태그하면 됩니다. Claude Tag는 소스 오브 트루스(Source of Truth) 파일에 연결되어 있기 때문에, 언제 찾든 빠르게 답변할 수 있습니다.

가장 큰 변화 하나를 꼽자면 모두의 생산성이 훨씬 높아졌다는 점입니다. 이것은 Claude Tag의 내부 버전이 이끈 변화입니다. 우리가 속한 제품 조직만 보면, Tag가 작성한 PR 수가 이제 약 65%인 것 같습니다. 그리고 계속 올라가고 있습니다.

저는 Claude Code가 엔지니어를 더 빠르게 만드는 도구라고 생각했습니다. 그런데 이 제품은 엔지니어를 훨씬 더 빠르게 만듭니다. 큰 이유는 상호작용 방식에 있다고 봅니다. Tag에게 일을 시키면 Tag가 응답하고, 사용자는 다음 작업으로 넘어갑니다. 그래서 Tag가 일을 하도록 설정하고, 사용자가 계속 확인하지 않아도 되는 방식으로 만드는 것이 좋습니다.

수백 개의 Claude Tag를 실행하고 있지만 여전히 Claude Code 파워 유저이기도 합니다. 둘 중 언제 무엇을 쓰나요?

예전에는 모든 일에 Claude Code를 썼습니다. 그러다 점점 더 많은 일에 Tag를 쓰기 시작했습니다. 처음에는 아주 간단한 수정이었습니다. 누군가 버그를 발견하면, 예를 들어 버튼이 몇 픽셀 어긋나 있는 문제 같은 것이 있으면 Claude에게 고쳐달라고 했습니다. 또는 아주 간단한 데이터 질문이 있으면 해결해달라고 했습니다.

지난 몇 주 동안 점점 더 제품에 익숙해지면서 Tag를 더 많은 일에 쓰게 되었습니다. 더 복잡한 작업도 실제로 해낼 수 있습니다. 자신의 작업을 검증할 수 있기 때문입니다. 모바일과 데스크톱 앱에 사용하는 것과 같은 원격 샌드박스(Remote Sandbox)에서 실행되고, 같은 에이전트 SDK(Agent SDK)를 사용합니다. 그래서 지능 수준은 같습니다.

여기에 메모리를 더하면, 채널마다 제가 원하는 검증 방식에 대한 특정 선호가 있습니다. 채널마다 조금씩 다를 수 있습니다. 그래서 Claude Tag는 보통 버그를 고친 다음 Slack에 영상을 올립니다. 그러면 저는 Slack을 떠날 필요도 없습니다.

Claude Tag의 다음 단계는 무엇인가요?

우리는 Claude Tag를 Slack에서 출시했습니다. 앞으로는 Microsoft Teams처럼 사람들이 협업하는 더 많은 플랫폼으로 가져가고 싶습니다. 모든 지식노동자가 어디에서 일하든 Claude에 손이 닿는 거리에 있게 만들고 싶습니다.

Claude Tag의 가장 멋진 부분 중 하나는 개인의 일하는 방식만 바꾸는 것이 아니라, Claude를 팀의 중심에 놓고 조직 전체를 변화시킨다는 점입니다. 우리는 Claude Code처럼 Claude Tag도 매우 커스터마이징 가능하게 만들었습니다. 조직들이 Claude Tag를 어떻게 자기 방식으로 맞춤화하고 자신들의 도구로 만들어갈지 정말 기대됩니다. 빨리 보고 싶습니다.
