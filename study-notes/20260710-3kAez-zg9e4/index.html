개념 왜 중요한가 한 줄
벤치마크(Benchmark)와 실제 업무 테스트 모델 순위표만으로는 내 업무에 맞는지 알 수 없음 실제 업무 프롬프트와 비용까지 같이 봐야 한다
에이전트 하네스(Harness) Claude Code, Codex 같은 실행 환경이 속도·토큰 사용량에 큰 영향을 줌 모델 성능만이 아니라 “어디서 돌리느냐”도 중요하다
출력 토큰(Output Tokens) 효율 같은 결과라도 토큰을 많이 쓰면 API 비용이 커짐 Sol은 전반적으로 토큰을 적게 써서 싸게 느껴진다
원샷 API 테스트(One-shot API Test) 짧은 단발성 요청에서는 고급 모델이 과할 수 있음 단순 요청은 Sol처럼 저렴하고 빠른 모델이 유리하다
매니저형 AI와 작업자형 AI AI를 역할별로 배치하면 비용과 품질을 동시에 잡을 수 있음 Fable이 지시·판단하고 Sol 에이전트들이 실행하는 구조가 이상적일 수 있다

내가 모를 만한 것 / 처음 보는 것

  • GPT 5.6 Sol — GPT 계열의 상위 모델로 언급됨. 화자는 Fable 5급 “차세대 모델”이라기보다는 Opus 4.8에 가까운 강한 실행 모델로 평가.
  • Terra, Luna — GPT 5.6 제품군 또는 모델 라인업으로 언급된 이름. 영상에서는 주로 Sol만 테스트.
  • Fable 5 — Claude 계열처럼 언급되는 고성능 모델. 창의성, 글쓰기, 전략 판단에서 강하다고 평가.
  • Codex — GPT 모델을 코드 작성·실행 에이전트처럼 쓰는 환경. 화자는 Sol을 Codex에서 실행.
  • Claude Code — Claude/Fable 계열을 코드 작성·수정·실행 에이전트처럼 쓰는 환경.
  • 에이전틱 루프(Agentic Loop) — AI가 한 번 답하고 끝나는 것이 아니라 계획, 작성, 실행, 수정, 검증을 반복하는 작업 방식.
  • 단위 경제성(Unit Economics) — 작업 1건을 처리하는 데 드는 실제 비용 대비 성능. AI 모델 선택에서 매우 중요.
  • 상태 없는 요청(Stateless Request) — 이전 대화 맥락을 거의 쓰지 않는 단발성 API 요청.

1. 벤치마크보다 실제 업무에서 비교해야 한다

화자는 GPT 5.6 라인업인 Sol, Terra, Luna가 공개되었고, 벤치마크(Benchmark)상으로는 Sol이 Opus와 Fable을 크게 앞서면서도 훨씬 저렴해 보인다고 말한다.

하지만 그는 단순히 벤치마크를 읽는 것은 지루하고 실제 판단에 부족하다고 본다. 그래서 하루 종일 GPT 5.6 Sol과 Fable 5를 나란히 놓고 실제 업무, 코드 에이전트 작업, API 단발 요청을 비교했다.

핵심 관점은 다음과 같다.

  • 어떤 모델이 더 “똑똑한가”만 보지 않는다.
  • 어떤 작업에 어떤 모델이 더 적합한가를 본다.
  • 비용, 속도, 토큰 사용량, 결과물 품질을 같이 본다.
  • Claude Code와 Codex 같은 에이전트 하네스(Harness)의 차이도 고려한다.

화자는 초반부터 결론의 방향을 암시한다. Sol은 비용과 실행력이 뛰어나고, Fable은 더 창의적이고 전략적으로 느껴진다.

2. 테스트 1: 브라우저에서 실행되는 오픈월드 자전거 게임

첫 번째 테스트는 양쪽 모델에 같은 목표 프롬프트를 주는 방식이었다.

요청은 브라우저에서 실행되는 진짜 재미있고 플레이 가능한 오픈월드 자전거 게임을 만들라는 것이었다. 조작은 WASD 이동, 스페이스바 점프, Q/E 공중 묘기, Shift 부스트 같은 방식이었다.

첫 번째 결과물은 탑다운(Top-down) 또는 조감도 느낌의 게임이었다.

  • 도시가 있음
  • 건물을 통과할 수 없음
  • 코인을 먹을 수 있음
  • 점프와 묘기가 작동함
  • 기능적으로는 잘 돌아감
  • 다만 카메라와 조작감이 어색함

두 번째 결과물은 훨씬 더 3D에 가까운 시점이었다.

  • POV 또는 GTA 같은 오픈월드 느낌
  • 도시를 돌아다니며 탐험하는 느낌
  • 맵이 더 커 보임
  • 램프와 물리 효과를 시도할 수 있음
  • 몰입감이 더 좋음

화자는 두 번째 결과물이 명확한 승자라고 봤고, 그 결과물은 Fable 5가 만든 것이었다.

비용과 시간 비교는 다음과 같다.

항목 Fable 5 GPT 5.6 Sol
시간 21분 37초 23분
비용 약 14.22달러 약 4.50달러
출력 토큰 약 90,000 약 31,000

화자의 해석은 명확하다. Sol은 훨씬 토큰 효율적이고 저렴하지만, 이 테스트에서는 Fable의 결과물이 단순히 조금 좋은 정도가 아니라 상당히 더 좋았다.

3. 테스트 2: 스크롤을 멈추게 하는 인터랙티브 웹사이트

두 번째 테스트는 “상상할 수 있는 가장 인상적인 인터랙티브 스크롤 웹사이트”를 만들라는 것이었다. 모델에게 거의 완전한 창의적 자유를 줬다.

Fable의 결과물은 우주와 시간의 흐름을 따라가는 몰입형 웹사이트였다.

  • “100억 년” 같은 우주적 시간 스케일로 시작
  • 마우스 움직임에 반응하는 3D 배경
  • 구름, 붕괴, 은하, 초신성, 빛 같은 단계
  • 소리 효과 포함
  • 마지막에는 “you”라는 단어로 사용자를 향해 수렴

Sol의 결과물은 “Vesper Archive”라는 이름의 스토리형 웹사이트였다.

  • 역시 3D 배경과 사운드가 있음
  • 마우스 반응형 요소가 있음
  • 어떤 여정이나 이야기를 전달함
  • 나쁘지는 않지만 첫 번째 결과물만큼의 몰입감은 부족

화자는 이번에도 Fable의 결과가 더 인상적이라고 봤다. 다만 비용 차이는 훨씬 극단적이었다.

항목 Fable 5 GPT 5.6 Sol
시간 23분 약 7분
비용 19.24달러 약 1달러 초반
출력 토큰 약 80,000 약 20,000

중요한 질문은 이것이다.

Fable 결과물이 Sol보다 20배 더 좋았는가?

화자의 답은 “품질만 보면 Fable을 고르겠지만, 비용 대비로 보면 그렇게까지 차이가 난다고 말하기 어렵다”에 가깝다.

즉, 고객에게 보여줄 중요한 랜딩 페이지나 브랜드 경험이라면 Fable이 나을 수 있지만, 빠른 시안이나 내부 테스트라면 Sol이 훨씬 경제적일 수 있다.

4. 테스트 3: 다섯 가지 완전히 다른 비주얼 월드

세 번째 테스트는 더 모호한 요청이었다.

“게임, 프레젠테이션, 웹사이트, 시뮬레이션 등 어떤 형태든 좋으니 근본적으로 다른 다섯 개의 비주얼 요소를 디자인하라.”

화자는 모호한 목표를 줬을 때 모델이 얼마나 다양하고 창의적으로 반응하는지 보려 했다.

Fable은 다섯 개의 독립된 월드를 만들었다.

  1. Singularity
  2. 시공간을 휘게 하고, 에너지를 주입하고, 폭발시키는 느낌의 인터랙션

  3. 다만 목적이 명확하지 않음

  4. Terra

  5. 마우스로 조종하는 비행 시뮬레이터 느낌
  6. 속도 조절, 상승·하강, 시간대 변경 가능

  7. 물리감은 괜찮지만 렌더링이 다소 이상함

  8. Orbit

  9. 두 개의 링 사이를 클릭으로 전환하며 코인을 먹는 아케이드 게임

  10. 반응성은 좋지만 메뉴가 사라지지 않는 버그 존재

  11. Inkflow

  12. 팔레트 변경, PNG 저장이 가능한 생성형 비주얼 장난감

  13. 화자는 “심심할 때 누르는 버튼” 같은 랜덤한 느낌이라고 평가

  14. The Descent

  15. 바닷속 깊이 내려가는 인터랙티브 스토리
  16. 압력, 햇빛, 온도 등이 변함
  17. 타이타닉보다 깊은 곳까지 내려가는 식의 여정

Sol도 다섯 개의 작은 세계를 만들었다.

  1. Aurora Orchestra
  2. 오로라를 조작하는 시각·음향 경험

  3. 일부 버튼이 작동하지 않는 버그 있음

  4. Atlas of Lost Echoes

  5. 지도에서 잃어버린 메아리를 찾는 경험

  6. 콘셉트는 있지만 게임성은 약함

  7. Glyph Heist

  8. 이상한 단어를 입력하는 타이핑 게임

  9. 분위기는 좋지만 피드백과 종료 조건이 약함

  10. 슬라이드 덱

  11. 다섯 장짜리 발표 자료 형태

  12. 디자인은 꽤 괜찮고 Claude 스타일처럼 느껴짐

  13. Tide Pool

  14. 씨앗을 뿌리고 햇빛과 비를 주는 생태계 시뮬레이션
  15. 컴퓨터가 느려질 정도로 내부 시뮬레이션이 있는 듯함

화자는 이 테스트에서는 Sol에 손을 들어줬다. 압도적 승리는 아니지만, 전체적으로 다양성과 경험 설계가 더 나았다고 봤다.

항목 Fable 5 GPT 5.6 Sol
시간 15분 7분
비용 약 15달러 약 1달러
출력 토큰 약 65,000 약 22,000

흥미로운 점은, 다섯 가지를 만들라고 해서 시간이 5배 걸릴 줄 알았지만 오히려 이 테스트가 양쪽 모두에서 가장 빨랐다는 것이다.

5. API 원샷 테스트: 단발성 요청에서는 Sol이 강했다

에이전트 작업과 별개로, 화자는 API를 통해 모델에 단발성 질문을 던지는 테스트도 했다. 이는 복잡한 에이전틱 루프(Agentic Loop)가 아니라 “이거 뭐야? 답해줘” 같은 원샷(One-shot) 요청에 가깝다.

결과는 Sol이 압도적이었다.

항목 Sol Fable
승리 횟수 24 3
총 비용 16달러 63달러
답변했을 때 점수 0.98 0.966

다만 해석이 중요하다. Fable이 능력이 없어서 진 것이 아니라, 여러 번 답변 자체를 거부했기 때문에 성과가 낮게 나왔다. 화자는 Fable의 보안 가드레일(Security Guardrails)이 강하게 박혀 있는 것 같다고 말한다.

답변했을 때의 품질은 Sol 0.98, Fable 0.966으로 매우 비슷했다. 따라서 짧고 상태 없는 요청(Stateless Request)에서는 굳이 가장 비싼 모델을 쓸 필요가 없다는 결론이 나온다.

화자는 이를 단위 경제성(Unit Economics) 문제로 설명한다.

예를 들어 작업 난이도가 5라면, 성능 10짜리 비싼 모델이 꼭 필요하지 않다. 성능 5나 6짜리 모델이면 충분하고, 이 경우 Sol이 비용 대비 훨씬 낫다.

6. 비용, 속도, 토큰 효율의 차이

화자는 Sol이 단순히 API 단가만 싼 것이 아니라, 토큰을 더 적게 쓰는 경향이 있다고 본다.

API 가격 자체도 Sol이 Fable보다 대략 절반 수준으로 언급된다. 입력 토큰(Input Tokens)은 절반 정도, 출력 토큰(Output Tokens)은 절반보다 조금 더 비슷한 수준이라고 한다.

그런데 실제 에이전트 작업에서는 가격 차이가 더 커진다. 이유는 두 가지다.

  1. Sol 자체가 더 저렴함
  2. Sol이 출력 토큰을 훨씬 적게 씀
  3. Codex라는 하네스(Harness)가 Claude Code보다 더 빠르고 토큰 효율적인 경향이 있음

화자는 이전에도 Codex와 Claude Code를 비교했을 때 Codex가 더 빠르고 토큰 효율적이었다고 말한다.

속도 면에서는 API 호출에서 Sol의 중앙값(Median Latency)은 Fable보다 빨랐지만, 평균(Mean Latency)은 Fable이 더 빨랐다. 이는 Sol이 어떤 호출은 매우 빠르고 어떤 호출은 매우 느려 편차가 크다는 뜻이다. 반면 Fable은 대체로 20초 근처에서 안정적으로 움직였다고 해석한다.

하지만 에이전트 빌드에서는 Fable이 거의 항상 더 느렸다.

7. 최종 결론: Fable은 매니저, Sol은 작업자

화자의 최종 평가는 역할 구분이다.

Fable 5는 매니저, 공동창업자, 전략가에 가깝다.
GPT 5.6 Sol은 매우 뛰어난 작업자, 실행자에 가깝다.

Sol이 더 나은 영역은 다음과 같다.

  • 가격
  • 컴퓨터 사용(Computer Use)
  • 빠른 실행
  • 검증 작업(Verification)
  • 버그 찾기
  • 악마의 변호인(Devil’s Advocate)처럼 반대 관점에서 확인하기
  • 사용자가 시킨 일을 정확히 수행하기

Fable이 더 나은 영역은 다음과 같다.

  • 창의성
  • 글쓰기
  • 브레인스토밍
  • 조언
  • 전략적 판단
  • 지식 노동(Knowledge Work)
  • 영상 기획과 제작
  • 과도한 엔지니어링을 피하는 감각

Fable은 때로 사용자의 요청을 그대로 수행하기보다 컨설턴트처럼 반박하거나 방향을 조정하려 한다. 이것은 단점이 될 수도 있지만, 매니저나 전략가 역할에서는 장점이 된다.

반대로 Sol은 일을 빠르게 처리하고, 테스트하고, 검증하고, 배송(Shipping)하는 데 강하다.

화자의 이상적인 구조는 다음과 같다.

Fable이 여러 Sol 에이전트를 지휘하고, Sol들이 실제 작업을 수행하는 구조

이는 이커머스/물류 업무에도 적용 가능하다. 예를 들어 Fable에게 “이번 달 운영 개선 전략과 우선순위를 판단”하게 하고, Sol에게 “상품 설명 수정, CS 답변 초안, 재고 리포트 정리, 광고 문구 A/B안 생성” 같은 실행 작업을 시키는 식이다.

8. 모델 포지셔닝: Sol은 강하지만 Fable 5급은 아니다

화자는 GPT 5.5와 Opus를 비슷한 위치에 놓고, Sol은 그보다 확실히 앞선다고 본다. 하지만 Fable 5와는 아직 큰 격차가 있다고 평가한다.

그는 Sol이 정말 Fable 5급 차세대 모델이었다면 이름이 Sol 6이 되었거나 가격도 Fable 5급으로 책정됐을 것이라고 추측한다. 현재 Sol은 Opus급 가격에 가깝기 때문에, OpenAI가 진짜 GPT-6에 해당하는 더 큰 모델을 따로 준비하고 있을 수도 있다고 본다.

최종적으로 화자는 이렇게 정리한다.

  • Fable 5: 추론, 판단, 전략, 창의 작업
  • GPT 5.6 Sol: 실행, 배송, 검증, 반복 작업
  • GPT 5.5/Opus: Sol보다 아래 또는 비슷한 이전 세대 고성능 모델

그리고 중요한 조언을 남긴다.

벤치마크만 보지 말고, 내가 매일 하는 실제 업무로 직접 테스트해야 한다.

첫 번째로 Claude Code에는 Fable 5를, Codex에는 GPT 5.6 Sol을 넣고 똑같은 프롬프트를 줬다. 목표는 브라우저에서 실행되는 진짜 재미있고 플레이 가능한 오픈월드 자전거 게임을 만드는 것이었다. 창의적 자유도 줬고, 모델들이 무엇을 만들어내는지 보고 싶었다.

두 번째 테스트는 “상상할 수 있는 가장 인상적인 인터랙티브 스크롤 웹사이트를 만들어 달라”는 요청이었다. 완전한 창의적 자유를 줬다.

한 모델은 100억 년이라는 우주적 시간 흐름을 보여주는 웹사이트를 만들었다. 스크롤하면 구름, 붕괴, 은하, 첫 빛, 초신성 같은 장면이 이어지고, 배경은 3D로 반응했다. 사운드도 있었고, 마지막에는 “you”라는 단어로 끝났다. 꽤 멋졌다.

다른 모델은 Vesper Archive라는 웹사이트를 만들었다. 이것도 사운드와 3D 배경, 마우스 반응형 요소가 있었다. 어떤 여정을 이야기하는 식이었다. 나쁘지는 않았지만 첫 번째 결과물의 몰입감과 와우 포인트가 더 컸다.

첫 번째 결과물이 Fable이었다. Fable은 23분이 걸렸고, Sol은 거의 7분이 걸렸다. 비용은 Fable이 19.24달러, Sol은 1달러 조금 넘는 수준이었다. 출력 토큰은 Fable이 8만 개, Sol이 2만 개였다. 비용 차이가 거의 20배였다. 품질만 보면 Fable을 고르겠지만, Fable의 결과물이 정말 20배 더 좋았느냐고 물으면 꼭 그렇다고 보기는 어렵다.

세 번째 테스트는 “근본적으로 다른 다섯 개의 비주얼 요소를 디자인해 달라”는 것이었다. 게임, 프레젠테이션, 웹사이트, 시뮬레이션 등 무엇이든 가능하게 했다. 아주 모호한 프롬프트를 줬을 때 모델이 어떻게 반응하는지 보고 싶었다.

Fable은 다섯 개의 독립된 세계를 만들었다. Singularity는 시공간을 휘게 하고 에너지를 넣고 폭발시키는 느낌의 인터랙션이었다. Terra는 마우스로 조종하는 비행 시뮬레이터 같았다. Orbit은 링을 바꿔가며 코인을 먹는 아케이드 게임이었다. 다만 메뉴가 사라지지 않는 버그가 있었다. Inkflow는 팔레트를 바꾸고 PNG로 저장할 수 있는 생성형 비주얼 장난감 같았다. The Descent는 바닷속으로 깊이 내려가는 인터랙티브 스토리였다.

Sol은 Impossible Objects라는 갤러리를 만들었다. Aurora Orchestra는 오로라를 조작하는 경험이었지만 일부 버튼이 작동하지 않았다. Atlas of Lost Echoes는 지도에서 메아리를 찾는 경험이었다. Glyph Heist는 이상한 단어를 입력하는 타이핑 게임이었다. 분위기는 좋았지만 게임 피드백은 약했다. 또 하나는 슬라이드 덱이었는데 디자인은 꽤 괜찮았다. 마지막 Tide Pool은 씨앗을 뿌리고 햇빛과 비를 주는 생태계 시뮬레이션이었다.

이 테스트에서는 Sol에 손을 들어주겠다. 전체적으로 다양성과 경험 면에서 조금 더 나았다. Fable은 15분, Sol은 7분이 걸렸다. 비용은 Fable 약 15달러, Sol은 약 1달러였다. 출력 토큰은 Fable 6.5만 개, Sol 2.2만 개였다. 다섯 가지를 만들라고 했기 때문에 가장 오래 걸릴 줄 알았는데, 오히려 양쪽 모두에서 가장 빨랐다는 점이 흥미로웠다.

에이전트 실험과 별개로 API를 통한 원샷(One-shot) 테스트도 했다. 복잡한 에이전틱 루프(Agentic Loop)가 아니라, 짧게 질문하고 답을 받는 방식이었다. 결과는 Sol이 24번 이기고 Fable이 3번 이겼다. Fable은 아예 답변을 거부하는 경우가 많았다. 보안 가드레일(Security Guardrails)이 꽤 강하게 들어간 것 같았다.

비용도 Sol은 16달러, Fable은 63달러였다. 다만 답변했을 때의 점수는 Sol 0.98, Fable 0.966으로 비슷했다. 즉 실제 능력만 보면 큰 차이는 아니지만, Fable이 답변 거부를 많이 해서 Sol이 압도적으로 이긴 것이다.

이것은 단위 경제성(Unit Economics)의 좋은 예다. 작업 난이도가 5라면 굳이 성능 10짜리 모델을 쓸 필요가 없다. 5나 6 정도 모델이면 충분하다. 이런 빠른 원샷 API 요청, 특히 상태 없는 요청(Stateless Request)에서는 Sol이 Fable을 압도한다.

입력·출력 토큰 비용 관점에서도 Sol은 Fable의 거의 절반 수준이다. Opus 4.8과 비교하면 비슷한 가격대다. 그래서 Sol 5.6과 Fable 5를 비교하기보다는 Sol 5.6과 Opus 4.8을 비교하는 편이 더 맞는 것 같다. Fable 5는 차세대 모델처럼 느껴지지만, Sol은 왜 Sol 6이 아니라 5.6인지 궁금하다. 진짜 GPT-6급 모델을 따로 준비하고 있는 것일 수도 있다.

API 호출 비용에서는 Sol이 더 저렴했다. 하지만 에이전트 작업으로 들어가면 비용 차이가 훨씬 커진다. Fable은 더 비싸고, 토큰도 더 많이 쓴다. 반대로 Sol은 모델 자체도 싸고 토큰 사용도 효율적이다. Codex라는 하네스(Harness)도 Claude Code보다 빠르고 토큰 효율적인 경향이 있다.

속도 면에서는 API 지연 시간(Latency)의 중앙값은 Sol이 더 빨랐지만, 평균은 Fable이 더 빨랐다. 이는 Sol의 편차가 더 크다는 뜻이다. 어떤 작업은 매우 빠르고, 어떤 작업은 매우 오래 걸린다. Fable은 대체로 20초 근처에서 더 안정적으로 움직였다. 하지만 에이전트 빌드에서는 Fable이 거의 항상 더 느렸다.

여러 테스트와 실제 업무 사용 후 내 결론은 이렇다. Fable은 더 좋은 매니저다. 공동창업자나 전략가처럼 느껴진다. Sol은 정말 좋은 작업자다. Fable이 여러 Sol 에이전트를 지휘하는 구조가 굉장히 좋을 것 같다.

Sol은 가격, 컴퓨터 사용(Computer Use), 악마의 변호인(Devil’s Advocate)처럼 버그를 찾고 다른 관점에서 보는 능력, 검증(Verification), 속도에서 강하다. 사용자가 무엇을 시켰는지 잘 확인하고 정확히 실행하려는 느낌이 있다.

Fable은 더 창의적이고, 글쓰기와 브레인스토밍, 조언, 전략적 판단이 더 좋다. 하루 종일 지식 노동(Knowledge Work)을 할 때는 여전히 Fable을 선호한다. 다만 비용을 항상 정당화하기는 어렵다. 영상 제작에서도 Fable이 더 낫다고 느꼈다.

Fable은 과도한 엔지니어링을 덜 하는 편이다. 반면 Sol은 테스트를 많이 돌리고 때로는 너무 많이 생각한다. 특히 Sol을 Ultra 모드로 두면 계속해서 작업을 이어가기도 한다. 좋을 때도 있고 나쁠 때도 있다.

순수 역량만 보면 Fable 5는 다른 티어에 있다. Sol은 매우 좋고 GPT 5.5보다 확실히 낫지만, Fable 5는 아니다. 만약 Fable 5급이었다면 가격도 Fable 5급이었을 것이다. 지금 Sol은 Opus에 가까운 가격이다.

정리하면 Fable은 내 추론과 판단을 위한 모델이고, Sol은 배송과 실행을 위한 AI 모델이다. GPT 5.5와 Opus는 비슷한 위치에 있고, Sol은 그보다 확실히 앞서 있다. 하지만 Sol과 Fable 사이에는 여전히 꽤 큰 격차가 있다.

벤치마크를 보는 것도 좋지만, 결국 직접 손을 더럽혀 봐야 한다. 내가 매일 하는 실제 업무에 넣어봐야 한다. 어떤 사람은 Sol이 Fable보다 무조건 낫다고 할 수 있고, 어떤 사람은 전혀 동의하지 않을 수 있다. 사용 사례, 느낌, 지시 방식, 하네스와 세팅에 따라 달라진다. 이것이 내가 하루 종일 모델을 써본 뒤의 의견이다.
