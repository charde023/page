핵심 학습 포인트 (내가 배워야 할 것)

개념 왜 중요한가 한 줄
LLM 지식 베이스(LLM knowledge base) 단순 메모장이 아니라, 에이전트가 읽고 연결하고 재구성할 수 있는 개인 데이터 자산이 됨 많이 쌓은 원시 메모를 LLM이 구조화하게 만든다
음성 입력(voice dictation) 생각을 타이핑보다 빠르게 쌓을 수 있음 완벽한 글보다 많은 원자료가 먼저다
Markdown 기반 노트 Obsidian, Warp, Git, 에이전트 자동화와 잘 맞음 노트는 앱보다 파일 형식이 중요하다
노트 보강(enrichment) 태그, 출처, 백링크, 타임스탬프를 붙여 탐색 가능하게 만듦 원시 메모를 찾아볼 수 있는 노트로 바꾼다
고정 태그 목록 LLM이 매번 새 태그를 만들어 혼란을 키우는 것을 막음 태그는 자유 생성보다 제한된 목록에서 고르게 한다
개인 위키(personal wiki) 여러 노트에서 인물, 개념, 출처를 뽑아 탐색 가능한 구조를 만듦 내 생각으로 만든 위키피디아가 된다
자동화(automation) 매번 수동 실행하지 않아도 매일 노트가 정리됨 밤에 에이전트가 일하고 아침에 새 위키를 본다
그래프 뷰(graph view) 내 관심사와 생각의 빈틈을 시각적으로 볼 수 있음 연결된 주제와 비어 있는 영역을 발견한다

내가 모를 만한 것 / 처음 보는 것

  • Wispr Flow — 음성 받아쓰기 도구. 말한 내용을 문장과 문단 형태로 정리해준다.
  • Handy — 로컬 모델을 쓰는 오픈소스 음성 받아쓰기 도구. 기기 안에서 동작한다.
  • VoiceInk — 유료 일회성 라이선스 방식의 음성 받아쓰기 앱. 화자는 실제로 사용한다고 말한다.
  • Obsidian — Markdown 파일 기반의 개인 지식 관리 도구.
  • Hubble — 화자가 만든 Markdown 노트 탐색·작성 앱.
  • Warp — 터미널과 AI 에이전트 기능을 결합한 개발 도구. 여기서는 에이전트 실행 환경으로 사용된다.
  • Exa — 웹 검색·리서치용 도구. 에이전트가 출처를 찾을 때 붙일 수 있다.
  • 에이전트 스킬(agent skill) — 특정 작업을 반복 수행하도록 만든 에이전트용 지침 묶음.
  • 백링크(backlink) — 관련 노트끼리 서로 연결하는 링크.
  • Obsidian Headless CLI — Obsidian 노트를 로컬 또는 클라우드 환경과 동기화하는 명령줄 도구.
  • 클라우드 샌드박스(cloud sandbox) — 에이전트가 클라우드에서 파일을 내려받아 작업하고 다시 올리는 실행 공간.
  • Oz.dev — 화자가 언급한 클라우드 자동화 실행 환경.
  • Tailwind — HTML 화면을 빠르게 꾸밀 때 쓰는 CSS 프레임워크.

화자의 디테일 (놓치기 쉬운 포인트)

화자가 흘리듯 말한 구체 수치·설정값·명령어·뉘앙스. 원어 용어 괄호 병기, 맥락까지.

  1. 음성 입력은 평균 약 분당 200단어(words per minute) 수준이라고 언급했다 — 타이핑보다 빠르게 원시 생각을 쌓기 위한 근거.
  2. VoiceInk는 약 20달러 평생 라이선스(lifetime fee) 라고 설명했다 — 구독형 음성 앱을 피할 수 있는 대안.
  3. 음성 입력 단축키로 Option 키 또는 Function 키를 누르는 예를 들었다 — 생각나는 즉시 기록하기 위한 UX.
  4. 노트 보강 시마다 보강 시각 타임스탬프(timestamp) 를 남긴다 — 다음 에이전트 실행 때 이미 처리한 노트를 건너뛰기 위함.
  5. 태그는 에이전트가 임의 생성하지 않도록 참조 폴더(reference folder) 에 고정 목록을 둔다 — Claude 같은 LLM이 창의적으로 새 태그를 남발하는 문제를 줄임.
  6. 출처 찾기는 웹 도구(web tools)나 Exa를 활용한다고 했다 — 팟캐스트 URL 등 원천 자료를 자동으로 붙이기 위함.
  7. 보강 스킬 이름은 Enrich Note로 소개했다 — 태그, 출처, 백링크를 붙이는 반복 작업.
  8. 클라우드 자동화는 노트를 샌드박스로 동기화한 뒤 에이전트가 수정하고 다시 동기화하는 구조다 — 로컬 노트와 클라우드 작업을 연결하는 핵심 패턴.
  9. Git clone도 가능하지만 화자는 Obsidian CLI 동기화를 선호한다고 했다 — 매번 push/pull 하기 귀찮기 때문.
  10. 그래프 뷰는 별도 제품이 아니라 에이전트에게 HTML과 Tailwind로 만들어 달라고 해서 생성했다 — 이제 시각화도 에이전트에게 맡길 수 있다는 주장.

# 섹션 요지
1 문제 정의 Apple Notes처럼 흩어진 메모를 LLM이 이해 가능한 지식 베이스로 바꾸는 것이 목표
2 원시 메모 수집 완벽한 정리보다 음성 입력으로 많은 생각을 빠르게 쌓는 것이 먼저
3 노트 보강 에이전트가 태그, 출처, 백링크, 타임스탬프를 붙여 탐색 가능하게 만든다
4 개인 위키 생성 여러 노트에서 인물, 개념, 조직, 출처를 뽑아 클릭 가능한 위키를 만든다
5 자동화 매일 또는 매주 에이전트가 노트를 보강하고 위키를 갱신하게 한다
6 시각화 그래프 뷰와 차트로 관심사, 연결, 빈틈을 확인한다

1. LLM 지식 베이스란 무엇인가

화자는 많은 사람이 Apple Notes 같은 메모 앱에 생각을 쌓아두지만, 시간이 지나면 정리되지 않은 더미가 된다고 지적한다. 목표는 이런 흩어진 메모를 LLM 지식 베이스(LLM knowledge base) 로 바꾸는 것이다.

여기서 말하는 지식 베이스는 단순한 폴더 정리가 아니다. 내가 남긴 생각, 회의 메모, 리서치 기록, 팟캐스트 감상 등을 LLM이 읽고 다음 작업을 할 수 있는 재료로 만드는 구조다.

전체 흐름은 다음과 같다.

  1. 생각을 Markdown 파일로 많이 저장한다.
  2. 에이전트가 각 노트에 태그, 출처, 백링크를 붙인다.
  3. 관련 개념과 인물, 출처를 모아 개인 위키를 만든다.
  4. 이 과정을 자동화해서 매일 갱신한다.
  5. 마지막으로 그래프나 차트로 전체 지식 구조를 본다.

핵심은 처음부터 예쁘게 쓰는 것이 아니라, 나중에 LLM이 정리할 수 있도록 충분한 원자료를 쌓는 것이다.

2. 원시 생각을 가장 빠르게 쌓는 방법: 음성 입력

화자는 생각을 기록하는 가장 빠른 방법으로 음성 받아쓰기(voice dictation) 를 추천한다. 주변 동료가 있으면 컴퓨터에 대고 말하는 것이 어색할 수 있지만, 평균적으로 말하기는 타이핑보다 훨씬 빠르다.

화자는 음성 입력 속도를 약 분당 200단어로 언급한다. 타이핑을 아주 빠르게 하는 사람이 아니라면, 음성 기록이 가장 빠른 입력 방식이라는 것이다.

도구로는 다음을 소개한다.

  • Wispr Flow
  • Handy
  • VoiceInk

특히 Handy는 로컬 모델을 쓰는 오픈소스 도구라 구독 비용이 필요 없고, VoiceInk는 약 20달러 평생 라이선스 방식이라고 설명한다.

중요한 점은 음성 입력 결과가 완벽하지 않아도 된다는 것이다. 문단과 구두점이 어느 정도 자동으로 정리되면 충분하다. 팟캐스트를 듣다가 떠오른 생각, 회의 중 맥락, 책을 읽고 남긴 감상 등을 바로 말로 남기면 된다.

3. 원시 메모를 보강된 노트로 바꾸기

많은 원시 메모가 쌓이면, 다음 단계는 LLM 에이전트에게 노트를 보강하게 하는 것이다. 화자는 이를 노트 보강(enrichment) 이라고 설명한다.

보강된 노트에는 다음이 붙는다.

  • 주제 태그(tags)
  • 출처(source)
  • 보강 시각(enriched timestamp)
  • 관련 노트 링크(backlinks)
  • 초점 영역(focus areas)

예를 들어 화자는 Ferrari 창업 관련 팟캐스트 메모를 보여준다. 원래는 음성으로 받아쓴 긴 메모였지만, 에이전트가 팟캐스트 출처 URL을 찾고, 관련 태그를 붙이고, 다른 창업자 팟캐스트 메모와 연결했다.

여기서 중요한 설계가 있다. 태그를 LLM에게 마음대로 만들게 하지 않는 것이다. 화자는 별도의 참조 폴더에 고정 태그 목록을 두고, 에이전트에게 그 목록 안에서 고르게 한다. Claude 같은 모델은 새 태그를 창의적으로 만들어내기 쉽기 때문에, 명시적으로 “새 태그를 함부로 만들지 말라”고 지시한다.

4. Enrich Note 스킬의 구조

화자가 만든 보강 스킬은 Enrich Note다. 이 스킬은 하나의 노트 파일을 받아 다음 작업을 수행한다.

  1. 노트가 언제 보강되었는지 타임스탬프를 남긴다.
  2. 고정 태그 목록에서 적절한 태그를 선택한다.
  3. 웹 검색으로 원출처를 찾는다.
  4. 키워드 검색으로 관련 노트를 찾는다.
  5. 관련 노트 백링크를 하단에 추가한다.

이렇게 하면 노트가 서로 연결된다. 하나의 팟캐스트 메모가 다른 팟캐스트, 책, 인물, 개념과 연결되고, 시간이 갈수록 개인 지식의 웹이 촘촘해진다.

수동 실행도 가능하지만, 화자는 Warp 같은 에이전트 실행 환경에서 이 스킬을 호출하는 모습을 설명한다. 중요한 것은 특정 도구보다 반복 가능한 지침을 만들어 에이전트에게 파일 단위로 실행하게 하는 패턴이다.

5. 개인 위키 만들기

보강된 노트만으로도 충분히 유용하다. 예를 들어 어떤 책을 읽으며 여러 장에 걸쳐 남긴 메모가 있다면, 에이전트가 관련 메모를 서로 연결해준다. 사용자는 Apple Notes 안에서 “내가 어디에 적었지?” 하고 헤맬 필요 없이 관련 주제를 따라가면 된다.

화자는 이를 “내 생각으로 만든 위키피디아 토끼굴”에 비유한다.

한 단계 더 나아가면, 에이전트가 노트 전체를 읽고 개인 위키(personal wiki) 를 만들 수 있다. 이 아이디어는 Andrej Karpathy의 gist에서 영향을 받았다고 설명한다.

개인 위키는 다음을 자동으로 뽑아낸다.

  • 사람(people)
  • 장소 또는 조직(places/organizations)
  • 개념(concepts)
  • 출처(sources)
  • 관심 주제(focus areas)

예를 들어 최신 AI 뉴스에 대한 위키를 만들면, 모델 시스템 카드, AI 업계 인물, 조직, 음악 산업과 AI의 교차점 같은 항목이 자동으로 묶인다. 화자는 Adam Neely라는 재즈 음악가가 AI와 음악 산업에 대해 말한 내용을 AI 위키 안으로 끌어온 예를 든다.

즉, 개인 위키는 단순 요약이 아니라 여러 노트 사이의 교차점을 드러내는 탐색 인터페이스다.

6. 업무용 지식 베이스로 확장하기

화자는 이 방식이 개인 관심사뿐 아니라 업무에도 유용하다고 말한다.

예를 들어 회의 메모가 많다면 다음과 같은 위키를 만들 수 있다.

  • 만난 사람별 페이지
  • 고객사별 페이지
  • 회의별 요약
  • 관련 원본 메모 링크
  • 출처 자료 링크

이커머스나 물류 업무에 적용하면, 고객사, 공급사, 배송 이슈, CS 패턴, 제품 카테고리, 회의 기록을 서로 연결하는 업무용 위키를 만들 수 있다.

핵심은 “정리된 문서를 직접 쓰는 것”이 아니라, 매일 남기는 원시 기록을 LLM이 구조화하게 만드는 것이다.

7. 자동화: 밤에 에이전트가 일하게 만들기

수동으로 에이전트에게 “이 노트를 보강해줘”, “위키를 만들어줘”라고 요청할 수도 있다. 하지만 노트가 많아지면 시간이 걸린다. 그래서 화자는 이 과정을 자동화해야 한다고 말한다.

자동화 방식은 크게 두 가지다.

방식 장점 단점
로컬 자동화(local automation) 내 컴퓨터에서 직접 실행 노트북이 켜져 있어야 함
클라우드 자동화(cloud automation) 내가 자는 동안에도 실행 가능 동기화 구조가 필요함

화자는 Codex 앱의 자동화 기능과 Oz.dev 같은 클라우드 자동화 환경을 언급한다. Oz.dev는 매일 정해진 시간 또는 Slack 메시지, iMessage 같은 트리거로 에이전트 작업을 실행할 수 있다고 설명한다.

8. Markdown 노트를 클라우드 샌드박스와 동기화하기

클라우드 자동화의 기본 구조는 단순하다.

  1. 내 Markdown 노트 폴더를 클라우드 샌드박스로 동기화한다.
  2. 에이전트가 샌드박스 안에서 노트를 보강하거나 위키를 갱신한다.
  3. 변경된 파일을 다시 내 노트 폴더로 동기화한다.

화자는 이를 위해 Obsidian Headless CLI를 사용한다고 말한다. GitHub에 노트를 올리고 Git clone으로 처리할 수도 있지만, 매번 push/pull 하는 것이 번거롭기 때문에 Obsidian CLI 동기화를 선호한다고 설명한다.

이 구조를 만들면 사용자는 낮에 음성 메모만 남기고, 밤에는 에이전트가 다음 작업을 수행한다.

  • 새 노트 찾기
  • Enrich Note 실행
  • 태그와 백링크 추가
  • 출처 검색
  • 개인 위키 갱신
  • 다시 동기화

아침에 컴퓨터를 열면 최신 상태의 개인 위키가 준비되어 있다. 화자는 이를 “내 생각으로 만든 일간 신문”처럼 표현한다.

9. 그래프 뷰와 시각화

마지막 단계는 Markdown 문서와 위키를 넘어 시각화로 확장하는 것이다. 화자는 에이전트에게 모든 Markdown 파일을 읽고 HTML과 Tailwind로 그래프 뷰를 만들어 달라고 했다.

그래프 뷰에서는 다음을 볼 수 있다.

  • 내 관심사가 어떤 주제에 몰려 있는지
  • 책, 창업, AI, 엔지니어링, 신앙 같은 주제가 어떻게 묶이는지
  • 특정 노드가 어떤 다른 개념과 연결되는지
  • 내가 충분히 쓰지 않은 영역은 어디인지

중요한 점은 이 그래프 도구를 직접 설치하거나 개발하지 않았다는 것이다. 화자는 “에이전트에게 만들어 달라고 했다”고 말한다. 이제 에이전트가 로컬 파일을 읽고 HTML을 만들 수 있으므로, 원하는 시각화를 자연어로 요청할 수 있다.

예를 들어 “우주처럼 보이게 해줘”라고 하면 별자리 같은 그래프 화면으로 바꿀 수도 있고, 노트 작성 습관을 GitHub 잔디처럼 보여주는 차트도 만들 수 있다.

종합 체크리스트

  • [ ] 내 메모를 Markdown 파일로 저장할 수 있는 구조를 만든다.
  • [ ] 음성 입력 도구를 하나 정해 빠르게 원시 메모를 쌓는다.
  • [ ] 태그를 자유롭게 만들지 말고 고정 태그 목록을 먼저 만든다.
  • [ ] 노트 보강용 에이전트 지침을 만든다.
  • [ ] 각 노트에 보강 시각, 태그, 출처, 백링크를 붙이게 한다.
  • [ ] 여러 노트를 묶어 개인 위키를 생성해본다.
  • [ ] 사람, 조직, 개념, 출처 단위로 탐색 가능한지 확인한다.
  • [ ] 매일 또는 매주 자동 실행되는 스케줄을 만든다.
  • [ ] 클라우드 자동화를 쓸 경우 노트 동기화 방식을 정한다.
  • [ ] 그래프 뷰나 차트로 내 지식 구조를 시각화해본다.

오늘은 LLM 지식 베이스(LLM knowledge base) 라는 주제에 대해 이야기하겠습니다.

먼저 손을 들어볼까요. Apple Notes 폴더가 완전히 정리 안 된 엉망진창인 분이 얼마나 있나요? 어떻게 처리해야 할지 모르는 상태 말입니다. 꽤 많네요.

Obsidian을 써본 분은 얼마나 있나요? 그리고 지금도 꾸준히 쓰는 분은요? 조금 줄어드네요. 괜찮습니다.

오늘 Obsidian 자체를 많이 보여드리지는 않겠지만, Obsidian을 좋아하는 분이라면 특히 흥미로운 발표가 될 겁니다.

우리가 다룰 내용은 여러분이 LLM과 함께 남기는 원시 생각과 메모를 어떻게 정리해서, 실제로 탐색하고 이해할 수 있는 구조로 바꾸느냐입니다. 더 나아가 잊고 있던 아이디어를 다시 발견할 수도 있습니다.

목표는 흩어진 생각의 더미를 보기 좋고 정리된 형태로 바꾸는 것입니다. 처음에는 단순히 모든 생각이 들어 있는 원시 폴더에서 시작합니다. 예시에서는 노트를 Markdown으로 관리하겠습니다. 제가 직접 만든 Hubble이라는 앱도 보여드릴 텐데, Markdown 노트를 쉽게 탐색하고 쓸 수 있는 앱입니다. 하지만 Warp, Obsidian 등 어떤 Markdown 뷰어를 써도 됩니다.

그런 다음 원시 생각 묶음을 더 정리되고 서로 연결된 형태로 바꾸는 방법을 이야기하겠습니다. 관련 백링크(backlinks) 를 연결하고, 카테고리에 따라 태그를 붙이면 사람이 찾기도 쉽고 에이전트가 찾기도 쉬워집니다.

그다음에는 위키로 넘어갑니다. 내가 연구하는 분야, 개인 관심사 등을 클릭하며 돌아다닐 수 있는 구조로 만들고, 모든 노트에 들어 있는 사람, 개념, 출처를 분류합니다.

마지막으로 제가 앞서 보여준 멋진 그래프 뷰 같은 시각화(visualization) 도 이야기하겠습니다. 요즘은 에이전트가 내 컴퓨터에 접근하고 HTML을 다룰 수 있기 때문에 이런 작업이 매우 쉬워졌습니다.

먼저 원시 생각을 어떻게 기록하느냐부터 이야기하겠습니다. Apple Notes를 꺼내 무언가를 적는 것은 이미 꽤 쉽지만, 저는 생각을 기록하는 일이 더 쉬워야 한다고 봅니다.

혹시 Wispr Flow 같은 도구를 쓰는 분이 있나요? 손이 충분히 많지 않네요. 정말 충분하지 않습니다. 왜냐하면 음성 받아쓰기는, 동료들이 주변에 있을 때 컴퓨터에 대고 말하는 것이 어색하긴 해도, 생각을 종이에 옮기는 가장 빠른 방식이기 때문입니다.

평균적으로 분당 약 200단어 정도가 나온다고 알고 있습니다. 올림픽급 타자 실력이 아니라면 여러분이 가진 어떤 방법보다 빠를 겁니다.

그래서 저는 맥락을 기록하기 위해 어떤 형태든 음성 입력 도구(voice input tool) 를 쓰라고 권합니다. 도구는 여러 가지가 있습니다. Wispr Flow 구독료를 내지 않는 분들에게는 좋은 소식이 있습니다. 이제 이런 기능에 꼭 돈을 낼 필요는 없습니다. 로컬 모델로도 가능합니다.

잠깐 도구 이야기를 하자면, 제가 좋아하는 도구가 있습니다. Handy라는 오픈소스 음성 받아쓰기 도구입니다. 로컬 모델을 사용하고, 기기 안에서 동작하며, 사용하기 쉽습니다.

또 VoiceInk라는 비슷한 도구도 있습니다. 이건 앱 업데이트를 받기 위한 약 20달러 평생 요금인 것으로 알고 있습니다. 개발자를 지원하는 의미로 써볼 만합니다. 제가 쓰는 도구가 이것입니다.

이 도구는 단축키와 모바일 앱을 제공합니다. 무언가를 기록하고 싶으면 컴퓨터에서 Option 키나 Function 키를 누르고 말하면 됩니다. 그러면 말하는 내용을 받아 적기 시작하고, 나중에는 문장과 문단 형태로 정리해줍니다.

끝부분이 조금 잘렸지만, 구두점이 잘 들어가는 것을 볼 수 있습니다. 여기 보이는 문단 나눔이 있는 전체 내용은 제가 팟캐스트를 듣고 한 번에 길게 말한 내용을 전사한 것입니다.

이 예시는 Walt Disney 창업 이야기를 다룬 Acquired 팟캐스트를 들은 뒤 남긴 메모입니다. 제 관심사와는 조금 다르지만, 이런 비즈니스가 어떻게 만들어졌는지 흥미로워서 음성 받아쓰기 앱을 꺼내 기록했습니다.

이제 저는 거의 모든 노트를 이런 방식으로 남깁니다. 컴퓨터든 휴대폰이든 그냥 말로 원시 데이터를 쌓습니다.

제가 이 방식을 권하는 이유는, LLM이 위키나 시각화 등을 만들게 하려면 많은 원시 데이터(raw data) 가 필요하기 때문입니다. 재료가 많아야 합니다.

그러니 조금 거칠고, 장황하고, 완벽한 글머리표 형식이 아니어도 걱정하지 마세요. 괜찮습니다. 목표는 그 순간의 생각을 가능한 한 많이 기록하는 것입니다.

회의 전사일 수도 있고, 중요한 글을 읽고 난 뒤의 리서치 메모일 수도 있습니다. 무엇이든 생각을 종이에 남길 수 있으면, 나중에 LLM이 접근하기 매우 좋습니다.

이제 이런 원재료를 더 유용한 형태로 바꾸는 이야기를 하겠습니다. 이것은 Ferrari 창업에 대해 제가 남긴 다른 노트입니다. 이 사람 이야기를 듣다가 약간 토끼굴에 빠졌습니다. 여기 보이는 것은 LLM에게 약간의 조사를 부탁하면 얻을 수 있는 결과입니다.

가운데에는 같은 노트, 즉 음성 받아쓰기 전사 스타일의 원문이 있습니다. 하지만 이제 세부 정보가 더 붙어 있습니다.

주제 태그를 볼 수 있고, 이것이 팟캐스트이며 어떤 초점 영역과 관련되어 있는지도 볼 수 있습니다. 출처도 있습니다. URL을 찾아 가져왔습니다. 언제 보강되었는지도 적혀 있습니다. 왜 이렇게 하는지는 곧 설명하겠습니다.

하단에는 백링크도 있습니다. “이 노트는 전에 들었던 다른 팟캐스트와 관련이 있으니 서로 연결하자”는 식입니다. 이런 연결망은 노트를 추가할수록 점점 더 촘촘해집니다.

이런 상태로 만드는 방법은 예상하시는 것처럼 에이전트 스킬(agent skill) 을 사용하는 것입니다. 저는 여기 Enrich Note라는 스킬을 만들었습니다.

이 스킬은 에이전트에게 노트 파일 하나를 받아 더 유용한 형태로 바꾸라고 지시합니다.

먼저 노트를 보강하고, 타임스탬프를 넣습니다. 그래야 나중에 에이전트가 다시 처리할 때 과거에 다른 에이전트가 이미 보강했다는 사실을 기억할 수 있습니다.

태그도 생성하게 합니다. 다만 저는 모든 태그를 작은 참조 폴더에 넣어둡니다. 그래야 에이전트가 매번 새로운 태그를 발명하지 않습니다. 구체적인 목록을 보고 고르게 하는 것입니다.

저는 에이전트에게 새 태그 추가를 꺼리라고 지시합니다. Claude는 창의적으로 굴기를 좋아하기 때문입니다. 그래서 “그러지 말고 지침을 따르세요. 정말 패턴을 발견했을 때만 목록에 추가하세요”라고 말합니다.

또한 웹 도구로 출처를 조사하라고 지시합니다. 요즘은 대부분의 에이전트가 웹 검색을 가지고 있습니다. 없다면 Exa 같은 도구를 연결해 출처를 찾게 할 수 있습니다.

마지막은 관련 노트입니다. 파일 호출을 사용하고, 핵심 용어 검색으로 관련 노트를 찾고, 하단에 백링크를 넣습니다. 그러면 서로 연결된 웹이 생깁니다.

이 스킬은 원하는 실행 환경에서 수동으로 실행할 수 있습니다. 여기서는 Warp를 사용하겠습니다. 저는 완전히 편향 없이 Warp의 큰 팬입니다.

Warp는 여러 모델에 접근할 수 있게 해주며, 오픈 웨이트 모델도 사용할 수 있습니다. 예를 들어 이런 작업에 꽤 좋은 GLM 5.2를 시험해볼 수도 있습니다.

이 노트로 들어가 Enrich Note를 호출하고, 앞서 만든 노트 파일 경로를 가져와 더 자세히 보강하라고 말하면 됩니다.

완료된 실행도 보여드릴 수 있습니다. 여기 보이는 것은 모든 노트에 자동화 형태로 실행한 결과입니다.

에이전트는 과거에 보강되지 않은 노트를 찾습니다. 앞에서 말했듯, 노트 상단에 보강될 때마다 타임스탬프를 남깁니다. 그래서 다음번 실행 때 아직 태그가 없는 노트를 찾을 수 있습니다.

그런 다음 모든 해당 노트에 전체 흐름을 실행합니다. 파일을 수정하고, 결과적으로 이전보다 더 정리된 노트북을 얻게 됩니다.

매우 쉽습니다. 이 작업은 백그라운드에서 돌아가게 두고, 위키 이야기를 이어가겠습니다.

관련 아이디어들을 연결한 다음 단계는 그 자체로도 충분히 유용할 수 있습니다. 예를 보여드리겠습니다.

여기 있는 것은 제가 어둠의 왼손(The Left Hand of Darkness) 을 읽으며 남긴 생각 덤프입니다. 좋은 책입니다. 여러 장을 읽다가 흥미로운 부분이 있을 때마다 자투리 메모를 남겼습니다.

에이전트는 관련 노트를 묶어주기 때문에 클릭해서 찾아갈 수 있습니다. Apple Notes에서 “2주 전에 이 내용 어디에 적었지?” 하고 찾을 필요가 없습니다. 관련 주제로 찾아줍니다.

Wikipedia 토끼굴을 따라가는 것을 좋아하는 분이라면, 이것은 내 생각으로 만든 Wikipedia 토끼굴을 발명해주는 느낌입니다. 꽤 재미있습니다.

더 탐색하기 쉽게 만들고 싶다면, 이 위에 위키를 생성하라고 할 수 있습니다. 원시 재료를 가져다가 더 든든한 무언가로 요리하는 셈입니다.

제가 관심 있는 주제들로 생성한 위키가 몇 개 있습니다. 하나는 예상 가능하겠지만 최신 AI 뉴스입니다.

팟캐스트를 듣거나 최신 모델의 시스템 카드 같은 리서치 문서를 읽을 때, 그 내용을 모두 끌어와 관련 주제별로 묶어주는 위키를 갖고 싶었습니다.

이 위키를 열어보면 사람, 장소, 사물 같은 묶음을 볼 수 있습니다. 출처 목록이 있고, 가장 관심 있는 주제들도 있습니다.

예상한 것도 있고 예상하지 못한 것도 있습니다. 예를 들어 Ralph Loeb 관련 토끼굴이 보입니다. 여러 아이디어에서 뽑힌 개념들도 있습니다.

Adam Neely는 재즈 음악가인데, AI가 음악 산업에 어떤 영향을 미쳤는지 이야기해왔습니다. 저는 그 내용을 흥미롭게 생각해 적어두었고, 최신 AI 위키 안에 끌어와 쉽게 찾을 수 있게 했습니다.

조직 항목도 있습니다. 대부분 예상 가능한 조직일 것입니다. 어떤 것은 음악 관련이고, 어떤 것은 이 발표 뒤에 직접 시험해볼 만한 것입니다.

에이전트가 이것을 생성하게 하는 아이디어는 Andrej Karpathy의 gist에서 왔습니다. LLM 지식 베이스 아이디어가 여기서 모였습니다. 지금은 그의 이름과 “wiki”를 검색하면 쉽게 찾을 수 있습니다. 많이 사용되었습니다.

원리는 간단합니다. Apple Notes에서 가져온 원시 노트들이 들어 있는 디렉터리를 가져오고, 우리가 관심 있는 초점 영역으로 결합합니다.

원시 출처를 가져와 위키를 만듭니다. 원하는 대로 얼마든지 조정할 수 있습니다. Karpathy도 이것을 하나의 아이디어라고 부릅니다.

최신 AI 위키를 만들 때 저는 관심 있는 내용을 설명하고, 원시 폴더 위치를 알려주고, 그의 gist에 있는 지침을 기반으로 “위키를 생성해달라”고 했습니다.

다른 주제로도 해봤습니다. 조금 특이한 예인데, Bible in a Year 팟캐스트를 듣고 있었기 때문입니다. 최근 공부해보고 싶었던 주제였고, 제 전문 분야와는 완전히 달랐으며, 이름을 자꾸 잊는 등장인물도 많았습니다.

종교 텍스트를 읽어본 분이라면 이름들이 비슷하게 들리고 발음하기 어려울 수 있다는 것을 아실 겁니다. 각 인물이 누구이고 무엇을 했는지 참조와 함께 정리해주는 것은 매우 유용합니다.

클릭하면 해당 인물이 누구인지 설명하는 항목이 생성됩니다.

이것은 업무 공간에서도 유용합니다. 회의 메모를 많이 남기고, 만난 사람들에 대한 섹션을 만들고 싶다면 가능합니다. 고객 성공(customer success) 업무에서 관심 고객을 정리하는 데도 쓸 수 있습니다.

관련 회의에 대한 백링크도 만들 수 있고, 출처 링크도 붙일 수 있습니다. 원본 메모로 돌아가고 싶다면 클릭해서 원재료를 확인할 수 있습니다.

결국 우리가 하려는 것은 매일 남기는 많은 노트를 이해 가능하게 만들고, 조금 더 탐색 가능하고 읽기 쉽게 만드는 것입니다.

다음으로 이야기할 것은, 필요할 때마다 에이전트에게 이런 것들을 생성하라고 요청할 수 있다는 점은 좋지만, 에이전트가 작업하는 데 시간이 걸린다는 것입니다.

이상적으로는 이 흐름이 백그라운드에서 돌아가야 합니다. 우리가 자는 동안 또는 자동 스케줄에 따라 실행되면 좋습니다. 그래서 다음 주제는 노트 보강, 위키 생성, 지속 업데이트 같은 스킬을 매일 또는 매주 일정으로 실행되게 만드는 것입니다.

이런 일을 해주는 플랫폼은 여러 가지가 있습니다. Codex 앱을 써봤다면 자동화 도구가 있어서 매일 내 컴퓨터에서 작업을 실행할 수 있습니다. 하지만 로컬 자동화이기 때문에 실행 시점에 노트북이 열려 있어야 합니다.

클라우드에서 실행하고 싶다면 Oz.dev라는 것도 있습니다. 웹 브라우저에서 검색하면 자동 스케줄과 Slack 메시지, iMessage 같은 트리거를 설정하는 데 도움을 줍니다.

저는 이런 작업을 스케줄로 설정했습니다. 앞서 보여준 위키 스킬을 지침으로 인코딩해둔 자동화도 있습니다.

작동 방식은 이렇습니다. Markdown 폴더를 가져와 어떤 박스, 예를 들어 Docker 기반 클라우드 샌드박스에 동기화합니다. 에이전트가 작업을 마치면 다시 동기화합니다.

저는 Obsidian Headless CLI를 사용했습니다. Obsidian에는 컴퓨터의 Markdown 묶음을 다른 곳으로 동기화하고 다시 내려받게 해주는 좋은 도구가 있습니다.

덜 창의적인 방식으로는 Git clone을 해도 됩니다. 모든 노트를 GitHub 폴더에 넣고 클라우드 에이전트가 내려받아 작업하게 하는 것입니다.

저는 Obsidian CLI를 더 선호합니다. 노트를 push하고 pull할 필요가 없기 때문입니다. 아무도 그럴 시간이 없습니다. 저는 그냥 백그라운드에서 동기화되기를 원합니다. 이 도구가 그 역할을 합니다.

클라우드 샌드박스에 이 도구를 설치하면 Markdown 폴더를 동기화할 수 있습니다. 그 안에서 프로세스를 실행합니다. 예를 들어 앞서 보여준 Enrich Note 스킬을 실행할 수 있습니다. 에이전트에게 “아직 보강되지 않은 N개의 노트에 Enrich Note를 실행하라”고 지시하면 됩니다. 그러면 도구 호출과 코드 변경을 수행하고, 끝나면 모든 것이 다시 동기화됩니다.

흐름은 정말 단순합니다. 클라우드 러너에게 이렇게 하라고 지시한 것입니다.

Oz를 잘 몰라도 괜찮습니다. 매일 떠서 에이전트에게 이 작업을 시키는 클라우드 샌드박스라고 보면 됩니다.

프롬프트는 이런 식입니다. “환경에 Obsidian CLI를 넣어두었다. 그것을 사용해서 위키를 내려받고 업데이트하라.” 제 설정에 맞춘 특별 지침을 넣고, 마지막에 다시 동기화하라고 했습니다.

그러면 아침에 컴퓨터로 돌아왔을 때 완전히 새로워진 위키를 볼 수 있습니다. 매일 아침 신문 같지만, 내 생각으로 만든 신문입니다. 정말 흥미롭습니다.

Enrich Note 단계에 대한 스케줄도 설정했습니다. 백링크를 생성하고 모든 노트를 더 쉽게 탐색하게 만드는 단계입니다. 이것도 스킬로 만들었습니다. 마찬가지로 동기화하고, Enrich Note를 실행하고, 다시 올립니다.

제가 컴퓨터를 켤 때쯤이면 모든 것이 준비되어 있습니다. 실행 결과도 브라우저에서 볼 수 있습니다.

여기서는 앞서 만든 모든 노트에 Enrich Note가 실행되었습니다. 같은 작업이지만 클라우드에서 돌아간 것입니다.

제가 자는 동안 에이전트가 그날 남긴 모든 노트를 살펴보고, 탐색하기 쉬운 형태로 연결했습니다. 매우 깔끔하고 사용하기 쉽습니다.

노드들을 클릭 가능하게 만들라고도 했습니다. 이제 어떤 노드를 선택하면 그것이 다른 것과 어떻게 연결되는지 볼 수 있습니다. 여러 아이디어와 연결되어 있고, 그래프를 걸어 다니듯 탐색할 수 있습니다.
