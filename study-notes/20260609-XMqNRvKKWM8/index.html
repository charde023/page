핵심 학습 포인트 (내가 배워야 할 것)

개념 왜 중요한가 한 줄
VRAM vs 시스템 RAM 역할 구분 모델이 VRAM을 초과하면 속도가 5-6배 떨어짐 VRAM에 다 올려야 빠름
Quantization (Q4/Q6/Q8) 모델 크기·속도·품질의 3각 트레이드오프 Q4가 크기·품질 균형점
MoE (Mixture of Experts) 큰 모델을 GPU+CPU에 나눠 올려 성능 확보 가능 active 파라미터만 GPU에
LM Studio 개발자 모드 + 서버 OpenAI 호환 API로 어느 클라이언트에든 연결 /v1 엔드포인트 공유
Continue 확장 roles 설정 autocomplete 모델과 agent 모델을 분리 운영 YAML에 roles: [autocomplete]
GitHub Copilot 로컬 모델 연결 Copilot 구독 없이 로컬 모델을 Copilot UI로 사용 VS Code Insider 필요
Pi CLI 에이전트 연결 터미널 기반 에이전틱 루프, 완전 오프라인 가능 /model 슬래시로 전환

내가 모를 만한 것 / 처음 보는 것

  • MoE (Mixture of Experts): 파라미터 일부만 활성화되는 아키텍처. 모델명에 35B+3B 또는 35x3 식으로 표기 — 첫 숫자가 총 파라미터, 둘째가 active 파라미터. LM Studio에서 number of layers for which to force MoE weights onto the CPU 슬라이더로 CPU 오프로드 비율 조절.
  • Quantization bit-depth: 16bit(원본) → 8bit(1단계 축소) → 4bit(4단계 축소) → 3bit·2bit. Q4 = 16 ÷ 4 개념으로 이해하면 쉬움.
  • GPU Offload 슬라이더: LM Studio 모델 로드 시 나타나는 설정. max로 올리면 전 레이어를 GPU에 올림. VRAM 초과 시 스스로 시스템 RAM 스필오버.
  • Continue 확장 (continue.dev): VS Code에서 autocomplete + agent 모드를 모두 제공. 설정 파일(YAML)에 provider·model·apiBase·roles 지정.
  • Pi CLI (pi.dev): 터미널 에이전트 프레임워크. pi.dev에서 install 명령 복사 후 설치. /model 슬래시 커맨드로 모델 선택.
  • Unsloth: HuggingFace에서 고성능 quantization 패키지로 유명. 4bit·3bit·2bit 버전 경량 모델 빠르게 찾을 수 있음 → 용어노트 추가 예정.
  • Mac 유니파이드 메모리: GPU VRAM과 시스템 RAM이 동일 풀 → 스필오버 없음. Windows 전용 VRAM+RAM 분리 구조와 다름.

화자의 디테일 (놓치기 쉬운 포인트)

  1. 자신의 GPU는 VRAM 16GB, 시스템 RAM은 고사양(영상 편집 목적) — 일반 개발자 기준이 아님. 더 낮은 스펙에서도 작동 가능하다고 강조.
  2. 모델 로드 시 context 길이를 늘리면 VRAM 사용량이 최대 2배까지 올라갈 수 있음 — context 크기가 모델 크기만큼 중요.
  3. GPU 완전 적재(VRAM 거의 꽉 참)에서 124 tokens/sec, 시스템 RAM 스필오버 발생 시 24 tokens/sec → 약 6배 차이.
  4. MoE 모델에서 CPU 오프로드 레이어를 30/40으로 설정했을 때 43 tokens/sec 수렴 — "느리지 않다"고 표현.
  5. autocomplete용 모델은 Qwen 2.5 1.5B (1GB) 사용 — 이유는 속도. timeout 1000ms보다 빨리 응답해야 해서.
  6. agent용 모델은 Qwen 3.6 (27B, Q4 quantization) — VRAM 17.48GB 추정이지만 MoE 오프로드로 16GB GPU에 올림.
  7. Continue 확장 도구 설정: run terminal command → ask first, create rules → excluded, fetch URLs → ask first, 나머지 파일 읽기·쓰기 → automatic.
  8. GitHub Copilot 로컬 모델 연결은 현재 VS Code Insider(베타)에서만 가능 — 일반 버전은 추후 지원 예정.
  9. GitHub Copilot 로컬 모델 사용 시 인터넷 연결 필요 (GitHub 서버와 통신) — 완전 오프라인은 Pi CLI 또는 Continue.
  10. 동일 프롬프트(스도쿠 앱 생성) → Qwen 3.6 로컬: 9분, Claude Sonnet 4.6: 9분 — 생성 시간이 같았으나 Sonnet은 더 많은 thinking 시간 포함.
  11. 버그 수정 작업에서: Sonnet 4.6 45초, Qwen 로컬 2.5분 — 코드베이스 읽기 속도 차이가 원인.
  12. 클라우드 플랜 $100–$200/월 구독을 2~3달 취소하면 더 고사양 AI 전용 하드웨어 구매 가능 — 화자 본인 하드웨어는 영상 편집 목적이라 AI 최적화 아님.
  13. Ctrl+Alt+Space 단축키: Continue 자동완성 강제 트리거.
  14. Pi CLI 설정 파일에서 api: openai completions로 명시해야 agent 모드가 작동.

# 섹션 요지
1 모델 동작 원리 파라미터 수·컨텍스트 크기 → 모델 용량 결정. GPU VRAM > 시스템 RAM 순위
2 모델 선택 (LM Studio) 모델 브라우저에서 파라미터·VRAM 추정치 확인, Q4 quantization 추천
3 Hugging Face에서 직접 내려받기 trending 필터 + inference available 필터, unsloth quantization 추천
4 LM Studio 개발자 모드 서버 실행, /v1 URL 확인, 여러 모델 동시 로드 가능
5 MoE 모델 활용 CPU 레이어 오프로드 슬라이더로 대형 모델을 중급 GPU에서 실행
6 Continue 확장 설정 autocomplete 모델 + agent 모델 분리, YAML roles 설정, 도구 권한 설정
7 GitHub Copilot 로컬 모델 VS Code Insider에서 OpenAI compatible 추가, 인터넷 연결 필요
8 Pi CLI 연동 /model 커맨드, models 파일에 LM Studio URL+모델ID 등록
9 성능 비교 스도쿠: 로컬=클라우드 동일 9분. 버그수정: 클라우드 45초 vs 로컬 2.5분

1. 모델 동작 원리 — VRAM·파라미터·컨텍스트

모델은 파라미터 수와 컨텍스트 크기 두 가지로 용량이 결정된다. 862B 파라미터짜리 모델은 어떤 소비자 GPU에도 올릴 수 없고, 9B 파라미터·Q4 quantization이면 6.55GB — 16GB GPU에 완전 적재 가능.

모델을 로드하면 먼저 VRAM에 꽉 채우고, 넘치면 시스템 RAM으로 스필오버된다. VRAM 완전 적재 시 124 tok/s, 스필오버 발생 시 24 tok/s — 약 6배 속도 차이. 컨텍스트 길이를 늘릴수록 추가 메모리를 차지하므로 VRAM 한계에서 컨텍스트를 무리하게 키우면 안 된다.

Mac 유니파이드 메모리는 GPU·CPU RAM이 동일 풀이라 스필오버 없이 최대 RAM까지 사용 가능하지만, 한계를 넘으면 그냥 실패한다.

2. 모델 선택 — LM Studio 브라우저 + Hugging Face

LM Studio 모델 탭에서 키워드 검색 → 파라미터 수·VRAM 추정치 직접 확인. 파라미터 옆에 VRAM 추정치(예: 17.48 GB)가 표시됨.

Quantization 가이드:

bit 설명 특징
16bit 원본 풀 모델 가장 크고 가장 정확
8bit 절반 크기 품질 거의 유지
4bit 추천 균형점 크기 절반·품질 소폭 저하
3bit 더 압축 대형 MoE 모델에서 활용
2bit 최소 크기 품질 저하 큼

모델 능력 태그 확인: vision(이미지 처리), tool use(도구 호출), reasoning(thinking 모드). 에이전틱 코딩에는 tool use + reasoning 둘 다 있는 모델 권장.

Hugging Face에서 직접 내려받을 때: trending 정렬 + inference available 필터 + unsloth 배포판 선택 → "Use this model" → "Browse quantizations" → LM Studio에서 열기.

3. LM Studio 설정 — 로드 파라미터

로드 시 "manually choose model load parameters" 토글 활성화 필수. 주요 설정:

  • GPU Offload: VRAM에 다 들어가면 max로 설정. 그러면 전 레이어가 GPU에 올라감.
  • Context Length: 늘릴수록 메모리 증가. 채팅용은 5,000~10,000이면 충분. 에이전틱 코딩이면 더 크게.
  • MoE CPU Layers: MoE 모델에서만 나타남. 낮을수록 GPU 많이 사용 → 빠름. GPU 부족하면 값 올려서 CPU로 오프로드.

개발자 탭에서 서버 status: running 확인. URL(기본 http://localhost:1234/v1)을 모든 클라이언트에서 공통으로 사용.

4. MoE 모델로 대형 모델 활용하기

MoE 모델 명명법: 35B+3B 또는 35Bx3 — 35B가 총 파라미터, 3B가 active 파라미터. active 파라미터 부분만 GPU에 올리고 나머지를 CPU로 내리는 게 핵심 전략.

Kyle의 설정 예시: 40레이어 모델에서 30레이어를 CPU로 오프로드(30/40) → GPU에 중요 레이어만 남김 → 43 tok/s 달성. 같은 모델을 MoE 오프로드 없이 전부 GPU에 때려 넣으면 스필오버로 1 tok/s 수준으로 추락.

5. Continue 확장 설정 (VS Code)

autocomplete용 소형 모델 분리 운영이 핵심. 에이전트 모델이 VRAM을 다 차지해도 autocomplete는 별도 소형 모델이 빠르게 처리.

YAML 설정 구조:

# autocomplete 모델
- name: autocomplete
  provider: lmStudio
  model: <LM Studio에서 복사한 정확한 모델 ID>
  apiBase: http://localhost:1234/v1
  roles:
    - autocomplete

# agent/chat 모델
- name: qwen-agent
  provider: lmStudio
  model: <LM Studio에서 복사한 정확한 모델 ID>
  apiBase: http://localhost:1234/v1
  capabilities:
    - tool_use
    - image_input

도구 권한 설정 (settings > tools):

도구 권장 설정
파일 읽기·생성·편집 automatic
터미널 명령 실행 ask first
URL 불러오기 ask first
rules 생성 excluded

자동완성 강제 트리거: Ctrl+Alt+Space. LM Studio 개발자 로그에서 호출 시간 확인 가능 (예: 259ms) — timeout(1000ms)보다 느리면 더 작은 모델로 교체.

6. GitHub Copilot 로컬 모델 연결

VS Code Insider 버전 필요 (일반 버전에는 아직 미지원). Copilot 구독 불필요.

설정 경로: Copilot 채팅 패널 → 모델 드롭다운 → 기어 아이콘 → "Add models" → "OpenAI compatible"

{
  "name": "LM Studio",
  "models": [
    {
      "id": "<LM Studio 모델 ID>",
      "name": "Qwen 3.6",
      "url": "http://localhost:1234/v1",
      "toolCalling": true,
      "vision": true,
      "maxInputTokens": <LM Studio context 길이 복사>,
      "maxOutputTokens": <원하는 값>
    }
  ]
}

변경 후 Developer: Reload Window 필수. 주의: Copilot UI 사용 시 GitHub 서버와 통신하므로 인터넷 연결 필요 — 완전 오프라인이 목표면 Continue나 Pi CLI 사용.

7. Pi CLI 에이전트 연결

pi.dev에서 install 명령 복사 → 터미널에서 실행 → pi 입력으로 실행.

모델 설정 파일(OS마다 경로 다름, Pi 문서 참고):

lmstudio:
  provider: lmStudio
  base_url: http://localhost:1234/v1
  api: openai completions    # agent 모드에 필요
  api_key: any               # 아무 값이나 OK
  models:
    - id: <LM Studio 모델 ID>
      context_window: <LM Studio context 길이>
      reasoning: true        # reasoning 모델이면
      input:
        - text
        - image              # vision 지원이면

/model 슬래시 커맨드로 모델 전환. 완전 오프라인 동작 가능.

8. 클라우드 vs 로컬 성능 비교

작업 Claude Sonnet 4.6 Qwen 3.6 (로컬) 비고
스도쿠 앱 vibe coding (one-shot) 9분 9분 동일. Sonnet은 thinking 시간 포함
코드베이스 버그 수정 45초 2.5분 코드 읽기 속도 차이
결과물 품질 center pencil marking 추가 등 미세 우위 거의 동등 복잡도에 따라 격차 벌어짐

비용 관점: 클라우드 플랜 $100~200/월 → 2~3달 절감 = AI 최적화 고사양 하드웨어 구매 가능. 영상 편집용 하드웨어는 AI 최적화 아니라 가성비 낮음.

전체 전사 펼치기

AI 요금이 너무 비싸다. 월정액 플랜은 거의 다 껍데기가 됐고, 결국 비싼 API 요금을 내야 한다. 그래서 나는 로컬에서 완전히 실행되는 AI를 셋업하는 게 어떤 것인지 파고들기로 했다 — 완전 프라이빗, 빠르고, 채팅뿐 아니라 자동완성(autocomplete)과 에이전트 모드까지 전부 된다. VS Code에서 직접 에이전트를 설정할 수 있고, Pi 커맨드라인 도구 같은 오픈 코드 스타일 에이전트도 쓸 수 있다.

단순히 "이렇게 해라"가 아니라 모든 개념이 어떻게 작동하는지 설명한다. 그래야 영상을 지금 보든 1년 뒤에 보든, 어떤 모델이든 어떤 하드웨어든 본인 상황에 맞게 완벽히 셋업할 수 있다.

WebDevSimplified에 돌아온 것을 환영한다. 나는 Kyle이고, 웹을 단순하게 만드는 게 내 일이다.

모델이 어떻게 실행되는가

모델은 크게 두 가지로 구성된다: 파라미터 수와 컨텍스트 크기. 862B 파라미터는 로컬 하드웨어에서 절대 실행 불가, 9B 정도가 현실적이다. 컨텍스트는 모델이 한 번에 얼마나 많은 정보를 담을 수 있냐 — 클수록 더 긴 작업을 더 잘 기억한다.

모델은 GPU(그래픽카드)에서 실행된다. GPU에서 가장 중요한 수치는 VRAM — 그래픽카드 전용 메모리. Mac 신형 모델은 통합 메모리(unified memory)를 써서 GPU와 시스템 RAM이 같은 풀 → 더 많은 공간을 GPU로 쓸 수 있지만 스필오버 없음. Windows 전용 GPU는 VRAM이 적지만 약간 더 빠름.

모델을 로드하면 VRAM에 통째로 올리려 하고, VRAM이 부족하면 시스템 RAM으로 넘친다. 16GB VRAM GPU를 예로 들면, 모델이 16GB를 초과하면 나머지가 시스템 RAM에 들어간다.

Windows에서 VRAM 확인: 작업관리자 > 성능 > 전용 GPU 메모리.

LM Studio로 시작하기

처음 시작하기 가장 좋은 도구는 LM Studio — UI가 직관적이고 메모리 관련 개념들을 잘 설명해준다. LM Studio를 내려받고, 모델은 LM Studio 내장 브라우저나 Hugging Face에서 찾는다.

모델 탭에서 검색하면 모델 이름, 파라미터 수(예: 27B, 35B, 9B), VRAM 추정치가 나온다. Qwen 3.6 27B는 17.48GB 추정 — 16GB GPU를 약간 초과. Qwen 3.5 9B는 6.55GB — 16GB GPU에 완전히 적재 가능.

Quantization: Q4, Q6, Q8 등이 있다. 16bit이 기준 원본. 8bit는 절반 크기. Q4는 4단계 quantization — 크기와 품질의 좋은 균형점. Q4에서 Q8로 가면 크기가 거의 2배. Q4에서 Q3·Q2로 가면 대형 MoE 모델을 더 압축할 때 유용하다.

모델 능력 태그: vision(이미지 처리), tool use(도구 호출), reasoning(thinking 모델). 에이전틱 코딩이면 tool use와 reasoning 둘 다 있는 것을 골라야 한다. reasoning 모델은 대체로 크기가 큰 편.

원하는 모델을 클릭 → 다운로드. 완료 후 세 번째 패널(다운로드된 모델 목록)에서 확인.

Hugging Face에서 찾을 때: trending 정렬 + "inference available" 필터 → unsloth 배포판 클릭 → "Use this model" → "Browse quantizations" → LM Studio 버튼 → LM Studio에서 직접 다운로드.

모델 로드 — 파라미터 설정

채팅 창에서 "select a model to load". "manually choose model load parameters" 반드시 활성화 — 세부 설정 접근 가능.

핵심 설정: - GPU Offload: VRAM에 모두 들어가면 최대값(max)으로 설정. 전 레이어가 GPU에 올라감. - Context Length: 올릴수록 메모리 증가. 경우에 따라 모델 크기의 2배까지 뛸 수 있음. 기본 채팅이면 5,000~10,000 정도로 충분.

실험: 16GB VRAM에 동일 모델을 완전 적재 → 124 tok/s. 컨텍스트를 최대로 늘려 스필오버 유발 → 24 tok/s. 6배 차이.

MoE(Mixture of Experts) 모델

MoE = "전문가 혼합". 큰 모델인데 특정 시간에 일부 파라미터만 활성화. 그 활성 파라미터를 GPU에 올리고, 나머지를 시스템 RAM으로 내린다. 모델명: 35B+3B → 총 35B 파라미터, 활성 3B. 또는 35x3 형식.

LM Studio에서 MoE 모델 로드 시 "number of layers for which to force MoE weights onto the CPU" 슬라이더 등장. 낮을수록 GPU 사용 많음 = 빠름. GPU 부족하면 값을 올려 CPU 오프로드 증가.

Kyle 설정 예시: 40레이어 모델, 30레이어를 CPU로 오프로드 (30/40). GPU에 중요 레이어만 남기고 → 43 tok/s. 같은 모델 MoE 없이 CPU 오프로드 0 → 1 tok/s 수준으로 추락.

MoE 모델이 일반 중급 하드웨어에서 대형 모델을 실용적으로 쓸 수 있는 최선의 방법.

LM Studio 개발자 모드 + 서버

developer 탭 활성화 (설치 시 "show developer settings" 선택 안 했으면 설정 > developer > 개발자 모드 ON).

여기서 여러 모델을 동시에 로드 가능. Kyle 예시: Qwen 3.6(대형, 에이전트용) + 940MB 소형 모델(autocomplete용) 동시 로드.

서버 status: running 확인. URL (기본 http://localhost:1234/v1) 모든 클라이언트에서 공통 사용. OpenAI 호환 엔드포인트 — OpenAI와 호환되는 것은 전부 LM Studio와도 호환됨.

Continue 확장 (VS Code)

Continue 확장 설치 → 사이드바 Continue 클릭 → 설정 아이콘 → config 파일 열기(YAML).

autocomplete 설정 추천: - timeout: 1000ms (기본보다 길게) - debounce: 100ms (타이핑 멈춘 후 대기 시간)

도구 권한: 파일 읽기·쓰기·생성은 automatic. 터미널 실행은 ask first. rules 생성은 excluded. URL 불러오기는 ask first.

YAML 설정 예시:

# autocomplete 전용 소형 모델
- name: autocomplete
  provider: lmStudio
  model: <LM Studio 모델 ID 복사>
  apiBase: http://localhost:1234/v1
  roles:
    - autocomplete

# 에이전트/채팅용 대형 모델
- name: qwen-agent
  provider: lmStudio
  model: <LM Studio 모델 ID 복사>
  apiBase: http://localhost:1234/v1
  capabilities:
    - tool_use
    - image_input

roles에 autocomplete를 지정한 모델은 채팅 목록에 나타나지 않음 — 자동완성 전용으로만 동작.

autocomplete 강제 트리거: Ctrl+Alt+Space. LM Studio 개발자 로그에서 호출 시간 확인 (예: 259ms). timeout보다 오래 걸리면 더 작은 모델 필요.

에이전트 모드에서 "create a file called test.ts that just has console.log test" → 파일 생성 성공 확인.

Continue 에이전트가 가끔 버그가 있어서, GitHub Copilot 로컬 모델 연결도 보여주겠다.

GitHub Copilot 로컬 모델 연결

VS Code Insider(베타) 필요. Copilot 구독 불필요.

Copilot 채팅 패널 → 모델 드롭다운 → 기어 아이콘 → "Add models" → "OpenAI compatible" → 이름 입력(예: "LM Studio") → API key 아무 값이나 입력(예: "key") → 설정 파일 열림.

설정 파일에 모델 추가:

{
  "id": "<LM Studio 모델 ID>",
  "name": "Qwen 3.6",
  "url": "http://localhost:1234/v1",
  "toolCalling": true,
  "vision": true,
  "maxInputTokens": <LM Studio context 길이>
}

변경 후 Developer: Reload Window 또는 VS Code 재시작. 이후 Copilot 모델 드롭다운 → "Other models"에서 추가한 모델 선택 가능.

주의: GitHub Copilot 관련 기능은 GitHub 서버와 통신 → 인터넷 연결 필요. 완전 오프라인이면 Continue 또는 Pi CLI.

Pi CLI 연동

pi.dev에서 install 명령 복사 → 터미널 실행 → pi 입력.

/model 슬래시 커맨드로 모델 선택. 처음엔 목록이 비어있음 → models 파일 수정 필요.

models 파일 위치는 Pi 문서 참고 (OS마다 다름). VS Code에서 해당 파일 열고:

lmstudio:
  provider: lmStudio
  base_url: http://localhost:1234/v1
  api: openai completions
  api_key: any
  models:
    - id: <LM Studio 모델 ID>
      context_window: <LM Studio context 길이>
      reasoning: true
      input:
        - text
        - image

이후 Pi에서 "describe this codebase" 같은 명령 → 에이전트가 자율 실행. context 사용량 하단에 실시간 표시.

클라우드 vs 로컬 성능 비교

스도쿠 앱 생성 (원샷 프롬프트: 펜슬 마킹, 난이도 3가지, 솔루션 체커 포함): - Qwen 3.6 로컬: 9분, 대부분 기능 구현, center pencil marking 누락 - Claude Sonnet 4.6: 9분, center pencil marking 포함, 미세 우위 → 시간은 동일, 품질은 거의 비슷.

버그 수정 (대형 코드베이스 비디오 에디터, 특정 씬에서 항상 전체 오디오 재생되는 버그): - Claude Sonnet 4.6: 45초 - Qwen 3.6 로컬: 2분 30초 → 코드베이스 읽기 속도 차이. 두 모델 모두 동일한 방식으로 동일한 코드 변경으로 수정.

마무리

클라우드 모델과 비교해 로컬 모델은 느리고 약간 품질이 낮지만, 완전 무료·오프라인·프라이빗. 클라우드 플랜 $100~200/월을 2~3달 취소하면 그 돈으로 AI 최적화 고사양 PC를 살 수 있다 — 영상 편집용 하드웨어보다 훨씬 가성비 좋은 AI 전용 하드웨어가 있다.

어떤 하드웨어든 맞는 모델을 찾을 수 있다. 스펙이 낮으면 더 작은 모델·더 높은 quantization 압축 레벨로 조정하면 된다. 이 영상의 개념을 이해했다면 앞으로 새 모델이 나와도 직접 판단할 수 있다.
