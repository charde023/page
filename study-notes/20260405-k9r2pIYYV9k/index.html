  • Local Images Plus: Obsidian 커뮤니티 플러그인. Web Clipper가 링크만 남기는 이미지를 로컬로 다운로드해 볼트 내에서 직접 표시

  • 위키 폴더 내 인덱스: 각 위키 하위 폴더에도 인덱스 파일을 두어 Claude Code가 계층적으로 탐색 가능
  • 위키링크 형식: Obsidian의 내부 링크 문법. CLAUDE.md에 이 형식을 명시하면 Claude Code가 파일 간 관계를 따라갈 수 있음

화자의 디테일 (놓치기 쉬운 포인트)

  1. RAW 폴더는 볼트 바깥에 두는 것이 원칙 — 볼트 폴더와 나란히 위치. 볼트 안에 넣지 말 것
  2. CLAUDE.md는 볼트 루트에 두고 지식 베이스 탐색 규칙을 명시해야 토큰 낭비가 줄어든다
  3. Web Clipper 기본 저장 위치가 "Clippings" — 이걸 RAW로 바꿔야 자동으로 RAW 폴더에 저장됨 (Location/Note Location 항목)
  4. Obsidian은 인간용 프론트엔드 역할: 문서가 어떻게 정리됐는지 사람이 직접 볼 수 있음. Night RAG(Langchain 기반 그래프형 RAG) 같은 시스템은 블랙박스에 가까워 실제 파악이 어렵다고 언급
  5. Claude Code는 RAW 폴더를 굳이 경유하지 않아도 됨 — 웹 검색 후 직접 위키 생성 가능. RAW 파이프라인은 사람이 직접 수집하고 싶은 자료를 위한 장치
  6. 마스터 인덱스가 현재 3개뿐이어도, 3,000개가 되어도 구조 자체는 동일하게 유지된다고 강조
  7. RAG 전환 시점: 문서가 수백만 개 규모가 되면 그때부터 진짜 RAG가 더 싸고 빠름. 그 이하라면 Obsidian으로 충분
  8. 초기 파일 구조 세팅은 Claude Code에 프롬프트 한 번이면 자동 생성 — Chase AI 커뮤니티에 프롬프트 템플릿 공유
  9. 기존에 Obsidian을 쓰고 있다면 RAW 폴더를 다른 이름으로 써도 됨. 핵심은 위키 변환 전 자료를 모을 버퍼를 별도로 두는 것

1. 도입 — Karpathy가 공개한 Obsidian 기반 지식 시스템

Andrej Karpathy가 트위터(X)에 자신의 Obsidian 기반 지식 베이스 구조를 공개했다. 핵심 주장은 벡터 데이터베이스·임베딩·복잡한 검색 파이프라인 없이도 Obsidian 마크다운 파일 구조만으로 기존 RAG가 하는 일 — 대량 문서 처리, LLM 질의응답, 정확한 정보 추출 — 을 똑같이 할 수 있다는 것이다.

장점: - 사실상 무료 - 1인 개발자·소규모 팀에 적합 - 사람도 Obsidian UI에서 문서 상태를 직접 파악 가능 (블랙박스 없음)

2. 파일 구조 — 3계층

볼트 상위 폴더/
├── raw/              ← 원본 자료 수집 버퍼 (볼트 바깥)
└── vault/            ← Obsidian 볼트
    ├── CLAUDE.md     ← 지식 베이스 탐색 규칙
    ├── master-index.md  ← 모든 위키 목록
    └── wiki/
        ├── AI-에이전트/
        │   ├── index.md
        │   └── *.md
        ├── 콘텐츠-제작/
        └── ...
  • raw/: 기사, 논문, 웹 클리핑, PDF 등 원본 자료가 쌓이는 임시 구역
  • wiki/: Claude Code가 raw를 소화해 만든 정제 위키들
  • master-index.md: 어떤 위키가 있는지 Claude Code가 가장 먼저 읽는 파일
  • 각 위키 폴더의 index.md: 해당 위키 내 세부 문서 목록

이 구조 덕분에 Claude Code는 불필요한 도구 호출 없이 정보를 빠르게 찾는다.

3. Obsidian 설치 및 초기 세팅

  1. obsidian.md에서 다운로드, 설치
  2. 특정 폴더를 볼트로 지정 (이름은 "vault" 등 임의)
  3. 볼트 폴더에서 Claude Code를 열고, Chase AI 제공 프롬프트 템플릿을 붙여넣기
  4. Claude Code가 raw/, wiki/, master-index.md, CLAUDE.md 구조를 자동 생성

기존에 Obsidian을 사용 중이라면 raw 폴더명을 달리해도 무방. 중요한 것은 위키 변환 전 자료를 모을 별도 버퍼를 두는 원칙이다.

4. CLAUDE.md — 지식 베이스 전용 설정

  • 볼트 루트에 위치
  • LLM이 볼트를 탐색하는 규칙 명시 (어떤 폴더를 먼저 볼지, 어떤 파일 형식을 따를지)
  • 위키링크 형식을 지정해두면 Claude Code가 파일 간 관계를 따라가며 답변 가능
  • 토큰 낭비 방지 효과: 어디를 봐야 할지 명확히 안내

5. 데이터 수집 — Obsidian Web Clipper + Local Images Plus

Web Clipper 설정: - 크롬 웹스토어에서 "Obsidian Web Clipper" 확장 설치 - 확장 옵션 → Location / Note Location 항목을 기본값 "Clippings"에서 "RAW"로 변경 - 이후 웹 클리핑 시 자동으로 raw/ 폴더에 저장

이미지 문제 해결 — Local Images Plus: - Web Clipper 기본 동작은 이미지를 링크로만 남김 - Obsidian 커뮤니티 플러그인에서 "Local Images Plus" 검색 → 설치 → 활성화 - 이후 Web Clipper 사용 시 이미지까지 로컬 다운로드되어 볼트 내에서 직접 표시

6. Claude Code로 위키 자동 생성

Claude Code에 요청하는 방식: - "클로드 코드 스킬에 대한 위키를 만들어줘. RAW 폴더에 넣어둔 자료도 있고, 필요한 건 더 검색해서 만들어줘" - Claude Code가 웹 검색 + RAW 폴더 자료를 종합해 위키 생성 - 생성된 위키는 master-index.md에 자동 등록 - 위키 내 문서끼리 링크로 연결되어 탐색 경로가 명확

RAW 파이프라인은 사람이 직접 수집하고 싶은 자료를 정리할 때 유용. Claude Code는 RAW를 경유하지 않고도 직접 위키를 만들 수 있다.

7. Obsidian vs 진짜 RAG — 언제 넘어갈까

기준 Obsidian 방식 진짜 RAG (벡터 DB)
문서 규모 ~수만 개 이하 수백만 개 이상
비용 사실상 무료 임베딩·벡터 DB 비용 발생
투명성 사람이 직접 파악 가능 블랙박스에 가까움
설정 난이도 낮음 높음
적합 대상 1인 개발자, 소규모 팀 대규모 서비스, 기업

화자 결론: 일단 Obsidian으로 시작하라. 한계에 부딪히면 그때 RAG로 전환해도 늦지 않다. 대부분의 사람에게 진짜 RAG는 필요 없다.

종합 체크리스트

  • [ ] Obsidian 설치 후 raw/ + wiki/ + master-index.md + CLAUDE.md 구조 세팅
  • [ ] CLAUDE.md에 볼트 탐색 규칙과 위키링크 형식 명시
  • [ ] Web Clipper + Local Images Plus 조합으로 웹 자료 수집 파이프라인 구성
  • [ ] 기존 노트(학습노트 등)를 raw/로 분류하거나 master-index에 연결
  • [ ] Claude Code에서 볼트 열고 특정 주제 위키 생성 테스트
  • [ ] 규모가 커질 때 어느 시점에 진짜 RAG가 필요한지 직접 판단

전체 전사 펼치기

안드레이 카파시(Andrej Karpathy)가 자기 Obsidian RAG 시스템의 핵심을 공개했습니다. "RAG"에 따옴표를 붙인 이유가 있습니다. 이 Obsidian 기반 지식 베이스에는 벡터 데이터베이스도 없고, 임베딩도 없고, 복잡한 검색 과정도 없습니다. 그런데도 더 복잡한 RAG 구조가 하겠다고 하는 일을 똑같이 해냅니다. 대량의 문서를 LLM이 다루고, 질문에 답하고, 정확한 정보를 끌어오는 일이죠. 게다가 이 시스템의 가장 좋은 점은 아주 가볍다는 겁니다. 사실상 무료에 가깝고, 1인 개발자나 소규모 팀에 딱 맞는 중간 지점입니다.

오늘은 카파시의 Obsidian 지식 시스템이 어떻게 작동하는지, 직접 어떻게 세팅하는지, 기존 RAG와 뭐가 다른지 보여드리겠습니다. 어제 Andrej Karpathy가 꽤 자세한 트위터 글로 이걸 정리했습니다. 핵심은 우리가 만드는 LLM 지식 베이스가 사실상 Obsidian만으로도 라이트 RAG나 KG(지식 그래프)형 RAG 시스템처럼 움직일 수 있다는 점입니다. 아주 영리한 파일 구조만으로도 꽤 단순하게 만들 수 있습니다.

구조는 이렇습니다. 먼저 raw 디렉터리에 데이터를 넣습니다. 기사도 넣고, 논문도 넣고, 인터넷이나 다른 곳에서 자료를 가져와 볼트 위에 있는 raw 디렉터리에 넣습니다. 여기는 자료가 쌓이는 대기 구역입니다. 그 다음 이 자료가 위키로 바뀌는 과정을 Obsidian에서 직접 볼 수 있습니다. Obsidian은 사실상 프론트엔드 역할을 합니다. 문서가 어떻게 정리되어 있는지 여기서 다 볼 수 있죠. 이건 Langchain 같은 블랙박스 뒤에 숨겨진 구조가 아닙니다. KG형 RAG 시스템도 안을 들여다볼 수는 있지만 실제로 전부 파악하기는 꽤 어렵습니다.

그리고 그 다음에 Claude Code 같은 도구로 질의응답을 하면 됩니다. Andrej도 처음엔 RAG가 필요할 거라 생각했지만, LLM이 인덱스 파일과 문서 요약을 꽤 잘 자동으로 유지해준다고 했습니다. 이건 아주 단순한 CLAUDE.md 파일 하나로 할 수 있습니다.

저는 그 파일을 드릴 거고, 프롬프트가 잔뜩 들어있는 가이드도 무료 Chase AI 커뮤니티에 올려두겠습니다. 이 영상 설명란에 링크를 넣어두겠습니다. Chase AI 얘기가 나왔으니, Claude Code 마스터 클래스도 잠깐 소개 드리겠습니다. 기술 배경이 없는 분들께도 좋습니다.

실제 파일 구조부터 보겠습니다. 데이터가 볼트로 들어와서 위키로 바뀌는 과정을 이해하려면 이게 중요합니다. Obsidian 볼트는 모든 게 들어있는 기본 공간입니다. 처음 써보는 분이라면, Obsidian을 설치할 때 특정 폴더 하나를 볼트로 지정하게 됩니다. 그리고 그 볼트 한 단계 위 폴더로 raw 폴더를 둡니다. 모든 리서치 자료가 여기에 들어옵니다. 위키에 직접 넣고 싶은 자료도 전부 여기에 넣습니다. 말 그대로 임시 보관 폴더입니다. 마크다운 파일도 되고, PDF도 됩니다.

또 다른 하위 폴더로 wiki 폴더를 둡니다. 여기서 Claude Code가 할 일은 — 필요할 때마다, 혹은 스킬이나 자동화로 돌려도 되는데 — raw 폴더를 보고 어떤 주제의 위키를 만들어 달라는 겁니다. 이렇게 여러 위키가 생기죠. AI 에이전트용 하나, 알림 시스템용 하나, 콘텐츠 제작용 하나처럼요. 그리고 wiki 폴더와 각 하위 위키 폴더 사이에는 Master Index 마크다운이 있습니다. 이건 지금까지 만든 모든 위키 목록입니다.

여러분이 Claude Code에 AI 에이전트를 더 알고 싶다고, 내 위키에 질문하고 싶다고 말하면 어떻게 될까요? 먼저 볼트로 들어갑니다. 그 다음 wiki 폴더의 인덱스를 보고 어떤 위키가 있는지 확인합니다. 이 사람은 RAG 시스템을 알고 싶어 하는구나. 그러면 RAG 쪽으로 내려가고, 각 위키 폴더 안 인덱스 파일에서 추가 내용을 찾습니다. 이 파일 구조 덕분에 정보가 엄청 많아도 어디를 봐야 하는지 경로가 아주 명확해집니다. 그래서 Claude Code도 데이터를 찾느라 헤매지 않습니다. 도구 호출을 쓸데없이 많이 돌릴 필요가 없죠.

예를 들어 여기 왼쪽이 제 Obsidian 폴더입니다. 모든 내용을 정리한 Master Index가 보입니다. 지금은 3개뿐이지만, 3,000개여도 그렇게 어렵진 않을 겁니다. 그냥 클릭하면 해당 위키의 인덱스로 들어갑니다. 정말 단순하죠? AI 입장에서도 마찬가지입니다. 단순한 마크다운 파일 구조만으로도 충분히 쓸 수 있습니다.

이론은 이쯤 하고, 이제 실제로 어떻게 세팅하는지 보겠습니다. 먼저 Obsidian을 설치해야 합니다. obsidian.md에서 다운로드를 누르고 설치를 진행하세요. 완전히 무료고, 어떤 폴더를 볼트로 쓸지만 정하면 됩니다. 그냥 하나 만들고 "vault"라고 부르세요. 볼트를 만들었으면 볼트 폴더에서 Claude Code를 열고, 이 파일 구조를 만들어 달라는 프롬프트를 넣으면 됩니다. 저처럼 이미 Obsidian을 좀 쓰고 있다면 raw 대신 다른 이름을 써도 됩니다. 핵심은 하나입니다 — 정보를 위키로 바꾸기 전까지 모아 둘 버퍼.

다음으로 할 일은 CLAUDE.md를 만드는 겁니다. 마크다운 비중이 큰 작업에는 CLAUDE.md가 정말 잘 맞습니다. 이 CLAUDE.md는 지식 베이스 규칙과 그 안을 어떻게 탐색할지까지 정리해줍니다. 그래서 질문할 때 토큰을 괜히 낭비하지 않게 됩니다. 이 CLAUDE.md는 마크다운 파일을 어떤 형식으로 정리할지도 Claude에게 알려줍니다. 위키링크 형식이면 파일을 아주 쉽게 따라갈 수 있습니다.

그 다음은 raw 폴더에 자료를 어떻게 넣느냐입니다. 가장 쉬운 방법은 Obsidian Web Clipper를 쓰는 겁니다. 이건 그냥 크롬 확장 프로그램인데, 웹페이지를 마크다운 데이터로 바꾸기가 아주 쉽습니다. 다만 이 웹 클리퍼에는 한 가지 문제가 있습니다. 이미지 처리가 약합니다. 아예 가져오지 않고 링크만 남기는 경우가 많습니다. 저는 불러온 문서 안의 이미지를 Obsidian에서 그대로 보고 싶습니다. 그래서 Obsidian 커뮤니티 플러그인을 같이 씁니다.

데스크톱 앱에서 톱니바퀴를 누르고 → 커뮤니티 플러그인 → 브라우저로 들어가세요. 거기서 "Local Images Plus"를 검색하세요. 다운로드하고 설치한 뒤 켜주시면 됩니다. 커뮤니티 플러그인 탭에서 스위치가 켜져 있으면 활성화된 겁니다.

이제 Obsidian Web Clipper를 쓰면 이미지까지 포함한 기사 전체가 들어옵니다. 여기서 웹 클리퍼 안에 한 가지만 더 세팅해야 합니다. 자동으로 RAW 폴더로 들어가게 만드는 겁니다. 그걸 매번 수동으로 옮기고 싶진 않으니까요. 웹 클리퍼 옵션으로 들어가서, Location과 Note Location 항목에서 기본값 "Clippings"를 RAW로 바꾸면 됩니다. 그러면 웹 클리핑 시 자동으로 RAW 폴더에 들어갑니다.

하지만 이건 데이터 유입 경로 중 하나일 뿐이고, 수동 방식입니다. 무거운 작업은 Claude Code가 많이 대신해 줄 수 있습니다. 예를 들어 Claude Code 스킬에 대한 위키를 만들고 싶다고 해보겠습니다. 웹 클리퍼로 이미 RAW 폴더에 넣어둔 자료도 있다고 알려주고, 필요한 자료를 더 조사해서 위키를 만들어 달라고 하면 Claude Code는 인터넷에서 웹 검색을 하고 Claude Code 스킬에 대한 위키를 만들어냅니다.

여기서 보이듯이 RAW 파이프라인은 사실 여러분을 위한 겁니다. 주로 여러분이 직접 넣고 싶은 정보를 정리할 때 쓰는 거죠. Claude Code는 스스로 리서치에서 중요한 것만 골라 바로 위키를 만들 만큼 똑똑합니다. RAW 폴더는 결국 사람인 여러분이 정리감을 갖기 위한 장치입니다.

이게 Claude Code가 실제로 만들어 준 결과입니다. Claude Code 스킬 위키를 만들었고, 마스터 인덱스에도 등록된 걸 볼 수 있습니다. 위키 안에 기사 4개가 들어 있습니다. 웹사이트 링크도 있고, 볼트 안 다른 기사 링크도 연결돼 있습니다. 스킬 에코시스템을 누르면 관련 자료가 더 나옵니다. 이렇게 한 기사에서 다음 기사로 넘어가는 경로와 관계가 아주 분명합니다. 그래서 Claude Code도 이런 기사와 주제에 대해 질문을 받았을 때 적은 비용으로 쉽게 답할 수 있습니다.

그러면 당연히 이런 질문이 나오죠. RAG가 아예 필요 없을까요? Langchain 같은 구성을 보고 제 이전 영상들에서 Night RAG [?NightRAG] 같은 걸 보셨다면, Obsidian 세팅이 이렇게 단순한데 굳이 왜 더 복잡한 구조를 써야 하냐는 생각이 드실 겁니다. 1인 개발자나 소규모 팀이라면, 수천 개 문서를 다루는 상황이 아니라면 Obsidian 쪽이 더 맞을 가능성이 큽니다.

물론 Obsidian 방식과 진짜 RAG의 차이를 세세하게 따질 수는 있습니다. 하지만 결국 핵심은 규모입니다. 문서를 수백만 개까지 늘릴 건지 아닌지죠. 어느 정도 규모를 넘기면 여러분이 만든 마크다운 문서 네트워크를 Claude Code가 아무리 잘 다뤄도, 제대로 된 RAG 시스템이 더 싸고 더 빠릅니다. 하지만 이 질문에 지금 당장 정확한 답을 낼 필요는 없습니다. 그냥 Obsidian으로 시작하면 됩니다. 써보니 이 구조가 감당할 수 있는 범위를 훨씬 넘는다면, 그때 RAG로 넘어가면 됩니다. 대부분 사람에겐 진짜 RAG가 필요 없습니다. 정말 그래요.
