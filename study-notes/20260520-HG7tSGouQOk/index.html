1. Karpathy는 누구인가

OpenAI 창립 멤버(2015). Tesla AI 총괄 5년. 2023년 OpenAI 복귀 후 1년 만에 재퇴사. Eureka Labs 창업 — LLM 101N(언어모델 제로 구현 무료 강의), LLM Wiki 등 퍼블릭 에듀케이션 프로젝트. "vibe coding"(영어로 원하는 것 설명 → AI가 코드 작성 → 사용자는 방향 조정) 용어 창시. "context engineering"(프롬프트 하나보다 환경·폴더·문서 설계가 진짜 기술)이라는 프레임 제안.

2. Anthropic의 현재 모멘텀

  • Ramp AI Index: Anthropic 34.4% vs OpenAI 32.3% — 기업 지출 기준 처음으로 역전. Ramp 고객사 한정 데이터임을 화자가 명시.
  • 엔터프라이즈 서비스 합작: Blackstone, Hellman & Friedman, Goldman Sachs와 합작으로 중견기업 Claude 도입 지원 서비스사 설립. "모델만 주고 알아서 쓰세요"가 아닌 서비스 레이어까지 직접 구축.
  • Claude Code가 개발자·업무 자동화 도구로서 빠르게 채택되며 이 성장의 핵심 드라이버 역할.

3. 진짜 제품은 Wrapper

모델 벤치마크 경쟁(GPT-5.5 vs Opus 4 vs Gemini)은 점점 덜 중요해진다. 실제로는 같은 모델로도 결과가 천차만별 — 그 차이를 만드는 것이 wrapper.

Wrapper의 구성 요소: - Claude Code, Codex 같은 도구 자체 - Skills, 서브에이전트, Hooks, MCP 커넥터 - CLAUDE.md, Memory, Docs, 예시 파일 - 프로젝트 폴더 구조

새 채팅창을 열 때마다 모델은 stateless(기억 없음). 파일·예시·워크플로우·스타일가이드·성공 기준을 미리 제공하면 완전히 다른 게임이 된다.

4. LLM Wiki — 데이터 Moat의 현실적 구현

Karpathy가 2026년 4월 공개한 패턴:

  • raw/ 폴더: 마크다운 파일 무더기
  • wiki/ 폴더: 에이전트가 raw를 합성·연결해 mind map 형태 living knowledge base 구성
  • schema 문서(CLAUDE.md 스타일): 시스템 작동 방식·수집 방법을 에이전트에게 설명

기업 대형 DB가 아니어도 된다. 내 회의록, 내부 SOP, 고객 콜 녹취, 트랜스크립트, 사내 명명 규칙 — 이것이 이미 개인·팀 규모의 data moat. 모델을 바꿔도 이 컨텍스트는 가져갈 수 있지만, 축적이 클수록 이 환경에 중독되어 이탈이 어려워진다.

화자 예측: Claude Code 프로젝트 메모리 안에 이 wiki 구조가 더 네이티브하게 통합될 것.

5. Auto Research와 /goal — 목표 기반 자율 루프

Auto Research (Karpathy, 2026년 3월): - 훈련 스크립트 변경 제안 → 단기 훈련 실행 → 객관 지표 통과 여부 확인 → 반복 - 목표를 주면 에이전트가 달성할 때까지 자율 실행

/goal 커맨드: Codex → Hermes → Claude Code 순으로 네이티브 지원 확대. 동일한 패턴의 인터페이스 전환.

이 둘은 내부 구현이 다르지만 패러다임은 같다: "한 프롬프트-한 답변"에서 "이 조건이 충족될 때까지 계속 실행"으로. LLM wiki의 컨텍스트 + /goal의 자율 루프가 결합되면 단순 챗봇이 아니라 비즈니스를 아는 직원처럼 작동하기 시작한다.

6. 교육이 다음 병목

Karpathy의 합류 트윗에서 "교육에 여전히 깊은 열정이 있다"는 한 문장. IBM 연구 결과 기술 보유와 실제 활용 사이의 격차가 여전히 크다. Anthropic이 context marketplace 방향으로 간다면 기술 구현만큼 중요한 것이 일반 사용자·기업이 실제로 활용하도록 돕는 교육 레이어다.

Karpathy는 극도로 기술적인 내용을 직관적으로 이해시키는 드문 능력을 가진 인물. 이 역량이 Anthropic의 기업 도입 전략과 맞닿는 지점이다.

7. 화자의 3가지 예측

예측 1: Context 앱스토어 단순 프롬프트 마켓플레이스가 아닌 스킬, 워크플로우, 프로젝트 메모리, 도메인별 컨텍스트, 평가 루프, 실데이터 커넥터를 사고파는 생태계. LLM wiki는 패턴, /goal은 루프 패턴, Karpathy의 교육 철학은 행동 패키징 패턴 — 세 가지가 합쳐지면 Claude Code가 코딩 도구를 넘어 마켓플레이스로.

예측 2: /goal 계열 전문 루프 다양화 현재 /goal은 1.0. 향후 research loop, debug loop, 특정 도메인 특화 루프로 분화. 인터페이스 패러다임 자체가 "단계 지시"에서 "조건 달성 명령"으로.

예측 3: 워크플로우 패키징 교육 레이어 도메인 전문가(회계사, 부동산인, 유튜버 등)가 자기 지식을 컨텍스트로 패키징해 마켓플레이스에 기여할 수 있는 교육·도구 환경. 지금은 전문 지식이 머릿속 또는 슬랙 스레드·ClickUp에 분산되어 있음. 이를 에이전트가 활용 가능한 형태로 구조화하는 것이 다음 단계.

전체 전사 펼치기

오늘은 5월 19일입니다. 몇 시간 전 Andrej Karpathy(안드레이 카르파티)가 Anthropic 합류를 발표하는 트윗이 올라왔습니다. 그가 누구냐면, 현대 AI에서 가장 중요한 인물 중 한 명입니다. OpenAI 창립 멤버, Tesla AI 총괄 5년, OpenAI 복귀 후 재퇴사, AI 교육 회사 창업. 그리고 이제 Anthropic에 합류했습니다.

단순히 "유명한 AI 인물이 대형 AI 랩에 합류했다"는 헤드라인으로 끝낼 수도 있지만, 더 흥미로운 질문은 왜 Anthropic이고 왜 지금인가입니다. 저는 모든 주요 AI 랩들이 Karpathy 같은 인물을 원했을 거라 생각합니다. 그런데 지난 수개월간 그가 공개적으로 구축하고 말해온 것들, 그리고 Claude Code가 이미 출시해온 것들을 보면, 두 방향이 같은 곳을 향해 수렴하고 있었다는 느낌이 듭니다.

이 영상에서 다룰 것은 세 가지입니다. 모델을 감싸는 wrapper(래퍼), 데이터와 컨텍스트가 진짜 제품이 되는 이유, 그리고 Claude Code의 다음 방향.

Karpathy는 누구인가

2015년 OpenAI 창립 멤버. Tesla AI 총괄 5년. 2023년 OpenAI 복귀 후 1년 만에 재퇴사. Eureka Labs 창업 — LLM 101N이라는 언어모델 제로 구현 무료 강의를 만든 곳입니다. 그리고 "vibe coding"이라는 용어를 만든 사람이기도 합니다. 영어로 원하는 걸 설명하면 AI가 코드를 쓰고, 사용자는 방향을 조정하며 이터레이션하는 방식이죠. 그는 AI 분야에서 일한 것을 넘어, 오랫동안 사람들이 AI를 이해하는 방식을 형성해왔습니다.

Anthropic의 모멘텀

첫째, Anthropic은 이미 빌더들 사이에서 강한 모멘텀을 갖고 있습니다. Claude Code는 에이전트 작업이나 코딩, 일반 지식 작업에서 사람들이 가장 먼저 찾는 도구 중 하나가 됐습니다. 약 일주일 전 Ramp가 AI 지수를 발표했는데, 이 데이터셋에서 처음으로 Anthropic이 OpenAI를 기업 채택률에서 앞질렀습니다(34.4% vs 32.3%). 이것은 Ramp 고객사 기준이라 전체 시장과 같지 않고, OpenAI는 여전히 거대한 소비자 브랜드와 엔터프라이즈 계약을 보유하고 있으니 과장하고 싶지 않습니다만, 분명한 모멘텀 신호입니다.

둘째, 이달 초 Anthropic은 Blackstone, Hellman & Friedman, Goldman Sachs와 합작으로 엔터프라이즈 AI 서비스 회사를 발표했습니다. 중견기업들이 Claude를 핵심 업무에 실제로 도입하도록 돕는 것이 목적입니다. 이것이 의미하는 바는, Anthropic이 단순히 "여기 모델 있습니다, 잘 쓰세요"를 넘어서고 있다는 겁니다. 모델을 만들고, 제품 표면을 만들고, 파트너 네트워크를 구축하고, 기업 도입을 돕는 서비스 레이어까지. 이건 완전히 다른 게임입니다. 그리고 같은 테제를 가리킵니다 — 모델이 영원한 해자(moat)는 아니다. 진짜 해자는 애플리케이션, 채택, 모델 밖에 존재하는 IP다.

Wrapper가 진짜 제품이다

아직도 많은 사람들이 AI를 모델 자체로만 이야기합니다. GPT-5.5가 더 나은가, Opus 4인가, Gemini인가, 어떤 벤치마크가 높은가. 물론 모델은 중요합니다. 하지만 이 도구들을 오래 쓰다 보면, 그리고 얼마나 빠르게 좋아지는지 보다 보면, 모델은 제품의 작은 레이어 하나일 뿐이라는 걸 깨닫게 됩니다.

같은 모델로 어떤 사람은 놀라운 결과를 내고, 어떤 사람은 형편없는 결과를 냅니다. 명백히 뭔가 다른 게 작동하고 있는 겁니다. 그 다른 것이 wrapper입니다 — 모델이 어떻게 사용되는지를 구성하는 모든 것들. Claude Code, Codex가 wrapper입니다. Skills, 서브에이전트, Hooks, MCP 커넥터, CLAUDE.md, Memory, Docs, 예시 파일들 — 이것이 모델이 그 안에서 살고 작동하는 환경입니다.

Karpathy는 이 부분에서 매우 일관된 입장을 유지해왔습니다. "context engineering"이라는 용어를 만든 것도 그 맥락입니다. 진짜 기술은 완벽한 프롬프트를 쓰는 게 아니라, 모델이 실제로 작동하고 유용하게 동작할 수 있는 올바른 환경, 폴더 구조, 문서를 만드는 것이라는 의미입니다.

새 채팅창을 열면 Claude는 여러분에 대해 아무것도 모릅니다. 본질적으로 stateless입니다. 그래도 유용할 수는 있지만 대체로 추측을 하게 되고, 같은 걸 계속 다시 설명하게 됩니다. 하지만 Claude가 여러분의 파일, 예시, 워크플로우, 스타일 가이드, 좋은 결과물의 기준을 갖고 있다면 — 완전히 다른 게임이 됩니다. 같은 모델, 완전히 다른 결과.

그래서 이 채용이 중요한 이유입니다. Anthropic은 wrapper를 만들어왔고, Karpathy는 사람들에게 모델을 다양한 방법으로 감싸서 최대한 활용하는 법을 가르쳐왔습니다. 두 철학이 하나의 회사로 합쳐진 겁니다.

LLM Wiki — Karpathy의 공개 작업

4월에 Karpathy는 "LLM wiki"를 공개했습니다. 간단히 말하면, raw 폴더에 마크다운 파일들을 모아두면, 에이전트가 wiki 폴더를 합성해 연구나 문서들의 mind map 형태 지식베이스를 구성합니다. 스키마 문서(CLAUDE.md 스타일)를 함께 줘서 에이전트가 시스템 작동 방식과 수집 방법을 이해하게 합니다. AI가 단순히 원본 파일을 검색하거나 벡터 DB 쿼리를 하는 게 아니라, 출처를 읽고 서로 다른 것들 사이의 관계를 이해하는 살아있는 진화하는 지식베이스를 만드는 겁니다.

사람들이 "데이터가 해자다"라고 할 때, 대부분은 거대한 기업 DB를 떠올립니다. 하지만 실제 사용자, 일반 빌더에게는 data moat이 훨씬 작고 현실적일 수 있습니다 — 회의록, 내부 SOP, 고객 콜, 트랜스크립트, 사내 명명 규칙, 우리 프레임워크를 진짜 우리 것으로 만드는 것들. Claude가 이것을 모델이 활용할 수 있는 컨텍스트로 만들 수 있다면, 모델은 매주 더 유용해집니다. 그리고 모델을 바꿀 수 없어서가 아니라, 이 운영체제에 중독될수록 그 안에 쌓인 컨텍스트와 메모리가 많아질수록 계속 쓰고 싶어지는 lock-in이 생깁니다.

Auto Research와 /goal — 목표 기반 자율 루프

3월에 Karpathy는 Auto Research를 공개했습니다. 훈련 스크립트 변경 제안 → 단기 훈련 실행 → 객관 지표 통과 여부 확인을 자율 반복합니다. 에이전트가 장기 실행되며 목표를 향해 작업하는 능력입니다. 목표를 정의하면 에이전트가 작업하고, 완료됐을 때 돌아오는 루프입니다.

최근에는 Codex에 /goal이 추가됐고, Hermes에도 /goal이, Claude Code에도 자체 /goal이 네이티브로 추가됐습니다. Auto Research와 /goal은 내부 구현이 다르지만 패턴은 명확히 같습니다. 둘 다 "한 프롬프트-한 답변"에서 벗어나, "결과를 설정하면 에이전트가 조건 달성까지 계속 실행"하는 방향으로 이동합니다. vibe coding을 스테로이드로 강화한 버전 — 무엇을 원하는지 정의하되 어떻게 할지는 정확히 정의하지 않고, 완성된 결과물을 가지러 돌아오는 것.

LLM wiki의 컨텍스트와 auto research·/goal의 자율 루프가 결합되면, 전체가 챗봇처럼 느껴지지 않고 비즈니스를 아는 실제 직원처럼, 목표를 달성할 때까지 알아서 일하는 직원처럼 느껴지기 시작합니다.

교육이 다음 병목

Karpathy의 합류 트윗에서 "교육에 여전히 깊이 열정적이다"는 한 문장. Eureka Labs의 핵심은 AI를 내부에서부터 이해하도록 돕는 것이었습니다. Karpathy는 극도로 기술적인 것을 이상하게 접근 가능하고 이해하기 쉽게 만드는 드문 능력을 가졌습니다. 아는 것과 다른 사람들이 이해하고 활용할 수 있게 가르치는 것은 별개의 기술입니다.

다음 단계가 컨텍스트·워크플로우·스킬·메모리·루프에 관한 것이라면, 병목은 기술적인 면만이 아니라 교육적인 면도 있습니다. IBM 연구에서 보듯 기술 보유와 실제 활용 사이의 격차가 큽니다. 조직 내 최고의 교육자 중 한 명을 두는 것 — 모든 기업들이 실제로 채택하고 빠져들게 하는 데 도움을 주는 것 — 이건 흥미롭게 생각해볼 지점입니다.

3가지 예측

(사전 경고: 이건 예측일 뿐입니다. Anthropic 로드맵에 대한 내부 정보는 없습니다.)

예측 1 — Context 앱스토어: Anthropic이 컨텍스트를 위한 자체 앱스토어를 만들 것입니다. 단순 프롬프트 마켓플레이스가 아닌 — 스킬, 워크플로우, 프로젝트 메모리, 도메인별 컨텍스트, 평가 루프, 실데이터 커넥터. 특정 직종에서 '좋은 결과물'이 어떤 것인지 모델에게 가르치는 예시들. 사람들이 이 컴포넌트들을 가져다 자기 도메인과 워크플로우에 꽂아서 즉시 더 많은 가치를 얻을 수 있게 하는 것. LLM wiki는 메모리 패턴, /goal은 루프 패턴, Karpathy의 교육 작업은 행동 패키징 패턴 — Anthropic이 그 행동과 교육 스타일을 진짜 생태계로 만든다면 Claude Code는 코딩 도구 이상으로 보이기 시작할 겁니다.

예측 2 — /goal 계열 전문 루프 확대: /goal은 첫 번째 버전에 불과합니다. research loop, debug loop, 특정 도메인에 특화된 루프들이 생길 겁니다. 인터페이스 자체가 "이 한 단계를 수행하세요"에서 "이 조건이 이 구체적인 영역에서 충족될 때까지 계속하세요"로 바뀝니다.

예측 3 — 워크플로우 패키징 교육 레이어: Anthropic이 일반인들이 자신의 워크플로우를 패키징할 수 있도록 교육 레이어를 만들 것입니다. 개발자·연구자뿐 아니라 특정 전문 지식을 가진 일반인들도 — 월말 결산 프로세스를 아는 회계사, 매물 접수 절차를 아는 부동산인, 좋은 패키징과 나쁜 패키징을 아는 유튜버. 이 모든 지식이 매우 가치 있지만, 지금은 머릿속이나 슬랙 스레드·ClickUp에 흩어져 있습니다. 그 전문 지식을 실제로 추출하는 방법이 있다면 — 마켓플레이스에 구독해서 정말 좋은 도메인 데이터를 활용할 수 있다면 — 큰 변화가 생길 겁니다.

이 이야기가 여러분에게 생각할 거리를 줬으면 좋겠습니다. 어제 전화해서 합류시킨 게 아닙니다 — 이건 오래전부터 논의됐을 것이고, 그 시작이 언제였는지, 무슨 이야기를 나눴는지 생각해보는 게 흥미롭습니다.
