Claude Code 단순 코드 자동완성이 아니라 대규모 작업을 수행하는 AI 코딩 도구로 소개됨 코드 작성보다 작업 조율에 가까운 도구
동적 워크플로(dynamic workflow) 수십, 수백, 수천 개의 에이전트를 생산적으로 움직이게 하는 기능 큰 개발 작업을 여러 AI 작업 단위로 나눠 실행
에이전트 오케스트레이션(agent orchestration) 여러 AI 에이전트가 병렬 또는 순차로 협업하게 만드는 핵심 방식 “AI 한 명”이 아니라 “AI 팀”을 운영하는 개념
Zig에서 Rust로 재작성 프로그래밍 언어와 런타임 수준의 대규모 마이그레이션 사례 매우 복잡한 코드베이스 전환을 AI로 수행
조향(steering) 완전 자동 한 번 실행이 아니라 사람이 방향을 잡아주는 과정 AI 작업도 중간 지도와 수정이 필요함

내가 모를 만한 것 / 처음 보는 것

  • 동적 워크플로(dynamic workflow) — Claude Code 안에서 여러 에이전트(agent)를 조직해 복잡한 작업을 처리하는 방식.
  • 에이전트 오케스트레이션(agent orchestration) — 여러 AI 에이전트에게 역할을 나누고, 결과를 합치며, 작업 흐름을 관리하는 개념.
  • Zig — 성능과 시스템 프로그래밍에 강점을 둔 프로그래밍 언어.
  • Rust — 메모리 안전성과 성능을 강조하는 시스템 프로그래밍 언어.
  • 자바스크립트 런타임(JavaScript runtime) — 자바스크립트 코드를 실행하는 환경. 예: Node.js, Bun.
  • Bun — 빠른 자바스크립트 런타임 및 개발 도구. 전사에서는 이름이 직접 나오지 않지만 설명상 관련 사례로 보임.

# 섹션 요지
1 Claude Code의 핵심 여러 에이전트를 조율하는 동적 워크플로가 핵심 기능
2 실제 사례 Zig로 된 자바스크립트 런타임 코드베이스를 Rust로 재작성
3 작업 방식 한 프롬프트로 시작했지만, 사람이 조향하며 진행
4 소요 시간 전체 작업이 11일 동안 실행됨
5 의미 과거에는 1년 이상 걸릴 수 있는 작업을 AI가 크게 단축

1. Claude Code는 단순 코드 작성기가 아니라 작업 조율 도구다

영상의 핵심은 Claude Code가 단순히 “코드를 몇 줄 써주는 도구”가 아니라는 점이다. 화자는 Claude Code의 기능 중 동적 워크플로(dynamic workflow)를 강조한다.

동적 워크플로는 수십, 수백, 많게는 수천 개의 AI 에이전트(agent)를 조직해 생산적으로 일하게 만드는 기능으로 설명된다. 즉, 한 AI가 혼자 긴 코드를 작성하는 방식이 아니라, 여러 작업 단위를 나누고 조율해 큰 개발 작업을 수행하는 구조에 가깝다.

2. Zig 코드베이스를 Rust로 재작성한 사례

화자는 한 모델이 기존 코드베이스를 Zig에서 Rust로 재작성했다고 말한다. 맥락상 이는 자바스크립트 런타임(JavaScript runtime)처럼 복잡한 시스템 소프트웨어를 대상으로 한 작업이다.

자바스크립트 런타임은 단순 웹앱보다 훨씬 복잡하다. 언어 실행, 성능, 호환성, 내부 API, 빌드 시스템 등 고려해야 할 요소가 많다. 그래서 “전체 코드베이스를 다른 언어로 옮긴다”는 것은 일반적인 리팩터링(refactoring)보다 훨씬 난도가 높은 작업이다.

3. 완전한 원샷은 아니고, 사람이 조향했다

인터뷰어가 “이게 한 번에 된 것이냐”고 묻자, 화자는 원샷(one shot)은 아니었다고 답한다. 중요한 점은 사람이 중간에 조향(steering)을 했다는 것이다.

여기서 조향은 AI가 잘못된 방향으로 가거나, 추가 판단이 필요한 지점에서 사람이 방향을 잡아주는 행위를 뜻한다. 즉, 이 사례는 “프롬프트 하나 넣고 11일 뒤 완벽한 결과가 나왔다”라기보다는, 하나의 큰 지시에서 시작해 AI 에이전트들이 장기간 작업하고, 사람이 필요한 순간 개입한 형태에 가깝다.

4. 그래도 이전 모델로는 불가능했던 작업

화자는 조향이 있었다는 점을 인정하면서도, 이전 모델로는 같은 방식으로 해도 불가능했을 것이라고 말한다. 이는 최신 모델과 Claude Code의 결합이 단순 정확도 향상을 넘어, 장기 작업 지속성, 복잡한 코드 이해, 여러 작업의 연결 능력에서 달라졌다는 주장이다.

특히 대규모 코드베이스를 다른 언어로 옮기는 작업은 한 번의 함수 작성이 아니라 수많은 의존성, 테스트, 호환성 문제를 해결해야 한다. 이 때문에 모델의 추론 능력뿐 아니라 작업 흐름을 유지하고 관리하는 능력이 중요하다.

5. 11일이라는 시간의 의미

전체 작업은 11일 동안 실행되었다고 한다. 인터뷰어는 이 짧은 기간에 놀라고, 과거라면 최고의 엔지니어들이 투입되어도 몇 달 또는 몇 년이 걸릴 수 있다고 반응한다. 화자도 1년 이상 걸렸을 가능성이 높다고 동의한다.

이 사례의 메시지는 “AI가 개발자를 완전히 대체했다”라기보다는, 복잡한 소프트웨어 작업에서 AI 에이전트 기반 워크플로가 시간 단위를 크게 줄일 수 있다는 데 있다.

6. 프로덕션에서 동작한다는 점

마지막으로 화자는 결과물이 실제로 작동하며, 프로덕션(production)에 있다고 말한다. 이는 단순한 연구 데모나 실험 코드가 아니라, 운영 환경에서 사용할 수 있는 수준이라는 의미다.

다만 영상은 Shorts 형식이므로 구체적인 검증 방법, 실패 사례, 테스트 범위, 사람의 개입 빈도 등은 설명하지 않는다. 따라서 이 사례를 받아들일 때는 “AI 코딩의 가능성을 보여주는 강한 사례”로 보되, 세부 조건은 원본 롱폼이나 추가 자료를 확인해야 한다.

그는 모델에게 코드를 Zig에서 Rust로 다시 작성하게 했습니다.

시작은 하나의 프롬프트(prompt)였습니다. 그리고 그것은 동적 워크플로(dynamic workflow)였습니다. 동적 워크플로는 Claude Code의 기능으로, 수십, 수백, 수천 개의 에이전트(agent)를 조율해서 생산적으로 일하게 해줍니다.

그 작업은 11일 동안 실행됐고, 전체 코드베이스(codebase)를 다시 작성했습니다.

“그게 한 번에 된 건가요?”

한 번에 된 것이냐고요? 아니요, 완전한 원샷(one shot)은 아니었습니다. 조향(steering)이 있었습니다. 사람이 방향을 잡아주는 과정이 있었죠. 하지만 이전 모델들은 이런 일을 할 수 없었습니다. 조향을 해도 가능하지 않았을 겁니다.

“겨우 11일이요? 세상에. 예전 같으면 최고의 엔지니어들이 붙어도 여러 달, 아니 몇 년은 걸렸을 텐데요.”

확실히 1년은 넘게 걸렸을 겁니다.

“네, 1년 이상이겠죠.”

이건 10만 줄이 넘는 수준의 작업입니다. 자바스크립트 런타임(JavaScript runtime)은 정말 복잡합니다. 그 안에는 많은 요소가 들어 있습니다. 그리고 실제로 작동합니다. 프로덕션(production)에서 사용되고 있습니다.
