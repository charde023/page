한 줄 요약

내가 모를 만한 것 / 처음 보는 것

  • Skill Specter (스킬 스펙터) — NVIDIA가 만든 AI 에이전트 스킬 보안 스캐너. CLI 도구. GitHub 리포에 테스트용 위험 스킬 폴더 포함.
  • skills.sh — 스킬 전용 git 리포 기반 공유 라이브러리. CLI로 검색 쿼리 실행 가능 (최근 업데이트).
  • Claude Code 헤드리스 모드 (headless mode) — 채팅 창 없이 백그라운드에서 명령만 실행하는 Claude Code 실행 방식.
  • Reverse shell (리버스 셸) — 원격 공격자에게 로컬 머신의 쉘 제어권을 넘겨주는 악성코드 유형.
  • Homoglyph (동형 문자) 공격 — 러시아어 등 다른 알파벳에서 생김새가 동일한 문자로 도구명을 위장하는 기법. 예: read의 a를 러시아 키릴 문자로 교체.
  • Nimblist — 에이전트 여러 개를 칸반 보드로 시각 관리하는 오픈소스 워크스페이스 툴 (스폰서).
  • Ailabspro — 영상 제작 팀의 커뮤니티. 디자인 시스템 등 스킬 리소스 제공.

화자의 디테일 (놓치기 쉬운 포인트)

화자가 흘리듯 말한 구체 수치·설정값·명령어·뉘앙스.

  1. 30,000개 이상의 스킬을 연구한 결과 25% 이상에 보안 취약점이 있었다 — 연구 수치이므로 원본 논문 확인 권장.
  2. Skill Specter 기본 모드(--no-llm 플래그 포함 상태)는 패턴 매칭만 → false positive 발생. AI 스캔 활성화는 해당 플래그를 제거하면 됨.
  3. AI 스캔에는 원래 OpenAI 키가 필요하나, 코드 내부의 해당 부분을 Claude Code로 교체하면 Anthropic 월간 크레딧으로 대체 가능 — 단일 라인 프롬프트로 Claude Code가 수정해줌.
  4. 테스트 폴더의 특정 위험 스킬은 기본 스캔 점수 0점, AI 스캔 점수 100점으로 극명하게 갈림 → AI 스캔 필요성을 직접 시연.
  5. 두 번째 스킬은 AI 스캔으로 점수 100 → 0으로 내려감 (즉, 기본 스캔 false positive였음).
  6. scan.sh 스크립트가 Claude 헤드리스 모드 수정을 내부에 베이크(bake)해 기본 제공 — 별도 수정 불필요.
  7. skill.md에 명시된 Discover Skills 루프: 타겟 식별 → 스캔 → 결과 표시 → 문제 수정 → 재스캔 순서.

1. 스킬 보안 문제 개요

연구자들이 30,000개 이상의 AI 에이전트 스킬을 분석한 결과, 4개 중 1개 이상에 보안 취약점이 존재했다. 에이전트는 스킬을 텍스트 파일 형태로 읽고 그 전체를 명령으로 처리하므로, 악성 스킬이 끼어들면 에이전트가 아무 의심 없이 따르게 된다. NVIDIA는 이 문제를 해결하기 위해 Skill Specter (스킬 스펙터)를 출시했다.

2. 설치 및 기본 사용

GitHub 리포에 있는 설치 명령어를 그대로 Claude Code (클로드 코드)에 넘기면 의존성 설치까지 자동으로 진행된다. 리포 내 test/ 폴더에 실제 위험 스킬이 포함되어 있어 바로 검증 가능하다. 스캔 결과는 점수(높을수록 위험), 충돌 발생 파일명, 줄 번호, 위치를 모두 출력한다.

3. 스킬 공격 6가지 유형

화자는 원래 14개 카테고리를 6개로 묶어 설명했다.

  1. 숨겨진 지시문 (Hidden Instructions) — 주석, 보이지 않는 문자, 인코딩된 텍스트로 에이전트에게만 전달되는 명령을 삽입.
  2. 도구 사칭 (Impersonation) — 기존 신뢰 도구(예: read)와 같은 이름이지만 동형 문자(키릴 등)로 한 글자를 교체해 에이전트를 속임.
  3. 거짓 설명 (Misdescription) — 설명은 단순 포매터라 하고 실제로는 인터넷 접속·파일 쓰기·명령 실행을 수행.
  4. 자격증명 탈취 (Credential Theft) — 머신에 저장된 API 키·비밀번호를 수집해 외부 서버로 전송.
  5. 악성코드 실행 (Malware) — Reverse shell (리버스 셸) 등 알려진 악성코드 패턴을 포함. 스캐너가 핑거프린트 라이브러리와 대조.
  6. 오염된 의존성 (Poisoned Dependencies) — 유명 패키지와 이름이 한 글자 다른 가짜 패키지(typosquatting)를 CLI 의존성으로 가져옴. 스캐너가 알려진 악성 패키지 DB와 비교.

4. AI 스캔 모드 활성화

기본 모드(패턴 매칭 전용)는 문맥 없이 패턴만 비교하므로 false positive(거짓 양성)가 발생하고, 특히 거짓 설명 유형의 공격을 잡지 못한다. AI 스캔은 --no-llm 플래그를 제거하면 활성화되지만, 기본적으로 OpenAI 키가 필요하다.

해결책: 코드 내 OpenAI 호출 부분을 Claude Code 헤드리스 모드로 교체. Claude Code가 직접 수정해주며(단일 라인 프롬프트), 이후 Anthropic 플랜의 월간 크레딧으로 AI 스캔을 무료에 가깝게 운용 가능하다.

5. Discover Skills 워크플로

skills.sh CLI를 통해 검색 쿼리 실행 → Skill Specter 스캔(scan.sh) → 문제 자동 수정 → 재스캔의 루프를 하나의 스킬로 패키징했다. 이름이 "Discover Skills"인 이유는 스킬을 찾는 과정 전체를 자동화하기 때문이다. scan.sh에는 Claude 헤드리스 모드 수정이 내장되어 있어 별도 설정 없이 AI 스캔 옵션도 바로 사용 가능하다.

6. 실전 데모

AI Labs 디자인 폴더 개선 작업에서 skills.sh로 관련 스킬 2개를 발견했다. Discover Skills 워크플로에 따라 설치 전 스캔을 의무적으로 수행했다. 결과: 첫 번째 스킬 점수 10(안전), 두 번째 스킬 점수 100(설치 금지). 두 번째 스킬에 AI 스캔을 돌리자 점수가 0으로 내려가 실제로는 안전한 스킬이었음이 확인되었다(false positive). 이 과정이 시스템의 핵심 가치를 보여주는 사례다.

교정 전사 (한국어)

전체 전사 펼치기

지금 AI 에이전트 스킬은 어디에나 있습니다. 모든 에이전트가 스킬을 실행하고, 우리는 아무 검사 없이 그것들을 신뢰합니다. 그런데 무서운 사실이 있습니다. 연구자들이 30,000개가 넘는 스킬을 조사했더니, 그 중 4분의 1 이상에 보안 취약점이 있었습니다. 그래서 NVIDIA가 Skill Specter (스킬 스펙터)라는 도구를 만들었습니다. 이 도구는 스킬을 설치하기 전에 스캔해서 얼마나 위험한지 정확히 알려줍니다. 그런데 흥미로운 부분이 있습니다. 특정 유형의 공격은 이 도구를 그냥 통과하고, 그것을 잡는 설정이 기본으로 꺼져 있습니다. 그래서 대부분의 사람들은 그 설정이 있다는 것조차 모릅니다. 그 설정을 켜면 원래 비용이 들지만, 우리는 우회하는 방법을 찾았습니다. 그리고 결국 스킬을 스캔하는 것에 그치지 않고, 스킬을 찾고 설치하는 방식 자체를 바꾸는 전체 워크플로를 만들었습니다.

전체 워크플로를 보기 전에, 먼저 도구 자체와 사용 방법을 빠르게 살펴보겠습니다. GitHub 리포에 설치 명령어가 있습니다. 그냥 복사해서 Claude Code (클로드 코드)에 넘기면 전체 설치와 설정을 알아서 해줍니다. Claude Code가 필요한 의존성을 모두 설치하고, 완료되면 Skill Specter를 바로 사용할 수 있습니다. 리포 안에 test/ 폴더가 있고, 거기에 실제로 위험한 스킬들이 들어 있어서 도구가 제대로 동작하는지 확인할 수 있습니다. 그 스킬들로 실행해보면, 각각에 대해 설치하지 말라고 알려줍니다. 점수가 높을수록 더 위험한 스킬입니다. 그리고 단순히 숫자만 주는 게 아니라 점수를 올린 충돌이 발생한 정확한 줄 번호, 위치, 파일 이름까지 알려줍니다.

이게 도구를 사용하는 유일한 방법은 아닙니다. 또 다른 모드가 있습니다. 하지만 왜 두 번째 모드가 필요한지 이해하려면 먼저 두 가지를 알아야 합니다. 스킬이 어떻게 공격하는지, 그리고 이 도구가 어떻게 그 공격을 잡는지입니다.

14가지 카테고리가 있지만, 간단하게 6가지로 묶었습니다.

첫 번째 방식은 숨겨진 지시문입니다. 스킬은 지시문으로 가득 찬 텍스트 파일이고, 에이전트는 그 전체를 읽고 명령으로 처리합니다. 문제는 악성 스킬이 거기에 여러분은 절대 볼 수 없지만 에이전트는 보는 추가 지시문을 숨겨놓을 수 있다는 점입니다. 주석 안에 숨기거나, 보이지 않는 문자를 사용하거나, 텍스트를 여러분에게는 무의미하게 보이지만 AI는 잘 읽는 코드로 변환합니다. 스캐너는 바로 이런 숨겨진 지시문을 찾아내도록 설계되었습니다.

두 번째 방식은 사칭입니다. 에이전트에게는 신뢰하는 도구들이 있고 이름으로 그것들을 호출합니다. 예를 들어 파일을 읽는 read라는 도구가 있다고 합시다. 악성 스킬이 그 도구와 완전히 같은 이름의 자체 도구를 만들면, 에이전트는 이미 알고 있는 안전한 도구라고 생각하고 악성 도구를 가져다 씁니다. 방법은 교묘합니다. 다른 알파벳에서 생김새가 똑같은 문자로 한 글자를 바꿉니다. read라고 이름 짓지만, a가 사실은 우리 것과 생김새가 똑같은 러시아 키릴 문자입니다. 여러분 눈에도, 에이전트 눈에도 얼핏 같은 단어처럼 보입니다. 하지만 내부적으로는 완전히 다른 도구입니다. 스캐너는 모든 문자의 실제 정체를 확인해서 그 가짜 문자 하나를 잡아냅니다.

세 번째 방식은 스킬이 하는 일을 거짓말하는 경우입니다. 설명은 한 가지를 말하고 코드는 다른 것을 합니다. 단순한 포매터라고 부르면서 백그라운드에서 조용히 인터넷에 접속합니다. 또는 파일 읽기 권한만 필요하다고 하면서 실제로는 파일을 쓰고 명령을 실행합니다. 이건 잡기 훨씬 어렵습니다. 바로 두 번째 모드가 필요한 이유인데, 나중에 설명하겠습니다.

네 번째 방식은 스킬이 자격증명을 훔치는 경우입니다. API 키, 비밀번호가 될 수 있습니다. 스킬이 머신에 저장된 키를 전부 훑어서 어딘가의 서버로 전송합니다.

다섯 번째 방식은 스킬이 그냥 악성코드를 실행하는 경우입니다. Reverse shell (리버스 셸)도 포함되는데, 이건 기본적으로 낯선 사람에게 컴퓨터 전체의 원격 제어권을 넘겨주는 겁니다. 이 종류의 악성코드는 알려진 패턴이 있어서, 스캐너가 코드를 그 패턴의 대형 라이브러리와 대조합니다.

여섯 번째 방식은 오염된 의존성입니다. 스킬은 종종 CLI 도구, 즉 터미널에서 실행하는 작은 외부 프로그램을 사용합니다. 악성 스킬은 실제로 악성인 프로그램을 가져옵니다. 인기 패키지에서 타이포 하나 차이인 가짜 패키지일 수도 있고, 그걸 잘못 받아서 악성코드를 실행하게 됩니다. 스캐너는 스킬이 가져오는 모든 패키지를 알려진 악성 패키지 DB와 대조해서 가짜 이름과 위험한 다운로드·실행 명령을 잡아냅니다.

첫 번째 모드에서는 문맥 없이 패턴만 매칭하기 때문에, 완전히 괜찮은 것도 걸리게 됩니다. 이것이 false positive(거짓 양성)입니다. 그래서 두 번째 모드, AI 스캔이 필요합니다. 활성화는 간단합니다. --no-llm 플래그를 제거하면 두 번째 스캔이 실행됩니다. 하지만 코드 내부를 보면 AI 스캔을 하려면 OpenAI 키를 연결해야 합니다. 그 비용을 우회하기 위해 Claude Code (클로드 코드) 자체를 사용해서 AI 스캔을 실행하도록 했습니다. Claude Code의 메인 에이전트가 직접 하는 게 아니라, Claude 헤드리스 모드를 사용합니다. 이건 채팅 창 없이 백그라운드에서 명령만 실행하는 Claude Code입니다. 이게 무료가 아니라는 건 대부분 아시겠지만, Anthropic 플랜에 월간 크레딧이 포함됩니다. Claude Code에 방금 말한 변경을 해달라고 하면 알아서 해줍니다. 물론 버그가 한두 개 생길 수도 있지만, 단일 라인 프롬프트로 Claude가 설정해줄 수 있습니다.

그리고 테스트 폴더에는 AI 스캔이 필요한 위험한 스킬도 있습니다. 그걸 --no-llm 포함해서 실행하면 점수가 0, 즉 완벽하게 안전합니다. 하지만 AI 스캔으로 실행하는 순간 점수가 100으로 뛰어오르고, 설치하지 말라고 하면서 왜 그런지 정확히 설명해줍니다.

스킬의 문제를 탐지하는 것을 넘어서 스캐너가 수정도 도와주면 어떨까요? 그래서 스캐너 자체를 스킬로 만들었습니다. 왜 "Discover Skills"라고 부르냐면, 별도의 스킬 하나만 만든 게 아니라, 더 많은 스킬을 발견하고 설치하기 전에 안전한지 확인하는 전체 과정을 만들었기 때문입니다.

skills.sh를 꽤 오래 사용해왔습니다. 스킬 전용으로 만들어진 git 리포라서 하나의 큰 공유 라이브러리에서 가져올 수 있습니다. 최근에 CLI 업데이트가 있었던 것 같아서, 이제 Claude가 커맨드 라인에서 직접 검색 쿼리를 실행하고 설치 전에 필요한 최적의 스킬을 가져올 수 있습니다. 그 위에 스캐너를 올리고 싶었습니다.

scan.sh가 실제로 Skill Specter (스킬 스펙터)를 실행하는 스크립트입니다. Skill Specter는 CLI 도구이기 때문에 명령으로 실행해야 해서 스크립트 전체를 만들었고, Claude 헤드리스 모드 수정도 내부에 베이크(bake)했습니다. 기본적으로 일반 스캔을 실행하지만, 원하면 AI 스캔도 실행합니다. skill.md를 보면 기본 단계가 정리되어 있습니다. 타겟 식별 → 스캔 → 결과 표시 → 문제 파악 후 수정 → 전체 루프 재실행으로 다 깨끗한지 확인.

예를 들어, 지금 보여주는 폴더가 AI Labs 디자인 폴더입니다. 우리 전체 디자인 프로세스를 하나의 폴더에 스킬 여러 개와 함께 압축한 겁니다. 이에 대한 별도 영상도 있고, 그 전체 시스템이 AI Labs Pro (저희 커뮤니티)에서 제공됩니다. 채널을 지원하고 이 디자인 시스템을 가져가고 싶다면 확인해보세요. Discover Skills 스킬도 거기에 업로드될 겁니다.

여기서 더 추가하고 있습니다. make design.md 스킬을 새로 추가하는 중인데, 이미 만든 앱에서 디자인 토큰(기본적으로 색상·폰트·간격 규칙)을 가장 빠르게 뽑아서 design.md 파일로 합치는 방법을 정리합니다. design.md 파일을 만들고 싶어서 개선하고 다른 도구도 검색해달라고 했더니 skills.sh를 사용했습니다. 그런 다음 Discover Skills 스킬을 로드했더니 스킬 몇 개를 가져왔습니다. 처음 두 개가 흥미로워 보여서 설치하고 테스트해달라고 했습니다. Discover Skills 워크플로대로, 스캔 없이는 어떤 스킬도 설치하지 않습니다. 설치하고 읽어본 결과, 두 스킬 모두 make design.md 스킬에는 도움이 되지 않는다고 했지만, 안전성 관점에서 첫 번째는 10점(안전), 두 번째는 100점(설치 금지)이었습니다. 두 번째 스킬에 AI 스캔을 돌리라고 했더니 Claude 헤드리스 모드로 다시 실행했고, 이번에 점수가 0으로 나왔습니다. 즉 안전한 스킬이었습니다. 그게 바로 이 시스템의 핵심입니다. 인터넷에서 스킬을 맹목적으로 가져오는 게 아니라, 스킬을 사용하는 것만으로 시작할 수 있는 전체 프로세스가 생기는 겁니다.

스폰서 Nimblist (님블리스트) 소개 — Claude Code (클로드 코드)나 Codex (코덱스)를 쓴다면 알 겁니다. 여러 세션이 돌아가고 파일은 계속 바뀌고, 에이전트들이 뭘 하는지 파악하려고 터미널·브라우저·에디터를 끊임없이 전환하는 문제 말입니다. Nimblist는 이 모든 것을 한 곳에 모아주는 오픈소스 비주얼 워크스페이스입니다. 세 에이전트가 프로젝트의 각기 다른 부분에서 동시에 작업하는 동안 칸반 보드 하나로 모두 볼 수 있고, 세션에 바로 들어가서 코드 변경을 빨간·초록 diff로 검토하고 개별 승인·거절을 할 수 있었습니다. 에이전트 바로 옆에서 마크다운 문서·UI 목업·아키텍처 다이어그램을 비주얼로 편집했습니다. 끝나고 나서 변경된 내용을 기반으로 git 커밋 메시지를 자동으로 생성해줬기 때문에 커밋을 수동으로 정리할 필요가 없었습니다. 태스크는 실제 세션과 연결되어 있고, 자리를 비울 때 세션을 이어갈 수 있는 모바일 앱도 있습니다. Nimblist는 완전 무료 오픈소스이며, 고정 댓글의 링크로 확인하세요.
