1. Cursor 창업 스토리 — "속옷 바람 프로토타입"

2022년 1월, 4명의 젊은 개발자가 회사를 시작했다. AI 코딩 도구를 만들고 싶었지만, 당시 이미 수십 개의 스타트업과 빅테크, 거대 AI 연구소가 진입해 있어 경쟁이 두려워 다른 프로젝트를 먼저 진행했다. 2022년 말, 시장에 마음에 드는 도구가 없다는 결론에 도달해 "자신들이 쓸 수 있는 개발 환경"을 목표로 Cursor를 착수했다.

2주 동안 처음부터 코드 에디터를 구현했다. 언어 서버 통합, remote SSH, Copilot 연동까지 직접 만들었다. 첫 베타 초대 20명 중 2~3명만 실제로 계속 사용했고, 나머지 대부분은 이탈하거나 연락을 끊었다. 그 소수의 "매일 쓰는 개발자"로부터 피드백 루프를 시작해 오늘까지 이어지고 있다. 초기 Discord 멤버 다수를 실제 채용했다.

2. Agent-first 전환과 Cursor 3

Cursor의 가장 큰 변화 방향은 "더 단순하고 더 강력하며 에이전트를 위해 근본적으로 설계된" 형태로의 전환이다. 이 전환은 지난 1년 반에 걸쳐 진행되었으며, 최근 3개월에 확실히 자리를 잡았다.

  • 사용자의 95% 이상이 주로 에이전트 모드 사용
  • 요청 건수 기준 에이전트가 Tab 등 보조 기능의 5배
  • 코드 라인 기준으로는 수십 배 차이

Cursor 3는 agent-first UI로 전면 재설계됐다. 좌측과 중앙 모두 에이전트 패널. 전문 개발 환경으로서 파일 편집, remote SSH, 언어 서버 lint 등 기존 기능은 그대로 유지하면서 에이전트 특화 기능을 추가했다. design mode(화면 제스처로 요소 지정), recursive subagents(서브에이전트를 호출하는 서브에이전트), 전체 컨텍스트 가시성 등이 포함된다.

3. 에이전트를 팀원처럼 — "로컬 에이전트는 미래가 아니다"

Michael Truell은 현재 대부분의 개발자가 에이전트에게 30분~1시간 분량의 작업을 쪼개어 로컬 컴퓨터에서 3~5개씩 병렬 실행하는 방식을 쓰고 있으나, 이는 미래 방식이 아니라고 단호하게 말한다.

"코딩 AGI가 나왔는데 로컬 컴퓨터에서 돌리면서 서로 같은 코드베이스에서 충돌하는 상황은 없어야 한다."

진짜 방향은 에이전트에게 프로젝트 전체를 맡기고 며칠 후 완성된 결과물을 받는 것이다. 그러려면 에이전트에게 자체 컴퓨터(dev environment)가 필요하다.

4. 자체 모델 여정 — Composer 시리즈

Cursor는 창업 초기부터 모델을 직접 훈련해왔다.

  • 2023: Tab 자동완성 모델. 당시 가장 많이 쓰인 코딩 모델 중 하나였다고 주장.
  • 2024~2025: 에이전트 기반 모델. API 모델의 약점(tool calling, 코드베이스 검색)을 보완하는 소형 surrogate 모델 방식.
  • Composer 1 (2025년 11월): RL at scale을 오픈소스 베이스에서 처음 구현. 에이전틱 코딩 기초 모델.
  • Composer 1.5: 동일 방식 스케일업.
  • Composer 2: continued pre-training(수십 조 토큰), 실시간 RL(5시간마다 모델 업데이트).
  • Composer 2.5: 스케일업.

Composer 시리즈의 초기 초점은 속도와 비용이었다. 개인 개발자·솔로 해커도 frontier 모델을 쓸 수 있어야 한다는 철학 때문.

5. Cloud Agents 업데이트 (Kevin 발표)

에이전트를 "항상 켜진 팀원"으로 만들기 위한 세 가지 원칙: 자율성(autonomous), 항상 켜짐(always-on), 어디서나(from anywhere).

자율성 — dev environment 지급 - 클론된 저장소, 설치된 의존성, 빌드 시스템/내부 툴체인 접근 크리덴셜 - 에이전트가 직접 테스트 실행, 데모 스크린샷 생성, 결과물 시각화 가능

항상 켜짐 - 최근 몇 달간 cloud agents 3배 빠르게, 가용성 3-nines 달성 - automations와 SDK로 에이전트 루프를 쉽게 빌드·배포 - Amplitude 사례: React 컴포넌트 20,000개를 Tailwind로 마이그레이션하는 automation 자체 제작해 백그라운드 실행 중 - 전체 automation 실행 횟수: 6백만 건 이상 (출시 몇 달 만)

어디서나 - Slack, Microsoft Teams, Jira, Linear 등에서 에이전트 kick-off - cloud API + webhook 지원 - 그리고 오늘 Cursor Mobile iOS 베타 공개

6. Cursor Mobile — 이동 중 에이전트 관리

Cursor Mobile에서 가능한 것: - 실행 중인 에이전트 전체 목록 확인 - 막힌(blocked) 에이전트 파악 - 전체 저장소 연결 - 에이전트가 생성한 아티팩트(스크린샷) 확인 후 어노테이션 추가 → 재지시 - 로컬 에이전트 원격 제어 (맥 미니 여러 대 쓰거나 랩톱 세미-오픈 상태인 사람들을 위해)

Compile 26 행사장에서 iOS 테스트플라이트 QR 코드 공개. 이후 며칠 내 일반 공개 예정.

7. Origin — Agent-Native Git 플랫폼 (Tomas 발표)

Graphite 공동창업자 Tomas가 2026년 1월 Cursor에 인수 합류 후 개발한 agent-native Git 플랫폼. Graphite는 Shopify, Snowflake, Notion, Figma 등 최고 수준 엔지니어링 팀에 Git 워크플로 툴링을 제공해왔다.

문제 인식: AI 도구 도입 이후 코드 볼륨(커밋, PR)이 급격히 증가하면서 기존 Git 인프라가 따라가지 못함.

Origin의 세 가지 키워드 1. Scale: novel gate architecture로 수천 에이전트의 동시 push/pull 처리. 현재 및 미래 수요에 대응. 2. Extensible: API, MCP, third-party app 플랫폼으로 원하는 모든 것을 위에 빌드 가능. 3. Keep code moving: Cursor와 동일한 AI로 merge conflict 해결, CI 실패 수정, PR 코멘트 대응 자동화. 리뷰 시간 절반 이상 단축.

현재 cursor.com 내부 + select design partners 사용 중. 2026년 가을 전체 공개. 대기자 등록: cursor.com/origin.

8. 새 모델 발표 — "처음부터 훈련, frontier 돌파 목표"

Composer 시리즈와 전혀 다른 유형의 모델을 현재 훈련 중이며 몇 주 내 출시 예정이라고 발표했다.

세 가지 차이점 1. 크기: Opus(Claude) 및 GPT-4급 대형 모델 2. 처음부터 훈련: 오픈소스 베이스 없이 완전 자체 훈련 → 모든 동작을 완전히 제어하고 원하는 workload에 최적화 가능 3. 컴퓨팅 10~20x 확장: Composer 시리즈는 frontier 대비 매우 적은 GPU로 훈련했는데, 이번 스케일업으로 frontier 도달 및 추월을 목표

코딩을 넘어 범용 지능(long-range planning, 도구 사용, 실제 UI 클릭 테스트, 에이전트 변경 사항 UX 등)도 목표. 컴퓨팅 인프라는 SpaceX 파트너십을 통해 제공.
