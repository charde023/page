Claude Code에 Codex를 더하면 AI 신급 조합이 될까요?

업로드 2026-04-01 · 10.2분 · 원본 영상 ↗
한 줄 요약

Claude Code에 Codex 플러그인을 붙이면 Adversarial Review 기능으로 Opus 4.6이 놓친 버그를 잡고, 반대로 Opus가 Codex 누락분을 보완하는 상호 검증 루프를 무료(ChatGPT $20/월) 수준에서 구성할 수 있다.

내가 모를 만한 것 / 처음 보는 것

  • Adversarial Review (적대적 검토) — 코드 작성자(AI)와 다른 관점에서 "분명 문제가 있다"는 가정으로 검토하는 방식. 표준 리뷰(중립 검토)와 구별됨
  • Codex Plugin for Claude Code — OpenAI가 배포한 Claude Code용 MCP 플러그인. GitHub: openai/codex-plugin-cc
  • Codex Rescue — Anthropic 한도 소진 시 Codex가 Opus 대신 전체 태스크를 수행하는 대체 실행 모드
  • Working Tree 변경 — 워킹트리 변경 9개(수정 파일 1 + 미추적 파일 8)처럼, Adversarial Review가 git 상태까지 인식해 범위 결정
  • 공격 표면 7가지 (Attack Surfaces) — 인증, 데이터 손실, 롤백, 경쟁 상태(Race Condition), 의존성 저하, 버전 불일치, 관측성 공백(Observability Gap) — Adversarial Review가 집중적으로 검토하는 항목
  • 스키마 드리프트 (Schema Drift) — DB 스키마와 코드 모델이 시간이 지나며 어긋나는 현상. Codex가 실제 발견한 문제 유형 중 하나
  • Softmax Picks — 확률 기반 트윗 선택 로직(화자의 트위터 참여도 분석 앱 내 기능)

화자의 디테일 (놓치기 쉬운 포인트)

  1. Codex 사용량은 ChatGPT 계정에서 차감됨 — 무료 계정도 연동은 되지만 사용량 한도 적용
  2. 설치 시 사용자 범위(user scope) 로 설치 선택 권장 — 시스템 전체 설치보다 격리됨
  3. Codex Adversarial Review는 리뷰 시작 전 먼저 리뷰 규모를 추정해 모드를 결정하고, 백그라운드 실행 여부를 사용자에게 물어봄
  4. 결과 출력 형식: 심각도(Critical / High / Medium / Low) + 영역 + 실제 문제 + 해당 파일·코드라인 + 영향 + 수정 방법 — 구조화된 JSON 형태
  5. 화자가 직접 테스트한 앱: 30~45분 간격으로 AI 분야 트윗 스캔 → 품질 필터 → 점수 계산 → Supabase 중복 제거 → Telegram 전송 → 응답 AI + 피드백 루프 구조 (복잡한 편)
  6. 공통 발견 문제는 Telegram 폴링 처리 1건뿐 — Codex는 High, Opus는 Critical로 심각도 평가가 달랐음
  7. 화자는 "Codex가 Opus보다 낫다"는 결론을 명확히 거부 — "이건 도구 상자에 새 도구가 추가된 것"이라는 입장
  8. $20(ChatGPT) vs $100(Anthropic Pro) vs $200 요금 구간 언급 — Codex 연동이 $20~$100 사이의 중간 선택지 역할을 할 수 있다고 봄
  9. Anthropic이 자체 엔지니어링 블로그에서 Opus의 자기 코드 평가 한계를 직접 인정했다고 언급 (지난주 공개)
  10. GitHub의 예시 프롬프트를 보면 Adversarial Review에 검토 항목을 매우 구체적으로 지정 가능 — 이번 테스트는 열린 프롬프트였음

1. Codex Plugin 주요 기능

Claude Code에서 OpenAI Codex를 쓸 수 있게 됐다. Anthropic의 가장 강력한 경쟁 모델을 Claude Code 생태계 안에서 직접 호출하는 구조다.

플러그인이 제공하는 기능은 크게 세 가지다.

  • 기본 코드 리뷰 (Standard Review) — 중립적 시각으로 코드 검토
  • Adversarial Review (적대적 리뷰) — "분명 뭔가 실수했을 것"이라는 가정으로 검토. 화자가 가장 중요하다고 꼽음
  • Codex Rescue — Codex가 Opus처럼 독립적으로 태스크를 수행
  • 진행 상태 확인 기능 추가 포함

Adversarial Review의 핵심 전제: 같은 AI가 기획·생성·평가를 모두 하면 자신의 실수를 제대로 못 잡는다. Anthropic도 자사 엔지니어링 블로그에서 이 점을 인정했다.

2. 설치 및 인증

# 마켓플레이스 추가 명령어 (설명란 참조)
# 플러그인 명령어로 설치
codex@openai  # 설치 위치: 사용자 범위(user scope) 권장
# 플러그인 리로드
codex setup   # → 브라우저로 ChatGPT 계정 인증

사용량은 ChatGPT 계정에서 차감된다. 무료 계정도 연동 가능하지만 한도가 있다. GitHub 저장소 openai/codex-plugin-cc에도 설치 명령어가 정리되어 있다.

3. 활용 사례 1 — 사용량 분산 (Codex Rescue)

Anthropic Pro / Max 요금제도 집중 사용 시 한도에 빠르게 도달할 수 있다(지난주 크레이 버그 이슈도 영향). 이때:

  • Opus 4.6으로 기획·설계
  • Codex Rescue로 실행
# Codex Rescue 실행
/codex-rescue "<프롬프트>" --effort <level>

Codex 모델 자체도 탄탄하고, 비용은 Anthropic 대비 크게 낮다.

4. 활용 사례 2 — Adversarial Review 실습

화자의 트위터 참여도 분석 앱(약 30~45분 간격 스캔 → Supabase → Telegram → 피드백 루프)을 대상으로 테스트.

프롬프트는 열린 형태로: "코드베이스를 보고 어떻게 생각하는지 알려줘."

Codex가 먼저 리뷰 규모를 추정하고, 백그라운드 실행 여부를 확인한 뒤 시작. 범위에 워킹트리 변경 9개(수정 파일 1 + 미추적 파일 8) 포함됨을 자동 인식.

5. Adversarial Review 내부 동작 (7단계)

단계 내용
1 인자 파싱 (플래그 없으면 기본값)
2 리뷰 규모 추정
3 리뷰 대상 결정
4 관련 컨텍스트 수집
5 Adversarial 품질 기준 확인
6 프롬프트 생성 (공격 표면 7가지 집중)
7 OpenAI 서버로 전송 → 구조화 결과 반환

공격 표면 7가지: 인증(Authentication), 데이터 손실, 롤백, 경쟁 상태(Race Condition), 의존성 저하, 버전 불일치, 관측성 공백(Observability Gap)

결과 형식: 심각도(Critical/High/Medium/Low) + 영역 + 문제 + 파일·코드라인 + 영향 + 수정 방법

6. Codex 단독 결과

문제 4건 발견, 전부 High 등급.

# 문제 유형
1 중복 제거(Dedup) 로직 결함
2 Telegram 폴링 처리 방식
3 스키마 드리프트(Schema Drift)
4 대시보드 빌드 문제

7. Opus 4.6 비교 실험

Codex가 생성한 Adversarial Review 프롬프트(구조·설계 선택을 적극 검증 + 동일 출력 형식)를 그대로 Opus에 입력.

결과 비교:

구분 내용
공통 발견 Telegram 폴링 처리 1건 (Codex: High / Opus: Critical)
Opus 단독 발견 추가 7건 (High 또는 Critical)
Codex 단독 발견 3건 (Opus가 놓침)

더 많이 찾았다고 Opus가 무조건 낫다는 뜻은 아님. 두 모델이 서로 다른 것을 잡아내는 것이 핵심.

8. 종합 판단

"Opus가 늘 자기 자신을 채점하는 것보다, 두 번째 눈으로 한 번 더 보는 게 낫다."

같은 AI가 기획·생성·평가를 모두 담당하는 구조에는 근본적 한계가 있다. Codex는 비용도 괜찮아서 이 역할에 잘 맞는다.

비용 구간 정리: - $20/월 ChatGPT → Codex Adversarial Review 가능 - $100/월 Anthropic Pro → Claude Code 집중 사용 - $200/월 → 부담스러운 구간

Codex 연동은 $20~$100 사이를 채우는 실용적 선택지. 이미 ChatGPT를 쓰고 있다면 추가 비용 없이 붙여 쓸 수 있다.

교정 전사 (한국어)

전체 전사 펼치기

이제 Claude Code 안에서 Codex를 쓸 수 있게 됐습니다. OpenAI [?오퍼네이에 → OpenAI]가 이 기능을 내놨습니다. Opus 4.6의 가장 큰 경쟁 모델을 이제 Anthropic 생태계 안에서도 쓸 수 있게 됐습니다. Claude Code를 즐겨 쓰는 분들에겐 반가운 소식입니다. 특히 사용량 제한 때문에 답답했던 분들이라면 더 그렇죠. 솔직히 말해 Codex가 달러 대비 크레딧, 토큰 효율이 훨씬 좋거든요.

그래서 이번 영상에서는 설정 방법을 보여드리고, Claude Code 위에 Codex를 얹었을 때 실제로 뭘 할 수 있는지 같이 보겠습니다. 더 중요한 건 Claude Code에서 Opus 4.6과 Codex를 함께 쓸 때 뭘 할 수 있느냐는 점입니다. 두 모델을 서로 견제하게 해서 각자 따로 쓸 때보다 더 좋은 결과를 만들 수 있을까요?

설치에 들어가기 전에 먼저 Claude Code 플러그인이 뭘 가져다 주는지 짧게 보겠습니다. 기능이 몇 가지 있는데 제가 보기엔 가장 중요한 건 코드 리뷰입니다. 쉽게 말해 Opus가 작성한 코드를 다시 살펴보게 할 수 있다는 뜻이고, 이건 두 단계로 나뉩니다. 첫 번째는 기본 Codex 리뷰입니다. 말 그대로 중립적으로 코드를 검토해주는 방식이죠. 두 번째는 제가 정말 좋아하는 Adversarial Review입니다. 이건 Codex에게 Opus든 다른 코딩 에이전트든 누가 만든 코드든 아주 까다로운 시선으로 보라고 하는 겁니다. 상대가 분명 뭔가 실수했을 거라고 가정하고 뭘 더 좋게 만들 수 있는지 찾으라는 뜻이죠. 그래서 결과물을 확실히 끌어올리는 데 아주 좋습니다.

많은 AI 모델의 문제는 자기 코드를 제대로 평가하지 못한다는 점이거든요. Anthropic도 지난주에 공개한 엔지니어링 블로그에서 이 얘기를 했습니다. 그래서 이런 Adversarial Review 같은 기능은 정말 좋습니다. 그 외에도 Codex Rescue를 쓸 수 있는데, 이걸 쓰면 Claude Code 안에서 Opus를 쓰듯이 Codex가 혼자서 무언가를 만들게 할 수 있습니다. 그 밖에는 작업 진행 상태를 확인하는 기능들도 있습니다.

그럼 바로 들어가서 설치를 보겠습니다. 설치는 아주 간단합니다. 이 명령어를 실행해서 마켓플레이스에 추가하면 되고, 관련 명령어는 설명란에 다 넣어두겠습니다. 그 다음 플러그인 명령어로 설치하면 됩니다. codex@openai가 설치 위치를 물어보는데 저는 사용자 범위로 설치하겠습니다. 그리고 플러그인을 다시 불러오면 바로 작동합니다. 마지막으로 codex setup을 실행하면 됩니다. 혹시 모르셨다면 이 플러그인용 GitHub 저장소도 있어서 설치 명령어가 거기에도 정리되어 있습니다. 그것도 설명란에 링크해두겠습니다. 그리고 사용량은 ChatGPT 계정에 연결됩니다. 무료 계정이어도 그렇다고 하더군요. 그러니 Codex 사용량에서 차감된다는 점은 알아두셔야 합니다. Codex를 설치할 거냐고 물으면 예를 누르시면 됩니다. 그러면 로그인하게 되고 브라우저로 넘어가서 인증 과정을 진행합니다.

Claude Code 안에서 이 Codex 도구를 쓰는 대표적인 활용 사례는 크게 두 가지입니다. 첫 번째는 Claude Code의 사용량 제한을 다루는 겁니다. 보통 Anthropic Pro나 Max 요금제를 쓰더라도 제한에 꽤 빨리 걸릴 수 있습니다. 특히 지난주에 보였던 [?크레이 버그들 → Claude 버그들]까지 겹치면 더 그렇죠. 그럴 때는 Opus 4.6으로 기획하고 실행은 Codex에 맡기면 됩니다. 이것도 아주 간단합니다. 그냥 Codex Rescue를 실행하면 됩니다. 그러면 거기에 프롬프트를 넣어주면 됩니다. 여기 보이는 것처럼 --effort 레벨 같은 여러 플래그도 함께 지정할 수 있습니다. 그리고 기억하셔야 할 건 Codex 모델 자체가 꽤 탄탄하다는 점입니다. 게다가 사용량도 Anthropic 요금에 비하면 비교가 안 될 정도로 부담이 적습니다.

하지만 제가 더 흥미롭다고 보는 건 아까 말한 Adversarial Review입니다. 그래서 이걸 한번 테스트해보겠습니다. 제 트위터 참여도 리서치 모드를 살펴보게 할게요. 클로드 코드로 만든 웹앱입니다. 대충 어떤 앱이냐면 30분에서 45분마다 AI 분야 트윗을 스캔하고 품질 필터도 있습니다. 여러 기준으로 점수 신호를 계산하고 트윗이 중복되지 않도록 Supabase와 연결되어 있습니다. 자체 점수 시스템도 있고 Softmax Picks도 연동되어 있습니다. 그리고 모든 결과는 Telegram으로 보내집니다. 응답을 돕는 AI도 안에 넣어뒀고, 제 응답들을 추적하는 피드백 루프도 있습니다. 아주 복잡한 시스템은 아니지만 그냥 랜딩 페이지 하나를 보는 수준도 아닙니다.

그래서 이 코드에 Adversarial Review를 돌렸을 때 Codex가 뭘 내놓는지 보겠습니다. 해석의 여지는 꽤 넓게 두겠습니다. Codex에게는 코드베이스를 보고 어떻게 생각하는지 알려달라고만 했습니다. 그러자 가장 먼저 리뷰 규모를 추정해서 어떤 모드가 적절한지 판단하겠다고 합니다. 그 다음에는 백그라운드로 돌릴지 아니면 결과를 기다릴지 묻습니다. 저는 결과를 기다리겠습니다. 그리고 전체 코드베이스에 더해 워킹트리 변경 9개가 리뷰 범위에 포함된다고 알려줍니다. 수정된 파일 1개와 추적되지 않은 파일 8개가 있다는 뜻이죠.

Adversarial Review가 실제로 어떻게 동작하는지 이야기해 보겠습니다. 우선 인자를 파싱했습니다. 플래그를 따로 주지 않았으니 기본 설정으로 진행했습니다. 그리고 리뷰 크기를 추정하고 대상을 정하고 관련 컨텍스트를 수집했습니다. 이 첫 4단계를 거친 뒤에는 Adversarial 품질을 확인하고 프롬프트를 만듭니다. 특별히 집중해서 볼 공격 표면이 7가지 있습니다: 인증, 데이터 손실, 롤백, 경쟁 상태, 의존성 저하, 버전 불일치, 관측성 공백. 이런 건 표면 안에 숨어 있지만 제대로 파악하지 못한 채 프로덕션에 밀어넣으면 크게 사고 날 수 있는 문제들입니다. 그 다음 이 정보를 전부 OpenAI 서버로 보내서 Codex가 검토하게 합니다. 그리고 나면 구조화된 결과를 돌려줍니다. 발견 사항의 심각도도 함께 보여줍니다. Critical, High, Medium, Low 같은 등급과 함께 권장사항, 다음 단계도 제시해줍니다.

Claude Code 안에서 응답을 기다리기만 하면 됩니다. Codex는 제 코드베이스에서 문제 4개를 찾아냈고 전부 심각도는 High였습니다. 각 항목마다 심각도, 영역, 실제 문제가 정리됩니다. 확인해야 할 파일과 코드라인, 그리고 실제 영향과 수정 방법까지 같이 알려줍니다. 첫 번째는 중복 제거 로직 문제였습니다. 두 번째는 Telegram 폴링 처리 방식, 그 다음은 스키마 드리프트 문제였습니다. 마지막은 실제 대시보드 빌드 문제였습니다.

그런데 제가 궁금한 건 이겁니다. 자기 코드베이스를 대상으로 비슷한 Adversarial Review를 요청하면 Claude는 어떤 결과를 줄까요? 둘을 정면으로 붙여보면 꽤 흥미로울 것 같았습니다. 그래서 지금 Opus에도 같은 방식의 Adversarial 코드 리뷰를 돌리고 있습니다. 프롬프트는 Codex가 짜준 걸 그대로 썼습니다. 핵심은 구현과 설계 선택을 적극적으로 검증해보라는 내용입니다.

이제 결과를 정리해서 보겠습니다. 우선 둘이 공통으로 찾은 문제가 하나 있었습니다. 둘 다 Telegram 이슈를 문제라고 봤습니다. 코덱스는 High라고 했고, Opus는 Critical이라고 했습니다. 그리고 Opus는 Codex가 찾지 못한 추가 문제 7개를 High 또는 Critical로 분류했습니다. 물론 문제를 더 많이 찾았다고 해서 Opus가 무조건 Codex보다 낫다고 말하는 건 아닙니다. 반대로 Codex가 찾았는데 Opus가 놓친 문제도 3개 있었습니다.

전체적으로 보면, 여기서 뭘 읽어낼지는 결국 각자 판단하기 나름입니다. 다만 분명한 건, 이 두 시스템을 함께 보는 데 가치가 있다는 점입니다. Opus가 늘 자기 자신을 채점하는 것보다, 두 번째 눈으로 한 번 더 보는 게 낫다는 거죠. 같은 AI 시스템이 기획도 하고, 생성도 하고, 평가도 하는 구조에는 근본적인 한계가 있다고 저는 생각합니다. 특히 Codex는 가격도 괜찮아서, 이런 Adversarial Review가 더 좋다고 생각합니다.

이미 ChatGPT를 쓰고 있다면 더더욱 그렇죠. 한 달에 20달러를 이미 내고 있는데, 이렇게 간단하게 Codex를 붙여서 뭐든 검토하게 할 수 있다면, 굳이 안 쓸 이유가 있을까요? 물론 이렇게 짧게 테스트한 것만으로는 확실한 결론을 내릴 수는 없겠죠. Codex가 Opus보다 낫다, 혹은 그 반대다라고 단정할 수는 없습니다. 그리고 저는 그런 논쟁 자체가 핵심을 놓친다고 생각합니다. 이건 그냥 우리 도구 상자에 하나 더 들어온 새로운 도구일 뿐이고, 이제 우리는 그걸 쓸 수 있습니다.

Adversarial Review도 훨씬 더 구체적으로 시킬 수 있습니다. 이번 프롬프트는 꽤 열려있는 편이어서 여러 방식으로 해석될 여지가 많았습니다. 하지만 GitHub의 예시만 봐도 Codex에게 정확히 뭘 봐야 하는지 꽤 구체적으로 지정할 수 있습니다. 전체적으로 보면, 이건 Claude Code 생태계의 아주 좋은 추가 기능이라고 생각합니다. 도구는 많을수록 좋죠. 특히 이미 ChatGPT를 쓰고 있거나, Anthropic Pro 요금제를 쓰면서 ChatGPT도 함께 쓰는 분들에게 더 그렇습니다. 월 100달러는 조금 부담스럽고 200달러는 확실히 너무 비쌀 수 있죠. 이건 20달러 구독과 100달러 구독 사이를 메워주는 중간 선택지처럼 느껴집니다. 실제로 Codex는 가성비가 정말 좋거든요. 꼭 한번 써보세요. 설정도 아주 쉽습니다.
