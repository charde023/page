Claude Code 창시자 보리스 체르니는 "코딩은 사실상 해결됐다"고 선언하며, 루프·서브에이전트·컴퓨터 유즈(computer use)가 개발자와 스타트업의 일하는 방식을 근본적으로 바꿀 것이라고 예측한다.

멀티에이전트 워크플로 병렬화로 처리량 수십 배 수백~수천 에이전트를 동시에 돌리는 것이 이미 보리스의 일상
/batch 대량 병렬 작업 단위 실행 loop와 함께 쓰면 PR 150개/일도 가능
서브에이전트 (sub-agent) 에이전트가 에이전트를 생성 Claude에게 "서브에이전트로 해줘" 요청만으로 작동
Routines (루틴) 서버 사이드 loop 노트북 닫아도 계속 실행
MCP (Model Context Protocol) 지식 업무의 "API 레이어" Salesforce·Google Docs·Slack 등 어디든 연결 가능
프로덕트 오버행 (product overhang) 모델 능력 > 기존 제품 한계 다음 모델을 위해 미리 제품 설계하는 전략
7 Powers (해밀턴) AI 시대에 모드(mode)의 가치 변화 분석 스위칭 비용·프로세스 파워는 감소, 네트워크 효과·규모 경제는 유지

내가 모를 만한 것 / 처음 보는 것

  • /loop: Claude Code CLI 명령. Claude에게 cron 스케줄 반복 작업을 맡기는 기능. PR 감시, CI 건강 유지, Twitter 피드백 클러스터링 등에 활용.
  • Routines: /loop의 서버 사이드 버전. 로컬 세션을 닫아도 에이전트가 계속 동작.
  • /batch: 멀티에이전트 대량 병렬 실행 명령.
  • 프로덕트 오버행 (Product Overhang): 모델이 이미 특정 능력을 갖췄지만, 그 능력을 활용하는 제품이 아직 없는 상태. Anthropic 내부에서 자주 쓰는 용어.
  • 7 Powers (Seven Powers): Hamilton Helmer의 경영 전략 프레임워크. 7가지 사업 해자(moat) — 스위칭 비용, 프로세스 파워, 네트워크 효과, 규모 경제, 코너드 리소스 등.
  • PMF (Product-Market Fit): 제품-시장 적합성. Claude Code는 출시 초기 6개월간 PMF가 없었음.
  • hill climb: 목표를 주고 "될 때까지 반복 개선"하도록 모델에 지시하는 패턴. Opus 4.7부터 자율적으로 수행.
  • computer use: Anthropic의 컴퓨터 직접 제어 기능. MCP가 없는 소프트웨어를 조작하는 catch-all 수단.
  • TypeScript + React 선택 이유: 모델이 가장 많이 학습한 "온 디스트리뷰션(on distribution)" 스택이라 초기 모델 품질이 낮을 때 유리했음.
  • Acquired Podcast: 기술 기업 심층 분석 팟캐스트. 보리스가 언급한 Seven Powers는 이 팟캐스트가 즐겨 인용.

화자의 디테일 (놓치기 쉬운 포인트)

  1. Claude Code는 2024년 말 Anthropic Labs(소수 혁신팀)에서 시작 — MCP, 데스크톱 앱도 이 팀 산출물.
  2. 초기 6개월간 Claude Code는 잘 작동하지 않았고, 보리스 자신도 전체 코드의 10%만 AI로 작성했다.
  3. 지수적 성장은 Opus 4(2025년 5월) 출시 시점부터 시작됐다. 이후 모델 릴리스마다 inflection.
  4. 보리스는 현재 하루에 보통 수십 개 PR을 처리하며, 기록은 하루 150 PR.
  5. Claude Code 코드베이스는 TypeScript + React — "별 비밀 없다, 단순하다"고 직접 발언.
  6. Anthropic 내부에서는 모든 SQL을 모델이 작성하며, 수동으로 작성된 코드가 단 한 줄도 없다.
  7. Anthropic 직원들의 Claude끼리 Slack MCP로 서로 대화하며 unknowns를 해결한다 — "코드를 짜는 동안 내 Claude가 다른 사람 Claude와 Slack으로 소통".
  8. Opus 4.7은 목표를 주면 스스로 loop를 시작하고 Slack으로 30분마다 리포트를 보내는 행동을 자율적으로 한다 — 사용자가 지시하지 않아도.
  9. 모델 측면의 격차는 없다 (외부 개발자와 동일한 모델 사용). 격차는 조직 구조와 프로세스에 있다.
  10. 보리스는 중학교 때 TI-83+ 계산기 Basic 가이드를 작성한 적 있으며 지금도 인터넷에 남아 있다 (본인이 매우 부끄러워함).
  11. 인쇄기 비유: 1400년대 유럽 식자율 10% → 500년 후 70%. 소프트웨어도 같은 민주화 경로를 밟되 훨씬 빠를 것.
  12. "최고의 회계 소프트웨어 개발자는 엔지니어가 아니라 뛰어난 회계사" — 도메인 지식이 코딩보다 중요해지는 미래.
  13. Claude Design을 "지금은 꽤 좋지만 훨씬 더 좋아질 것"의 대표 사례로 꼽음 (product overhang 전략의 현재 진행형).
  14. YC 첫 번째 직원 경험 — "사람들이 사랑하는 것을 만들어라(build something people love)"가 제품 디테일에 집착하는 이유.
  15. 로컬 vs. 클라우드 모델 논쟁: "결국 모델이 알아서 결정할 것 — 엔지니어가 고민할 문제가 아니게 된다."

1. Claude Code 탄생 배경

2024년 말 보리스 체르니는 Anthropic 내부 혁신 인큐베이터 "Anthropic Labs"에 합류했다. 팀원 수가 매우 적었고 Claude Code, MCP, 데스크톱 앱을 모두 이 팀이 만들었다. 팀은 이후 해산됐다가 지금은 Mike Krieger(Anthropic CPO, Instagram 공동창업자) 주도로 재결성.

출발점은 프로덕트 오버행 인식이었다. 2024년 말 기준 코딩 도구의 최첨단은 탭 자동완성(Typeahead)이었지만, Sonnet 3.5 수준의 모델은 이미 그 이상을 할 수 있었다. 그래서 "에이전트가 모든 코드를 작성하도록 하자"는 방향으로 전환.

초기 6개월은 잘 작동하지 않았고 — 보리스 자신도 10%만 사용. 지수적 성장은 Opus 4(2025년 5월) 출시 이후. 이후 매 모델 릴리스(4.5, 4.6, 4.7)마다 재차 inflection.

핵심 메시지: "다음 모델을 위해 제품을 미리 만들고 있었다. PMF가 6개월 후에 온다는 걸 알면서 만들었다."

2. "코딩 solved"의 의미와 현황

보리스 기준으로는 이미 100% AI 작성. 하루 수십 PR이 기본이고 기록은 150 PR/일. Claude Code 코드베이스 자체도 TypeScript + React로 단순하게 구성돼 있으며, 이 선택은 초기 모델의 "온 디스트리뷰션" 특성을 활용한 것.

아직 solved가 아닌 영역: - 매우 크고 복잡한 레거시 코드베이스 - 모델 학습 데이터가 적은 특수 언어·프레임워크

이 경우에도 보리스의 답은 단순하다: "다음 모델을 기다리면 된다."

행사장 청중 대상 즉석 설문에서 "AI로 100% 코드 작성"하는 참가자는 소수였고, 절반 이상이 "중간 어딘가"에 있었다.

3. 보리스의 개인 워크플로

Claude 앱을 열면 왼쪽에 코드 탭이 있고, 항상 5~10개 세션 유지. 각 세션마다 여러 에이전트 — 일반적으로 수백 개, 야간에는 수천 개가 딥 워크를 수행.

주요 루프 목록: - PR 감시 + CI 자동 리베이스 - 플레이키 테스트 자동 수정으로 CI 건강 유지 - Twitter 피드백 30분마다 클러스터링

/loop = Claude에게 cron 스케줄 반복 작업 위임. Routines는 서버 사이드 동일 기능 (노트북 꺼도 실행됨). 보리스는 "루프가 미래"라고 단언하며 직접 실험해볼 것을 강력 권장.

4. 미래 팀 구조

단순한 full-stack 제너럴리스트가 아닌 학제 간 제너럴리스트 증가 예측.

Anthropic Claude Code팀의 현재 모습: - 엔지니어링 매니저, PM, 디자이너, 데이터과학자, 재무, 유저 리서처 — 모두 코딩 - 전문 분야는 유지하되 코딩은 기본 공통 스킬

5. SaaS 격변 (SaaS-pocalypse)

보리스가 가장 좋아하는 질문이라고 밝힘. Hamilton Helmer의 7 Powers 프레임워크를 통해 분석:

AI로 약해지는 모드: - 스위칭 비용: 모델이 다른 시스템으로 포팅을 쉽게 해줌 - 프로세스 파워: Claude가 프로세스를 역설계·최적화. 특히 4.7은 목표만 주면 hill climb 자율 수행

AI로 유지되는 모드: - 네트워크 효과 - 규모 경제 - 코너드 리소스

6. 스타트업 기회

향후 10년, 스타트업 수가 지금의 10배가 될 것이라는 예측. 이유: - 소규모 스타트업이 대기업과 정면 경쟁 가능 - 대기업은 비즈니스 프로세스 전환, 임직원 재교육, 내부 저항에 막힘 - AI 네이티브로 처음부터 시작하는 스타트업은 이 비용이 없음

"지금이 스타트업 하기 가장 좋은 시대."

7. 소프트웨어 민주화 — 인쇄기 비유

1400년대 유럽 인쇄기 등장 전 식자율: 10% (왕·귀족을 위해 글을 읽고 쓰는 직업군 존재). 인쇄기 이후 50년간 출판물이 이전 1000년치를 넘어섰고, 책 가격은 100배 하락. 이후 수백 년에 걸쳐 식자율 70%로 상승.

소프트웨어도 같은 궤적을 밟는다 — 단, 훨씬 빠르게. 그 결과: - "최고의 회계 소프트웨어는 엔지니어가 아닌 뛰어난 회계사가 만든다" - 코딩보다 도메인 전문성이 핵심 경쟁력이 되는 미래

8. Anthropic 내부 vs 외부 개발자 격차

모델 측면에서는 격차 없음 — 외부 개발자와 동일한 모델 사용. 차이점은: - 조직 구조: 모든 직군이 코딩 - 프로세스: Claude끼리 Slack MCP로 소통하며 unknowns 해결 - 코드 생산: SQL 포함 전사에서 단 한 줄도 수동 작성 코드 없음

9. 멀티에이전트·병렬화 전략

현재는 프롬프트 튜닝으로 병렬 행동 유도. 하지만 4.7부터 모델이 자연스럽게 스스로 병렬화 결정. 예시: 데이터 쿼리를 요청하자 모델이 "데이터가 계속 바뀌니 루프 시작해서 30분마다 Slack으로 리포트 줄게"라고 자율 제안.

"사용자가 툴을 더 잘 쓰는 법을 고민해야 한다면 그건 제품 설계 실패 — 모델이 알아서 해야 한다."

10. 로컬 vs. 클라우드 모델 논쟁

"결국 모델이 직접 판단해서 로컬 모델을 쓸지 클라우드를 쓸지 결정할 것 — 엔지니어가 이 결정을 하는 시대는 끝난다."

11. Co-work와 지식 업무 자동화

개발자 도구(Claude Code)가 로컬 환경 접근에 유리했던 것처럼, 지식 업무도 연결이 관건. 해법은 MCP: Salesforce, Google Docs, Google Calendar 등 연결. 연결이 안 되는 시스템에는 computer use가 catch-all 수단. Anthropic이 computer use에서 앞서 있다고 보리스가 자평.

다음 발표자를 소개하겠습니다. 손 들어보세요 — Claude Code를 쓰는 분? (다수 손) Claude Code 중독(psychosis)이 있는 분? 저희 팀은 제가 Claude Code 중독이라고 하는데, 사실일 수도 있습니다.

오늘 함께해 주신 Boris Cherny를 환영합니다. 보리스는 Claude Code의 창시자입니다. 그 과정에서 현대 소프트웨어 개발 방식을 재발명하는 최전선에 있었습니다. 인터뷰어는 저희 팀의 Lauren Reeder입니다.

인터뷰어: 오늘 함께해 주셔서 감사합니다, 보리스. 이 자리의 모든 분이 빌더(builder)입니다. 제가 보기에 당신은 빌딩 자체를 완전히 바꾸고 있습니다. 소프트웨어와 코딩의 미래, 그리고 우리가 남는 시간을 무엇에 써야 하는지 들어보고 싶습니다. 먼저 간략한 소개를 드리자면 — 보리스는 TypeScript 교과서 저술 등 경력 내내 코드를 많이 작성해온 엔지니어의 엔지니어입니다. 그런데 2026년 들어 직접 쓴 코드 줄이 하나도 없다고 하셨는데, 상당한 변화죠.

보리스: 중학교 때 TI-83+ 계산기 Basic 가이드를 쓴 것도 있는데, 아직 인터넷에 있어요. 너무 부끄러우니 검색하지 마세요.

인터뷰어: 반드시 찾겠습니다. Claude Code를 어떻게 시작하게 됐는지부터 말씀해 주세요. 이후 청중 Q&A도 많이 할 예정입니다.

보리스: 잠깐 청중 조사 — CLI 주로 쓰는 분? (다수 손) 데스크톱? (손) VS Code/JetBrains? (소수) 저는 요즘 iOS가 메인이에요.

Claude Code는 어떤 면에서 우연히 시작됐어요. 2024년 말에 Anthropic Labs라는 사내 인큐베이터 팀에 합류했습니다. 소수 팀이었는데 Claude Code, MCP, 데스크톱 앱을 만들었어요. 이후 팀은 해산됐고, 지금은 Instagram 공동창업자 Mike Krieger(Anthropic CPO)가 이끄는 새 팀으로 재결성됐습니다.

코딩을 시작한 이유는 프로덕트 오버행이라는 개념 때문이었습니다. 모델이 할 수 있는 것에 비해 제품이 따라오지 못하고 있다는 생각이요. 2024년 말 코딩 도구의 최첨단은 탭 자동완성이었는데 — 에디터 열고 탭 눌러서 한 줄씩 완성하는 것 — Sonnet 3.5가 그걸 처음으로 가능하게 했죠. 그런데 우리는 훨씬 더 나아갈 수 있다고 느꼈습니다. 자동완성이 아니라 에이전트가 코드 전부를 쓰게 하자.

그래서 만들었는데, 처음 6개월은 별로였어요. 제가 제 코드의 10%쯤만 쓸 정도였습니다. 출시 후에도 처음에는 폭발적 성장이 없었어요. 지수적 성장은 Opus 4(2025년 5월)부터 시작됐습니다. 기억이 생생해요. 그 이후 모델 릴리스마다 재차 inflection — Opus 4, 4.5, 4.6, 4.7. 계속 꺾이고 있습니다.

핵심은 처음부터 PMF가 없을 걸 알면서 만들었다는 겁니다. 다음 모델을 위해 제품을 미리 만들고 있었던 거죠.

인터뷰어: "코딩이 solved됐다"고 말씀하셨는데 — 무슨 의미인지, 아직 solved가 안 된 건 뭔지 설명해 주세요.

보리스: 청중 조사 한 번 더 — 코드 100% 손으로 쓰는 분? (소수) Claude Code 같은 에이전트로 100%? (소수) 중간? (다수) 저는 100%입니다.

Claude Code 코드베이스는 유출돼서 공개됐죠 — TypeScript + React, 별 비밀 없습니다. TypeScript와 React를 고른 이유는 모델이 가장 많이 학습한 "온 디스트리뷰션" 스택이기 때문입니다. 초기 모델 성능이 낮을 때 언어·프레임워크 선택이 중요했어요. 요즘은 모델이 어떤 언어든 처음 보는 것도 잘 씁니다.

덕분에 꽤 이른 시점에 모델이 100% 코드를 쓰게 됐어요. 작년 10~11월쯤부터. 지금 저는 보통 하루에 수십 개 PR, 지난주에는 150 PR을 하루에 처리한 날도 있었어요. 기록을 밀어붙여 본 거지만요.

그런데 이게 모든 곳에 해당하는 건 아닙니다. 크고 복잡한 레거시 코드베이스나 모델이 아직 잘 못 하는 특수 언어도 있어요. 그래도 보통은 "다음 모델 기다리면 된다"고 봐요.

인터뷰어: 개인 워크플로를 알려주세요. 며칠 전에 보여주셨는데 꽤 충격적이었어요.

보리스: 6개월쯤 전에 Twitter에 공유했는데, 의외로 놀라는 반응이 많았어요. 저한테는 그냥 코딩 방식이었거든요.

지금은 Claude 앱을 열면 왼쪽 코드 탭에 세션이 5~10개 있고, 각 세션마다 에이전트가 여러 개 — 보통 수백 개 돌아가고, 밤에는 수천 개가 심층 작업을 합니다.

관리 방법은 두 가지예요. 하나는 Claude에게 서브에이전트를 써서 작업하도록 시키는 것. 또 하나, 요즘 제가 더 많이 쓰는 게 /loop입니다. 가장 심플하고 가장 잘 되는 것. 원리는 Claude가 cron으로 미래에 반복 실행될 작업을 스케줄링하는 것 — 1분마다, 5분마다, 매일, 원하는 주기로.

현재 수십 개의 루프가 돌아가고 있어요. PR 감시 + CI 자동 리베이스, CI 건강 유지(플레이키 테스트 자동 수정), Twitter 피드백 30분마다 클러스터링. 루프가 미래라고 생각해요. 안 써보셨다면 강력 추천합니다. 최근 Routines도 출시됐는데, 서버 사이드 버전이라 노트북 닫아도 계속 실행됩니다.

인터뷰어: 미래 팀 구조는 어떻게 될까요?

보리스: 예측하기 어렵지만 해볼게요. 제너럴리스트가 훨씬 많아질 것 같습니다. 지금 말하는 제너럴리스트는 iOS + 웹 + 서버 다 하는 풀스택 엔지니어지만 — 앞으로는 학제 간 제너럴리스트입니다. 제품 엔지니어링 + 디자인, 또는 제품 + 데이터과학 + 엔지니어링.

우리 팀에서 이미 보이고 있어요. Claude Code 팀에서 EM, PM, 디자이너, 데이터과학자, 재무, 유저 리서처 — 모두가 코딩합니다. 각자 전문 분야가 있지만 코딩은 공통 스킬이에요.

인터뷰어: AI가 코딩을 10~100배 저렴하게 만들면 소프트웨어 제품의 가치는 어떻게 될까요? SaaS 대학살이 오는 건가요?

보리스: 제가 제일 좋아하는 질문입니다. Acquired 팟캐스트 듣는 분? (청중 일부) 최고의 팟캐스트예요. 최근 저도 한 번 출연했는데 영웅들을 만난 느낌이었어요.

거기서 자주 언급하는 Hamilton Helmer의 7 Powers 개념이 있습니다. AI로 일부 모드는 더 중요해지고 일부는 덜 중요해집니다.

덜 중요해지는 것: 스위칭 비용 (모델이 포팅을 쉽게 해줌), 프로세스 파워 (Claude가 프로세스를 역설계·최적화). 특히 4.7은 목표만 주면 될 때까지 hill climb합니다. 이런 모드를 가진 기업에게는 위협.

유지되는 것: 네트워크 효과, 규모 경제, 코너드 리소스 — AI로 크게 변하지 않음.

두 번째로, 향후 10년간 스타트업 수가 10배 늘 것입니다. 소규모 스타트업이 대기업과 정면 경쟁할 수 있게 됐으니까요. 대기업은 내부 전환 비용, 재교육, 저항에 막히지만 스타트업은 처음부터 AI 네이티브로 시작할 수 있습니다. 지금이 스타트업 하기 가장 좋은 시대예요.

청중 질문 1 (Dan): Claude Code를 PMF 6개월 전에 만들었다고 하셨는데, 성공의 요인이 모델 vs 제품 결정의 비율이 어떻게 됩니까?

보리스: 6개월~1년 전에는 50:50이었어요. YC에서 첫 직원으로 일하면서 스타트업 여러 개 해봤는데, YC가 반복해서 가르치는 게 "사람들이 사랑하는 것을 만들어라"입니다. 모델이 뭐든 결국 제품이 사랑받아야 합니다. 그래서 우리는 디테일에 많이 신경 씁니다.

모델이 좋아질수록 하네스(harness)의 중요성은 줄어들 겁니다. 지금 고민하는 것은 하네스를 어떻게 발전시키냐 — 루프를 first class로, 에이전트 대량 실행을 쉽게. 1년 후에는 모델 alignment가 훨씬 좋아져서 프롬프트 인젝션 방어, 명령어 정적 검증, 권한 모드, human-in-the-loop 같은 안전장치가 지금보다 덜 중요해질 겁니다. 모델이 그냥 올바른 일을 할 테니까요.

청중 질문 2: Claude Code가 소프트웨어 민주화를 시작했습니다. 가게 주인이 직접 소프트웨어를 만들고, 마이크로컨트롤러로 문 열릴 때 불을 제어하는 것까지. 소프트웨어가 Microsoft Office처럼 누구나 쓰는 기술이 될까요?

보리스: 네, 그 이상이요. 저는 SF와 기술사를 많이 읽는데, 지금 상황과 가장 명확한 역사적 유사점이 있습니다 — 1400년대 유럽 인쇄기.

인쇄기 이전 유럽 식자율은 10% 정도였어요. 왕과 귀족을 위해 읽고 쓰는 직업군이 있었죠. 인쇄기 발명 후 50년 만에 그 이전 1000년보다 많은 책이 나왔고, 책 가격은 100배 하락. 이후 수백 년에 걸쳐 식자율이 70%로 올라갔습니다.

소프트웨어도 같은 궤적을 밟을 것입니다 — 훨씬 빠르게. 그리고 회계 소프트웨어의 최고 개발자는 엔지니어가 아니라 뛰어난 회계사가 될 겁니다. 코딩은 쉬운 부분이고, 도메인 지식이 어려운 부분이니까요.

청중 질문 3: Anthropic 내부와 외부 개발자 간 격차 — 몇 개월인가요? 격차가 커지고 있나요 줄어들고 있나요?

보리스: 모델 측면에서는 격차가 없어요. 저희도 동일한 모델 씁니다. 내부에서 새 모델(지금은 일종의 미토스 같은 것)로 dog food 해보고, 그게 Opus 4.7 형태로 출시됩니다. 제품 측면에서는 격차가 더 큽니다.

Anthropic 전체에서 Claude를 모든 것에 씁니다. 제가 코딩하는 동안 제 Claude가 다른 사람의 Claude와 Slack으로 소통해서 미지의 것들을 해결합니다. 회사 전체에 수동 작성 코드가 하나도 없어요 — SQL 포함 전부 모델이 씁니다.

제가 앞서 있는 부분은 기술이 아니에요 — 같은 기술이 모두에게 열려 있으니까요. 저희가 플랫폼을 만드는 것이기 때문에 개발자들이 저희와 같은 것을 쓸 수 있어야 합니다. 실제로 앞서 있는 것은 조직 구조와 프로세스입니다. 이런 자리에서 공유하면서 모두가 배울 수 있으면 좋겠어요.

청중 질문 4 (Jared): 멀티에이전트, /batch, /loop, 서브팀 등 관련해서 — 모델 레벨과 하네스 레벨에서 병렬화를 어떻게 개선하고 있나요?

보리스: 제품 측면에서는 프롬프트 조정으로 병렬 행동을 유도합니다. 하지만 솔직히 모델이 좋아질수록 자연스럽게 됩니다. 4.7은 루프를 스스로 시작합니다. 데이터 쿼리를 요청했더니 "데이터가 계속 바뀌네요, 루프 시작해서 30분마다 리포트 줄게요"라고 하고, 제가 "Slack으로 보내줘"라고 했더니 Slack MCP를 써서 바로 합니다.

시간이 지나면 사용자가 툴을 잘 쓰는 법을 고민하지 않아도 됩니다. 그게 아직 안 되면 제품 설계 실패예요. 모델이 해야 합니다.

청중 질문 5: 클라우드 중앙집중 AI vs 로컬 AI 트렌드, 어떻게 보세요?

보리스: 몇 가지 방식으로 답할 수 있는데, 가장 근본적인 답은 "그게 중요하지 않게 될 것"입니다. 몇 년 후에는 모델이 모든 코드를 짜고, 에이전트를 시작하고, 환경을 구축할 겁니다. 로컬 모델을 쓸지 클라우드를 쓸지 모델이 스스로 결정할 거예요. 엔지니어가 내리는 결정이 아니게 됩니다.

청중 질문 6 (Jamie): Claude Code가 로컬 개발 환경을 잘 활용한 것처럼, Co-work는 어떻게 지식 업무 도구에 충분한 접근권을 줄 건가요?

보리스: 좋은 질문입니다. 대기업에서 환경을 리모트로 전환하는 데만 5년 걸리는 걸 봤는데 — 지식 업무는 이미 Salesforce, Google Docs 같은 클라우드 도구로 대부분 거기 있어요. 답은 MCP입니다. Claude 앱에 있는 MCP 커넥터로 Salesforce, Google Docs, Google Calendar 연결하면 Co-work도, Claude CLI도, Claude Code 어디서든 쓸 수 있어요.

MCP가 없는 시스템은 computer use가 catch-all입니다. Anthropic이 컴퓨터 유즈에서 꽤 앞서 있다고 생각해요. 4.7로 거의 모든 소프트웨어를 다룰 수 있는데 속도가 느리지만 잘 됩니다. 아니면 MCP, CLI, API — 어떤 형태든 프로그래매틱 접근이면 됩니다. 모델에게는 다 토큰이니까요.

청중 질문 7 (Ryan/Sean): product overhang을 보고 미리 제품을 만든 것처럼, 지금 만들고 있는 것 중 6개월~1년 후 모델이 좋아지면 훨씬 흥미로워질 것이 있다면?
