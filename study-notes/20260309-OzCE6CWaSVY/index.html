내가 모를 만한 것 / 처음 보는 것

  • GTM (Go-To Market) 엔지니어링 — Clay.com이 처음 확립한 개념. 콜드 이메일·아웃리치에서 시작했으나 지금은 마케팅·광고·제품까지 확장 중
  • Keywords Everywhere — 키워드 볼륨·CPC 데이터를 API로 제공하는 SEO 도구. Claude가 직접 API 호출 가능
  • Graph MCP (graphed.com) — GTM팀용 AI 데이터 분석 도구. Google Search Console 등 데이터를 MCP로 Claude에 연결
  • Super Whisper — 음성 → 텍스트 변환 로컬 앱. Option + Spacebar로 트리거. Claude Code에 프롬프트를 타이핑 대신 음성으로 입력
  • Strapi — 오픈소스 Headless CMS. 블로그 콘텐츠 발행 API 제공 (→ 용어노트/Strapi)
  • CLAUDE.md — Claude Code 프로젝트 루트에 두는 지시사항 파일. 에이전트 행동 규칙 정의
  • X대 Y (vs) 키워드 전략 — "Looker Studio vs Metabase" 같은 비교형 키워드. 구매 의도가 높아 전환율 좋음

화자의 디테일 (놓치기 쉬운 포인트)

  1. 터미널 5개 병렬 운용 — 실제 작업 방식: Claude 인스턴스를 터미널 창 5개에 동시에 띄워 각각에 다른 작업 지시. 기다리지 않고 다음 창에서 계속 작업
  2. 음성 입력으로 프롬프트 — Super Whisper (Option + Spacebar)로 Claude에게 말로 지시. 타이핑 없이 복잡한 지시 전달
  3. API 키 관리 패턴 — .env 파일 하나에 전체 스택 모든 API 키 집중. CLAUDE.md에 "새 API 키 받으면 .env에 추가하라" 지시 → 누적 재사용 가능
  4. 블로그 1500단어 기준 — 데모에서 1500 단어 분량으로 지정. 구글 첫 페이지 랭킹 콘텐츠 구조 기반
  5. 콘텐츠 품질 향상법 — AI가 30분간 화자를 인터뷰 → 트랜스크립트에서 관점·의견·시각 추출 → 소스 자료 + 톤&스타일 가이드와 함께 컨텍스트에 포함 → 최고 결과
  6. Graph MCP 무료 체험 — graph.com에서 14일 무료 체험, 팀원 무제한 포함
  7. GTM 엔지니어링 무료 코스 — gtmengineeringcourse.com 완전 무료 제공 (Cody Schneider + graph.com 운영)
  8. Google Search Console 연동 구체 흐름 — graph.com에서 GSC를 데이터 소스로 선택 → 대시보드 생성 → 상위 5개 버서스 페이지 추출 → 연관 키워드 + 최적화 인사이트 자동 분석
  9. 대시보드 이중 Y축 — 노출 수(왼쪽)와 클릭 수(오른쪽)를 별도 Y축으로 분리. 스케일 차이가 크기 때문
  10. "서쪽" 비판 반박 — AI 콘텐츠 = 쓰레기라는 주장에 "실력 문제"라고 직접 반박. 가이드라인을 제대로 주면 100% 좋은 콘텐츠 가능하다고 단언

# 섹션 요지
1 GTM 엔지니어링이란 중간 실행 작업을 Claude에게 넘기고 사람은 지휘·검수만
2 Claude Code 초기 설정 폴더 생성 → claude 실행 → .env + CLAUDE.md 구성
3 키워드 리서치 데모 Keywords Everywhere API로 vs 키워드 자동 수집
4 블로그 작성 → 발행 GSC 1위 콘텐츠 소스 기반 1500단어 작성 → Strapi 자동 발행
5 성과 분석 & 최적화 Graph MCP로 GSC 데이터 연결 → 대시보드 생성 → 개선 인사이트

1. GTM 엔지니어링이란

GTM(Go-To Market)은 전통적으로 콜드 이메일과 아웃리치 프로세스를 의미했다. Clay.com이 "GTM 엔지니어링"이라는 역할을 처음 확립했고, 지금은 마케팅·유료 광고·고객 경험·제품까지 빠르게 확장 중이다.

핵심 개념: 사람이 직접 키보드·마우스로 하던 중간 실행 작업을 Claude Code에게 넘기는 것. 사람의 역할은 아이디어 제시 → 에이전트 지시 → 결과 검수·마무리로 바뀐다.

화자 Cody Schneider는 graph.com 공동 창업자이며 15년 마케팅 경력자. 엔지니어 아닌 GTM/마케터 관점에서 접근한다.

2. Claude Code 초기 설정 (10분 구축)

단계:

  1. 작업 폴더 생성 (예: Documents/demo)
  2. 터미널에서 해당 폴더로 이동: cd Documents/demo
  3. claude 입력 → Claude Code 실행
  4. Claude에게 지시: "이 디렉토리에 .env 파일을 만들고, CLAUDE.md 파일도 추가해줘. CLAUDE.md에는 API 키를 받을 때마다 .env에 추가하라는 지시사항을 넣어줘"
  5. Claude가 두 파일 자동 생성

음성 입력 방식: Super Whisper (Option + Spacebar)로 말하면 터미널에 텍스트로 변환되어 입력됨. 타이핑 없이 복잡한 지시 전달 가능.

실제 운용 방식: 터미널 5개를 열어놓고 에이전트들이 각자 작업하는 동안 다른 창에서 다음 작업 지시. 화자는 이 영상 인트로 스크립트를 편집하면서 동시에 키워드 리서치 에이전트를 돌렸다고 언급.

3. 키워드 리서치 데모

API 키가 저장된 작업 폴더에서 Claude 실행 후 지시:

"Keywords Everywhere API를 사용해서 Looker Studio vs [경쟁사] 스타일의 vs 키워드를 모두 찾아줘"

Claude가 Keywords Everywhere API를 자동 호출해서 vs 비교 키워드 목록 반환. 이 과정에서 화자는 다른 창에서 별도 작업을 동시에 진행.

4. 블로그 작성 → CMS 발행

키워드 결과에서 Looker Studio vs Metabase를 선택 후 지시:

"이 타겟 키워드로 1500단어 블로그 글을 작성해줘. 현재 구글 첫 페이지에 랭킹된 콘텐츠를 소스 자료로 사용해줘"

전략 근거: 구글이 이미 "좋은 검색 결과"라고 판단한 콘텐츠 구조를 역으로 활용. 구글의 랭킹 시그널을 그대로 학습해서 적용.

고급 방법 (이 영상에서 미다룸): AI가 화자를 30분 인터뷰 → 관점·의견·시각 담긴 트랜스크립트 생성 → 소스 자료 + 톤&스타일 가이드와 함께 컨텍스트에 포함 → 훨씬 더 개성 있는 콘텐츠

작성 완료 후:

"Strapi API를 사용해서 이 글을 블로그에 발행해줘"

→ 몇 초 후 라이브. WordPress, Webflow 등 다른 CMS도 동일한 방식으로 가능.

5. 성과 분석 및 콘텐츠 최적화

graph.com + Graph MCP 연동 흐름:

  1. graph.com에서 Google Search Console을 데이터 소스로 연결
  2. 대시보드 생성 지시 → 라인 차트 자동 생성 (일별/주별/월별 필터, 팀 공유 링크)
  3. 같은 Claude Code 채팅에서 Graph MCP 활성화 후 지시:
  4. "내 블로그의 상위 5개 vs 페이지를 찾아줘"
  5. "각 URL의 연관 키워드를 GSC 데이터에서 가져와"
  6. "콘텐츠와 GSC 데이터를 분석해서 최적화 인사이트 달아줘"
  7. 스코어카드 추가: "vs 포함 URL의 노출 수 스코어카드 추가해줘"
  8. 차트 수정: "클릭 수를 오른쪽 Y축으로 옮겨줘" (노출 수는 왼쪽, 클릭 수는 오른쪽)

결과: 어떤 콘텐츠를 어떻게 개선해야 할지 실시간 AI 분석 제공.

전체 전사 펼치기

이 영상에서는 Claude Code를 사용하는 방법을 알려드리겠습니다. 마케팅, 영어, 고객 경험, 제품 관련 업무 등 비즈니스 성장과 관련된 모든 것을 할 수 있습니다. 엔지니어링, 또는 GTM(Go-To Market) 엔지니어링이라고 하죠.

이 영상에서 10분 안에 시작하는 방법을 보여드리겠습니다. 이걸 설정하고 나면 실제로 Claude Code가 여러분을 위해 일하도록 만들 수 있습니다. 키워드 리서치를 해주고, 블로그 글을 작성하고, 실제로 블로그 글을 발행하는 것까지 말하는 겁니다. 페이스북 광고에서 어떤 내용을 다뤄야 하는지 리서치하고, 실제로 광고를 만들고, 페이스북에 게시한 다음, 어떤 광고가 성과가 낮고 높은지 분석하는 것까지 포함합니다. 이건 단순한 스킬이 아닙니다. 실제 일이 처리되는 겁니다. 그게 가장 큰 차이점이에요.

저는 Cody Schneider입니다. graph.com이라는 회사의 공동 창업자입니다. 15년 넘게 마케팅을 해봤습니다. 이 영상에서 여러분이 필요한 모든 것을 알려드리겠습니다. Claude Code를 사용해서 GTM 엔지니어링을 시작할 수 있도록 말이죠.

설정하는 방법을 보여드리겠습니다. Claude Desktop이나 다른 도구 대신 왜 바로 이걸 사용해야 하는지도 알려드리겠습니다. 더 나아가서 개인 소프트웨어와 개인 에이전트를 직접 만드는 방법도 알려드리겠습니다.

시작하기 전에 잠깐, 이 영상은 graph.com의 후원으로 제작되었습니다. GTM팀을 위한 AI 데이터 분석 도구입니다. 모든 데이터를 한 곳에 통합하고, 분석해서 정보로 전환한 다음 리포트와 라이브 대시보드를 만들 수 있습니다. MCP를 통해 연결해서 Claude Code 안에서 사용할 수도 있습니다.

GTM 엔지니어링의 배경을 설명드리겠습니다. GTM은 Go-To Market의 약자로, 전통적으로는 콜드 이메일이나 아웃리치 프로세스에 관련된 것을 의미했습니다. Clay.com이 처음에 이 용어를 확립하고 주도했습니다. 지금은 마케팅과 관련된 모든 것으로 빠르게 확장되고 있어요. 고객 경험, 제품, 유료 광고 등 무엇이든 될 수 있습니다. GTM 프로세스에 관련된 것들을 AI를 사용해서 엔지니어링하고, 소프트웨어를 개발하고, 구축하는 것이죠.

이전에는 직접 키보드를 치면서 해야 했던 중간 작업들을 말하는 겁니다. 이제 여러분의 역할은 아이디어를 가지고, 그 중간 작업을 Claude Code에 넘기는 것으로 변하고 있습니다. 여러분은 마무리하고 최종 확인하는 역할입니다.

시작하려면, 먼저 작업할 폴더를 만들어야 합니다. 저는 Graph-GTM-Agent라는 폴더에서 작업합니다. 오늘은 데모라는 새 폴더를 만들겠습니다. 폴더를 만든 다음에는 Claude Code 터미널에서 작업할 겁니다. 해당 폴더를 선택하면 됩니다.

이 시점에서 Claude가 실제로 일을 시작하게 하려면 두 가지를 해야 합니다. 먼저 환경 파일(.env)을 설정해야 하는데, 여기에 전체 스택의 모든 API 키가 저장됩니다. 그리고 CLAUDE.md라는 파일을 설정해야 합니다. 이 파일은 새로운 API 키를 제공할 때마다 환경 파일에 추가하라고 Claude에게 알려줍니다.

저는 Claude Desktop 대신 터미널에서 작업합니다. 여러 창을 동시에 열어 놓고 왔다 갔다 하면서 작업할 수 있거든요. 터미널에 들어가면 cd Documents/demo를 입력해서 방금 만든 데모 폴더로 이동합니다. 이제 claude라고 입력하면 됩니다. 말 그대로 이게 전부입니다.

제가 실제로 이걸 하는 방법은 음성 인식 소프트웨어를 사용하는 겁니다. Super Whisper라고 합니다. Option + Spacebar를 누르면 음성 인식이 시작됩니다. "이 디렉토리 안에 환경 파일을 만들어 달라. CLAUDE.md 파일도 추가한다. API 키를 받을 때마다 환경 파일에 추가해서 나중에도 사용할 수 있도록 하라"고 말합니다. 전송하면 Claude가 대신 해줍니다.

비전을 보여드리자면, 저는 이런 터미널을 5개 정도 열어놓습니다. 그 사이를 왔다 갔다 하면서 에이전트들이 일을 하도록 지시합니다. 핵심 아이디어는 이 에이전트들이 여러분 대신 실제 키보드 작업을 하도록 만드는 겁니다. 여러분은 에이전트가 하는 작업의 지휘자이자 큐레이터 역할을 하는 겁니다.

실제 예시를 보여드리겠습니다. 키워드 리서치를 하고, 블로그 글을 작성하고, 발행하겠습니다. 이 모든 걸 Claude가 5분 안에 해낼 겁니다.

모든 API 키가 저장된 작업 폴더에서 Claude를 실행하고, Keywords Everywhere API를 사용해서 Looker Studio vs [경쟁사] 스타일의 키워드를 모두 찾으라고 지시합니다. 키워드 결과가 돌아왔습니다. Looker Studio vs Metabase를 선택하겠습니다.

원하는 사양에 맞춰 블로그 글을 작성하라고 프롬프트를 입력합니다. 1500단어 분량, 타겟 키워드로 구글 첫 페이지에 랭킹된 콘텐츠를 소스 자료로 제공합니다. 현재 랭킹된 콘텐츠는 구글이 좋은 검색 결과라고 판단한 것이기 때문입니다.

가장 좋은 방법은 AI가 여러분을 30분 정도 인터뷰하게 하는 겁니다. 그 트랜스크립트에는 특정 콘텐츠 주제에 대한 여러분의 관점, 의견, 시각이 담겨 있고, 이걸 소스 자료와 톤&스타일 가이드와 함께 포함시키면 최고의 결과물이 나옵니다.

글 작성이 완료되었습니다. 이제 Strapi API를 사용해서 블로그에 이 글을 발행하라고 프롬프트를 입력하겠습니다. 블로그 글이 방금 발행되었습니다. 이미 라이브 상태입니다.

이제 이 vs 캠페인을 추적하고 싶을 겁니다. graph.com에 가서 데이터 소스로 Google Search Console을 선택합니다. 대시보드를 만들라고 지시합니다. 라인 차트가 생성됩니다. 드래그해서 일별, 주별, 월별로 필터링하고, 링크를 만들어서 팀과 공유할 수도 있습니다.

Graph MCP를 Claude Code 안에서 활성화하고, "블로그의 다른 vs 글을 찾아라. GSC 데이터 연결을 사용해서 상위 5개 vs 페이지를 가져와라. 관련 키워드를 찾고 최적화 인사이트를 달아줘"라고 지시합니다. 이 모든 도구를 병렬로 사용해서 마케팅을 지속적으로 개선하고, GTM 관련 모든 작업의 리포팅도 처리할 수 있습니다.

graph.com에서 무료로 시작할 수 있습니다. 14일 무료 체험판이 있고, 팀원 무제한까지 지원됩니다. gtmengineeringcourse.com에 가서 뉴스레터에 가입하면 이런 영상들을 보내드립니다. 완전 무료입니다. 결론적으로, 라이브 데이터를 기반으로 분석을 해주는 겁니다. 어떻게 개선할 수 있는지 알려주고 있습니다.
