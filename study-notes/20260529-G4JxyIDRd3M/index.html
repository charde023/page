1. 능동형 에이전트를 구축할 때의 기존 과제

현재 Claude Code는 강력한 코딩 도구이지만 사용자가 Enter를 눌러야 시작된다. 능동형 에이전트를 직접 구축하려면 세 가지 문제에 부딪힌다.

문제 1: 실행 환경 로컬 머신에서 돌리면 노트북을 닫는 순간 에이전트 세션이 종료된다. 호스팅, 데이터 영속성, 인증 등 프롬프트 외부 인프라를 전부 직접 관리해야 한다.

문제 2: 트리거 크론(cron)을 직접 구성하거나, 스핀업한 엔드포인트에 POST를 날려야 한다. 보일러플레이트 코드가 많다.

문제 3: 가시성과 조향 헤드리스 Claude Code 세션이 실행 중일 때 무엇을 하는지 실시간으로 알 수 없다. 감시·방향 전환·재개가 불가능하다.

2. Routines — 세 가지 문제에 대한 해법

Routines는 Claude Code에 내장된 신기능이다. 정의해야 할 것은 4가지뿐이다.

  • 프롬프트 — 무엇을 할지
  • 연결할 레포 — 어떤 코드베이스에 접근할지
  • 커넥터 — 어떤 외부 도구를 쓸 수 있는지
  • 트리거 — 언제 킥오프할지

나머지(호스팅, 세션 상태, 커넥터 인증)는 Claude Code 관리 인프라가 처리한다. 노트북 상태와 무관하게 항상 실행된다.

핵심 특성: - 루틴으로 시작된 Claude Code 세션은 웹·CLI·데스크탑에서 열고, 지켜보고, 조향하고, 재개할 수 있다 - 세션은 일반 터미널 Claude Code 세션과 동일하게 동작한다

3. 내부 사례: 문서 자동화 (Sarah의 루틴)

Claude Code의 주간 PR이 200% 증가하면서 문서 담당 엔지니어 한 명이 부담을 감당하게 됐다. Routines 출시 후 그녀가 두 가지 루틴을 만들었다.

루틴 A: 주간 문서 동기화 (스케줄 기반)

  • 트리거: 매주 월요일 오전 10시
  • 동작: 소스코드 레포의 최신 변경사항을 문서 레포와 비교 → 차이가 있으면 PR 생성
  • 커넥터: GitHub, Slack (PR 생성 시 알림)
  • 생성 방법: Claude Code 터미널에서 /schedule 입력 → 자연어로 설명 → Claude가 세부 사항 질문 → 루틴 자동 생성 및 지침 문서화

루틴 B: 이슈 이벤트 기반 문서 갭 감지

  • 트리거: Claude Code 문서 레포에 GitHub 이슈가 열릴 때
  • 동작: 이슈가 문서 갭과 관련 있는지 조사 → 갭이 맞으면 PR 생성 + Slack 알림
  • 이벤트 페이로드: 이슈 내용이 컨텍스트로 자동 주입됨
  • 실시간 조향: 이미 같은 변경에 대한 PR이 열려 있다면 웹에서 세션에 접속해 직접 중단 지시 가능

  • 소스코드 레포 (1개 이상)
  • 문서 레포
  • Google Drive (마케팅 브리프 등 스타일 참고용)
  • Slack, Datadog, Grafana, Twilio 등 커넥터

4-3. 조향성 (어떻게 품질을 보장할 것인가)

세 가지 방법을 함께 사용한다.

  1. 에이전트-온-에이전트 리뷰 (Generator-Critiquer 패턴) — 생성 루틴과 리뷰 루틴을 분리. PR 생성 이벤트가 리뷰 루틴을 트리거해 인간 리뷰 전에 자동 코멘트 생성
  2. 웹 실시간 조향 — claude.ai 웹에서 진행 중인 세션을 열어 질문하거나 방향을 전환
  3. 출력 검증 — 문서의 경우 변경된 문서 페이지를 직접 렌더링해 기대 결과 확인

전체 전사 펼치기

안녕하세요, 여러분. 잘 지내고 계신가요? 좋아요. 오늘 마지막 워크숍 세션에 오신 것을 환영합니다. Code with Claude 첫째 날을 즐기셨길 바랍니다. 제 이름은 Maya이고, Anthropic의 Applied AI 팀 소속입니다. 업무 시간의 절반은 자사 퍼스트파티 제품과 기능을 개발하고, 나머지 절반은 고객사가 자체 제품·기능·에이전트를 저희 모델 위에 구축하는 것을 돕는 일을 합니다. 오늘은 Claude Code로 능동형(proactive) 에이전트 워크플로를 구축하는 방법을 이야기하겠습니다.

먼저 손 한번 들어볼까요. Claude Code의 Routines 기능을 사용해본 분? 몇 분 계시는군요. 좋아요. 그게 오늘 이야기할 주제입니다.

기존 능동형 에이전트 구축의 문제

첫 번째 질문입니다. Claude Code를 cron으로 실행해본 분 계신가요? 손 들어보세요. 이번에는 그 인프라를 유지·관리하는 게 즐거웠다면 손을 유지해보세요. 한 분만 남으셨네요. 저희도 Anthropic 내부에서 능동형 에이전트를 Claude Code로 개발하면서 비슷한 고통을 느꼈습니다. 그래서 뭔가를 만들기로 했습니다.

코딩 에이전트는 여러분이 Enter를 눌러야 시작돼서는 안 된다고 생각합니다. 지금의 Claude Code는 매우 강력한 코딩 도구입니다. 그런데 저희는 Claude Code를 강력한 코딩 팀메이트로 만들고 싶습니다. 팀메이트는 뭔가 잘못됐을 때 스스로 알아채고 조치를 취합니다. 도구는 프롬프트를 입력하고 Enter를 눌러야 시작됩니다.

오늘 발표는 네 가지를 다룹니다. - 능동형 에이전트 구축 시 기존에 겪는 어려움 - Claude Code의 새 기능 Routines 소개 - Anthropic 내부에서 문서 자동화에 Routines를 활용한 실제 사례 - 여러분의 워크플로에 Routines를 적용하는 방법

능동형 에이전트 구축의 세 가지 어려움

첫째, 에이전트를 어디서 실행할 것인가. 로컬 머신에서 돌리고 싶지 않을 겁니다. 노트북을 닫거나 꺼지면 에이전트 세션이 끝나니까요. 호스팅, 데이터 영속성, 인증을 직접 관리해야 합니다. 프롬프트 외부에 전체 인프라를 구축해야 하는 셈입니다. 가능하지만 보일러플레이트가 많습니다.

둘째, 언제 에이전트를 킥오프할 것인가. cron을 구성하거나, 직접 스핀업한 엔드포인트에 POST를 날려야 합니다. 역시 직접 만들어야 할 인프라가 많습니다.

셋째, 사람이 루프 안에 있어야 할 때. 헤드리스 Claude Code 세션이 실제로 무엇을 하는지 실시간으로 파악하기 어렵습니다. 감시하거나, 방향을 전환하거나, 세션을 재개할 방법이 없습니다.

저희는 이 세 가지 문제를 해결하고자 했습니다. 그 결과물이 Routines입니다.

Routines란

Routines는 Claude Code의 완전히 새로운 기능입니다. 프롬프트, 연결할 레포, 사용할 커넥터, 트리거만 정의하면 원격 Claude Code 세션을 킥오프할 수 있습니다. 나머지는 Claude Code가 처리합니다.

Routines 개발 시 세 가지를 핵심 원칙으로 삼았습니다.

  1. 항상 가용 — Routines는 Claude Code의 관리형 인프라에서 실행됩니다. 호스팅, 세션 상태, 커넥터 인증을 저희가 처리합니다. 노트북 상태에 의존하지 않습니다.

  2. 능동적이고 커스터마이즈 가능한 트리거 — 시간 기반 스케줄이나 이벤트 기반 중 선택할 수 있습니다. GitHub 이벤트를 네이티브로 지원하고, 웹훅 엔드포인트에 POST 요청으로 커스텀 이벤트 트리거도 가능하며 이벤트 페이로드가 컨텍스트로 전달됩니다.

  3. 인터랙티브하고 조향 가능 — Routines로 시작된 Claude Code 세션은 터미널에서 Claude Code를 실행하는 것처럼 웹·CLI·데스크탑에서 열고, 지켜보고, 대화하고, 방향을 바꾸고, 재개할 수 있습니다.

내부 사례: 문서 자동화

Claude Code의 주간 PR 수가 연초 대비 200% 증가했습니다. Claude Code 엔지니어링 팀의 생산성은 엄청납니다. 여러분도 Claude Code에 새 기능이 매우 빠르게 추가되는 것을 체감할 겁니다. 그런데 이게 좋지 않은 한 사람이 있었습니다. 문서 유지를 담당하는 엔지니어 한 명입니다.

그녀는 Claude Code와 에이전트 SDK의 열렬한 팬이었고, Routines가 출시되자마자 조기 도입자가 됐습니다. 그녀가 문서 자동화를 위해 설정한 루틴을 살펴봅시다.

터미널에서 /schedule을 입력합니다. 그리고 이렇게 입력했습니다:

"매주 main에 머지된 새 변경사항을 문서 레포와 비교해 변경이 필요하면 docs를 업데이트하는 PR을 생성해줘."

여러분도 지금 생각해보세요. 매일 하는 작업 중 스케줄로 실행하거나 Claude Code가 먼저 시작해줬으면 하는 게 무엇인지.

Claude Code가 킥오프된 후 몇 가지 질문을 해옵니다. "Maya, 매주 언제 실행할까요?" "PR을 만들면 Slack으로 알림 줄까요?" 이 질문에 답하면 Claude가 루틴을 생성합니다.

루틴 설계의 세 가지 결정

첫째, 트리거 — 언제 실행할 것인가? 시간 기반(주간 문서 리뷰)이거나, 이벤트 기반(릴리스 컷 시 브랜치 비교, need docs 라벨이 붙은 PR 머지 시)입니다.

둘째, 컨텍스트 — Claude가 성공하려면 무엇을 알아야 하는가? 이 문서 사례에서는 Claude Code 소스코드 레포와 문서 레포 모두 필요합니다. 추가로 마케팅 브리프(Google Drive), 알림용 Slack 커넥터도 연결했습니다. Claude가 접근할 수 있는 것이 Claude 성공의 천장입니다.

셋째, 조향성 — Claude 출력 품질을 어떻게 보장할 것인가?

  • 에이전트-온-에이전트 리뷰: Generator-Critiquer 패턴을 빌려왔습니다. 문서를 생성하는 루틴과, 해당 PR 생성 이벤트에 의해 트리거되어 PR에 코멘트를 남기는 리뷰 루틴을 별도로 설정합니다. 인간이 보기 전에 에이전트끼리 먼저 검증합니다.
  • 웹 실시간 조향: claude.ai 웹에서 진행 중인 세션을 열어 질문하거나 방향을 전환하거나, 과거 세션을 재개할 수 있습니다.
  • 출력 검증: 문서의 경우 Claude가 변경·생성한 문서 페이지를 직접 렌더링해 기대 결과인지 확인합니다.

데모 요약

claude.ai 좌측 패널 > 코드 버튼 > Routines에서 이전에 만든 루틴을 확인할 수 있습니다. 루틴 설정 화면에는 연결된 레포 2개(소스코드, 문서), 실행 주기(매주 월요일 10시), 연결된 커넥터(GitHub, Slack)가 표시됩니다. 오른쪽에는 Claude가 초기 프롬프트를 바탕으로 자동 생성한 상세 지침이 있습니다.

세션을 클릭하면 Claude가 지침을 읽고 소스코드 레포를 조회해 최근 PR을 확인하고, 변경 로그를 비교하고, 차이를 발견해 PR을 열었음을 볼 수 있습니다.

이벤트 기반 예시에서는 문서 레포에 새 이슈를 생성하자 즉시 새 실행이 픽업됐습니다. 이슈 내용이 컨텍스트로 자동 주입됐고, 이미 같은 변경에 대한 PR이 열려 있어서 웹에서 직접 세션에 접속해 "이미 변경했어, 중단해"라고 지시하자 Claude가 세션을 멈췄습니다. 실시간 조향의 실제 예시입니다.

루틴으로 해결할 수 있는 개발자 과제들

배포 검증기: CD 파이프라인이 배포 후 웹훅에 POST → Claude가 소스코드 레포와 Datadog/Grafana에서 모니터링 데이터를 분석 → go/no-go 판단을 웹에서 확인 → 신뢰가 쌓이면 롤백 실행까지 Claude에 위임. Slack이나 Twilio로 알림도 가능.

온콜 조사기: 장애 이벤트에 반응해 자동 원인 조사.

PM 백로그 정리: 주간 스케줄로 GitHub Issues나 Slack 채널 게시물을 읽고 우선순위화하여 가장 중요한 이슈에 대해 PR을 자동 생성.

마무리

능동형 에이전트가 반응형 에이전트를 이깁니다. Claude Code를 도구에서 팀메이트로 전환하는 게 목표입니다. Enter를 기다리는 에이전트에서, 문제가 생기면 스스로 반응해 PR을 여는 에이전트로. Routines는 인프라 유지를 저희가 처리하도록 만들었습니다. 여러분은 자신의 도메인과 프로세스 전문성에 집중하면 됩니다. 오늘 바로 시작하세요. Claude Code 터미널에서 /schedule 한 줄이면 첫 루틴을 만들 수 있습니다.
