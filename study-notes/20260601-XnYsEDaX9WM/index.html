Claude Code 토큰 사용량을 90% 줄이는 방법

Claude Code 토큰 사용량을 90% 줄이는 방법

한 줄 요약

CodeGraph(코드 인덱싱), RTK(출력 압축), Caveman(응답 단축), 세션 관리 — 네 가지 무료 전략을 상황에 맞게 조합하면 토큰 사용량을 최대 90%까지 절감할 수 있다.

영상 정보

원작자 Jonny K · Bytebyteai · https://www.linkedin.com/in/jonnykvids · 업로드 2026-06-01 · 18.5분 · 전사 Whisper large-v3 (auto)

핵심 학습 포인트 (내가 배워야 할 것)

개념 왜 중요한가 한 줄
CodeGraph 코드 인덱싱 파일 일일이 grep 대신 의미 검색으로 필요한 파일만 로드 사전 인덱스로 불필요한 파일 읽기를 줄인다
RTK 출력 압축 CLI 로그는 대부분 Claude Code가 필요로 하지 않는 잡음 43개 테스트 결과를 한 줄로 압축해 토큰 낭비를 막는다
Caveman 응답 단축 긴 응답이 컨텍스트 창을 빠르게 채워 품질을 떨어뜨린다 같은 정보를 절반 분량으로 표현해 맥락 효율을 높인다
세션 관리 (/context, /clear, /model) 불필요한 컨텍스트가 매 세션마다 토큰을 낭비한다 작업 전환 시 clear, 모델 선택으로 비용·품질 균형을 맞춘다

내가 모를 만한 것 / 처음 보는 것

  • CodeGraph (npx codegraph 또는 npm install -g codegraph) — 코드베이스 전체를 의미 그래프로 인덱싱하는 CLI 오픈소스. Claude Code가 자동으로 CLI를 학습해 활용. GitHub: colbymchenry/codegraph
  • RTK — 오픈소스 CLI 프록시. 노이즈한 터미널 출력을 압축해 Claude Code에 도달하기 전에 줄여준다. GitHub: rtk-ai/rtk
  • Caveman (npm install caveman) — Claude Code 세션을 경량 출력 모드로 전환하는 스킬(skill). light / full / ultra / weigh 단계 선택 가능. GitHub: juliusbrussee/caveman
  • agentic loop (에이전틱 루프) — Claude Code가 메시지를 주고받으며 컨텍스트를 축적하는 반복 구조. 응답 품질을 이 루프의 히스토리 품질에 의존한다.
  • ByteByteGo — 화자가 소속된 기술 교육 플랫폼. 유료 라이브 코스 제공.

화자의 디테일 (놓치기 쉬운 포인트)

  1. CodeGraph 인덱싱 시 CLAUDE.md가 모듈 디렉토리에 있을 경우 의미 검색 경로로 접근하면 해당 CLAUDE.md를 건너뛸 수 있다 — 일반적인 파일 읽기 경로에서는 자동으로 상위 CLAUDE.md를 로드하지만 CodeGraph 쿼리 경로에서는 누락될 수 있다.
  2. RTK는 손실 압축(lossy compression)이다 — 디버깅 중인 서버 로그가 필요한 경우 반드시 꺼야 한다. 자가 수정(self-healing) 시나리오에서 특히 중요.
  3. Caveman은 ultra 모드로 상시 사용하되, plan mode처럼 맥락이 많이 필요한 작업에서는 비활성화할 것을 화자가 직접 권장.
  4. /context 명령으로 현재 컨텍스트를 감사(audit)할 수 있다 — CLAUDE.md가 50k 토큰을 차지하는 경우처럼 눈치채지 못하는 낭비를 발견할 수 있다.
  5. Haiku (하이쿠) 모델은 Chrome 탐색처럼 빠른 작업에 적합하고, Sonnet (소넷)은 반복 스케줄 작업에 효율적 — 고품질 계획·심층 분석은 최상위 모델 유지가 오히려 토큰 절약이 된다(품질 저하로 인한 재작업 비용 고려).
  6. plan mode 먼저 실행 후 구현에 들어가는 것을 권장 — 무작정 실행 대신 계획을 세워 불필요한 반복을 줄인다.

한눈에 보기

# 전략 핵심 효과 주요 트레이드오프
1 CodeGraph 인덱싱 코드 탐색 토큰 감소 인덱스 동기화 부담, CLAUDE.md 누락 위험
2 RTK 출력 압축 CLI 로그 토큰 대폭 감소 손실 압축 — 중요 로그 누락 가능
3 Caveman 응답 단축 응답 길이 ~50% 감소 컨텍스트 히스토리 품질 저하 위험
4 세션 관리 잡음 제거, 모델 최적화 수동 관리 필요

1. 전략 1 — CodeGraph: 코드 인덱싱

Claude Code는 기본적으로 코드베이스를 grep으로 파일을 하나씩 읽으며 탐색한다. 필요한 파일에 도달하기까지 불필요한 파일을 많이 읽는다.

CodeGraph는 전체 코드베이스를 의미 그래프(semantic graph)로 사전 인덱싱한다. Claude Code가 이 CLI를 학습해 자연어 쿼리로 필요한 파일을 직접 찾는다.

설치 및 사용:

npx codegraph init -i      # 프로젝트 초기화
codegraph status           # 인덱스 메타 확인 (노드 종류·수량 등)
codegraph query "LLM"      # 의미 검색 예시

트레이드오프: - 인덱스와 코드베이스 두 개의 진실 출처(source of truth)가 생긴다 — 동기화를 잊으면 Claude Code가 존재하지 않는 함수/파일을 있다고 확신하는 오류가 발생한다. - 모듈 내 CLAUDE.md를 탐색 경로에서 누락할 수 있다. - 결국 실제 파일은 한 번 읽어야 하므로, 탐색 토큰은 줄어도 파일 읽기 토큰은 여전히 발생한다.

2. 전략 2 — RTK: 출력 압축

터미널 로그·테스트 출력·CLI 잡음은 Claude Code에 도달하기 전에 대부분 불필요하다.

RTK는 이 출력을 압축한다. 예: 43개 테스트 통과 → 43 tests passed 한 줄. 경고 묶음 처리, 억제된 항목 수 표시.

설치:

brew install rtk    # macOS

트레이드오프: - 손실 압축이다. 중요한 로그가 사라질 수 있다. - 서버 로그 디버깅, 자가 수정(self-healing) 작업처럼 로그가 중요한 상황에서는 반드시 비활성화해야 한다. - 언제 켜고 끌지를 개발자가 판단해야 한다.

3. 전략 3 — Caveman: 응답 단축

Claude Code는 agentic loop 안에서 메시지를 주고받으며 컨텍스트를 쌓는다. 긴 응답이 쌓이면 컨텍스트 창이 빠르게 소모되고 이후 응답 품질이 떨어진다.

Caveman은 Claude Code 세션을 "짧게 말하기" 모드로 전환한다. ultra 모드에서는 동일한 정보를 약 절반 분량으로 출력한다.

설치:

npm install -g caveman    # 또는 프로젝트별 설치

모드: light / full / ultra / weigh — 세션 중 언제든 변경·제거 가능.

트레이드오프: - 메시지 히스토리 품질이 낮아지면 이후 응답 품질도 낮아진다. - plan mode처럼 풍부한 맥락이 필요한 작업에서는 비활성화할 것. - 화자 권장: ultra 상시 유지, 필요 시 해제.

4. 전략 4 — 세션 관리 (내장 명령)

Claude Code 공식 문서에서 커버하는 기본 전략들.

명령 용도
/context 현재 컨텍스트 감사 — 어떤 파일·MCP가 얼마나 토큰을 쓰는지 확인
/clear 컨텍스트 초기화 — 새 작업 시작 전 이전 세션 내용 제거
/model 모델 전환 — Haiku·Sonnet·최상위 모델 상황별 선택

모델 선택 권장: - Haiku: Chrome 탐색, 빠른 단순 작업 - Sonnet: 반복 스케줄 작업, 성공 검증된 단순 작업 - 최상위 모델: 계획(planning), 심층 분석, 복잡한 프로그래밍 — "품질 저하로 인한 재작업"이 Sonnet 절약분을 상쇄한다

추가 권장: - plan mode를 먼저 실행한 뒤 구현 시작 — 무작정 실행보다 토큰 효율적 - CLAUDE.md를 최대한 작게 유지, 인덱스 포인터 방식으로 구성 - MCP가 컨텍스트를 얼마나 차지하는지 /context로 정기 확인

안녕하세요 여러분.

이 영상에서는 Claude Code (클로드 코드) 토큰 사용량을 최대 90%까지 줄이는 네 가지 전략을 소개하겠습니다. 무료이고 바로 적용할 수 있습니다. 시각적으로 토큰 차이를 비교하는 데모도 함께 보여드립니다. 모든 전략에는 트레이드오프가 있으니 끝까지 봐주세요.

전략 1: 코드 인덱싱 (CodeGraph)

첫 번째 전략은 코드를 인덱싱하는 것입니다. 코드베이스의 그래프 맵을 만드는 개념입니다. 인덱스는 구글이 키워드를 웹사이트와 매핑하는 것과 비슷한 원리입니다.

Claude Code는 기본적으로 파일을 하나씩 grep해서 읽으며 탐색합니다. 서버 구현이나 인증 파일을 찾을 때 불필요한 파일을 많이 읽게 되고, 그게 토큰 낭비가 됩니다. 코드베이스 전체를 쿼리 가능한 그래프로 인덱싱하면 자연어로 의미 검색을 할 수 있습니다. Claude Code가 이 도구를 학습해 활용합니다.

사용 방법: codegraph라는 리포를 설치합니다.

npx codegraph init -i    # 초기화
codegraph status         # 메타 확인
codegraph query "LLM"    # 의미 검색 예시 → HTML to text, active session 등 결과 반환

Claude Code가 CLI를 학습해 직접 쿼리합니다. 수동으로 쓰는 도구가 아닙니다.

트레이드오프: - 진실 출처가 두 개 생긴다 (코드베이스 + 인덱스). 동기화를 잊으면 Claude Code가 존재하지 않는 함수가 있다고 확신하는 오류를 낸다. - 모듈 내 CLAUDE.md를 의미 검색 경로에서 누락할 수 있다. 일반 파일 읽기는 상위 CLAUDE.md를 자동 로드하지만 쿼리 경로는 그렇지 않다. - 결국 파일은 한 번 읽어야 하므로 파일 읽기 토큰은 여전히 발생한다.

전략 2: 출력 압축 (RTK)

npm run 같은 CLI 출력은 굉장히 노이즈가 많고 Claude Code에 불필요한 정보가 대부분입니다. RTK라는 오픈소스 라이브러리가 이 출력을 압축합니다. 예: 43개 테스트 통과를 일일이 나열하는 대신 43 tests passed 한 줄로. Claude Code에 도달하기 전에 토큰을 줄입니다.

설치: brew install rtk (macOS)

CLI도 MCP보다 나은 형태가 많다는 게 최근 추세입니다. Claude Code가 CLI를 잘 다루기 때문입니다.

시연: git log 원본은 정보가 넘치는데, RTK를 적용하면 몇 줄로 압축되고 몇 줄이 생략됐는지 보여줍니다.

트레이드오프: - 손실 압축이다. 중요한 로그가 사라질 수 있다. - 서버 로그 디버깅, 자가 수정 시나리오에서는 반드시 비활성화해야 한다. - 대부분의 경우는 로그 전체가 필요 없으므로 꽤 효과적인 전략이다.

전략 3: 응답 단축 (Caveman) — 개인적으로 가장 선호

Caveman은 오픈소스 라이브러리로, Claude Code가 더 짧게 말하게 만듭니다. 다이어그램에서 왼쪽이 일반 출력, 오른쪽이 Caveman ultra 적용 출력입니다.

"I waste time. Say lot word when few word do trick" — 더 적은 단어로 같은 의미를 전달하는 것이 핵심. (참고: 화자는 "Kevin"이라는 이름이 더 어울렸을 거라고 농담했습니다.)

설치:

npm install -g caveman

세션에 스킬로 적용: light / full / ultra / weigh 모드. 언제든 제거·변경 가능.

시연: "이 프로젝트에 대해 알려줘" — Caveman 없이는 긴 응답, Caveman ultra에서는 약 절반 분량. 정확도는 비슷.

화자 본인은 ultra로 상시 사용하다가 필요 시 해제합니다.

트레이드오프: - 응답이 짧아지면 컨텍스트 히스토리 품질이 낮아질 수 있다. - Claude Code의 agentic loop는 이 히스토리를 바탕으로 다음 답변을 생성하므로, 히스토리 품질 저하 → 출력 품질 저하로 이어질 수 있다. - plan mode처럼 풍부한 맥락이 필요한 작업에서는 비활성화 권장.

전략 4: 세션 관리 (내장 기능)

가장 기본적이지만 확실한 방법입니다. Claude Code 공식 문서에서 커버합니다.

  • /context: 현재 컨텍스트 확인. 무엇이 얼마나 토큰을 쓰는지 감사. CLAUDE.md가 40k 토큰을 차지하면 세션 시작마다 4%가 날아가는 것을 이걸로 발견할 수 있다.
  • /clear: 컨텍스트 초기화. 새 작업 시작 시 이전 세션 내용 제거.
  • /model: 모델 전환.
  • Haiku: Chrome 탐색 같은 빠른 작업에 적합, 대부분 경우 오히려 더 잘 동작.
  • Sonnet (소넷): 반복 스케줄 작업, 데스크톱 파일 정리 같은 단순 반복 작업에 효율적.
  • 최상위 모델: 계획(planning), 심층 분석은 최상위 유지가 오히려 토큰 절약 (재작업 방지).

추가 팁: - plan mode 먼저 실행 후 구현 시작 - 코딩 전 Figma·Pencil로 설계 후 시작 - agent team은 비용이 많이 드므로 공식 문서 advanced strategies 참고

결론: 모든 전략을 써야 하나?

화자 의견: 그렇다. 하지만 각각 트레이드오프가 있다.

  • CodeGraph: 인덱스가 낡을 수 있다
  • RTK: 손실 압축, 메시지 누락 가능
  • Caveman: 메시지 히스토리 품질 저하 가능
