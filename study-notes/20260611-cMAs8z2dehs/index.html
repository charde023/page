핵심 학습 포인트 (내가 배워야 할 것)

개념 왜 중요한가 한 줄
모델이 하네스를 먹는다 (Model eats the harness) 스캐폴딩 구축에 투자하는 전략의 유효기간이 약 12개월 지금 하네스에 올인하면 곧 모델 기본 기능이 됨
Antigravity Gemini 생태계의 새 결합조직 — 기존 Gemini API 역할을 대체 Windsurf 팀 합류로 만들어진 Google의 단일 에이전트 하네스
Jagged 초지능 (Jagged Superintelligence) AGI 이전에 수직 영역별 초지능이 들쭉날쭉하게 먼저 도달 코딩에 이어 수학·금융·과학 순으로 도달 예상
단일 Omni 모델 텍스트·오디오·음악·이미지·비디오를 8개 모델 대신 1개로 멀티모달 파이프라인 설계 패러다임의 전환
에이전트 주도 성장 (Agent-led growth) 에이전트가 인프라 선택권까지 행사 — 브랜드 노출 구조 변화 구글·아마존 등 플랫폼 선택이 인간 아닌 에이전트 손으로
코딩 = 범용 에이전트 하네스 코딩이 특수 케이스가 아니라 에이전트 일반의 증명 플랫폼 "코딩이 에이전트를 증명했고, 이제 전 영역으로 확산"
아이볼 최대화 → 아웃컴 최대화 구글의 KPI 전환 — 광고·SEO 모델에 대한 장기 함의 사용 시간이 아니라 사용자 목표 달성률로 성공 측정

내가 모를 만한 것 / 처음 보는 것

  • Antigravity: Windsurf 팀(Cursor 경쟁 IDE)이 Google에 합류하면서 탄생한 에이전트 하네스. IDE·웹·CLI·SDK를 포함하는 생태계이며, Search·Gemini 앱·Cloud·AI Studio 전반에 적용됨.
  • GDM (Google DeepMind): DeepMind와 Google Brain이 합쳐진 조직. Demis Hassabis가 노벨상 받은 AlphaFold 등을 만든 곳.
  • Gemini Flash 3.5: 포스트-트레이닝 이득만으로 이전 Pro 모델을 코딩에서 능가한 경량 모델. 플래시 모델이 프로 모델 능력치를 넘겼다는 점이 핵심.
  • Omni (Gemini Omni): 텍스트·비디오·오디오·이미지를 단일 모델로 처리. Google IO 2026에서 발표. 현재 비디오 편집 기능부터 제공.
  • GEO (Generative Engine Optimization): SEO의 AI 버전. 에이전트가 검색·쇼핑·선택을 대행하면서 부상하는 최적화 분야. 용어노트 참고.
  • Genie (Google DeepMind): 전통적 세계 모델(action-conditioned video model). Omni와 비교 맥락에서 언급됨.
  • TPU (Tensor Processing Unit): Google의 AI 전용 하드웨어. "10,000 TPU를 잘못 써버리는" 위험 때문에 대형 학습 실행은 아직 인간이 결정함.
  • Harness bench: Logan이 제안한 아직 없는 벤치마크 — 각 모델이 다양한 에이전트 하네스에 얼마나 잘 적응하는지 측정하는 개념.
  • 3js (Three.js): 브라우저에서 3D 그래픽을 구현하는 JavaScript 라이브러리. 바이브 코딩 게임 맥락에서 "모델이 아직 못하는 레이어"의 예시로 언급.
  • Game Arena: GDM이 AGI 진행 측정용으로 만든 게임 기반 벤치마크.

화자의 디테일 (놓치기 쉬운 포인트)

  1. 에이전트 하네스의 수명 예측을 "약 12개월"로 명시 — "12개월 후엔 모델이 직접 소화할 것".
  2. AI Studio에서 Android 앱 빌드 기능 출시 1주일 만에 35만 개 앱 생성됨.
  3. 당시 AI Studio 앱 생성 카테고리: 게임 20% → 이후 금융·크립토 관련 약 20%, 개인 생산성, 생성 미디어 순.
  4. Gemini 3 Flash는 포스트-트레이닝만으로 이전 Pro 모델을 코딩 성능에서 추월.
  5. Google 내부 엔지니어 10만 명 이상이 모델 피드백 플라이휠 — 이를 경쟁 우위로 명시.
  6. Josh 팀(Gemini macOS 앱)이 antigravity로 macOS 앱을 Google 역사상 가장 빠르게 출시.
  7. Gemini 2.0 때 에이전틱 기능을 "조금 이르게" 발표했고, 3.5 시대에 실제로 "진짜"가 됐다는 자기 평가.
  8. 모델 피드백 루프 상 대형 학습 실행(big pre-training run)의 타이밍이 외부에서 안 보여서 "뒤처진 것처럼" 보이는 오류가 생긴다고 언급.
  9. Logan 본인이 AI Studio에서 처음 Android 앱을 만들어봤으며 — 내용은 정원 관리(gardening) 앱.
  10. Omni 영상 편집 데모: 청중이 현장에서 실시간으로 Omni에 요청 → 강연 무대에 개가 올라온 영상으로 편집, 개가 Logan 무릎에 앉고 Logan은 계속 강연 — 세부 물리 동작(시선, 웃음)까지 문맥 정확하게 합성됨.
  11. Harness bench 개념을 Logan이 직접 제안 — 아직 공식 존재하지 않음.
  12. Google 현재 에이전틱 성숙도: "crawl" 단계, Gemini 앱과 Antigravity가 "walk"에 가장 가까움.
  13. 바이브 코딩 비디오 게임 가능 시점: 모델 품질 갭은 없고 "scaffolding 갭"이 있음 — 스프라이트 생성·게임 엔진 연결 레이어.
  14. 전통 세계 모델(action-conditioned video model) vs Omni 세계 모델 구분 — Omni는 아키텍처가 다르며 확장성 면에서 더 유리한 방향으로 진화.

2 Antigravity 하네스 Windsurf 팀 기반, Google 전 제품의 에이전트 결합조직으로 확장
3 에이전트와 카니발라이제이션 AI로 검색·광고가 잠식될 것이라는 우려와 달리 실제로는 positive-sum
4 에이전틱 성숙도 현재 Google 대부분 제품은 crawl, Gemini 앱·Antigravity가 walk 근접

12 GDM 문화 노벨상 과학자 Demis 주도의 연구 문화 + Google 12억 유저 제품 배포 경험의 독특한 결합

1. Agentic Gemini 시대와 Antigravity

Sundar Pichai가 Google IO에서 "에이전틱 Gemini 시대"를 선언했다. Logan에 따르면 Gemini 2.0 때 관련 기능을 "조금 이르게" 발표했고, 3.5 시대에 들어서야 실제로 "진짜"가 됐다.

Antigravity는 이 시대의 결합조직(through line)이다. 기존에는 Gemini 모델이 Google 50여 개 제품을 연결하는 공통 레이어였다면, 이제는 Antigravity 에이전트 하네스가 그 역할을 확장한다. Search·Gemini 앱·Cloud·AI Studio 전반이 동일 하네스 위에서 동작하게 됨.

Antigravity의 구성: 핵심 IDE + 웹 에이전트 경험 + CLI + SDK. Windsurf 팀(IDE 스타트업)이 Google에 합류하면서 만들어졌다.

2. 에이전트 = 카니발라이제이션인가

"에이전트가 내 이메일을 다 처리해주면 내가 Gmail에 접속할 이유가 없어지지 않느냐"는 질문에 Logan은 positive-sum 논리로 응답:

  • AI가 검색을 대체할 것이라는 우려가 있었지만 실제로는 검색량이 늘었다.
  • 에이전트도 검색한다 — 인간이 더 하고 에이전트도 더 하면서 전체 생태계 가치가 커짐.
  • 단기(1~2년)는 이 패턴이 지속, 장기(3~5년)는 불확실.
  • 구글의 성공 기준이 "아이볼 최대화"에서 "사용자 아웃컴 최대화"로 이동 중.

3. 에이전틱 성숙도: Crawl-Walk-Run

구글 제품 대부분은 현재 crawl 단계. 13억 명 이상이 쓰는 제품에 에이전트를 무작정 풀면 안 된다는 스튜어드십 때문.

  • Walk에 가장 가까운 것: Gemini 앱(24/7 상시 에이전트) + Antigravity(자율 코딩 에이전트, 수천 달러·수십억 토큰 규모 작업)
  • Run에 가장 가까운 것: GDM 내 실험적 에이전트(프론티어 탐색 중)
  • 장기 KPI: 에이전트 실행의 평균 작업 시간(task duration) 측정이 중요해질 것 — 현재 공개된 지표 없음

4. Gemini 코딩 경쟁력

Logan이 솔직하게 인정: "많은 개발자가 Claude와 Codex를 쓰고 Gemini 언급이 적은 건 사실".

그러나: - Gemini Flash 3.5는 포스트-트레이닝만으로 이전 Pro 모델을 코딩에서 추월 — 팀의 대형 성과. - 좋은 코딩 모델을 만들려면 코딩 제품(하네스)이 있어야 한다 — Antigravity를 만든 이유. - Google 내부 10만+ 엔지니어의 피드백 플라이휠이 경쟁 우위. - 대형 사전학습 실행(big pre-training run)의 타이밍이 외부에서 안 보이기 때문에 뒤처진 것처럼 보이는 착시가 있음. - Logan은 내부 코딩 팀을 "AI의 어벤져스"로 표현.

5. 바이브 코딩 게임: 모델 갭 vs 스캐폴딩 갭

2025년 10월 Logan의 예측: "2025년 말까지 누구나 비디오 게임을 바이브 코딩할 수 있을 것". 결과는 "거의 맞다, 하지만 AAA 게임은 아직".

핵심 분석: - 모델 품질 갭은 없다 — 이미 충분히 좋음. - 스캐폴딩 갭이 있다 — 스프라이트 생성, 게임 엔진 연결, 반복 가능한 게임 루프 구성이 미해결. - 3js 같은 레이어가 일부 해결하지만 재사용 가능한 게임 경험을 만들기 위한 오케스트레이션 레이어가 필요. - 단기 해법: 코딩 에이전트 + 게임 엔진 조합. 세계 모델 기반은 아직 시기상조. - AI Studio에서 앱 생성 카테고리: 게임 20% → 이후 금융/크립토 약 20%, 개인 생산성, 생성 미디어 순.

6. 세계 모델과 Omni

Logan의 핵심 주장: 세계 모델과 비디오 모델의 경계가 Omni로 인해 흐려지고 있다.

전통 세계 모델: action-conditioned video model (행동 조건부 비디오 모델). Genie 같은 것. 매우 고비용, 확장성 낮음.

Omni 세계 모델: "세계에 대한 이해를 가진 모델" — 기술적으로 다른 아키텍처. 실시간은 아니지만 유사 기능 수행 가능.

Omni의 구조: - 진짜 단일 모델 (여러 모델로 라우팅하는 것 아님) - 기존: 텍스트·Lyria(음악)·Nano Banana·Vo(비디오)·오디오 8개 별도 모델 - Omni: 단일 모델로 통합. 현재 비디오 편집 기능부터 공개. - Flash 기반 첫 번째 버전 — 더 강력한 버전 예정.

데모 인상: Logan이 강연 도중 청중이 실시간으로 Omni에 개를 무대에 추가 요청 → 다른 패널들의 시선, 웃음 반응, Logan 무릎에 앉는 개 등 세밀한 물리 맥락까지 정확히 합성. Logan이 "모델이 해냈다"고 표현.

7. 모델이 하네스를 먹는다

이 영상의 핵심 테제: 에이전트 하네스는 약 12개월 안에 모델 기본 기능으로 흡수된다.

역사적 패턴: - 2년 전 "모델 = 가중치 집합" → 지금은 가중치 + 툴 콜링 + 코드 실행 + 검색 + 컨테이너 실행 + 하네스 전체가 "모델"로 불림. - 스캐폴딩은 항상 모델보다 몇 단계 앞서가다가, 결국 모델이 그것을 흡수. - 검색 같은 일부 케이스는 외부 스캐폴딩이 남아있을 수 있음(다양한 공급업체 지원 필요 등).

스타트업 관점: - "내 하네스 = 공급업체 종속 방지" 논리는 모델 품질이 높아지면 설득력 감소. - Logan이 제안한 Harness bench: 각 모델이 다양한 하네스를 얼마나 잘 쓰는지 측정하는 벤치마크 — 아직 미존재. - 스타트업 알파의 이동: 하네스 구축 → 수직 도메인 전문성 + 포커스.

8. GDM 문화와 Jagged 초지능

GDM 문화 세 가지 관찰: 1. 포트폴리오 폭이 넓다 — 어떤 영역에서 뒤처지면 집중해서 따라잡는 방식. 집중력이 유지되기 어렵지만, 따라잡는 방식이 원래 딥마인드 문화와 일치. 2. 리더의 문화 DNA: Demis(노벨상 과학자) → 과학적 접근 문화 / Sam Altman → 비즈니스 문화 / Dario(Anthropic) → 다소 esoteric한 분위기. 3. 엔진룸 역할: 연구 조직이면서 동시에 10억+ 유저 제품 배포 경험. "이걸 동시에 할 수 있는 회사는 전 세계에 두 곳뿐".

Jagged 초지능: AGI 이전에 코딩·수학·금융·과학처럼 검증 가능성이 높은 영역에서 먼저 초지능 도달. "들쭉날쭉하게(jagged)" 펼쳐질 것. 코딩이 이미 그 경계에 있다고 Logan은 평가.

Logan의 개인 경험: "예전엔 아이디어가 손에 닿지 않았다. 지금은 반대로 더 야심차게 생각하게 된다 — 코딩 에이전트가 가능하게 해주니까."

소냐: 이 세트를 편집해서 다르게 보이게 할 수 있을까요? 로건: 네, 그렇죠, 저도 그게 좋겠어요. 카메라 밖에서 얘기하던 것처럼, 인트로에 그 방식을 써야 할 것 같아요. 이런 것들이 훨씬 더 강력해지는 거잖아요. 저는 이런 예시들을 봐왔는데, 너무 미묘한 뉘앙스들이 있어서 이게 진짜 세계를 이해하고 있구나 싶었어요.

강연을 하고 있었는데, 모델팀을 이끄는 제 친구 Tulsi와 무대에 함께 있었어요. 청중 중 한 명에게 영상을 편집해달라고 했더니, 그 사람이 Omni로 실시간으로 사진을 편집했어요. 그랬더니 개가 무대에 올라온 버전의 영상이 나왔어요. 편집된 버전에서 다른 패널들이 개를 내려다보고 슬쩍 웃는데, 저는 뭔가를 열심히 떠들고 있었어요. (웃음) 제 농담 때문이 아니라 개 때문이었죠. 개가 제 무릎에 올라왔고, 저는 개를 인식하면서도 계속 얘기하면서 쓰다듬고 있었어요. 그 미묘함을 이렇게 정확하게 표현한다는 게 정말 대단하고, 모델이 완벽하게 해냈어요.

[Logan 소개]

소냐: Google AI Studio와 Gemini API를 이끄는 Logan을 모시게 돼서 정말 기쁩니다. 다음 세대 개발자들을 위해 생각하고 구축하는 데 많은 시간을 쓰시죠. 에이전틱 AI부터 AI 코딩, 세계 모델까지 많은 것을 이야기 나눠보겠습니다.

[에이전틱 Gemini 시대]

소냐: Sundar가 IO를 열면서 "에이전틱 Gemini 시대"라고 했는데, 구글에서 에이전틱 AI란 무엇인가요?

Logan: 좋은 질문이에요. Gemini 2.0 때 이런 것들을 일부 언급했는데, 그게 조금 이른 시기였어요. Gemini 3.5 시대가 이제 진짜로 실현되고 있는 것 같아요. 에이전틱 코딩, 에이전틱 제품, 모든 게 에이전트 중심의 시대가 됐어요.

Gemini 관점에서 이 에이전틱 레이어는 사실 IO에서 발표했는데, Antigravity 에이전트 하네스가 Google 전체를 연결하는 새로운 결합조직이 됐어요. 예전에 Gemini 이전에는 50개에 달하는 Google 제품들을 연결하는 공통 스레드가 없었어요. Gemini가 그 역할을 했고, 이제는 Antigravity가 모든 제품을 에이전트 네이티브로 만드는 역할을 하고 있어요.

소냐: Antigravity가 정확히 뭔가요?

Logan: Antigravity는 여러 가지예요. 핵심 IDE도 있고, 웹에서 에이전트 우선 경험도 있고, CLI도 있고, SDK도 있어요. 개발자가 어디에 있든 만날 수 있도록 설계된 에코시스템이에요. Gemini API를 통해서 쓸 수도 있고요. 그리고 중요한 건, Antigravity가 그냥 Antigravity 제품 생태계가 아니라 실제로 Search, Gemini 앱, Cloud, AI Studio 등 다른 Google 제품들에도 동일한 하네스가 적용되고 있어요.

[카니발라이제이션 vs 긍정합]

소냐: 에이전트 기능을 강화할수록 예를 들어 이메일을 에이전트가 처리해버리면 사용자가 Gmail에 접속할 이유가 없어지지 않나요?

Logan: 흥미로운 관점이에요. 초기 AI 시대에 모든 사람이 AI가 질문에 답해주면 검색에 부정적일 거라고 했는데, 실제론 검색이 훨씬 더 늘었어요. 에이전트도 검색하니까요. 인간이 더 많이 하고 에이전트도 더 많이 하면서 생태계 가치가 전반적으로 커지고 있어요. 1~2년 후는 어느 정도 보이는데, 3~5년 후는 기술이 발전하면서 제품이 많이 달라질 거라 불확실해요. 궁극적으로 구글의 성공은 아이볼 시간 최대화가 아니라 사용자가 원하는 결과를 얻도록 돕는 것이 될 거예요.

소냐: "에이전트 주도 성장(agent-led growth)"이라는 개념이 있는데, 코딩 에이전트를 쓰면서 에이전트가 인프라 선택을 다 해주잖아요. 광고와 가치 포착이 어떻게 바뀔 것 같나요?

Logan: SEO가 GEO(Generative Engine Optimization)와 직결된다는 느낌이 있어요. 기존 SEO와 유사한 방식으로 진행될 것 같고, 예상보다 급격한 변화는 아닐 것 같아요.

[에이전틱 성숙도 - 기기, 걷기, 달리기]

소냐: Google 제품의 에이전틱 수준을 Crawl-Walk-Run으로 평가하면?

Logan: 지금은 확실히 Crawl이에요. 13억 명 이상이 쓰는 제품이 있어서 그냥 에이전트를 풀기가 어렵죠. 사람들이 아직 AI가 모든 걸 자율적으로 하는 건 원하지 않아요. 핸들을 본인이 잡고 싶어하죠.

Walk에 가장 가까운 건 Gemini 앱이에요. 24/7 상시 에이전트가 여러 액션을 대신 해주는 거거든요. Antigravity도 비슷하게, 자율 코딩 에이전트가 운영 체제를 재구축하거나 수천 달러를 쓰면서 수십억 토큰을 소비하는 규모의 작업을 할 수 있어요. 하지만 대부분의 Google 제품은 아직 Crawl이고, 이게 자연스러운 일이라고 생각해요.

[Gemini 코딩 경쟁력]

소냐: 솔직히 말해서, 제 개발자 친구들은 Claude와 Codex를 많이 쓰는데 Gemini는 별로 언급이 없어요.

Logan: 맞아요. 작년 12월에 Gemini 3가 나왔을 때 "Google이 이겼다"는 분위기였는데, 그 다음 에이전틱 코딩 혁명이 연휴 기간에 일어나면서 내러티브가 바뀌었어요. 이건 아주 최근 일이에요.

뒤에서 일어나고 있는 일은, 코딩 분야에서 최대한 빠르게 프론티어를 밀어붙이는 거예요. Antigravity가 중요한 이유가 여기 있어요. 오래 실행되는 코딩 태스크를 잘 하려면 그런 제품이 없으면 안 돼요. Windsurf와의 딜이 그래서 일어난 거고, 그 팀이 Antigravity를 만든 거예요.

Gemini Flash 3.5는 이전 Pro 모델보다 코딩에서 더 낫고, 포스트-트레이닝만으로 그렇게 됐어요. 사전학습 위에 엄청난 추가 작업 없이 이룬 성과라 팀이 대단한 거예요. 그리고 사전학습 대형 실행(big run) 타이밍이 외부에서 안 보여서 "뒤처진 것처럼" 보이는 착시도 있어요.

[코딩 에이전트 내부 문화]

소냐: 내부에서 다른 모델도 사용하나요?

Logan: 모든 모델을 써봐야 해요. 생태계를 이해하려면요. 하지만 주력은 Gemini고, 구글 전체 10만+ 엔지니어가 Gemini 피드백을 주는 플라이휠은 경쟁 우위예요. AB 테스트, 실험, 규모 있는 피드백을 할 수 있는 곳이 거의 없잖아요.

[코딩 에이전트 = 가속기]

소냐: "충분히 좋은 에이전틱 코딩 모델이 나오면 연구 속도가 자기강화적으로 가속된다"는 이야기에 동의하나요?

Logan: 어느 정도 징조는 보여요. 모델 관점에서는 대형 학습 실행 자원 배분에 아직 인간이 필요하죠 — 10,000 TPU를 잘못 쓰면 큰일이니까요. 하지만 제품 관점에서는 확실히 보여요. Gemini macOS 앱을 Google 역사상 가장 빠르게 출시했어요. Antigravity 덕분에요.

소냐: "시스템이 코드로 뭐든 만들 수 있다면 인간이 경쟁할 수 없다 — 이게 좁은 초지능"이라고 한 적 있죠. 이미 그 단계인가요?

Logan: 코딩에선 그런 느낌이 들어요. 세부적으로 어떻게 정량화하느냐에 달렸지만. 중요한 건 AGI 이야기가 현재의 실질적인 영향력을 가리면 안 된다는 거예요. 코딩에서 이미 이렇게 임팩트가 있는데, 그 사실을 제대로 인식해야 해요.

개인적으로는 예전엔 아이디어가 살짝 손에 닿지 않았는데, 지금은 반대로 더 야심차게 생각하게 돼요. 기술이 가능하게 해주니까. "그냥 MVP 만들면 안 되겠다, 10단계 더 나아가야겠다"는 생각이 드는 거죠.

다음으로 초지능 도달할 수직 분야는? 검증 가능성이 높은 곳이 먼저 될 거예요 — 수학, 금융, 과학. 특히 과학이 흥미롭고, 수학 증명에서 이미 많은 일이 일어나고 있어요. 저는 이걸 "Jagged 초지능"이라고 불러요 — AGI 이전에 수직 영역별로 들쭉날쭉하게 도달할 거예요.

[바이브 코딩 게임]

소냐: "2025년 말까지 누구나 비디오 게임을 바이브 코딩할 수 있을 것"이라고 했는데, 맞았나요?

Logan: 거의요. 물론 AAA 게임은 아니지만. 흥미로운 건 비디오 게임을 만들려면 다른 것들도 많이 필요하다는 거예요 — 3js가 많은 것을 가능하게 해주는데, 스프라이트 생성 같은 건 여전히 안 되거든요. 그리고 반복 재생 가능한 게임 경험을 만들려면 신뢰성 높은 오케스트레이션이 필요해요.

AI Studio 초기 데이터 보면 앱 생성 중 게임이 20%였어요. 지금은 금융/크립토 관련이 약 20%로 1위, 개인 생산성, 생성 미디어 순이에요.

소냐: 바이브 코딩 게임이 게임 엔진+코딩 에이전트 방식으로 갈까요, 세계 모델 방식으로 갈까요?

Logan: 장기적으로는 세계 모델과 코딩 에이전트의 경계가 흐려질 거예요. 하지만 단기적으로는 코딩 에이전트 + 게임 엔진 조합에서 훨씬 더 많은 알파가 나올 거예요.

[세계 모델과 Omni]

소냐: 세계 모델의 정의가 모호하다고 했는데 설명해주세요.

Logan: Omni가 좋은 예예요. IO에서 발표했는데, 어떤 입력이든 받고 어떤 출력이든 만들 수 있어요. Demis가 "세계 모델"이라고 불렀는데, 전통적인 action-conditioned 비디오 모델과 아키텍처가 달라요. Genie 같은 전통 세계 모델은 매우 비싸고 확장성이 낮았는데, Omni는 다른 방식으로 접근해요. "세계 이해"를 갖추면서도 세계 모델 같은 기능을 많이 할 수 있어요.

Omni의 기술: 단일 모델이에요. 이전엔 텍스트 모델, Lyria(음악), Nano Banana, Vo(비디오), 오디오 모델 등을 별도로 학습시켰는데, 이제 단일 모델이 다 해요. 라우팅 방식이 아닌 진짜 단일 모델. 현재는 비디오 편집 기능이 가장 잘 되어서 그것부터 공개. 이건 첫 번째 Omni Flash 버전이고, 더 강력한 버전이 나올 예정.

[진정성 있는 생성 미디어]

Logan: 저는 개인적으로 제가 만드는 콘텐츠에 AI를 안 써왔어요. 항상 제 말, 제 목소리, 제 얼굴. 진정성에 알파가 있다고 생각해서요. Omni가 좋은 건 저를 바꾸는 게 아니라 "저"가 아닌 주변 비트들을 바꾼다는 거예요 — 세트, 배경, 커피 테이블 같은 것들. 원본 사람, 원본 콘텐츠는 그대로이고 주변만 바뀌는 것. 이게 제가 원하는 생성 미디어의 방향이에요. AI 아바타나 AI 생성 콘텐츠가 아니라.

[Android 바이브 코딩]

소냐: AI Studio에서 Android 앱 바이브 코딩 기능을 출시했는데 어떻게 되고 있나요?

Logan: 정말 신나요. AI Studio의 핵심 원칙이 개발자가 다양한 Google 생태계와 여러 UI를 통하지 않고 AI Studio를 통해 만날 수 있게 하는 거예요. Android가 그 예시고, 기존에 Android 앱을 만들 생각도 못 했던 사람들에게 문을 열어주고 있어요. 저도 AI Studio에서 처음으로 Android 앱을 만들었어요 — 정원 관리 앱이었는데요.

출시 1주일 만에 35만 개 앱이 만들어졌어요. 이 앱들의 많은 부분이 개인 문제 해결용이에요. "일반 소비자용 앱"이 아니라 "자신만의 문제 해결 소프트웨어"를 만드는 경우가 많아요. 네이티브 폰 기능을 열어준다는 것도 중요하고요. Android가 점점 빌더들의 플랫폼이 되고 있어요.

[모델이 하네스를 먹는다]

소냐: 모델이 스캐폴딩을 먹는다는 이야기를 해주세요.

Logan: 2년 전에 "모델"은 가중치 집합이었어요. 토큰 넣고 토큰 받고. 지금은 여전히 Gemini 3.5라고 부르지만, 실제론 툴 콜링, 코드 실행, 검색, 에이전트 하네스, 컨테이너 실행 등 방대한 시스템 전체가 "모델"로 불려요.

스캐폴딩은 항상 모델보다 몇 단계 앞서가다가 결국 모델이 그것을 흡수해요. 지금 에이전트 하네스가 딱 그런 위치에 있고, 저는 약 12개월 안에 모델이 직접 소화할 것이라고 예측해요.

소냐: 스타트업들이 공급업체 종속 방지를 위해 자체 하네스를 만드는데요?

Logan: 처음에는 맞는 말인데, 모델 품질이 높아지면서 점점 덜 중요해질 거예요. 저는 "Harness bench"라는 게 있어야 한다고 생각해요 — 각 모델이 다양한 하네스에 얼마나 잘 적응하는지 측정하는 벤치마크. 아직 없지만 필요해요.

스타트업 관점에서는, 어디서나 기회가 엄청나게 많아요. 한편으론 모델이 더 많이 하고 있고, 다른 한편으론 수직 도메인에서 전문성을 가진 스타트업은 대형 모델 랩도 따라잡기 힘들어요. 포커스가 스타트업의 초능력이에요. Google 같은 큰 회사는 집중할 수가 없어요. 스타트업은 할 수 있고요.

[GDM 문화]

소냐: GDM 내부에서 일하는 게 어떤 느낌인가요?

Logan: 정말 대단한 순간이에요. GDM 문화 세 가지를 말하자면:

첫째, 포트폴리오가 넓어요. 많은 걸 하다 보니 어떤 영역에서 집중이 덜 됐다가 따라잡는 일이 반복돼요. 그런데 따라잡는 방식이 딥마인드 원래 문화와 닮아있어요 — 스마트한 사람들 모아서 문제 해결하는 거죠. Demis의 다큐멘터리를 몇 번 봤는데 옛날 문화가 지금도 살아있어요.

둘째, 리더의 DNA: Demis는 노벨상 과학자 — 과학적 접근의 문화. Sam Altman은 세계 최고 사업가 중 하나 — OpenAI의 상업적 문화. Dario(Anthropic)는 다소 esoteric한 분위기. 구글 딥마인드는 과학적 접근 문화가 강해요. "왜 이걸 하는가"의 답이 질병 해결, 인류 문제 해결이에요.

Gavin Belson 명언 ("우리가 다른 사람들보다 더 세상을 좋게 만들 수 없어"): 실리콘밸리에서 제가 가장 좋아하는 인용구예요. 다들 누가 더 세상을 좋게 만드느냐 싸우는 거잖아요. 그렇게 생각하면 좀 우습죠.

셋째, GDM은 Google의 엔진룸이에요. 연구 조직이면서 동시에 13개 10억+ 유저 제품에 Gemini를 배포하는 경험을 갖고 있어요. 이걸 동시에 할 수 있는 회사는 전 세계에 두 곳뿐이에요. 안드로이드, Cloud, Gmail, Workspace 등 전반에 걸쳐 협력하면서 정말 많은 것들이 일어나고 있어요.
