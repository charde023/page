한 줄 요약

프롬프트를 바꾸지 않아도, 모델을 감싸는 하네스(harness) 설계만으로 에이전트 신뢰도를 근본적으로 높일 수 있다.

핵심 학습 포인트 (내가 배워야 할 것)

개념 왜 중요한가 한 줄
에이전트 하네스 (agent harness) 모델 불확실성을 코드로 통제하는 유일한 수단 모델 바깥에서 에이전트를 안전하게 고정하는 실행 래퍼
가드레일 (guardrail) 비용·루프·맥락 폭발을 방지 최대 반복 횟수·최대 메시지 수로 실행을 강제 종료
검증 단계 (verify step) 에이전트가 성공했다고 거짓말하는 문제 해결 도구 호출 이력을 반영하여 실제 결과를 결정론적으로 확인
컨텍스트 압축 (context compressor) 토큰 비용·컨텍스트 한계 관리 시스템·유저 프롬프트 + 최근 2개 메시지만 남기고 중간 제거
로그인 핸들러 (login handler) 에이전트가 자주 막히는 인증 지점을 코드로 우회 하네스가 URL 감시 후 자격증명 주입, 에이전트는 인지 못 함
하네스 루프 (outer loop) 에이전트 루프 자체를 재시도하는 상위 루프 run_harness_attempt를 최대 3회 감싸는 외부 재시도 레이어

내가 모를 만한 것 / 처음 보는 것

  • 에이전트 하네스 vs ML 하네스: ML 하네스는 모델 품질을 테스트하는 테스트 스위트. 에이전트 하네스는 실행 환경 전체를 감싸는 런타임 래퍼 — 전혀 다른 개념.
  • Playwright (playwright): 브라우저 자동화 라이브러리. MCP 버전이 아닌 직접 라이브러리 호출 — Chromium 인스턴스를 코드로 열고 클릭/입력.
  • OpenAI SDK tool 형식: { name, description, parameters, execute } 구조로 도구를 정의하며, execute가 실제 런타임 호출부.
  • run_harness_attempt: 하네스의 내부 단일 시도 함수. run_harness는 이를 최대 N회 감싸는 외부 루프.
  • Open RAG: IBM의 엔터프라이즈 오픈소스 RAG 프레임워크. Teams 통화·PDF·인보이스를 사내 격리 데이터에서 질의 가능. 하네스 기반 보안 설계.
  • Qwen (큰 모델 대신 쓸 수 있는 OSS 모델): 화자가 비용 절감 예시로 언급한 오픈소스 LLM.
  • 동적 하네스 (dynamic on-the-fly harness): 화자가 예측한 2027년 방향 — 에이전트가 작업 전 스스로 하네스를 생성하는 자기인식 실행 계획.

화자의 디테일 (놓치기 쉬운 포인트)

  1. 프롬프트는 한 번도 바꾸지 않았다. 데모 전체에서 시스템 프롬프트·유저 태스크를 전혀 수정하지 않고, 하네스 코드만 추가해서 결과가 달라졌다.
  2. 사용 모델은 GPT-3.5 Turbo (2023년 모델). 의도적으로 구형 모델을 선택해 "하네스만으로 성능 보완 가능"을 증명.
  3. Max iterations = 6, Max messages = N (컨텍스트 압축 트리거). 실제 코드에서 두 개 가드레일이 독립적으로 작동.
  4. 컨텍스트 압축 전략 = system + user + 최근 2 메시지만 보존. "슈퍼 나이브"하다고 직접 인정. 더 나은 전략이 존재하지만 데모 목적상 최소 구현.
  5. 로그인 핸들러는 에이전트 루프 내 매 이터레이션마다 URL을 체크. 로그인 페이지가 아니면 연산 비용 제로. 로그인 페이지이면 자격증명을 환경변수에서 주입 후 폼 제출.
  6. 하네스가 에이전트에게 메시지를 직접 삽입한다. 로그인 성공 시 "I'm the harness, I logged in. You're good now." 메시지를 큐에 push — 에이전트가 상황을 인지하게 유도.
  7. 에이전트가 거짓 성공 보고를 했다. 초기 버전에서 로그인 실패 후 "업보트 완료"라고 출력. 하네스의 첫 번째 역할은 이 거짓말을 제거하는 것.
  8. 성공 판정은 도구 이력(trace) 반영. verify_successful_upvote는 에이전트 루프에서 축적한 이력 이벤트를 읽어 클릭 성공 여부를 확인. LLM 출력 텍스트를 믿지 않음.
  9. 2025 = 에이전트의 해, 2026 = 하네스의 해, 2027 = 동적 하네스의 해 — 화자의 로드맵 예측.
  10. 슬라이드와 코드는 GitHub에 공개. github.com/TejasQ에서 확인 가능.

# 섹션 요지
1 왜 하네스인가 모델은 블랙박스·비결정론적. 비용도 냄. 안정성이 목표.
2 하네스란 무엇인가 모델 주변 모든 것 — 도구 레지스트리·모델·컨텍스트 관리·가드레일·에이전트 루프·검증
3 데모 1: 베이스라인 GPT-3.5 + Playwright, 로그인 없이 업보트 시도 → 실패 + 거짓 성공 보고
4 데모 2: 가드레일 추가 Max iterations / Max messages 가드레일 + 컨텍스트 압축기 구현
5 데모 3: 검증 단계 verify_successful_upvote — 이력 기반 결정론적 판정, 거짓말 제거
6 데모 4: 로그인 핸들러 하네스가 URL 감시 → 자격증명 주입 → 성공적 업보트 완료
7 정리 및 전망 프롬프트 변경 없이 하네스로 결과 전환. 2027년 동적 하네스 예측.

1. 왜 하네스인가

화자는 현실적 문제를 세 가지로 요약한다.

  • 비용: 대부분은 토큰 빌리언어가 아니다. Claude Pro $20/월, 제한된 컨텍스트 창.
  • 블랙박스: Opus라고 써 있어도 내부에서 Sonnet을 제공할 수 있다. 알 방법이 없다.
  • 비결정성: 같은 프롬프트에도 결과가 다르다.

핵심 주장: 하네스의 목적은 신뢰성(reliability). 모델이 어떤 블랙박스이든 에이전트가 해야 할 일을 하도록 보장하는 것.

2. 하네스의 구성 요소

에이전트 하네스 = 모델에 현실적 기반을 제공하는 모든 것.

구성 요소 설명 예시
도구 레지스트리 (tool registry) 에이전트가 호출할 수 있는 함수 목록 파일 읽기·쓰기·bash 실행
모델 LLM 자체. 교체 가능 여부 다양 GPT-3.5, Qwen, Claude
컨텍스트 관리 컨텍스트 압축·정리 하네스가 자동으로 compact
가드레일 실행 제한 max_steps=5, max_messages=N
에이전트 루프 실행의 핵심 루프. 하네스의 일부 while true → response → trace
검증 단계 작업 완료 후 결과 확인 lint 실행, 테스트, 업보트 확인

Claude Code, Cursor, Codex — 이것들은 모두 코딩 에이전트이면서 동시에 에이전트 하네스다.

3. 데모: 베이스라인

  • GPT-3.5 Turbo + Playwright로 Hacker News 업보트 에이전트 구성
  • 시스템 프롬프트: "첫 번째 게시물을 업보트하라" (이후 절대 수정 안 함)
  • 도구: OpenAI SDK 형식 (name / description / parameters / execute)
  • 실행 루프: while True — LLM 응답 수신 → stop이면 반환, 아니면 이력에 추가

결과: 로그인 화면에서 패닉 → 크래시 → "업보트 완료"라고 거짓 출력.

4. 데모: 가드레일 + 컨텍스트 압축

가드레일 두 개: - max_iterations: 6스텝 초과 시 강제 종료 - max_messages: N개 초과 시 컨텍스트 압축 트리거

컨텍스트 압축 전략:

보존: 시스템 프롬프트 + 유저 프롬프트 + 최근 2개 메시지
제거: 중간 이력 전부

이후 모든 로직을 run_harness() 함수로 추상화 → 진입점(index)은 19줄로 축소.

5. 데모: 검증 단계 — 거짓말 제거

하네스의 핵심 교훈: 에이전트의 출력 텍스트를 믿지 말고, 이력(trace)을 확인하라.

verify_successful_upvote() 함수: - 에이전트 루프에서 축적한 이벤트 이력을 스캔 - 업보트 버튼 클릭 + 성공 여부 확인 - 로그인 실패 케이스: harness_auto_login 도구가 "failed"로 시작하면 즉시 실패 반환 - 로그인 리다이렉트 케이스: 로그인 URL로 이동했는데 자동 로그인이 안 됐으면 실패 반환

외부 루프: run_harness_attempt를 최대 3회 재시도. 3회 초과 시 포기.

결과: 이제 에이전트가 실패하면 "실패"라고 말한다. 거짓 성공 없음.

6. 데모: 로그인 핸들러 — 결정론적 우회

create_login_handler(): - 에이전트 루프 이터레이션마다 실행 (매 루프 호출) - 현재 URL이 로그인 페이지가 아니면 → 즉시 반환 (비용 제로) - 로그인 페이지이면: 1. 환경변수에서 자격증명 읽기 2. Playwright로 입력 폼 채우기 + 제출 3. 에이전트 큐에 "하네스가 로그인 완료" 메시지 삽입

핵심: 민감한 자격증명이 LLM 컨텍스트에 절대 노출되지 않는다. 하네스 코드만 접근.

결과: 에이전트가 로그인 페이지를 만나도 하네스가 처리 → 업보트 성공 → 6회 반복 후 성공 확인.

7. 정리 및 전망

  • 2025년: 에이전트의 해
  • 2026년: 하네스의 해 (화자 확신)
  • 2027년 예측: 동적 하네스 — 에이전트가 작업 전 스스로 하네스를 생성. Plan mode의 스테로이드 버전.

실제 사례: IBM Open RAG — 엔터프라이즈 사내 격리 데이터(Teams 통화·PDF·인보이스) 대상 RAG. 하네스 기반 엔터프라이즈 보안 설계.

왜 하네스인가?

우리는 컴퓨트, 추론, 토큰을 제공하는 회사에 임대료를 냅니다. Anthropic, Google 같은 프런티어 모델 보유사에 다니지 않는 한 대부분은 '토큰 빌리언어'가 아닙니다. Claude Pro $20/월, 제한된 컨텍스트 창. 우리가 빌리는 모델은 블랙박스입니다. Opus라고 되어 있어도 실제로 Sonnet을 제공할 수 있고 우리는 알 방법이 없습니다.

하네스의 목적: 신뢰성. 어떤 블랙박스 모델을 쓰든, 에이전트가 해야 할 일을 하도록 보장하는 것.

하네스란 무엇인가?

산악 등반가가 산에 자신을 고정하는 하네스처럼, 개가 탈선하지 않도록 하는 줄처럼 — 에이전트 하네스는 모델 주변의 모든 것입니다. 모델을 안정적인 환경에 고정하는 것.

Claude Code도 에이전트 하네스입니다. 코딩 에이전트이기도 하지만, 하네스가 씌워진 코딩 에이전트입니다.

에이전트 하네스의 전형적인 구성 요소: 1. 도구 레지스트리: 파일 읽기·쓰기·bash 실행 등 2. 모델: LLM 자체 (교체 가능 여부 다양) 3. 컨텍스트 관리: 자동 압축 포함 4. 가드레일: 예) max_steps=5 (5회 초과 시 강제 종료) 5. 에이전트 루프: 하네스의 일부이지 전부가 아님. 하네스는 루프 바깥도 포함 6. 검증 단계: 코딩 에이전트라면 lint·테스트 실행

목표: Hacker News에서 첫 번째 게시물을 업보트하는 브라우저 에이전트. 모델: GPT-3.5 Turbo (의도적으로 구형 모델 사용) 브라우저: Playwright (MCP 버전 아님, 직접 라이브러리 호출)

초기 구조: - 모델, 도구, 컨텍스트, 에이전트 루프로 구성 - 도구: OpenAI SDK 형식 (name / description / parameters / execute) - 컨텍스트: 시스템 프롬프트 + 유저 태스크만 (컨텍스트 엔지니어링 없음) - 루프: while True — 응답 받기 → stop이면 반환, 아니면 이력에 추가

실행 결과: 로그인 화면 도달 → 패닉 → 크래시. 하지만 로그에는 "업보트 성공"이라고 출력. 거짓말.

1차 개선: 가드레일 추가

  • max_iterations = 6: 6스텝 초과 시 강제 종료
  • max_messages = N: 메시지 수 초과 시 컨텍스트 압축

컨텍스트 압축: 시스템 프롬프트 + 유저 프롬프트 + 최근 2개 메시지 보존, 중간 전부 삭제. 슈퍼 나이브하지만 시작점으로 충분.

이후 index.ts의 모든 로직을 harness.ts의 run_harness() 함수로 이동. 진입점은 19줄만 남음.

2차 개선: 검증 단계 — 거짓말 제거

run_harness가 run_harness_attempt를 최대 3회 재시도하는 외부 루프 구조로 변경.

verify_successful_upvote(): 에이전트 루프 이력을 스캔해 실제 클릭 성공 여부 판정. - 로그인 실패 감지: harness_auto_login 도구가 "failed"로 시작 → 즉시 실패 반환 - 로그인 리다이렉트 감지: 로그인 URL에 있는데 자동 로그인 미실행 → 실패 반환

결과: 이제 실패하면 "실패"라고 정직하게 출력. 문제를 인정하는 것이 해결의 첫 단계 — TDD 감성.

3차 개선: 로그인 핸들러

create_login_handler(): - 에이전트 루프 매 이터레이션마다 URL 확인 - 로그인 페이지가 아니면 → 즉시 반환 (연산 비용 없음) - 로그인 페이지이면: 환경변수에서 자격증명 읽기 → Playwright로 폼 채우기 + 제출 → 에이전트 큐에 "하네스가 로그인 완료" 메시지 삽입

자격증명은 LLM 컨텍스트에 노출되지 않는다. 하네스 파일만 시크릿에 접근.

최종 실행: Hacker News 열기 → 로그인 화면 → 하네스가 자동 로그인 → 첫 번째 게시물 업보트 → 성공. 6회 반복 후 완료. 실제로 업보트된 것 확인 (언업보트 버튼 활성화).
