1. Parallel이 만드는 것

Parallel은 AI 에이전트(Agent)가 웹을 검색(Search)하고 사용(Use)할 수 있도록 돕는 기술을 만들고 있다.

여기서 중요한 점은 단순히 “AI가 구글 검색을 한다” 수준이 아니다. 사람은 브라우저(Browser)를 열고, 검색어를 입력하고, 링크를 클릭하고, 여러 페이지를 돌아다니며 정보를 얻는다. 화자는 에이전트도 이와 비슷하게 웹에서 정보를 찾고 활용할 수 있어야 한다고 본다.

즉, 앞으로의 에이전트는 내부 지식만으로 답하는 챗봇이 아니라, 웹이라는 외부 정보 공간을 직접 탐색하는 작업자가 된다.

2. 인간이 웹을 쓰는 방식과 에이전트의 방식

화자는 인간이 지금까지 웹을 사용하는 법을 익혀왔다고 말한다.

사람은 검색엔진(Search Engine)을 쓰고, 브라우저에서 클릭하고, 페이지를 이동하면서 원하는 정보를 찾는다. 하지만 에이전트가 이 작업을 하려면 사람용 화면을 그대로 흉내 내는 것만으로는 부족할 수 있다.

사람은 느리게 읽고 판단하지만, 에이전트는 동시에 여러 검색을 수행하고, 반복적으로 비교하고, 더 많은 페이지를 빠르게 확인할 수 있다. 그래서 에이전트에게 맞는 검색 인프라가 필요해진다.

3. Parallel의 핵심 가설: 에이전트는 웹을 1,000배 더 많이 쓴다

Parallel은 에이전트가 인간보다 웹을 1,000배 더 많이 사용할 것이라는 베팅에서 출발했다.

이 말은 단순한 과장이 아니라, 웹 사용의 단위가 바뀐다는 뜻이다. 사람 한 명은 상품 비교를 몇 번 검색하고 끝내지만, 에이전트는 가격, 재고, 리뷰, 배송 조건, 경쟁사 정보, 정책 변경 등을 계속 확인할 수 있다.

예를 들어 이커머스 관점에서는 다음과 같은 일이 가능해진다.

  • 경쟁사 가격을 주기적으로 확인
  • 공급사 재고와 납기를 자동 조회
  • 고객 리뷰와 문의를 요약
  • 상품 상세페이지의 오류를 탐지
  • 배송 지연 이슈를 외부 정보와 함께 확인

이런 작업이 자동화되면 웹 검색량은 사람이 직접 하던 때보다 폭발적으로 늘어날 수 있다.

4. 기술과 사업 모델을 함께 다시 만들어야 한다

화자는 에이전트 시대에는 검색을 구동하는 기술뿐 아니라, 그 옆에 붙는 사업 모델(Business Model)도 새로 만들어야 한다고 말한다.

기존 웹의 사업 모델은 대체로 사람의 클릭, 광고 노출, 페이지뷰(Page View)에 맞춰져 있다. 하지만 에이전트가 웹을 사용하면 사람이 광고를 보는 구조가 약해질 수 있다. 대신 다음과 같은 모델이 중요해질 가능성이 있다.

  • API 기반 정보 제공
  • 사용량 기반 과금
  • 신뢰도 높은 데이터 접근권
  • 에이전트 전용 검색 인프라
  • 기업용 대량 검색 계약

결국 Parallel이 보는 기회는 “검색창을 하나 더 만드는 것”이 아니라, 에이전트가 웹을 대규모로 사용하는 시대의 기반 기술과 수익 구조를 만드는 것이다.

에이폼 적용 관점

① 이 얘기가 이커머스·물류 운영에 꽂히는 지점: 에이전트가 가격, 재고, 배송, 리뷰, 경쟁사 정보를 사람보다 훨씬 자주 확인하게 되면 운영 의사결정 속도가 빨라질 수 있다.

③ 우리 상황과 다른 전제 하나: 영상은 에이전트용 웹 인프라 회사를 전제로 하지만, 에이폼은 당장 인프라를 만들기보다 기존 도구와 API를 조합해 운영 자동화부터 검증하는 편이 현실적이다.
