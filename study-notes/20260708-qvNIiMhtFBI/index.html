레포 문서화를 위한 오픈소스 에이전트 OpenWiki를 소개합니다

한 줄 요약

OpenWiki는 코드베이스 문서를 자동으로 만들고 최신 상태로 유지하며, 코딩 에이전트가 저장소 맥락을 놓치지 않도록 AGENTS.md와 연동해주는 오픈소스 에이전트다.

핵심 학습 포인트 (내가 배워야 할 것)

개념 왜 중요한가 한 줄
OpenWiki 코드 저장소 문서화를 자동화해 코딩 에이전트가 더 정확한 컨텍스트를 갖게 한다 에이전트용 코드베이스 위키를 자동 생성·관리하는 도구
초기화(init)와 갱신(update) 한 번 생성한 문서는 코드 변경에 맞춰 계속 갱신되어야 한다 openwiki init으로 만들고 openwiki update로 최신화한다
모델 제공자(Model Provider) 선택 OpenWiki가 문서를 생성할 때 어떤 LLM을 쓸지 정해야 한다 OpenRouter, 오픈소스·폐쇄형 모델, 커스텀 모델 ID를 지원한다
LangSmith 트레이싱(Tracing) 에이전트가 내부적으로 어떤 작업을 했는지 추적할 수 있다 선택 사항이지만 디버깅과 관찰 가능성에 유용하다
quickstart.md 코딩 에이전트가 저장소를 이해할 때 가장 먼저 보는 문서 역할을 한다 저장소 개요와 하위 문서 색인을 담는 OpenWiki의 진입점
GitHub Action 자동화 사람이 문서를 수동으로 업데이트하지 않아도 된다 하루 1회 등 원하는 주기로 문서 갱신 PR을 자동 생성한다
Git 히스토리 기반 문서화 단순 코드 구조뿐 아니라 변경 이유와 의사결정 맥락을 문서화할 수 있다 커밋, PR 설명, 댓글 등을 읽어 문서 업데이트 여부를 판단한다
AGENTS.md / CLAUDE.md 연동 코딩 에이전트가 OpenWiki 문서를 언제 참고해야 하는지 알게 된다 별도 프롬프트 없이 에이전트가 자동으로 문서를 활용한다

내가 모를 만한 것 / 처음 보는 것

  • OpenWiki — LangChain에서 만든 오픈소스 에이전트로, 코드 저장소 문서를 자동 생성하고 관리한다.
  • DeepAgents — OpenWiki가 기반으로 사용하는 에이전트 프레임워크. 내부 실행 흐름과 작업 단위를 에이전트 방식으로 구성한다.
  • LangSmith 트레이싱(Tracing) — LLM 애플리케이션과 에이전트의 실행 과정을 기록·분석하는 관찰 도구.
  • OpenRouter — 여러 LLM 제공자와 모델을 하나의 API처럼 사용할 수 있게 해주는 모델 라우팅 서비스.
  • AGENTS.md — 코딩 에이전트에게 프로젝트 작업 규칙, 참고 문서, 사용 지침을 알려주는 파일.
  • CLAUDE.md — Claude Code가 프로젝트에서 참고하는 지침 파일.
  • GitHub Action — GitHub 저장소에서 일정 주기 또는 이벤트에 따라 자동으로 명령어를 실행하는 자동화 기능.
  • PR(Pull Request) — 코드나 문서 변경을 저장소에 병합하기 전 검토 요청하는 단위.
  • 커밋 해시(Commit Hash) — Git에서 특정 변경 시점을 식별하는 고유 ID.

화자의 디테일 (놓치기 쉬운 포인트)

화자가 흘리듯 말한 구체 수치·설정값·명령어·뉘앙스. 원어 용어 괄호 병기, 맥락까지.

  1. 설치는 npm으로 진행한다 — OpenWiki는 Node.js 패키지 형태로 제공되며, 로컬 머신에 설치해 CLI로 사용한다.
  2. 초기 문서 생성 명령은 openwiki init이다 — 온보딩, 모델 선택, API 키 입력 후 바로 저장소 문서 생성을 시작한다.
  3. 모델 제공자(Model Provider)는 오픈소스와 폐쇄형 모두 지원한다 — 영상에서는 OpenRouter를 선택한다.
  4. 미리 정의된 모델 외에도 커스텀 모델 ID(Custom Model ID)를 지정할 수 있다 — 원하는 모델이 기본 목록에 없으면 직접 입력 가능하다.
  5. 기본 설정에 추가하고 싶은 제공자나 모델이 있으면 PR을 올리라고 말한다 — OpenWiki가 오픈소스 패키지이기 때문에 기여를 받는다.
  6. 예시 모델로 GLM 5.2를 선택한다 — 모델 선택 과정의 구체 예시다.
  7. LangSmith API 키 입력은 선택 사항이다 — 입력하면 OpenWiki 실행의 모든 액션을 트레이싱 프로젝트로 보낼 수 있다.
  8. OpenWiki 저장소 안에는 OpenWiki 디렉터리가 생긴다 — 그 안에 하위 디렉터리와 quickstart.md가 생성된다.
  9. quickstart.md는 OpenWiki 문서의 색인(Index)이다 — 저장소 개요, 주요 파일, 하위 문서 링크를 제공한다.
  10. 갱신 명령은 openwiki update다 — GitHub Action에서 이 명령을 실행해 문서를 자동 업데이트한다.
  11. GitHub Action은 기본 예시로 하루 한 번 실행된다 — 문서 갱신 후 자동으로 PR을 생성한다.
  12. 업데이트 기준은 마지막으로 문서가 갱신되기 전 체크된 커밋 해시다 — 그 이후 병합된 커밋, PR 설명, 댓글 등을 검사한다.
  13. 실행 주기는 저장소 상황에 맞게 바꿀 수 있다 — 덜 바뀌는 저장소는 주 1회, 변경이 매우 많은 저장소는 4시간 또는 6시간마다 실행 가능하다.
  14. openwiki 명령만 실행하면 채팅 인터페이스가 뜬다 — 문서 생성뿐 아니라 저장소와 문서에 대해 질문할 수 있다.
  15. OpenWiki는 AGENTS.md 또는 CLAUDE.md를 자동 생성·수정한다 — 코딩 에이전트가 OpenWiki 문서를 참고하도록 지침을 추가한다.
  16. 사용자는 초기 설정 후 문서 갱신 PR만 병합하면 된다 — 일상적인 문서 유지보수는 OpenWiki와 GitHub Action이 맡는다.

# 섹션 요지
1 OpenWiki 소개 코드베이스 문서를 에이전트용으로 자동 생성·관리하는 LangChain의 오픈소스 도구
2 설치와 초기화 npm 설치 후 openwiki init으로 모델 제공자와 API 키를 설정하고 문서 생성
3 생성 문서 구조 quickstart.md가 색인 역할을 하고, 하위 문서가 아키텍처·CLI·작업 흐름을 설명
4 왜 문서에 비즈니스 로직이 필요한가 에이전트는 코드가 어떻게 동작하는지뿐 아니라 왜 그렇게 구현됐는지도 알아야 한다
5 GitHub Action 자동 갱신 openwiki update를 일정 주기로 실행해 문서 업데이트 PR을 자동 생성
6 OpenWiki 채팅 CLI 채팅 인터페이스로 문서 검색, 질문, 타깃 수정이 가능
7 코딩 에이전트 연동 AGENTS.md와 CLAUDE.md를 통해 에이전트가 OpenWiki 문서를 자동 참고
8 향후 계획과 기여 현재는 단순한 코딩 에이전트용 위키지만 기능 제안과 PR을 받으며 확장 예정

1. OpenWiki는 무엇인가

OpenWiki는 LangChain이 만든 최신 오픈소스 에이전트다. 목적은 코드베이스 문서(Codebase Documentation)를 자동으로 생성하고 유지보수하는 것이다.

일반적인 문서화 도구와 다른 점은, 사람이 읽기 위한 문서만 만드는 것이 아니라 코딩 에이전트(Coding Agent)가 저장소를 더 잘 이해하도록 설계되었다는 점이다.

코딩 에이전트가 저장소에서 작업하려면 다음을 알아야 한다.

  • 이 저장소가 무엇을 하는지
  • 핵심 파일과 디렉터리가 어디인지
  • 기능별 구조가 어떻게 나뉘어 있는지
  • 특정 코드가 왜 그런 방식으로 구현됐는지
  • 최근 변경 사항과 의사결정 배경은 무엇인지

OpenWiki는 이런 정보를 문서로 만들고, 코딩 에이전트가 필요할 때 자동으로 참고하게 만든다.

2. 설치와 초기 설정 흐름

OpenWiki는 npm을 통해 로컬 머신에 설치한다. 설치 후 핵심 명령은 다음이다.

openwiki init

이 명령을 실행하면 온보딩 과정이 시작된다. 여기서 사용자는 문서 생성을 위해 사용할 모델 제공자(Model Provider)를 선택한다.

영상에서는 OpenRouter를 선택한다. OpenWiki는 오픈소스 모델뿐 아니라 폐쇄형 모델 제공자도 지원한다. 미리 정의된 모델 목록에서 선택할 수도 있고, 원하는 모델이 없다면 커스텀 모델 ID(Custom Model ID)를 직접 지정할 수도 있다.

화자는 OpenWiki가 오픈소스이므로, 기본 설정에 추가하고 싶은 제공자나 모델이 있다면 PR(Pull Request)을 보내면 실제 패키지에 반영할 수 있다고 설명한다.

예시에서는 GLM 5.2 모델을 선택한다.

그다음 LangSmith API 키 입력 단계가 나온다. 이 설정은 선택 사항이다. API 키를 넣으면 OpenWiki가 실행하는 모든 액션과 단계가 LangSmith 트레이싱 프로젝트에 기록된다. 즉, 에이전트가 내부에서 어떤 판단과 작업을 했는지 확인할 수 있다.

3. OpenWiki가 생성하는 문서 구조

초기화가 끝나면 OpenWiki는 해당 저장소의 문서 생성을 시작한다.

OpenWiki 저장소 자체를 예시로 보면, 저장소 안에 OpenWiki라는 디렉터리가 있고 그 안에 여러 하위 디렉터리와 quickstart.md 파일이 있다.

quickstart.md는 OpenWiki 문서의 색인(Index) 역할을 한다. 이 파일에는 다음 내용이 들어간다.

  • 저장소가 무엇인지에 대한 상위 수준 개요
  • 저장소가 하는 일
  • 중요한 파일 목록
  • 다른 OpenWiki 문서로 가는 링크
  • 코드베이스 안의 실제 파일 참조

코딩 에이전트가 저장소 문서를 확인하려 할 때 가장 먼저 보는 파일이 바로 quickstart.md다. 따라서 이 파일은 단순 소개 문서가 아니라, 저장소 안에서 필요한 정보를 빠르게 찾기 위한 지도에 가깝다.

하위 문서에는 저장소의 다양한 측면이 나뉘어 정리된다. 예를 들어 OpenWiki 저장소의 경우 다음과 같은 내용이 문서화된다.

  • OpenWiki 에이전트 자체
  • 에이전트 아키텍처(Architecture)
  • CLI(Command Line Interface)
  • CLI 내부 작업(Operation)
  • OpenWiki가 수행한 업데이트 기록

4. 단순 기술 문서보다 중요한 비즈니스 로직

화자는 OpenWiki 문서가 단순한 기술 문서만 포함하지 않는다고 강조한다. 문서에는 저장소의 각 영역에 대한 상위 수준의 비즈니스 로직(Business Logic)도 포함된다.

코딩 에이전트에게 중요한 것은 단순히 “코드가 어떻게 작동하는가”만이 아니다. 사실 에이전트는 코드를 읽으면 어느 정도 동작 방식은 파악할 수 있다.

하지만 더 중요한 질문은 다음이다.

  • 왜 이 기능이 이런 구조로 구현됐는가
  • 왜 이전 방식이 아니라 현재 방식이 선택됐는가
  • 어떤 PR이나 커밋에서 어떤 맥락으로 변경됐는가
  • 주석이나 리뷰에서 어떤 의사결정이 있었는가

OpenWiki는 Git 커밋 히스토리, PR 설명, 댓글 등을 참고해 이런 결정 배경까지 문서화한다. 그 결과 코딩 에이전트는 코드를 수정할 때 더 풍부한 맥락을 가지고 작업할 수 있다.

실무적으로 보면, OpenWiki는 “신입 개발자 온보딩 문서”와 “AI 코딩 에이전트용 프로젝트 설명서”를 동시에 자동 생성하는 도구에 가깝다.

5. 문서를 최신 상태로 유지하는 방법

문서는 한 번 만들고 끝내면 금방 낡는다. 코드가 바뀌면 문서도 같이 바뀌어야 한다.

OpenWiki는 이를 위해 복사해서 사용할 수 있는 GitHub Action을 제공한다. 이 액션은 일정 주기로 실행되어 OpenWiki 문서를 자동으로 업데이트한다.

초기 생성 명령이 다음이었다면,

openwiki init

갱신 명령은 다음이다.

openwiki update

GitHub Action은 이 업데이트 명령을 실행하고, 변경된 문서가 있으면 저장소에 Pull Request를 자동으로 생성한다.

기본 예시는 하루 한 번 실행이다. 하지만 저장소 상황에 따라 주기를 바꿀 수 있다.

  • 변경이 적은 저장소: 주 1회
  • 변경이 많은 저장소: 4시간마다 또는 6시간마다
  • 일반적인 저장소: 하루 1회

중요한 점은 실행 주기가 에이전트 자체와 독립적이라는 것이다. OpenWiki는 특정 시간 범위에 의존하지 않고 Git 히스토리를 확인한다. 마지막으로 문서가 업데이트되었을 때의 커밋 해시를 기준으로, 그 이후 병합된 모든 커밋과 변경 사항을 살펴본다.

그 과정에서 다음 정보를 검사한다.

  • 커밋 내용
  • 코드 변경 사항
  • PR 설명
  • 댓글
  • 기타 변경 맥락

그리고 필요하다고 판단되면 문서를 업데이트한다.

6. OpenWiki와 직접 채팅하기

OpenWiki는 문서 생성과 업데이트 명령만 제공하는 것이 아니다. 에이전트와 직접 채팅할 수도 있다.

명령은 다음이다.

openwiki

이 명령을 실행하면 채팅 인터페이스가 뜬다. 이 안에서 사용자는 다음 작업을 할 수 있다.

  • 모델 제공자 커스터마이즈
  • 문서 업데이트
  • 문서 삭제 또는 초기화
  • 저장소에 대해 질문
  • OpenWiki가 작성한 문서 검색
  • 특정 부분의 문서만 수정

예를 들어 “너는 무엇을 할 수 있니?”라고 물으면, OpenWiki는 자신이 단순 문서 생성기가 아니라 저장소와 문서에 대해 답변할 수 있는 챗봇이기도 하다고 설명한다.

즉, OpenWiki는 문서를 만들어두는 도구이면서 동시에 그 문서를 기반으로 저장소를 질의할 수 있는 인터페이스이기도 하다.

7. 코딩 에이전트는 OpenWiki 문서를 어떻게 쓰는가

OpenWiki 문서가 만들어졌다고 해서 코딩 에이전트가 자동으로 알 수 있는 것은 아니다. 그래서 OpenWiki는 AGENTS.md 또는 Claude Code를 사용하는 경우 CLAUDE.md와 연동한다.

OpenWiki는 이 파일들을 자동으로 업데이트하거나, 없으면 새로 만든다. 그리고 그 안에 OpenWiki 문서에 대한 참조를 추가한다.

이 지침은 코딩 에이전트에게 다음을 알려준다.

  • OpenWiki 문서가 어디에 있는지
  • 언제 OpenWiki 문서를 참고해야 하는지
  • 코드베이스 맥락이 필요할 때 어떤 문서를 먼저 봐야 하는지
  • 저장소 이해를 위해 quickstart.md와 하위 문서를 어떻게 활용해야 하는지

이 구조 덕분에 사용자는 초기 설정 이후 OpenWiki를 계속 신경 쓰지 않아도 된다.

흐름은 다음과 같다.

  1. openwiki init으로 초기 문서를 생성한다.
  2. GitHub Action을 추가해 문서 업데이트를 자동화한다.
  3. OpenWiki가 AGENTS.md에 관련 지침을 추가한다.
  4. 이후 코딩 에이전트는 저장소에서 실행될 때 AGENTS.md를 읽는다.
  5. 그 결과 OpenWiki 문서를 자동으로 참고한다.
  6. 사용자는 OpenWiki가 생성한 문서 업데이트 PR만 검토하고 병합하면 된다.

이 방식의 장점은 매번 코딩 에이전트에게 “이 문서를 참고해”라고 별도로 프롬프트를 넣지 않아도 된다는 것이다.

8. 현재 상태와 향후 계획

화자는 OpenWiki가 현재는 코딩 에이전트를 위한 비교적 단순한 도구라고 말한다. 하지만 LangChain은 이 “위키(Wiki)” 아이디어를 더 확장할 계획이다.

기능 요청, 제안, 기여를 원하는 사람은 OpenWiki GitHub 저장소에 방문해 다음을 할 수 있다.

안녕하세요, 여러분. 저는 LangChain의 Brace입니다. 오늘은 LangChain의 최신 오픈소스 에이전트인 OpenWiki를 소개하려고 합니다.

OpenWiki는 코드베이스 문서를 생성하고 유지보수하는 가장 쉬운 방법입니다. 특히 에이전트를 위해 만들어졌습니다. 시작하는 방법은 명령어 하나만 실행하면 될 정도로 간단합니다. 먼저 로컬 머신에 npm을 통해 설치하겠습니다.

설치가 끝나면 openwiki init을 실행하면 됩니다. 그러면 온보딩 과정이 시작되고, 여기서 모델 제공자(Model Provider)를 선택할 수 있습니다. 보시는 것처럼 OpenWiki는 오픈소스 모델뿐 아니라 폐쇄형 모델 제공자도 지원합니다. 저는 OpenRouter로 시작하겠습니다. 그다음 API 키를 입력하라고 나오면 키를 붙여 넣고 모델을 선택합니다.

몇 가지 사전 정의된 모델이 있어서 그중에서 고를 수 있습니다. 물론 원하는 모델이 목록에 없다면 커스텀 모델 ID(Custom Model ID)를 설정할 수도 있습니다. OpenWiki는 오픈소스이기 때문에, 기본 설정에 추가하고 싶은 제공자나 모델이 있다면 PR(Pull Request)을 올려주세요. 실제 패키지에 추가할 수 있습니다.

저는 GLM 5.2를 선택하겠습니다. 다음으로 LangSmith API 키를 물어봅니다. 이것은 선택 사항입니다. 하지만 OpenWiki는 DeepAgents와 LangSmith 위에 만들어졌기 때문에, 여기에 API 키를 설정하면 OpenWiki가 실행하는 모든 액션과 작업을 트레이싱 프로젝트로 보낼 수 있습니다. 그러면 내부에서 정확히 어떻게 실행되는지 언제든 확인할 수 있습니다.

지금은 건너뛰겠습니다. 엔터를 누르면, init 명령을 실행했기 때문에 곧바로 이 저장소의 문서 생성을 시작합니다.

실행되는 동안, 실제로 저장소 안에서 이 문서들이 어떻게 생겼는지 살펴보겠습니다.

지금 저는 OpenWiki 저장소 자체에 들어와 있습니다. 당연히 이 저장소에도 OpenWiki로 생성된 문서가 있습니다. OpenWiki라는 디렉터리가 보이고, 그 안에는 몇 개의 하위 디렉터리와 quickstart.md라는 파일이 있습니다.

이 quickstart 파일은 OpenWiki 문서의 색인(Index)입니다. 실제 저장소가 무엇인지, 무엇을 하는지, 중요한 파일이 무엇인지에 대한 상위 수준의 개요가 들어 있습니다. 또한 나머지 OpenWiki 문서로 연결되는 링크 역할도 합니다. 여기서 다른 디렉터리를 참조하고, 코드베이스 안의 실제 파일들도 참조하는 것을 볼 수 있습니다.

코딩 에이전트가 저장소 문서를 수집하려고 할 때 가장 먼저 확인하는 파일이 바로 이 파일입니다. 따라서 이 파일은 저장소에 대한 상위 수준 설명일 뿐 아니라, 저장소 안에서 필요한 내용을 빠르게 찾기 위한 쉬운 참조 지점 역할도 합니다.

이 디렉터리들을 펼쳐보면, 저장소의 여러 측면에 대한 문서를 담은 하위 파일들이 있습니다. OpenWiki의 경우 실제 에이전트 자체, 에이전트의 아키텍처(Architecture), CLI(Command Line Interface), CLI 안의 여러 작업, 그리고 OpenWiki가 수행한 업데이트를 추적하기 위한 파일들이 있습니다.

이 파일들은 기술 문서뿐 아니라 저장소의 여러 영역에 대한 상위 수준의 비즈니스 로직(Business Logic)도 포함합니다. 이런 내용은 에이전트의 컨텍스트에 매우 중요합니다. 에이전트는 코드가 어떻게 작동하는지만 알면 되는 것이 아니라, 왜 그런 방식으로 구현되었는지도 알아야 하기 때문입니다. 코드만 읽어도 작동 방식은 어느 정도 알 수 있습니다. 하지만 Git 커밋, 커밋 히스토리, 주석 등을 살펴보면 OpenWiki는 여러 변경 사항 뒤에 있는 비즈니스 로직과 의사결정을 문서화할 수 있습니다. 그래서 에이전트가 실제로 저장소에서 코드를 작성할 때 가장 좋은 컨텍스트를 갖게 됩니다.

이것이 실제 문서의 모습이며, 초기 파일을 생성하는 방식입니다.

이 문서를 최신 상태로 유지하려면 수동으로 계속 관리하거나 변경하고 싶지는 않을 것입니다. 그래서 복사해서 사용할 수 있는 GitHub Action을 제공합니다. 이 액션은 하루에 한 번 실행되어 OpenWiki 문서를 자동으로 업데이트합니다.

여기서 보시는 것처럼 OpenWiki 업데이트 명령을 실행합니다. 처음에는 init을 실행했고, 업데이트 명령은 단순히 update입니다. 이 명령은 하루에 한 번 실행되고, 저장소에 Pull Request를 만들어 문서를 자동으로 업데이트합니다.

이 문서를 업데이트하는 방식은 주로 Git을 사용하는 것입니다. 문서가 마지막으로 업데이트되기 전에 확인된 마지막 커밋 해시(Commit Hash)를 추적합니다. 그런 다음 그 이후 병합된 모든 커밋을 살펴보고, 만들어진 모든 변경 사항, PR 설명, 댓글 등을 검사합니다. 그리고 필요하다면 그 정보를 사용해 문서를 업데이트합니다. 이렇게 해서 문서가 항상 최신 상태로 유지됩니다.

자주 업데이트하지 않는 저장소라면 실행 주기를 주 1회로 바꿀 수 있습니다. 반대로 하루에 수십만 개의 커밋이 병합되는 저장소라면 4시간마다, 6시간마다 또는 원하는 주기로 실행할 수도 있습니다.

스케줄은 에이전트와 완전히 독립적입니다. 에이전트는 어떤 시간 범위에서도 동작합니다. 에이전트가 하는 일은 Git 히스토리를 보고, 그 커밋들을 바탕으로 문서 자체를 업데이트하는 것이기 때문입니다.

OpenWiki에는 실행과 업데이트를 위한 두 가지 명령만 있는 것이 아닙니다. 에이전트와 직접 채팅할 수도 있습니다. 어떻게 생겼는지 보겠습니다.

OpenWiki와 채팅하려면 openwiki를 실행하기만 하면 됩니다. 그러면 채팅 인터페이스가 시작됩니다. 여기에서 모델 제공자를 커스터마이즈하거나, 문서를 업데이트하거나, 문서를 지우는 등의 작업을 할 수 있습니다. 에이전트와 대화할 수도 있습니다. 예를 들어 “너는 무엇을 할 수 있니?”라고 물어볼 수 있습니다. 여기서 볼 수 있듯이 OpenWiki는 문서만 생성하는 것이 아니라 챗봇이기도 합니다. 그래서 저장소에 대해 질문하거나, 문서에 대해 질문하거나, OpenWiki가 작성한 문서를 검색하는 데 사용할 수 있습니다.

이 기능을 사용하면 OpenWiki 문서를 관리할 수 있고, 문서의 특정 부분을 대상으로 변경할 수도 있습니다.

이제 문서가 생겼습니다. 그렇다면 코딩 에이전트는 실제로 이 문서를 어떻게 사용할까요?

코딩 에이전트는 AGENTS.md를 통해 OpenWiki를 알게 됩니다. Claude Code 파일을 사용한다면 CLAUDE.md를 통해 알게 됩니다. OpenWiki는 이 파일들을 자동으로 업데이트하거나, 파일이 없다면 생성합니다. 그리고 OpenWiki에 대한 참조를 포함시켜 코딩 에이전트에게 OpenWiki 문서를 어떻게, 어디서, 언제 사용해야 하는지 알려줍니다. 즉, 코드베이스에 대한 컨텍스트가 필요할 때마다 사용하도록 지시합니다.

OpenWiki가 AGENTS.md를 자동으로 변경해주기 때문에, 초기 설정 이후에는 OpenWiki에 대해 거의 신경 쓸 필요가 없습니다. init 명령을 실행해 초기 문서를 만들고, 저장소에 변경 사항이 생길 때 문서를 자동 업데이트하도록 GitHub Action을 추가하면 됩니다. 그리고 OpenWiki는 AGENTS.md에 해당 섹션을 추가합니다.

즉, 에이전트들이 백그라운드에서 문서를 항상 최신 상태로 유지해 줍니다. 사용자는 에이전트가 올린 Pull Request를 병합하기만 하면 됩니다. 그리고 저장소에서 코딩 에이전트를 실행할 때마다, 에이전트는 자동으로 AGENTS.md 파일을 읽습니다. 그러면 OpenWiki 섹션도 읽게 되고, OpenWiki를 어떻게 사용해야 하는지, 언제 문서를 참조해야 하는지 지시받게 됩니다. 이런 방식으로 에이전트는 매번 추가 프롬프트나 참조를 넣지 않아도 저장소 전체 컨텍스트를 항상 가질 수 있습니다.

이것이 OpenWiki가 동작하는 상위 수준의 방식입니다. 현재는 코딩 에이전트용이고 비교적 단순하지만, 저희는 이 위키 아이디어를 이제 막 시작했으며 앞으로 훨씬 더 많은 일을 할 예정입니다.

기능 요청이나 제안이 있거나 기여하고 싶다면, 설명란에 링크된 OpenWiki 저장소로 가서 PR을 올리거나 기능 요청 이슈를 만들어주세요. 여러분의 의견을 곧 듣게 되기를 기대하겠습니다.
