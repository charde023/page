먼저 읽는 쉬운 요약

처음 보는 사람을 위한 읽기 안내

영상 미시청 기준 · 약 2분 · 선수지식: 없음 이 부분만 읽어도 아래 중심 질문에 자기 말로 답할 수 있게 설명한다.

이 영상의 중심은 “어느 모델이 코드를 더 잘 쓰나”보다 “내 일을 끝까지 처리하는 경험이 좋은가”로 도구를 고르자는 화자의 경험담이다. 화자는 최고 설정에서 Codex와 Claude Code의 코딩 결과가 대체로 비슷했다고 말한다. 대신 Codex는 화면을 뒤에서 조작해 여러 작업을 동시에 진행하고(컴퓨터 사용), 휴대전화에서 새 작업을 시작해 업무와 코딩을 한 흐름으로 잇는 점이 더 편했다고 평가한다.

핵심은 답을 찾는 데서 멈추지 않고 실제 화면에서 테스트·설정·결제 직전까지 확인하는 것이다. 다만 이런 조작은 사용량을 빨리 소모하며, 화자의 평점과 비용 주장은 벤치마크가 아닌 개인 판단이다. 따라서 가장 싼 요금제에서 시작해 사용량과 완료율이 부족할 때만 올리고, 어려운 작업에만 비싼 모델이나 두 번째 모델 검토를 붙이는 것이 화자의 제안이다. 도구 선택 기준은 이름보다 내 작업의 병목, 끝까지 검증되는 정도, 비용보다 얻는 가치다.

여기까지만 이해하면 충분

  • 코딩 결과가 비슷해도 실제 작업을 끝내는 사용자 경험은 다를 수 있다.
  • 좋은 에이전트는 답을 제시하는 데서 멈추지 않고 실제 화면에서 결과를 검증한다.
  • 요금제와 고성능 모델은 사용량과 확인된 가치가 부족할 때만 단계적으로 올린다.

화자는 외출 중 앱 오류 이메일을 받는 상황을 가정한다. 휴대전화에서 에이전트에게 이메일 확인을 요청하면, 에이전트가 코드 수정부터 시뮬레이터 테스트, 배포, 답장 초안까지 이어서 처리한다는 구상이다. 이는 실제 완료 사례가 아니라 화자가 설명한 가상 워크플로다.

비유와 깨지는 지점

화면을 직접 다루는 개인 비서

검색 결과만 전달하는 비서가 아니라, 대시보드를 열고 설정을 바꾸며 실제 작동 여부까지 확인하는 비서에 가깝다. 화자도 작은 화면 작업을 맡길 수 있다는 점에서 개인 비서와 비슷하다고 표현한다.

비유가 깨지는 지점: 사람 비서처럼 결과를 항상 올바르게 판단한다는 뜻은 아니다. 화자도 토큰 소비가 크고 성능을 따로 벤치마크하지 않았다고 밝혔다.

1. 원인

화자는 코딩 결과가 비슷하다고 보면서도 왜 Codex를 주 도구로 바꿨는가?

모범 답안 보기

화자의 비교에서는 최고 설정의 코딩 결과가 대체로 비슷했다. 차이는 백그라운드 컴퓨터 조작, 여러 에이전트의 동시 작업, 실제 화면을 통한 검증, 모바일에서 새 작업을 시작하는 경험에서 생겼다. 따라서 모델의 코드 생성 능력보다 전체 워크플로의 마찰이 선택을 바꿨다.

2. 대조

답을 찾아 주는 에이전트와 작업을 끝까지 검증하는 에이전트는 무엇이 다른가?

모범 답안 보기

전자는 웹에서 후보나 설명을 찾아 제시할 수 있지만, 정보가 오래됐거나 사용자 조건에 맞지 않을 수 있다. 후자는 실제 앱·브라우저·시뮬레이터를 조작해 결과가 작동하는 지점까지 확인한다. 다만 화자의 사례만으로 모든 환경에서 같은 성능이 보장되지는 않는다.

3. 적용

새 AI 도구나 상위 요금제를 시험할 때 무엇을 기준으로 유지 여부를 판단해야 할까?

모범 답안 보기

먼저 반복되는 실제 작업 하나를 정하고, 답변 품질보다 검증된 완료율과 사람의 개입 필요성을 기록한다. 현재 도구보다 병목을 줄이고 그 가치가 추가 비용을 넘는지 확인한 뒤 확대한다. APOM이나 자동화에 적용한다면 아직 확인되지 않은 가설로 시험해야 한다.

이번 글의 통찰

1. 모델 순위보다 작업의 마지막 구간이 선택을 바꾼다

  • [원문] 화자는 고성능 설정에서 Codex와 Claude Code의 코딩 결과가 대체로 비슷했지만, Codex의 컴퓨터 사용과 모바일 경험 때문에 주 도구를 바꿨다고 말했다.
  • [해석] 도구 비교에서는 생성된 답만 볼 것이 아니라 실제 테스트, 설정, 후속 조치까지 어디에서 사람이 다시 개입하는지 봐야 한다.
  • [경계] 화자는 정식 벤치마크를 하지 않았으며 5점·9점 같은 평가는 개인 경험이다. 특정 모델과 제품 버전에 관한 평가를 일반적인 우열로 확정할 수 없다.

2. 신뢰는 그럴듯한 후보보다 실제 완료 확인에서 생긴다

  • [원문] 화자는 항공권 에이전트들이 유효하지 않은 거래를 찾곤 했지만, Codex는 일본항공 결제 흐름에서 카드 입력과 결제 직전까지 진행해 이용 가능 여부를 확인했다고 주장했다.
  • [해석] 자동화의 가치는 “답을 냈는가”보다 “현실의 조건에서 통과했는가”로 측정하는 편이 낫다.
  • [경계] 항공권 탐색은 화자의 단일 사례이며 가격, 포인트 가치, 실제 자격 여부는 독립적으로 확인되지 않았다. 이메일 확인부터 앱 배포까지의 모바일 장면은 실행 완료 보고가 아니라 화자가 제시한 가상 상황이다.

3. 수치와 명칭의 불일치를 숨기지 말아야 한다

  • [원문] 본문은 두 개의 월 200달러 Codex 구독과 한 개의 월 200달러 Claude Max 구독, 합계 약 600달러를 설명한다.
  • [해석] 비용 판단에는 계정 수, 서비스 수, 설정 이름과 같은 단위를 먼저 분리해야 한다.
  • [경계]
  • 제목은 “두 개의 구독”이라고 하지만 본문은 Codex 계정 2개와 Claude 계정 1개, 총 3개 유료 계정을 말한다. 제목이 Codex 계정 2개를 뜻하는지, 두 서비스 종류를 뜻하는지는 명확하지 않다.
  • 화자는 “두 가지 추가 예”(a couple more examples)를 예고한 뒤 개발 테스트, 대시보드·DNS 설정, 항공권 탐색을 첫째·둘째·셋째 사례로 열거한다. 예고 수량 2와 실제 열거 3이 일치하지 않는다.
  • 앱 이름이 앞에서는 Amy, 뒤에서는 Amie로 기록돼 있어 어느 표기가 맞는지 확인되지 않는다.
  • Fable 5 설정은 앞부분에서 High 또는 Ultra Code, 뒤에서는 High와 Max로 표현돼 설정 명칭이 일관되지 않는다.
  • META의 creator는 비어 있고 전사에는 이름 Chris만 나온다. 링크 경로에 chrisraroque가 있지만 META도 이름과 SNS에 따른 추정이라고 밝혔으므로 전체 이름을 원작자로 확정하지 않았다. Ref 역시 META에 기록된 추정 소속 후보이지 독립적으로 확인된 소속이 아니다.

  • 관련성: 화자는 월 구독료와 토큰 사용량을 실제로 얻는 가치와 비교했다.
  • 통찰: APOM에 옮긴다면 비싼 자동화가 좋은지가 아니라 사람의 개입과 미완료 작업을 얼마나 줄이는지가 검증 전 가설이 된다.

마케터 · 구조적 비유

  • 관련성: 항공권 사례에서는 “좋은 거래를 찾았다”는 주장보다 실제 결제 직전까지 진행한 장면이 설득 근거로 쓰였다.
  • 통찰: 상세페이지에서도 추상적인 성능 주장보다 고객이 확인할 수 있는 마지막 검증 장면이 더 강한 증거가 될 수 있다.
  • 질문/행동: 카피의 핵심 주장마다 실제 작동을 보여 주는 화면·기록이 있는지 확인한다.

AI/SW 학습자 · 직접 전이

  • 관련성: 컴퓨터 사용, 병렬 작업, 모바일 연결, 모델별 작업 분배가 영상의 핵심 비교 기준이다.
  • 통찰: 에이전트 평가는 정상 답변뿐 아니라 실제 완료율, 예외 발생, 사람의 개입, 사용량을 함께 봐야 한다.
  • 질문/행동: 같은 작업을 여러 번 실행해 검증된 완료율을 기록한 뒤 모델과 요금제를 결정한다.

1. 전환의 전제

화자는 Claude Code를 1년 넘게 사용하고 추천해 왔지만, 최근 몇 주 동안 Codex를 함께 사용한 뒤 Codex를 주 도구로 바꿨다고 말한다. 두 도구 모두 훌륭하며 무조건 전환하라고 권하는 것은 아니라고 선을 긋는다. OpenAI의 후원을 받은 영상도 아니라고 밝혔다.

최고 설정에서 비교했을 때 코딩 결과는 대체로 비슷했으며, 전환 이유는 코딩 성능보다 사용자 경험이었다는 것이 핵심 주장이다.

2. 컴퓨터 사용

화자는 Claude의 컴퓨터 사용을 10점 만점에 5점, Codex를 9점으로 평가했다. 특히 Codex는 사람이 컴퓨터를 계속 쓰는 동안 백그라운드에서 여러 에이전트가 동시에 화면을 조작할 수 있다고 설명했다.

제시된 사례는 다음과 같다.

  1. XcodeBuildMCP만으로 어려웠던 길게 누른 뒤 끌기 같은 동작을 컴퓨터 사용으로 수행하고, iPhone과 Apple Watch 시뮬레이터를 동시에 시험했다는 사례
  2. Substack과 Cloudflare 대시보드에서 사용자 지정 도메인과 DNS를 약 10분 만에 설정했다는 사례
  3. 댈러스에서 일본까지 가는 직항 왕복 비즈니스석을 약 4,000달러 상당의 포인트로 찾고, 일본항공 결제 직전까지 약 3~4시간 동안 검증했다는 사례. 화자는 해당 항공권의 일반 판매가가 약 16,000달러라고 주장했다.

화자는 대시보드가 클릭 가능하면 99%의 경우 처리할 수 있다고 표현했고, 이런 작은 일을 하루에 100번가량 한다고 말했다. 두 수치는 측정 근거가 제시되지 않았다.

또한 OpenAI가 Sky를 인수했으며, 화자가 이해하기로 그 팀은 Apple Shortcuts 출신이라고 설명했다. 이 인수와 인력 배경은 전사 밖 자료로 확인되지 않았다.

3. 모바일 경험

화자는 Claude의 원격 제어 경험을 3점, Codex를 9점으로 평가했다. Claude에서는 컴퓨터에서 시작한 기존 세션을 사용해야 하고 폴더가 필요하지만, Codex에서는 휴대전화로 새 대화를 시작하거나 폴더 없는 일회성 작업을 만들 수 있다는 설명이다.

이메일의 앱 오류 보고를 읽고 코드 수정, 시뮬레이터 테스트, 배포, 사용자 답장 초안까지 처리하는 흐름도 제시했다. 그러나 이는 “그런 상황이라면”이라는 가정으로 설명한 것이며 실제 실행 완료 사례로 제시된 것은 아니다.

4. 모델 분배

화자의 개인 순위는 Fable 5, GPT-5.6 Sol, Opus 5 순이다. GPT-5.6 Sol은 주력 모델, Opus 5는 디자인 작업, Fable 5는 다른 모델이 풀지 못한 어려운 문제에 사용한다고 말했다.

큰 작업이 끝나면 다른 모델로 두 번째 검토를 시켜 결론을 비교하는 방식도 사용한다. Fable 5 Max는 세 번의 프롬프트만으로도 주간 사용량을 소진할 수 있다고 표현했으며, 하위 설정도 프롬프트를 더 신중히 쓰면 같은 결과를 낼 수 있다고 말했다.

한편 월 200달러 소비자 구독은 투자자와 기업용 API 매출로 보조된다고 주장했다. Anthropic은 최대 사용 시 약 4,000달러, OpenAI는 약 4,000~5,000달러를 잃을 수 있다고 추정했으며, 월 200달러 계정 3개를 약 15,000달러의 API 사용 가치에 가깝다고 해석했다. 정확한 수치는 모른다고 직접 밝혔으므로 검증된 비용 자료로 취급할 수 없다.

이게 너무 좋아서 실제로 월 200달러짜리 구독을 두 개 결제하고 있습니다. 왜 그런지는 이 영상 후반에 이야기하겠습니다.

처음 오신 분들, 채널에 오신 것을 환영합니다. 제 이름은 Chris이고, 생산성 앱을 만들고 있습니다. 저는 1년 넘게 Claude Code를 사용하고 추천해왔습니다. 제가 모든 것을 만드는 방식의 중추였죠. 하지만 오늘부터는 주로 Codex를 사용하고 있습니다.

물론 Claude Code도 여전히 사용하고 있기 때문에, Codex 구독 200달러 두 개에 더해 200달러짜리 Max 플랜도 결제하고 있습니다.

본격적으로 들어가기 전에 한 가지 말하고 싶은 것은, 두 도구 모두 정말 대단하다는 점입니다. 각자 쓰임새가 있습니다. 무작정 Codex로 바꾸라고 말하는 게 아닙니다. 여러분의 워크플로에 가장 잘 맞는 것을 사용하세요. 저는 그저 제 개인적인 경험을 공유하는 것뿐입니다.

그리고 댓글이 달리기 전에 간단히 밝히자면, 이 영상은 어떤 방식으로도 OpenAI의 후원을 받은 것이 아닙니다.

이번 영상에서는 제 생각을 바꾸고 Codex를 사용하기 시작하게 만든 일이 무엇이었는지 이야기하겠습니다. 스포일러를 하나 하자면, 핵심은 코딩이 아닙니다. 마지막에는 누가 무엇에 돈을 내야 하는지도 이야기하겠습니다. 여러분 대부분은 AI 구독에 600달러를 쓸 필요가 없습니다. 아니면 써야 할 수도 있고요. 할 말이 많으니 하나씩 이야기해보겠습니다.

가장 놀랐던 것부터 시작해보죠.

저는 이 채널에서 Codex에 대해 이야기한 적이 거의 없으니, 잘 모르는 분들을 위해 간단한 배경부터 설명하겠습니다. Codex는 OpenAI의 코딩 에이전트(coding agent)이며, ChatGPT 데스크톱 앱 안에서 작동합니다. Claude Code처럼 터미널 안에서 사용할 수도 있지만, 저는 개인적으로 OpenAI의 Mac 앱 안에서 사용하고 있는데, 정말 놀라운 경험입니다.

그럼 왜 바꿨을까요? Codex가 코드를 더 잘 작성하기 때문일까요? 저는 지난 몇 주 동안 두 도구를 동시에 실행해왔고, Codex에서는 가장 높은 설정을 사용하고 있습니다. 거의 모든 작업에 GPT-5.6 Sol을 Ultra 모드로 사용하고 있습니다. Claude Code에서는 Ultra Code 설정으로 Opus 5를 사용합니다. 경우에 따라서는 High, 때로는 Ultra Code 설정으로 Fable 5도 사용합니다.

논란의 여지가 있겠지만, 이런 고급 모델들을 사용했을 때 결과는 꽤 비슷합니다. 몇 가지 미묘한 차이는 있고 영상 후반에 이야기하겠지만, 전체적으로는 두 도구에서 같은 결과를 얻고 있습니다.

코딩이 무승부라면, 왜 Codex를 선택할까요? 결국 한 가지로 귀결됩니다. 바로 사용자 경험(user experience)입니다.

Codex의 경험을 아주 좋게 만드는 작은 요소들이 많지만, 그중 두 가지를 강조하고 싶습니다.

첫 번째는 컴퓨터 사용(computer use)입니다. 왜 더 많은 사람들이 이 이야기를 하지 않는지 정말 모르겠습니다. 컴퓨터 사용을 아는 사람들만의 비밀 클럽에 들어와 있는 기분입니다.

아직 보지 못했다면, 컴퓨터 사용은 Codex가 실제로 여러분의 컴퓨터를 제어할 수 있게 해주는 기능입니다. 마우스를 움직이고, 키보드로 입력하고, 여러분이 할 수 있는 모든 일을 스스로 수행합니다.

여러분 중 일부는 이렇게 생각할 겁니다. Claude에도 컴퓨터 사용 기능이 있지 않나? 기술적으로는 맞고, 저도 같은 생각을 했습니다. 하지만 둘은 전혀 같은 수준이 아닙니다.

Claude Desktop과 Claude Code의 컴퓨터 사용 기능은 10점 만점에 5점 정도라고 말하고 싶습니다. 일을 해내기는 하지만, Codex는 9점 정도라고 생각합니다.

차이점은 정말 많지만, 가장 큰 차이는 Codex의 컴퓨터 사용 기능이 백그라운드에서 작동하도록 최적화되어 있다는 점입니다. 즉, Codex가 동시에 컴퓨터를 사용하려고 하더라도 여러분은 계속 컴퓨터를 사용할 수 있고, 여러 Codex 에이전트를 동시에 실행해 컴퓨터를 제어하게 할 수도 있습니다.

Claude Desktop에서는 이 작업을 할 수 없습니다. Claude가 컴퓨터 사용 기능을 사용하는 동안에는 데스크톱을 사실상 만질 수 없습니다. Claude가 데스크톱을 완전히 제어하고 있어서, 건드리면 작업이 중단됩니다. 에이전트를 백그라운드에서 실행하는 이유가 멀티태스킹인데, 멀티태스킹을 할 수 없으니 다소 쓸모없게 됩니다.

Codex를 사용하면, 제가 다른 일을 하는 동안—가령 어떤 문제를 해결하고 있다고 해보죠—Codex가 App Store 리뷰를 분석하게 할 수 있습니다. 말 그대로 제 컴퓨터에서 App Store 목록을 살펴보게 하는 겁니다. 또 다른 에이전트는 컴퓨터 사용 기능으로 시뮬레이터를 제어하며 무언가를 테스트하게 하고, 또 다른 에이전트는 Cloudflare를 조작하며 일부 설정을 최적화하도록 할 수 있습니다.

이 모든 일이 제가 다른 작업에 집중하는 동안 동시에 백그라운드에서 일어날 수 있습니다. 이런 일을 거의 어떤 다른 코딩 에이전트에서도 할 수 없습니다.

제가 컴퓨터 사용 기능을 제대로 설명하지 못하고 있는 것 같으니, 예를 몇 가지 더 들어보겠습니다. 그중 하나라도 여러분에게 와닿았으면 좋겠네요.

개발자에게 특히 유용한 사례가 하나 있습니다. Claude Code로 iOS 앱을 테스트할 때 저는 XcodeBuildMCP라는 것을 사용해왔습니다. 정말 놀라운 MCP입니다. 기본적으로 Claude Code가 시뮬레이터를 제어할 수 있게 해주지만, 한 가지 문제가 있습니다. 여러 손가락으로 드래그하는 동작(multi-drag gesture)을 수행할 수 없습니다.

시뮬레이터를 이리저리 탭할 수는 있지만, 예를 들어 앱에서 목록 항목을 길게 눌러 순서를 바꾸고 싶다면 이를 효과적으로 테스트할 수 없습니다.

Codex는 마우스와 키보드를 완전히 제어할 수 있기 때문에 컴퓨터 사용 기능으로 이런 여러 손가락 드래그 동작을 실제로 수행할 수 있습니다. 이제 컴퓨터 사용 기능을 통해 완전한 테스트 흐름을 갖추게 됐습니다. Codex가 변경 사항을 구현하고, XcodeBuildMCP를 사용해 시뮬레이터를 빌드한 다음, 복잡한 여러 손가락 드래그 동작까지 지원되는 상태로 완전히 테스트할 수 있습니다.

컴퓨터 사용 기능으로 여러 시뮬레이터를 동시에 테스트할 수도 있습니다. Amy의 Apple Watch 연동을 테스트할 때 이 기능이 정말 중요했습니다. 동기화가 제대로 되는지 테스트하고 확인하려면 iPhone 시뮬레이터와 Apple Watch 시뮬레이터에 동시에 접근해야 했기 때문입니다.

컴퓨터 사용 기능이 없었다면 이 작업은 정말 어려웠을 겁니다. 이것이 첫 번째 예입니다.

컴퓨터 사용 기능의 또 다른 훌륭한 활용 사례는 대시보드 설정입니다. Vercel, AWS 같은 서비스에 들어가거나 그와 비슷한 작업을 할 때 컴퓨터 사용 기능이 훨씬 편합니다.

이런 서비스 중 상당수에는 CLI, MCP 또는 플러그인이 있습니다. 특히 상당히 최첨단인 Vercel이나 Cloudflare 같은 서비스에는 그렇습니다. 하지만 여전히 그런 기능이 없는 곳도 많고, 특히 개발자 중심이 아닌 서비스라면 더 그렇습니다.

예를 들어 저는 새 뉴스레터를 운영하기 위해 Substack을 설정하려고 했습니다. 그런데 여러분도 구독하셔야 합니다. 여러 단계 중 하나는 제 사용자 지정 도메인(custom domain)으로 Substack을 설정하는 것이었습니다. 그래서 Substack과 Cloudflare에 들어가 여러 DNS 설정을 수정해야 했습니다.

어려운 일은 아니었지만, 저는 다른 작업을 하던 중이었습니다. 그래서 ‘이걸 컴퓨터 사용 기능으로 Codex에게 시키면 되지 않을까?’라고 생각했습니다. 그래서 “내 사용자 지정 도메인을 설정해줘. Substack과 Cloudflare를 사용할 수 있으니 알아서 처리해줘”라고 말했습니다.

Codex는 설정을 이리저리 클릭하기 시작했습니다. 원한다면 실시간으로 진행 상황을 보면서 확인할 수 있었지만, 모든 설정을 클릭해 DNS를 구성했고, 약 10분 뒤에는 모든 설정이 완료됐습니다.

Substack에는 이런 작업을 구성할 MCP나 CLI가 없습니다. Cloudflare에는 아마 이를 위한 MCP가 있을 수도 있지만, 컴퓨터 사용 기능 덕분에 그런 것을 걱정할 필요가 전혀 없습니다. 대시보드가 있고 클릭할 수만 있다면—99%의 경우가 그렇죠—컴퓨터 사용 기능이 처리할 수 있다는 확신이 있습니다.

10분밖에 걸리지 않은 일이지만, 저는 하루에도 이런 사소한 일을 수백 번씩 하고 있고, 그러다 보면 정말 귀찮아집니다. 하루의 한두 가지 큰 작업에 집중하는 동안 이런 일을 어시스턴트에게 넘길 수 있다는 것은 실제로 큰 차이를 만듭니다. 개인 비서가 있는 것과 거의 같습니다.

세 번째로 공유하고 싶은 사례는 좋은 항공권 특가를 찾는 일입니다.

항공사 포인트를 사용해 특정 조건에 맞는 아주 좋은 항공권 특가를 찾는 작업입니다. 놀랍게도 지금까지 제가 테스트한 모든 에이전트가 이 작업에 실패했습니다. ChatGPT도 실패했고, Perplexity도 실패했으며, Claude도 실패했습니다.

결국 어떤 일이 일어나냐면, 에이전트에게 이 작업을 시키면 Reddit 게시글 같은 곳에서 어떤 특가를 찾아옵니다. 그런데 실제로 그 특가를 사용하려고 하면 유효한 특가가 아닙니다.

특가를 찾아내더라도 실제로 적용되지 않는 경우가 대부분입니다. 보통 오래된 정보를 바탕으로 작업했거나, 제가 자격을 충족하지 못하는 이상한 예외 조건이 있어서 사용할 수 없는 경우입니다. 과거에 이 작업을 시도할 때마다 성공한 에이전트는 없었습니다.

그래서 Codex에게 맡겨봤습니다. Codex는 아마 엄청난 수의 토큰을 사용하면서 3~4시간 동안 실행됐지만, 결국 댈러스에서 일본까지 직항으로 왕복하는 비즈니스석 항공권을 약 4,000달러어치의 포인트로 찾았습니다.

항공사 포인트를 아신다면, 이건 엄청나게 좋은 조건입니다. 이런 항공권은 보통 정가가 약 16,000달러이기 때문입니다.

무엇보다 중요한 점은 대부분의 에이전트가 건너뛰는 부분을 실제로 확인했다는 것입니다. Codex는 제가 자격이 되는지 검증하기 위해 Japan Airlines 웹사이트에서 신용카드 정보를 추가하고 결제 버튼을 누르기 직전까지 체크아웃 과정을 진행했습니다. 이것이 유효한 특가인지 확인하기 위해서였습니다.

항공권이 실제 체크아웃 과정을 통해 유효한지 확인하는 바로 그 마지막 1%에서 컴퓨터 사용 기능이 빛을 발합니다. 실제 브라우저를 사람처럼 사용하면서 내용을 검증하기 때문입니다. Airbnb 숙소나 Zillow의 주택 매물을 찾아볼 때도 정말 유용합니다.

단순히 공개된 인터넷을 스크랩하는 것이 아닙니다. 여러분이 직접 탐색하는 것처럼 웹을 탐색합니다.

저는 궁금해졌습니다. Codex는 왜 컴퓨터 사용을 이렇게 잘할까요? Anthropic은 왜 이렇게 하지 못하는 걸까요?

알고 보니 OpenAI가 실제로 Sky라는 회사를 인수했습니다. 제가 이해한 바로는 그 회사는 Apple Shortcuts를 만든 팀이었습니다. 그들은 Apple을 떠나 Sky를 설립했고, 컴퓨터 사용 에이전트 같은 것을 만들 계획이었습니다. 그러자 OpenAI가 재빨리 인수해 팀을 데려갔고, 지금은 그들이 컴퓨터 사용 기능을 개발하고 있습니다.

결국 컴퓨터 사용이 놀라운 이유는, 정말 뛰어난 실적을 가진 이 훌륭한 팀이 좋은 경험을 만드는 데 온전히 집중하고 있기 때문입니다.

컴퓨터 사용(computer use)의 솔직한 단점은 토큰을 많이 소모한다는 것입니다. 정확히 얼마나 소모되는지는 벤치마크를 돌려 보지 않아서 잘 모르겠지만, 사용해 보면 사용량이 꽤 빠르게 줄어드는 것을 느꼈습니다.

사용하는 모델이 중요하다고 생각합니다. 5.6 High로도 어떻게든 사용할 수 있을지 모르지만, 특히 컴퓨터 사용에서는 5.6 Sol을 Ultra 설정으로 사용할 때 결과가 훨씬 좋았습니다.

그래서 제 설정이 항상 이런 상태인 것이 큰 이유입니다.

컴퓨터 사용과 실제 코딩을 함께 하다 보니 한도에 꽤 빨리 도달합니다. Fast 모드는 사용하지 않고 사용량을 아끼려고 노력하고 있지만, 보통 일주일 치 사용량을 약 3일 만에 다 씁니다.

이것이 제가 200달러짜리 Codex 구독을 두 개 결제하는 가장 큰 이유입니다.

컴퓨터 사용에 대한 이야기는 이쯤 하고, 놀라운 경험이라는 측면에서 제가 Codex로 전환한 두 번째로 큰 이유는 모바일 경험입니다.

Claude Code에도 모바일 경험이 있습니다. 세션에서 /remote-control을 사용할 수 있고, 그러면 모바일 앱으로 보내서 그곳에서 계속할 수 있습니다.

하지만 점수를 매긴다면 Claude의 원격 제어 경험은 10점 만점에 3점이고, Codex는 9점이라고 생각합니다.

구체적인 이유를 몇 가지 말씀드리겠습니다. Claude에서는 새 스레드를 처음부터 시작할 수도 없습니다. 컴퓨터에서 시작해 둔 기존 스레드를 사용해야 합니다. 하지만 Codex에서는 앱을 열고 버튼을 누른 다음 새 대화를 바로 시작할 수 있습니다. 이게 훨씬 자연스럽습니다. 이와 관련해 Claude에서는 모든 스레드가 어떤 폴더 안에 있어야 합니다. 반면 Codex에서는 폴더 안에서 대화를 시작할 수도 있고, 폴더 없이 시작할 수도 있습니다. 저는 일회성 작업을 할 때 후자를 많이 사용합니다.

작은 차이점도 정말 많습니다. Codex 원격 제어는 훨씬 안정적으로 느껴집니다. 스트리밍도 더 일관되고 Claude 모바일 경험보다 훨씬 더 다듬어져 있습니다. 왜 그런지 알아보려고 찾아봤는데, OpenAI가 Codex 모바일 경험을 개발할 아주 뛰어난 iOS 엔지니어들을 영입했기 때문인 것 같습니다. 두 앱을 모두 많이 사용해 봤다면 그 차이를 느낄 수 있습니다. 경험이 워낙 좋아서 저는 실제로 휴대폰에서 Codex를 아주 많이 사용하게 됩니다.

모바일 경험을 컴퓨터 사용과 결합하면 꽤 놀라운 일이 됩니다. 이제 컴퓨터 앞에 있을 필요가 없기 때문입니다. 그냥 저 대신 일을 해 달라고 요청할 수 있습니다.

예를 들어 제가 밖에 있는데 누군가 “Amie 앱이 고장 났어요”라고 이메일을 보냈다고 해 보겠습니다. 휴대폰에서 Codex를 열고 새 스레드를 시작한 다음, “마지막 이메일을 확인해 줄래? 누군가 앱이 고장 났다고 했어. 대신 디버깅하고 고쳐 줘”라고 말할 수 있습니다.

Codex는 Gmail에 연결되어 있으므로 해당 스레드를 가져옵니다. 코드베이스에 접근할 수 있기 때문에 실제 문제를 수정합니다. 컴퓨터 사용 기능도 있으므로 시뮬레이터를 열고, 모든 것을 테스트하고, 수정 사항을 배포한 다음, 사용자에게 보낼 이메일 초안까지 휴대폰에서 한 번의 프롬프트로 작성할 수 있습니다.

안타깝게도 제가 설명한 정확한 작업 흐름은 현재 Claude Code로 구현하기가 매우 어렵습니다. 주된 이유는 Claude가 코딩용인 Claude Code와 그 밖의 업무 관련 작업용인 Claude Cowork로 기능을 나누기 때문입니다. 우선 둘은 서로 분리되어 있고 실제로 서로 잘 통하지 않습니다. Gmail 스레드를 Claude Code로 넘겨서 무언가를 고치게 한 다음 서로 대화하도록 만들기가 어렵습니다. 현재로서는 상당히 까다롭습니다.

설상가상으로 Claude Cowork는 모바일에서 제대로 작동하지 않습니다. Dispatch라는 것을 사용해야 하는데, 조금 이상합니다. 컴퓨터를 제어할 수 있는 스레드도 한 번에 하나뿐입니다. 정말 엉망이고, 저에게는 전혀 말이 되지 않습니다.

하지만 모든 것이 통합되어 그냥 작동하는 Codex의 모바일 경험은 저에게 매우 자연스럽습니다. 저를 Codex 쪽으로 끌어당긴 또 다른 큰 차이는 업무 관련 작업과 코딩 작업을 통합했다는 점입니다. 예를 들어 회사에서 사용하는 경우라면 모든 사람에게 적합하지는 않을 것입니다. 하지만 저처럼 그 두 가지가 얽혀 있는 사람에게는 삶이 훨씬 편해집니다.

Claude에서는 Claude Cowork로 갔다가 Claude Code로 가야 하고, 둘이 서로 잘 소통하지 않아서 정말 혼란스럽습니다. Anthropic이 둘을 통합하려고 노력하고 있다고 생각합니다. 실제로 작은 단계들이 진행되는 것이 보이기 때문입니다. 하지만 현재 이 부분에서는 Codex가 분명히 앞서 있습니다.

다시 말하지만, 업무와 개인 생활이 어느 정도 통합되어 있는 제 작업 흐름에서는 정말 좋은 경험입니다.

이제 제가 보여 드린 모든 것에 해당하는 짧은 이야기를 하나 하겠습니다. 저는 이 에이전트들에게 실제로 어떻게 말할까요? 대부분의 시간 동안 타이핑하지 않습니다. 보통 모든 내용을 받아쓰기하고 있습니다.

이제 Codex, 특히 모델에 대해 다시 이야기해 보겠습니다. 이 부분에는 여러 미묘한 차이가 있고, 제가 여전히 Claude Code에 돈을 내고 있는 큰 이유이기도 합니다.

다음은 현재 제가 생각하는 코딩 모델 순위입니다. 다시 말하지만 이것은 어디까지나 제 경험입니다. 이것이 사실이라고 말하는 것은 아닙니다. 가장 위에는 Fable 5가 있습니다. 단연코 최고의 코딩 모델이며, 많은 분들이 제 의견에 동의할 것이라고 생각합니다.

그보다 기능 면에서 조금 아래에는 GPT-5.6 Sol이 있고, 저는 이를 Ultra 설정으로 사용하고 있습니다. 그보다 조금 아래에는 Opus 5가 있고, 저는 이를 Ultra Code 설정으로 사용합니다. 모두 가장 높은 설정에서 사용하고 있습니다.

Fable 5가 최고라고 생각하지만, 문제는 너무 비싸서 모든 작업에 현실적으로 사용할 수 없다는 점입니다. 저는 보통 가장 어려운 문제에만 사용합니다.

GPT-5.6 Sol은 매우 탄탄한 모델이고, 실제로 제가 일상적으로 사용하는 모델입니다. 문제 해결을 아주 잘합니다. 그다음에는 Opus 5가 있는데, GPT-5.6보다 약간 떨어진다고 생각하지만 디자인 관련 작업에서는 GPT-5.6보다 실제로 더 낫다고 생각합니다.

현재 제 작업 흐름은 거의 모든 작업에 GPT-5.6을 사용하는 것입니다. 디자인 관련 작업은 보통 Ultra Code 설정의 Opus 5에 넘깁니다. 두 모델 모두 어려워하는 작업은 High 설정의 Fable 5에 넘깁니다. 정말 복잡한 작업에는 Max 설정의 Fable 5를 사용합니다.

제가 정말 좋아하는 패턴이 하나 있습니다. 보통 Codex로 큰 작업을 마무리한 다음, “Claude Code를 Opus 최고 설정으로 실행해서 2차 검토를 하게 해 줄래? 같은 결론에 도달하는지 확인해 봐”라고 말합니다.

두 모델을 실행하고 서로의 결과를 비교하게 하는 것이 정말 좋습니다. 보통 무언가를 발견해 내기 때문입니다. 정말 어려운 작업 대부분에 이 작업 흐름을 사용하게 됩니다. 그래도 해결되지 않는 작업은 High 모드의 Fable 5로 넘어갑니다. 여전히 해결되지 않는 작업에는 Max의 Fable 5를 사용합니다.

하지만 Fable 5 Max를 사용하면 프롬프트 세 개만으로 일주일 사용량을 모두 날려 버릴 수 있기 때문에 아주 아껴서 사용하고 있습니다.

Claude 모델도 여전히 제 작업 흐름에서 역할이 있습니다. 그래서 여전히 200달러짜리 Max 구독을 결제하고 있습니다.

이 모든 모델을 반드시 가장 높은 설정으로 사용해야 할까요? 물론 아닙니다. 꼭 그럴 필요는 없습니다. 여러 코딩 작업에서 하위 모델을 테스트해 봤는데 같은 결과를 얻을 수 있었습니다. 다만 프롬프트를 훨씬 더 신중하게 작성해야 합니다.
