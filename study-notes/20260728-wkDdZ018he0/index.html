개념 왜 중요한가 한 줄
제어 이론(Control Theory) AI 코딩 에이전트가 코드를 수정하고 다시 확인하는 과정을 설명하는 기본 틀 현재 상태와 목표 상태의 차이를 줄이는 반복 시스템
목표값(Set Point) 에이전트가 도달해야 할 원하는 결과를 명확히 정의해야 함 “어떤 코드 상태가 성공인가?”를 정하는 기준
측정 오차(Measured Error) 현재 코드와 목표 코드 사이의 차이를 알아야 다음 행동을 정할 수 있음 에이전트가 고쳐야 할 차이
컨트롤러(Controller) 오차를 보고 어떤 수정 행동을 할지 결정하는 부분 AI 모델이나 에이전트의 판단 역할
액추에이터(Actuator) 실제 시스템에 변화를 적용하는 실행 장치 코드 수정, 명령 실행, 파일 변경에 해당
피드백 루프(Feedback Loop) 한 번에 끝내지 않고 측정, 수정, 재측정을 반복해야 안정적인 결과에 도달 에이전트 작업의 핵심 반복 구조

내가 모를 만한 것 / 처음 보는 것

  • 제어 이론(Control Theory) — 동적인 시스템을 원하는 안정 상태나 최적 상태로 이동시키는 방법을 다루는 이론.
  • 동적 시스템(Dynamic System) — 시간이 지나며 상태가 변하는 시스템. 영상에서는 코드베이스(Codebase)가 여기에 해당한다.
  • 목표값(Set Point) — 시스템이 도달해야 할 원하는 상태. 예: 테스트 통과, 버그 제거, 기능 구현 완료.
  • 측정 오차(Measured Error) — 현재 상태와 목표 상태의 차이. AI 코딩에서는 실패한 테스트, 린트 오류, 요구사항 미충족 등이 될 수 있다.
  • 제어 신호(Control Signal) — 시스템에 어떤 작은 변경을 적용할지 알려주는 신호. 예: 특정 함수 수정, 패키지 추가, 설정 변경.
  • 액추에이터(Actuator) — 제어 신호를 실제 변화로 바꾸는 실행 장치. AI 코딩에서는 파일 편집 도구, 터미널 실행, API 호출 등이 될 수 있다.
  • 외란(Disturbance) — 시스템에 영향을 주는 예측하기 어려운 방해 요소. 예: 기존 코드의 복잡성, 의존성 충돌, 숨은 버그.

화자의 디테일 (놓치기 쉬운 포인트)

화자가 흘리듯 말한 구체 수치·설정값·명령어·뉘앙스. 원어 용어 괄호 병기, 맥락까지.

  1. 코드베이스(Codebase)를 동적 시스템(Dynamic System)으로 본다 — AI가 코드를 고치는 과정은 단순 편집이 아니라 계속 변하는 시스템을 안정 상태로 유도하는 과정이라는 뜻이다.
  2. 목표 상태를 목표값(Set Point)이라고 표현한다 — “원하는 세계의 상태”와 “현재 세계의 상태”를 비교해야 오차가 생긴다.
  3. 컨트롤러(Controller)는 오차를 읽고 제어 신호(Control Signal)로 바꾼다 — AI 에이전트가 테스트 실패나 요구사항 차이를 보고 다음 수정안을 만드는 과정과 닮았다.
  4. 액추에이터(Actuator)는 실제 변경을 시스템에 적용한다 — 생각만 하는 모델이 아니라, 코드 수정 도구나 실행 도구가 있어야 루프가 완성된다.
  5. 시스템은 외란(Disturbance)을 겪는다 — 수정하는 동안에도 예상치 못한 문제나 부작용이 생기므로 재측정이 필요하다.
  6. 전투기 예시를 든다 — 화자의 쌍둥이 형제가 항공우주 엔지니어이며, 전투기를 추락하지 않게 유지하는 원리도 이런 제어 이론이라고 설명한다.
  7. 복잡해 보이지만 기본 구조는 단순하다고 강조한다 — AI 코딩 에이전트의 루프도 “측정 → 비교 → 수정 → 재측정”으로 축약할 수 있다.

3 오차와 제어 신호 차이를 측정하고, 그 차이를 줄이는 작은 변경을 만든다

5 재측정 루프 다시 상태를 측정하고 같은 과정을 반복한다

1. 제어 이론은 원하는 상태로 시스템을 몰고 가는 방법이다

제어 이론(Control Theory)은 어떤 동적 시스템(Dynamic System)을 원하는 안정 상태나 최적 상태로 이동시키는 방법을 다룬다.

영상에서는 이 시스템을 코드베이스(Codebase)로 비유한다. 즉, AI 코딩 에이전트가 코드를 수정하는 일은 단순히 파일을 고치는 작업이 아니라, 현재 코드 상태를 원하는 결과로 점점 가까이 보내는 제어 문제로 볼 수 있다.

예를 들면 다음과 같다.

  • 현재 상태: 테스트가 실패하는 코드
  • 원하는 상태: 모든 테스트가 통과하고 요구사항을 만족하는 코드
  • 제어 과정: 오류를 읽고, 수정하고, 다시 테스트하는 반복

2. 현재 상태와 목표 상태의 차이가 오차다

제어 루프에는 먼저 센서(Sensor)가 필요하다. 센서는 현재 시스템 상태를 측정한다.

AI 코딩에서는 센서가 다음과 같은 역할을 할 수 있다.

  • 테스트 결과 확인
  • 빌드 로그 확인
  • 린트 오류 확인
  • 사용자 요구사항과 현재 구현 비교
  • 코드 리뷰 결과 확인

그다음에는 목표값(Set Point)이 필요하다. 목표값은 원하는 상태다.

현재 상태와 목표 상태의 차이가 측정 오차(Measured Error)다. 이 오차가 있어야 에이전트가 “무엇을 고쳐야 하는지” 판단할 수 있다.

3. 컨트롤러는 오차를 행동으로 바꾼다

컨트롤러(Controller)는 측정 오차를 읽고, 시스템에 적용할 제어 신호(Control Signal)를 만든다.

AI 코딩 에이전트로 비유하면 컨트롤러는 다음 역할이다.

  • 실패 원인 추론
  • 어떤 파일을 고칠지 결정
  • 어떤 함수나 설정을 수정할지 판단
  • 한 번에 얼마나 크게 바꿀지 결정

중요한 점은 제어 신호가 보통 점진적 변경(Incremental Change)이라는 것이다. 즉, 시스템 전체를 한 번에 뒤집기보다 작은 수정을 적용하고 다시 확인한다.

4. 액추에이터는 실제로 시스템을 바꾼다

액추에이터(Actuator)는 컨트롤러가 만든 제어 신호를 실제 시스템에 적용한다.

AI 코딩에서는 다음이 액추에이터에 해당할 수 있다.

  • 코드 편집 도구
  • 터미널 명령 실행
  • 패키지 설치
  • 설정 파일 수정
  • 테스트 실행 자동화 도구

컨트롤러가 “이 부분을 수정하라”고 결정해도 실제 코드에 반영되지 않으면 루프는 완성되지 않는다. 그래서 AI 에이전트에서는 추론 능력뿐 아니라 도구 사용(Tool Use)과 실행 권한도 중요하다.

5. 시스템에는 외란이 있고, 그래서 재측정이 필요하다

시스템은 변경을 적용하는 동안 외란(Disturbance)을 겪는다. 외란은 예상치 못한 방해나 부작용이다.

코딩에서는 다음이 외란이 될 수 있다.

  • 한 버그를 고쳤더니 다른 테스트가 실패함
  • 라이브러리 버전이 맞지 않음
  • 기존 코드 구조가 예상과 다름
  • 문서와 실제 코드가 다름
  • 숨겨진 의존성이 있음

그래서 한 번 수정했다고 끝나지 않는다. 다시 측정하고, 다시 오차를 계산하고, 다시 수정한다. 이것이 피드백 루프(Feedback Loop)다.

6. 전투기 제어와 AI 코딩 루프는 같은 원리로 설명된다

화자는 항공우주 엔지니어인 쌍둥이 형제를 언급하며, 전투기가 하늘에서 떨어지지 않도록 유지하는 데에도 이런 제어 이론이 쓰인다고 말한다.

물론 실제 항공 제어는 매우 복잡하지만, 기본 아이디어는 같다.

  1. 현재 상태를 측정한다.
  2. 원하는 상태와 비교한다.
  3. 오차를 계산한다.
  4. 오차를 줄이는 조작을 한다.
  5. 다시 측정한다.

AI 코딩 에이전트도 마찬가지로, 목표를 향해 반복적으로 상태를 확인하고 수정하는 루프를 잘 설계해야 한다.

전체 전사 펼치기

제어 이론(Control Theory)은 동적 시스템(Dynamic System)을 원하는 안정 상태나 최적 상태로 어떻게 이끌어 갈 것인가를 다루는 분야입니다. 여기서 그 동적 시스템은 여러분의 코드베이스(Codebase)가 될 수 있습니다.

먼저 현재 세계의 상태를 측정하는 센서(Sensor)가 있습니다. 그리고 목표값(Set Point), 즉 원하는 세계의 상태가 있습니다. 이 둘 사이의 차이가 측정 오차(Measured Error)입니다.

컨트롤러(Controller)는 이 측정 오차를 읽고, 시스템에 적용할 점진적인 변경(Incremental Change)에 대한 제어 신호(Control Signal)로 바꿉니다.

그리고 액추에이터(Actuator)가 그 변경을 시스템에 적용합니다. 그동안 시스템은 외란(Disturbance)을 겪고 있을 수 있습니다.

그런 다음 다시 측정하고, 측정 오차를 다시 계산합니다. 그러면 우리는 다시 출발점으로 돌아와 같은 과정을 반복하게 됩니다.

이 설명은 굉장히 복잡하게 들릴 수 있고, 실제로 복잡할 수도 있습니다. 제게는 항공우주 엔지니어인 쌍둥이 형제가 있는데, 전투기가 하늘에서 떨어지지 않도록 유지하는 데에도 이런 원리가 쓰입니다.

하지만 아마 여러분 대부분이 생각하는 것보다는 조금 더 단순한 구조일 것입니다.
