Conductor로 코딩 에이전트 오케스트레이션 — Charlie Holtz의 AI 코딩 세팅

한 줄 요약

Conductor CEO가 Mac에서 여러 코딩 에이전트(Claude·Codex)를 PR 단위로 동시 지휘하는 실전 세팅을 공개 — 핵심은 도구가 아니라 사람이 경계를 긋고(slop-free zone) AI에게 자유 영역을 주는 워크플로 강제.

개념 왜 중요한가 한 줄
slop-free zone AI가 나쁜 코드를 보면 더 나쁜 코드를 쓰는 악순환을 끊는 장치 코드베이스/문서에 "사람만 손대는 영역"을 명시(do not touch if you are an AI)
워크플로 강제 자유 편집을 막아야 리뷰·품질이 유지됨 Conductor는 직접 파일 편집 불가 — 워크스페이스=worktree → PR → merge 강제
"don't let the AI be your architect" 구조·UI를 AI에 맡기면 "crafted" 느낌이 사라짐 아키텍처·인터페이스 결정은 사람이, 구현은 에이전트가
fast mode + dangerously 권한 토큰 맥싱·속도의 실전 디폴트 fast mode 상시, --dangerously-skip-permissions 상시(둘 다 기본값 아님)
에이전트 = 작은 회사 직원 멘탈모델: 나는 CEO, 에이전트는 보고서 올리는 직원 대시보드에서 진행/리뷰/완료 상태로 지휘
코드는 톱밥(sawdust) 가치가 코드→프롬프트로 이동 차세대 모델 나오면 프롬프트 재실행→새 코드. 남는 건 프롬프트
모델 선택 기준 같은 작업도 모델 성향이 다름 새 기능 설계=Opus(창의적 파트너), 밀어붙여 끝내기=Codex(워크호스)

내가 모를 만한 것 / 처음 보는 것

  • Conductor — Mac에서 여러 코딩 에이전트를 worktree·PR 단위로 동시 지휘하는 데스크톱 앱. Conductor 스필오버 후보.
  • slop-free zone — "AI 슬롭이 없는 구역". 사람이 직접 쓴/검증한 코드 경계. (전사 slot free zones → 교정)
  • Tauri — 네이티브 웹렌더러(여기선 Safari)로 가벼운 데스크톱 앱을 만드는 프레임워크. (전사 towery app → 교정)
  • Parakeet — 로컬에서 도는 음성인식(STT) 모델(NVIDIA). 그가 control+space 받아쓰기에 사용.
  • Context7 MCP — 라이브러리 최신 문서를 LLM에 물려주는 MCP 서버. (전사 context seven → 교정)
  • GStack / GSD (Garry Tan) — 스킬을 1급 시민으로 다루는 셋업. "Gary mode"의 영감.
  • Elixir/Phoenix — Conductor 웹앱이 쓰는 함수형 언어/프레임워크.
  • malleable software — "주물러 바꿀 수 있는 소프트웨어". 비디오게임 모드(mod)처럼 사용자가 워크플로를 바꿔 쓰는 개념.

화자의 디테일 (놓치기 쉬운 포인트)

화자가 흘리듯 말한 구체 수치·설정·도구·뉘앙스. 이게 진짜 알맹이.

  1. $20 구즈넥 마이크(Amazon) — 오픈플로어 사무실에서 컴퓨터에 말 걸 때 덜 방해되게. 팀 전원이 샀다. "PR 3475 머지해줘"를 속삭이듯.
  2. 키보드 단축키 광 — 모든 동작에 단축키. 새 작업 command N, 워크스페이스 이동 command shift Y.
  3. caveman mode — Conductor에서 드물게 손으로 파일을 직접 고칠 때 켜는 모드. "이름값 하는 모드"라며 거의 안 씀(주로 하이라이트+코멘트나 음성으로 지시).
  4. 음성 스택 — control+space에 Spokenly[?]로 받아쓰기, 로컬 Parakeet 모델 구동. RAM 128GB 머신(로컬 모델 구동용). 동시에 최저 사양 MacBook Neo[?]를 일부러 주문 — 저사양 강제 적응용.
  5. OpenClaw[?]를 Telegram으로 대화(최근 추가). (전사 open claw → 교정)
  6. CLAUDE.md 수백 줄 + 스킬 파일 — 예: "엔지니어링 관행: 우리는 스타트업이다. 너는 엔터프라이즈 코드에 익숙하겠지만 우리는 그렇게 안 한다." 같은 규칙을 시간 들여 축적. (전사 cloud MD → CLAUDE.md)
  7. 상시 fast mode — "토큰 맥싱하려면 fast mode 필수". 기본값 아님.
  8. 상시 --dangerously-skip-permissions — "기본값 아닌데, Conductor에선 이게 Claude 실행 기본".
  9. slop-free zone 운영 — 코드베이스에 do not touch if you are an AI / this is for human eyes only 라인. AI도 기여 가능하지만 모든 줄을 사람이 읽어야 함. 안 그러면 AI가 나쁜 코드→더 나쁜 코드 악순환(반대로 선순환도).
  10. Conductor 스택 — Tauri(네이티브 Safari 렌더러), 백엔드는 기술적으로 Rust지만 데스크톱 앱은 TS 90~95%. 웹앱은 Elixir/Phoenix(로그인만 되는 작은 앱) — 그는 Elixir 광팬.
  11. 워크스페이스 = worktree 추상화 — 지금은 git worktree 위 추상화(곧 바뀔 예정). 이 개념조차 사람이 설계.
  12. 토큰 맥싱 수치 — 최고 지출은 2025년 7월 Conductor 시작기 월 $22,000(이전 세대 모델, 그 달 코드 수만 줄). 단 라인 수는 최소로 유지("코드베이스가 통제 불능으로 불어난다").
  13. 6개월 전과 달라진 점 — 예전엔 어려운 PR에 IDE 열어 손수정 + GitHub 웹앱 많이 씀. 지금은 Conductor 안에서 리뷰·코멘트. PR 체크용 checks 탭을 최근 추가.
  14. Gary mode — Garry Tan용 전용 모드: 툴콜을 기본 접지 않고 다 보여줌, Gary 얼굴까지 표시. (전사 Gary → Garry Tan)
  15. 확신 구축법 — A/B·애널리틱스 거의 안 봄. 매일 직접 써보며 gut feel로 결정(도그푸딩).
  16. 곧 올 변화 — 에이전트가 10배 길게·10배 똑똑하게 돌고, 내 노트북 CPU에 묶이지 않는 환경 필요 → 그래서 Claude(클라우드) 워크스페이스에 투자.

# 섹션 요지
1 세팅·하드웨어 구즈넥 마이크·음성받아쓰기·128GB·단축키 광
2 워크플로 command N으로 작업 던지고 사이드바에서 PR 리뷰·머지. 상태(진행/리뷰/완료) 대시보드
3 커스터마이징 CLAUDE.md·스킬·fast mode·dangerously 권한·Context7 MCP
4 경계 설계 slop-free zone, "AI를 아키텍트로 두지 마라", 사람이 만든 API/계약
5 모델 선택 Opus=창의적 파트너, Codex=워크호스
6 철학 코드는 톱밥, 프롬프트가 자산, malleable software

1. 세팅과 워크플로

여러 에이전트를 동시에 굴린다. command N으로 새 작업을 음성으로 던지고("최신 linear 이슈 보고 대략 어떻게 풀지 초안 줘"), 다른 채팅으로 넘어간다. 사이드바에서 준비된 워크스페이스를 열어 Claude에게 빠른 리뷰를 받고, 어색하면 GitHub 스타일 코멘트를 달아 다시 굴린다. 상태는 진행→(PR 생성)리뷰→(머지)완료 폴더로 흐른다. 멘탈모델은 작은 회사의 CEO — 에이전트들이 소화 가능한 보고서를 올리면 방향을 잡아주거나 머지한다.

2. 경계 설계 — 이게 핵심

  • slop-free zone: 사람이 쓴 영역을 명시하고 AI 기여분도 전 줄 사람 검수. 악순환 차단.
  • "don't let the AI be your architect": 워크스페이스 개념·좌(채팅)·중(대화)·우(코드리뷰/앱실행) 같은 UI는 사람이 오래 고민해 crafted 느낌을 냄. AI에 UI를 맡기면 그 느낌이 사라진다.
  • 워크플로 강제: 직접 편집 불가, 워크스페이스는 반드시 worktree→PR→merge.
  • 개선 중: 핵심은 사람이 쓴 API·계약 위에 짓고, 큰 덩어리는 AI 자유 영역으로. 지금 경계가 모호한 게 숙제.

3. 모델 선택과 철학

  • Opus: 더 창의적, 파트너 같음 → 새 기능 설계 때 본능적으로.
  • Codex: 워크호스. 툴콜 잔뜩·오래 디버깅도 마다 않음 → "이제 끝내자" 때.
  • 왜 터미널만으론 부족?: 인간은 공간·시각적 동물. 80년대에 GUI로 옮긴 이유가 있다. CLI는 AI 두뇌엔 맞아도 사람에겐 제약적.
  • 코드는 톱밥: 예전엔 코드를 깎아 만들었지만 이제는 원하는 걸 서술하고 코드는 그 부산물. 차세대 모델 나오면 프롬프트만 다시 돌리면 됨 → 남는 자산은 프롬프트.
  • malleable software: prompt request 기능은 그 초기 실험. 비디오게임 모드처럼, 구조는 같되 사용자가 자기 워크플로를 얹어 쓰게.

안녕하세요, 저는 Conductor 공동창업자 Charlie입니다. Conductor는 Mac에서 여러 코딩 에이전트를 오케스트레이션하게 해주는 앱이고, 저희는 YC 2024 여름 기수였어요. 제 세팅을 보여드릴게요.

최근 없으면 못 사는 게 이 구즈넥 마이크예요. Amazon에서 $20. 다들 컴퓨터에 더 많이 말 걸려고 하잖아요. 오픈플로어 사무실은 좀 산만한데, 이걸로 몸을 기울여 Claude[?Cloud]에게 속삭이듯 "PR 3475 머지해줘" 하면 덜 방해돼요. 더 많이 말 걸게 하려고 팀 전원이 샀죠.

저는 하루 대부분을 Conductor 안에서 보내요. Conductor로 Conductor를 만들죠. 늘 새 작업을 던집니다 — 계속 command N. (방금 살짝 보인 건 작업 중인 Claude[?Cloud] 워크스페이스예요.) command N 누르고 컴퓨터에 말해요 "최신 linear 이슈 보고 어떻게 풀지 대략 초안 줘" 하고 엔터. 사이드바에서 도는 게 보이고, Claude가 일하는 동안 다른 채팅으로 가요. 단축키 광이라 모든 걸 단축키로 — 여기선 command shift Y. 머지 준비된 워크스페이스를 열어 Claude에게 빠른 리뷰를 받아요. 작은 PR이면 괜찮아 보이지만, 종종 Claude가 정확히 못 맞히면 GitHub 스타일로 "이 부분 좀 이상한데 왜 필요해?" 코멘트 달고 엔터, 다시 굴리고 다른 워크스페이스로.

Conductor 사용의 큰 부분은 실험이에요. 늘 워크스페이스를 띄워 아이디어를 시험하죠. 리뷰 중인 PR 4개에 더해, 빛을 못 볼 수도 있는 잡다한 시도가 진행 중이에요. 맘에 들면 internal 세팅, 그다음 experimental 세팅으로 승격돼요.

흥분되는 건 이동 중에도 폰에 말하는 거예요. "테마를 hacker mode로 바꾸는 기능 추가하자" 하고 conduct, run 누르면 컴퓨터가 일을 시작해요. 이동 중에도 지휘(conduct)할 수 있죠.

— 아직도 코드 직접 쓰나요? — 아뇨, 거의. 아주 가끔 Tailwind 클래스 수정이나 .env 파일 바꾸려 IDE를 열어요. 실은 그럴 때 켜는 caveman mode라는 걸 만들었어요 — 클릭하면 키보드로 직접 타이핑·파일 수정 가능. 가끔 손으로 고쳐야 할 때가 있지만, 이름값 하는 모드라 거의 안 써요. 보통은 하이라이트+코멘트나 음성으로 "그 버튼 좀 넓어 보여, 줄여줄래?" 지시해요.

방금 이건 머지 준비됐네요. archive 누르면 사이드 패널에서 사라지고 코드베이스에 머지돼요. 이건 체크가 도는 중이라 끝나면 merge 누르면 들어가고요. 최근 좌측에 status 개념을 넣었어요 — 시작되면 진행(in progress), PR 생기면 리뷰(in review), 머지되면 완료(done) 폴더로. dashboard 페이지에선 한곳에서 모든 에이전트가 뭘 하는지 보고 다음 행동으로 넘길 수 있어요. 인터페이스는 아직 만지작거리는 중이고요. 이상은 작은 회사의 CEO 같은 느낌 — 에이전트들이 일하고 소화 가능한 보고서를 올리면 방향을 잡아주거나 좋으면 머지.

— 다른 주력 앱은? — Telegram으로 제 OpenClaw[?open claw]랑 꽤 대화해요(최근 추가). 음성→텍스트는 Spokenly[?]를 쓰는데 control+space로 뜨고, 실은 로컬 모델을 돌려요 — Parakeet. 컴퓨터를 빵빵하게 맞춰서 RAM 128GB예요, Parakeet 같은 로컬 모델 돌리려고요. 여담으로 최근 최저 사양 MacBook Neo[?]를 주문했어요 — 일부러 가장 낮은 스펙을 쓰게 강제하려고.

— 그래도 고수하는 커스터마이징은? — 몇 가지요. 저흰 스킬 파일과 CLAUDE.md[?cloud MD]에 시간을 많이 써요. 열어보면 수백 줄은 될 거예요. 예컨대 "엔지니어링 관행: 우린 스타트업이다. 넌 엔터프라이즈 코드에 익숙하겠지만 우린 그렇게 안 한다" 같은 것들을 시간 들여 넣었죠. 그리고 저는 항상 fast mode를 써요. 기본값 아니에요. 토큰 맥싱하려면 fast mode여야 해요. Context7 MCP[?context seven]도 써요, 문서 가져오는 데 유용하죠. 그 외엔 대부분 기본 그대로 써요. 핵심 하나는 항상 Claude를 dangerously accept all permissions로 실행한다는 것 — 기본값 아닌데, Conductor에선 그게 Claude 실행 기본이에요.

정말 중요한 건 명확한 경계예요. 저흰 slop-free zone[?slot free zones]이라 불러요. 코드베이스나 문서에서 사람이 쓴 게 확실한 부분. AI가 그 구역에 기여할 순 있지만 모든 줄을 사람이 읽어야 해요. 안 그러면 AI가 나쁜 코드를 보고 더 나쁜 코드를 쓰는 악순환에 빠질 수 있거든요(반대 방향 선순환도 가능). 코드베이스에 AI라면 손대지 마 / 이건 사람 눈 전용 같은 줄도 있어요.

— Conductor 기술 스택은? — Tauri[?towery] 앱이라 네이티브 Safari 웹렌더러를 써요. 백엔드는 기술적으론 Rust지만 거의 다 TypeScript로 써서 데스크톱 앱은 90~95% TS예요. 웹앱은 Elixir/Phoenix고요 — 지금은 로그인만 되는 아주 작은 앱이지만 저는 Elixir 광팬이라 늘 코드베이스에 Elixir를 더 넣자고 밀어요.

또 하나는 "AI를 네 아키텍트로 두지 마라"예요. 사이드바의 워크스페이스 개념조차 지금은 worktree 위 추상화인데(곧 바뀔 예정) 그 개념을 사람이 고민해 정했어요. 디자인·인터페이스 결정도요 — 좌측 채팅들, 가운데 대화, 우측에서 코드 변경 리뷰·앱 실행. 여기 많은 고민을 넣었죠. AI에 UI 선택을 맡기면 crafted 느낌이 안 나는 결과가 나와요. 예컨대 이 open-end 버튼 동작도 오래 고민했는데, 지금은 많은 앱이 같은 패턴을 써요. 처음엔 상단바에 아이콘 보여주는 걸 반대했어요(다른 앱 광고처럼 느껴져서) — 근데 지금은 좋아해요, 클릭 시 뭐가 일어날지 시각적으로 분명하니까.

다르게 했다면 — 앱의 핵심을 사람이 쓴 API와 계약 중심으로 짓고 AI 기여를 줄였을 거예요. 그리고 코드베이스 큰 덩어리는 AI 자유 영역으로 둬서 온갖 아이디어를 던져도 핵심 인프라엔 영향 없게요. 지금은 경계가 좀 모호한데, 개선 중이에요.

저흰 프런티어보다 살짝 앞서 사람들의 컴포트존을 좀 더 밀어붙이는 걸 중요시해요. Conductor 처음 출시 때 대부분 피드백이 "미쳤다, 난 Claude Code 하나도 겨우 관리하는데 3개, 5개를 어떻게?"였죠. 그리고 일부러 직접 파일 편집 불가로 만들었어요 — 워크스페이스는 항상 worktree여야 하고, PR을 만들고, 머지해야 해요. 워크플로를 강제하는 거죠.

지금이 신나면서도 어려운 건 모델이 가는 방향에 끊임없이 적응해야 한다는 거예요. 그래서 지금 Claude(클라우드)에 공을 들여요 — 지금은 노트북을 닫으면 에이전트가 멈추지만, 곧 에이전트가 10배 길게·10배 똑똑하게 돌고, 네 CPU에 묶이지 않는 환경이 필요한 세상으로 빠르게 가니까요.

— 매우 의견 강한 방식으로 Conductor를 만드는데, 확신은 어떻게? — 좋은 질문이에요. 특히 우리 사용자층은 설정 자유도를 많이 원해요. 도구가 유연하고 내 것처럼 느껴지는 건 중요하죠. 근데 우리가 확신을 쌓는 법은 우리가 강제로 매일 쓰는 것 — 실은 강제도 아니고 그냥 매일 써요. 안 맞으면 빨리 알아채죠. A/B 테스트나 애널리틱스를 크게 안 봐요. gut feel — 클릭했을 때 가운데에서 열리는 게 맞다고 느껴지면, 별도 composer 없이 여기서 메시지 치고 다 통일된 느낌이 들면 그게 맞는 거예요.

— Conductor가 Codex도 지원하는데 언제 Codex로? — 최근 Codex를 더 써요. Codex는 워크호스예요. 특정 문제를 밀어붙이고, 툴콜 잔뜩에 오래 디버깅도 마다 않죠. Claude는 좀 더 주거니 받거니 하고 싶을 때. Opus는 좀 더 창의적이고 파트너 같아서, 새 기능을 설계할 땐 본능적으로 Opus, 이제 끝내자 싶으면 Codex.

— 그냥 터미널론 부족한가요? — 80년대에 터미널에서 GUI로 옮긴 데는 이유가 있어요. 인간은 공간적·시각적 동물이라 CLI는 제약적으로 느껴져요. AI 두뇌엔 더 맞을지 몰라도 사람 두뇌엔 아니죠. "내 채팅은 여기, 리뷰 패널은 여기, AI랑은 가운데서 대화" 식으로 알고 싶어요. 터미널로 못 하는 게 UI론 많기도 하고요.

— 토큰 맥싱 얘기. 하루 코드 라인 또는 월 지출 최고 기록은? — 최고 지출은 2025년 7월 Conductor 시작 때 월 $22,000. 이전 세대 모델이었고 그 달 코드가 수만 줄이었죠. 저흰 토큰 맥싱엔 진심이에요 — fast mode, think extra hard, 항상 high effort. 근데 라인 수엔 진심 아니에요. 오히려 최소로 유지하려 해요. 안 그러면 코드베이스가 통제 불능으로 불어나거든요. 다만 새 앱을 시작할 때와 Conductor 같은 기존 코드베이스는 다르게 봐요.

— 6개월 전과 달라진 워크플로? — 예전엔 어려운 PR에 IDE 열어 손수정하고 GitHub 웹앱도 많이 썼는데, 지금은 훨씬 덜 써요. Conductor 안에서 코드 변경을 리뷰하고 필요하면 코멘트 달죠. PR 체크가 많이 도는데, 그래서 최근 checks 탭을 추가해 GitHub 코멘트를 Conductor로 가져와요.

— 남이 Conductor로 한 가장 놀라운 것? — 누가 모바일 버전 Conductor를 만들었어요. 데스크톱 앱에 IPC 콜을 spoofing하는 식인데 어떻게 도는지 저도 잘 몰라요. 그리고 Garry[?Gary]가 Conductor의 가능성을 많이 보여줬어요. 그에게 스킬을 얼마나 세게 밀어붙일 수 있는지 배웠죠 — GStack에선 스킬이 1급 시민이에요. 특히 온보딩 쪽에 흥미로운 아이디어가 있고요. 그를 위해 Gary mode라는 전용 모드를 넣었는데, 기본적으로 툴콜을 접지 않고 다 보여줘요. 심지어 Gary 얼굴도 보이죠.

— 너희 팀엔 당연한데 세상은 아직 모르는 것? — 인간과 AI의 협업에 탐험할 멋진 게 많아요. 서브에이전트와 대화할 수 있어야 할까? 여러 사람이 AI와 같은 일을 하는 멀티플레이어 채팅은? 자주 쓰는 비유는 오케스트라의 지휘자(conductor) — 지휘봉을 흔들면 악기들이 한 호흡으로 연주하고, 가끔 트럼펫에게 "음 안 맞아", 현악 섹션엔 "좀 더 빠르게" 하지만 대부분은 오케스트라 레벨에서 지휘하죠.

코드는 이제 거의 톱밥(sawdust) 같아요. 예전엔 코드가 곧 만드는 대상이고 구조였고, 시간을 들여 깎았죠. 지금은 원하는 걸 어떻게 만들지 서술하는 데 시간을 쓰고 코드는 그 과정의 부산물이에요. 흥미로운 결론들로 이어지죠 — 정말 중요한 건 네 프롬프트예요. 차세대 모델이 나오면 프롬프트를 다시 돌려 새 코드를 얻으면 되고, 옛 코드는 별로 안 중요했던 거예요. 세상이 천천히 깨닫는 중이죠. prompt request 기능은 malleable software(주물러 바꾸는 소프트웨어)의 초기 실험이에요. 제가 늘 떠올리는 비유는 비디오게임 — Call of Duty처럼 구조는 같되 커스텀 스킨이나 빠른 재장전 같은 mod를 얹잖아요. 저는 여러분이 Conductor를 mod해서 자기 워크플로를 얹길 바라요. 구조는 같게 느껴지되 — 사람들은 crafted되고 충분히 고민된 소프트웨어를 원하니까 — 게임 mod가 게임을 더 내 것처럼 만들듯, 소프트웨어에도 그런 일이 일어날 거예요.
