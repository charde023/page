Claude 활용은 "질문 한 번 던지고 끝"인 아마추어 단계에서 프로젝트·커넥터·스킬·Claude Code·자율 에이전트 오케스트레이션까지 6단계로 성장하며, 각 단계마다 사람의 역할이 "직접 하는 사람"에서 "지시하는 사람", 결국 "루프 위에서 관망하는 사람"으로 바뀐다.

핵심 학습 포인트 (내가 배워야 할 것)

개념 왜 중요한가 한 줄
Claude 6단계 레벨 지금 내가 어느 단계인지 진단하고 다음 단계를 목표로 잡을 수 있음 아마추어→정규→통합자→운영자→빌더→에이전트 오케스트레이터
프로젝트 (Projects) + 마스터 프롬프트 Claude가 매번 나를 "처음 보는 사람"처럼 대하지 않게 함 역할별 작업공간 + 나에 대한 정보 파일
시스템 프롬프트 (System Prompt) 같은 품질·형식으로 반복 산출물을 뽑는 핵심 "재료(마스터 프롬프트)"가 아니라 "레시피"
커넥터 (Connectors) Gmail·Drive·Slack·Notion을 오가며 복붙하는 낭비를 없앰 Claude가 도구 안에서 일하고 결과만 가져옴
스킬 (Skills) 주 3회 이상 반복하는 작업은 슬래시 명령으로 고정 /회사현황 식으로 반복작업 자동화
플랜 모드 (Plan Mode) 코드 짜기 전에 계획부터 승인받아 비용·시행착오를 줄임 /plan → 질문 받고 계획 승인 후 실행
에이전트 오케스트레이션 사람이 "루프 안"이 아니라 "루프 위"에 있게 되는 마지막 단계 메인 에이전트가 서브 에이전트들을 지휘

내가 모를 만한 것 / 처음 보는 것

  • Projects(프로젝트) — Claude의 작업공간 기능. 역할·클라이언트·이니셔티브별로 별도 공간을 만들어 파일과 맥락을 저장해두면 매번 설명을 반복하지 않아도 됨.
  • 마스터 프롬프트(Master Prompt) — "나는 누구고 어떻게 일하는지" 전체를 담은 파일. Claude에게 "인터뷰해서 만들어줘"라고 하면 질문을 받아가며 자동 생성됨.
  • 시스템 프롬프트(System Prompt) — 특정 워크플로우의 "레시피"(절차·형식·품질기준). 마스터 프롬프트(재료·맥락)와 구분되는 개념. 완성되면 프로젝트의 커스텀 인스트럭션에 붙여넣어 매번 같은 품질을 재현.
  • Connectors(커넥터) — Claude를 Gmail·Calendar·Drive·Slack·Notion 등 외부 툴에 직접 연결하는 기능. 연결 후엔 대화 중 해당 데이터 소스를 검색·참조 가능.
  • 아티팩트(Artifacts) — 대화 안에서 만드는 클릭 가능한 미니 앱(슬라이더·버튼 등 인터랙티브 요소 포함).
  • Composer — 채팅 안에 있는 "Google Docs 같은" 문서 편집 공간. 텍스트를 붙여넣고 그 자리에서 직접 편집·조정 가능.
  • Claude in Chrome — 브라우저 확장. 채팅에서 만든 지시문을 그대로 특정 웹사이트 안에 붙여넣어 Claude가 대신 작업을 수행하게 함.
  • Skills(스킬) — 반복 워크플로우를 슬래시 명령(/이름)으로 저장해 즉시 재실행. Claude가 기본 제공하는 스킬도 있고, 회사 고유 프로세스로 직접 만들 수도 있음.
  • Co-work(코워크) — 컴퓨터에서 실행되는 앱으로, 컴퓨터를 사실상 대신 조작해 장시간 작업(예: 시스템 마이그레이션)을 예약 실행할 수 있음.
  • 스킬 체이닝(Chaining Skills) — 여러 개의 개별 스킬(예: 카피라이팅 스킬 + 이메일 작성 스킬)을 상위 스킬(예: 받은편지함 자동화) 안에서 서로 호출하도록 연결하는 방식.
  • Claude Code — 코드를 직접 작성해 앱·대시보드·내부 툴을 만드는 레벨의 Claude. 화자는 이 레벨 사용자가 전체 이용자의 0.04%뿐이라고 언급(출처 미검증, 화자 주장).
  • Loops(루프, Claude Code 맥락) — 서버에서 상시로 돌아가며 다른 에이전트·시스템·API와 통신하는 반복 작업. Co-work보다 더 고급 형태.
  • Tools(툴, 일회성) — 특정 프로젝트·상황을 위해 한 번 쓰고 버리는 용도로 만드는 코드 산출물.
  • Apps(앱) — 실제 프로덕션 수준 소프트웨어. 화자의 해커톤 사례에서 비개발자 직원(하우스 매니저 Betty)이 개인 업무 전체를 관리하는 시스템을 직접 만든 예시가 소개됨.
  • Plan Mode(플랜 모드) — /plan 명령으로 아이디어를 던지면 Claude가 필요한 질문을 하고, 코드 작성 전에 완성된 계획을 먼저 승인받는 기능.
  • Claude Code Remote(리모트 컨트롤) — 터미널에서 /remote 명령으로 폰의 Claude 앱과 연결해, 노트북을 떠나도 이어서 코드 작성 진행 상황을 확인·개입 가능.
  • 에이전트 오케스트레이터(Agent Orchestrator) — 메인 에이전트(예: 화자의 "카이") 아래 여러 서브 에이전트를 두고, 메인이 서브들에게 업무를 지시·취합하는 구조. 사람은 "루프 안"이 아니라 "루프 위"(human on the loop)에 위치.
  • Apex — 화자가 언급한 자체 플랫폼(apex.host). 내부적으로 Claude를 메인 에이전트 모델로 쓰되, 보안성과 조작 편의성을 더한 래퍼로 소개됨(제품 홍보성 언급, 객관적 검증 필요).
  • 크리틱 에이전트(Critique Agent) — 메인 에이전트가 결과물(카피·리서치 등)을 다시 검토받기 위해 호출하는 별도 에이전트. 개선 노트를 만들어 원 에이전트에 돌려주고 재작업시킴.

화자의 디테일 (놓치기 쉬운 포인트)

화자가 흘리듯 말한 구체 수치·설정값·명령어·뉘앙스.

  1. "Claude와 1,000시간 이상 사용" (Over 1,000 hours) — 화자가 스스로 밝힌 누적 사용 시간. 검증 불가한 자기소개성 수치.
  2. "NASA 슈퍼컴퓨터로 2+2 계산하는 격" — 아마추어 단계(단발성 질문만 던지는 사용)를 빗댄 비유. 활용도가 5% 수준이라고 주장(근거 미제시).
  3. "체크 유어 워크(check your work)" 한마디 — 화자가 매일 쓰는 검수 트리거 문구. Claude가 자기 실수를 스스로 잡아내게 함.
  4. "인터뷰해서 마스터 프롬프트 만들어줘" — 프로젝트 설정 시 사용하는 실제 프롬프트 문구(원문: interview me to build a master prompt for my role).
  5. "YouTube OS" — 화자가 인스타그램 DM으로 배포한다는 무료 AI 회사 운영체계(AI Company OS) 플레이북 이름. 홍보성 언급.
  6. "주 3회 이상 하면 스킬로 만든다" — 화자의 개인 규칙(자신이 스킬화 여부를 판단하는 기준).
  7. "매일 밤 8시 리마인더" — 화자가 co-work/스케줄 기능으로 다음 날 이메일·캘린더 요약을 자동으로 받는다는 사례. "실제로 비서(chief of staff)가 있지만 이 자동화는 그와 별개로 직접 세팅했다"는 뉘앙스.
  8. "산악자전거 타다가 버금(berm)에서 앞바퀴가 미끄러진 순간에도 Remote로 코드 작업 3~4번" — Claude Code Remote 사용의 구체 일화. 부상(추정)과 연결지어 극단적 사용 사례를 강조.
  9. "AI 해커톤으로 이틀간 회사 전체 업무 중단, 전 직원이 코딩을 배움" — 빌더 레벨 도입 사례. 하우스 매니저 Betty가 비개발자임에도 실제 프로덕션 시스템을 만들었다고 언급.
  10. 메인 에이전트 이름 "카이(Kai)", 부동산 서브에이전트 "리스(Reese)" — 화자의 실제 에이전트 오케스트레이션 구조 예시. 카이는 직접 일을 하지 않고 서브에이전트들을 지휘·보고 취합만 한다고 설명.
  11. "apex.host" — 화자가 언급한 자체 에이전트 플랫폼 도메인(제품 홍보 성격, 검증 필요).
  12. "30일 동안 한 가지 기능만 매일 연속 사용해보라"는 마무리 챌린지 — 시청자에게 실천을 유도하는 구체적 액션 아이템.

# 섹션 요지
1 레벨 1: 아마추어 Claude를 "고급 구글 검색"처럼 씀. 인터뷰 요청 + 자기검수 요청 2가지 팁으로 탈출
2 레벨 2: 정규 사용자 Projects로 역할별 작업공간 구축. 마스터 프롬프트·시스템 프롬프트·파일 첨부 3단계
3 레벨 3: 통합자 Gmail·Drive·Slack·Notion 커넥터 연결, 시각화·아티팩트·Composer·Claude in Chrome 활용
4 레벨 4: 운영자 시스템 프롬프트·스킬·Co-work 스케줄링으로 반복 업무를 위임. 스킬 체이닝으로 파이프라인 구성
5 레벨 5: 빌더 Claude Code로 루프·툴·앱을 직접 만듦. Plan Mode와 Claude Code Remote 활용
6 레벨 6: 에이전트 오케스트레이터 메인 에이전트가 서브 에이전트들을 지휘. 사람은 "루프 위"의 감독자로 이동
7 마무리 챌린지 기능 1개를 골라 30일 연속 사용하는 습관화를 제안

1. 레벨 1: 아마추어

아마추어는 Claude를 질문 한 번 → 답변 한 번 받고 탭을 닫는 방식으로 쓴다. 메모리도 없고 프로젝트도 안 쓰기 때문에 Claude는 사용자가 무슨 일을 하는지 전혀 모른다. 화자는 이를 "NASA급 슈퍼컴퓨터로 2+2를 계산하는 것"에 비유하며 활용도가 5% 수준이라고 표현한다(구체 근거는 제시되지 않음, 화자의 주관적 평가).

탈출 팁 2가지: - 답하기 전에 나를 인터뷰하게 하기 — "답하기 전에, 이 작업을 제대로 하려면 필요한 질문을 먼저 해줘"라고 지시하면 Claude가 맥락 파악용 질문을 던진다. - 자기검수 시키기 — "체크 유어 워크(check your work)"라고만 말해도 Claude가 스스로 오류를 잡아내며 결과물 품질이 올라간다.

2. 레벨 2: 정규 사용자 — Projects로 지속 기억 만들기

정규 사용자는 Claude를 대화 상대가 아니라 작업공간(workspace)으로 쓴다. Projects(프로젝트) 기능을 역할별·이니셔티브별·클라이언트별·워크플로우별로 만들어, 매번 돌아올 때마다 Claude가 사용자를 기억하게 한다.

설정 3단계: 1. 새 프로젝트 생성 — 좌측 메뉴에서 New Project, 이름은 자신의 역할(예: marketing)로. 2. 마스터 프롬프트(Master Prompt) 만들기 — "내 역할(마케터)을 위한 마스터 프롬프트를 만들도록 나를 인터뷰해줘"라고 요청하면, Claude가 질문하고 그 답으로 파일 하나(마스터 프롬프트)를 만들어준다. 이 파일에는 나에 대한 모든 것(일하는 방식·팀 구성·사용 툴 등)이 담긴다. 3. 파일 추가 — 마스터 프롬프트 외에 샘플 데이터·예시·프로세스 문서 등을 프로젝트 파일 디렉토리에 추가한다.

화자는 자신의 유튜브 영상 기획 프로젝트 예시를 든다 — 보이스 문서, 브랜딩 문서, 과거 스크립트 예시를 파일로 넣어두면, 방향만 지시해도 과거 스타일에 맞는 아웃라인이 나온다는 것.

프로 팁 — 시스템 프롬프트(System Prompt): "특정 워크플로우를 위한 시스템 프롬프트를 만들도록 나를 인터뷰해줘"라고 요청. 마스터 프롬프트가 "재료(나에 대한 정보)"라면, 시스템 프롬프트는 "레시피(절차·형식)"다. 완성된 시스템 프롬프트를 프로젝트의 커스텀 인스트럭션에 붙여넣으면 매번 같은 품질·형식으로 결과가 나온다.

(화자는 이 지점에서 "AI Company OS"라는 자신의 무료 배포 플레이북을 언급 — 홍보성 내용이라 그대로 신뢰하기보다는 참고용으로만 받아들일 것.)

3. 레벨 3: 통합자 — 도구가 있는 곳으로 Claude를 연결

통합자는 Claude를 실제 업무가 벌어지는 도구(이메일·캘린더·드라이브·브라우저)에 연결한다. 굳이 이메일을 복사해서 Claude에 붙여넣을 필요 없이, Claude가 직접 도구에서 정보를 가져오게 한다는 것이 핵심.

운영 방법: 1. 커넥터(Connectors) 연결 — Gmail·Drive·Slack·Notion 등을 연결하면, 대화 중 해당 시스템을 검색해 활용할 수 있다. 2. 시각화(Visualization) 활용 — 채팅 안에서 그래프·막대차트·목업 등을 바로 만들 수 있는 기능. 3. 인터랙티브 아티팩트(Artifacts) — 클릭 가능한 미니 앱, 슬라이더·버튼 등을 포함한 산출물. 4. Composer 활용(숨은 팁) — 텍스트를 붙여넣고 "Composer 안에 넣어줘"라고 지시하면 채팅 내 Google Docs 같은 편집 공간이 열려, 그 자리에서 다듬을 수 있다.

화자는 자신의 Claude가 Drive·Slack·캘린더·이메일과 연결돼 있어 "내 캘린더 봐줘, 놓친 거 알려줘", "이메일 봐줘, 알아야 할 거 알려줘", "슬랙 지난 1주 스캔해서 CEO 시각으로 요약해줘" 등을 거의 매일 사용한다고 언급.

프로 팁 — Claude in Chrome 설치: 채팅에서 만든 작업 지시문을 복사해 Chrome 확장 안 특정 사이트에 붙여넣으면 Claude가 대신 실행한다.

4. 레벨 4: 운영자 — 일을 시키는 사람이 되기

운영자는 더 이상 "직접 하는 사람(doer)"이 아니라 "지시하는 사람(director)"이다. 화자는 이를 "human in the loop"(사람이 루프 안에서 검토·승인)이라고 표현. 작업을 설정해두고 결과만 검토·승인하는 방식.

운영자가 Claude를 배치하는 3가지 방법: 1. 시스템 프롬프트 — 반복 산출물마다 시스템 프롬프트를 만들도록 인터뷰시킴. 화자는 "앞으로 팀·회사의 지적 자산 가치는 이런 시스템 프롬프트가 정의돼 있느냐에 달렸다"고 주장. 2. 스킬(Skills) — 반복하는 워크플로우를 슬래시 명령으로 저장. Claude는 재무·마케팅 등 기본 제공 스킬도 있지만, 회사 고유 프로세스는 직접 만든다. 화자의 규칙: 주 3회 이상 하는 일이면 스킬로 만든다. 예시로 "회사 현황(company status)" 스킬을 만들어 애널리틱스·리포트·팀 업데이트를 종합한 요약을 /company status 한 번에 받는다고 소개. 3. Co-work(코워크) 예약 작업 — 컴퓨터에서 실행되며 시스템 마이그레이션 같은 장시간 작업을 예약 실행할 수 있는 앱. "실행하고 저녁 먹으러 갔다 오면 끝나 있는" 방식.

프로 팁 — 스킬 체이닝(Chaining Skills): 카피라이팅 스킬 + 이메일 작성 스킬을 받은편지함 자동화라는 상위 스킬 안에서 서로 호출하도록 연결. 여러 개별 스킬이 하나의 파이프라인으로 연쇄된다.

5. 레벨 5: 빌더 — Claude Code로 직접 만들기

화자는 회사가 이틀간 업무를 멈추고 전 직원 대상 AI 해커톤을 열어 모두에게 코딩을 가르쳤다고 소개한다. 이 레벨에서는 Claude Code를 이용해 대시보드·내부 툴·커스텀 앱을 만든다. 화자는 "이 레벨에 이미 있다면 인구의 0.04%"라고 언급(근거 불명, 화자 주장 그대로 인용).

Claude Code 안에서 만들 수 있는 3가지 범주: 1. 루프(Loops) — 서버에서 상시로 돌아가며 다른 에이전트·시스템·API와 통신하는 반복 작업. Co-work보다 더 고급. 2. 툴(Tools) — 일회성 프로젝트를 위해 만드는 것. 영구적으로 쓸 게 아니라서 "일회용(disposable)"으로 간주. 3. 앱(Apps) — 실제 프로덕션 소프트웨어. 화자는 자신의 하우스 매니저 Betty(비개발자)가 부부의 생활 전반(차량·부동산·투자·예산)을 관리하는 시스템을 직접 만든 사례를 소개하며 "AI 시대엔 영어가 새로운 프로그래밍 언어"라고 강조.

프로 팁 1 — Plan Mode: 코드를 짜기 전 100% /plan을 사용한다는 화자의 규칙. 아이디어를 던지면 필요한 질문을 하고, 완성된 계획을 사용자가 승인한 뒤에야 코드를 작성한다. 화자는 "AI 앱 만드는 비용이 비싸다고 불평하는 사람들은 미리 계획을 세우지 않은 것"이라고 지적.

프로 팁 2 — Claude Code Remote: 터미널에서 /remote(원문: forward slash remote control)를 입력하면 폰의 Claude 앱과 연결돼 노트북을 떠나도 코드 작성이 이어진다. 화자는 산악자전거를 타다 사고 순간에도 폰으로 코드를 작성했다는 일화를 언급.

6. 레벨 6: 에이전트 오케스트레이터 — 팀원을 만드는 단계

오케스트레이터는 부서·프로세스·워크플로우 전체를 계속 돌리는 루프를 설계하는 사람이며, 더 이상 직접 관여하지 않는다. 화자는 이를 "human on the loop"(사람이 루프 위에서 지켜봄, 앞선 레벨4의 human in the loop과 대비)이라고 구분한다. Claude는 이제 도구가 아니라 인프라가 된다.

에이전트를 만드는 프레임워크(특정 방법 하나가 아니라 사고 틀): 1. 메인 에이전트 하나로 시작 — 화자의 예시는 "카이(Kai)"라는 CEO 에이전트. 실제로는 아무 일도 직접 하지 않고 다른 에이전트들을 지휘만 한다. 2. 전문 서브에이전트 생성 — 각 서브에이전트가 하나의 워크플로우를 담당하고, 메인 에이전트가 이들과 소통하며 지시한다. 3. 텔레그램 연결 — 폰으로 에이전트와 대화할 수 있게 연결. 화자의 부동산 서브에이전트 "리스(Reese)"가 투자 매물을 찾으면 카이가 매일 확인·보고를 취합해 화자에게 전달한다고 소개.

화자는 자체 플랫폼 "Apex"(apex.host)를 언급하며, 내부적으로는 Claude를 메인 에이전트 모델로 쓰되 보안성과 조작 편의성을 더한 것이라고 설명한다(제품 홍보 성격이 강해 객관적 검증은 별도로 필요).

프로 팁 — 크리틱 에이전트(Critique Agent): 메인 에이전트가 카피라이팅이나 리서치 등의 결과물을 별도 크리틱 에이전트에게 검토받도록 함. 개선 노트를 만들어 돌려주면 원 에이전트가 다시 작업해, 항상 최선의 결과물을 받는다는 구조.

전체 전사 펼치기

저는 Claude(원문 Cloud로 인식된 부분 전부 Claude로 교정) 안에서 1,000시간 넘게 시간을 보냈고, 매일 도구를 만들고 워크플로우를 돌리고, 심지어 수백만 달러짜리 회사를 론칭하는 데도 씁니다. 지금 여러분이 Claude를 쓰며 꽤 생산적이라고 느낄 수 있지만, 사실은 겉핥기만 하고 있는 거라면 어떨까요? 이 영상에서는 아마추어부터, 손 하나 까딱 안 해도 완전히 자율적으로 돌아가는 시스템을 만드는 사람까지, Claude 사용자의 모든 레벨을 훑어드리겠습니다.

레벨 1: 아마추어. 아마추어는 Claude를 고급 구글 검색처럼 씁니다. 질문 하나 던지고 답 받고 탭을 닫아버리죠. 메모리도 없고 프로젝트도 안 씁니다. Claude는 여러분이 뭘 하고 있는지 전혀 모르고, 여러분은 Claude가 할 수 있는 것의 5% 정도만 쓰고 있는 겁니다. NASA 슈퍼컴퓨터에 접속해서 2+2를 계산하는 격이에요. 이 레벨에 있다면, 레벨업할 팁 두 가지를 드릴게요.

첫째, Claude가 먼저 나를 인터뷰하게 만드세요. 예를 들어 "답하기 전에, 이 작업을 제대로 하려면 필요한 질문을 나에게 물어봐줘"라고 말하면, Claude가 최선의 답을 주는 데 필요한 맥락을 확보할 질문들을 던지는 걸 볼 수 있습니다.

둘째, Claude가 자기 작업을 스스로 검수하게 만드세요. 원래는 처음부터 그렇게 했으면 좋겠지만, "본인 작업을 확인해봐(check your work)"라고 매일 말하는 것만으로도 Claude가 자기 실수를 스스로 잡아내는 걸 볼 수 있고, 결과물이 더 좋아집니다.

다음 레벨로 가기 전에, 우리는 매번 처음부터 다시 시작하는 걸 멈춰야 합니다. 그럼 어떻게 Claude에게 지속적인 메모리를 갖게 할까요?

레벨 2: 정규 사용자. 정규 사용자는 Claude를 작업공간처럼 씁니다. 그냥 채팅만 하는 게 아니라, Claude 안에 있는 프로젝트(Projects) 기능을 자신의 역할에 맞게 씁니다. 이니셔티브별로, 클라이언트별로, 워크플로우별로 사용하죠. 멋진 건, Claude가 돌아올 때마다 여러분이 누구인지 기억해서 작업 결과가 점점 좋아진다는 겁니다.

제대로 세팅하는 방법입니다. 첫째, 왼쪽에서 "새 프로젝트 만들기"를 클릭하세요. 그리고 자신이 일하는 역할로 프로젝트 이름을 짓습니다. 예시로 "마케팅"이라고 해봅시다. 그게 여러분의 역할입니다.

둘째, 자신의 역할을 위한 마스터 프롬프트(master prompt)를 만들어야 합니다. 그래야 매번 대화할 때 Claude가 여러분이 누구고 뭘 이루려는지 알 수 있으니까요. 여기서 재밌는 부분은, "내 역할(마케터)을 위한 마스터 프롬프트를 만들도록 나를 인터뷰해줘"라고 입력하면 됩니다. Claude가 질문을 하고, 여러분이 답하면 파일 하나를 받게 되는데, 그게 바로 마스터 프롬프트입니다. 마스터 프롬프트란 AI에게 여러분에 대한 모든 것 — 일하는 방식, 팀 구성, 사용하는 도구, 역할에 대한 모든 것 — 을 알려주는 지시문 파일입니다. 그래야 답을 줄 때마다 그 정보를 활용해서 결과물을 만들 수 있습니다.

셋째, 파일을 추가해야 합니다. 마스터 프롬프트를 만들었으니, 프로젝트로 돌아가서 그걸 프로젝트 파일로 추가하세요. 그리고 회사 안에 있는 다른 문서들 — 샘플 데이터, 예시, 파일, 프로세스 — 도 마스터 프롬프트와 함께 파일 디렉토리에 넣으세요. 이제 메모리와 맥락을 갖춘, 여러분이 일하는 방식에 맞춘 특화된 공간이 생긴 겁니다.

예를 들어, 저는 유튜브 영상을 만들 때마다 아이디어 구상·아웃라인·전략을 도와주는 프로젝트 폴더가 있습니다. 파일 안에는 필요한 모든 걸 넣어뒀어요 — 제 보이스 문서, 브랜딩 문서, 제가 좋아하는 이전 스크립트 예시들. 과거에 제가 어떻게 해왔는지 기반으로 아웃라인을 만드는 데 필요한 모든 게 들어있습니다. 그리고 저는 그냥 방향만 지시하고 엔터를 치면, Claude가 아웃라인을 줍니다.

프로 팁을 드리자면, 프로젝트를 한 단계 더 끌어올리고 싶다면 이렇게 하세요. AI에게 여러분이 만들려는 특정 워크플로우를 위한 시스템 프롬프트(system prompt)를 만들도록 인터뷰해달라고 요청하세요. 마스터 프롬프트는 여러분의 재료 같은 겁니다 — 여러분에 대한 모든 것, 맥락 등이요. 시스템 프롬프트는 레시피입니다. 지시문이고, 프로세스입니다. 여러분은 이미 프로세스를 갖고 있을 텐데, 그냥 문서화한 적이 없는 것뿐이에요. 그래서 AI가 인터뷰해서 그 결과물을 뽑아주는 겁니다. 그걸 받으면, 시스템 프롬프트를 복사해서 커스텀 인스트럭션에 붙여넣고 이게 기계처럼 돌아가는 걸 지켜보세요. 그러면 그 프로젝트를 쓸 때마다 매번 똑같은 품질, 똑같은 형식을 유지할 수 있습니다.

그리고 만약 Claude나 어떤 AI든 회사의 모든 부서에 통합시키는 방법을 더 깊이 알고 싶다면, 제가 모든 사업에 쓰는 정확한 플레이북인 "AI 컴퍼니 OS(AI Company OS)"를 무료로 드립니다. 인스타그램에서 "YouTube OS"라고 DM 주시면 보내드릴게요.

자, 이제 프로젝트는 Claude를 프로세스와 함께 돌아가는 자동화된 책상 같은 작업공간으로 만들어줍니다. 그런데 그 밖의 것들은요? 이메일, 캘린더, 브라우저에서 해야 하는 일들 말이죠.

레벨 3: 통합자(Integrator). 통합자는 일이 실제로 이루어지는 도구들에 Claude를 연결합니다. 우리는 Gmail, Calendar, Drive, Slack, Notion을 씁니다. 통합자는 이것들을 Claude에 연결해서, 여러 도구와 탭을 오가는 걸 멈춥니다. 이메일을 복사해서 Claude에 붙여넣을 필요가 왜 있겠어요, Claude한테 직접 가져오라고 하면 되는데. 멋진 건 이제 Claude 안에서 액트(act)를 만들 수 있다는 겁니다. 통합자는 도구를 떠나지 않고, 도구 안에서 작업을 하고, 그 도구가 만든 정보를 필요한 곳으로 보냅니다.

통합자 레벨에서 일하는 방법입니다. 첫째, 커넥터(connectors)를 씁니다. Gmail, Drive, Slack, Notion 등 가지고 있는 모든 시스템을 연결하세요. 그러면 다음에 대화할 때 그 데이터 시스템들을 검색할 수 있는 능력이 생깁니다. 둘째, 시각화(visualization)를 만드세요. 이건 제가 Claude에서 가장 좋아하는 기능인데, 채팅 안에서 바로 그래프·막대차트·목업을 만들 수 있습니다. 그리고 더 좋은 건, 셋째로 인터랙티브 아티팩트(interactive artifacts)를 만드는 겁니다. 클릭 가능하고, 슬라이더와 버튼이 있는 작은 미니 앱 같은 거예요. 정보를 학습하거나 시각화하거나 다루는 걸 훨씬 쉽게 만들어줍니다.

그리고 아무도 얘기 안 하는 고급 기술 하나 — 텍스트를 채팅에 붙여넣고 그걸 컴포저(Composer) 안에 넣어달라고 지시할 수 있습니다. 채팅 안에 있는 구글 문서 같은 거죠. 그러면 원하는 대로 정확히 결과물이 나올 때까지 편집하고 다듬을 수 있습니다.

제 Claude는 구글 드라이브, 슬랙, 캘린더, 이메일에 연결돼 있습니다. 그래서 저는 항상 이렇게 말합니다. "내 캘린더 봐줘, 내가 놓친 게 뭔지 알려줘." "내 이메일 봐줘, 알아야 할 게 뭔지 알려줘." "나는 회사의 CEO야. 지난 1주일 슬랙을 스캔해서 회사 전체가 어떻게 돌아가는지 CEO 수준으로 이해할 수 있게 정리해줘." 이런 걸 거의 매일 실행해서 항상 상황을 파악하고 있습니다.

레벨업 팁을 원한다면, Claude를 Chrome에 설치하세요. 저는 하루 종일 씁니다. 종종 채팅이 저에게 뭔가를 해달라고 하면, "나를 위해 지시문을 써줘"라고 말하고, 그걸 복사해서 Chrome 안 Claude에 특정 사이트에서 붙여넣고 엔터를 치면, 저 대신 가서 작업을 해줍니다.

이건 다 정말 멋지지만, 사실 이 레벨에서 Claude는 그냥 여러분을 도와주는 것뿐입니다. 다음 레벨은, Claude가 실제로 우리 대신 일을 하는 곳입니다.

레벨 4: 운영자(Operator). 운영자는 더 이상 직접 하는 사람이 아니라 지시하는 사람이 되는 단계입니다. 저는 이걸 "human in the loop"라고 봅니다 — 운영자인 여러분이 이제 스스로 돌아가는 작업들을 세팅해두고, 검토하고 승인만 하는 거죠. 이제는 Claude를 그냥 쓰는 게 아니라, 문제를 풀도록 배치(deploy)하는 단계입니다.

운영자가 Claude를 배치해서 일을 시키는 세 가지 방법입니다. 첫째는 시스템 프롬프트입니다. 만들고 싶은 결과물 종류마다 Claude가 인터뷰해서 시스템 프롬프트를 만들게 하세요. 저는 미래의 지적 재산과 팀·회사의 가치는, 자신들이 만드는 것들에 대한 시스템 프롬프트가 정의돼 있느냐에 달려있다고 믿습니다.

둘째는 스킬(skills)입니다. 이런 워크플로우를 계속 반복하다 보면, 그걸 스킬로 저장할 수 있다는 걸 알게 됩니다. Claude에는 이미 설치할 수 있는 스킬이 많습니다. 재무 스킬, 마케팅 스킬 등 수백 개를 만들어놨어요. 하지만 여러분 회사 안에는 고유한 방식으로 하는 일들이 있을 수 있습니다. 그렇다면 슬래시를 만들고, 이름을 붙이고, 실행한 다음 그걸 스킬로 만드세요. 제 규칙은 이겁니다 — 일주일에 세 번 이상 하는 일이라면, 그냥 스킬로 만들어버립니다. 예를 들어 저는 항상 회사 안에서 무슨 일이 벌어지고 있는지 궁금해하는데, 그래서 회사 현황(company status) 스킬을 만들어서 모든 애널리틱스, 지표, 리포트, 모두의 업데이트를 분석해서 회사가 지금 어떤 상태인지 깔끔하고 간결한 업데이트를 줍니다. 그래서 그냥 슬래시 "회사 현황"이라고 치면 매번 해줍니다.

셋째는 코워크(co-work) 작업 스케줄링입니다. 코워크에 대해 들어보셨다면, 컴퓨터에서 실행되는 앱인데 말 그대로 여러분의 컴퓨터를 넘겨받을 수 있습니다. 그래서 "이 시스템에서 저 시스템으로 마이그레이션해줘" 같은 작업을 실행시키고, 엔터를 치고, 저녁 먹으러 갔다가 돌아와서 끝난 걸 확인할 수 있습니다. 훌륭한 운영자는 자신의 시스템 프롬프트와 스킬을 보면서, "이거 반복 가능한 여러 결과물인데, 스케줄링하고 코워크로 매일 실행되게 할 수 있지 않을까?"라고 생각합니다. 예를 들어 저는 매일 밤 8시에 다음 날 일정을 보여주는 메시지를 받는데, 제 이메일과 캘린더를 보고 제가 해야 할 모든 걸 알려줍니다. 마치 비서(chief of staff)가 있는 것처럼요. 실제로 있고 정말 훌륭하지만, 이건 그녀가 안 해도 되게 제가 직접 세팅한 겁니다. 그러면 내일 뭐가 있는지 알 수 있으니, 막판에 변경할 게 있으면 할 수 있죠. 한 번 세팅해두면 매일 밤 실행되고, 다시는 신경 쓸 필요가 없습니다. 운영자는 AI로 일을 "지시"한다는 걸 깨닫습니다. 그냥 직접 하는 게 아니라요.

이건 정말 큰 프로 팁인데, "스킬 체이닝(chaining your skills)"이라고 부릅니다. 예를 들어 여러분 목소리로 글을 쓰는 카피라이팅 스킬이 있고, 이메일을 쓰는 것도 그 자체로 스킬인데, 그게 카피라이팅 스킬을 사용합니다. 그리고 그 두 스킬은 받은편지함 전체를 자동화하는 완전히 다른 스킬 안에서 호출될 수 있습니다. 이 스킬들은 각각 별도로 패키징된 작은 천재 에이전트들처럼, 함께 연쇄되어 하나의 결과물을 만들어냅니다. 전체 파이프라인이 연쇄된 스킬들인 거죠. 운영자는 이제 정말로 AI를 활용하고 있는 겁니다.

자, 스케줄과 스킬은 기존 도구와 커넥터를 자동화합니다. 그런데 만약 그 도구가 아직 존재하지 않는다면요?

레벨 5: 빌더(Builder). 얼마 전 저희 회사는 이틀 동안 업무를 멈췄습니다. AI 해커톤을 열었죠. 모두에게 코딩하는 법을 가르쳤습니다. 그 이틀 동안 팀 전원이 빌더가 됐습니다. 본질적으로 여러분이 할 수 있는 건, Claude를 이용해 코드를 작성하고, 커스텀 앱·대시보드·내부 도구를 만드는 겁니다. 전부 Claude Code 안에서요. 이제 Claude는 그냥 질문에 답하거나 스킬을 세팅하는 게 아니라, 말 그대로 소프트웨어를 출시하고 있는 겁니다.

이 레벨에서는 Claude Code라는 새로운 레벨을 소개합니다. 그리고 참고로, 만약 여러분이 이미 이 레벨에 있다면, 전체 인구의 0.04%에 속하는 겁니다. 대부분의 사람들은 이걸 모릅니다.

Claude Code 안에서 세 가지 범주로 빌드할 수 있습니다. 첫째는 제가 "루프(loops)"라고 부르는 것들입니다. 이건 반복적으로 실행되며 작업을 하는 작업들인데, 코워크와 비슷하지만 서버 안에서 실행되고 다른 에이전트들과 대화할 수 있습니다. 다른 시스템들과 대화하고, 다른 API를 쓸 수 있고, 훨씬 더 고급이지만, 항상 실행되고 있기 때문에 "루프"라고 부릅니다. 둘째는 툴(tools)입니다. 이건 한 번의 상황을 위해 만드는 것들입니다. 프로젝트 하나를 위해 툴을 만들 수도 있고, 뭔가를 이루도록 돕기 위해 만들 수도 있습니다. 영원히 계속 쓸 건 아니기 때문에, 저는 이걸 일회용(disposable)이라고 봅니다. 셋째 레벨은 앱(apps)입니다. 저는 진짜 소프트웨어를 말하는 겁니다. 제가 말씀드린 해커톤에 참여한 모든 사람들이 실제로 작동하는 프로덕션 소프트웨어를 만들었습니다. 예를 들어 저에게는 정말 놀라운 사람인 베티(Betty)가 있는데, 저희 하우스 매니저입니다. 그녀는 저와 아내의 삶을 관리해줍니다. 그녀는 우리의 모든 워크플로우, 개인적 삶의 모든 측면 — 차량, 부동산, 투자, 예산 — 을 관리하는 시스템을 만들었습니다. 그게 전부예요. 그리고 그녀는 프로그래머가 아닙니다. AI의 세계에서는, 영어가 새로운 프로그래밍 언어입니다.

자, 프로 팁을 드리자면, 저는 뭔가를 만들기 전에 100% 플랜 모드(plan mode)라는 기능을 씁니다. 본질적으로 슬래시 플랜(forward slash plan)을 치고 엔터를 누른 다음, 여러분의 아이디어를 그냥 쏟아내면 됩니다. Claude가 여러분이 말한 걸 전부 듣고, 필요하면 질문을 하고, 코드를 쓰기 전에 여러분이 먼저 승인할 완전한 계획을 작성해줍니다. 플랜 모드가 그렇게 중요한 이유는, 사람들이 항상 "이런 AI 앱 만드는 데 비용이 너무 많이 든다"고 불평하기 때문입니다. 그건 미리 계획을 세우지 않았기 때문입니다. 이렇게 하면 돈을 많이 아낄 수 있습니다.

또 하나의 프로 팁 플러스 플러스는 Claude Code 리모트(Cloud Code Remote, 문맥상 Claude Code Remote로 교정)입니다. 저는 노트북을 떠날 때마다 이걸 씁니다. 코드를 작성하는 터미널 창에서, "슬래시 원격 제어(forward slash remote control)"라고 말하면 폰에 있는 Claude 앱과 연결됩니다. 계속 코드를 씁니다. 저는 이걸 산악자전거를 타면서 서너 번 해봤습니다. 폰으로 코드를 쓰고 있었죠. 그리고 이게 바로 제가 이걸(부상 또는 사고, 문맥상 정확한 지칭 불명) 얻은 경위입니다, 왜냐하면 버금(berm, 트레일의 경사 곡선 구간)을 타다가 앞바퀴가 미끄러졌거든요.

이제 우리는 방금 도구를 만드는 법을 이야기했는데, 만약 팀원을 만드는 법을 배울 수 있다면 어떨까요?

레벨 6: 에이전트 오케스트레이터(Agent Orchestrator). 오케스트레이터는 여러분이 설계한 에이전트가 실제로 뭔가를 운영하는 단계입니다. 이제는 부서, 프로세스, 워크플로우를 계속 실행하는 루프가 되고, 여러분은 더 이상 관여하지 않습니다. 왜냐하면 우리가 방금 얘기한 모든 조각들을 가져다가 Claude 에이전트에 꽂아 넣었기 때문입니다. 이제 여러분은 "human in the loop"가 아니라 "human on the loop"입니다. Claude는 더 이상 그냥 도구가 아니라, 이제 인프라가 됩니다.

에이전트를 만드는 방법은 수백만 가지가 있지만, 딱 하나의 방법을 알려드리기보다, 에이전트를 만드는 걸 사고하는 프레임워크를 드리고 싶습니다. 먼저, 하나의 메인 에이전트로 시작해야 합니다. 이게 여러분의 에이전트입니다. 비서 에이전트일 수도 있고, 관리 에이전트일 수도 있습니다. 저는 CEO 에이전트가 있어요. 이게 오케스트레이터입니다. 제 것은 "카이(Kai)"라고 부릅니다. 사실 그는 별로 하는 일이 없습니다. 그냥 다른 에이전트들을 지휘할 뿐이에요. 이게 미쳤다는 거 압니다.

다음으로, 전문화된 서브 에이전트들을 만들어야 합니다. 그리고 각 서브 에이전트는 하나의 워크플로우를 담당합니다. 메인 에이전트가 서브 에이전트들과 소통하며 뭘 해야 할지 알려줍니다. 셋째는 텔레그램을 연결해서 폰으로 에이전트와 대화하는 겁니다. 리스(Reese)는 제 부동산 에이전트인데, 제가 할 수 있는 투자 매물을 찾아줍니다. 그리고 카이는 매일 리스와 확인하고 저에게 보고하는데, 그는 제 모든 에이전트들에게 그렇게 합니다. 제가 아무것도 안 해도 전부 다 됩니다. 에이전트들이 생각하고, 결정하고, 주어진 범위 안에서 실행합니다. 우리는 기계를 돌리는 기계를 만들고 있는 겁니다. 여러분의 메인 에이전트가 그 기계입니다.

저는 제 자체 플랫폼인 Apex를 씁니다. apex.host에서 확인하실 수 있는데, 여러분은 Claude로 이걸 할 수 있습니다. 사실 Apex 뒤에서도 우리는 Claude를 메인 에이전트 모델로 씁니다. Apex는 그냥 이걸 더 안전하고 더 다루기 쉽게 만들어줄 뿐입니다.
