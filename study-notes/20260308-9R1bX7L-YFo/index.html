1. /loop 출시 배경과 과대 광고 문제

Anthropic이 Claude Code에 에이전트 루프(Agent Loops)를 출시했다. 출시 24시간도 안 돼 "클로드 2.0", "24시간 에이전트", "텔레그램으로 Claude Code와 대화 가능" 같은 잘못된 정보가 급속히 퍼졌다.

화자는 이를 명확히 부정한다. 루프는 유용하지만 패러다임을 바꾸는 기능이 아니며, 영구 백그라운드 세션을 만드는 것도 아니다. 혼란이 생기는 이유는 "Claude Code"라는 이름 아래 두 가지 다른 제품이 존재하기 때문이다 — CLI 터미널 버전과 Claude Code Desktop(GUI) 버전. 이 둘은 예약 작업을 완전히 다르게 처리한다.

2. /loop 명령어 — 무엇을 할 수 있나

세션 내에서 반복되는 예약 작업을 실행할 수 있다. Boris Cherny(Claude Code 제작자)가 제시한 사용 사례:

  • 모든 PR 모니터링: 빌드 이슈를 자동 감지하고, 댓글이 오면 worktree 에이전트를 통해 자동 수정
  • 매일 아침 Slack 요약: Slack MCP를 통해 내가 태그된 중요 게시물 요약 제공 (최대 3일)

사용법은 간단하다: /loop 입력 → 간격 지정 (5분, 1시간, 아침마다 등) → 원하는 작업 프롬프트 입력.

3. /loop의 실제 한계

"세션 내에서"라는 조건이 핵심이다.

조건 실제 동작
터미널 창 닫음 즉시 종료
컴퓨터 종료 즉시 종료
절전 모드 진입 즉시 종료
앱 재시작 유지 안 됨
최대 지속 시간 3일

또한 같은 터미널에서 출력되므로 루프 실행 중 대화 중이면 대화가 끝날 때까지 보고가 지연된다.

이를 이해하면 "24시간 에이전트"라는 표현이 왜 잘못된지 분명해진다.

4. /loop의 올바른 활용 시나리오

하나의 작업 세션(같은 터미널, 최대 3일) 내에서 반복할 마이크로 태스크에 적합하다:

  • 10분마다 웹사이트 배포 상태 확인
  • 5분마다 Playwright로 폼 제출 동작 점검
  • 특정 프로젝트 진행 중 빌드 상태 주기 모니터링

루프를 하나의 스킬처럼 만들어, Claude Code와 반복하던 작업을 체계화할 수 있다. 생산성 향상은 실제다.

5. Claude Code Desktop /schedule — 더 강력한 예약

CLI에는 없고 Desktop에만 있는 기능이다. 예약 메뉴 또는 /schedule 명령어로 사용.

항목 /loop (CLI) /schedule (Desktop)
만료 3일 없음 (영구)
세션 기반 예 아니오
재시작 후 유지 아니오 예
실행 방식 같은 터미널 창 매번 새 세션 생성
사용자 작업 간섭 간섭 가능 격리됨
CLI 사용 가능 예 아니오

주의: 매번 새 세션이 열리므로 너무 짧은 간격(예: 1분)으로 설정하면 세션이 폭발적으로 증가한다. 실행하려면 Desktop 앱과 컴퓨터가 켜져 있어야 한다.

Boris의 두 번째 예시("매일 아침 Slack 요약")는 사실 Desktop /schedule의 영역이다. CLI /loop으로 하면 3일마다 같은 명령을 반복 입력해야 하므로 비효율적이다.

6. GitHub Actions — 클라우드 실행

Claude Code를 GitHub Actions Workflow 안에서 실행하는 방식이다.

  • 컴퓨터, 터미널, Desktop 앱 모두 불필요
  • GitHub 자체 인프라에서 실행
  • PR 처리, 코드 구현 등 GitHub 연동 작업에 최적
  • 텔레그램 연결, 범용 에이전트 용도로는 부적합 — GitHub 에코시스템 한정

7. Claude Code Remote의 한계

텔레그램으로 Claude Code와 대화하고 싶다면 Remote가 답처럼 보이지만, Remote 역시 세션 기반이다. 터미널 종료나 컴퓨터 꺼짐과 함께 소멸한다. 영구 연결 불가.

8. 도구 선택 가이드

전체 전사 펼치기

출시 24시간도 안 돼서 Anthropic이 에이전트 루프(Agent Loops)를 출시했다. 이것은 Claude Code 안에서 예약 작업을 처리하는 방식에 있어서 상당한 혁신이다.

그런데 이미 잘못된 정보가 너무 많이 퍼지고 있다. 이 새로운 기능이 실제로 무엇을 할 수 있는지에 대해서 말이다. 벌써 "클로드 2.0"이라고 부르는 영상도 봤고, "24시간 에이전트"라는 말도 나온다. 텔레그램으로 Claude Code와 대화할 수 있도록 설정하는 방법을 알려주겠다는 사람도 있었다. 아니다. 전혀 그렇지 않다.

에이전트 루프는 매우 유용한 기능이다. 하지만 이것이 Claude Code의 패러다임을 바꾸는 순간이라고 생각하거나, Claude Code의 영구적인 세션을 백그라운드에서 계속 돌리면서 예약 작업을 할 수 있다고 생각한다면 매우 실망하게 될 것이다. 잘못된 정보를 퍼뜨리는 사람들을 탓하지는 말자. 사실 Claude Code와 예약 작업은 정말 혼란스러운 영역이기 때문이다.

우리가 말하는 Claude Code에는 두 가지 버전이 있다. Claude Code Desktop과 Claude Code CLI가 있고, 이 둘은 예약 작업을 다르게 처리한다. 사실 Claude Code Desktop이 예약 작업에 있어서 더 강력한 기능을 제공한다는 것, 터미널을 주로 사용하는 분이라면 몰랐을 수도 있다.

GitHub Actions는 어떨까? GitHub Actions를 사용하면 Claude Code를 클라우드에서 실행할 수 있다. 그리고 Claude Code Remote는 어떻게 되는 건가? 이 부분은 꽤 복잡한 영역이고, 루프 기능은 훌륭하지만 반드시 알아야 할 한계가 있다. 그렇지 않으면 이미 퍼지고 있는 과대 광고에 실망하게 될 것이다. 이 영상에서 모든 것을 정리하겠다.

에이전트 루프는 어제 최신 업데이트에서 출시되었다. 클로드 코드에서 /loop 명령어가 보이지 않는다면 업그레이드만 하면 된다.

이 기능은 세션 내에서 반복되는 예약 작업을 할 수 있게 해준다. "세션 내에서"라는 것이 중요한 포인트다. Claude Code의 실제 제작자인 보리스 체르니(Boris Cherny)가 몇 가지 사용 사례 인사이트를 제공한다. 예를 들어 루프로 모든 PR을 모니터링하고 빌드 이슈를 자동으로 수정하고, 댓글이 들어오면 워크트리 에이전트(worktree agent)를 사용해서 수정하라고 할 수 있다. 또는 매일 아침 Slack MCP를 사용해서 내가 태그된 중요한 게시물의 요약을 제공하도록 할 수도 있다. 이것은 최대 3일까지 할 수 있다.

이걸 읽으면 자연스럽게 "그냥 터미널 열어놓고 루프로 매일 아침 Claude Code 변경 사항에 대한 웹 보고서를 작성하면 되겠다"고 생각하기 쉽다. 보고서는 받을 수 있지만, 정확히 그런 건 아니다.

세션 기반이라는 것은 — 이 정확한 터미널 창이 열려 있을 때만 매일 아침 실행된다는 의미다. 터미널 창을 닫으면 끝이다. 컴퓨터를 끄면 끝이다. 절전 모드에 들어가도 끝이다. 그리고 최대 3일이다. 이것은 엄청난 제약이고, 그래서 어떤 한계가 있는지 이해해야 한다.

한계 정리: - 3일마다 만료됨 - 앱 재시작 후에도 유지되지 않음 - 앱이 항상 열려 있어야 함 - 컴퓨터가 켜져 있어야 함 - 같은 세션에서 실행 — 이 터미널 창에서 출력이 나옴 - 대화 중이면 루프 실행이 대화 완료까지 지연됨

그러면 루프 명령어가 실제로 무엇을 해줄 수 있을까? 하나의 작업 세션 동안 계속 반복하게 될 마이크로 태스크를 수행하는 능력을 제공한다. 예를 들어 10분마다 웹사이트 배포 상태를 확인하거나, 5분마다 Playwright로 폼 제출이 잘 작동하는지 확인하는 식이다. 루프를 거의 하나의 스킬처럼 만들 수 있다. 훌륭하다. 생산성 향상은 확실하지만, 이런 한계는 현실이고 이해해야 한다.

사용법: /loop 입력 → 간격 지정(5분, 1시간, 아침마다 등, 상당히 유연) → 원하는 작업 프롬프트 입력.

Claude Code Desktop은 어떨까? 예약 작업에 있어서는 사실 이쪽이 더 강력하다. 루프에 대한 모든 관심과는 별개로, 이 기능은 Claude Code Desktop에서 이미 어느 정도 사용할 수 있었다. Desktop에서 예약 메뉴로 가면 작업을 예약할 수 있고, /schedule 명령어를 사용할 수도 있다. 참고로 터미널 CLI에는 /schedule 옵션이 없다. 존재하지 않는다.

Desktop의 예약이 더 강력한 이유: - 만료되지 않음 — 시간 제한 없음, 영구 실행 - 세션 기반이 아님 — 재시작해도 유지됨. Desktop을 종료해도 작업이 사라지지 않음 - 새 세션 생성 — 실행될 때마다 별도의 새 터미널 창을 열어서 실행. 사용자 현재 작업을 방해하지 않음

단, 주의할 점: 매분마다 실행하면 60분에 60개 세션이 열린다. Desktop과 컴퓨터가 켜져 있어야 실행된다.

정리: - 에이전트 루프(/loop) = 특정 작업 기간 내의 반복 마이크로 태스크 - Desktop /schedule = 장기적이고 영구적인 예약 (매일 아침 보고서 등) - CLI에서 Desktop의 스케줄링 기능을 사용할 수 없는 것은 아쉽지만, 시간이 지나면 바뀔 것으로 예상

GitHub Actions는 어떨까? 더 고급 내용이다. GitHub Actions는 Claude Code가 GitHub Actions Workflow 안에서 작업을 실행하는 것이다. 컴퓨터가 켜져 있을 필요도 없고, 터미널 앱도 필요 없고, Desktop도 필요 없다. 실제로 GitHub 인프라에서 실행된다. PR 처리나 코드 구현 같은 작업에는 적합하다. 하지만 텔레그램으로 Claude Code와 대화하는 용도로는 맞지 않는다.

Claude Code Remote는 어떨까? 텔레그램으로 Claude Code와 대화하고 싶다면 내장된 Remote를 쓰면 되지 않을까 생각할 수 있다. 하지만 역시 세션 기반이다. 터미널 클로드 코드 Remote를 사용하고 있다면 그건 그 세션뿐이다. 닫히거나 컴퓨터가 꺼지면 끝이다.

결론: 에이전트 루프는 훌륭하지만 범위가 실제로는 꽤 작고, 여러분의 특정 프로젝트와 작업에 따라 다르다. Boris가 준 두 번째 예시(매일 아침 Slack MCP 요약)는 사실 CLI가 아닌 Desktop의 영역이다. CLI에서 그걸 하면 3일마다 같은 명령어를 다시 반복해야 하기 때문이다.

Claude 관련 제품이 정말 많다. 미묘한 차이를 이해하고, 언제 무엇을 사용해야 하는지 알아야 이 도구들을 최대한 활용할 수 있다. 간격을 정하고 원하는 작업을 지정하되, 한계를 이해하라. 그렇지 않으면 실망하게 된다.
