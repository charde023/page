핵심 학습 포인트 (내가 배워야 할 것)

개념 왜 중요한가 한 줄
에이전트 스킬(Agent skills) AI 에이전트가 특정 작업을 더 잘 수행하도록 지식과 절차를 추가하는 핵심 방식 스킬은 모델의 기본 능력을 업무 맥락에 맞게 보강한다.
지식 격차(Knowledge gap) 모델이 훈련 데이터에서 충분히 보지 못한 분야는 답변 품질이 떨어질 수 있음 스킬은 모델이 모르는 영역을 메우는 보조 지식층이다.
모델에 내장된 지식(Baked-in knowledge) 모델은 학습·파인튜닝·강화학습으로 얻은 지식만 기본적으로 갖고 있음 최신 코드베이스나 특수 도메인은 기본 지식에 없을 수 있다.
컨텍스트(Context) 프롬프트, 코드베이스, 웹 검색 등으로 모델에게 추가 정보를 줄 수 있음 스킬은 컨텍스트 제공 방식 중 하나로 볼 수 있다.
도메인 특화 지식(Domain-specific knowledge) 특정 산업·업무·라이브러리에 맞는 지식이 필요할 때 성능 차이가 커짐 내 업무에 맞는 스킬을 만들면 에이전트가 더 실용적으로 동작한다.

내가 모를 만한 것 / 처음 보는 것

  • 에이전트 스킬(Agent skills) — AI 에이전트에게 특정 작업을 수행하는 방법, 참고 지식, 절차를 추가하는 구조.
  • 지식 격차(Knowledge gap) — 모델이 어떤 주제나 도구에 대해 충분히 알지 못해서 생기는 성능 공백.
  • 모델에 내장된 지식(Baked-in knowledge) — 사전학습(training data), 파인튜닝(fine-tuning), 강화학습(reinforcement learning)을 통해 모델 안에 이미 들어간 지식.
  • 컨텍스트(Context) — 사용자가 프롬프트(prompt), 코드베이스(code base), 문서, 웹 검색 결과 등으로 모델에게 제공하는 추가 정보.
  • Effect 라이브러리(Effect library) — 자바스크립트/타입스크립트 생태계의 함수형 프로그래밍 기반 라이브러리. 모델이 React나 Express처럼 대중적인 라이브러리보다 덜 학습했을 수 있다는 예시로 등장.

화자가 흘리듯 말한 구체 수치·설정값·명령어·뉘앙스. 원어 용어 괄호 병기, 맥락까지.

  1. 에이전트 스킬의 이유는 “두 가지”라고 시작하지만, 이 쇼츠에서는 첫 번째 이유인 지식 격차 해소만 다룬다.
  2. 모델의 기본 지식은 훈련 데이터(training data), 파인튜닝(fine-tuning), 강화학습(reinforcement learning)에서 온다고 설명한다.
  3. 추가 지식은 사용자가 주는 컨텍스트(context), 코드베이스(code base), 프롬프트(prompt), 웹 리서치(web research)를 통해 들어올 수 있다.
  4. 스킬(skill)은 단순 명령어가 아니라 특정 작업(task)이나 특정 도메인(domain)에 대한 지식을 추가하는 방법으로 설명된다.
  5. Effect 라이브러리(Effect library)는 모델이 충분히 보지 못했을 가능성이 있는 라이브러리 예시다. 즉, 유명한 라이브러리보다 덜 “모델에 구워져” 있을 수 있다.
  6. 화자의 핵심 뉘앙스는 “에이전트 스킬을 무작정 쓰는 것”보다, 모델이 무엇을 모르는지 파악하고 그 공백을 메우는 용도로 써야 한다는 점이다.

# 섹션 요지
1 에이전트 스킬의 목적 에이전트 스킬은 모델의 부족한 지식을 보완하기 위해 사용된다.
2 모델이 아는 것의 출처 모델은 훈련 데이터, 파인튜닝, 강화학습으로 내장 지식을 갖는다.
3 외부에서 주는 지식 프롬프트, 코드베이스, 웹 검색 결과로 추가 컨텍스트를 줄 수 있다.
4 스킬이 필요한 상황 모델이 잘 모르는 업무·도메인·라이브러리를 다룰 때 스킬을 만든다.
5 Effect 예시 덜 대중적인 라이브러리는 모델이 충분히 학습하지 못했을 수 있으므로 스킬이 유용하다.

1. 에이전트 스킬은 지식 격차를 메우기 위한 도구다

화자는 에이전트 스킬(Agent skills)이 존재하는 이유를 크게 두 가지로 나누며, 이 영상에서는 첫 번째 이유를 설명한다. 첫 번째 이유는 지식 격차(knowledge gap)를 줄이는 것이다.

대형 언어 모델(LLM)은 이미 많은 지식을 갖고 있지만, 그 지식은 어디까지나 학습 데이터(training data), 파인튜닝(fine-tuning), 강화학습(reinforcement learning)을 통해 모델 안에 들어간 것이다. 즉, 모델이 모든 라이브러리, 모든 업무 방식, 모든 회사 내부 절차를 완벽히 아는 것은 아니다.

특히 차드처럼 이커머스나 물류 업무에 AI를 적용하려는 경우, 모델은 “일반적인 물류”는 알 수 있어도 우리 회사의 출고 규칙, CS 처리 기준, 반품 정책, 송장 예외 처리 방식은 모를 수 있다. 이때 에이전트 스킬은 그 부족한 지식을 보완하는 역할을 한다.

2. 모델은 컨텍스트를 통해 추가 지식을 받을 수 있다

모델이 기본적으로 갖고 있는 지식 외에도, 사용자는 여러 방식으로 추가 지식을 줄 수 있다.

예를 들어 다음과 같은 것들이 컨텍스트(Context)가 된다.

  • 사용자가 작성한 프롬프트(prompt)
  • 현재 작업 중인 코드베이스(code base)
  • 첨부한 문서나 정책 파일
  • 에이전트가 수행한 웹 리서치(web research)
  • 특정 업무 절차나 규칙

에이전트 스킬은 이 컨텍스트 제공을 더 구조화한 방식으로 볼 수 있다. 단순히 매번 긴 프롬프트를 쓰는 대신, 특정 작업에 필요한 지식과 절차를 스킬로 만들어두면 에이전트가 반복적으로 더 안정적인 결과를 낼 수 있다.

3. 특정 도메인이나 라이브러리에는 스킬이 특히 유용하다

화자는 Effect 라이브러리(Effect library)를 예로 든다. Effect는 특정 프로그래밍 라이브러리인데, 모델이 React나 Express처럼 널리 쓰이는 라이브러리만큼 많이 학습하지 않았을 수 있다.

이런 경우 모델에게 그냥 “Effect로 코드를 작성해줘”라고 하면 부정확한 코드나 오래된 패턴을 만들 가능성이 있다. 그래서 Effect를 사용하는 프로젝트라면, 해당 라이브러리의 사용 방식, 프로젝트 규칙, 자주 쓰는 패턴을 담은 스킬을 만드는 것이 좋다고 말한다.

이 개념은 코딩에만 해당하지 않는다. 예를 들어 이커머스/물류 업무에서는 다음과 같은 스킬을 만들 수 있다.

  • 스마트스토어 주문 처리 스킬
  • 쿠팡 로켓그로스 정산 확인 스킬
  • 3PL 출고 예외 처리 스킬
  • 반품 사유별 CS 응대 스킬
  • 송장 업로드 오류 점검 스킬

핵심은 AI가 일반적으로 아는 내용과 내가 실제 현장에서 필요한 지식 사이의 간극을 줄이는 것이다.

  • [ ] 반복되는 업무 중 “규칙 설명이 매번 필요한 작업”을 스킬 후보로 정리한다.
  • [ ] 회사 내부 정책, 예외 처리 기준, 용어 정의를 스킬에 넣을 수 있는 형태로 문서화한다.

전체 전사 펼치기

일반적으로 에이전트 스킬(Agent skills)이 존재하는 이유는 크게 두 가지입니다.

첫 번째 이유는 지식 격차(knowledge gap)를 메울 수 있기 때문입니다.

모델들은 훈련 데이터(training data), 파인튜닝(fine-tuning), 또는 강화학습(reinforcement learning)을 통해 어느 정도의 지식을 갖고 있습니다. 이것이 말하자면 모델 안에 이미 내장된 지식(baked-in knowledge)입니다.

그리고 모델은 여러분이 제공하는 컨텍스트(context), 코드베이스(code base), 프롬프트(prompt), 또는 모델이 수행하는 웹 리서치(web research)를 통해 추가 지식을 얻을 수도 있습니다.

하지만 여기에 더해, 여러분이 직접 만든 스킬(skill)을 통해 더 많은 지식을 추가할 수도 있습니다. 특정 작업(task)에 대한 지식, 또는 여러분이 다루는 특정 도메인(domain)에 대한 지식을 넣는 것입니다.

예를 들어 제가 Effect 라이브러리(Effect library)를 사용하는 프로젝트에서 작업한다고 해보겠습니다. 이 라이브러리는 모델 안에 충분히 깊게 내장되어 있지 않을 수 있습니다. 즉, 모델이 다른 라이브러리에 비해 Effect 관련 코드를 많이 보지 못했을 수 있습니다.

그런 경우라면 저는 스킬을 만들고 싶을 것입니다.
