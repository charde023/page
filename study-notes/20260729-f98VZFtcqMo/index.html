올해 Claude에게 있었던 일들 #Shorts

한 줄 요약

Anthropic 내부 제품 엔지니어링팀에서는 Claude Code가 현재 제품 PR의 65%를 처리하고 있으며, 복잡한 대화형 작업은 Claude Code, 선제적 자동 처리는 Claude Tag가 맡는 식으로 역할이 나뉘고 있다.

핵심 학습 포인트 (내가 배워야 할 것)

개념 왜 중요한가 한 줄
Claude Code 개발자가 AI 에이전트와 상호작용하며 코드를 작성·수정하는 도구로, 실제 제품 개발 업무에 깊게 들어오고 있음 복잡한 코딩 작업은 여전히 대화형 에이전트 환경이 강함
제품 PR(Product PR) 실제 서비스 코드 변경을 검토·병합하기 위한 단위라서, AI가 개발 흐름에 얼마나 들어왔는지 보여주는 지표 Claude Code가 내부 제품 PR의 65%를 처리 중이라고 언급됨
Claude Tag 사용자가 직접 매번 실행하지 않아도, 버그 리포트나 기능 관련 작업을 선제적으로 처리하는 방식으로 설명됨 반복적·예측 가능한 작업을 자동으로 맡기는 용도
대화형 반복 작업(Interactive Iteration) 복잡한 문제는 한 번에 끝나지 않고, AI와 질문·수정·검토를 반복해야 함 어려운 개발 작업은 Claude Code에서 계속 조율하는 방식이 적합
선제적 작업(Proactive Work) 사람이 명령을 내리기 전에 필요한 일을 미리 진행하는 자동화 개념 버그 리포트 대응처럼 계속 발생하는 업무에 유리

내가 모를 만한 것 / 처음 보는 것

  • 제품 PR(Product Pull Request) — 제품 코드에 실제 반영될 변경사항을 리뷰하고 병합하기 위한 요청. 개발팀의 실무 생산성을 보는 중요한 기준.
  • PR을 랜딩한다(Land a PR) — PR이 승인되어 메인 코드베이스에 병합되는 것을 뜻하는 개발자 표현.
  • Claude Code — Anthropic의 AI 코딩 에이전트 도구. 개발자가 에이전트와 대화하면서 코드 작성, 수정, 테스트, 리팩터링을 진행하는 맥락으로 사용됨.
  • Claude Tag — 전사상 “Claude Tag”로 들리며, 문맥상 특정 작업을 자동으로 맡기거나 트리거하는 Anthropic 내부/관련 기능으로 보임. 정확한 제품명은 확인 필요.
  • 내부 버전(Internal Version) — 공개 제품이 아니라 Anthropic 내부 제품 엔지니어링팀이 사용하는 Claude Code 버전을 의미.

화자의 디테일 (놓치기 쉬운 포인트)

화자가 흘리듯 말한 구체 수치·설정값·명령어·뉘앙스. 원어 용어 괄호 병기, 맥락까지.

  1. 65% — Claude Code가 현재 Anthropic의 “제품 엔지니어링팀” 제품 PR(Product PR)의 65%를 처리한다고 말함.
  2. 전체 Anthropic이 아니라 제품 엔지니어링팀 기준 — 질문자가 “Anthropic 전체냐, Claude Code만이냐”를 묻자, 화자는 “우리 제품 엔지니어링팀 기준”이라고 범위를 좁힘.
  3. 50%를 넘는 변화 — 화자는 이 수치가 “절반 이상”이기 때문에 매우 큰 변화라고 강조함.
  4. Claude Code의 최적 용도 — 가장 복잡한 작업, 특히 에이전트와 상호작용하며 반복 수정하는 작업에 적합하다고 설명함.
  5. Claude Tag의 최적 용도 — 사용자가 매번 Claude Code를 직접 실행하지 않아도, 버그 리포트 같은 일을 대신 선제적으로 처리하는 데 좋다고 설명함.

# 섹션 요지
1 Claude Code의 PR 처리 비율 Anthropic 내부 제품 엔지니어링팀에서 제품 PR의 65%를 Claude Code가 처리 중
2 수치의 범위 확인 Anthropic 전체가 아니라 제품 엔지니어링팀 기준이라고 정정
3 Claude Code와 Claude Tag의 역할 분리 복잡한 대화형 작업은 Claude Code, 선제적 자동 처리는 Claude Tag
4 실무적 의미 AI 코딩 도구가 단순 보조를 넘어 실제 개발 흐름의 큰 비중을 차지하기 시작함

1. Claude Code가 제품 PR의 65%를 처리한다

영상의 핵심은 Anthropic 내부에서 Claude Code가 이미 상당한 비중의 개발 업무를 맡고 있다는 점이다.

화자는 “Claude Code가 현재 우리 제품 PR(Product PR)의 65%를 랜딩한다”고 말한다. 여기서 PR은 풀 리퀘스트(Pull Request)로, 개발자가 코드 변경을 제안하고 리뷰를 거쳐 실제 제품 코드에 병합하는 단위다.

즉, 단순히 “AI가 코드를 조금 도와준다” 수준이 아니라, 실제 제품 개발 프로세스에서 AI 코딩 도구가 절반 이상 관여하고 있다는 뜻이다.

2. 이 수치는 Anthropic 전체가 아니라 제품 엔지니어링팀 기준이다

질문자는 이 65%가 Anthropic 전체 기준인지, Claude Code 관련 팀 기준인지 확인한다.

이에 대해 화자는 “우리 제품 엔지니어링팀 기준”이라고 답한다. 즉, 이 수치를 모든 Anthropic 개발 조직 전체에 그대로 적용하면 안 된다.

다만 제품 엔지니어링팀에서 65%라는 수치가 나온다는 것은, AI 코딩 도구가 실제 제품 개발 업무에서 이미 핵심 도구로 자리 잡고 있다는 신호로 볼 수 있다.

3. Claude Code와 Claude Tag의 역할은 다르다

화자는 사람들이 Claude Code와 Claude Tag를 나눠 쓰는 방식도 설명한다.

Claude Code는 여전히 가장 복잡한 작업에 적합하다. 특히 개발자가 에이전트와 상호작용하면서 여러 번 수정하고 실험하는 대화형 반복 작업(Interactive Iteration)에 강하다.

반면 Claude Tag는 사용자를 대신해 선제적으로 작업하는 데 적합하다고 설명된다. 예를 들어, 어떤 기능을 개발하는 동안 관련 버그 리포트가 계속 올라오면, 사용자가 매번 Claude Code를 수동으로 실행하지 않아도 Claude Tag가 대신 일을 시작할 수 있다는 뉘앙스다.

4. 차드에게 중요한 실무적 의미

이커머스나 물류 사업 관점에서 보면, 이 이야기는 “AI가 개발자 일을 얼마나 대체하느냐”보다 “반복적인 디지털 업무를 어디까지 자동화할 수 있느냐”로 보는 것이 더 중요하다.

예를 들어 쇼핑몰 운영에서도 반복되는 업무가 있다.

  • 상품 정보 오류 수정
  • 주문/배송 관련 버그 리포트 정리
  • 고객 문의 유형 분류
  • 관리자 페이지 개선 요청 정리
  • 개발 외주사에 전달할 이슈 문서화

Claude Code 같은 도구는 복잡한 시스템 수정이나 자동화 스크립트 작성에 유리하고, Claude Tag 같은 개념은 반복적으로 발생하는 이슈를 자동으로 감지해 작업을 시작하는 방식에 가깝다.

핵심은 앞으로 AI를 “한 번 물어보는 챗봇”이 아니라, 업무 흐름 안에서 계속 움직이는 작업자로 설계해야 한다는 점이다.
