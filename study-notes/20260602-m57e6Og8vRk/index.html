최신 Codex 업데이트와 Opus 4.8의 진실

원작자 Riley Brown · Chorus (chorus.com) · AI Native 시리즈 진행자 · 업로드 2026-06-02 · 26.9분 · 원본 영상 ↗
한 줄 요약

Opus 4.8은 체감 차이가 거의 없고, 진짜 혁신은 Codex 슈퍼앱의 컴퓨터 사용·브라우저·에이전트 멀티스레드 업데이트에 있다.

내가 모를 만한 것 / 처음 보는 것

  • DeepSuite — 프런티어 코딩 에이전트를 장기(long-horizon) 소프트웨어 엔지니어링 태스크 기준으로 측정하는 벤치마크 회사. 비용·시간·출력 토큰을 점수에 매핑해 플롯.
  • SWE-Bench Pro — 에이전트 코딩 벤치마크. Opus 4.8이 여기서 GPT 5.5보다 낮은 점수.
  • Codex Windows Computer Use — Codex 앱에서 @computer use 입력 시 GPT 5.5가 Windows 전체를 제어.
  • Codex Remote (QR 연동) — Codex 앱 내 폰 아이콘 → QR 코드 → ChatGPT 앱으로 Codex 원격 제어.
  • Proof (by Dan Shipper) — 에이전트가 직접 편집 가능한 오픈소스 문서 편집기. "에이전트 네이티브 앱"의 대표 사례.
  • Chorus (chorus.com) — Riley Brown의 회사. iMessage 안에 Claude Code·Codex 같은 에이전트를 연동하는 제품.
  • BYOT / BYOA (Bring Your Own Tokens / Bring Your Own Agent) — 토큰과 에이전트를 직접 공급하는 SaaS 모델 개념.

화자의 디테일 (놓치기 쉬운 포인트)

  1. 화자는 iMessage에서 직접 AI 에이전트를 운영 중이며 Opus 4.6을 일반 에이전트 작업에 가장 선호한다고 밝힘 — 4.7·4.8과 차이를 못 느껴서.
  2. GPT 5.5 extra high를 보안 취약점 점검(vulnerability check)에 특히 추천 — 장기 에이전트 작업·딥 코딩에서 Opus 4.8보다 신뢰도가 높다고 평가.
  3. Codex에서 4 billion 토큰, 43일 연속 사용, 최장 단일 태스크 3시간 7분이라는 개인 사용 데이터를 공개.
  4. Codex 브라우저에서 Command + 클릭(또는 Command open) 시 멀티 탭이 열림 — + 버튼으로는 안 됨. UI 트릭.
  5. Codex 내 Command G로 채팅 내용 전체 검색 가능 (제목뿐 아니라 본문 포함). 기존에는 불가능했음.
  6. Vibe coding 플랫폼(Replit·Lovable)의 핵심 기능(DB·인증·호스팅)을 Codex 단일 프롬프트 + 플러그인(Neon·Google Auth·Vercel·AI Gateway·FAL) 조합으로 완전 재현 가능하다고 실연.

1. Opus 4.8 — 실체는 무엇인가

Anthropic이 Opus 4.8을 "세계 최고 AI 모델"로 발표했으나, 화자는 3시간 동안 4.7과 비교해도 차이를 감지하지 못했다.

모델 카드 기준으로는 agentic coding(SWE-Bench Pro)·추론·컴퓨터 제어·문서 작업·금융 태스크에서 4.7보다 앞서지만, GPT 5.5보다 터미널 코딩 점수가 낮다.

Greg Eisenberg: "GPT 5.5 대비로도 의미 있는 차이가 없다." Matt Wolfe: "최근 뉴스 영상에서 1분도 안 다뤘다." 두 사람 모두 모델 릴리즈가 iPhone 업그레이드처럼 인지 불가 수준이 되었다는 점에 동의.

화자 자신은 일반 에이전트 작업에 Opus 4.6을 계속 사용 중이며, 4.6·4.7·4.8 구분이 불가하다고 밝힘.

2. GPT 5.5 vs. Opus 4.8 — DeepSuite 벤치마크

DeepSuite는 장기 소프트웨어 엔지니어링 태스크를 비용·시간·출력 토큰·점수 4축으로 플롯. 결과 요약:

지표 GPT 5.5 (medium/high/extra high) Opus 4.8
점수 더 높음 낮음
비용 더 낮음 높음
토큰/태스크 더 적음 많음
태스크 시간 더 짧음 길음

화자 의견: 장기 에이전트 작업·딥 코딩·컴퓨터 제어에는 GPT 5.5 권장. Opus 계열은 디자인·발표자료·랜딩 페이지처럼 시각적 완성도가 중요할 때 강점.

3. Codex 업데이트 — Windows 컴퓨터 사용 + 모바일 연동

  • Windows computer use 공식 지원: Codex 앱에서 @computer use 입력 → GPT 5.5가 Windows 전체 제어. Canva 같은 앱도 에이전트가 직접 조작.
  • Codex Remote (Windows): 앱 내 폰 아이콘 클릭 → QR 코드 → iPhone ChatGPT 앱의 Codex 섹션에서 프롬프트 입력 → Codex → 컴퓨터 제어. Mac·Windows 동일 채팅 스레드 실시간 동기화.

4. Codex 업데이트 — 브라우저 로그인 유지 + 멀티탭

이전에는 인앱 브라우저를 열 때마다 로그인이 필요했다. 업데이트 후:

  • 로그인 유지: twitter.com·Notion 등에 자동 로그인 상태 유지.
  • 멀티탭: Command + 클릭으로 여러 탭 동시 열기 가능. + 버튼으로는 불가.
  • 에이전트가 Notion 문서를 찾아 오른쪽 클릭 → 브라우저 열기 → 인앱에서 직접 편집. Claude Desktop은 이 기능이 아직 없다고 화자가 지적.

5. Codex 업데이트 — 에이전트가 서브에이전트 스레드 생성

Codex 내에서 "슈퍼 프롬프트" 1개로 6개의 별도 채팅 스레드를 자동 생성·실행. 각 스레드는 AI가 명명(triage 등)하고, "Codex가 다른 스레드에서 보낸 메시지"로 식별됨. 10개 스레드도 동시 가동 가능. 오케스트레이터-서브에이전트 패턴을 Codex UI 안에서 즉시 구현.

화자: 마스터 에이전트 → 서브에이전트 → 결과 취합 자동화 가능성을 탐색 중이며 별도 영상 예고.

6. 기타 소소한 업데이트

  • Command G 전체 검색: Codex 내 모든 채팅 제목+본문 대상 키워드 검색.
  • GitHub 활동 페이지: Settings → Profile에서 사용 일수 스트릭, 최장 태스크 시간, 누적 토큰 수 확인 가능.

7. Vibe Coding 플랫폼 대체 가능성

Replit·Lovable·Bolt 등 전용 vibe coding 플랫폼이 Codex·Claude Code로 대체될 가능성 논의.

Codex 단일 프롬프트 + 플러그인으로 Replit 기능 완전 재현 예시: - DB: Neon Postgres 플러그인 - 인증: Google Sign-in - 호스팅: Vercel - AI 기능: AI Gateway (Vercel) + FAL(이미지·영상 모델) - 보안 점검: GPT 5.5 extra high

화자 예측: 2026년 내에 Replit·Lovable 기능을 Codex 플러그인으로 래핑한 BYOT/BYOA 서비스가 등장. 월 $10 수준의 얇은 마진 모델로 운영 가능.

8. Agent Mini App 비전 — 다음 단계

현재 Codex 플러그인으로 Gmail·Slack·Notion·GitHub·Vercel 등 30여 개 서비스에 인증 연결이 가능하다. 그러나 플러그인 인증을 에이전트가 생성한 앱에 직접 주입하는 것은 현재 불가.

화자의 비전(Agent Mini App):

  1. 에이전트가 태스크별로 최적 UI를 동적 생성 ("Tinder for email" 예시: 수신 메일·초안·아카이브/발송 버튼).
  2. 미니앱이 이미 연결된 플러그인 인증을 활용해 실제로 이메일 발송·Slack 메시지 전송 등을 수행.
  3. 사용자가 아카이브/발송 선택을 반복할수록 에이전트가 학습 → 정확도 향상.
  4. 사용자·팀이 자체 미니앱을 만들어 공유 가능.

화자는 Chorus(iMessage 에이전트 플랫폼)에서 이 방향을 실험 중. "Jarvis"(모든 작업에 최적 인터페이스를 즉시 제공하는 에이전트)를 가능케 할 핵심 기술로 본다.

교정 전사 (한국어)

전체 전사 펼치기

이번 주 Anthropic이 Opus 4.8을 출시했습니다. 세계에서 가장 앞선 AI 모델이라고 하는데요, 반면 일부에서는 AI 모델이 아이폰 시대에 접어들었다고 말합니다. 새 모델이 나와도 이전 모델과 차이를 느끼기 어렵다는 거죠. 오늘 이 주제를 다룰 겁니다.

또한 Codex 이야기도 합니다. 이번 주 OpenAI가 자사 슈퍼앱 Codex에 대대적인 업데이트를 발표했는데, 공식 발표에 없던 변경도 있습니다.

저는 AI Native 채널의 Riley Brown입니다. 바로 시작하죠.

Anthropic이 목요일에 Claude Opus 4.8을 발표했습니다. Opus 4.7을 기반으로 판단력이 더 날카로워졌고, 자신의 진행 상황을 더 솔직하게 보고하며, 이전 모델보다 독립적으로 더 오래 작업할 수 있다고 합니다. 모델 카드에 따르면 Opus 4.8은 코딩에 더 강해졌습니다. agentic coding SWE-Bench Pro에서 GPT 5.5보다는 낮지만, Opus 4.7과 GPT 5.5를 포함한 다른 모든 모델보다 추론·컴퓨터 제어·문서 작업(문서·스프레드시트·발표자료)·금융 태스크에서 앞섭니다.

솔직히 Opus 4.8 단독 영상을 만들 계획이었는데, 3시간 동안 Opus 4.8과 이전 버전인 Opus 4.7을 비교했지만 차이를 전혀 느끼지 못했습니다. 저만 그런 게 아닙니다. Greg Eisenberg도 말하길 "Opus 4.8은 GPT 5.5보다 의미 있게 좋지 않아서 팟캐스트에서 다루지 않았다. 4.7 대비로도 의미 있는 개선이 아니다"라고 했고, "아이폰 시대에 진입하고 있다. 예전에는 새 아이폰이 나오면 진짜 도약이 있었지만 지금은 카메라가 조금 좋아진 수준이라 차이를 못 느낀다. 4.6에서 4.7, 4.8로 가면서 약간씩 다르지만 어느 것이 최선인지 알 수가 없다"고 했습니다.

개인 경험을 덧붙이자면, 저는 현재 iMessage에서 OpenClaw [?OpenClaw]와 유사한 AI 에이전트를 운영 중인데 Opus 4.6을 쓰고 있습니다. 적어도 제 사용 방식 기준으로는 일반 에이전트 작업에 가장 좋다고 생각하고, 세 모델 사이 차이를 정말 느끼지 못합니다.

Matt Wolfe도 같은 의견입니다. "최근 뉴스 영상에서 Opus 4.8을 1분도 안 다뤘다. 솔직히 별로 할 말이 없었다"고 했죠. Matt가 중요한 업데이트를 다룰 때는 5분, 10분도 쓰는데 1분밖에 안 썼다는 건 의미심장합니다.

이제 GPT 5.5와 Opus 4.8을 비교해 봅니다. DeepSuite라는 회사가 흥미로운 데이터를 올렸습니다. 프런티어 코딩 에이전트를 독창적인 장기 소프트웨어 엔지니어링 태스크로 측정하는 곳인데, 비용·시간·출력 토큰을 점수에 매핑해 플롯을 그립니다.

차트를 보면 GPT 모델이 한쪽에, Opus 모델이 다른 쪽에 있습니다. 위로 갈수록 점수가 높고 오른쪽으로 갈수록 비용이 높습니다. GPT 5.5(medium/high/extra high)가 Anthropic의 Opus 4.8보다 낮은 비용에 더 높은 점수를 냅니다. OpenAI가 더 낮은 비용에 더 좋은 점수를 내고 있죠. 토큰/태스크 수도 적고, 평균 비용도 낮습니다. 이 모델이 가장 효율적입니다.

최근에 "신뢰도" 관점에서도 GPT 5.5를 선호한다는 이야기가 많습니다. "Opus 4.8은 느낌이 좋고 중독성이 있다. 특히 vibe coding할 때. 하지만 대부분 표면적인 수준이다"라는 평도 있습니다. Opus 계열은 디자인에 강하고, 발표자료·랜딩 페이지가 더 보기 좋게 나오고 Claude 디자인에 많은 공을 들였습니다. 하지만 긴 에이전트 태스크·딥 코딩·컴퓨터 제어·iMessage에서 직접 문자 메시지 관리 등에는 GPT 5.5를 강력 권장합니다.

이제 저는 대형 AI 랩의 발표를 두 범주로 나눕니다. 모델 업데이트와 슈퍼앱 업데이트. 9개월 전만 해도 모델 업데이트에 더 흥분했습니다. 모든 모델 업데이트가 큰 도약처럼 느껴졌고, 대부분 터미널 작업이라 앱 레이어의 혁신이 별로 없었으니까요. 하지만 최근 4개월 동안 저는 슈퍼앱에 집착하고 있습니다. Claude Desktop이나 Codex 같은 앱에서 에이전트와 쉽게 대화하고, 왼쪽 패널에 태스크 목록, 가운데에 에이전트, 오른쪽에 에이전트가 작업하는 내용이 보이는 구조 말이죠. 이 흐름을 끊김 없이 만들기 위해 아직 해야 할 혁신이 많습니다.

OpenAI가 이번 주 Codex 앱 업데이트를 여러 가지 발표했습니다.

첫 번째는 Windows computer use(컴퓨터 사용)입니다. Codex 앱에서 @computer use를 입력하면 GPT 5.5가 Windows를 완전히 제어합니다. Canva도 조작 가능합니다.

Windows 사용자를 위한 또 다른 기능, Codex Remote입니다. 앱 아래의 폰 아이콘을 누르면 QR 코드가 나옵니다. iPhone에 ChatGPT가 설치되어 있으면 ChatGPT 앱의 Codex 섹션에서 프롬프트를 입력해 Codex를 제어하고, Codex를 통해 컴퓨터를 조작할 수 있습니다. iPhone과 Windows 데스크톱이 동일한 채팅 스레드를 실시간 공유합니다. Mac에서도 이미 됐고 이제 Windows도 지원합니다.

두 번째 업데이트 묶음은 제가 가장 많이 사용할 기능입니다. Codex 안에서 브라우저를 열 수 있었는데, 이제 로그인이 유지됩니다. twitter.com에 들어가면 이미 로그인된 상태입니다. Notion 플러그인이 연결되어 있으면 에이전트가 Notion 문서를 찾아 브라우저에서 바로 열 수 있고, 저는 자동으로 로그인된 Notion에서 내용을 편집할 수 있습니다. Codex를 떠나지 않고요. Claude Code나 Claude Desktop도 이 기능이 생길 것 같지만, 현재는 많이 뒤처져 있습니다. 저는 이 기능을 출시 후 72시간 동안 매 시간 사용했습니다.

멀티탭도 됩니다. + 버튼으로는 탭을 열 수 없지만, 브라우저 안에서 Command + 클릭(Command open)하면 여러 탭이 열립니다. Codex 안에 Google Chrome이 들어온 것 같은 수준입니다.

세 번째 업데이트는 많은 분들이 가장 좋아하는 기능입니다. 이제 Codex 안에서 에이전트가 다른 에이전트 스레드를 생성할 수 있습니다. 예를 들어 Codex에서 이런 "슈퍼 프롬프트"를 입력합니다: "Codex 안에서 새 채팅 세션 6개를 만들어서 각 태스크를 처리해줘." 실행하면 "6개의 별도 Codex 스레드를 좁고 간결한 완료 기준으로 생성하겠습니다"라고 하면서 스레드 1, 2, 3, 4, 5, 6을 만들고 AI가 이름을 붙입니다(triage 등). 각 스레드에는 "Codex가 다른 스레드에서 보낸 메시지"라는 표시가 붙습니다.

10개 스레드를 동시에 돌릴 수도 있습니다. 1개의 마스터 에이전트로 서브에이전트를 띄우고 결과를 취합하는 자동화도 가능해 보입니다. 이 기능은 별도 영상으로 깊이 다룰 예정입니다.

소소한 업데이트도 있습니다. Command G로 모든 채팅 본문을 전체 검색할 수 있습니다. 예를 들어 "OpenAI"를 검색하면 제목뿐 아니라 본문에 해당 단어가 언급된 모든 채팅이 나옵니다. 그리고 새 GitHub 활동 페이지가 생겼습니다. Settings → Profile에서 Codex 사용 일수·스트릭·최장 태스크 시간·누적 토큰 사용량을 볼 수 있습니다. 저는 43일 연속 사용, 최장 태스크 3시간 7분, 누적 40억 토큰이었습니다.

다음으로, 많은 분들이 Lovable·Replit·Bolt 같은 vibe coding 플랫폼을 Codex나 Claude Code로 옮겨가는 추세입니다. 앞으로 1~2개월 내에 이 플랫폼들이 완전한 vibe coding 플랫폼이 될 것 같습니다.

Codex에서 한 번의 프롬프트로 다음이 가능합니다: "우리 회사 내부 도구 만들어줘 — Neon Postgres로 DB 설정, Google 로그인 인증, Vercel로 호스팅, AI Gateway로 AI 기능 추가, 보안 취약점 점검도 해줘." 이 프롬프트 하나로 Neon 플러그인(DB), Google Auth, Vercel, FAL(이미지/영상 모델)을 모두 활용할 수 있습니다. GPT 5.5 extra high는 취약점 점검에 탁월합니다.

이 조합이 Replit·Lovable의 핵심 가치를 완전히 대체합니다. 제가 예측하는 2026년 트렌드: 누군가 BYOT(Bring Your Own Tokens)·BYOA(Bring Your Own Agent) 기반의 AI 네이티브 Replit·Lovable을 Codex 플러그인으로 만들 것입니다. 에이전트를 직접 만들 필요 없고 토큰 비용도 없으니 훨씬 얇은 마진으로 운영 가능합니다.

마지막으로, 제가 2개월째 집착하는 것은 "에이전트 미니앱(Agent Mini App)"입니다.

제 이전 영상에서 "에이전트 네이티브 앱"을 다뤘습니다. Dan Shipper가 만든 Proof라는 오픈소스 문서 편집기가 예시입니다. 에이전트가 문서를 만들고 사람이 편집하는 구조가 매우 자연스럽습니다.

지금 Codex 플러그인에는 Gmail·Slack·Typefully(트위터 예약 발행)·GitHub·Vercel 등 30여 개가 연결되어 있습니다. 문제는 이 플러그인 인증을 에이전트가 생성한 앱에 주입하는 것이 현재 불가능하다는 겁니다.

제 비전은 이렇습니다: Codex에서 "이메일 정리 도와줘"라고 하면, 에이전트가 수신 메일을 보고 초안을 만든 뒤, "이메일 틴더(Tinder for email)" 같은 미니앱을 동적으로 생성합니다. 화면에는 보낸 사람, 초안 답장, 아카이브/발송 버튼이 보입니다. 사용자가 아카이브하면 데이터가 저장되고, 다음번에는 에이전트가 아카이브될 메일 초안을 생성하지 않습니다. 발송할 때마다 에이전트가 학습해 정확도가 높아집니다.

이 미니앱들은 이미 연결된 플러그인 인증을 통해 실제로 이메일 발송·Slack 메시지 전송 등을 수행합니다. 사용자가 직접 앱을 만들어 팀과 공유할 수도 있고요.

저는 New York으로 이사한 회사에서 iMessage를 통해 이 방향을 실험 중입니다. chorus.com에서 현재 이용 가능하고, 에이전트가 링크를 보내면 미니앱이 열리는 형태를 탐색 중입니다. 이 미니앱이 에이전트의 운영 체제가 될 것이라고 생각합니다. Codex는 브라우저를 갖추고 있어 완벽한 환경이 되겠지만, 현재는 플러그인 인증을 에이전트 생성 앱에 연결하는 것이 불가능합니다.

오늘 업데이트는 여기까지입니다. 저는 지금 New York의 에어비앤비에 있습니다. SF에서 New York으로 회사를 옮겼는데 에너지가 넘칩니다. 스튜디오가 없어서 새로 꾸리는 중이고, 콘텐츠 노력을 10배 올릴 계획입니다. 목표는 여러분이 "에이전트 네이티브(agent native)"가 되도록 교육하는 것입니다. 에이전트 네이티브가 되지 않으면 에이전트가 여러분을 사용하게 됩니다. 소셜 미디어처럼 크리에이터가 될지 소비자가 될지 선택해야 합니다. 저는 AI 혁명의 생산자 쪽에 있고 싶습니다. 다음 영상에서 뵙겠습니다.
