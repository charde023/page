CMUX 워크스페이스 + 오케스트레이터 패턴 + Obsidian 대시보드를 조합해, 10개의 Claude Code 에이전트를 하나의 터미널에서 혼란 없이 운영할 수 있다.

개념 왜 중요한가 한 줄
CMUX 워크스페이스 에이전트별 격리 환경 제공 탭 혼란 대신 이름 붙인 워크스페이스로 분리
오케스트레이터 패턴 상위 에이전트가 하위 에이전트를 제어 cmux send 명령으로 다른 워크스페이스에 프롬프트 전송
cmux read-screen 오케스트레이터가 서브 에이전트 화면을 읽음 폴링 없이 진행 상황 파악
Obsidian Dataview 대시보드 세션 상태를 구조화해 추적 frontmatter의 type: session + status 필드로 자동 집계
세션 파킹 (Session Parking) 진행 중 세션을 끊지 않고 저장 Claude Code 세션 ID를 frontmatter에 기록 → 나중에 재개
CMUX 알림 시스템 에이전트 완료 시 즉시 인지 왼쪽 패널에서 알림 확인, 단축키로 해당 워크스페이스 이동
HTML 태그 코멘트로 소통 에이전트가 파일을 읽을 때 피드백 전달 세션 파일에 코멘트 달면 에이전트가 다음 읽기 시 반영

내가 모를 만한 것 / 처음 보는 것

  • CMUX — Artem Zhutov가 만든 터미널 멀티플렉서. tmux와 유사하지만 Claude Code 에이전트 운영에 특화. 프로그래밍 방식으로 워크스페이스 목록 조회·화면 읽기·명령 전송이 가능 (cmux list-workspaces, cmux read-screen, cmux send)
  • Obsidian Dataview — Obsidian 플러그인. frontmatter 기반 메타데이터를 SQL스러운 쿼리로 집계해 대시보드 테이블 생성. CMUX 세션 추적에 활용
  • 오케스트레이터 워크스페이스 — 메인 Claude Code 인스턴스 하나가 다른 모든 서브 에이전트 워크스페이스를 관리·제어하는 허브 역할
  • 세션 파킹 (parking) — 현재 Claude Code 세션 ID를 Obsidian 세션 파일 frontmatter에 저장해두고, 나중에 그 ID로 세션을 재개하는 패턴
  • CMUX 스킬 — 오케스트레이터에게 CMUX 사용법을 가르치는 클로드 스킬 파일. cmux-artemzhutov.netlify.app에서 다운로드 가능
  • Excalidraw — 다이어그램 생성 도구. 영상에서 에이전트가 CMUX 구조도를 Excalidraw 형식으로 자동 생성하는 예시로 등장
  • 완료의 정의 (Definition of Done) — Obsidian 세션 파일에 명시하는 항목. 이 세션이 끝났다는 기준을 사전에 적어두어 에이전트와 사람이 공유

화자의 디테일 (놓치기 쉬운 포인트)

  1. cmux read-screen 명령 하나로 워크스페이스 전체 화면 텍스트를 읽어 오케스트레이터에게 전달한다 — API 없이 화면 파싱
  2. 오케스트레이터가 서브 에이전트에게 명령 전송 후 15초 sleep → 화면 재읽기 루프로 응답을 폴링하는 패턴을 직접 시연
  3. Obsidian 세션 파일 frontmatter 구조: type: session, title, date, status, goals, progress, outcomes, definition_of_done 필드 포함
  4. Dataview 쿼리로 특정 대시보드(예: demoweek-plan)에 연결된 세션만 필터링 — WHERE dashboard = demoweek-plan 형태
  5. CMUX 워크스페이스 이름에 이모지를 포함할 수 있어서 어떤 작업인지 시각적으로 즉시 파악 가능 (자동 이름 변경도 지원)
  6. 세션 파킹 시 Claude Code 세션 ID를 Obsidian frontmatter에 기록하면, 나중에 그 ID를 입력해 정확히 그 시점으로 세션 복원 가능
  7. 에이전트에게 피드백 줄 때 세션 md 파일에 HTML 태그로 코멘트를 달면 에이전트가 파일 재독 시 그 코멘트를 반영해 작업 수정
  8. 워크스페이스 집중 모드: 나머지 워크스페이스를 숨기고 하나의 터미널에만 포커스하는 기능 존재
  9. Ghosty 터미널·커서(Cursor) IDE의 탭 방식은 에이전트 관리에 부적합하다고 명시 — 작년 여름부터 그 한계를 인식했다고 언급
  10. cmux send [워크스페이스명] [명령] 형태로 특정 워크스페이스에 프롬프트를 프로그래밍 방식으로 전송

# 섹션 요지
1 문제 정의 에이전트 탭이 많아질수록 맥락 파악이 불가능해지는 문제
2 CMUX 소개 워크스페이스·터미널·단축키 기반 멀티 에이전트 관리 도구
3 오케스트레이터 패턴 메인 에이전트가 서브 에이전트 화면을 읽고 명령을 전송하는 루프
4 Obsidian 대시보드 Dataview로 세션 상태(백로그/진행중/완료) 자동 집계·추적
5 실전 시연 다이어그램 생성·세션 파킹·전체 보고서 수집 흐름
6 주간 루프 데일리 노트 → 오케스트레이터 읽기 → 세션 생성 → 진행 확인
7 CMUX 스킬 배포 cmux-artemzhutov.netlify.app에서 스킬 다운로드

1. 문제 정의: 탭 혼란

Claude Code에서 작업을 시작하면 추가 에이전트가 필요해지고, 금방 탭이 10개가 넘는다. 어느 탭에서 무엇이 돌아가는지 파악하기 어렵고, 탭 전환만으로 집중력이 끊긴다. 세션도 금방 낡아져 컨텍스트가 사라진다.

2. CMUX 소개

CMUX는 프로그래밍 방식으로 제어 가능한 터미널 멀티플렉서다.

  • 워크스페이스: 작업 단위로 독립 공간 생성. 이름 + 이모지 지정 가능
  • 터미널 분할: 워크스페이스 안에서 창을 여러 패널로 분할
  • 단축키: 워크스페이스·터미널 간 빠른 이동
  • CLI 접근: cmux list-workspaces, cmux read-screen [ws명], cmux send [ws명] [텍스트]

각 작업마다 분리된 워크스페이스를 두어, 다른 에이전트가 무엇을 하는지 명확히 구분한다.

3. 오케스트레이터 패턴

오케스트레이터 워크스페이스가 핵심이다.

  1. 오케스트레이터에게 CMUX 스킬(사용법 문서)을 제공
  2. 오케스트레이터가 cmux list-workspaces로 워크스페이스 목록 파악
  3. cmux read-screen [ws명]으로 서브 에이전트 화면 내용 읽기
  4. cmux send [ws명] [프롬프트]로 서브 에이전트에게 명령 전송
  5. 15초 sleep → 화면 재읽기로 응답 확인
  6. 모든 서브 에이전트 상태를 취합해 보고서 형태로 정리

오케스트레이터는 직접 타이핑하지 않아도 다른 워크스페이스의 에이전트와 대화하고, 그 결과를 집계한다.

4. Obsidian 대시보드로 세션 추적

각 세션은 Obsidian의 md 파일로 관리된다.

세션 파일 frontmatter 구조:

type: session
title: 다이어그램 생성
date: 2026-03-18
status: active  # backlog / active / done
dashboard: "demoweek-plan"
goals: ...
progress: ...
outcomes: ...
definition_of_done: ...

Dataview 쿼리로 특정 대시보드에 연결된 세션만 필터링해 표로 렌더링. 오케스트레이터도 이 대시보드를 읽어 어느 세션이 진행 중인지 파악한 뒤 각 세션에 맞는 워크스페이스를 자동 생성한다.

5. 실전 시연: 다이어그램 생성 + 세션 파킹

다이어그램 생성 흐름: 1. 오케스트레이터에게 "대시보드 구조를 Excalidraw 다이어그램으로 만들어줘" 요청 2. 오케스트레이터가 cmux send diagram-gen [프롬프트]로 서브 에이전트 호출 3. 서브 에이전트가 CMUX 스킬을 써서 Excalidraw 파일 생성 4. CMUX 알림이 왼쪽 패널에 표시 → 단축키로 해당 워크스페이스로 이동 5. 완성된 다이어그램 확인

세션 파킹 흐름: 1. 핸드오프 스킬로 진행 상황 문서화 요청 2. 오케스트레이터가 해당 워크스페이스에 파킹 명령 전송 3. Claude Code 세션 ID가 Obsidian 세션 파일 frontmatter에 기록됨 4. 나중에 그 세션 ID를 입력하면 정확히 그 시점에서 세션 복원

6. 주간 운영 루프

데일리 노트 작성 (오늘 계획)
  ↓
오케스트레이터가 데일리 노트 읽기
  ↓
이번 주 세션 목록 파악 (Obsidian Dataview)
  ↓
세션별 워크스페이스 자동 생성 + 시작 프롬프트 주입
  ↓
진행 확인: 오케스트레이터가 각 워크스페이스 화면 읽기 → 보고서
  ↓
필요 시 세션 파일에 HTML 코멘트로 피드백
  ↓
완료 세션 파킹 → 다음 작업으로

이 루프를 통해 에이전트들이 병렬로 작업하는 동안, 사람은 오케스트레이터에게 의도만 전달하면 된다.

교정 전사 (한국어)

전체 전사 펼치기

저는 매일 여러 Claude Code 에이전트를 동시에 돌려서 리서치도 하고, 초안도 쓰고, 영상 스크립트도 만들고, 자동화 작업도 하는데 하나도 놓치지 않아요.

Claude Code에 들어가서 작업을 시작하면 다른 일을 맡길 또 다른 에이전트가 필요해져요. 그러다 또 하나, 또 하나 계속 열게 되고, 금방 탭이 열 개가 되면 이 탭에서 뭐가 돌아가는지도 모르겠고, 그걸 계속 왔다 갔다 하는 것만으로도 흐름이 완전히 끊겨요. 세션은 금방 낡아지고 컨텍스트도 사라지죠.

저도 정확히 이런 문제를 겪었고, 이번 영상에서는 그걸 해결해주는 CMUX라는 도구를 보여드릴게요. 이 도구를 쓰면 워크스페이스와 오케스트레이터 패턴을 이용해서 하나의 터미널에서 전부 관리할 수 있어요. 하나의 에이전트가 모든 워크스페이스에 걸쳐 Claude Code를 통해 동작하면서 전체를 제어할 수 있습니다.

각 에이전트의 진행 상황을 추적하고 무슨 일이 벌어지고 있는지 파악하고, 결과물까지 검증할 수 있게 도와주는 대시보드도 함께 살펴볼게요.

CMUX 기본 구조:

왼쪽에 CMUX가 있습니다. 여기에는 워크스페이스가 있고, 각 워크스페이스마다 터미널을 둘 수 있고, 그 안에서 다른 터미널도 띄울 수 있습니다. 단축키가 있어서 이 모든 터미널 사이를 쉽게 이동할 수 있습니다. 워크스페이스로도 이동할 수 있고, 이름도 바꿀 수 있습니다. 창도 분할할 수 있고, 다른 패널을 만들어서 Claude Code 전체를 띄워둘 수도 있습니다. 이렇게 각 작업마다 분리된 워크스페이스를 얻게 됩니다.

CMUX의 핵심 — 프로그래밍 방식 접근:

CMUX가 프로그래밍 가능하다는 점이 핵심입니다. 워크스페이스의 내용을 프로그래밍 방식으로 접근할 수 있어요. 저는 오케스트레이터 워크스페이스를 만들어 두고 CMUX 사용법을 설명하는 CMUX 스킬도 함께 둡니다.

예를 들어 워크스페이스 목록만 보고 싶다면, 이 커맨드라인 도구로 워크스페이스와 그 이름을 정확하게 매핑할 수 있습니다. 각 워크스페이스의 화면도 읽을 수 있어요.

이 영상에서는 오케스트레이터에게 영상 관련 워크스페이스에서 무슨 일이 벌어지고 있는지 물어볼 계획이었습니다. 오케스트레이터는 cmux read-screen 명령 하나로 워크스페이스의 내용을 읽고 정확히 파악하게 됩니다. 더 강력한 점은 프로그래밍 방식으로 그 워크스페이스들과 상호작용할 수도 있다는 거예요.

예를 들어 "방금 읽은 이 워크스페이스의 진행 상황이 어떠냐"고 물어볼 수 있어요. cmux send 명령을 보내면, 제가 타이핑하지 않는데도 에이전트가 이 워크스페이스에 말을 걸기 시작합니다. 오케스트레이터는 15초 동안 기다렸다가 화면을 읽어와 응답을 확인합니다. 아직 생각 중이라면 조금 더 기다리고, 이 워크스페이스에서 컨텍스트를 가져오게 됩니다.

실전 예시 — 데일리 리뷰 워크스페이스 생성:

"제 하루 진행 상황을 검토할 워크스페이스를 만들어줘. 제 데일리 노트에 뭐가 있었는지, 지금까지 얼마나 잘하고 있는지 봐줘." 라고 하면, 오케스트레이터가 daily-review라는 워크스페이스를 만들고 오늘의 데일리 노트를 읽어 요약하는 프롬프트를 주입합니다. Claude Code 에이전트가 파일을 읽고 작업을 끝내는 패턴입니다.

Obsidian 세션 추적:

이런 세션들을 어떻게 전부 추적하느냐는 문제가 있습니다. Obsidian vault를 사용합니다. 주간 대시보드 안에서 모든 세션을 추적해요. frontmatter에 type: session, 제목, 날짜, 상태가 있고 대시보드와 연결됩니다. Dataview 쿼리로 특정 대시보드에 연결된 세션만 필터링합니다. 세션에는 목표, 진행 상황, 결과, 완료의 정의가 있어요.

오케스트레이터도 이 대시보드를 읽을 수 있습니다. "이 대시보드를 읽고 Dataview를 써서 표로 보여달라"고 하면, 모든 세션 파일과 상태를 표로 렌더링해 줍니다.

그러면 각 세션마다 CMUX 워크스페이스를 띄우고, 에이전트에게 세션 파일을 읽게 한 다음 "이 세션을 완수하는 데 가장 영향력이 큰 작업이 무엇인지 알려달라"고 할 수 있습니다. 각 세션마다 별도 워크스페이스가 뜨고, 이름도 붙여주고, 시작 프롬프트도 주입됩니다. 에이전트들이 이미 그 작업을 하고 있죠. 오케스트레이터가 모든 서브 에이전트 화면을 읽어 보고서 형태로 정리해 줍니다.

다이어그램 생성 시연:

에이전트에게 Excalidraw를 사용해서 대시보드 개념을 설명하는 다이어그램을 만들게 합니다. 오케스트레이터가 다이어그램 생성 워크스페이스의 서브 에이전트에게 명령을 전달하고, 그 에이전트가 코딩 스킬을 써서 다이어그램을 만듭니다. CMUX 알림이 완료되면 왼쪽 패널에 표시되고, 단축키로 해당 워크스페이스로 바로 이동합니다.

완성된 다이어그램에는 대시보드에 연결된 세션들(백로그/액티브/완료), 세션별 진행 상황, 각 세션에 연결된 CMUX 워크스페이스 구조가 모두 나타납니다.

세션 파킹:

핸드오프 스킬로 진행 상황을 문서화하면서 다이어그램 생성 세션을 파킹합니다. 오케스트레이터가 해당 워크스페이스에 파킹 명령을 전송하면, Claude Code 세션 ID가 생성되고 Obsidian 세션 파일 frontmatter에 기록됩니다. 나중에 그 세션 ID를 입력하면 정확히 그 시점으로 세션을 복원할 수 있습니다.

"내 세션을 전부 파킹해줘 (단, 10-에이전트 영상 작업과 데일리 리뷰는 제외)" 라고 하면 오케스트레이터가 각 세션에 파킹 명령을 보냅니다.

주간 루프 전체:

데일리 노트에 하루 계획을 작성하면, 오케스트레이터가 그 계획을 읽고 세션을 만들거나 이번 주에 계획해 둔 세션들을 읽어 워크스페이스를 자동 생성합니다. 진행 상황 확인 시 에이전트에게 코멘트를 남기는 방법은 세션 파일에 HTML 태그 코멘트를 다는 것입니다. 에이전트가 파일을 읽을 때 그 코멘트를 보고 작업을 수정합니다.

Ghosty 터미널이나 Cursor의 탭 방식은 에이전트 관리에 좋은 방식이 아니었습니다. 지난 여름부터 그렇게 느꼈고, 이제는 CMUX가 훨씬 낫습니다. 워크스페이스, 세션, 대시보드 개념을 더해 더 확장 가능하고 통제 가능하며 Obsidian과도 통합됩니다.
