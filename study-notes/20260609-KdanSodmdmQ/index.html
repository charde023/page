  • Nous Research (Noose [?NousResearch]) — 오픈소스 AI 선도 연구소, Hermes 에이전트 개발사. NousResearch GitHub 참고.
  • Hermes 에이전트 — Nous Research의 오픈소스 개인 에이전트 프레임워크. Claude Code보다 먼저 존재했으나 초기엔 비주목.
  • Cline [?OpenClaw] — 영상에서 "Open Claw"로 표기된 것은 오픈소스 VS Code AI 코딩 에이전트 Cline으로 추정. 비교 대상.

  • .mcp.json — Claude Code의 MCP 서버 설정 파일. 프로젝트 단위 or 루트 .claude/ 폴더에 추가 가능.
  • non-interactive 모드 — Claude Code를 사람 개입 없이 백그라운드로 실행하는 모드. 에이전트가 주로 활용.
  • Skill Hub — Hermes 공식 스킬 마켓플레이스. 기업·유스케이스별 스킬 제공.
  • PRD (Product Requirements Document) — 제품 요구사항 문서. 스킬로 저장하면 개발 세션 중 자동 컨텍스트 삽입.
  • Educative — 스폰서 언급 플랫폼. LLM·MCP·에이전트 과정 제공, 3백만 개발자 사용. (광고)
  • VPS (Virtual Private Server) — 임대 서버. Hermes 실행 위치 옵션 중 하나(로컬 / VPS / 호스팅).

화자의 디테일 (놓치기 쉬운 포인트)

  1. Hermes는 기본 설치 시 스킬 90개가 사전 탑재된다. 조직이 직접 관리하므로 보안 검증 상태.
  2. Anthropic의 새 정책: 구독에 월별 Agent SDK 크레딧 포함, 초과 시 추가 과금. Claude Code 비대화형(non-interactive) 모드도 동일 적용. 2026-06-15 기준 — 그러나 화자 경험상 이미 6월 전부터 일부 점진 적용 중.
  3. Hermes 설치: 터미널에 인스톨 커맨드 복사·실행 → 의존성 설치 후 인터랙티브 인스톨러 실행. hermes setup 명령으로 나중에 재설정 가능.
  4. Cline [?OpenClaw] 임포트 시 채널 로그인 정보가 Cline 설정을 그대로 가리키고, 지침 파일도 Cline 전용이라 충돌 → 화자는 임포트 안 함 권장.
  5. Claude 모델을 Anthropic 구독으로 쓰려 했으나 오류 → 정책이 일찍 적용된 것으로 추정. Claude Code를 non-interactive 모드로는 여전히 사용 가능.
  6. Hermes를 MCP 서버로 연결하면 이미 Hermes에 연결된 모든 앱(Slack, Discord 등)을 Claude Code에서 별도 설정 없이 재사용 가능.
  7. Slack MCP의 한계: 기본적으로 태그된 메시지만 읽음, 전체 대화 히스토리 불러오기 불가 → Hermes 크론잡이 더 나은 이유.
  8. PRD 크론잡 주기: 30분마다 Slack 채널 모니터링, 요구사항 변경 감지 시 스킬 업데이트 + 프로젝트 내 스킬 파일도 동기화.
  9. 헬스체크 스킬은 실행될 때마다 스스로 개선되고, 개선된 버전이 로컬 프로젝트에도 싱크됨 → Claude Code가 항상 최신 헬스체크 컨텍스트 보유.
  10. Mac Mini 여러 대를 에이전트 실행 전용으로 운용 중이라고 언급 — AI B2B SaaS 팀으로 보임. 팀 규모 소규모 스타트업 추정.
  11. 화자 커뮤니티: AI Labs Pro (ailabspro.io) — Discord bot 설정, Slack 연결 가이드, 헬스체크 스킬 예시 등 상세 자료 보관.

1. Hermes vs Cline [?OpenClaw] — 핵심 차별점

Hermes는 Nous Research가 만든 오픈소스 에이전트. Cline(Claude Code의 외부 경쟁자)보다 먼저 나왔지만 초기엔 주목받지 못했다. Nous Research가 직접 Cline을 써보다 문제를 겪고 직접 만든 게 Hermes다.

3가지 핵심 차이:

  1. 자기 진화형 스킬 (Self-Evolving Skills) — 채팅 중 재사용 가능한 워크플로를 감지하면 자동으로 스킬로 저장·개선. Cline에는 없음.
  2. 지속 메모리 토큰 제한 — user.md·memory.md 파일 크기 상한을 설정. 넘으면 모델이 직접 불필요한 내용 정리. Cline은 제한 없이 계속 쌓임 → 컨텍스트 노이즈 증가.
  3. 내장 샌드박스 — Cline은 직접 샌드박스 구성 필요. Hermes는 기본으로 격리 환경 실행.

왜 메모리 제한이 중요한가: 모델은 컨텍스트 창 내 모든 정보(프롬프트·도구·시스템 지침·파일)를 동시에 처리한다. 정보가 많아질수록 실제 작업에 대한 집중도가 떨어진다. 최신 정보만 유지하고 오래된 것은 제거해 집중도를 유지하는 것.

2. Hermes 설치 및 초기 설정

설치는 터미널에 인스톨 커맨드 복사·붙여넣기로 시작. 의존성 설치 후 인터랙티브 모드로 전환.

선택 항목: - Nous 플랜 vs 수동 설정 — Nous 모델+빌트인 도구 번들 vs 직접 구성. 화자는 수동 선택. - Cline 설정 임포트 여부 — 사용자 프로필·크리덴셜·스킬·soul 파일(에이전트 성격·지침) 가져옴. 단, Cline 전용 지침이라 충돌 발생 → 임포트 비권장. - 모델 선택 — Anthropic 구독으로 Claude 모델 시도 → 정책 오류. Claude Code non-interactive 모드는 여전히 사용 가능. - 실행 환경 — 로컬 / VPS / 호스팅 중 선택. - 메시징 플랫폼 — Discord, Slack 등 연결.

설정 후 hermes 명령으로 UI 로드, 채팅 시작. 개인화를 위해 직접 본인 정보를 입력하거나 second brain(Obsidian 볼트) 경로를 알려주면 스스로 온보딩.

3. Anthropic 구독 정책 변경 (2026-06-15~)

2026년 6월 15일부터 Claude Code 구독으로 Hermes 등 3rd-party 앱을 무료로 연결하는 것이 종료된다.

  • 구독에 월별 Agent SDK 크레딧이 포함되며, Hermes 같은 외부 앱 연결 시 이 크레딧 차감.
  • Claude Code non-interactive 모드(에이전트가 백그라운드 실행하는 방식) 도 동일하게 적용.
  • 화자 경험상 이미 6월 전부터 일부 사용자에게 점진 적용 중.

4. Hermes를 MCP 서버로 연결 → Claude Code에서 활용

핵심 아이디어: Hermes를 MCP 서버로 띄우면, Claude Code에서 Hermes의 모든 기능(스킬·메모리·연결된 앱)을 도구로 호출할 수 있다. Claude Code가 혼자로는 부족한 것들을 Hermes를 통해 채운다.

hermes mcp serve

터미널 출력이 없어도 서버는 실행 중. .mcp.json에 Hermes MCP 추가:

  • 프로젝트 단위: 해당 프로젝트 폴더에만 적용
  • 전역 적용: 루트 .claude/ 폴더에 추가 → 모든 프로젝트에서 사용 가능

Hermes에는 기본 Claude Code 스킬이 내장되어 있어 Claude Code를 에이전트 내에서 어떻게 활용할지 가이드를 제공. 이미 Hermes에 연결된 앱(Discord, Slack 등)을 Claude Code에서 별도 설정 없이 바로 사용 가능.

5. 실전 유스케이스 A — Slack PRD 자동 갱신

시나리오: 팀 Slack 채널에서 요구사항을 논의 → Hermes가 이를 PRD 스킬로 변환하고 자동 갱신.

흐름: 1. Hermes에 Slack 연결 (Discord처럼 봇 설정 필요) 2. Hermes에 크론잡 생성 요청 → 30분마다 특정 채널 모니터링 3. 채널 논의에서 요구사항 변경 감지 → PRD 스킬 자동 업데이트 4. 프로젝트 내 스킬 파일에도 동기화 → Claude Code가 항상 최신 PRD 참조

왜 PRD를 스킬로 관리?: PRD를 단순 파일로 넣으면 모델이 어디에 주의를 기울여야 할지 혼동. 스킬은 필요할 때만 호출되어 컨텍스트 창의 신선한 부분에 위치 → 모델 집중도 유지.

왜 Slack MCP가 아닌 Hermes 크론잡?: Slack MCP는 기본적으로 태그된 메시지만 읽음. 전체 대화 히스토리 불러오기 불가. Hermes 크론잡이 직접 채널 히스토리를 동기화하므로 더 나음.

6. 실전 유스케이스 B — 배포 앱 헬스체크 자동화

시나리오: Claude Code로 만든 배포 앱의 상태를 Hermes가 자율적으로 모니터링·개선.

흐름: 1. Claude Code로 앱 빌드 → 헬스체크 스킬 생성 (Claude Code가 앱 컨텍스트 가장 잘 앎) 2. 해당 스킬을 Hermes에 임포트 3. Hermes가 크론잡 설정 → 스케줄에 따라 헬스체크 스킬 자동 실행 4. 이슈 발견 시: 스킬 자체를 개선·업데이트 + 로컬 프로젝트에도 싱크 5. Claude Code가 MCP를 통해 리포트·수정 제안 수신 → 직접 구현 or Hermes에 자동 수정 위임

핵심: 스킬이 실행될 때마다 자기 개선 → 헬스체크 품질이 점점 높아짐.

7. Skill Hub 보안 및 기타 특징

  • 기본 90개 스킬 사전 탑재. Nous Research가 직접 관리 → 보안 검증됨.
  • Skill Hub: 공식 스킬 마켓플레이스. 업로드 시 보안 스캔 + 위험 프롬프트·데이터 유출 스크립트 감지.
  • Cline 스킬과 달리 안전한 스킬만 유통 — 화자 이전 영상에서 Cline 스킬 다수가 실제 데이터 유출 위험 있었다고 언급.
  • 어떤 MCP도 Hermes에 연결 가능. Hermes 자체를 MCP 서버로도 실행 가능 → 양방향 통신.

Claude Code 자체는 훌륭하지만, 한 가지 결정적인 게 빠져 있다. Hermes의 자기 진화형 스킬 시스템. 이게 더해지면, 우리가 자동화할 수 있을 거라 생각조차 못 했던 것들까지 훨씬 더 자율적인 워크플로를 만들 수 있다. 개인 에이전트뿐 아니라, 프로세스를 자동화하려는 어떤 비즈니스에든 설정할 수 있고, 방법도 정말 간단하다.

Hermes 에이전트가 처음인 분들도 걱정 마라. 처음부터 안내할 테니. 본격적인 설정에 앞서, 자기 진화형 스킬 시스템이 왜 중요한지부터 시작하자. 우리가 이것을 처음 접했을 때, Cline보다 실제로 더 낫겠다는 생각이 들었다. 단순한 프로젝트가 아니다. Nous Research(뇨 [?노우스] 리서치) — 오픈소스 AI 선도 연구소 중 하나 — 가 만들었고, 그 연구소의 가장 인기 있는 프로젝트 중 하나가 됐다.

흥미로운 사실 하나. Hermes 에이전트는 사실 Cline보다 먼저 만들어졌다. 처음엔 주목받지 못했을 뿐이다. Nous Research 팀도 Cline을 써봤는데 문제가 생겨서 자체 설정으로 전환했다. 문제를 직접 겪고 해결책을 오픈소스로 공개한 것이다. Hermes의 기능 대부분은 Cline과 동일하다. Cline처럼 여러 플랫폼에 연결 가능하다. 하지만 두 가지가 훨씬 낫다. 첫째는 지속 메모리, 둘째는 자기 개선 스킬이다.

Cline도 지속 메모리가 있어서 사용자에 대한 정보를 기억하고 답변을 맞춤화할 수 있지만, 한계가 있다. Hermes는 더 나아간다. 메모리를 저장하고, 채팅에서 재사용 가능한 워크플로를 발견하면 스킬로 변환한다. Hermes의 지속 메모리는 매우 스마트한 구조 위에 만들어졌다. user.md와 memory.md 파일에 크기 제한을 건다. 채팅을 하다 보면 매 실행 후 이 파일들이 업데이트된다. 왜 제한이 필요한가? 모델이 작동하는 방식 때문이다.

사람처럼 모델도 주의 집중 범위가 한정되어 있다. 한 번에 제한된 양의 정보만 처리할 수 있고, 정보가 너무 많으면 혼동한다. 프롬프트·도구·시스템 지침·사용자 파일까지 모든 정보가 컨텍스트 창 안에서 모델의 주의를 놓고 경쟁한다. 컨텍스트에 넣는 게 많아질수록 실제 작업에 대한 집중이 흐려진다. 여분의 정보가 전부 노이즈가 된다. 그래서 토큰 제한이 필요하다.

Hermes는 파일이 토큰 한계에 도달하면 모델이 직접 파일을 검토해 불필요한 것을 잘라낸다. 최신 정보만 메모리에 유지해 에이전트가 이제 필요 없는 오래된 내용에 방해받지 않게 한다. Cline은 이런 게 전혀 없다. 메모리가 그냥 계속 커진다.

Cline에서 겪은 또 다른 문제는 보안이다. Cline을 보안 처리하려면 직접 샌드박스를 구성해야 했다. Hermes는 자체적으로 샌드박스 안에서 실행된다. 격리 환경이라 접근해선 안 될 것에 손대거나 실수로 잘못된 행동을 하지 않는다. Cline의 보안 문제 대부분이 사라지는 것이다.

Hermes를 Claude Code와 함께 구동하려면 지금이 최적의 타이밍이다. 인색한 다리오 [?Dario Amodei]가 Claude 구독으로 서드파티 앱을 사용하는 것에 돈을 청구하는 새 방법을 발견했으니까. 6월 15일 이후로는 Claude Code 구독으로 Hermes 같은 에이전트를 무료로 실행할 수 없다. Anthropic에 추가 요금을 내야 한다. 구독에 월별 Agent SDK 크레딧이 포함되고, 구독을 통해 서드파티 앱을 연결하면 그 크레딧이 소진된다. non-interactive 모드 — 많은 에이전트가 권한 프롬프트 없이 백그라운드로 Claude Code를 실행하는 방식 — 에도 동일한 제한이 적용된다. 6월 15일까지는 어처구니없는 API 비용 없이 Hermes를 계속 돌릴 수 있다.

Hermes 에이전트 설정은 사실 꽤 간단하다. 인스톨 커맨드를 복사해서 터미널에서 실행하면 된다. 필요한 의존성을 먼저 설치하고 인터랙티브 모드로 인스톨러를 실행한다. Nous 플랜(모델+빌트인 도구 번들)으로 설정하고 싶다면 그렇게 해도 된다. 우리는 자체 설정을 원해서 수동 옵션을 선택했다. hermes setup 명령으로 나중에 언제든 재설정 가능하다.

이 단계에서 에이전트에 필요한 모든 것을 설정한다. Hermes는 이전 Cline 설정을 임포트할 수 있어서, 먼저 그걸 가져올지 묻는다. 정확히 무엇이 넘어오는지 직접 확인할 수 있다. 사용자 프로필·크리덴셜, 스킬, soul 파일(기본적으로 에이전트의 성격·지침)이 포함된다.

하지만 혈통을 대물림하면 그 장점과 함께 문제도 따라오듯, 에이전트 간 임포트에도 문제가 있다. 가져온 로그인 정보가 여전히 Cline 에이전트가 쓰던 채널을 가리키고, Cline이 의존하던 파일들도 깔끔하게 옮겨오지 않는다. 그 지침들이 Cline 전용으로 작성됐기 때문이다. 임포트하면 문제만 생기고, 그래서 우리는 임포트하지 않았다.

그다음 Hermes가 사용할 모델을 선택한다. Anthropic 구독으로 Claude 모델을 써보려 했지만 오류가 났다. 다리오가 이미 추가 사용 설정을 요구하고 있었다. 6월 15일도 되지 않았는데. 그 정책이 이미 점진적으로 적용되고 있는 것 같다. 단, 여러분은 아직 될 수도 있다. 어찌됐든 Claude Code의 non-interactive 모드는 지금 당장도 사용 가능하고, 대부분 작업에 이 방식을 쓸 것이다. 모델 제공자는 나중에 언제든 변경 가능하다.

모델 설정 후 에이전트가 어디서 실행될지 묻는다. 호스팅 서버 또는 VPS — VPS는 임대해서 직접 운영하는 서버 — 중 선택. 우리는 이 용도로만 돌리는 Mac mini가 있어서 로컬을 선택했다. 참고로 Mac mini 품절 사태를 일으킨 건 우리가 아니다. 불행히도 우리의 AI B2B SaaS 사업도 자금이 바닥났거든. 그다음 원하는 메시징 플랫폼을 연결한다. 우리는 Discord를 선택했지만 어느 것이든 연결 가능하다. Discord 봇 설정은 여기선 다루지 않는다. 커뮤니티 AI Labs Pro에 전체 가이드가 있다. 이것저것 몇 가지 더 묻고 나면 에이전트 준비 완료. hermes를 입력하면 UI가 로드되고 바로 채팅할 수 있다.

에이전트가 실제로 필요한 것에 맞춰 스스로를 조정하려면 나에 대한 정보가 필요하다. 한 달 정도 쓰면서 스스로 파악하게 둘 수도 있고, 아니면 처음부터 직접 알려줘도 된다. 다른 작업을 시키기 전에. 개인 에이전트로 설정하고 싶다면 채팅에서 직접 정보를 주거나, second brain(Obsidian 볼트 등) 경로를 알려주고 거기서 온보딩하게 하면 된다. 특정 자동화 유스케이스를 위해 설정하려면 해당 유스케이스 문서나 설정 대상 회사의 일반 정보를 제공하면 된다.

(스폰서: Educative — LLM 에센셜, MCP 기초, 에이전틱 시스템 설계, 16시간 LLM 부트캠프. 코드 직접 작성, AI 피드백, 3백만 개발자 사용. 무료 체험 링크 설명란에.)

Skill Hub에서 Hermes 에이전트용 스킬 컬렉션을 직접 구성할 수 있다. 공식 스킬 마켓플레이스로 기업·유스케이스별 스킬이 다양하다. Hermes는 기본 90개 스킬이 설치된다. 이 사전 설치 스킬들은 조직이 직접 관리하므로 실제로 보안이 검증되어 있다. 이전 영상에서 다룬 Cline 스킬과 비교하면 실질적인 차이다. Cline 스킬 상당수가 위험 프롬프트나 데이터를 서버로 빼돌리는 스크립트 등 심각한 보안 문제가 있었다. Skill Hub는 각 스킬에 대해 보안 스캔을 실행하고 이런 문제를 감시한다. 원하는 스킬을 위험 없이 추가할 수 있다.

다른 에이전트와 마찬가지로 어떤 MCP든 Hermes에 연결 가능하다. 하지만 Hermes를 나머지와 구분짓는 것은 이거다: Hermes 설정 자체를 MCP 서버로 실행해서 다른 에이전트에 연결할 수 있다. 그러면 다른 에이전트들이 도구를 통해 Hermes에 접근할 수 있다. 통신이 양방향이 되는 것. 이렇게 Hermes를 다른 에이전트에 연결하면 그 에이전트에 없는 것들을 채워준다. Claude Code 단독으로는 나에 대한 기억이 없고 스킬이 스스로 수정·개선되지 않는다. 하지만 MCP 연결을 통해 Hermes가 할 수 있는 모든 것에 접근을 줄 수 있다. 또한 에이전트마다 개별 앱에 일일이 연결할 필요 없이, Hermes에 이미 연결된 모든 앱을 그냥 사용할 수 있다.

Hermes를 MCP로 실행하려면 hermes mcp serve 명령을 실행한다. 서버가 시작됐다는 터미널 출력은 없지만 실제로 실행 중이다. 에이전트에 연결하려면 .mcp.json 파일에 Hermes MCP를 추가한다. 프로젝트 스코프로 설정하면 해당 프로젝트에서만 접근 가능하다. 루트 .claude/ 폴더에 설정을 추가하면 모든 프로젝트에서 Hermes MCP를 사용할 수 있다.

스킬 얘기가 나왔으니, Hermes에는 Claude Code 스킬이 기본 탑재되어 있다. 에이전트를 통해 Claude Code를 어떻게 활용하는지 가이드가 들어있다. Hermes 설정이 MCP로 실행되는 것과 결합하면 엄청난 가능성이 열린다.

Hermes 에이전트와 Claude Code를 함께 쓰면 수많은 유스케이스가 열린다. 특히 반복 프로세스를 여러 자동화로 처리하고 싶은 비즈니스에서. 그중 하나가 Claude Code를 팀 Slack 워크스페이스에 연결하는 것이다. 이게 잘 맞는 이유: Hermes는 항상 돌아가는 에이전트이고, Claude Code는 실제 개발이 일어나는 곳이다. Hermes 에이전트로 팀 워크스페이스에 접근한다. Discord 설정과 마찬가지로 Slack 연결은 여기서 다루지 않는다. 커뮤니티에 전체 가이드가 있다.

대부분 워크스페이스에는 프로젝트 전용 채널이 있고 팀 전체가 거기서 다양한 논의를 한다. Hermes 에이전트로 할 수 있는 것은, 그 특정 채널을 모니터링하는 크론잡을 만들어달라고 하는 것이다. 그 채널에서 논의된 요구사항을 기반으로 PRD 스킬을 만들고, 요구사항이 바뀌면 그게 진화한다. PRD를 스킬로 갖고 있으면 특히 제품을 실제로 개발하는 세션에서 유용하다. 필요할 때마다 PRD의 관련 부분이 컨텍스트에 들어와 프로젝트가 원래 요구사항과 정렬 상태를 유지한다.

PRD만으로도 될 것 같지만, 앞서 말한 이유 때문에 에이전트가 무엇에 주의를 기울여야 할지 헷갈릴 수 있다. 스킬은 필요할 때만 호출되어 모델이 실제로 주의를 기울이는 컨텍스트 창의 신선한 부분에 위치한다. 그래서 Hermes가 지시한 대로 스킬을 만들고 30분마다 크론잡으로 실행한다. 채널에서 요구사항 변경이 논의되면 PRD를 업데이트하고, Hermes 에이전트가 그 변경이 양방향으로 흐르도록 한다. 프로젝트 내 스킬도 최신 상태를 유지하게.

이쯤 되면 생각할 수 있다: Hermes 에이전트용 MCP가 이미 연결되어 있으니, 그냥 Slack 채널에서 정보를 가져오는 도구를 쓰면 되지 않나? 이유는 Slack MCP의 한계 때문이다. 기본적으로 전체 대화 기록을 읽을 수 없다. 태그된 메시지만 읽고, 태그된 메시지가 그 컨텍스트를 명시적으로 필요로 할 때만 전체 기록을 가져온다. 그래서 Hermes 에이전트를 통해 설정하는 게 더 나은 방법이다. 정보를 거기서 직접 동기화할 수 있으니까.

거기서 더 나아가, Claude Code non-interactive 모드를 Hermes 에이전트 채널을 통해 직접 기능 구현에 활용할 수도 있다. 앞서 말한 Claude Code 스킬을 로드하고, Claude Code를 실행해서 Hermes 에이전트를 빌드하는 데 사용한다.

이 콘텐츠가 도움이 됐다면 좋아요 버튼을 눌러줘라. 더 많은 사람들에게 닿는 데 도움이 된다. Claude Code로 빌드한 배포 앱에도 Hermes를 붙일 수 있다. 개인용이든 클라이언트용이든. 배포된 앱이 있다면, 앱 모니터링 및 헬스체크를 위한 스킬을 만들 수 있다. 앱이 실제로 뭘 필요로 하는지는 Claude Code가 가장 잘 안다. 그 스킬들을 Hermes 에이전트에 임포트한다. 크론잡을 설정하면 Claude Code가 스케줄에 맞춰 자체적으로 실행되며 에이전트가 호스팅 앱과 코드 양쪽을 모니터링한다. 스킬을 실행하다 이슈를 발견하면 스킬을 업데이트하고 로컬 프로젝트에도 싱크해서 Claude Code도 최신 정보를 갖게 한다.

이것이 자기 진화형 스킬이 매번 실행마다 더 나아지는 지속적 헬스체크 설정에 어떻게 도움이 되는지다. Hermes에 프롬프트를 주면 크론잡을 설정해준다. 테스트 실행으로 올바르게 설정됐는지 확인 가능. 설정한 채널에 리포트가 온다. MCP가 설정된 상태에서 Claude Code 안에서 바로 그 리포트와 팀원들의 수정 제안을 받아볼 수 있고, 프로젝트에 직접 구현 가능하다. 직접 수정을 푸시하거나, Hermes 에이전트가 Claude Code로 이슈를 자동 수정하게 설정할 수도 있다.
