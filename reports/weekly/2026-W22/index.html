QCDP — 보고의 4축

풀 리포트는 금지. 이 프로젝트에서 가장 중요한 축만 골라 보고한다.

축 핵심 질문 실전 예
Q Quality 쓸 수 있는 수준인가? 데이터 무결성, 납품 기준 충족 여부
C Cost 얼마나 들었고 앞으로는? 투입비, 맨아워, LLM 토큰
D Delivery 언제 나오는가? D-day, 퍼블리싱 일정
P Productivity 양산(정규화) 가능한가? 병렬화, 반복성, 재구현성

보고 3원칙

  1. 보스의 머릿속 먼저 — 내가 하고 싶은 말이 아니라, 상대가 궁금한 것을 가져간다.
  2. 토픽 하나에 집중 — 풀 리포트가 아니라 그 프로젝트의 핵심 QCDP 축만.
  3. D-day는 반드시 — 딜리버리 날짜 없는 보고는 보고가 아니다.

파레토 — 급소부터 해결

"급소만 해결하면 완전하지 않아도 출시는 된다."

실무자 함정 경영자 관점
완벽하게 끝낸 뒤 출시 급소 해결 → 출시 → 수익화 → 수정
100% 완성에 시간 소진 → 지연 80% 급소로 먼저 시장 진입

맨아워 → LLM 전환

옛날의 "인력 투입"이 지금은 "LLM 투입"으로 바뀌었다. 토큰 = 새로운 맨아워.

옛날 (사람) 지금 (LLM)
인력 채용 LLM 인스턴스 추가
3명 투입 → 처리 시간 1/3 LLM 3개 병렬 → 처리 속도 향상
장비 구매 = 생산 투자 토큰 증가 = 맨아워 증가

보고 실패 vs 성공

실패하는 보고 성공하는 보고
내가 보고하고 싶은 것 보스가 궁금한 것
D-day 없음 D-day 명시
풀 리포트 (전부 나열) 핵심 토픽 하나만
완벽 추구 → 지연 급소 해결 → 출시
