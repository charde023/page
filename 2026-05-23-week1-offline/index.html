2. 멍멍 님 사례 — 노트북LM 웹 클리퍼 만들기

멍멍 님은 비개발 문과생이라고 자신을 소개했지만, 노트북LM을 더 편하게 쓰기 위해 크롬 확장 프로그램을 만들었습니다. 출발점은 업무에서 반복적으로 자료를 찾고 답변해야 하는 문제였습니다. 과거에는 업무 자료를 기반으로 답하는 RAG 챗봇을 만들었고, 이후 노트북LM이 자료 요약, FAQ, 발표 자료, 팟캐스트, 동영상 보고서까지 만들어 주는 것을 보며 입력 과정을 줄이고 싶어졌습니다.

RAG는 AI에게 참고서를 쥐여 주는 방식입니다

발표에서는 RAG를 오픈북 방식으로 설명했습니다. AI가 모르는 내용을 억지로 외우게 하는 파인튜닝 대신, 필요한 자료를 색인해 두고 질문이 들어오면 관련 자료를 찾아 답하게 하는 방식입니다. 노트북LM은 이런 자료 기반 작업을 쉽게 해 주지만, 좋은 자료를 노트북에 넣는 반복 과정이 귀찮았습니다.

개념 쉬운 설명 발표에서의 용도
파인튜닝 AI 자체를 다시 학습시키는 방식 비용과 난도가 높아 일반 사용자가 바로 쓰기 어렵습니다.
RAG AI에게 참고서를 찾아보게 하는 방식 업무 자료나 웹 문서를 근거로 답변하게 합니다.
노트북LM 자료를 넣고 그 자료 기반으로 대화, 요약, 콘텐츠 생성을 하는 도구 개인 지식과 덕질 자료를 정리하는 기반이 되었습니다.
크롬 익스텐션 브라우저에서 바로 쓰는 미니 앱 웹페이지, 자막, 캡처, 파일을 노트북LM에 넣기 위한 입구가 되었습니다.

바이브 코딩은 작은 기능부터 붙이는 방식으로 진행되었습니다

멍멍 님은 처음부터 완성된 기획 문서를 만들지 않았습니다. 웹스토어의 기존 확장 프로그램을 벤치마킹하고, 현재 페이지 저장, 유튜브 자막 추출, 노트북 채팅, 지식 분류, 스크롤 캡처, 파일 드래그 앤 드랍 같은 기능을 하나씩 붙였습니다.

막히는 지점에서는 LLM에게 질문했습니다. “크롬 확장 프로그램은 어떻게 만들지”, “웹스토어 등록은 어떻게 하지”, “이 버튼이 왜 동작하지 않지”처럼 문제를 말로 설명하고, 화면 캡처를 던지며 수정했습니다. 중요한 것은 개발 용어를 완벽히 아는 것이 아니라, 현상을 정확히 설명하고 작게 테스트하는 태도였습니다.

3. 댁 님 사례 — 헤르메스로 음악 자동화 파이프라인 만들기

댁 님은 헤르메스를 이용해 수노에서 음악을 생성하고, 플레이리스트를 만들고, 유튜브 업로드까지 자동화하는 파이프라인을 소개했습니다. 목적은 수익화보다 본인이 들을 음악을 꾸준히 만드는 것이었고, 인기 있는 카페 음악보다 IDM처럼 개인 취향이 강한 장르를 대상으로 삼았습니다.

시스템은 하나의 큰 봇이 모든 일을 하는 방식이 아니라 역할 분담 구조였습니다. 메인 봇은 매일 작업을 호출하고, 오퍼레이터 봇은 생성, 검증, 업로드를 실행하고, 데브 봇은 코드 문제를 수정하며, PKM 봇은 지식 관리를 맡는 식입니다.

역할 하는 일 운영상 의미
메인 봇 매일 정해진 시간에 작업 호출 자동화의 시작점을 일정하게 만듭니다.
오퍼레이터 봇 생성, 검증, 업로드 실행 반복 작업을 실제로 처리합니다.
데브 봇 코드 수정과 문제 해결 자동화 시스템 자체의 유지보수를 맡습니다.
PKM 봇 지식과 실패 패턴 관리 다음 실행에서 같은 실수를 줄입니다.

브라우저 유즈는 사람이 조작하듯 브라우저를 다룹니다

수노는 자동화 탐지가 강해 일반적인 브라우저 자동화 도구만으로는 캡차가 뜨기 쉽습니다. 댁 님은 브라우저 유즈를 사용해 사람이 실제 브라우저를 조작하는 방식에 가깝게 접근했습니다. 플레이라이트처럼 뒤에서 제어하는 방식과 달리, 브라우저 유즈는 화면 위에서 클릭하고 조작하는 방식이라 봇 탐지를 피하는 데 유리하다고 설명했습니다.

하지만 자동화에는 안전장치가 필요합니다. 캡차, 결제 팝업, 권한 UI가 뜨면 즉시 중단하도록 했고, 해결 후 다시 진행하게 했습니다. 음악 생성도 처음에는 30번 생성해 60곡 중 30곡을 골랐지만, 버려지는 곡이 아까워 나중에는 15번 생성해 30곡에서 플레이리스트를 구성하는 식으로 조정했습니다.

위험 지점 자동화 규칙 이유
캡차 발견 즉시 중단 자동화 탐지 상태에서 무리하게 진행하지 않기 위해서입니다.
결제 팝업 발견 즉시 중단 저장된 카드로 원치 않는 결제가 되는 것을 막습니다.
권한 요청 발견 즉시 중단 사용자가 확인해야 하는 영역을 AI가 넘지 않게 합니다.
잘못된 음원 중복, 단음 반복, 이전 곡 삽입을 검사 결과물 품질을 자동화 단계에서 보정합니다.
커버 생성 실패 대체 도형으로 임의 처리하지 말고 보고 실패를 숨기지 않고 운영 지식으로 남깁니다.

4. 사례 발표에서 배울 것은 단어와 맥락입니다

운영자는 발표 중간에 도구 이름을 아는 것만으로도 AI에게 더 명확히 지시할 수 있다고 설명했습니다. “브라우저 유즈를 써서 해 봐”라고 말할 수 있으려면, 브라우저 유즈라는 단어와 그것이 쓰이는 맥락을 알아야 합니다.

이 관점에서 오프모임의 발표는 완성된 정답지가 아니라 어휘를 얻는 자리였습니다. RAG, 크롬 익스텐션, 노트북LM, 브라우저 유즈, 칸반, 크론, 실패 패턴, 오토 메모리 같은 단어를 실제 사례와 함께 들으면, 이후 자신의 AI에게 더 정확한 작업 지시를 할 수 있습니다.

들은 단어 어디에 쓰였나 다음에 시킬 수 있는 말
RAG 내 자료를 근거로 답하는 AI 비서 “이 자료들을 RAG 방식으로 검색해서 답하게 해 주세요.”
크롬 익스텐션 노트북LM 입력을 줄이는 브라우저 미니 앱 “현재 페이지를 저장하는 크롬 확장 기능부터 만들어 주세요.”
브라우저 유즈 수노 자동화에서 사람이 조작하듯 클릭 “브라우저 유즈로 로그인 상태를 확인하고 작업해 주세요.”
칸반 생성, 검증, 업로드 작업 단계 관리 “이 자동화 작업을 칸반 카드 단위로 쪼개 주세요.”
실패 패턴 잘못된 커버 생성이나 중복 음원 같은 반복 오류 “이번 실패를 다음 실행에서 피하도록 메모리에 남겨 주세요.”

5. 1주차 이후의 학습 루틴

마지막 운영 안내에서는 사례글, OT 과제, 아티클 챌린지, 학습반장 제도가 소개되었습니다. 핵심은 숙제를 위한 숙제가 아니라 시행착오를 공유해 다른 멤버도 배울 수 있게 하는 것입니다.

사례글은 “내 결과물을 자랑하기 위해서”보다 “내 시행착오를 공유하기 위해서” 쓰는 것입니다. 게시글이 시스템에서 인정되려면 해당 스터디 태그가 필요하고, 작성 후에는 카톡방에도 알려야 다른 사람들이 읽고 반응할 수 있습니다.

항목 해야 할 일 이유
사례글 수강 스터디 태그를 달고 작성 시스템에서 제출 글로 인식되게 합니다.
OT 과제 OT를 따라 하며 겪은 시행착오를 내일까지 자정 전 공유 1주차 실습 경험이 사라지지 않게 합니다.
청강 스터디 접근 수강 스터디 사례를 스터디 시작 전까지 작성 청강 스터디 다시보기 접근 조건과 연결됩니다.
아티클 챌린지 좋은 아티클 링크와 한 줄 요약을 네트워킹 방에 인증 AI 시대의 읽기 루틴을 만듭니다.
게시글 댓글 지피터스 게시글을 읽고 댓글 인증 같은 기수의 시행착오를 서로 학습합니다.
미니세션 화요일 8시에서 9시 실습 세션 참여 필요한 설치와 기초 작업을 학습반장에게 도움받습니다.

아티클 챌린지는 단순히 AI와 친해지는 수준에서 더 나아가, 매주 공유되는 좋은 글을 읽고 요약하는 루틴으로 바뀌었습니다. 또는 지피터스 게시글을 읽고 댓글을 남기는 것도 인증이 됩니다. 중요한 것은 매일 조금씩 읽고, 반응하고, 기록하는 것입니다.

6. 자주 막히는 곳

증상 대응
처음 왔는데 다들 너무 잘하는 사람처럼 보여 위축됩니다. 처음 온 사람, 재참여자, 장기 참여자가 모두 같은 과정을 거쳤다는 점을 기억하고 작은 발표나 댓글부터 시작합니다.
사례글에 무엇을 써야 할지 모르겠습니다. 결과물이 완성되지 않아도 괜찮으므로 따라 하며 막힌 지점, 실패한 이유, 다음에 바꿀 점을 씁니다.
게시글을 올렸는데 제출로 인정될지 모르겠습니다. 수강 스터디 태그와 필요한 경우 OT 과제 태그를 반드시 달고, 카톡방에 공유합니다.
비개발자인데 크롬 확장 프로그램이나 자동화를 만들 수 있을지 막막합니다. 불러오기, 저장하기, 버튼 고치기처럼 작은 기능 하나를 정하고 LLM에게 화면과 현상을 설명하며 진행합니다.
자동화가 결제나 권한 화면까지 넘어갈까 불안합니다. 캡차, 결제, 권한 요청을 발견하면 즉시 중단하도록 규칙을 먼저 둡니다.
AI에게 무엇이라고 시켜야 할지 모르겠습니다. 발표에서 나온 도구 이름과 맥락을 기록하고 “브라우저 유즈로”, “RAG 방식으로”, “칸반 작업으로”처럼 구체적으로 지시합니다.
아티클 챌린지를 AI로 자동화해도 되는지 고민됩니다. 자동화 자체도 학습이 될 수 있지만, 최소한 핵심 내용은 직접 읽고 한 줄 의미를 남기는 방향을 권장합니다.
