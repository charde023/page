## 강의는 어떤 내용이었나

지피터스 22기 4주차 베스트 발표회 중 콘텐츠와 지식 사례를 모은 세션이다. 진행자 보배 교수가 지난주 각 스터디에서 투표로 선정된 우수 사례 7개를 12분 내외씩 소개하도록 안내했고, 발표자들은 영상 제작, 코드 교육, 의료 앱, 주식 자동화, 강의 자동화 사례를 공유했다.

세션의 공통점은 단순한 도구 소개가 아니라 "내가 잘 아는 문제에 AI를 붙이면 어떤 일이 일어났는가"였다. 영상은 처음 만들어보는 사람이 AI 어시스턴트에 의지해 카페 홍보 쇼폼을 완성했고, 게임학과 교수는 마크다운 파일로 학생들의 코딩 품질을 올렸으며, 한의원 원장은 4개 AI를 교차 검증해 체질 분류 앱을 만들었다. 자동매매는 에이전트 3분리 구조로 개선하고 있었고, 전자책은 30분 안에 초안이 완성됐으며, 강의 공장은 5입력→6에이전트 검수→자동 슬라이드 생성까지 파이프라인으로 묶였다.

## 0. 한눈에 보는 콘텐츠와 지식 사례

1. 내가 잘 아는 문제를 찾는다 — 카페 홍보, 게임 수업, 한의원 체질, 부동산 강의처럼 각 발표는 자신의 일상 또는 업무 문제에서 시작했다.
2. 첫 시도는 단순하게 시작한다 — 조연은 처음 만들어보는 영상, 아루네는 설문지 수준으로 시작해서 완성도를 높여갔다.
3. 파일로 컨텍스트를 준다 — 마크다운 파일, 54개 파일 경로, 5입력 기획서처럼 구조화된 정보를 파일로 던지면 결과가 달라진다.
4. AI 하나가 아니라 여러 개를 교차한다 — 아루네는 4개 AI를, 도시아재는 6개 에이전트를 교차 검증에 활용했다.
5. 자동화는 역할별로 쪼갠다 — 에이전트가 하나의 긴 파이프라인을 혼자 담당하면 실패 원인을 추적하기 어렵다.
6. 사람이 검수할 지점을 정해둔다 — 강의 교안, 의료 체질 판별, 주식 매매처럼 영향이 큰 영역은 사람 승인 단계를 제거하지 않는다.
7. 작게 만들고 계속 반복한다 — "계속 만들다 보면 나만의 노하우가 생긴다"는 말이 여러 발표자에게서 반복됐다.

## 1. 조연 — 코알못이 AI 도구로 카페 홍보 쇼폼을 완성하기까지

조연 발표의 출발점은 "영상은 하면 나온다"는 스터디장의 말이었다. AI 도구를 잘 쓰지 않던 사람이 바이브 코딩도 처음 해보고 영상도 두 번째로 만들어보는 상황에서 카페 홍보 쇼폼을 완성했다.

사용한 도구는 **안티그래비티**, **Gemini**, **Flow**, 그리고 스터디장이 제공한 **물결님 대시보드**였다.

| 단계 | 한 일 | 막힌 지점 |
|---|---|---|
| 레퍼런스 분석 | 유튜브 영상 링크를 Gemini와 안티그래비티에 넣어 분석 요청 | 안티그래비티가 지브리풍으로 알아서 설정해서 Gemini 프롬프트로 교체 |
| 캐릭터 생성 | Flow에서 바리스타 남녀 2인 캐릭터 반복 수정 | 얼굴·옷·앞치마 색깔을 일관되게 맞추는 데 여러 번 시도 필요 |
| 씬 6개 제작 | Gemini의 프롬프트를 안티그래비티에 붙여넣어 씬별 영상 생성 | 원두 장면에서 홀빈 원두로 내리는 오류 → 1~2번 수정으로 해결 |
| 캐릭터 수정 | 합장 장면을 손 흔드는 장면으로 변경 요청 | 구글 정책 위반이 반복됨. 프롬프트를 조정해 뒷부분만 수정 요청으로 해결 |
| 음악 추가 | 안티그래비티에 음악 파일 삽입 방법 문의 | — |
| 최종 영상 | 6개 씬을 붙여 한 영상으로 완성 | 말·자막 길이가 짤리는 문제 → 프롬프트 조정으로 해결 |

> "촬영 없이도 이렇게 여러 AI 도구들을 이용해서 영상을 만들 수 있다는 게 되게 재미있었고요."

회고도 실용적이었다. 캐릭터 생성이 제일 어려웠고, 정책 위반은 크레딧이 들어가서 가장 난감했으나 프롬프트를 물어봐서 해결했다. 스터디장이 제공한 대시보드는 씬별 프롬프트와 산출물을 한 화면에서 정리해 볼 수 있어서 수정 흐름에 큰 도움이 됐다.

## 2. 공대언니 — 마크다운 파일로 요청하면 AI가 수준에 맞는 코드를 짠다

공대언니(게임학과 교수) 발표는 학생들에게 AI로 더 잘 코딩하도록 가르치는 방법이었다.

문제는 세 가지였다. 무료 AI에 "객체지향으로 짜줘"라고 해도 static으로 코드를 만들어주고, 학생들이 배운 수준보다 너무 어렵게 짜주고, 같은 요청을 반복하는 게 비효율적이었다.

해결책은 **마크다운 파일**이었다.

| 방법 | 효과 |
|---|---|
| 마크다운에 "나는 어디까지 배웠다"고 명시 | AI가 학습 수준에 맞게 코드를 생성 |
| 파일명까지 지정해서 요청 | 통으로 짜지 않고 파일별로 명확하게 분리 |
| 앞에 "전문가라고 생각하고 짜줘라" 추가 | 품질 향상 |
| "부족한 부분이 있으면 네가 업데이트해줘라" | 귀찮아하는 학생도 보완된 코드 얻음 |
| 대화 내용을 마크다운으로 저장 후 웹페이지로 배포 | 학생들이 집에 가서도 참고 가능한 강의 자료 생성 |

실습 현장에서 변화가 있었다. 평소에는 AI로 만들어 붙이면서 에러가 엄청 뜨고 했었는데, 마크다운 방식으로 바꾸고 나서는 에러도 덜 나고 학생들이 재미있어 하는 걸 느낄 수 있었다.

> "클로드는 저보다 더 높으신 분이 제가 이런 걸 하려고 하는데 어떻게 할까 하면 좀 더 풍성하게 만들어주는 것 같은 느낌이 들었습니다." — (노명숙의 회고에서, ChatGPT 대비 Claude의 차이)

Q&A에서는 게임학과 AI 교육의 현실도 나왔다. 잘 사용하면 자신이 짤 수 있는 것보다 훨씬 높은 퀄리티를 만들 수 있지만, 이해 없이 의존도가 높은 학생은 더 못해질 가능성이 높다. 코딩보다 "글을 직접 써라. 분석은 네가 해야 된다"가 오히려 더 중요한 역량이 됐다는 것이 현장의 변화였다.

## 3. 아루네 — 4개 AI를 교차 검증해 사상체질 정밀진단 앱을 만들다

아루네(지식베이스 스터디) 발표는 한의원 대기실용 체질진단 앱 개발기였다. 처음에는 간단한 설문지로 시작했지만 알고리즘이 너무 단순하면 재미없고 신뢰도가 낮아서 완성도를 계속 올려가고 있는 상황이다.

프로젝트를 시작한 계기는 토큰 초과로 다른 걸 할 수 없어서 현재 자원 안에서 결과물을 만들기로 결심한 것이었다. Gemini에 "이번 주 뭘 할까"를 물어봤더니 지난주에 만든 사상의학 자료를 학습시켜 분류하는 웹앱을 추천했다.

**4개 AI의 역할 분담**

| AI | 강점 | 이 프로젝트에서의 역할 |
|---|---|---|
| NotebookLM | 내가 준 소스 안에서만 답변 | 로직 오류 검증 수단. 소스 근거 없는 창작 방지 |
| Gemini | 인적 오류에 대한 관점 | 환자가 어떻게 반응할지, 알고리즘 인간 맹점 찾기 |
| ChatGPT | 통계적·시스템 보완 제안 | 결과 확신도 시스템, 중복 가중치 상한제 제안 |
| Claude | 인간에게 가장 편안한 형태 | 로직 통합, 최종 코딩 |

4개 체질로 자꾸 뭉뚱그리는 문제는 아직 완전히 해결되지 않았다. Claude에게 소스를 줘도 9개 분류를 지시해도 어느 순간 다시 4개로 회귀하는 현상이 있는데, 참가자들은 "사상체질에 대한 이미 학습된 4가지 분류 자료가 많기 때문"이라고 코멘트했다. 9가지를 아예 새로 정의해서 4가지에 의존하지 않는 방식도 시도 방법이 될 수 있다는 제안도 나왔다.

> "결국 AI마다 강점이 조금 다르고 다 이렇게 주장하는 바가 조금씩 다른 면이 있어서, 결과적으로는 4개를 다 써야지 조금 더 완벽한 결과물이 나오는 것 같습니다."

현재 Firebase를 통한 데이터 업로드 방식으로 진행 중이며, GitHub에 배포했으나 정확도가 아직 낮다. 환자들 피드백에서 "왜 계속 같은 질문이 반복되냐"는 지적이 있어서 문항 배치도 개선해야 한다.

## 4. 송세현 — 코스피 자동매매를 공급자·Ticker·전략 에이전트 3개로 쪼갰다

송세현(투자자동화 스터디) 발표는 2주 연속 베스트 사례였다. 지난주에 이어 이번에는 에이전트를 3개로 분리하고 왜 분리했는지를 설명했다.

**지난주 발표 요약**: 코스피 1,600개 종목에서 재무점수 → 테마 필터링 → 차트 기술 분석 → 에이전트 매매 시도. 유튜브에서 언급되는 종목은 이미 상승 후 후행성으로 언급되는 것이어서 수익이 어렵다는 걸 확인.

**이번 주 핵심**: 에이전트 단일 운용 → 실패 원인 추적 불가 → 3분리 구조로 개선.

| 에이전트 | 역할 | 입력 | 판단 기준 |
|---|---|---|---|
| 공급자(스카우트) | 텔레그램에서 신호 수집 및 신뢰성 평가 | 텔레그램 채널 (2~3만 명) 메시지 5분 단위 | 웹서치로 실제 뉴스 확인, LLM 점수 0.7 이상이면 채택 |
| Ticker | 종목별 차트 기술 분석 | 공급자가 넘긴 티커 | 현재 상승 여력 있는지 기술적 지표 판단 |
| 전략 | 포트폴리오 자원 배분 | Ticker 분석 결과 + 현재 보유 자산 | 자산 여유 있을 때만 매수 허용, 균등 분배 |

**결과 및 한계**: 세 에이전트를 동작시켰을 때 전략 에이전트가 매우 보수적으로 자원을 균등 배분해서 실질적으로 전체 자산의 10%도 매매되지 않았다. 천만 원 투자 기준 약 12만 원 수준.

**2026-06-08 당일**: 장이 -8% 폭락했을 때 에이전트가 오히려 고장이 나서 안 팔린 게 전화위복이 됐다. 공포성 매매를 에이전트가 실행하지 못한 결과였다.

앞으로의 방향은 **레짐(Regime)** 지표 추가 — 코스피 전반의 낙폭이 얼마나 되는지를 보고, 개별 종목 신호와 별도로 시장 전반 상황에 따라 매매를 보류할 수 있는 로직이다.

> "결국은 뉴스를 수집해서 구현하면 되는데, 정말 그 뉴스들이 신뢰도가 있냐 신빙성이 있냐를 하는 게 정말 더 진짜이더라고요."

## 5. 천안한마당 — 드래곤볼을 AI 도구로 재현한 3분 단편영상

천안한마당(영상놀이터 스터디) 발표는 아이디어 고갈 없이 창의적 영상을 만드는 방법이었다. 평소 한국사 채널을 운영하고 있어 영상 제작에 거부감은 없었지만, 이번에 AI 도구로 스펙트럼이 더 넓어졌다고 했다.

제작한 영상은 드래곤볼의 손오공 대 프리저 결투 장면 약 3분 분량이다.

**제작 도구 및 흐름**

| 단계 | 도구 | 방법 |
|---|---|---|
| 레퍼런스 수집 | 구글링 | 드래곤볼 이미지를 검색해서 수집 |
| 캐릭터 실사화 | ChatGPT | 수집한 이미지를 바탕으로 실사화, 메모리에 기억시킴 |
| 대본 + 스토리보드 | ChatGPT | 씬 분해 2단계, 스토리보드 이미지·대본 생성 (약 20씬) |
| 이미지 재생성 | Codex | 스토리보드 이미지를 화질 손상 없이 씬별 재생성 |
| 영상 생성 | Grok | 스토리보드 프롬프트로 씬별 영상 생성, 공통 프롬프트로 일관성 유지 |
| 효과음 | CapCut + ChatGPT | "이 장면에 어울리는 CapCut 효과음 찾아줘" 요청으로 적재적소 배치 |
| 배경음악 | Suno | 직접 휴대폰으로 녹음 후 Suno에서 재제작 (저작권 우회) |

씬 구성은 황량한 하늘, 쓰러진 동료들, 프리저와 도발, 손오공의 결의 4가지였다. 배경이 너무 어두워서 밝기를 조정한 것이 중요한 수정 포인트였다.

격렬한 격투씬에서 Grok이 실사에서 점점 애니메이션 느낌으로 변하는 문제가 있었다. 스터디장에 따르면 CinemaDynamics 같은 특화 도구를 쓰면 더 잘 뽑아준다고 했다.

제작 시간은 약 3시간. 청중에서 "진짜로 AI가 맞는 거냐"는 반응이 나올 정도로 완성도가 높았다.

## 6. 노명숙 — 클로드 코드로 498개 Q&A를 전자책 원고로 만들기

노명숙(전자책 스터디) 발표는 단순하지만 임팩트 있는 사례였다. 54개 소그룹(목장) 탐방 파일에 담긴 신앙 관련 Q&A 498개를 전자책 한 권으로 만드는 데 30분이 걸렸다.

**작업 흐름**

| 회차 | 요청 | 결과 |
|---|---|---|
| 1차 | 54개 파일 경로 복사해서 붙여넣기 + "전자책을 만들려고 해" | 54개 스토리 → Word 파일로 하드에 자동 저장 |
| 2차 | 6개 카테고리 지정 (직장생활·결혼과 부부·육아·목사님 이야기·교회와 신앙·기타) + 몽골·베트남 소그룹 이름 오해 수정 | 파트 1~6 카테고리별 구분 완성 |
| 3차 | "중복된 질문과 답변을 통합해서 다시 써줘" | 498개 → 440개로 줄어 완성 |
| 표지 | "네가 내용을 다 읽었지 않느냐, 컨셉에 맞는 표지를 만들어줘" | 표지 이미지 생성 |

가장 인상적인 부분은 Claude Code가 **Word 파일로 직접 로컬 저장**을 해준다는 것이었다. 채팅 결과를 복사해서 붙여넣는 수작업이 없었다.

이전에 ChatGPT로 어르신 회고록을 쓸 때와 비교해서, ChatGPT는 학생이 짜깁기해서 가져온 것 같았다면 Claude는 지능이 높은 비서처럼 원본 자료를 살리면서 창의적으로 통합해준다고 평가했다.

> "진짜 자료 수집이 핵심이고, 결국 내가 하고 있는 거, 잘하는 거, 남과 다른 무언가에서부터 시작되는 것 같습니다." — 진행자 마무리 코멘트

Claude Code는 3번 작업 시 토큰 90% 소진 경고를 했다. 소진 직전에 작업을 마쳤다.

## 7. 도시아재 — 강의 기획부터 피드백까지 자동화한 Lecture Kit

도시아재(강의자동화 스터디) 발표는 세션 마지막이자 가장 복잡한 구조였다. 부동산 강의와 AI 강의를 병행하는 실무자가 "강의 콘텐츠는 내가 만들지만, 강의 운영 전반을 AI 공장에 맡기면 어떨까"라는 질문에서 시작한 프로젝트다.

이름은 **Lecture Kit**. 아직 패키징 안 된 플러그인 형태지만, 앱으로 진행할 계획이다.

**5개 입력 포인트**

| 입력 | 예시 |
|---|---|
| 주제 | 지난주 스터디 발표 자료 |
| 대상 | 22기 수강생, 강의 자동화 관심자 |
| 날짜 | 2026-06-08 |
| 맥락 | 7번째 발표, 가장 마지막, 피곤한 상태 |
| 시간 | 12분 → 9장 슬라이드 제안 |

**공장 구조 (4층)**

| 층 | 구성 요소 | 역할 |
|---|---|---|
| 최상위 | 지휘자 1명 | 전체 조율 |
| 중간 | 작업반장 9명 | 단계별 스킬 실행 |
| 검수 | 검사관 5명 + 수석 검사관 1명 | 5항목 검수 후 합격/불합격 판정 |
| 외부 연동 | NotebookLM CLI, Gamma, Gmail, 구글 폼, Make | 지식 저장, 슬라이드 생성, 발송 자동화 |

**6에이전트 × 5항목 검수 시스템**

| 검수 항목 | 내용 |
|---|---|
| 정합성 | 숫자·건수·순서가 맞는가 |
| 일관성 | 용어·이름 표기가 통일됐는가 |
| 시간 | 정해진 분량 안에 완료 가능한가 |
| 민감 정보 | 개인 정보·공개 불가 내용이 포함됐는가 |
| 재연성 | 수강생이 복사 붙여넣기 했을 때 재현 가능한가 |

대전 강의에서 중대 문제 6건을 3번 검수 사이클로 0건으로 처리한 실적이 있다.

**강의 파이프라인 흐름**

```
강의 전:
입력 5개 → 기획서 MD → 지식 자산(NotebookLM) → 슬라이드(Gamma) → 6에이전트 검수 → 하루 전 점검 → QR·구글 폼 생성

강의 중:
강의 진행 → 피드백 수집 (구글 폼)

강의 후:
구글 시트 대시보드 → 감사 메일 → Call-to-Action (심화 과정 소개)
```

노란 버튼(사람 검수)은 4지점: 기획서 확인, 노트북 내용 확인, 외부 발송 메일 최종 확인, 피드백 결과 검토.

> "강의 콘텐츠는 여러분들께서 전문가라고 생각이 들고요. 다만 강의에 대한 전반적인 운영은 AI한테 맡기는 것이 강의를 잘하고 오래 할 수 있는 방법이 아닌가라는 생각으로 말씀드리면서 발표를 마치겠습니다."

## 8. 자주 막히는 곳

| 증상 | 대응 |
|---|---|
| AI가 내 의도와 다른 스타일로 영상을 만들어준다 | 레퍼런스 영상을 분석시키고 Gemini 등에서 받은 프롬프트를 다른 도구에 그대로 붙여넣는다. 도구별로 기본값이 다르다. |
| 사람 얼굴이 포함된 장면을 수정하면 구글 정책 위반이 뜬다 | 사람 얼굴 전체를 교체하는 방식보다 뒷부분이나 동작만 수정 요청하는 형태로 프롬프트를 바꾼다. |
| AI가 프롬프트 한 줄로는 수준에 맞는 코드를 안 짜준다 | 마크다운 파일에 현재 학습 수준, 파일명, 요구 사항을 기록해서 파일째 업로드한다. |
| 같은 체질 분류 AI에 소스를 줘도 계속 원래 4개 분류로 돌아간다 | 9가지 체질을 새로 정의해서 기존 4가지 분류에 의존하지 않는 전혀 새로운 용어 체계로 자료를 만든다. |
| 에이전트가 일했지만 실패 원인을 알 수 없다 | 에이전트를 역할별로 쪼개서 공급자·판단자·전략 에이전트로 분리하면 각 단계 결과를 추적할 수 있다. |
| Claude Code에 파일을 넣었는데 모르는 단어로 착각한다 | "몽골/베트남은 나라가 아니라 소그룹 이름이니 삭제해" 처럼 AI의 오해를 명시적으로 수정해준다. |
| 전자책 원고 작업 중 토큰이 소진될 것 같다 | Claude Code는 90% 소진 경고를 준다. 작업 회차를 나눠서 각 단계에서 저장 후 다음 회차로 넘긴다. |
| 강의 슬라이드를 만들었는데 시간, 용어, 민감 정보 오류가 있다 | 6에이전트 검수 시스템처럼 정합성·일관성·시간·민감정보·재연성 5항목을 체크리스트로 만들어 AI에게 검수 역할을 준다. |

> 막히는 지점 대부분은 AI에게 내 상황을 충분히 전달하지 않을 때 생긴다. 한 줄 프롬프트보다 파일과 구조화된 입력이 AI를 더 정확하게 움직이게 한다.
