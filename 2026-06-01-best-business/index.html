강의는 어떤 내용이었나

지피터스 22기 베스트 발표회 중 업무와 비즈니스 사례를 모은 세션이다. 발표자들은 옵시디언 지식관리, 공공기관 보고서 자동화, 개인 LLM 위키, 당근 비즈프로필 사업화, 부동산 중개 서비스, 로블록스 타이머 앱, 인생 OS 루틴을 실제로 적용한 과정을 공유했다.

핵심은 도구 이름보다 적용 방식이었다. 각 사례는 병목을 찾고, AI가 맡을 단위를 정하고, 사람이 검수할 지점을 만든 뒤, 실사용에서 깨지는 부분을 고치는 흐름으로 이어졌다.

섹션 내용
오프닝 발표 시간과 순서 안내
PKM 볼트 위키링크와 허브 구조를 측정하고 정리
보고서 자동화 HWP/PDF에서 지식·양식·초안을 분리
개인 LLM 위키 raw 자료를 위키로 만들고 교차 참조 관리
당근 비즈니스 녹음 대화에서 사업계획서와 슬라이드 생성
부동산 AI 조직 앱·공공데이터·통화요약·운영 에이전트 연결
타이머 앱 하루 MVP와 실사용 안정화의 차이 공유
인생 OS 북극성 지표와 10분 실행 기록으로 루틴 구축

0. 한눈에 보는 업무·비즈니스 AI 적용 패턴

  1. 반복되는 고통을 고른다 — 문서 변환, 링크 단절, 자료 정리, 매물 관리, 시간 통제처럼 자주 막히는 일을 찾는다.
  2. 기준값을 잰다 — 사용률, 깨진 링크, 파일 수, 처리 시간, 오류 유형을 기록한다.
  3. AI 입구를 만든다 — raw 폴더, inbox 스킬, 녹음 파일, 공공데이터 API, COO 에이전트처럼 투입 지점을 정한다.
  4. 단계를 쪼갠다 — ingest, extract, template, draft, critique, lint, deploy처럼 한 번에 하나씩 맡긴다.
  5. 사람 승인 지점을 둔다 — 의도, 독자, 템플릿, 최종본, 배포 여부는 사람이 결정한다.
  6. 실제 환경에서 부딪힌다 — PC 권한, 해상도, 앱 우회, 데이터 정확성, 컨텍스트 한계를 확인한다.
  7. 템플릿과 규칙으로 남긴다 — 다음 실행이 5분 안에 시작될 수 있게 문서화한다.

1. PKM 볼트에 그물 짜기

야호심 발표는 강의를 그대로 따라 하기보다 자기 옵시디언 볼트의 “부채 청소”부터 시작한 사례였다. 964개 노트 중 위키링크가 있는 파일은 6%뿐이었고, 폴더 이동으로 깨진 링크도 22개 있었다.

지표 전 후
위키링크 사용률 6% 16%
깨진 링크 22개 0개
사용 파일 50개 153개
허브 수 5개 11개
외부 수집 자료 연결 0% 15%

측정 없는 PKM은 신앙이다.

핵심은 허브 템플릿을 만들되 영역별 중심축은 다르게 둔 점이다. 달리기는 시간, 업무는 부서, 독서는 책, 인맥은 사람을 중심축으로 삼아 “통일은 빠르고 차이는 정확한” 구조를 만들었다.

2. 보고서 자동화는 6개 스킬과 승인 게이트로 만든다

고호원 발표는 공공기관 보고서 자동화 사례였다. HWP, HWPX, PDF를 MD로 바꾸고, 보고서의 구조·개념·사실관계·판단·양식을 분리해 다시 보고서 초안으로 조립했다.

스킬 역할 품질 기준
Inbox HWP/PDF를 MD로 변환 페이지 이미지를 먼저 보고 헤딩 계층을 잡음
Extract 구조·개념·사실·판단 추출 보고서를 요소 단위로 분해
Template 회사·부서·문서종·개인 문체 계층화 공통 양식과 개인 표현 분리
Wiki 지식을 개념 카드로 전환 보고서 간 재사용 가능
Draft 질문, 조사, 템플릿 선택, 초안 작성 독자·목적·의도를 최소 8개 질문으로 확인
Output MD를 한글·워드로 변환 프로세스는 있으나 만족도는 아직 낮음

중요한 원칙은 “각 단계가 최소 품질 기준을 통과해야 다음 단계로 넘어간다”는 점이다. AI가 초안을 만들고, 양식·논리·정합성·상사 페르소나·최종 독자 관점으로 다시 크리틱한 뒤 사람이 승인한다.

3. AI 사서가 개인 LLM 위키를 관리한다

BK 발표는 안드레 카파시의 LLM 위키 아이디어를 클로드 코드와 옵시디언으로 구현한 사례였다. 기존 개인 위키가 실패하는 이유를 유지관리 비용으로 보고, 정리·교차 참조·링크 복구를 AI 사서에게 맡겼다.

구성 역할
raw 폴더 웹 자료, PDF, 개인 아이디어를 넣는 입구
CLAUDE.md 위키 명령과 운영 규칙
schema.md 위키 페이지 형식과 분류 기준
ingest raw 자료를 위키 페이지로 생성·업데이트
query 지식베이스에 질문하고 글감 추출
lint 끊어진 링크, 누락 태그, 교차 참조 오류 복구

사용자는 자료를 고르고 질문하고 창조적 산출물을 만드는 데 집중한다. AI는 새 페이지 작성, 기존 페이지 업데이트, 링크 연결, 태그 보정 같은 유지관리 비용을 줄인다.

4. 당근 비즈프로필을 로컬셀러 플랫폼으로 확장하다

준 발표는 라이오와 나눈 사업 아이디어 녹음 파일을 코덱스에 넣어 사업계획서와 발표 자료로 발전시킨 사례였다. 출발점은 “AI 공부를 하면서 1달러라도 벌어보자”였고, 결과는 AI 기반 로컬셀러 산지직송 커머스 플랫폼 아이디어였다.

단계 입력 산출
녹음 투입 아이디어 회의 파일 전사와 요약
사업계획 요청 당근 비즈프로필과 산지직송 맥락 플랫폼 초안
리서치 공식 자료와 딥리서치 MD 정리
슬라이드 구성 사업계획서 초안 피그마에서 다듬을 발표 자료

핵심 구조는 산지 공급자와 동네 로컬셀러를 연결하고, 상품·주문·홍보·정산 같은 중앙 운영을 AI 에이전트가 보조하는 것이다. 코덱스는 전사 품질은 괜찮았지만 30분에서 1시간 사이 녹음 처리에 약 30분이 걸려, 빠른 전사만 필요할 때는 다른 도구와 병행하는 편이 현실적이었다.

5. 부동산 중개업을 AI 조직으로 운영하다

골든 레비 발표는 금토끼 부동산 업무에서 나온 서비스와 AI 조직 운영 사례였다. 공공데이터 앱, 매물장, 매물 지도, 재개발·재건축 지도, 통화 요약 메신저를 프롬넷이라는 서비스 틀 안에 묶었다.

서비스 문제 해결
부동산 백과 공공데이터 검색이 번거로움 앱에서 정보 검색
매물장 에어테이블 한도와 용량 문제 자체 입력·관리 도구
매물 지도 광고 사이트와 지도 입력 중복 매물 입력 후 지도 자동 표시
정비구역 지도 재개발 맥락 확인이 분리됨 공공데이터 지도 시각화
프로톡 긴 통화 내용을 팀이 듣기 어려움 통화 파일 자동 요약

AI 조직은 CEO/COO가 지시를 받아 기획, 디자인, QA, 개발팀에 업무를 나누는 방식이다. CLAUDE.md에는 Whisper 로컬 설치 금지, 키와 환경파일 커밋 금지, 같은 파일 동시 수정 방지 같은 운영 규칙을 넣었다.

6. 하루 MVP와 실사용 앱 사이의 거리를 배운다

얼른 머스크 발표는 로블록스 시간관리 앱을 만든 후기였다. Windows Family Safety가 자주 오작동했고, 아이가 시간을 우회하는 문제가 있어 직접 타이머 앱을 만들었다.

단계 기능 배운 점
MVP 타이머, 경고, 로블록스 종료 하루 만에 그럴듯한 앱은 가능
실사용 세션 기록, 설정 저장, 평일·주말 시간 요구사항이 급격히 늘어남
방어 앱 미실행, 강제 종료, 재부팅, 삭제 대응 사용자는 규칙을 우회함
배포 GitHub 릴리즈, 설치·권한 이슈 개발 환경과 사용자 PC는 다름
안정화 29회 커밋, 버전 0.6 MVP 이후가 진짜 개발

질의응답에서는 “시간 차단”뿐 아니라 “약속을 지키면 보상”하는 구조도 제안됐다. 기능을 통제 도구로만 보지 않고 행동 설계까지 확장해볼 수 있다는 관점이다.

7. 인생 OS는 북극성과 10분 기록에서 시작한다

마지막 영상 사례는 AI 초보 디자이너가 인생 OS 강의를 통해 북극성을 설정하고 포트폴리오 제작 루틴을 만든 과정이었다. 연봉, 포트폴리오 방문자, 전환 같은 수치형 지표를 잡고 매일 10분 단위로 실행을 기록했다.

북극성 설정 커리어 목표를 수치형 지표로 바꿈 막연한 불안을 실행 기준으로 전환

8. 자주 막히는 곳

증상 대응
AI가 한 번에 문서를 처리하다 깨뜨림 문서를 1개씩 처리하고, 이미지로 구조를 먼저 잡은 뒤 텍스트를 매칭한다.
위키가 커질수록 연결 관리가 부담됨 ingest와 lint 명령을 분리하고, 교차 참조 복구를 반복 명령으로 만든다.
초안은 빨리 나오지만 실사용에서 오류가 터짐 권한, 저장 위치, 해상도, 표준 계정, 설치 환경을 별도 체크리스트로 둔다.
에이전트가 위험한 파일을 건드릴 수 있음 키, 환경파일, 설치 금지, 파일 소유권 규칙을 CLAUDE.md에 명시한다.
코덱스 전사가 오래 걸림 빠른 전사는 전용 도구와 병행하고, 리서치·정리까지 묶을 때 코덱스를 쓴다.
목표가 추상적이라 실행이 안 됨 북극성 지표를 수치로 만들고 10분 단위 기록부터 시작한다.

자주 막히는 지점은 도구 문제가 아니라 공정 문제인 경우가 많다. 입력, 품질 기준, 승인 지점, 운영 규칙을 분리하면 다음 시도가 쉬워진다.
