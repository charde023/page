## 강의는 어떤 내용이었나

발표는 영상 제작, 논문과 글쓰기, 취업 공고 크롤링, 학습 웹앱, 전자책 게임북, 주식 자동매매, 뮤직비디오 제작으로 이어졌다. 주제는 달랐지만 핵심은 비슷했다. AI를 도구 하나로 쓰기보다 역할을 나누고, 검토 지점을 만들고, 실패를 통해 프롬프트와 작업 환경을 고쳤다.

## 0. 한눈에 보는 콘텐츠와 지식 사례
1. 문제를 좁힌다 — "영상 만들기"가 아니라 "선수 이름이 들어간 직관 영상"처럼 실제 막힌 작업을 잡는다.
2. AI 역할을 나눈다 — 질문자, 진단자, 실행자, 검토자처럼 권한을 다르게 둔다.
3. 입력 구조를 만든다 — 지침, PRD, 캐릭터 시트, 목차, 재무 점수처럼 반복 가능한 재료를 준비한다.
4. 산출물을 본다 — 웹앱, 엑셀, 영상, 작업실처럼 눈으로 확인 가능한 형태로 뽑는다.
5. 실패 원인을 분리한다 — 정책 차단, 레이아웃, 데이터 누락, 자막, 번호판, 중복 공고를 따로 본다.
6. 다시 시도한다 — 새 창에서 시작하거나, AI에게 회고를 시키거나, 프롬프트를 분리한다.
7. 공유 가능한 형태로 묶는다 — 링크, GitHub, Netlify, 게시글로 다른 사람이 따라 할 수 있게 만든다.

## 1. 글쓰기와 연구 — 빙봉빙봉
빙봉빙봉의 사례는 "공동 플레이북에 하네스를 걸어보기"였다. 다오랩의 Human Agent Teaming Lab 연구 맥락에서 여러 사람이 각자 쓴 글을 하나의 연구 플레이북으로 엮어야 했다.
핵심은 AI에게 바로 통합본을 쓰게 하지 않는 것이다. 먼저 독자, 핵심 주장, 구체 사례, 톤을 물어보게 하고, 초고를 합칠 때도 "통합하지 말고 충돌만 진단하라"고 역할을 좁혔다.
| 적용 지점 | 하네스 방식 | 기대 효과 |
|---|---|---|
| 개인 글쓰기 | 답변 전 독자, 주장, 사례, 톤을 질문 | 맥락 없는 일반론 방지 |
| 공동 초고 통합 | 용어, 중복, 입장, 형식 충돌만 표로 진단 | 사람이 결정할 편집점 확보 |
| 다음 단계 | 진단, 결정 기록, 통합 실행, 검수를 분리 | AI 권한을 단계마다 다르게 부여 |
> "진단만 하고 결정은 사람이 한다"가 이 사례의 가장 중요한 안전벨트다.

## 2. 영상 입문 — 채원
채원은 AI 초보자 관점에서 K리그 직관 브이로그 영상을 만들었다. AntiGravity에서 프로젝트와 캐릭터, 장면 프롬프트를 정리하고, GPT로 이미지 두 장을 만든 뒤 Gemini에 넣어 10초 영상을 생성했다.
처음 나온 영상은 자연스러웠지만, 유니폼 뒷면 이름이 외계어처럼 생성됐다. 실제 선수 이름과 등번호를 넣는 시도는 정책 차단에 걸렸고, 발표자는 "실존 인물 묘사"와 "텍스트가 프린트된 유니폼"을 분리해야 한다는 힌트를 얻었다.
| 배운 점 | 내용 |
|---|---|
| 빠른 몰입 | 한 줄 프롬프트만으로도 영상이 나오면 학습 동기가 커진다. |
| 정책 이해 | 이름, 얼굴, 유니폼이 섞이면 딥페이크 차단으로 해석될 수 있다. |
| 시행착오 | 실패를 반복하며 AI에게 이유를 묻는 과정 자체가 학습이다. |

## 3. 스킬 패키징 — 송주환
송주환은 취업 공고를 모으는 작업을 Claude Code 스킬로 만들고 GitHub에 배포했다. 원티드, 점핏, 사람인 같은 플랫폼을 탭으로 열어보는 대신, 키워드와 플랫폼, 기간, 정렬 방식을 물어보고 결과를 엑셀로 여는 방식이다.
의미 있었던 지점은 "나만 쓰는 자동화"에서 끝내지 않았다는 점이다. 스킬로 패키징해 다른 사람도 설치할 수 있게 만들었고, 기본값과 질문 흐름을 넣어 비슷한 사용자가 커스텀할 수 있게 했다.
| 구성 | 설명 |
|---|---|
| 입력 | 키워드, 플랫폼, 등록 기간, 정렬, 출력 방식 |
| 처리 | 플랫폼별 크롤링, 오류 우회, 결과 정리 |
| 출력 | 상위 공고 미리보기, 필터가 있는 엑셀 파일 |
| 남은 과제 | 플랫폼 간 동일 공고 중복 제거 |
질문에서 흥미로웠던 부분은 오류 해결 방식이었다. 잡코리아 요청 차단이나 Playwright 전환 같은 문제를 발표자가 일일이 분석한 것이 아니라, 작업 세션 로그를 AI가 읽고 해결 과정을 남겼다.

## 4. 지식 웹앱 — 자몽블랙티
자몽블랙티는 수험 영어 학습을 위한 웹앱을 만들었다. Claude 프로젝트에 페르소나, 태스크, 컨텍스트, 포맷을 넣고, Gemini로 PRD 작성법을 배운 뒤, NotebookLM의 학습 자료를 연결했다.
결과물은 Day 1부터 Day 40까지 확장할 수 있는 학습 페이지였다. 단어, 발음, 의미 구분, 오디오 복습, 복습 테스트, 영상 강의까지 한 화면에서 다루는 구조였다.
| 만든 것 | 사용한 방식 | 막힌 점 |
|---|---|---|
| Claude 프로젝트 | 맞춤 지침과 사례 양식 파일 투입 | 일관성 유지 |
| 학습 콘텐츠 | NotebookLM 자료를 수험용으로 재가공 | 불필요한 잡담 제거 |
| 웹 배포 | Netlify 드래그 앤 드롭 | 파일 누락, 모바일별 동작 차이 |
| 영상과 음성 | 기존 영상 스터디 경험, TTS 설정값 활용 | 음성 끊김과 플랫폼별 재생 문제 |
이 사례는 사업 계획으로 이어질 수 있는 수준의 프로토타입이었다. 핵심은 한 번 만든 지침을 다음 Day 콘텐츠 생산의 자동화 기반으로 삼는다는 점이다.

## 5. 모바일 게임북 작업실 — 백구
백구는 선택형 어드벤처 게임북을 만들고 있었다. 쌍둥이를 키우는 상황이라 컴퓨터 앞에 오래 앉기 어렵고, Telegram과 Hermes를 활용한 모바일 작업 환경이 필요했다.
Telegram은 회의실로 쓰고, 본문은 별도 웹 작업실에서 검토했다. 게임북은 분기가 많아질수록 페이지와 선택지가 폭발하므로 모바일 본문 검토실, 큰 작업실, 흐름 검토실을 나눴다.
| 작업 공간 | 역할 |
|---|---|
| Telegram | 아이디어, 장면, 캐릭터 대사 회의 |
| Claude Code | 대규모 파일과 코드 작업, 본문 검토 화면 제작 |
| 모바일 작업실 | 섹션별 본문 읽기 |
| 흐름 검토실 | 선택지 노드와 이어지는 본문을 함께 확인 |
현재 병목은 기획이었다. 세계관과 캐릭터 설정이 약하면 분기형 스토리는 빠르게 꼬인다. 그래서 새 장면을 더 쓰기보다 전체 체계와 전개 방향을 다시 잡는 단계였다.

## 6. 자동매매 에이전트 — 송세현
송세현은 AI를 활용한 코스피, 코스닥 자동매매 실험을 공유했다. 종목 선택이 중요하다고 보고 재무, 테마, 차트, AI 판단의 네 단계 필터를 만들었다.
AI가 모든 것을 직접 매매하는 구조는 아니었다. 재무 점수와 테마 언급, 기술적 신호는 프로그램이 계산하고, 에이전트는 주어진 정보 안에서 살지 말지와 매수 강도를 판단했다.
| 단계 | 판단 기준 |
|---|---|
| 재무 | 매출, 이익률, 장부가치 등으로 기본 안전성 필터링 |
| 테마 | 경제 유튜브와 네이버 테마에서 언급량과 정서 확인 |
| 차트 | 거래량, 추세, 매집 가능성 등 기술적 신호 확인 |
| 에이전트 | 스카우트, 티커, 전략 에이전트가 관심 종목과 비중 조정 |
결론은 솔직했다. 손실은 없지만 수익도 크지 않았다. 안전장치를 많이 넣어 너무 보수적으로 움직였기 때문이다. 다만 매매 뒤 회고를 시키며 전략과 코드를 계속 단단하게 만들고 있었다.

## 7. 뮤직비디오 제작 — 엘리
엘리는 "굿바이 마이카" 뮤직비디오를 만들었다. 면허 반납과 오래 탄 차에 대한 정서를 포크 트로트풍 노래와 영상으로 풀었다.
프로세스는 Claude Code로 스토리와 가사를 잡고, Suno로 음악을 만들고, Grok과 Gemini로 이미지와 영상을 생성한 뒤, CapCut으로 편집하는 방식이었다. 3분 37초 영상이라 6초에서 10초짜리 씬을 수십 개 만들어야 했다.
| 작업 | 핵심 포인트 |
|---|---|
| 가사 | 리듬이 어색한 부분을 Claude Code로 여러 번 검토 |
| 음악 | 트로트 팝, 포크 팝 중 포크 트로트 선택 |
| 이미지 | 젊은 주인공, 나이 든 주인공, 자동차 캐릭터 시트 제작 |
| 씬 제작 | 4x4 그리드로 여러 컷을 뽑고 마음에 드는 컷 선택 |
| 편집 | 자막, 번호판, 쇼츠 구간 분석까지 후처리 |
막힌 곳은 디테일이었다. 운전석 방향, 자동차 속도, 번호판 유지, 여러 인물 자세처럼 사람이 보면 쉬운 장면이 생성 모델에는 계속 흔들렸다.
