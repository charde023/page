## 0. 한눈에 보는 콘텐츠와 지식 작업 흐름

1. 발표 소재를 고른다 — 글쓰기, 영상, 크롤러, 학습 앱, 전자책, 자동매매, 뮤직비디오 중 자기 문제와 맞는 사례를 고른다.
2. 작업을 쪼갠다 — 기획, 자료 수집, 초안, 검토, 배포, 회고처럼 AI에게 줄 단위를 나눈다.
3. 기준을 먼저 준다 — 독자, 톤, 안전장치, 투자 기준, 영상 장면 조건을 먼저 정의한다.
4. 작은 산출물을 만든다 — 10초 영상, 첫 Day 학습 페이지, 첫 크롤러, 첫 작업실처럼 작게 완성한다.
5. 막힌 지점을 기록한다 — 정책 차단, 파일 누락, 오디오 끊김, 분기 복잡도, 과도한 보수성을 적는다.
6. 도구를 조합한다 — Claude Code, Gemini, NotebookLM, Suno, Grok, CapCut, Netlify를 목적별로 연결한다.
7. 사람이 판단한다 — AI는 진단과 실행을 돕고, 최종 결정과 품질 기준은 사람이 유지한다.
8. 다음 버전을 만든다 — 질문과 피드백을 받아 자동화, 작업실, 영상, 투자 전략을 다시 다듬는다.

## 1. 하네스와 입문 사례는 기준을 먼저 세우는 연습이다

빙봉빙봉의 발표는 공동 플레이북 글쓰기에서 하네스를 쓰는 실험이었다. AI에게 바로 글을 쓰게 하는 대신, 독자·핵심 주장·구체 사례·톤을 먼저 묻도록 하고, 여러 저자의 초고를 합칠 때도 통합이 아니라 충돌 진단만 맡겼다.

채원의 발표는 AI 입문자가 K리그 직관 브이로그 영상을 만드는 과정이었다. Antigravity에서 프로젝트 대시보드와 프롬프트를 만들고, ChatGPT로 캐릭터와 경기장 이미지를 생성한 뒤 Gemini로 10초 영상을 만들었다. 이후 실제 선수명과 등번호를 넣으려다 생성 정책에 막혔고, “실존 인물”이 아니라 “텍스트가 프린트된 유니폼”처럼 표현을 분리해야 한다는 힌트를 얻었다.

| 사례 | 바로 한 요청 | 더 나은 기준 |
|---|---|---|
| 하네스 글쓰기 | “이 주제로 글을 써줘” | 본문 작성 전 독자, 주장, 사례, 톤을 질문하게 한다. |
| 초고 통합 | “다섯 초고를 합쳐줘” | 용어 충돌, 중복, 입장 충돌, 형식 불일치만 표로 진단하게 한다. |
| 영상 생성 | “선수 이름 유니폼을 입은 사람” | 사람과 텍스트·의상·소품을 분리해서 설명한다. |
| 반복 수정 | 같은 대화에서 계속 우회 | 실패 맥락이 누적되면 새 대화에서 제로 베이스로 다시 시작한다. |

> 좋은 결과는 AI에게 더 많이 시키는 데서 나오기보다, 다음 단계로 넘어가기 전에 무엇을 확인해야 하는지 정하는 데서 나온다.

## 2. 스킬과 지식 베이스는 개인 작업을 재사용 가능한 도구로 바꾼다

송주환은 취업 공고를 크롤링하는 작업을 Claude Code 스킬로 패키징했다. Wanted, Jumpit, Saramin 같은 플랫폼에서 키워드, 플랫폼, 기간, 정렬, 출력 방식을 차례로 고르게 하고, 결과는 미리보기와 Excel 파일로 확인하게 했다. 중요한 점은 개인 작업을 GitHub에 올려 다른 사람도 설치하고 쓸 수 있게 만든 것이다.

자몽블랙티는 수험 영어 학습 웹앱을 만들었다. Claude 프로젝트에 페르소나, 태스크, 컨텍스트, 포맷을 넣고, NotebookLM으로 학습 콘텐츠를 정리하고, Gemini로 PRD를 작성한 뒤 Netlify에 웹페이지를 배포했다. Day 1부터 Day 40까지 확장할 수 있도록 일관된 지침을 쌓아두는 것이 핵심이었다.

| 발표자 | 입력 | AI 처리 | 산출 |
|---|---|---|---|
| 송주환 | 취업 키워드, 플랫폼, 기간, 정렬 기준 | 공고 크롤링, 오류 우회, 엑셀 출력 | 설치 가능한 잡 크롤러 스킬 |
| 자몽블랙티 | 수험 영어 자료, 사례글 양식, PRD, NotebookLM 자료 | 학습 콘텐츠 변환, 웹 구성, 오디오·영상 복습 흐름 생성 | Day별 영어 학습 웹앱 |

## 3. 게임북 전자책은 생활 제약에서 작업실 설계가 시작됐다

백구는 전자책 스터디에서 `어스름 너머의 세계`라는 어드벤처 게임북을 만들고 있었다. 낮에는 쌍둥이 육아로 컴퓨터 앞에 오래 앉기 어렵기 때문에, 필요한 것은 “오래 작업하는 법”이 아니라 핸드폰으로 회의하고 검토할 수 있는 모바일 작업 환경이었다.

Hermes와 Telegram은 방향 조율, 장면 아이디어, 캐릭터 대사 같은 회의에 쓰고, Claude Code는 큰 파일 구성과 웹 작업실을 만드는 데 썼다. 게임북은 선택지에 따라 분기가 계속 늘어나기 때문에, 본문만 읽는 작업실과 분기 흐름을 보는 작업실을 나눴다.

| 작업 공간 | 맡은 일 | 왜 필요한가 |
|---|---|---|
| Telegram 회의실 | 아이디어, 장면, 대사, 간단한 요청 | 모바일로 짧게 대화할 수 있다. |
| 작은 작업실 | 섹션 제목과 본문을 모바일에서 읽기 | 본문 검토를 채팅방 밖으로 분리한다. |
| 큰 작업실 | 전체 스토리 줄기와 선택지 그래프 보기 | 분기가 늘어날 때 흐름을 한눈에 본다. |
| 흐름 검토실 | 노드와 본문을 함께 눌러가며 읽기 | 선택지 이후 스토리가 자연스러운지 확인한다. |

### 게임북 작업에서 얻은 교훈

| 막힌 지점 | 대응 |
|---|---|
| Telegram 안에 본문을 펼치면 토큰과 맥락이 쌓임 | 회의는 채팅방, 본문 검토는 웹 작업실로 분리한다. |
| 분기가 많아지면 그래프가 복잡해짐 | 선택한 섹션에서 이어지는 줄기만 따라보는 흐름 검토실을 만든다. |
| 세계관과 전개가 중구난방이 됨 | 스토리 작성보다 전체 구도와 설정을 다시 잡는다. |
| 화면에서 바로 편집은 어려움 | 조회는 작업실에서 하고 실제 편집은 Markdown 파일에서 한다. |

## 4. 주식 자동매매는 AI 판단보다 필터와 회고가 중요했다

송세현은 에이전트를 활용한 주식 투자 스터디 사례로 자동매매 파이프라인을 공유했다. 핵심은 AI가 아무 종목이나 사게 하는 것이 아니라, 코스피·코스닥 종목을 재무, 테마, 기술적 차트, 에이전트 판단의 네 단계로 거르는 구조였다.

발표자는 자동매매를 맡기려면 사람이 불안해서 계속 개입하지 않아도 될 정도의 기본 안전장치가 필요하다고 봤다. 그래서 재무 점수로 부실 종목을 거르고, 경제 유튜브와 테마 언급으로 관심 종목을 잡고, 차트 신호를 본 뒤, 에이전트가 매수 여부와 강도를 판단하게 했다.

| 단계 | 판단 내용 | 역할 |
|---|---|---|
| 1. 재무 | 매출, 이익률, ROE, PBR 등 기본 체력 | 자동매매를 맡길 수 있는 종목만 남긴다. |
| 2. 테마 | 네이버 테마, 경제 유튜브 언급량, 긍·부정 맥락 | 지금 관심을 받는 종목을 찾는다. |
| 3. 차트 | 거래량, 추세, 진입 신호 | 사도 되는 타이밍인지 본다. |
| 4. 에이전트 | 수급, 뉴스, 프롬프트 기준, 매수 강도 | 살지 말지와 얼마만큼 살지 결정한다. |

### 에이전트 구조

| 에이전트 | 역할 |
|---|---|
| 스카우트 | 외부 신호를 감지해 관심 종목 리스트를 만든다. |
| 티커 | 개별 종목의 매수 타이밍과 매수 강도를 판단한다. |
| 전략 | 포트폴리오 전체에서 종목별 비중을 조정한다. |
| 회고 루프 | 잘한 것과 못한 것을 돌아보고 코드와 전략을 다시 다듬는다. |

> 수익보다 먼저 확인한 것은 “손실을 크게 내지 않도록 AI 판단을 얼마나 보수적으로 통제할 수 있는가”였다.

## 5. 뮤직비디오는 가사, 장면, 자막을 끝까지 쪼개는 작업이었다

엘리는 영상 놀이터 스터디에서 `굿바이 마이카` 뮤직비디오를 만들었다. 주제는 고령자 운전면허 반납을 응원하는 노래와 영상이었다. Suno로 노래를 만들고, Grok과 Gemini로 이미지와 영상을 만들고, CapCut으로 편집과 자막을 붙였다.

3분 37초짜리 뮤직비디오는 한 번에 만들어지지 않는다. 6초에서 10초짜리 장면을 수십 개 만들고, 마음에 드는 컷을 고르고, 운전석 위치, 차선, 속도, 번호판, 인물 자세 같은 디테일을 계속 조정해야 했다.

| 제작 단계 | 도구 | 핵심 작업 |
|---|---|---|
| 스토리·가사 | Claude Code | 노래 스토리, 가사 초안, 리듬 검토 |
| 음악 | Suno | 트로트 팝과 포크 팝 버전 생성, 최종 장르 선택 |
| 이미지 | Grok, Gemini | 주인공의 젊은 시절, 노년, 자동차 캐릭터 시트와 장면 생성 |
| 영상 | 이미지 기반 영상 생성 | 6~10초 장면을 여러 번 만들고 골라 붙임 |
| 자막·편집 | CapCut | 가사 자막과 최종 뮤직비디오 편집 |
| 쇼츠 운영 | Gemini | 유튜브 분석과 쇼츠 구간 추천 |

### 긴 영상에서 막힌 지점

| 어려움 | 대응 |
|---|---|
| 이미지 그리드에서 원하는 컷을 잘라야 함 | Python 그리드 이미지 분할기를 만들어 반복 작업을 줄였다. |
| 운전석과 차선이 계속 틀어짐 | 위치, 속도, 카메라 구도, 차선 조건을 프롬프트에 더 구체적으로 넣었다. |
| 번호판이 장면마다 바뀜 | 번호판을 고정 조건으로 박아 넣는 식의 프롬프트 작업이 필요했다. |
| 자막 비용과 편집 방법이 고민됨 | CapCut 자동 자막과 Claude Code 기반 대안을 함께 검토했다. |
| 무료 생성물의 권리 문제가 있음 | Suno는 저작권과 권한 문제 때문에 유료 사용을 권장했다. |

## 6. 자주 막히는 곳

| 증상 | 대응 |
|---|---|
| AI가 글을 바로 써버려 내 관점이 빠진다. | 독자, 핵심 주장, 사례, 톤을 먼저 묻도록 하네스를 둔다. |
| 여러 사람의 글을 합치면 용어와 주장이 섞인다. | AI에게 통합을 맡기지 말고 충돌 진단 표만 만들게 한다. |
| 영상 생성이 실존 인물 정책에 막힌다. | 사람을 묘사하는 대신 텍스트, 의상, 소품, 배경을 분리해서 설명한다. |
| 크롤러 결과에 중복 공고가 생길 수 있다. | 플랫폼별 중복 제거 기준을 후속 기능으로 넣고 GitHub 이슈나 댓글로 개선한다. |
| Netlify 배포 후 모바일에서 음성이 끊긴다. | 오디오 경로, 브라우저별 재생 정책, Android·iOS 차이를 따로 확인한다. |
| 게임북 분기가 많아져 흐름을 못 따라간다. | 본문 작업실과 분기 그래프 작업실을 분리하고 노드별로 읽는다. |
| 자동매매가 너무 보수적으로만 돈다. | 안전장치를 유지하되 회고 루프에서 매수 강도와 조건을 조금씩 조정한다. |
| 뮤직비디오 컷이 계속 마음에 들지 않는다. | 장면을 6~10초 단위로 쪼개고 컷 선택, 그리드 분할, 자막을 별도 작업으로 둔다. |
| 무료 음악 생성물의 권리가 애매하다. | 공개·상업 활용 가능성을 확인하고 필요하면 유료 플랜을 사용한다. |
